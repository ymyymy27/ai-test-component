## 3 未走通与问题

### 3.1 首次环境准备失败（已定位）

隔离 profile 原先把 `aitest.pythonPath` 指向仓库 `.venv`。该解释器由 uv 管理，
`sys._base_executable` 位于 junction 路径；`EnvironmentProbe._no_links` 按安全合同拒绝链接路径，
`carrier_configuration` 抛错，面板只显示通用的“准备未完成，请核对目录、Python 3.11+ 和安全凭据”。

- 影响：用户无法从界面知道是“基础解释器路径含链接”，只能猜。
- 临时绕过：改用本机非链接的 Python 3.11 核心运行时（`AppData\Local\AITest\python`），
  环境准备随即成功。
- 待办：要么在 onboarding 中给出可操作的错误分类，要么明确支持“已解析的基础解释器”并保留安全核对。

### 3.2 本机核心包过期（已定位）

环境准备成功后，向导调用 `restart-core` 失败（`CORE_UNAVAILABLE`）。检查发现本机
`AppData\Local\AITest\python` 中安装的核心 CLI 仍是旧包，没有 `restart-core` 子命令。
把当前 wheel 安装到该运行时后，受控重启成功。

- 影响：扩展与核心版本不一致时，用户只看到“核心未在限定时间内重启并连接”，无法区分版本不匹配。
- 待办：扩展启动时核对核心版本/入口能力；旧核心应给出明确的“核心版本过旧，请更新”提示。

### 3.3 原生确认窗口不可键盘确认（已修）

Tk 原生窗口把按钮绘制在 canvas 上，Windows UI Automation 只返回窗口壳，不暴露
“确认本次操作/取消”按钮；合成鼠标点击对 Tk 无效；普通回车按设计是取消。
结果：自动化无法确认，人工只能用鼠标点击。

本次在 `native_confirmation.py` 增加显式 `Ctrl+Enter` 确认（`Enter` 仍取消），
避免误按；该快捷键也方便键盘用户。加入后确认窗口可以被键盘确认。

### 3.4 确认断言依据阶段仍不稳定

确认独立预期后，向导继续到“确认断言依据”。该阶段多次出现：

- 面板停留在“正在执行：确认断言依据”，进度停止；
- Windows 上出现 1–2 个 `dispatch --native-confirmation` 进程，但有时没有可见窗口；
- 终止无窗口进程后，面板返回 `CORE_RESULT_UNVERIFIED`；
- “重试本阶段”从“保存项目”重新开始，而不是只重试失败的断言依据确认。

因此本次没有进入计划发布、准备/登记运行、执行、核验、报告、规则和提测阶段。
**不能据此判定全链路可用，也不能评价真实宿主中的整体“好用”。**
