## 修复前实际反例

1. [状态读取反例](state-reader-before.json)：重复 state 将 prepared 覆盖成 rolled_back，或 capturing 覆盖成 sealed，普通读取没有给出阻塞；未知迁移注册表版本也返回无维护原因。纯组件、小文件，不启动第二核心或重测试。
2. [永久引用反例](reference-reader-before.json)：后面的重复摘要字段隐藏前面的永久引用；真实 reclaim(dry_run=False) 在一次性临时目录删除了应保留的暂存字节。没有操作产品用户数据目录。
3. [计划身份反例](checkpoint-origin-before.json)：当前 prepared 检查点与成功登记来自两份不同计划，仍返回无维护原因；缺准确关联不得证明原步骤已经结束。

## 修复及范围

迁移材料、采集状态和永久 JSON/JSONL 引用统一使用既有 decode_json：只接受严格 UTF-8、唯一字段、有限 JSON 数字和可表示的 Unicode，不另造解析口径。注册表/计划核对已有 1.0 schema，计划材料同时核对准确 plan_id；拒绝时不改历史、不重放迁移、不删除材料。prepared 只有对应同一准确计划的成功登记才能解除维护原因；其他计划或缺身份继续要求恢复。

维护审计的重复字段行不投影为 verified 备份事实，原审计字节保留。错误读取继续阻塞普通写；三种 LocalAPI 接缝检查证明 doctor 不受该写闸门影响，不能据此声称损坏注册表下真实核心启动/恢复通过。

没有修改公开字段、DTO、Schema、枚举或有效记录语义；CORE 1.85、AB 1.45 与 reviewing/partial/not_run 保持。完整历史闭包、独立迁移备份位置、新 generation 切换、真实核心重启/宿主/物理掉电仍未闭合。
