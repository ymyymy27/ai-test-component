两次修复各自的作用：

1. **3 项真失败**——查清是**测试写错**（载荷不自洽 / 选错被测对象 / 断言否定了 fixture 自带数据），用临时工作树证明它们在 `fix` 合并前就失败、与本次改动和合并无关，已按原意修正（断言强度未降低）。

## 3 这条结论的意义

首次全量暴露了一个**会让验证失效**的问题：并发/满负荷下的假失败与真失败混在一起，容易被笼统归为"噪声"而放过真回归（`AGENTS.md` 第 5.5.4 条正是要防这件事）。本次修复后：

- **噪声源已消除**：同一条命令、同一台机器、同样的满负荷条件下，失败数从 9 降到 0；
- 因此**今后全量跑若再出现失败，应先当作真失败处理**，而不是先怀疑负载。
