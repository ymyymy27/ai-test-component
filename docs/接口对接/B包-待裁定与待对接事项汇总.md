## 2 三个端口的定义归属与提交方式

### 2.1 冲突事实

《01-项目与计划》第 9 节"本册的端口"表列出：`ModelProvider`、`SourceSnapshotPort`、`SourceControlPort`、`Clock`。
即这三个端口按原文是**B 自己的端口定义**（`Clock` 另见下）。

但 `application/ports.py` 的所有者按现行约定是 A，于是形成**定义权与提交权分离**：
B 有定义权却无提交权，而 A 至今未提供任何签名。

**仓库实测（`develop` = `8a72b0e`）**：`application/ports.py`（3958 字节）中
`WorkspaceUnitOfWork`、`RecordRepository`、`SourceSnapshotPort`、`SourceControlPort`、
`ModelProvider`、`ProjectionPort`、`SecretPort` **全部只有文档字符串，没有方法签名**；
有签名的只有 `Clock`（A）与 C 的 `EvidenceObjectStore` / `ExecutionPort` / `Spool*` / `VerificationPort`。

### 2.2 两处口径重复（需一并明确）

| 端口 | 《01》第 9 节 | 《04》第 9 节 | 问题 |
| --- | --- | --- | --- |
| `Clock` | 列出 | 列出 | **同一端口被两份分册同时列为本册端口** |
| `ProjectionPort` | 正文指定 B 为使用者，**表内未列** | 未列 | **归属无原文可依** |

### 2.3 三选一

| 选项 | 做法 | 影响 |
| --- | --- | --- |
| **甲（B 推荐）** | 端口定义以 `B-A` 第 8 节草案为准，**由 B 在自己的 PR 内、按"只追加本包段落、不重排他人段落"的约定加入 `application/ports.py`**，PR 说明中注明并请 A 事后复核 | 与 C 已有做法一致（C 已改过两次该文件）；不重排则合并冲突面小；**需先修改 B 包 AI 规则第 2 节**（该规则现禁止 B 修改该文件），属规则变更，须批准 |
| 乙 | 维持现状：B 只提需求，等 A 加入 | 零风险，但 A 缺席期间 B 的端口类工作全部停在原地（当前 12 项受阻项中的多数） |

## 3 GitHub 只读的获取方式与范围（B-Q04）

### 3.1 现状

需求与架构只规定"GitHub 只读为**可选**能力、绿色状态不能替代业务通过、`plain` 不注册不调用 Git 能力"，
**未规定用什么方式获取**（本地 `git` 元信息 / `gh` CLI / HTTPS API），也未规定失败降级口径。
适配器位于 `infrastructure/adapters/source_control.py`（A 的目录）。

### 3.2 B 侧的 4 类信息需求

| # | 信息 | B 的用途 | 缺失时 |
| --- | --- | --- | --- |
| 1 | 本地 Git 元信息（仓库标识、分支、基准提交） | 建立 `git` 形态绑定的基准 | 降级为"无远端信息"，不阻塞 |
| 2 | 工作区相对基准的新增/修改/删除清单 | 快照差异摘要、变更影响与回归范围（FR03） | 保留未知，不用其他字段冒充 |
| 3 | 远端落后/领先提交 | 提示"依据可能已过期" | **不阻塞任何本地运行** |
| 4 | 远端已有检查状态（CI 结果） | 仅供报告**分开展示** | 标注"未获取"，**不得默认通过** |

### 3.3 请确认

1. 获取方式（B 建议：本地元信息优先走 `git`，远端走 HTTPS，**不依赖 `gh` CLI 是否安装**）；
2. 第 3、4 类是否纳入一期范围（若纳入，需要适配器返回结构以便 B 消费）；
3. 失败降级口径（B 建议：远端不可用与本地 Git 不可用**分开报告**）。
