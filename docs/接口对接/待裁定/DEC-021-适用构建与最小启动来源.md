# DEC-021 适用构建与最小启动的来源与判定

2026-11-04；**已确认并实现，待真实验收**。影响：CORE-001、CD-001、AB-001、A-08、B-04、D-02、P1-FR08/P1-AC13。

## 0. 已确认决定（2026-11-04）

1. **显式登记**：在 `PreparedRun.ExecutionSourceBinding` 增加可选 `source_checks`，构建/启动命令、超时和就绪判据显式登记；核心不猜命令。
2. **最小启动范围**：`MINIMAL_START` 仅 `python-service` 必需；`python-library` 默认 `not_applicable`。
3. **缺登记处理**：模板要求但未登记命令时，准备阶段返回 `BLOCKED`（`source_check_plan_unregistered`），不保存为可执行准备。
4. **构建安全**：argv 无 shell、cwd 固定 worktree、默认拒绝出站网络、产物只写临时目录、结束回收进程树。

## 1. 问题

`SourceCheckType` 已有 `APPLICABLE_BUILD` 与 `MINIMAL_START`，但默认来源 provider 只实现 `SYNTAX` 与 `LOAD`；`bootstrap.py:646` 明确写明二者需要显式构建配置与最小启动来源，合同尚未冻结字段，因此本轮前不实现，L1 不能声称完整通过。

内置模板已给出适用性：

- `python-library`：L1 语法与加载；最小启动不适用，库/纯函数不常驻运行。
- `python-service`：L1 构建/加载/最小启动；仅适用于常驻服务或带启动入口的项目。
- 其他模板不套用 Python 构建/启动检查。

缺的是**来源字段**和**判定口径**，不是枚举或模板说明。

## 2. 建议冻结的语义

### 2.1 适用性

| 模板/项目 | `APPLICABLE_BUILD` | `MINIMAL_START` |
| --- | --- | --- |
| `python-library` | 默认 `not_applicable`，除非用户显式登记构建配置 | 默认 `not_applicable` |
| `python-service` | `required`；未登记不得判通过 | `required`；未登记不得判通过 |
| 其他模板 | `not_applicable` | `not_applicable` |

“无法判断”只能 `UNKNOWN`，不得由核心代判 `not_applicable`。

### 2.2 来源：在 `PreparedRun.ExecutionSourceBinding` 增加可选 `source_checks`

冻结形状：

```json
{
  "source_checks": {
    "build": {
      "applicability": "required",
      "descriptor": "pyproject.toml",
      "command": ["python", "-m", "build", "--no-isolation"],
      "timeout_ms": 120000
    },
    "minimal_start": {
      "applicability": "required",
      "command": ["python", "-m", "app"],
      "ready_when": "stdout_contains:ready",
      "timeout_ms": 10000
    }
  }
}
```

约束：

- `command` 为 argv 数组，不经过 shell；`cwd` 固定为冻结 workdir。
- 只允许冻结环境中的解释器/入口；不得使用用户 `PYTHONPATH`、用户 site 或任意绝对路径。
- 默认拒绝出站网络（连接、DNS、UDP 发送）；本地监听允许，否则最小启动的真实服务无法监听端口。构建需要出站网络时必须另行显式登记并走环境/凭据合同。
- 运行器把 `HOME`/`TMP`/缓存指向临时目录；登记命令必须把构建产物写到临时输出目录。运行器不阻止命令在冻结 workdir 内写文件，这属于登记命令的约束，需在真实服务样例中核对。启动检查结束必须回收进程树。
- `ready_when` 只支持有限、可机械核对的判据（如 stdout 行匹配、端口监听）；不支持自然语言。
- 未登记 `required` 项时，准备阶段阻塞或给出明确缺口，不能到执行期猜命令。

### 2.3 判定

- **构建**：退出码 0 且输出/产物符合冻结判据 → `VERIFIED`；非零退出按失败分类区分源码/依赖/环境/工具；超时/无法启动 → `BLOCKED`/`UNKNOWN`。
- **最小启动**：在超时内观察到就绪判据，随后受控停止并确认进程退出 → `VERIFIED`；提前退出、超时、无就绪观察 → `UNKNOWN`/`BLOCKED`，不得用“进程存在”代替就绪。
- 每项检查产生独立 `SourceCheckStatus`（持久化为 `SourceCheckStatusFact`），`check_type` 使用既有枚举；失败分类写入既有 `FailureClass`，不新增同义枚举。
- 任一必需检查未通过，L1 不得整体 `VERIFIED`；不适用项必须带原因，不能静默跳过。

### 2.4 证据

至少保存：实际 argv、workdir、解释器 realpath/版本、允许的环境键、原始 stdout/stderr（有界且已脱敏）、退出事实、就绪观察、超时、进程身份和失败分类。证据仍按现有对象仓/证据引用合同保存。

### 2.5 兼容

- 旧 `PreparedRun` 没有 `source_checks`：服务模板要求的两项按 `UNKNOWN` 并带 `source_check_plan_unregistered` 缺口，不追溯升级、不把旧报告改为通过；库/其他已知模板按 `not_applicable` 带原因记录。
- 新增字段为可选；旧记录读取不因缺字段失败。
- 新增检查结果不改变既有 `SYNTAX`/`LOAD` 语义和判定优先级。

## 6. 实现记录（2026-11-04）

- **合同**：`PreparedRun.ExecutionSourceBinding.source_checks` 为可选 `SourceCheckPlans`，含 `build` / `minimal_start` 两条 `SourceCheckPlan`；`applicability` 为 `required / optional / not_applicable`，`not_applicable` 必须带 `reason`；`minimal_start` 适用时必须带机械 `ready_when`；构建命令禁止携带就绪判据。`source_checks` 进入准备请求摘要（`execution_source` 请求侧字段）。
- **准备阻塞**：`python-service` 模板下，任一项未登记或未登记为 `required`，准备返回 `BLOCKED`，阻塞码 `source_check_plan_unregistered`，不落准备意图。`python-library` 与其他已知模板未登记时由核验侧记录 `not_applicable`，不阻塞。
- **执行范围**：构建/最小启动只在 L1 动作的来源核验中实际执行；L2/L3 动作把两项记为 `not_applicable`（`not_an_l1_action`），不重复启动服务，也不把未执行写成通过。
- **执行器**：`ControlledSourceCheckRunner` 使用冻结解释器、argv 无 shell、cwd 限定在冻结 workdir、环境白名单（不含 `PYTHONPATH`/代理/凭据，`HOME`/`USERPROFILE` 也指向临时目录）、临时目录承载产物、Windows Job / POSIX 进程组回收整棵进程树；支持 `python -m <module>` 与 workdir 内脚本，拒绝其他可执行文件、越界脚本与含已知凭据的 argv。
- **判定**：构建退出 0 → `verified`；依赖缺失/环境不可用按 `blocked` 分类；非零源码失败 → `mismatch`；超时 → `blocked`。最小启动必须实际观察 `stdout_contains:` 判据后停止并确认进程树回收；提前退出/无就绪 → `unknown`，不得用进程存在代替就绪。
- **产物隔离边界**：`HOME`/`USERPROFILE`/`TMP`/`TEMP`/`PIP_CACHE_DIR`/`PYTHONPYCACHEPREFIX` 均指向临时目录；运行器不提供文件系统沙箱，登记命令仍可能向冻结 workdir 写 `dist/`、`build/` 等产物，需在真实样例中核对并在登记命令里指定临时输出。
- **证据**：每次检查发布有界（64 KiB/流，对象总上限 192 KiB）的 stdout/stderr 摘要对象，含 argv、cwd、解释器、退出码、超时、就绪观察、停止确认、失败分类和“Python 审计钩子拒绝出站连接，允许本地 bind”说明；对象仓在落盘前再次过滤已知凭据。
- **持久化**：`ExecutionSourceVerification.checks` / `SourceVerificationFact.checks` 保存每个子项的状态、原因与证据引用；只有 `required` 子项失败会降级总来源核验。
- **兼容**：旧 `PreparedRun` 没有 `source_checks` 键时，服务模板要求的两项按 `unknown` 并带 `source_check_plan_unregistered` 缺口；库/其他已知模板按 `template_default_not_applicable` 记录，不追溯升级。
- **验证**：`tests/unit/test_source_check_plans.py`、`tests/unit/test_source_check_commands.py`、`tests/integration/test_source_check_python_service.py`、`tests/contracts` 通过；全量 `tests/unit` + `tests/integration` 5376 passed / 3 skipped；Schema 与合同/功能夹具已重新生成。
- **未验证**：真实 Trae 服务样例、真实业务服务启动/端口占用、掉电与跨机；本机 Windows 外的进程树回收仅有代码路径，未做真实系统验收。
