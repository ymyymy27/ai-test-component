# DEC-006：`Module` 是否增加「模块 ↔ 源码路径」字段

状态：**待裁定**

提出日期：2026-10-01

提出方：B 包（项目与计划）

受影响方：B、C、D

裁定方：袁（项目负责人）

期望裁定日期：待定

影响合同：`BD-001`（B→D 展示口径）；并影响 `BC-001` 的模板与用例关联面

## 1. 待裁定问题

B-04 要求"回归建议不再由调用方提供变更与模块映射，改用真实冻结来源/版本/环境/选定清单做映射和缺口"。
但 `Module` 记录**没有源码路径或文件范围字段**，因此"实际变化的文件 → 受影响的模块"这一步无法推导。

需要确定：是给 `Module` 增加路径范围字段，还是承认"模块映射由调用方提供"为既定口径、
并相应改写 B-04 的完成条件。

## 2. 冲突依据（逐字引用）

| 来源 | 原文 |
| --- | --- |
| `docs/一期工程检查-B包.md` 第 3.2 节 B-04 | "回归建议目前由调用方提供变更与模块映射；源码适配器 dict 尚未转成正式 SourceSnapshot，准备与启动之间无完整漂移核对链" |
| 同上，B-04 完成条件 | "AC03/12/13/25/30；B 用真实冻结来源/版本/环境/选定清单做映射和缺口，C 启动前重新核对" |
| `docs/项目文档/一期/架构文档/01-项目与计划.md` 第 154 行（记录字段表） | \| Module \| 稳定模块ID、名称、职责、接口说明、输入、输出、实现状态、责任人、修订 \| `domain/project/context.py` \| |
| 现行实现 `src/aitest/domain/project/context.py` 的 `Module` 字段 | `module_id` / `project_id` / `name` / `responsibility` / `interface_note` / `inputs` / `outputs` / `implementation_status` / `owner` / `revision` |

架构分册的记录字段表与现行实现**一致**，都没有路径或文件范围；
而 B-04 的完成条件要求从真实来源推导映射。两者对不上。

## 3. 选项与代价

### 选项甲：给 `Module` 增加路径范围字段

- 做法：例如 `source_paths: tuple[str, ...]` 或 `scope_globs`，用于把变化的文件映射到模块。
- 代价：
  - 属领域模型与架构分册记录字段表的变更，需同步《01-项目与计划》第 154 行；
  - 六个内置模板生成的模块元数据要一并补默认值；
  - 已有记录需要兼容口径（旧记录无该字段时的行为要定义）；
  - `BD-001` 的展示面要决定是否呈现该字段。

### 选项乙：维持现状，改写 B-04 的完成条件

- 做法：承认"变更文件 → 模块"的映射由调用方（宿主/面板/用户）提供，
  B 只负责"从模块到影响面"这一段（**这部分已完成**：依赖反向传播改为读真实落盘的依赖图）。
- 代价：
  - B-04 的完成条件需要按新口径重写；
  - 需要说明调用方提供的映射如何被核对，避免它成为无依据的自由输入。

## 4. B 侧倾向（**仅为建议，不作为结论**）

B **不提出倾向**。理由：这不只是 B 的内部实现问题——它决定"回归范围"的输入从哪里来，
涉及 C 的启动核对与 D 的展示，且改动架构分册的记录字段表属于跨分册同步。
裁定方在两条路之间选择时，需要同时考虑一期是否要求"自动推导回归范围"这一产品能力。

## 5. 阻塞影响

- 不裁定则 B-04 第①条无法闭合，检查文档会持续挂账；
- 若选甲而未同步架构分册与模板，会出现"代码有字段、分册没有"的不一致。

## 6. 裁定结论

- **结论：采用选项甲。** `Module` 增加**可选**字段 `source_paths: tuple[str, ...] = ()`，
  用于把变化的文件映射到模块。
- **裁定方式**：项目负责人于 2026-10-01 指示由 B 侧按现有文档证据自行裁定并回写本节。
- 判定日期：2026-10-01
- 确认人：待项目负责人确认（本节已回写，合同同步见下）
- **选甲的理由**：选乙只是把缺口改名——B-04 的完成条件明确要求"不再由调用方提供变更与模块映射"，
  乙做不到；甲把映射并进**项目上下文记录**，使它随项目修订冻结、可复核、可重启读回，
  这才是"从真实来源推导"的前提。
- **安全默认（重要）**：`source_paths` 为空表示"该模块**未登记**源码范围"，
  此时"变化文件 → 模块"仍由调用方提供，**不得**把空解释成"该模块影响所有文件"，
  也不得静默跳过该模块的回归——两种都会伪造完整的影响面。
- **不破坏既有记录**：字段可选且默认空，历史记录与六个内置模板无需迁移。
- 需同步的合同／Schema／夹具／测试：
  - `src/aitest/domain/project/context.py`：`Module` 增字段（含非空项校验与去重）；
  - `src/aitest/application/project/serialization.py`：模块 payload 的往返，
    沿用"未登记时**省略该键**、读取时缺键与 `null` 同等拒绝"的既有约定；
  - `tests/unit/test_binding_serialization.py`：补空/非空两种往返；
  - `docs/项目文档/一期/架构文档/01-项目与计划.md` 第 154 行记录字段表：补 `source_paths`；
  - `BD-001`：需要决定该字段是否在面板呈现（D 侧动作，不阻塞 B 侧实现）。
