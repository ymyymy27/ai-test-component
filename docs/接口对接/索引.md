# 接口对接目录说明

本目录用于存放**跨包**合同文档。依据：组长《一期工程四部分拆分与低对接实施方案》第 6 条——
"每个人负责的部分不同，但也不是完全独立的……A 和 B 需要对接，可以一人出一份接口文档，之后两人讨论出一份合适的接口文档，放在公共目录里"。

## 目的

一期四包之间只通过冻结的合同交换数据。跨包字段一旦各自定义，就会出现两套语义（例如"档位"与"结论上限"混用），
此类不一致无法由单元测试发现，仅在 D 包聚合报告时暴露。

因此约定：跨包字段、枚举与身份标识的语义，必须先在目录内形成双方确认的文档，再行实现。

## 目录约定

| 文件名 | 含义 |
| --- | --- |
| `索引.md` | 本文件 |
| `B-C-*.md` | B 包与 C 包（执行与证据）之间的合同 |
| `B-A-*.md` | B 包与 A 包（核心底座与存储）之间的合同 |
| `B-D-*.md` | B 包与 D 包（判定、报告与入口）之间的合同 |
| `A-C-*.md`、`C-D-*.md` 等 | 其他两两组合，命名规则同上 |

命名规则：`<提出方>-<接收方>-<主题>.md`。中文主题，方便人读（组长第 5 条）。

## 每份文档的固定结构

```markdown
# <主题>

版本 / 日期 / 提出方 / 接收方 / 状态（待确认 | 已确认 | 已冻结）

## 1 目的与依据          —— 引用架构/功能分册的具体章节
## 2 双方现状            —— 逐字引用对方已有代码或文档，不转述
## 3 冲突与缺口清单      —— 表格，每条带编号，便于回复
## 4 建议方案            —— 可执行的具体改动
## 5 待确认问题清单      —— 编号问题，对方可逐条回复
## 6 兼容性影响          —— 会影响哪些现有夹具/测试
## 7 确认记录            —— 双方确认的时间与结论，只在原文基础上追加，不覆盖历史
```

## 处理规则

1. **只追加，不覆盖。** 已确认的内容保留；新结论作为新版本追加，并注明改变了什么。
2. **本目录只记录应当修改的内容**，实际改动由字段所有者执行。
3. **存在分歧时不得各自实现。** 依据仓库根 `AGENTS.md` 第 1.3 条：记录涉及的 FR/AC、两处原文及影响，
   先核对 `docs/项目文档/阅读索引.md` 指定的主责合同，再同步修正，不只在代码里选一种解释。
4. **跨包字段只能由合同所有者修改 Schema/夹具**，并做兼容检查（实施方案第 3 节）。
