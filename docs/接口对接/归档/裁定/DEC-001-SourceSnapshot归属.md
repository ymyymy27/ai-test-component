# DEC-001：`SourceSnapshot` 归属

状态：**已裁定并同步，归档记录**

提出日期：2026-09-28

整理日期：2026-09-30

提出方：B 包（项目与计划）

受影响方：A、B、C

裁定方：袁（项目负责人）

影响合同：`AB-001`、`AC-001`、`BC-001`

## 1. 待裁定问题

`SourceSnapshot` 的建立时机、内容身份、排除规则和有效性判断属于 B 的项目与计划职责，
现有领域对象却位于 C 的 `domain/execution/sources.py`；底层固定、复取和物化能力又需要 A 的适配器与存储能力。
需要确定规则定义、领域模型位置和端口实现各自的唯一责任方，避免出现两套源码身份。

## 2. 冲突依据

| 来源 | 当前含义 |
| --- | --- |
| 一期架构《01-项目与计划》第 1、2、9 节及 P1-FR01 | B 负责快照建立时机、内容身份、排除规则，并使用 `SourceSnapshotPort` |
| 一期架构《01-项目与计划》第 7 节 | `SourceSnapshot` 主责模块写为 `domain/execution/sources.py` |
| 一期架构《02-执行与证据》 | `sources.py` 为项目与执行共用 |
| 当前代码 | C 已在 `domain/execution/sources.py` 定义 `SourceFile` 与 `SourceSnapshot` |

现有对象已覆盖逐文件相对路径、大小和摘要，但相较项目与计划分册仍缺少 Git/Plain 身份、工作目录范围、
排除规则、差异摘要、内容引用、创建时间、复取依赖与可复取范围等合同字段。

## 3. 备选方案

| 选项 | 做法 | 影响 |
| --- | --- | --- |
| 甲（B 推荐，A/C 已表示支持） | 规则定义归 B；领域类继续位于 C 的 `domain/execution/sources.py`；C 按冻结字段补齐模型；A 实现端口适配 | 不搬迁现有类，保持一套模型；必须明确跨包修改和评审顺序 |
| 乙 | 模型、规则整体归 B | 需要移动 C 现有代码、测试和导入，并同步架构模块表 |
| 丙 | 模型、规则整体归 C，B 只传选择条件 | 会削弱 P1-FR01 对 B 的源码身份职责，需要修改主责合同 |

## 4. 已有意见

- B 推荐选项甲。
- A 的 `AB-001/review-A.md` 支持选项甲，但要求裁定后同步修正文档歧义。
- C 已在 `BC-001/contract.md` 第 14 节接受“规则归 B、类位置留 C、C 消费冻结事实”的分工。
- 上述意见不等于最终裁定；当前仍缺有权裁定人的明确结论。

## 5. 裁定前约束

- B 不新建第二套 `SourceSnapshot`。
- C 不自行改变内容身份、有效性和重新准备规则。
- Git 形态尚缺的身份字段不以临时字段冒充。
- 任何新增字段先通过受影响合同确认，不能只改代码。

## 6. 需要裁定的结论

1. 选择甲、乙或丙；若为其他方案，写明规则、模型、端口和适配器的唯一归属。
2. 指定字段补齐的负责方和评审方。
3. 指定主责分册需要同步修改的章节。
4. 指定实施顺序及兼容既有 `PreparedRun` / `ExecutionFacts` 的方式。

## 7. 裁定记录

裁定：**采用方案甲。** `SourceSnapshot` 的建立时机、`purpose`、范围与依赖闭包、排除规则、内容身份算法、Git/plain 身份、复取范围以及失效/重新准备判据由 B 主责；`SourceSnapshot` / `SourceFile` 类继续唯一位于 `domain/execution/sources.py`，C 不复制模型并只负责实际执行来源核对；A 负责 `SourceSnapshotPort`、物化与持久化适配。
