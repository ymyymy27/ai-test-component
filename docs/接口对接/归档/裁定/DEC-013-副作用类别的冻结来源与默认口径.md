# DEC-013 副作用类别的冻结来源与默认口径

- 状态：**已裁定并归档**（2026-10-09，负责人授权代决；未涉及字段改名或 Schema 变更）
- 涉及合同：[AB-001 端口与保存](../../进行中/AB-001-端口与保存/contract.md)
- 主责位置核对：执行请求的组成见 `docs/项目文档/一期/架构文档/02-执行与证据.md` 第 7 节（`ExecutionRequest` 含副作用类别）；执行来源与物化边界见 `docs/项目文档/一期/架构文档/01-项目与计划.md` 第 12 节。两处均要求"动作授权与实际执行是不同事实"，但**未定义副作用类别由哪个冻结事实提供**。

## 1. 事实与问题

`ExecutionRequest.side_effect_class` 与 `Attempt.side_effect_class` 是领域既有必填字段（取值：`read_only` / `idempotent_write` / `non_idempotent_write` / `unknown`），但现行一期分册与 `AB-001` 都没有规定它的冻结来源：

- 计划/步骤记录里没有该字段；
- 冻结的注册入口 `RegisteredEntryRef` 只有 `entry_id/adapter_kind/entrypoint/arguments`；
- 冻结环境事实 `EnvironmentResolutionFact` 与该类别无关。

因此生产解析器（`application/execution/action_resolver.py`）无法从冻结数据推出它，若自行按适配器类型猜测，等于**在代码里新造业务口径**——违反"字段、状态、时序和验收预期以现行分册为准"与"未知不得解释为安全/通过"。

## 2. 裁定（方案 B：先严后补）

1. **默认口径**：在计划/步骤合同冻结该字段之前，装配一律取 `SideEffectClass.UNKNOWN`（**最严**取值），实现为 `default_side_effect_class`；
2. **禁止的推断**：不得由 `adapter_kind`、命令名、参数或幂等开关反推"只读/幂等"，也不得因为缺该字段而放行受控确认；
3. **行为后果（接受）**：默认装配下所有动作按"未知副作用"处理——不自动重放，受控确认照常要求。这是**更严**而非更松，与"未知副作用不自动重放"一致；
4. **后续唯一改动点**：若计划/步骤合同新增并冻结该类别的字段，只需把装配从 `default_side_effect_class` 改为读取该字段（`build_saved_action_resolver` 一处），解析器与领域对象无需改动；
5. **登记**：结论写入 `AB-001`（1.38 条目）与本记录；`待裁定/` 不保留待决项。

## 3. 影响与迁移

- 字段、枚举、生成 Schema、已保存材料与 D 侧消费**均不变**；
- 默认装配行为：默认动作按 `unknown` 处理（见上第 3 点）；
- 证据：[test_action_resolver.py](../../../../tests/unit/test_action_resolver.py) 以 `test_default_side_effect_class_is_unknown_not_read_only` 固定"绝不默认成只读"。
