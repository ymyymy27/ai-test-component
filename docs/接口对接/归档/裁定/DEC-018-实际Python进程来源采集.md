# DEC-018 实际 Python 进程来源采集

2026-10-15：用户已授权技术取舍；已裁定并回写接口合同，实现已落地；组件回归及真实验收分别登记。

依据一期架构01第12节，启动前探针不证明实际业务进程来源。为普通 Python 文件入口增加 `python-script/1` 采集策略：策略与固定文件摘要进入原动作请求、授权摘要；执行适配器使用隔离 Python 引导器，保留业务脚本及参数，在同一个受控进程内执行并观察代码加载。引导器版本属于策略，不把应用 stdout 当作来源证据。

通过专用继承匿名管道传递来源元数据；不监听端口、不把过滤前输出落盘。观察绑定 Attempt、原进程出生身份、入口、解释器和实际执行代码。项目文件按冻结摘要与实际代码对象双重比对；不以文件存在或退出码代替来源核验。策略不承诺防御恶意同用户进程篡改解释器。

未声明动态代码、外部项目代码、自定义不透明加载、子进程执行、采集不完整或脱敏导致证据不完整，均保留缺口。旧动作不增加采集策略，不追溯升格。新观察发布新的执行事实快照；历史准入证据与旧报告保持不变。

新增动作使用 `aitest.resolved-execution-action/1.2`，带来源回执的采集结果使用 `aitest.execution-collection/1.1`；旧版本保持原形状读取，不补造来源事实。首次登记运行时，依据冻结步骤正文摘要及期望值生成唯一断言引用，将独立核验接入报告生产者；引用存在不代表依据已确认或断言通过。
