## 1. 待裁定问题

需求和架构只规定 GitHub 是可选只读能力、绿色状态不能替代业务通过、`plain` 项目不注册也不调用 Git 能力，
但没有确定获取方式、一期信息范围以及本地 Git 与远端 GitHub 分别失败时的降级行为。

## 2. 信息需求

| # | 信息 | 用途 | 缺失时行为 |
| --- | --- | --- | --- |
| 1 | 本地仓库标识、分支、基准提交 | 建立 Git 绑定基准 | 明确标记本地 Git 信息不可用，不伪造远端状态 |
| 2 | 相对基准的新增、修改、删除清单 | 快照差异和回归影响 | 保留未知，不用 `mtime` 或其他字段冒充内容结论 |
| 3 | 远端领先/落后提交 | 提示依据可能过期 | 不阻塞本地运行 |
| 4 | 远端 CI/检查状态 | 报告分开展示 | 标记未获取，不默认通过，也不参与业务判定 |

## 3. 当前意见

- B 建议本地信息优先调用本地 `git`，远端信息通过 HTTPS 获取，不依赖 `gh` CLI 是否安装。
- A 建议第 1、2 类纳入一期；第 3、4 类作为可选能力，是否一期实现等待裁定。
- A、B 对以下硬约束没有分歧：`plain` 不调用 Git；绿色状态不替代业务通过；凭据通过 `SecretPort`，不进入配置、日志、面板、导出或上传材料。

## 4. 需要裁定的结论

1. 第 1—4 类信息哪些属于一期必交付、哪些属于可选或后续能力。
2. 本地 Git 的调用方式和最低版本要求。
3. 远端是否固定使用 HTTPS API，以及认证引用如何通过 `SecretPort` 传递。
4. 本地 Git 不可用、远端不可用、未认证、限流和网络失败的独立错误状态。
5. 哪些状态只用于展示，哪些会阻塞准备；任何远端状态都不得直接产生业务通过。

## 5. 裁定前约束

- 本地能力不得因 GitHub 不可用而整体失效。
- `plain` 项目不得出现仓库、分支、提交、远端字段，即使显示为空或“未知”也不允许。
- 未获取 CI 状态不等于 CI 通过。
- 不把 GitHub 凭据正文写入合同、配置、日志、诊断、夹具或证据。

## 6. 裁定记录

裁定：本地仓库标识/分支/基准提交及相对基准的新增、修改、删除清单属于一期 `git` 形态必需能力；远端领先/落后及远端检查状态属于一期可选 GitHub 能力，不阻塞本地闭环。`plain` 完全不注册 Git 能力。

获取与降级：本地使用受控 `git` CLI，并按所需只读命令做能力探测，不在缺乏验证证据时冻结最低版本；GitHub 远端统一走 HTTPS API，不依赖 `gh` CLI，认证引用经 GitHub 用途 `SecretPort`。本地 Git 不可用会阻塞依赖 Git 身份的固定/准备且不得静默转成 `plain`；远端未配置、未认证、限流、网络失败和服务不可用分别记录，只降级远端状态。远端状态只展示，永不直接产生 L1 或业务通过。
