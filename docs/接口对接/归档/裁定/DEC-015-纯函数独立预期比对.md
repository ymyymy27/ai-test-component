# DEC-015：纯函数独立预期比对

2026-10-15，用户授权本次代理依据项目文档代为技术裁定；不代表其他人员签名或真实环境验收。

依据：一期《能力与模板清单》§6 原文「首发支持已配置只读HTTP查询及纯函数独立预期比对」；§4 原文「python-library的纯函数没有持久化时，数据库核验条目不适用但独立预期比对仍适用」。涉及 FR10、AC30，CORE/BC/CD。

裁定：增加严格依据编码 `aitest.pure-function-basis/1`，仅含 schema_version 和非空 expected_facts 对象。预期只读准确 StepRevisionRef 对应的 Case；实际值读取当前 Attempt 完整、未过滤、校验摘要后的永久 stdout JSON 对象。沿用既有共同字段比较与保存/重启回读用例，不执行第二次函数、不发起 HTTP、不索要数据库或模型凭据。

核验方法固定为 `<project_id>:pure-function-stdout`，对象固定为 Attempt ID，目标固定为 `attempt:<attempt_id>`；保留实际输出证据引用。仅供纯函数结果比对，不能替代有持久副作用业务的独立回读；核验不证明无副作用，也不单独授予有效验证/通过。HTTP 登记保留该方法名，禁止占用。异常/截断/重复键/非对象/过期/过滤材料阻塞，不以退出码或自报通过代替结果。

其他方案：复用 HTTP 服务会增加纯函数不需要的依赖；重跑被测函数会改变执行身份且不能产生独立预期；均不采用。首次实现范围为输出对象的顶层预期字段（可包含 JSON 嵌套值），使用领域既有严格 JSON 比较。
