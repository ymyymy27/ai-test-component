# 接口对接目录协作规则

本文件适用于 `docs/接口对接/` 及其全部子目录。进入本目录工作前，必须先读同目录 `README.md`，再读仓库根 `AGENTS.md`、`docs/项目文档/阅读索引.md` 及任务涉及的现行主责分册。

## 1. 唯一入口

- `README.md` 是目录规则、状态定义和总台账的唯一入口。
- `contract.md` 是一个对接主题的唯一现行合同正文。
- 评审意见、交付说明、修改日志、聊天记录和 `归档/` 材料不得覆盖现行合同。
- 相同字段、枚举、身份、状态或公式不得在多个合同中另起定义；引用主责来源和合同版本。

## 2. 放置规则

- 草案、评审中、待确认和接入中的合同统一放在 `进行中/<合同编号-主题>/`，不再按双方增加目录层级。
- 同时面向三个及以上包的基础合同使用 `CORE-*` 编号，也直接放在 `进行中/`。
- 只有满足 `README.md`“移入已完成的条件”的整个主题目录才能进入 `已完成/`。
- 跨多个合同的冲突一项一文件放入 `待裁定/DEC-*.md`；项目文档只读、不在本目录工作中修改，裁定结论及项目文档依据同步到接口合同后移入 `归档/裁定/`，未完成实现转记到合同状态和下一动作。
- 已裁定、失效或被替代材料放入 `归档/`，并在文件顶部标明不再生效及现行入口。
- 不在 `docs/接口对接/` 根目录散放业务合同。

## 3. 命名和责任

- 使用稳定合同编号，如 `AB-001`、`CD-001`、`CORE-001`；目录名不使用成员姓名。
- 双方编号不表示方向，提供方和消费方写在合同元数据中。
- 每个能独立确认、独立变更或拥有不同阻塞项的主题使用独立合同目录。
- 每项待确认问题必须有编号、责任方、下一动作和阻塞影响。

## 4. 状态不得混写

每份合同必须分别维护：

- `contract_status`；
- `provider_implementation`；
- `consumer_implementation`；
- `verification_status`；
- `last_verified_commit`；
- `blockers`、`next_owner`、`next_action`。

禁止用一个“已完成”同时表示文档确认、提供方实现、消费方接入和真实环境验收。提供方完成不等于双方对接完成；契约或单元测试通过不等于真实 Trae、Python 3.13、文件系统故障恢复或平台对拍通过。

## 5. 修改流程

1. 从 `README.md` 总台账找到现行合同和主责分册。
2. 检查工作区现有改动，保留他人的未提交成果。
3. 先改 `contract.md` 或新建待裁定记录，再修改代码、Schema、夹具和消费方。
4. 双方确认必须回写合同；聊天和单方评审不能作为最终确认。
5. 已冻结合同发生变更时更新版本、影响和迁移说明，破坏性变更提升主版本。
6. 文件移动或重命名后，全仓更新文档、代码注释和测试中的路径引用。
7. 同步更新 `README.md` 总台账和对应修改日志。

## 6. 验证要求

- 运行受影响的 Schema、夹具、合同和集成检查。
- 检查本目录 Markdown 本地链接及全仓旧路径残留。
- 运行 `git diff --check`。
- 在交付说明中分别列出已实现、静态/单元/合同检查、真实环境验收和未验证项。
- 失败检查必须如实记录，不能因为与本次改动无关就写成全部通过。

## 7. 禁止事项

- 不按成员姓名新建目录。
- 不创建第二份并行生效的合同正文。
- 不把多个无关裁定问题重新合并成一个汇总文件。
- 不手工编辑生成 Schema 或生成夹具。
- 不把未知状态静默解释为成功、通过、空结果或无需处理。
- 不删除历史确认记录；被替代内容进入归档并指向现行入口。
