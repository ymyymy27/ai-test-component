## 7 2026-10-10 二次复核：纠正的过期结论

1. **"3.11 独有 3 项待查"不成立。** `tests/unit/test_model_policy_approval.py::…[boolean_revision]` 与 `tests/unit/test_execution_start_integrity.py` 的两项，在 **3.13 上同样失败**，与解释器无关。
   - `boolean_revision`：`6951674` 给底座准确身份守卫加了 `type(record.revision) is not int`，`bool` 修订在仓储身份层就被拒，用例层按"非法输入"归一为 `B_INVALID_PARAMETER`，走不到策略来源证明；原断言仍期待 `AWAITING_USER_CONFIRMATION`。产品行为符合**"不以等待确认替代非法输入"**的既定口径（`test_runtime_publication_origin.py` 对同一注入即期待 `ValueError`），因此修的是陈旧断言。
   - 两项启动完整性用例：`f5074d9` 给启动事务加入"同提交检查点引用"后，一次启动在同一事务里落地 **7** 条记录，而断言仍是 `9230929` 写下的 `before + 6`。计数改为常量 `_START_TRANSACTION_RECORDS` 并列出 7 条记录，仍保持精确断言。
2. **根因是"改完没重跑受影响的旧用例"**，不是 Python 版本问题，也不是新的产品缺陷。教训：批次验证必须覆盖被改动路径的**既有**用例，不能只跑新增反例。

## 8 本机环境与可复现边界

- **临时目录**：本机 `TEMP/TMP`、用户目录、各盘根均不可写，`tempfile.gettempdir()` 会回退到检出目录，使 pytest 临时根落在 Git 工作树内。`.gitignore` 已覆盖 `.runtime/` 与 `/pytest-of-*/`；仍应优先把 `TEMP/TMP` 指向工作区内后再跑真实文件类用例。
- **建议命令**（`pyproject.toml` 与锁文件为准）：

  ```powershell
  $env:TEMP = (Resolve-Path ".runtime\tmp").Path; $env:TMP = $env:TEMP
  .venv/Scripts/python.exe -m ruff check src tests
  .venv/Scripts/python.exe -m mypy
  .venv/Scripts/python.exe -m pytest tests/architecture tests/contracts tests/acceptance tests/unit/test_acceptance_status.py -q
  .runtime/venv311/Scripts/python.exe -m pytest tests/unit/test_execution_start_integrity.py -q   # 3.11 冒烟
  ```
- 真实文件事务类用例很慢；按修改影响**分块**跑并保留每块日志，不要以"未跑完"充当通过。
