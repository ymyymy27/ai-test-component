三期仅P3-FR01和P3-FR02，验收P3-AC01—08。平台审核不保留为插件功能编号，不占用插件验收。插件不接收别人的运行、不保存共享视图、不展示跨账号审核、不提供宿主子应用。

## 1 P3-FR01 账号与项目关联

输入平台会话、账号/项目接口和可用凭据后端；用户登录、刷新、退出/切换、选参与项目和上传策略。平台维护账号/成员/项目，插件不另建目录。账号身份为精确(issuer,account_id)，显示名非键，account_id不小写化。安全摘要account_key用于目录，不直接拼原始标识作路径。

项目选择必需；仓库仅Git且有平台关联时选择，plain不显示仓库、不被阻塞。PlatformProjectBinding和LocalProjectBinding分别保存，绑定修订冻结目标和策略。本地原始来源不因登录而改写。

并发会话刷新合并；身份改变结束原会话。退出清令牌和本账号临时界面缓存，保留待发送材料；已发请求不可假装撤销，迟到响应只按原账号/绑定/请求核对并存原提交，不显示到新账号。令牌正文仅凭据后端保存，工作空间只引用。

待发送材料脱敏后明文按账号分区，依赖OS用户目录权限，不增加应用层加密；不承诺同一OS用户不同进程间保密。会话不可用只影响上传，不阻断本地。

### 模块职责

> **本册是规划稿。** 平台尚未建设，因此本册只写清"用户看到什么、结果如何流转、边界在哪"，不规定接口实现与部署方式。
>
> 一期与二期的判定口径、状态规则、问题清单与导出字段继续有效；本册只增加协作相关的记录与规则，不重写它们。

## 2 P3-FR02 上传与补交

输入已可靠保存的运行/步骤/尝试/证据/问题/报告及确定策略。上传不含源码正文、GitHub Issue/PR；本地问题记录的脱敏投影属于可上传事实，与GitHub Issue不同。路径/文件名默认全字段及正文均去除，显式策略只能加入允许的路径信息；源码正文始终排除。

先保存本地，再登记候选，身份/目标核实后冻结提交和脱敏字节。Submission固定账号、来源、目标、绑定、Run/Step/Attempt、内容修订、对象upload_digest/大小/类型、投影策略和manifest_hash；原source_digest只本地追溯。回执逐项匹配上传对象，不比原始未脱敏字节。

同运行可产生多个递增内容修订提交；同submission_id永远同目标同内容。传输重试同号同内容复用结果；目标、账号、材料/投影策略或内容变化新建提交；仅发送模式/暂停状态变化按第7节更新许可，不重写提交。原提交查询、补缺优先于重发；绝不调用被测业务重建回执。

发送状态表为界面投影；接收、传输、控制和许可分别保存，技术字段唯一见[上传架构](../架构文档/02-结果上传.md#接收传输与控制字段)。

| 状态 | 含义与动作 |
| --- | --- |
| PENDING | 冻结已保存，未发送 |
| SENDING | 请求已发，等待受控截止 |
| UNKNOWN | 接收结果未知，先查询原号；查询仍有界重试 |
| INCOMPLETE | 已接收部分，按缺失清单补交 |
| ACKNOWLEDGED | 完整回执与账号/项目/修订/清单和每个upload_digest一致 |
| PAUSED | 认证/参与/冲突/失败周期耗尽，待人工处理 |
| ABANDONED | 用户明确放弃该份提交，决定和材料永久保存；再次发送新建关联提交，暂停/关闭同步不属于放弃 |

回执缺对象或未声明完整为INCOMPLETE；错误摘要/修订/归属为冲突PAUSED，不能把部分接收当送达。重登原账号只解除认证障碍，核实同一绑定、暂停原因已解决及发送许可有效后才可恢复PAUSED原提交；ABANDONED不自动恢复，须显式新建关联提交并先查询原号；目标改变不改原号，需新提交关联旧记录。

放弃决定与接收事实独立：放弃后迟到的有效完整回执仍记已送达且保留放弃决定，不恢复自动发送；迟到失败不撤销放弃。

候选只订阅允许的业务记录修订，排除上传自身状态写入；候选与游标同事务持久化，重复扫描按来源记录修订去重。失败/阻塞/取消的运行也保存并按策略进入候选。队列拒绝新提交不回滚本地事实；未登录或离线候选不自动猜账号，稍后由用户关联目标。逻辑待发送量与永久材料物理占用分别统计；放弃停止发送并释放待发送逻辑占用，不删除历史材料。磁盘不能接纳新材料时明确提示，不静默丢弃。

## 4 策略、预览与覆盖

SendPolicy按账号/项目/目标/材料范围保存mode=manual/on_run_end/per_step，默认manual；用户确认自动模式只授权匹配策略的提交，不授权新目标/新类别/未知关键缺口。候选持续保存，发送前按当前策略与冻结提交双重检查；用户执行“关闭自动同步”时撤销当时所有未完成发送许可，停止后续自动网络请求（含补交/查询），在途结果照常记录；之后可对指定提交重新手动确认送达或单次查询。默认manual本身不等于已撤销某次明确手动发送许可。

preview_submission返回冻结投影与包含/排除清单及原因；confirm_submission关联准确submission_id和manifest_hash。首次发送须预览确认，已授权自动模式中同范围无新增关键缺口可继续；关键投影缺口进入PAUSED(reason=projection_review_required)，用户预览并显式确认部分材料后可发送。输入改变产生新提交，不换掉用户已看字节。

EvidenceDeliveryCoverage保存预期业务证据引用、已投影、排除、缺失及原因，与接收状态分开。ACKNOWLEDGED可伴随业务证据缺口；UI并列显示，不自动设平台完整交付标记、不改变本地判定。平台仍禁止源码正文，导出的本地证据包不直接作为绕过投影的上传载荷。

| `ProjectMembership` | 账号引用、平台项目编号、项目名称、参与状态、关联仓库清单、核对时间；缓存只供展示 |

## 7 单份送达许可与自动同步

SendPolicy决定是否为后续候选自动创建发送许可；SubmissionDeliveryGrant决定一份冻结提交能否完成送达。Grant是既有提交的确认元数据，不增加服务。manual默认不自动启动任何候选，但用户明确“确认发送这份材料并完成送达”可授予该提交的有界恢复许可。

SendPolicy的发送模式/启停修订与材料白名单/投影策略修订分开引用。仅切换manual/on_run_end/per_step或暂停/恢复不改变冻结投影，不强制新submission_id；原提交保留创建时策略来源，新许可引用当前获确认的发送控制修订并核对材料策略仍适用。账号/目标/材料类别或投影规则改变须新提交。

许可绑定submission_id、manifest_hash、账号/目标、投影与适用材料策略修订、当前发送控制修订、确认来源或已批准自动策略来源。只允许这份提交的首次发送、原号查询、确认缺失对象的补交、合同允许的同号同字节重传；不创建新材料、新目标或新业务执行。自动模式首次仍要求预览，关键投影缺口不得由策略自动授权。

| 事件 | 许可与行为 |
| --- | --- |
| 默认manual下手动确认一份提交 | 可按有界失败周期完成该份查询/补交；不自动发送其他候选 |
| 网络断开或核心重启 | 持久许可不扩大、不重置失败次数；会话/参与/目标/策略仍有效才续行，否则暂停 |
| 关闭自动同步 | 改为manual并撤销当时全部未完成许可，停止后续自动发送/查询/补交；在途回执继续登记 |
| 暂停本份/退出/切账号 | 撤销对应许可；原材料保留，重登不自动恢复，需重新确认原提交 |
| 失败周期耗尽 | PAUSED；显式恢复并确认原提交才开新周期，不能仅重启或重登 |
| 内容/目标/账号/投影策略变化 | 新提交和新许可，不扩大或覆盖原许可；当前门禁撤销的类别不得继续发送 |
| 放弃 | 撤销许可，ABANDONED不复活；再次发送按原规则先查原号并显式新建关联提交 |
| 已完整送达 | 许可结束，保留回执；后续对账是单独允许的查询，不无限轮询 |

关闭同步之后，用户仍可手动确认某份提交的新许可，按钮明确包含有界查询/补交；这不会重新开启后续候选自动同步。手动“查询一次”只授权这次只读查询，查询发现缺项不自动补交。暂停/撤销与发请求先在核心按提交串行裁决：撤销后不得登记新发送意图，已登记在途请求尽量停止但不承诺撤回；迟到结果始终核对原归属。

许可恢复除人工来源或批准策略，还须核对暂停原因。认证恢复不解除摘要冲突，重试按钮不绕过projection_review_required；未知或不满足门禁仍暂停。三期人工策略/提交确认沿用一期入口权限，relay不能自造许可。

## 8 停止与放弃的最终决策

暂停本份、关闭同步和退出只撤销许可并保存控制原因；接收事实仍为UNKNOWN/INCOMPLETE/ACKNOWLEDGED等，不重置已收对象。仅明确“放弃这份提交”生成ABANDONED。未放弃原提交可明确重授许可，先查询原号，再只补缺；仅模式变化可复用冻结提交，材料/目标变化新建提交。重登不复活许可、不清零失败次数，查询一次不补交；迟到回执仍记录真实送达。详见上传架构第10节。

## 9 本账号安全预览

列表不显示正文，独立预览显示当前账号Submission的冻结安全投影；打开/分块取对象均由核心核对账号、项目、目标及manifest_hash。切账号使旧预览读取失效并清临时视图，不删除历史材料。预览不等于发送许可，实际发送继续核对同一固定字节；禁止展示原始密钥和原始敏感材料。[账号与归属合同](../架构文档/01-账号与项目关联.md#1-记录与账号键)是权限唯一来源，UI不能自行放行。P3-AC01/07/08覆盖该路径。

## 10 候选扫描与恢复周期

候选只在允许业务提交出现时登记；固定高水位，经通用业务变更稀疏索引读取允许类型，跳过纯上传/诊断尾部。无新增候选不发布纯游标提交。候选与持久游标同事务，队列满/登记失败不越过未保存候选；重启从索引seek并按稳定键去重，索引缺失显式维护，不隐式全历史扫描。

本册所有“失败周期”均包含成功但无接收进展的请求，使用[上传架构第14节](../架构文档/02-结果上传.md#14-传输成功与接收进展)的总轮次及连续无进展计数。没有可信对象或块偏移进展的重复UNKNOWN/INCOMPLETE不清零；经校验的连续确认偏移增长属于真实进展，真实进展也不重置总轮次；耗尽PAUSED，面板展示原因和明确恢复入口，重登不自动续发。发送控制与接收事实保持独立，迟到回执如实保存。

### 分块与候选的实现对齐

分块续传展示可信连续偏移；正常块确认是接收进展，完整对象确认与整个提交送达仍分别核对。一次恢复周期总轮次包括剩余正常块及控制请求，再加有限额外请求额度；不把固定失败重试次数用作大对象的全部正常块数。具体字段、平台能力前置与边界样例唯一见[上传架构第14节](../架构文档/02-结果上传.md#14-传输成功与接收进展)。P3-AC04/07按需求补充场景验收。

候选发现走存储维护的业务变更稀疏索引，按允许业务类型和固定高水位范围读取。普通恢复不得顺序遍历所有上传/诊断尾部；旧库首次索引构建属于显式维护。P3-AC03按需求补充场景验收；不新增Worker、消息队列或独立数据库。
