# 三期设计：账号、发送策略与上传预览

版本：2.6  
更新日期：2026年9月21日  
状态：开发基线，待真实平台与界面验证。

只覆盖P3-FR01/02，沿用本地流程；无共享查询、审核、远程执行或平台宿主。

## 1 账号与策略

设置固定平台账号入口，未登录本地可用；登录不抢走当前测试。平台返回参与项目，plain不要求仓库。绑定显示实际接收方、账号、项目和策略，旧提交目标不可改。

默认人工发送；可显式开启运行结束同步或逐步同步，确认项目/账号/目标/材料范围。关闭自动同步不删除候选或在途事实，撤销当时未完成许可并停止后续自动发送/补交/查询；用户仍可查询一次或重新确认单份送达。账号/目标/材料范围变化重新确认。

## 2 列表与冻结预览

```text
账号：平台返回账号    项目：工单系统
发送方式：人工发送 [修改策略]
候选3项 [选择并预览]
当前提交：已送达
业务证据：有上传缺口（截图1项未包含） [查看原因]
[查看提交] [管理账号]
```

候选生成不等于网络发送。列表只显示摘要、运行/修订、目标、状态、原因；独立预览展示冻结的安全投影、包含/排除原因、范围与接收方，不展示原始密钥。确认绑定这份manifest_hash，修改材料产生新提交，不在发送时换最新原文。

自动模式首次仍预览确认；同批准范围无新增关键缺口可继续。关键材料无法安全投影则暂停并引导预览，用户知悉缺口后可按合同发送部分材料，不宣称证据齐全。源码正文禁传，路径默认关闭；模型策略不改变平台规则。

## 3 状态动作

| 状态 | 主动作 | 边界 |
| --- | --- | --- |
| 待关联 | 选择账号/目标 | 不猜归属 |
| 待确认/投影缺口 | 预览并确认 | 只看冻结脱敏字节 |
| 待发送 | 发送已确认提交 | 人工或明确自动策略 |
| 结果未知 | 查询原提交 | 不重跑被测业务 |
| 部分接收 | 补交缺失 | 不重新执行 |
| 已暂停 | 处理具体原因 | 认证、冲突、投影分别导航 |
| 已放弃 | 查看接收情况 | 不由登录复活；重发需显式新关联提交并先查原号 |
| 已送达 | 查看回执/覆盖 | 不代表业务通过或原证据齐全 |

放弃只停止自动发送、材料永久保存；迟到完整回执显示已送达并保留曾放弃决定。逻辑队列与磁盘占用分开，放弃不释放永久材料。新报告修订提示未上传，旧回执保留。

退出清当前账号视图/令牌，迟到回执只更新原提交。平台接口未配置明确不可用；无平台不影响本地，存储不可写按本地规则处理。项目/提交链接经核实后在平台打开，不复刻审核。

## 4 验收

P3-AC01—08覆盖账号、恢复、放弃、发送策略、预览、已送达但有证据缺口。预览/确认/返回支持键盘，状态配文字和原因，不仅用颜色。

## 5 登录入口与账号字段

三期设置中固定显示“平台账号”，未登录仍可进入；上传页可显示候选与登录提示，不因未登录隐藏唯一登录入口。登录成功不抢走当前工作台。平台接口未配置时说明所缺配置，本地导航不变。

| 字段 | 显示与操作 | 来源/保护 |
| --- | --- | --- |
| 账号 | 平台返回账号标识及显示名 | 身份为精确issuer/account_id，显示名非键 |
| 会话 | 有效/过期/刷新失败，刷新、退出、切换 | 不显示令牌正文；并发刷新由核心合并 |
| 参与项目 | 平台返回列表与当前选择 | 旧缓存说明未重新核实，不能作为发送权限 |
| 关联仓库 | 仅Git且平台确有关系时显示可选项 | plain整块省略，不要求伪造仓库 |
| 本地绑定 | 本地项目→实际平台项目/接收方 | 与本地目录绑定分开，不修改历史提交 |
| 发送策略 | 人工/运行结束/逐步，账号/项目/目标/类别 | 默认人工，改变范围重新确认 |

## 6 候选、冻结预览与回执页

```text
上传 / 本地项目：工单系统
账号：Alice（平台标识）  目标：项目P1 / 已确认接收方
方式：人工发送                 [管理账号] [修改策略]
-----------------------------------------------------
候选：运行R1、报告修订3、尚未冻结提交
操作区：[选择并预览]
-----------------------------------------------------
冻结预览：提交S1 / 报告修订3
包含：运行事实、报告、日志投影
排除：截图1项，无法安全去除源码；业务证据有缺口
路径/文件名：不发送；源码正文：不发送
范围与接收方：本次固定值
操作区：[确认发送并完成本份送达] [返回]
-----------------------------------------------------
回执：清单已全部接收
接收状态：已送达    业务证据：仍缺截图1项
操作区：[查看回执] [查看缺口]
```

预览只读已冻结安全字节，不展示原始敏感材料。返回不发送，确认记录绑定准确提交及清单摘要；原记录更新后仍发送原预览，用户要新内容则新建提交。首次自动策略也要明确预览确认；新目标/类别或关键缺口再次核对。不会出现“登录即同步全部历史”的隐含行为。

列表行显示本地来源、Run/报告修订、目标、接收状态、控制状态、覆盖缺口及原因；正文和附件通过明确详情按需查看。账号切换后不把旧账号材料当当前待发；可保留原归属摘要提示重登处理，不跨账号打开正文或重绑旧提交。

## 7 状态文案、空态与恢复

| 情形 | 界面呈现 | 可用操作 |
| --- | --- | --- |
| 无候选 | 尚无可上传的已保存结果 | 返回本地检查 |
| 候选未关联 | 需要确认账号和目标 | 选择目标，不自动猜测 |
| 结果未知 | 接收结果尚未确定 | 查询原提交，不能直接执行业务重建 |
| 部分接收 | 列缺失对象与实际接收范围 | 按缺失清单补交 |
| 摘要/归属冲突 | 具体冲突对象及原因 | 查看原回执，处理后新建关联提交 |
| 投影需复核 | 列关键材料排除及影响 | 预览并明确确认部分材料，或停止发送 |
| 同步关闭 | 当时未完成许可已撤销，在途结果仍可能返回 | 查询一次，或预览并重新确认单份送达 |
| 已放弃 | 自动发送已停止，永久材料仍在 | 查看接收情况；再次发送按新关联提交处理 |
| 放弃后收到完整回执 | 已送达，同时显示曾放弃决定 | 查看回执，不自动恢复队列 |
| 逻辑队列满 | 新提交待处理，候选仍保留 | 补交或明确放弃；不承诺释放永久磁盘占用 |
| 平台不可用 | 仅上传不可用及具体原因 | 本地检查/报告/导出继续 |

放弃确认说明停止自动发送、不会删除材料，也不能撤回平台已接收内容。关闭同步同样不能撤销已发请求。新报告修订提示该修订尚未上传，旧版送达状态不覆盖新版。P3-AC01—08验证上述路径，键盘/焦点与一期保持一致；无共享查询、审核按钮或平台接收管理界面。

## 8 手动送达与停止说明（2.5）

确认按钮旁明确：“仅发送本份冻结材料；允许有界查询、补交和重启恢复，不发送其他候选。”显示接收方、材料摘要、失败周期和停止入口；默认manual不自动选择或发送历史候选。单独“查询一次”不授权补交。

“关闭自动同步”说明会停止后续候选自动启动，并撤销当时未完成送达许可，包含查询/补交；仍可能收到在途回执。之后手动发送须重新确认单份许可，不重新开启其他候选同步。“暂停本份”、退出/切账号同样撤销相关许可；重登显示“会话已恢复，仍待确认送达”，不直接显示自动恢复中。失败耗尽需显式恢复，摘要冲突/投影复核不能用同一重试按钮跳过。

提交详情分别显示SendPolicy模式、当前单份许可active/revoked/completed、接收状态与覆盖缺口。曾关闭同步后新授的单份许可显示其新确认来源，避免“同步关闭”却无说明仍发送。人工确认沿一期受控交互完成，MCP不能确认策略或提交。

## 9 暂停与放弃的不同入口（2.6）

“暂停本份”保留原提交，显示“已暂停，可重新确认后继续”；“关闭自动同步”说明暂停范围并撤销当时未完成许可；两者均不显示已放弃。“放弃提交”是单独的明确确认动作，说明再次发送须新建关联提交，不能用一个“停止”按钮兼任三种语义。

恢复原提交时展示最近接收事实：未知先查询、部分接收只补缺、已送达只查看回执。暂停/放弃后迟到完整回执仍显示“已送达，同时保留原控制决定”，不能丢失真实接收信息。
