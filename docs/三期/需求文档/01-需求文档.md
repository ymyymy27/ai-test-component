> **本册是规划稿，且范围已收敛（2026-09-21 定调）：平台侧一概不管，插件只做到"能把本地结果上传到平台"。** 平台的账号体系、接收端实现、共享查询、跨账号审核、宿主加载与运维全部由平台项目负责，**不在插件交付范围**；插件侧只保证：拿到可用会话后，能把已保存的结果与证据**可靠地提交上去**（含重试、补交与回执核对），并在平台不可用时完全不影响本地能力。三期不提供独立服务端，插件不做服务端部署。

## 1 目标

让本地已经产生的测试结果可以**上传到平台**，其余协作能力交给平台：

- 用平台给定的账号标识把结果归到项目；插件本地不保存第二份成员目录。
- 只上传一期已经产生的事实（运行、证据、报告），不上传代码正文、GitHub Issue、PR。
- 平台不可用、接口未就绪或上传失败都不影响本地测试与本地结论。

## 2 范围

### 2.1 三期覆盖

插件侧只做**上传**；平台侧能力不设计、不实现、不验收：

| 归属 | 功能 | 说明 |
| --- | --- | --- |
| **插件（本期交付）** | P3-FR01 上传账号与项目关联 | 使用平台会话、选择参与项目与目标、绑定本地项目（只读平台数据） |
| **插件（本期交付）** | P3-FR02 结果上传 | 提交、回执、失败与断连后的重试和补交、离线待发送队列 |
| **平台（不编号、不验收）** | 审核与共享查询 | 插件不实现接收服务、审核、共享投影、宿主或远程 MCP |

**平台实现由平台负责**：插件只根据商定上传合同发送，不提供可加载子应用或接收端；接口未确定不阻塞本地能力。

三期验收场景 P3-AC01—P3-AC08，共 8 项，全部为**插件侧**场景（P3-AC05／P3-AC06 已按新范围改写为"上传不改变本地结论"与"平台不可用不影响本地"）。

### 2.2 平台职责与插件职责

| 事项 | 平台 | 插件 |
| --- | --- | --- |
| 账号、项目编号、成员关系 | 提供并维护 | 只读取，不维护第二套 |
| 项目与 GitHub 仓库关联 | 按平台能力提供并维护 | 有关联时读取并选择，普通目录不强制关联 |
| 接收结果、去重、回执 | 提供接口与存储 | 按协议提交、查询、补交 |
| 共享查询与结果展示 | 提供查询与页面 | **不实现**（插件不展示跨账号结论） |
| 跨账号审核与投影 | 提供并计算 | **不实现**（不写入审核、不计算投影） |
| 宿主加载与运维 | 提供并承担 | **不实现**（插件只提供可上传的本地能力） |
| 会话校验与身份认定 | 校验会话并给出稳定账号 | 使用返回的账号，正文自填不作身份依据 |
| 服务端部署与运维 | 承担 | 不承担、不提供独立服务端 |

### 2.3 三期不做

- 不新建独立站点或数据库；插件侧不引入数据库、消息队列或独立 Worker。
- 不做自动操作录制与回放、任意语言自动插桩。
- 不做自动处理合并冲突、无人确认自动修复发布、生产部署管理。
- 上传范围不含代码正文、GitHub Issue 与 PR。
- **不做平台侧任何能力**：不实现共享查询、跨账号审核、审核投影、宿主接收模块与远程 MCP（这些平台自己做）；插件侧不引入接收端、不监听端口。

### 2.4 上传边界

| 事项 | 约定 |
| --- | --- |
| 上传内容 | 运行、证据、报告与问题记录（脱敏投影）；**不含代码正文、GitHub Issue 与 PR** |
| 上传触发 | 每步结束与运行终止后先本地保存，再生成上传候选；账号、目标及发送策略确认后冻结提交；默认人工发送，可显式开启运行结束或逐步同步，候选生成不等于已获发送许可。失败、阻塞、取消同样保留候选，无会话不得猜测归属 |
| 上传不改判定 | 提交成功不改变执行、断言、验收结论，也不确认缺陷、不发布规则 |
| 平台不可用 | 一期的本地测试、证据、报告与导出完全不受影响；待发送材料保留在本地 |

## 3 功能要求

### 插件账号与提交

### P3-FR01 统一账号与项目关联

- 登录、查看当前账号、会话刷新、退出与重新登录；支持并发刷新合并。
- 登录后取得参与项目列表。选择平台项目必需；仓库关联仅在 Git 且平台确有该关联时适用，普通目录不被迫选择或伪造仓库。
- 显示名仅供展示，不能作为账号唯一键；正文自填用户编号不能作为身份依据。
- 退出或切换账号：清除当前账号临时视图与令牌类凭据，保留尚未送达的材料（未送达材料以明文保存在工作空间的 `outbox/<account_key>/`，依赖操作系统用户目录权限保护，不做额外加密）；迟到响应核对账号与绑定修订，不显示到新账号视图。
- 本地已产生的记录保留本地来源，登录与上传不改写其采集来源。

### P3-FR02 结果上传（提交、回执与补交）

- **提交冻结**：实际账号、来源、目标项目、绑定修订、源码身份、运行/步骤/尝试、内容修订、脱敏策略、对象上传摘要与清单摘要。身份原样保留，不整体小写；目录键取安全规范编码摘要。运行身份、提交身份和请求身份分开。
- 平台从验证后的会话确定账号；同编号同内容返回原回执，异内容或修订冲突拒绝覆盖。**插件侧不校验身份正文**：账号一律以平台返回／注入的会话为准，不从正文、显示名或本地记录推断身份。
- 断连后先查询原提交，只补交缺失材料，**不再次执行被测业务**。
- 上传不确认缺陷、不关闭问题、不发布规则、不形成审核通过；GitHub 保持只读。
- 失败、阻塞、取消的运行同样保存与提交；提交成功不改变执行、断言与验收结论。
- **候选与恢复**：从本地提交游标建立候选，恢复时可重复补建且去重；候选登记和游标推进同事务，只订阅允许业务记录，不订阅上传自身写入；离线未关联候选不自动归到下次登录账号。发送队列满不回滚本地保存，候选保留待处理。ABANDONED 只停止自动发送，永久保留材料与用户决定；迟到的有效完整回执仍登记已送达且保留放弃决定，不恢复自动发送，重新登录也不复活已放弃提交；逻辑待发送占用和物理存储占用分别显示。
- **上传投影**：在入队时冻结脱敏字节，回执比对 upload_digest，不拿原始 source_digest 代替。默认全字段与正文均不含路径/文件名，只能按显式上传策略加入允许路径；代码正文始终排除。

### 平台边界（不属于插件功能编号）

- **由平台承担**：审核、意见留痕、审核状态投影、共享查询与跨账号可见性全部在平台实现；**插件不做审核写入、不计算投影、不展示跨账号结论**（如需查看，走平台页面）。
- 插件侧只做一件事：把报告与证据以**报告内容修订 + 冻结上传投影摘要（upload_digest）**的形式上传，并在本地保留"已上传"标记；报告修订变化时提示需要重新上传，由平台决定旧修订的意见如何保留。
- 审核相关的规则（谁可审、能否自审、通过前提、确认编号与防重放）由平台定义并在平台侧验收；**插件侧不为其定义接口，也不占用插件验收场景**。
- 若平台后续要求插件展示只读的审核结论，按新增需求单独立项，不在本册承诺范围。

## 5 交付验收

- 平台具备后，账号、项目参与与仓库关联以平台返回结果为准，插件不保存第二份成员目录。
- 结果提交可追溯到账号、项目、源码快照、运行与尝试编号及内容修订。
- 断连与重复提交不产生错误结论。
- **前置条件**：平台提供会话、标识、提交方式/字段/错误、完整回执/查询合同；插件提供规范清单、报告修订摘要、冻结投影与测试向量双方对拍。分块或单次上传均可，不要求平台实现特定四步内部流程。
- **平台不可用时，一期的本地测试、证据、报告与导出功能完全不受影响。**

## 6 发送策略与预览

P3-FR01/02：SendPolicy按账号、平台项目、目标和材料范围修订；manual为默认，用户显式开启on_run_end或per_step，不影响每步生成候选。未冻结的候选可按同一运行/修订引用组织，不能丢失原始事实；失败/取消仍保留候选。账号/目标/材料允许范围变化须重新确认策略。首次提交预览接收方、冻结脱敏材料、包含/排除原因和业务证据缺口；不得预览原始密钥。

自动同步仅处理已明确批准策略范围的对象；本轮出现关键材料无法安全投影、额外材料类别、目标变化等情况停在待确认。用户明确知道缺口后可按合同发送部分材料，不宣称业务证据齐全。预览用冻结Submission投影，不在发送时重新取最新原文。关闭自动同步撤销当时全部未完成送达许可并停止后续自动发送/补交/查询，候选和接收事实永久保留；在途请求可能已经完成，不假装撤回。之后可明确手动重授单份送达许可，默认manual不妨碍完成该份许可内的有界查询/补交。

接收状态与EvidenceDeliveryCoverage分别呈现：ACKNOWLEDGED仅说明冻结清单完整接收；被排除、未采集、损坏材料仍作为业务缺口显示。平台完整业务交付标记必须按双方合同及该缺口判断，不能由HTTP成功或ACKNOWLEDGED推断。模型出站策略不能授权平台发送代码。

## 7 单份送达与停止的验收合同（2.5）

手动确认发送授权的是准确submission_id/manifest_hash的一次完整送达过程，包含同份材料有界查询/补交及安全同号重传，不只是一包网络请求；不授权新材料或后续候选。许可持久保存，重启不重置失败周期。退出/换账号、暂停本份或关闭同步撤销对应未完成许可；重登只恢复会话，不复活许可。停止后用户可再次明确确认未放弃的原提交；ABANDONED仍按新关联提交处理。

界面在确认前说明是否包括查询/补交；另有“查询一次”仅查原号，不自动补交。发送、查询、补交前均核对当前门禁；摘要冲突及关键投影缺口不能靠重登或普通重试解除。人工确认来源沿用一期入口权限，不接受AI工具调用自称已获同意。详细决策表见三期功能第7节，技术字段见上传架构第9节。

## 8 上传停止动作区分（2.6）

暂停本份、退出/切账号、关闭自动同步均撤销相应许可而不写放弃决定；原因解除并重新确认后可继续原提交。只有用户明确确认“放弃提交”才进入ABANDONED。接收事实独立保存，恢复不能把UNKNOWN/INCOMPLETE改成未发送，已送达不因恢复再发。
