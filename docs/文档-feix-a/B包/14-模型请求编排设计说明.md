## 2 与既有纯规则的关系：**编排不重复判定**

Sprint 5 已实现三块纯规则（`domain/planning/model_outbound.py`，40 项测试）。本模块只串起来：

| 纯规则 | 本模块的用法 |
| --- | --- |
| `ModelOutboundPolicy.effective_material_kinds()` | 决定可送类别（已撤销的自动排除） |
| `ModelOutboundPolicy.is_confirmed_for_current_scope()` | 决定策略是否已确认当前目标与范围 |
| `TASK_MATERIAL_KINDS` | 决定某类别是否属于该任务 |
| `validate_outbound_material()` 九条门禁 | 投影**之前**再校验一次（含空项与重复项） |
| `response_currency()` | 迟到响应判定，**人工版本优先** |

有一处**顺序要求**：准入在**投影之前**。先拦住不该送的材料，再花代价做脱敏投影。

## 3 四条硬约束的落点

| 约束 | 落点 | 测试 |
| --- | --- | --- |
| **只发送显式选定的脱敏材料** | 九条门禁通过后，把 `Projection.projected`（**已脱敏**）交给 `ModelCaller`；编排不接触原始字节 | `test_only_projected_material_reaches_the_caller` |
| **凭据正文不进配置、日志、面板、导出** | `CredentialResolution` **只有状态**，`CredentialResolver` 协议里没有返回正文的方法；出站记录只存 `credential_purpose` | `test_credentials_never_reach_the_record`、`test_credential_resolution_carries_no_body` |
| **模型只输出草稿** | 产出 `GeneratedContent(status=draft)`；`OutboundOutcome` 没有"通过"这一档 | `test_successful_request_produces_a_draft` |
| **迟到响应不覆盖人工版本** | `settle_response()` 判 `CURRENT` 才产出草稿，否则只留响应事实 | `test_manual_edit_supersedes_a_late_response` |

### 3.1 失败一律返回态，**不抛异常**

需求 §7 与 P1-AC32 要求"模型不可用时人工路径仍可用"。抛异常会把失败扩散成调用方崩溃，
因此以下都是**返回 `blocked_by`**：

- AI 已关闭；策略未确认；类别不被允许或不属于该任务；源码片段开关关闭；
- 凭据缺失或用途不匹配；材料无法安全投影而被排除；
- 模型调用失败（归类错误）。

**但"写盘失败"仍然向上抛**（与其他用例一致）：那属于存储故障，不能伪装成"模型不可用"。

### 3.2 **不重试、不暗换供应方**

`request_model_draft()` 对一次请求只调用 `caller.call()` **一次**。
"不在失败重试中暗换供应商"（需求 §7）因此是**结构上成立**的，不依赖实现者的自觉。

### 3.3 失败也留出站记录

需求要求"保留请求关联编号、模型配置、原始输出及分析结果"。
失败是一次**真实发生的出站事实**，因此无论成败都登记 `OutboundRequest`
（含 `call_status` 与 `error_kind`）。

只落**错误分类**，不落供应商的错误正文：错误文本可能回显请求内容，而请求内容取自被测项目。
细节只留摘要与长度（`error_detail_digest` / `error_detail_chars`），足够与供应商日志对账。

### 3.4 出站次序：**先登记意图，再调用**

外部调用是**不可撤销的副作用**，因此顺序固定为：

| 步 | 动作 | 事务 |
| --- | --- | --- |
| 1—5 | 准入、九条门禁、凭据解析、投影 | **无事务**（不产生副作用） |
| 6 | 登记出站**意图**（要发什么、发给谁、凭什么） | 短事务一，提交 |
| 7 | 发起模型调用 | **事务外** |
| 8 | 登记**结果**；成功时草稿正文与引用同批落盘 | 短事务二，提交 |

反序（先调用后登记）在"调用已发生、进程随后崩溃"时会丢掉整条出站事实，事后无法补记。
同一出站记录因此产生两个修订：修订 1 的 `state` 是 `intent`，修订 2 是 `outcome`，
调用方据此可程序化区分，不需要靠字段是否存在来猜。

草稿正文与其摘要一起落盘（`generated_content` 记录）：只存元数据会让
"模型确实产出了什么"没有可核对的字节，报告与导出也就无法引用真实内容。

## 4 投影缺口：**比"部分脱敏放行"更保守**

`Projection` 有两种状态，语义严格区分：

| 状态 | 含义 |
| --- | --- |
| `COMPLETE` | 全部所选材料都已安全投影，`excluded` 必须为空 |
| `PARTIAL` | 有材料无法安全投影而**被排除**，必须逐项列出 |

**投影不全 → 阻塞**（不是"发出去剩下的部分"）。理由：

> 部分材料被摘掉后，模型看到的就不是完整上下文，而报告里也没有对应缺口 ——
> 那等于**伪造完整证据**。需求原文是"无法安全投影则排除并**显示分析缺口**"，
> 因此缺口必须显式呈现，由用户决定是否继续。

内存替身（`MemoryProjector`）把**含疑似凭据的材料整项排除**，不"剥掉一行继续发"——
同样是为了避免"部分脱敏后假装完整"。

## 5 出站记录的字段

`OutboundRequest` 记录**实际送出了什么**（需求 §7"只发送显式选定脱敏材料"要可核对）：

| 字段 | 用途 |
| --- | --- |
| `request_id` | 按（项目、策略修订、任务）**稳定**，重复请求不产生第二条记录标识 |
| `task_type` | 任务类型；材料子集由它限定 |
| `policy_revision` | 策略修订（出站依据） |
| `source_revision` / `base_manual_revision` | 迟到响应的判定输入 |
| `material_kinds` / `item_count` | **实际送出**的类别与项数 |
| `projection_digest` | 投影内容的摘要 |
| `endpoint_address` / `model_id` | 接收目标（**不含凭据**） |
| `credential_purpose` | 只记**用途** |
| `provider_request_id` / `call_status` / `error_kind` | 供应方回执与结果 |

**落盘 payload 里没有、也不应有**：任何凭据值、任何未投影的原始材料。
