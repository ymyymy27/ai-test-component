### 2.3 任务类型 ↔ 材料类别

架构文档第 9 节：**「任务类型限定可选字段」**。因此任务类型与材料类别**不是同一个概念的两个名字**，而是"请求目的"与"允许送出的材料"两个维度：

- `MaterialKind` 决定**哪些材料可以被送出**（策略里的 `allowed_material_kinds`）；
- `ModelTaskType` 决定**这次请求要模型做什么**，并限定该请求**可用的材料类别子集**。

| `ModelTaskType` | 含义 | 允许携带的 `MaterialKind`（只读子集） |
| --- | --- | --- |
| `CONTEXT_SUMMARY` | 上下文摘要 | `PROJECT_CONTEXT`、`MODULE_DEPENDENCY_FACTS`、`SOURCE_SNIPPET` |
| `CHECK_CONTENT_DRAFT` | 检查内容草稿 | `PROJECT_CONTEXT`、`MODULE_DEPENDENCY_FACTS`、`TEMPLATE_CONTENT`、`ACCEPTANCE_ITEM`、`SOURCE_SNIPPET` |
| `ACCEPTANCE_SUGGESTION` | 验收项建议 | `PROJECT_CONTEXT`、`ACCEPTANCE_ITEM`、`TEMPLATE_CONTENT` |
| `DELIVERY_DRAFT` | 交付说明草稿 | `PROJECT_CONTEXT`、`DELIVERY_NOTE` |
| `CASE_SUGGESTION` | 用例建议 | `PROJECT_CONTEXT`、`ACCEPTANCE_ITEM`、`TEMPLATE_CONTENT`、`CASE_CONTENT`、`SOURCE_SNIPPET` |
| `EVIDENCE_ANALYSIS` | 证据分析 | `EVIDENCE_REFERENCE`、`EXECUTION_FACT`、`SOURCE_SNIPPET` |

`MaterialKind` 取值：

```text
PROJECT_CONTEXT         项目上下文摘要（名称、目标、模块清单）
MODULE_DEPENDENCY_FACTS 模块与依赖事实
TEMPLATE_CONTENT        模板正文与必测集合
ACCEPTANCE_ITEM         验收项
DELIVERY_NOTE           交付说明
CASE_CONTENT            用例内容
EVIDENCE_REFERENCE      证据引用（引用与摘要，不含正文）
EXECUTION_FACT          执行事实摘要
SOURCE_SNIPPET          源码片段（受 source_snippets 开关控制）
```

**不改合同层**：`PreparedRun` 已有 `model_outbound_policy_revision` 与 `source_snippets_enabled` 两个字段，
本次不新增、不改名、不改 Schema。

## 3 数据模型与不变量

### 3.1 `ModelEndpoint`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `provider` | `str` | 供应方标识（如 `deepseek`） |
| `address` | `str` | 接收地址 |
| `model_id` | `str` | 模型标识 |
| `purpose` | `str` | 凭据用途，一期固定为 `model`（架构文档第 1 节：模型/HTTP/数据库核验/GitHub 分用途） |

**不变量**

1. 四个字段均非空。
2. **本对象在类型层面无法表达凭据正文**——只有"用途"这一个字符串，没有 `value` / `secret` / `api_key`

   类字段。测试用 `dataclasses.fields()` 断言字段集合，防止后续新增正文类字段。
3. 只保存**引用与地址**，不保存密钥。

### 3.2 `OutboundConfirmation`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `confirmation_id` | `str` | 确认记录标识 |
| `endpoint_digest` | `str` | **绑定的接收地址/供应方摘要** |
| `allowed_material_kinds_digest` | `str` | **绑定的允许类别集合摘要** |
| `source_snippets_enabled` | `bool` | 确认时的源码片段开关取值 |
| `confirmed_at_commit` | `str` | 确认时的提交序号 |

**不变量**：均非空；`confirmed_at_commit` 用于业务顺序，**不用系统时间**（功能文档第 5 节）。

**为什么绑摘要而不是绑整个策略对象**：需求 §7 是"**范围或目标变化重新确认**"，
不是"任何字段变化都重新确认"。确认绑定目标与范围这两个维度，才既能拦住目标/范围变化，
又不会因为无关字段（如策略修订号递增）让用户反复确认。

### 3.3 `ModelOutboundPolicy`

需求 §7 原文：**「首次出站确认项目、供应方/接收地址和材料类别，源码片段默认关闭；
只发送显式选定脱敏材料，范围或目标变化重新确认。开启源码片段也不发送全仓。」**
功能文档第 9 节原文：**「`ModelOutboundPolicy` 按项目修订，保存接收地址/供应方、允许类别、
`source_snippets=false` 默认值及确认记录。」**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `project_id` | `str` | 所属项目 |
| `revision` | `int` | 按项目修订，从 1 起；对应 `PreparedRun.model_outbound_policy_revision` |
| `endpoint` | `ModelEndpoint` | 接收地址/供应方 |
| `allowed_material_kinds` | `frozenset[MaterialKind]` | **显式选定**的允许类别 |
| `source_snippets_enabled` | `bool` | **默认 `False`** |
| `ai_enabled` | `bool` | 关闭 AI 后阻止**后续**模型发送 |
| `confirmation` | `OutboundConfirmation \| None` | 已确认的接收目标与范围 |
| `revoked_material_kinds` | `frozenset[MaterialKind]` | 已撤销类别，立即生效 |

**不变量**

1. `project_id` 非空；`revision >= 1`。
2. **`source_snippets_enabled` 默认 `False`**（`dataclass` 默认值即关闭）。
   开启 `SOURCE_SNIPPET` 的唯一路径是显式传入 `source_snippets_enabled=True`，
   且该类别**必须同时出现在 `allowed_material_kinds`**。
3. `allowed_material_kinds` 非空，且每项为合法 `MaterialKind`。
4. **`revoked_material_kinds ⊆ allowed_material_kinds`**：只撤销已允许的类别。
5. `confirmation` 非空时，其 `source_snippets_enabled` 必须与本对象一致
   （否则是"确认了一个与当前开关不符的范围"）。
6. `ai_enabled=False` 时**不阻止构造**，也不清空任何字段——关闭 AI 只阻止新的模型请求，
   已有人工配置、规则、证据与报告继续可用（需求 P1-AC32）。

### 3.5 出站准入：`validate_outbound_material()`

这是"**不能通过另一类别夹带未授权源码**"（需求 §7）的落点。
签名草案：

```python
@dataclass(frozen=True, slots=True)
class OutboundItem:
    material_kind: MaterialKind
    field_path: str      # 该材料在出站字段中的定位，供报错与缺口登记
    text: str            # 已脱敏文本（脱敏由 A 的 ProjectionPort 完成，本层不重复实现）

def validate_outbound_material(
    policy: ModelOutboundPolicy,
    task_type: ModelTaskType,
    items: Sequence[OutboundItem],
) -> tuple[OutboundItem, ...]:
    """返回可送出的项；任一项违规即抛 ValueError 并指出具体项。"""
```

逐条门禁：

| # | 门禁 | 依据 |
| --- | --- | --- |
| 1 | `ai_enabled is False` → 拒绝整个请求 | 需求 P1-AC32「关闭 AI 阻止新模型请求」 |
| 2 | 项数 `== 0` → 拒绝（**空集不等于"不适用"**） | 根 `AGENTS.md` 第 4 节 |
| 3 | 材料类别未确认（无 `confirmation`）→ 拒绝 | 需求 §7「首次出站确认……材料类别」 |
| 4 | 材料类别被撤销（在 `effective_material_kinds` 之外）→ 拒绝 | 功能文档第 9 节「缩小范围立即生效，不再发送被撤销类别」 |
| 5 | 材料类别不属于该 `task_type` 的允许子集 → 拒绝（防跨任务夹带） | 架构文档第 9 节「任务类型限定可选字段」 |
| 6 | 项含 `SOURCE_SNIPPET` 但 `source_snippets_enabled is False` → 拒绝 | 需求「源码片段默认关闭」 |
| 7 | 项含 `SOURCE_SNIPPET`、开关已开，但该类别不在 `allowed_material_kinds` → 拒绝 | 需求 §7「开启源码片段也不发送全仓」 |
| 8 | 任一 `field_path` 或 `text` 为空 → 拒绝 | 无法定位的空项不能作为"已发送材料" |
| 9 | 同一 `(material_kind, field_path)` 重复 → 拒绝 | 重复项会让"显式选定"失去意义 |

**第 6 条是核心反例门禁**：模型任务类型允许携带 `SOURCE_SNIPPET`（如"用例建议"），
但策略开关关闭时必须拒绝——即使调用方把源码片段**塞进了别的类别字段**，
第 5 条也会因为该字段声明的类别与任务不匹配而拒绝。

### 3.6 迟到响应：`response_currency()`

架构文档第 9 节：**「迟到响应核对来源内容修订，变化后标记过期，不覆盖新分析」**；
功能文档第 5 节：**「迟到响应核对来源修订」**；施工清单第 9 节：**「迟到响应核对来源修订并标过期，未覆盖当前人工版本」**。

```python
class ResponseCurrency(StrEnum):
    CURRENT = "current"
    SOURCE_CHANGED = "source_changed"
    SUPERSEDED_BY_MANUAL = "superseded_by_manual"

@dataclass(frozen=True, slots=True)
class ModelResponseEnvelope:
    response_id: str
    request_revision: int          # 发出请求时的策略修订
    source_revision: int           # 发出请求时的来源修订
    base_manual_revision: int      # 发出请求时人工版本的修订
    received_at_commit: str
    is_draft: bool = True          # 模型只输出草稿

def response_currency(
    response: ModelResponseEnvelope,
    current_source_revision: int,
    current_policy_revision: int,
    current_manual_revision: int,
) -> ResponseCurrency:
    """判定迟到响应的当前性；不修改任何入参，也不返回"最新草稿"。"""
```

| 判定顺序 | 条件 | 结果 |
| --- | --- | --- |
| 1 | `current_manual_revision > response.base_manual_revision` | `SUPERSEDED_BY_MANUAL`（**不覆盖当前人工版本**） |
| 2 | `current_source_revision != response.source_revision` | `SOURCE_CHANGED`（来源已变，标过期） |
| 3 | `current_policy_revision != response.request_revision` | `SOURCE_CHANGED`（策略修订已变，本次请求的依据不再是当前依据） |
| 4 | 其他 | `CURRENT` |

**为什么用 `base_manual_revision` 而不是直接与 `request_revision` 比**：策略修订与人工草稿修订
是两套独立的计数器，直接比较会得出错误结论。响应必须**记住它是在哪个人工修订之上发出的**，
才能判断"期间用户是否已经手改过"。

**三条硬性不变量**

1. **人工版本优先**：只要当前人工修订比该响应新，一律判 `SUPERSEDED_BY_MANUAL`，
   即使来源未变也不得覆盖。
2. **模型只输出草稿**：`is_draft=False` 的响应在构造时即被拒绝——
   模型不得直接修改断言、关闭缺陷或作出结论（架构文档第 9 节）。
3. **不返回"最新"**：本函数只返回状态枚举，**不返回任何可被当成结论使用的对象**，
   避免下游拿派生结果当人工确认。

## 4 设计决定

| # | 决定 | 依据 | 备选与代价 |
| --- | --- | --- | --- |
| 1 | 新建 `domain/planning/model_outbound.py`，不塞进 `plans.py` | `plans.py` 已 478 行，且模型出站与计划冻结是两件事 | 备选：继续追加。代价：单文件过大，且让别人误以为出站属计划发布的一部分 |
| 2 | 任务类型与材料类别**分成两个枚举** | 架构文档第 9 节区分"任务"与"可选字段" | 备选：合成一个枚举。代价：无法表达"同一材料可服务多个任务、同一任务可用多种材料" |
| 3 | `SOURCE_SNIPPET` 是 `MaterialKind` 的一个取值，而不是"开关" | 需求 §7「源码片段开关作用**所有**出站字段及日志/附件投影」 | 备选：只在策略上留一个 bool。代价：无法逐项拦截"塞进别的类别字段" |
| 4 | 出站确认**绑摘要**（目标摘要 + 类别集合摘要） | 需求 §7「范围或目标变化重新确认」 | 备选：绑策略修订号。代价：无关字段变化也会强制重新确认 |
| 5 | `effective_material_kinds()` 是**派生函数**，不回写策略 | 与 `effective_assertion_basis_state` 一致 | 备选：在策略上存有效集合。代价：出现两个真值来源 |
| 6 | `ai_enabled=False` **不阻止构造策略**，只派生空的可送出集合 | 需求 P1-AC32「关闭AI阻止新模型请求，已有人工/规则/报告继续」 | 备选：关 AI 时禁止保存策略。代价：用户无法先关掉再改配置 |
| 7 | 本 Sprint 不实现真实脱敏投影，只做准入规则 | 脱敏与字节投影属 A 的 `ProjectionPort`；（根 `AGENTS.md` 第 3 节：采集安全由适配器与端口承接） | 备选：自己写一套脱敏。代价：与 A 的实现形成两套，且 B 不得改 `infrastructure/` |
| 8 | 迟到响应判定**先比人工修订，再比来源修订** | 施工清单第 9 节「未覆盖当前人工版本」 | 备选：先比来源。代价：来源未变但人工已改时会被判成可覆盖 |
