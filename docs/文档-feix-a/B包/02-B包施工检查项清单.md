## 2 领域模型

- [ ] `domain/` 只使用标准库，未 import `pydantic` / `contracts` / `application` / `infrastructure` / `interfaces`
- [ ] 领域对象为 `@dataclass(frozen=True, slots=True)`
- [ ] 违反不变量抛 `ValueError`（与现有代码风格一致）
- [ ] 时间经 `Clock` 端口，未使用 `datetime.now()`
- [ ] 业务顺序按**提交序号**判断，未按系统时间选最新
- [ ] `local_project_id` 与对外 `project_id` 是**同一值**，不是两个编号
- [ ] 绑定与项目身份分离；目录移动创建**新绑定修订**，历史仍归同一项目
- [ ] `plain` 形态**完全省略** Git 字段，未用 `None` / 空字符串 / "未知"占位
- [ ] 界面/展示按 `BindingForm` 渲染，不靠"取不到值"判断形态
- [ ] `Dependency` 允许循环，传播遍历按来源去重
- [ ] 同步盘/网络盘位置**拒绝建立工作空间**并说明原因

## 3 模板与草稿（FR04）

- [ ] 模板只生成草稿，**未提供自动发布路径**
- [ ] 模板给出：适用条件、稳定 `item_id`、必测集合、关键链路清单
- [ ] 空关键链路有 `no_critical_path_reason`
- [ ] 模板正文未写成可执行 shell
- [ ] 未在项目上下文缺失时编造依赖与结论，而是列缺口并阻塞
- [ ] 人工修订不会被重新生成覆盖
- [ ] `GeneratedContent` 记录了**实际依赖的修订集合**
- [ ] 相关来源变化后草稿被标**定向**过期（未变部分可复用）
- [ ] 六个模板的真实版本可在安装后被列出

## 4 规则版本（FR05）

- [ ] 规则正文、结构化规则、发布状态分开保存
- [ ] 导入只创建草稿，不执行其中命令
- [ ] 未确认发布不生效
- [ ] 发布后不可变；新测试绑定新修订，旧运行仍引用原版
- [ ] 往返保留编号、来源与未识别扩展字段
- [ ] **未知执行字段不得静默启用**

## 5 用例、依据与计划（FR06）

- [ ] 用例含：层级、前置、输入、步骤、预期、验证方法、允许 Mock 范围、重要性
- [ ] 无预期/前置/必要核验方式的用例不能发布为可直接验收
- [ ] 发布时关联**全部适用关键链路**并登记**独立核验方式**
- [ ] 确无适用链路时保存显式空集合**及理由**；缺清单字段仍阻止发布
- [ ] `missing` 依据不能进入 full 必测
- [ ] `present_unconfirmed` 可执行、保留分母、计"断言未核实"、**不计 V**
- [ ] `confirmed` 仍须实际证据/独立核验有效才计 V
- [ ] `assertion_basis_state` 是冻结值；`effective_assertion_basis_state` 是**派生值**
- [ ] 依据文本变化后**旧确认失效**
- [ ] 补充确认**没有**直接把 `verified_count` 加一
- [ ] `CaseLink` 覆盖验收项/模块/检查内容/适用环境
- [ ] `AcceptanceScope` 含目标、包含/排除及原因、依赖闭包、适用性、模板修订
- [ ] 计划发布固定**精确**的用例与规则修订（不是"最新"）

## 6 档位、范围与门禁（FR07）

- [ ] `T ⊆ M`；`full` 要求 `M ⊆ S`
- [ ] `full` 跳过项为 0
- [ ] `ConclusionCeiling` **只由档位派生**，未由覆盖率或驱动方式放宽
- [ ] `quick` / `on_demand` 的结论上限为 `partial`，证据等级为"不打分"
- [ ] 不适用项给出原因且**不计入分母**
- [ ] "未执行"未被当作"不适用"
- [ ] 运行中不得删必测、弱化断言、变更适用性；违反时拒绝或要求新建运行
- [ ] 无关新增用例**不能**抵消模板漏项
- [ ] 驱动只允许 `planned → stepwise`；反向被拒并提示新建运行
- [ ] 运行中修订只作用于**尚未执行**的步骤
- [ ] 正在执行的步骤拒绝修改
- [ ] 依据失效时暂停并列出需重跑的用例，当前完整通过**不使用失效依据**

## 7 准备意图与幂等

- [ ] 源码读取与摘要计算在**短事务外**
- [ ] 按 `(project_id, client_id, prepare_request_id)` 登记 `PreparationRecord`
- [ ] 同请求同输入**幂等**返回；同键异输入摘要返回**冲突**
- [ ] 并发完成同一准备请求**只发布一条**记录，其余取得已发布结果
- [ ] `intent_id` 与准备记录**同一次提交**
- [ ] 未用 `request_id` 代替业务身份
- [ ] prepare 期间源码变化 → 返回"依据需重新准备"，**未把新字节塞进旧意图**
- [ ] 提交时校验项目、绑定、计划、规则、模板、环境修订及准备请求是否仍有效
- [ ] `expected_revision` 冲突时返回当前修订与差异提示，**不自动覆盖用户编辑**
