## 1 目标

B 包完成一期"测试开始之前"的纵向切片（P1-FR01—FR07）：

1. 建立本地项目、模块、依赖、环境与源码内容身份（FR01），交付标准交付说明（FR02）。
2. 按已登记依赖做确定性变更影响与回归建议（FR03）。
3. 落地六个版本化模板，AI 只生成草稿（FR04）。
4. 规则草稿发布为不可变版本（FR05）。
5. 计划与用例的字段、关联、断言依据三态与发布校验（FR06）。
6. 档位、驱动、结论上限、必测下限与准备意图去重（FR07）。
7. **始终维护"草稿 / 发布 / 授权 / 执行 / 核验"是不同事实**这一边界。

**唯一对外业务交付**：`PreparedRun`（B 产生、C 读取、D 仅作展示）。
具体字段见架构文档第 11、12 节，最终以 `docs/接口对接/` 定稿版本为准。

## 2 边界

**B 负责**

- 本地项目、模块、Git/plain 绑定、源码快照（建立时机与内容身份规则）、环境引用、交付说明、单模块及跨模块回归范围。
- 六个版本化模板、规则草稿/发布、计划与用例、验收范围、独立断言依据确认。
- 快速检查/按需自测/完整验证的范围与结论上限输入；计划驱动/逐步驱动配置；`prepare_request_id` 对应的准备意图。
- 计划发布、运行中允许的待执行步骤修订、弱化必测项拒绝的**纯规则**。
- 模型出站策略与草稿辅助、选定源码读取/固定、可选 GitHub 只读适配。

**B 不负责**

- 文件事务、索引、恢复、传输协议（A）。
- L1/L2/L3 实际执行、授权持久化、采集、独立核验（C）。
- 判定 S/M/E/R/V/P/F/U/H、证据等级、问题闭环、报告、面板、CLI、MCP（D）。
- **不直接编辑 `file_store`**；只经 A 的端口保存材料。

## 4 实施阶段

### Sprint 0：锁合同（最高优先级）

产物：`PreparedRun` Pydantic 合同；成功/失败/未知三类夹具；与 C 的词汇表对齐；`docs/接口对接/` 三份文档定稿。

完成条件：

- `scripts/generate_schemas.py` 纳入 `PreparedRun`，重生成后 `git diff --exit-code -- src/aitest/contracts/schemas` 通过；
- 三类夹具可被 `model_validate_json()` 解析；
- C 确认 `docs/接口对接/B-C-PreparedRun与词汇表合同.md` 的 C-01—C-08；
- 词汇表漂移锁定测试（domain ↔ contracts）通过。

**本阶段不写任何业务逻辑**，目的是让 C/D 不必再猜字段。

### Sprint 1：领域层（纯规则）

产物：项目/模块/依赖/环境/交付领域对象补全；`T/M/S` 校验；档位→结论上限派生；断言依据三态与 `effective_assertion_basis_state` 派生；回归传播。

完成条件：领域层只依赖标准库；`ruff` / `mypy --strict` / `pytest tests/unit tests/architecture` 通过；
每条不变量都有对应测试（见 `02-B包施工检查项清单.md`）；无任何 I/O。

### Sprint 2：应用用例与端口接入

产物：建立项目/绑定/环境用例；模板应用与草稿生成；计划发布；`prepare_run` 用例与幂等登记。

完成条件：

- 同 `prepare_request_id` 重复调用返回同一结果；同键异输入摘要返回冲突；
- prepare 后源码变化 → 返回"依据需重新准备"；
- 缺上下文 / 依据 `missing` / 模板目低于下限 → 阻塞并给出具体原因；
- 全程不 import `infrastructure`；源码读取与摘要计算在短事务外。

### Sprint 3：六个模板落地

产物：六个模板补齐必测集合、关键链路清单、适用条件、正常/边界/异常样例与漏项拒绝案例。

完成条件：`tests/contracts/test_templates.py` 通过（**注意该测试断言 `implementation_status == "scaffold"`，
升级模板时须同步修改该断言并在 PR 中说明理由**）；模板只能生成草稿。

### Sprint 4：规则版本与计划/用例发布

产物：规则草稿→发布；用例字段、`CaseLink`、独立核验方式、依据三态；发布校验门禁。

完成条件：发布后不可变；人工修改不被生成覆盖；缺字段阻止发布并指出**具体**缺哪个；
`publish_plan` / `publish_rules` 仍是 `HUMAN_ACTIONS`（`agent_relay` 不可调用）。

### Sprint 5：模型出站与可选 GitHub 只读

产物：`ModelOutboundPolicy`、投影后草稿请求、迟到响应过期、GitHub 只读适配。

完成条件：`source_snippets` 默认关闭；模型只输出草稿；模型不可用时可人工建计划；
迟到响应不覆盖当前人工版本；plain 项目不注册、不调用 Git 能力。

### Sprint 6：两次业务交接

- 交接一：以真实 `PreparedRun` 替换 C 的夹具，核对准备/启动间来源变化。
- 交接二：配合 C→D 的 `ExecutionFacts` 交接，核对档位、结论上限、范围口径一致。

完成条件：C 不再需要猜字段；D 的面板能读到计划/档位/驱动/范围/依据状态；三方枚举无重复定义。

### Sprint 7：验收（B 牵头的 8 项 AC）

产物：`tests/acceptance/p1/status.json` 中 B 牵头条目的结果与证据路径。

完成条件：按 AC 编号记录**输入、软件及制品版本、预期、实际、证据位置和未验证原因**；
断言不能只检查"调用成功"。

## 5 验证策略

| 层次 | 内容 |
| --- | --- |
| 领域单元测试 | 档位派生、`T/M/S` 边界、三态派生、驱动单向收窄、依赖循环去重、plain/git 形态互斥 |
| 合同测试 | `PreparedRun` 成功/失败/未知三类夹具；词汇表漂移锁定 |

| 架构测试 | `domain` 不依赖 pydantic/contracts/application/infrastructure/interfaces |
| 幂等测试 | 同 `prepare_request_id` 同输入幂等、异输入冲突、并发只发布一条 |
| 门禁测试 | full 缺必测被拒、弱化断言被拒、删必测被拒、反向驱动切换被拒 |
| 反例测试 | plain 不出现 Git 字段；模板缺清单阻塞；依据 `missing` 阻止 full 必测 |
