## 3 数据模型与不变量

字段命名对齐 `src/aitest/contracts/prepared_run.py` 已冻结的 `PreparedRun`，避免 Sprint 2 组装时二次翻译。

### 3.1 `LocalProject`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `local_project_id` | `str` | 稳定业务身份。对外 DTO 名称为 `project_id`，**二者为同一值** |
| `workspace_id` | `str` | 工作空间标识；`PreparedRun.workspace_id` 取值来源 |
| `name` | `str` | 显示名。变化不改变业务身份 |
| `goal` | `str` | 项目目标 |
| `revision` | `int` | 内容修订，从 1 起 |
| `created_at_commit` | `str` | 创建时的提交序号。业务顺序以此判断，不用系统时间 |
| `modules` | `tuple[Module, ...]` | 已登记模块 |

**不变量**

1. `local_project_id`、`workspace_id`、`name`、`goal` 去除首尾空白后非空。
2. `revision >= 1`。
3. `created_at_commit` 非空。
4. `module_id` 在项目内唯一。
5. 项目内所有 `module.project_id == local_project_id`。

> **为什么不叫 `project_id`**：架构文档第 1 节要求"稳定 `local_project_id`（对外 DTO 名称 `project_id`，二者为同一值而非两个编号）"。
> 领域层用 `local_project_id` 表明这是本地身份，合同／DTO 层用 `project_id`。**实现中必须存在一个权威别名属性 `project_id` 返回同一值**，
> 防止下游各写一个转换函数、把"同一值"做成"两个编号"。该别名由测试锁定 `project.project_id == project.local_project_id`。

### 3.2 `LocalProjectBinding` 与 `BindingForm`

```python
class BindingForm(StrEnum):
    GIT = "git"
    PLAIN = "plain"
```

| 字段 | 类型 | 适用形态 | 说明 |
| --- | --- | --- | --- |
| `binding_id` | `str` | 两者 | 绑定标识 |
| `binding_revision` | `int` | 两者 | 从 1 起；移动或形态变化产生新修订 |
| `project_id` | `str` | 两者 | 指向 `LocalProject.local_project_id` |
| `canonical_path` | `str` | 两者 | 规范化绝对路径 |
| `binding_form` | `BindingForm` | 两者 | 决定下方字段的**存在性** |
| `repository_id` | `str \| None` | 仅 `git` | 仓库标识 |
| `branch` | `str \| None` | 仅 `git` | 当前分支 |
| `base_commit` | `str \| None` | 仅 `git` | 基准提交 |
| `manifest_digest` | `str \| None` | 仅 `plain` | 文件清单摘要 |
| `environment_ref` | `EnvironmentRef \| None` | 两者 | 环境引用，可缺（见 3.5） |
| `local_owner` | `str \| None` | 两者 | 本地责任人 |
| `confirmed` | `bool` | 两者 | 是否已重新确认；移动或形态变化后置 `False` |

**不变量**

1. `binding_id`、`project_id`、`canonical_path` 非空；`binding_revision >= 1`。
2. `canonical_path` 必须是绝对路径文本（`PureWindowsPath` / `PurePosixPath` 判定），且不含 `.` / `..` 段。
3. `binding_form == GIT` 时：`repository_id`、`branch`、`base_commit` **必须非空**；`manifest_digest` **必须为 `None`**。
4. `binding_form == PLAIN` 时：`repository_id`、`branch`、`base_commit` **必须全为 `None`**；`manifest_digest` 必须非空。
5. **禁止用空字符串或 `"unknown"` 占位**：形态不适用一律用 `None`，并可省略为不存在。

> 不变量 3／4 的措辞是"必须为 `None`"，而需求原文是"完全省略字段、不显示空值"。
> 领域对象是进程内值对象，无法真正"省略字段"，因此用**条件性 `None` + 强制校验**表达同一语义；
> 落到 JSON／DTO 时由序列化层负责真正省略键（`PreparedRun` 合同已如此实现，见 `contracts/prepared_run.py` 第 311—320 行）。
> 这一层映射关系由测试覆盖：`plain` 绑定序列化后不得出现 `repository_id` / `branch` / `base_commit` 键。

**`plain` 形态是合法的一等形态**：FR01 明确"不得因为不是 Git 仓库而拒绝建立项目或降级检查范围"。
测试必须同时验证 `plain` 项目能建立成功，且仓库相关字段不出现。

### 3.3 `Module` 与 `Dependency`

`Dependency` 表示**使用者 → 提供者**的有向边（需求 FR03）。

```python
class DependencyOrigin(StrEnum):
    REGISTERED = "registered"   # 人工登记
    INFERRED = "inferred"       # 推导得出，须标"可能不完整"
```

| 记录 | 字段 |
| --- | --- |
| `Dependency` | `consumer_module_id`、`provider_module_id`、`origin`、`source`（`str \| None`） |
| `Module` | `module_id`、`project_id`、`name`、`responsibility`、`inputs`、`outputs`、`interface_note`、`implementation_status`、`dependency_provider_ids` |

**不变量**

1. `module_id`、`project_id`、`name`、`responsibility` 非空。
2. `interface_note` 非空（接口说明是 FR01 必填上下文）。
3. `Dependency` 两端模块 id 非空且**不相等**（自环无意义，直接拒绝）。
4. `DependencyOrigin.INFERRED` 时 `source` 必须非空（否则无法在 FR03 中标注推导来源）。
5. **允许循环**：`a → b → a` 合法，不得因成环拒绝建立项目。循环只影响传播遍历，由遍历算法去重（`application/planning/regression.py` 已实现并已有测试）。

> **重大决定 1：`Module.dependencies` 与 `Dependency` 的记录关系**
>
> 仓库现状：`Module.dependencies: tuple[str, ...]`（仅提供者 id，无来源、无循环标记），
> 而架构文档第 1、7 节要求 `Dependency` 是独立记录（使用者 → 提供者 + 来源 + 循环标记）。
> 两者是同一关系的两种表示，同时存在会形成"两套真相"。
>
> **决定**：`Dependency` 记录为唯一权威来源；`Module` 上**不再保留** `dependency_provider_ids` 作为可写字段，
> 改为由模块集合 + 依赖边集合投影出的只读视图（`ModuleDependencyGraph`）。
> 现有 `application/planning/regression.py::affected_modules` **不移动、不改签名语义**，
> 仅把入参标注从 `dict[str, tuple[str, ...]]` 放宽为 `Mapping[str, Sequence[str]]` 以同时接受旧字典与投影结果，
> 既有测试 `test_dependency_cycle_terminates_and_keeps_changed_module` 继续通过。
> 这样既满足架构要求，又不破坏 C 或其他包的既有引用。

### 3.4 `EnvironmentRef`

架构文档第 1 节：环境是**运行冻结属性**；需求 FR07：依赖环境方式、业务数据隔离/复位、目标部署版本**分别记录**。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `environment_id` | `str` | 环境标识 |
| `revision` | `int` | 从 1 起 |
| `isolation_mode` | `IsolationMode` | `venv`（默认）/ `none`（显式不隔离）/ `unmanaged` |
| `isolation_confirmed` | `bool` | `isolation_mode != VENV` 时为 `True` 才可保存 |
| `interpreter_requirement` | `str` | 解释器与版本要求（声明） |

**不变量**

2. `isolation_mode != VENV` 时 `isolation_confirmed` 必须为 `True`（需求 FR07："显式选择不隔离冻结于运行"，需确认）。
3. 超时字段非 `None` 时必须 `> 0`。
4. **`EnvironmentRef` 只保存声明与引用，不保存已解析的事实**：解释器实际身份、依赖集合摘要不属于本对象。

> **重大决定 2：声明与解析结果分离**
>
> `PreparedRun.EnvironmentRefFact` 已冻结三个**已解析事实**字段：`interpreter_identity`、`dependency_set_digest`、`isolation_mode`。
> 这三者值在 prepare 时刻才由应用用例解析产生（读 `py -3.13 --version`、读锁文件摘要），领域层不能自己算（零 I/O）。
> 因此本 Sprint 拆成两个对象：
>
> | 对象 | 层 | 何时产生 | 内容 |
> | --- | --- | --- | --- |
> | `EnvironmentRef` | `domain/project/` | 用户登记环境时 | 声明、策略、引用 |
> | `ResolvedEnvironment` | 应用用例产物（Sprint 2） | prepare 时 | 与 `EnvironmentRefFact` 同构的事实 |
>
> **不得**把 `interpreter_identity` 做成 `EnvironmentRef` 的必填字段——那会迫使领域层编造或提前解析，
> 两者都会违反"来源无法证实时保留待核实"（根 `AGENTS.md` 第 3 节）。Sprint 2 的 `resolved_input_digest` 由 `ResolvedEnvironment` + `ExecutionSourceBinding` 共同计算。

### 3.5 工作空间位置判定（纯函数）

需求 FR01／功能文档 10.1：工作空间位于**同步盘／网络盘**时**拒绝建立并说明原因**（同步器会破坏排他锁与原子替换语义）。

领域层零 I/O，因此只提供纯判定：

```python
class DriveKind(StrEnum):
    FIXED = "fixed"
    REMOVABLE = "removable"
    NETWORK = "network"
    SYNC_FOLDER = "sync_folder"
    UNKNOWN = "unknown"

class WorkspaceLocationRejection(StrEnum):
    NETWORK_DRIVE = "network_drive"
    SYNC_FOLDER = "sync_folder"

def reject_workspace_location(
    canonical_path: str, drive_kind: DriveKind
) -> WorkspaceLocationRejection | None: ...
```

**规则**

1. `NETWORK` → 拒绝，原因 `network_drive`。
2. `SYNC_FOLDER` → 拒绝，原因 `sync_folder`。
3. `FIXED` / `REMOVABLE` / `UNKNOWN` → 不拒绝（`UNKNOWN` 由调用方决定是否阻塞，领域层不替它决定）。
4. **拒绝必须带原因**，不得只返回布尔值。

> `DriveKind` 由调用方（Sprint 2 的应用用例，经 A 的端口）探测：
> Windows 上网盘映射可用盘符类型判定，同步盘目录可用 `OneDrive` / `OneDriveCommercial` 等环境变量或已知同步器标记判定。
> **本 Sprint 不实现探测**，只实现规则与规则测试。这是"领域规则只算一次、事实由调用方提供"的落地。

### 3.6 `Delivery`：自述与验证事实分离

需求 FR02／功能文档 10.2：**开发自述完成与测试验证完成分别展示**；AI 草稿不作完成证据。

现状问题：`Delivery` 的"完成项 / 未完成项"是自由文本，且无任何字段区分"这是开发自述"还是"已测试验证"，无法满足"分别展示"。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `delivery_id` / `task_id` / `version` | `str` | 身份 |
| `self_report` | `SelfReport` | **开发方自述**，非证据 |
| `verified_in_scope` | `tuple[str, ...]` | 已由测试验证的范围，**只能来自执行事实** |
| `unverified_scope` | `tuple[str, ...]` | 未验证范围，缺省为空但必须可显式列出 |
| `mock_declarations` | `tuple[str, ...]` | 声明的 Mock |
| `run_method` | `str` | 运行方法 |
| `test_data` / `dependencies` / `self_test_evidence` | `tuple[str, ...]` | 数据、依赖、自测证据引用 |
| `changed_modules` / `api_changes` | `tuple[str, ...]` | 变更模块、接口变化 |
| `known_issues` | `tuple[str, ...]` | 已知问题 |
| `submitted_by` | `str \| None` | 提交人 |
| `revision` | `int` | 从 1 起；已确认交付变化形成新修订，不覆盖历史 |

`SelfReport`：`completed`、`incomplete`（均为 `tuple[str, ...]`）。

**不变量**

1. `delivery_id`、`task_id`、`version`、`run_method` 非空。
2. `self_report.completed` 与 `self_report.incomplete` **不重叠**。
3. `verified_in_scope` 与 `unverified_scope` **不重叠**。
4. **`verified_in_scope` 不得由自述推导**：本对象不提供"把 `completed` 复制进 `verified_in_scope`"的构造方法或默认行为；
   `self_report.completed` 非空**不能**使 `verified_in_scope` 非空。测试必须覆盖"自述称已完成但未测试时，`verified_in_scope` 仍为空"。
5. `revision >= 1`。
6. 所有 `tuple[str, ...]` 字段不含空串。

> **重大决定 3：`Delivery` 的兼容性**
>
> 现有 `Delivery` 有 `completed` / `incomplete` 两个顶层字段，`test_deliveries.py` 依赖它们。
> 本次把二者收进 `self_report`，会**影响既有测试**。按"不删除断言、在 PR 中说明"的做法处理：
> 保留 `completed` / `incomplete` 作为**只读属性**（转发到 `self_report`），既有测试不改，同时新增自述／验证分离的测试。
> 若组长认为应当直接改测试，再按裁定调整。**本轮不删除任何既有断言。**

### 3.7 `SourceManifest`（`plain` 内容身份，最小集）

需求 FR01：非 Git 目录保存**文件清单内容摘要、必要内容和差异**；架构文档第 2 节要求记录**复取依赖与可复取范围**。

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `source_scope` | `str` | 选定范围说明 |
| `exclusion_rules` | `tuple[str, ...]` | 排除规则 |
| `files` | `tuple[SourceFileDigest, ...]` | 逐文件：`relative_path`、`size`、`mtime_hint`、`content_digest` |
| `manifest_digest` | `str` | 清单整体摘要，写入 `LocalProjectBinding.manifest_digest` |
| `refetch_dependencies` | `tuple[str, ...]` | LFS、子模块等复取依赖 |
| `refetch_scope` | `str \| None` | 可复取范围；缺失即缺口，必须显式登记而非留空 |

**不变量**

1. `source_scope` 非空；`manifest_digest` 非空；`files` 的 `relative_path` 唯一且为**相对路径**（无盘符、无 `..`）。
2. `content_digest` 非空——**内容身份必须来自实际字节摘要**。
3. `mtime_hint` 只作为变化提示：**任何"文件相同"的判定都不得只依据 `mtime_hint`**。本对象不提供此类比较方法。

> `GitSourceIdentity`（基准提交、未提交新增/修改/删除、差异摘要）属 `git` 形态。架构文档第 7 节把 `SourceSnapshot` 归到
> C 的 `domain/execution/sources.py`，而归属尚待裁定（见 1.2）。为避免与 C 重复定义，本 Sprint **只在 `plain` 形态实现最小内容身份**，
> `git` 形态的身份字段待裁定后再定归属。这是有意留的缺口，不是遗漏。
