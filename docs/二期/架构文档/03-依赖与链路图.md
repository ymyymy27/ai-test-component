# 二期架构03：依赖与链路图

版本：3.3  
更新日期：2026年9月23日  
文档类型：工程设计文档

application/diagrams从已提交记录生成DiagramDefinition与DiagramRevision，经WorkspaceUnitOfWork保存；DiagramRenderPort只渲染，同一图修订供DTO与自包含HTML。

## 1 定义与身份

依赖图来源Module/Dependency，节点=module_id，边=使用者→提供者。链路图来源实际TraceNode，节点=(run_id,attempt_id,trace_node_id)，边仅实际父子/请求关联。源码路径/符号是导航附加属性，不是调用节点身份，重复调用不合并。缺采集以已知范围挂缺口标记，不新增虚构调用。

Definition保存类型、精确来源记录/修订集合、投影策略版本和事实节点/边/缺口；Revision保存定义修订、坐标/折叠/注释、来源、schema_version与导出引用。单模块无依赖边显示不适用，实际业务链路仍可显示。层级结果图/问题关联图不属必交范围。

### 模块职责

本册负责把已提交的记录渲染成可交互图件。图是**记录投影**：不新增未采集的节点，不改变测试事实。

### 图的数据来源

| 图 | 数据来源 | 节点与边 | 需求归属 |
| --- | --- | --- | --- |
| 依赖图 | `domain/project` 的模块与依赖边 | 节点＝模块；边＝使用者 → 提供者 | 需求二期 P2-FR04（**必须实现**） |
| 链路图 | `TraceNode` 与 `EvidenceRef` | 节点＝已采集调用节点；边＝实际采集到的父子或请求关联 | 需求二期 P2-FR04（**必须实现**） |
| 问题关联图 | `domain/review` 的问题与回归关联 | 节点＝问题与执行；边＝复现与回归关系 | 后续可选探索，不属于本次P2-FR04或二期验收；现有问题/回归关系仍用列表与详情承载 |

单模块项目没有依赖边时，依赖图返回"不适用"并说明原因，**不生成空图、不报错**。

## 2 编辑与失效

仅允许布局、折叠和独立注释；保存时校验节点ID、事实边、状态和缺口均未删除/篡改，不能仅检查缺口数量。人工补事实须先采证/执行生成新来源，再重新投影。

来源变化整图标过期，重新生成时按稳定业务节点锚点沿用可匹配布局。未浏览链路不预物化；已发布定义/修订永久保留，缺记录提示缺口，不偷偷用推断补齐旧图。

### 图定义与修订

| 记录 | 核心字段 |
| --- | --- |
| `DiagramDefinition` | 图编号、类型、**来源集合 `[{record_type, record_id, content_revision}]`**、生成策略版本、投影时间 |

**落盘归属**：`DiagramDefinition` 与 `DiagramRevision` 是**投影记录**，按不可变记录经 `WorkspaceUnitOfWork` 提交，编号与修订空间**独立于领域记录**；**不参与判定、不计入统计分母**。报告对图的引用写在**附件索引**里（`diagram_definition_rev` + `diagram_revision`，见第3节），**不进报告必需字段**，缺失时报告照常可读、只标"图件引用缺失"。

规则：图修订只改变布局、折叠和注释；保存前比对来源修订及事实节点/边/缺口集合，不可删改事实。新布局不自动升级报告，已有报告继续引用其冻结图修订。

### 边界

- 图不参与判定：统计、结论上限与缺陷关闭仍由领域层计算。
- 图不替代原始证据：报告中必须同时保留证据索引。
- 不做自动操作录制与回放（仍在三期之外，属独立扩展）。

## 3 展示与导出

面板消费图DTO，不用iframe加载完整HTML；独立HTML只加载内嵌/包内资源，不外部CDN、不含凭据。支持缩放/搜索/聚焦/按需展开，节点跳证据或经定位用例跳源码。导出按统一脱敏，DTO与HTML字段/缺口一致。

报告附件引用definition_revision＋diagram_revision；新布局不自动生成新报告。用户明确重新选图纳入报告时按报告规则生成新内容修订，旧报告仍指原图。图不计入业务分母，不替代原始证据。

验收P2-AC04/05/08：重复函数调用、无源码人工节点、删除事实边/缺口、重新布局、来源变更和导出一致性。

### 验收映射

| 验证主题 | 关键检查 | 场景 |
| --- | --- | --- |
| 可交互 | 图件可打开、可缩放、可搜索、可聚焦 | 二期 P2-AC04 |
| 可跳转 | 节点跳转到对应证据或问题 | 二期 P2-AC04 |
| 缺口如实 | 未采集节点保留缺口标记，不用推断补全 | 二期 P2-AC04 |
| 修订不改事实 | 人工布局调整生成新图修订，原始记录与判定不变 | 二期 P2-AC05 |
| 落盘与归属 | 图定义与图修订经 `WorkspaceUnitOfWork` 提交、编号独立于领域记录、不参与判定与分母；报告引用精确到图修订 | 二期 P2-AC05 |
| 拒绝删缺口 | 保存缺少原定义缺口标记的图修订被拒绝并说明原因 | 二期 P2-AC05 |
| 导出安全 | 导出不含密钥 | 二期 P2-AC05 |
| 单模块项目 | 依赖图显示不适用并说明原因，不生成空图、不报错 | 一期 P1-AC03（单模块规则沿用） |

## 4 数据流与保存合同

| 阶段 | 输入 | 输出及校验 |
| --- | --- | --- |
| 定义投影 | 项目、图类型、来源记录类型/ID/精确修订集合 | Definition含策略版本、事实节点/边/缺口；来源不齐明确缺口 |
| 初始布局 | 已冻结Definition | 新Revision保存坐标、折叠/注释、生成来源和schema_version |
| 人工调整 | 定义/旧修订、expected_revision、允许的布局字段 | 守卫逐项校验事实集合与缺口集合，拒绝增加/删除/篡改事实 |
| 渲染/导出 | 精确Revision、统一投影策略 | DTO和HTML同源，产物按摘要存对象、记录经工作单元发布 |
| 报告引用 | 用户明确选择definition_revision/diagram_revision | 新报告内容修订，旧报告不动 |

定义与修订是records中的投影记录，导出HTML才是objects中的内容产物。只在请求图时投影，不为每条运行提前生成所有图。来源变化把旧图标过期，仍可查看冻结旧修订；重新生成新定义时仅对仍存在的业务ID保留可匹配布局。

缺口无实际trace节点时挂在已知业务范围的缺口项，点击回证据详情，不创建虚构调用；导出即使折叠也保留缺口清单。标签与人工注释按文本净化，不能执行脚本。图无需网络CDN且不替代原始证据。

### 子域结构

```text
application/diagrams.py            # 图定义投影：从记录生成节点与边
infrastructure/adapters/diagram_render.py   # 渲染实现（自包含 HTML）
resources/diagrams/                # 渲染器资源与图件模板
resources/panel/                   # 面板内嵌预览（复用同一图件）
```

端口：`DiagramRenderPort` 在一期 `ports.py` 中只预留**名称与用途**；**方法签名与返回类型在本期（二期）定稿**并登记进 `application/ports.py`，实现于 `adapters/diagram_render.py` 并在 `bootstrap.py` 注册（口径见[总体架构](../../总体架构.md)第4节）。
