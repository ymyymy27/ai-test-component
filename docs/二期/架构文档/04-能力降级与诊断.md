# 二期架构04：能力降级与诊断

版本：3.3  
更新日期：2026年9月23日  
文档类型：工程设计文档

宿主负责探测，应用connectivity负责校验并经工作单元保存，入口不是文件写入者。CapabilityState键=(workspace_id,editor_instance_id,editor_version)，独立修订，不与Environment/ConnectionState混写。

| 类别 | 事实 | 行为 |
| --- | --- | --- |
| 宿主能力 | 面板、MCP配置/登记、文件跳转及调用失败 | 缺项分别给CLI/命令、手动配置、相对路径文字，不改变测试判定 |
| 源码目录权限 | 可读但不可写 | 可固定到可写workdir执行，不修改源仓库 |
| 工作空间权限 | 数据目录不可写 | NOT_READY于写动作；已有记录可查询，不承诺新运行/新导出登记 |
| 项目信任 | 未信任代码/配置 | 不自动执行入口或加载项目MCP，说明宿主信任步骤 |
| 被测环境 | 目标不可达、依赖缺失、数据条件不满足 | 阻塞关联步骤，不伪装业务失败 |
| 模型连接 | 不可用 | 仅降级AI，人工/证据/本地报告继续 |

doctor和面板从同一健康DTO读取READY/DEGRADED/NOT_READY及原因、最近检查记录；单一可替代宿主能力缺失为DEGRADED，核心不可写/不可用才禁止写。环境与宿主按不同来源记录聚合。

启动、显式重检或宿主版本变化时更新，不在每条UI查询重探测。权限和信任变化由宿主事件上报，执行入口仍校验实际操作权限，不能仅信旧缓存。调用失败与能力不存在分开，日志脱敏；重试由connectivity统一，无界面循环。

验收P2-AC02/06/08以及多宿主并发上报、信任/权限中途变化。不把运行时报错写成兼容清单通过记录。

## 1 探测记录与健康合成

CapabilityState保存宿主实例/发行版/版本、探测修订、能力项、supported/unsupported/failed/unknown、错误原因和探测来源。扩展只上报事实；connectivity校验实例/修订后经工作单元保存，不能由宿主直接写records。ConnectionState按环境/连接配置修订记录探测事实，两者不会相互覆盖。

| 状态 | 判断 | 下一步 |
| --- | --- | --- |
| READY | 当前所需本地核心与写入条件就绪，可用能力已核实 | 进入既有流程，不等于测试通过 |
| DEGRADED | 有可替代宿主能力缺失或可选模型/连接故障 | 列缺项、影响动作及替代入口 |
| NOT_READY | 核心/记录写入不可用或所需运行条件无法解析 | 阻止受影响动作，核心可用且已有记录可读则保留插件查询；核心不可用时只能由普通文件工具读取已导出产物 |

健康结果含检查来源/修订、最近确认时间、已完成阶段、未检查项和下一步。一次自检超时只把未完成项标未知，不把前面已确认结果抹掉；可选连接未配置不是所有业务不可用。入口执行时仍检验当前权限，不能拿历史READY绕过新发生的不可写/未信任状态。

### 模块职责

本册负责"宿主缺什么、怎么替代"：各编辑器能力不一致时明确报缺项并给出替代入口，不让单一能力缺失阻塞本地测试。

### 子域结构

```text
application/connectivity.py        # 健康模型与错误分类的唯一实现处（一期已有）
interfaces/local/editor_host.py    # 能力探测结果的接收与暴露
integrations/<editor>/src/         # 各编辑器的能力探测实现
interfaces/tools/cli.py            # aitest doctor 的呈现
```

### 能力探测

| 能力 | 探测内容 | 缺失时的替代 |
| --- | --- | --- |
| 面板宿主 | 能否创建 Webview 容器 | 降级为命令面板或独立窗口 |
| 工具登记 | 能否登记 MCP 工具 | 报告缺项，改为手动触发入口 |
| 文件跳转 | 能否打开文件并定位行 | 给出相对路径与行号文本 |

规则：宿主只上报探测事实，核心connectivity校验后经唯一工作单元保存；区分能力缺失、调用失败、源码只读、数据目录不可写和不受信任，不能把它们统一解释为可无条件执行。

### 诊断与兼容清单

- 健康模型沿用一期：返回 `READY`、`DEGRADED` 或 `NOT_READY`、检查时间及原因；`aitest doctor`、面板诊断与健康检查读取同一份结果。
- 结构化日志记录编辑器类型与版本、能力清单、缺失项、错误分类与相关修订。
- 诊断不返回私有正文、敏感地址参数或密钥。
- 每个编辑器与操作系统组合的实测结果记入 `docs/compatibility.json`；未实测组合不得声明通过。

### 验收映射

| 验证主题 | 关键检查 | 场景 |
| --- | --- | --- |
| 缺项可见 | 缺文件跳转或工具登记时明确报缺项 | 二期 P2-AC06 |
| 替代可用 | 缺面板时仍能通过命令入口完成执行与导出 | 二期 P2-AC06 |
| 不误报 | 能力存在但调用失败时与「缺失」区分开 | 二期 P2-AC06 |

### 边界

- 不实现平台侧健康检查（三期）。
- 不在本模块实现重试策略：重试周期由 `connectivity` 统一定义，界面层只展示。

## 2 按动作依赖降级矩阵

connectivity统一返回动作可用性及原因，UI/CLI不依据全局健康色推断全部动作可用。调用时仍检查真实依赖，不仅依靠缓存。

| 缺失条件 | 可继续 | 必须阻塞 |
| --- | --- | --- |
| 可选模型凭据/网络 | 核心和存储满足时已有规则、手工配置、其他执行与查询 | 依赖该模型的生成/分析 |
| 被测HTTP或核验凭据 | 不依赖该凭据的步骤与历史查询 | 使用该凭据的请求/核验，不回退明文 |
| 被测运行时缺失，核心可用 | 历史查询，记录目录可写时的新导出 | 相应执行方式 |
| 核心运行时缺失/核心不能启动 | 普通工具读取已经导出的文件 | 插件查询、新执行、新导出 |
| 记录目录可读不可写，核心可用 | 已发布事实只读查询 | 新运行、确认、报告/导出登记等写动作 |

P2-AC02/06/08分别注入上述缺失，核对按钮、错误、下一步与持久状态；恢复后不自动重放未知副作用。宿主面板或跳转缺失可替代，不等于核心运行时缺失也有同样替代能力。
