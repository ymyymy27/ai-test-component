# 二期架构04：能力降级与诊断

版本：2.4  
更新日期：2026年9月21日  
状态：修订基线，待实现与实测；文档不代表产品已通过验收。

宿主负责探测，应用connectivity负责校验并经工作单元保存，入口不是文件写入者。CapabilityState键=(workspace_id,editor_instance_id,editor_version)，独立修订，不与Environment/ConnectionState混写。

| 类别 | 事实 | 行为 |
| --- | --- | --- |
| 宿主能力 | 面板、MCP配置/登记、文件跳转及调用失败 | 缺项分别给CLI/命令、手动配置、相对路径文字，不改变测试判定 |
| 源码目录权限 | 可读但不可写 | 可固定到可写workdir执行，不修改源仓库 |
| 工作空间权限 | 数据目录不可写 | NOT_READY于写动作；已有记录可查询，不承诺新运行/新导出登记 |
| 项目信任 | 未信任代码/配置 | 不自动执行入口或加载项目MCP，说明宿主信任步骤 |
| 被测环境 | 目标不可达、依赖缺失、数据条件不满足 | 阻塞关联步骤，不伪装业务失败 |
| 模型连接 | 不可用 | 仅降级AI，人工/证据/本地报告继续 |

doctor和面板从同一健康DTO读取READY/DEGRADED/NOT_READY及原因、最近检查记录；单一可替代宿主能力缺失为DEGRADED，核心不可写/不可用才禁止写。环境与宿主按不同来源记录聚合。

启动、显式重检或宿主版本变化时更新，不在每条UI查询重探测。权限和信任变化由宿主事件上报，执行入口仍校验实际操作权限，不能仅信旧缓存。调用失败与能力不存在分开，日志脱敏；重试由connectivity统一，无界面循环。

验收P2-AC02/06/08以及多宿主并发上报、信任/权限中途变化。不把运行时报错写成兼容清单通过记录。

## 1 探测记录与健康合成

CapabilityState保存宿主实例/发行版/版本、探测修订、能力项、supported/unsupported/failed/unknown、错误原因和探测来源。扩展只上报事实；connectivity校验实例/修订后经工作单元保存，不能由宿主直接写records。ConnectionState按环境/连接配置修订记录探测事实，两者不会相互覆盖。

| 状态 | 判断 | 下一步 |
| --- | --- | --- |
| READY | 当前所需本地核心与写入条件就绪，可用能力已核实 | 进入既有流程，不等于测试通过 |
| DEGRADED | 有可替代宿主能力缺失或可选模型/连接故障 | 列缺项、影响动作及替代入口 |
| NOT_READY | 核心/记录写入不可用或所需运行条件无法解析 | 阻止受影响动作，已有记录可读则保留查询 |

健康结果含检查来源/修订、最近确认时间、已完成阶段、未检查项和下一步。一次自检超时只把未完成项标未知，不把前面已确认结果抹掉；可选连接未配置不是所有业务不可用。入口执行时仍检验当前权限，不能拿历史READY绕过新发生的不可写/未信任状态。
