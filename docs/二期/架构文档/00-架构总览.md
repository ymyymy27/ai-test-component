## 记录演进与交付边界

| 新增内容 | 归属 | 兼容 |
| --- | --- | --- |
| DiagramDefinition/Revision | 应用投影记录，工作单元保存 | 原记录无图则显示缺图，用户可显式生成新图，不推断旧图 |
| CapabilityState | 宿主上报、核心connectivity校验保存 | 与ConnectionState独立修订；不同宿主实例互不覆盖 |
| LocationDTO | application/locations，经源码端口校验 | 缺字段按unknown，新增动作先能力协商 |
| History/Diagram DTO | 已保存来源的查询/显示投影 | 沿用业务结论与永久留存，不新建第二套统计 |

一期面板骨架、三段与报告基础筛选不再放进二期任务；本期只交付历史分组、自检可视化、定位/图以及已承诺的新增编辑器和系统组合。平台、自动录制、任意插桩、证据批采集和AI报告草稿不在该增量内。每个扩展组合分别保留制品和实测证据。

### 与一期的关系

| 主题 | 处理方式 |
| --- | --- |
| 三层判定、统计分母、结论上限 | **不变**，由一期领域层唯一实现 |
| 记录格式与编号 | **既有记录不变**：本地项目编号与内容修订口径一致，不改既有字段语义；**新增投影记录**（`DiagramDefinition`／`DiagramRevision`）与**能力状态记录**（`CapabilityState`），经一期工作单元落盘、编号独立 |

### 二期新增记录与字段的兼容处理

| 新增项 | 归属 | 兼容处理 |
| --- | --- | --- |
| `DiagramDefinition`、`DiagramRevision` | 投影记录（`records/`，编号独立于领域记录） | 旧记录不含该类型时读作"图定义缺失"并保留缺口入口，不重建、不推测；不参与判定与统计分母 |
| `CapabilityState` | 连接/能力状态记录（唯一写入者：核心工作单元；宿主探测上报，`connectivity`校验并编排保存） | 与一期 `ConnectionState` 分记录，各自独立修订，互不覆盖（见[能力降级与诊断](04-能力降级与诊断.md)第1节） |
| `location_state`、`reason` | 定位投影 DTO 字段 | 只增不改：缺失即"不能确认定位"，界面按未知处理，不阻断跳转入口的展示 |
| `Attempt.attempt_index` | 一期执行记录字段，二期沿用 | 从1起；retry_count=attempt_index−1。旧记录仅在可证明尝试顺序时转换，不能凭文件数量推算；无法确定显示未知 |

### 二期的模块落点

| 层 | 新增内容 |
| --- | --- |
| 入口层 | `integrations/<editor>/`：每个编辑器一个目录，互不引用 |
| 接口适配层 | 各编辑器的跳转与装饰器适配；仍调用同一批动作 |
| 应用用例层 | `application/locations.py`统一位置解析，`application/diagrams.py`统一图投影；二者共用来源引用与DTO，通过定位动作导航 |

| 外部能力层 | `adapters/diagram_render.py`：自包含图件渲染 |

### 演进规则

- **加适配器不加分支**：平台与编辑器差异只允许出现在 `infrastructure/` 与入口适配中，应用层与领域层不出现平台判断。
- **各有唯一投影入口**：定位由 `application/locations.py`、图由 `application/diagrams.py` 生成；多个编辑器共用，图导航调用定位动作，不另算位置或各自拼装数据。
- **不做第二套规则**：新增编辑器不实现自己的重试、判定或记录格式。
- **实测才声明**：每个编辑器与操作系统组合实测通过后写入 `docs/compatibility.json`。
- **建设顺序**：先把源码定位、依赖与链路图、面板增量（历史记录页、环境自检可视化、图联动）做出来，再按试点用户真实在用的编辑器与操作系统组合逐个铺开——不做"全部编辑器逐个实测"的全量铺开，其余按需排期。

## 统计与恢复沿用

高级历史及跨编辑器面板沿用一期S/M、E/R/V及当前Attempt优先规则；显示复用来源，不把复用显示成本轮执行。读取SnapshotEnvelope及配对游标，从边界之后续读；二期不另算结论或维护第二套复用状态。
