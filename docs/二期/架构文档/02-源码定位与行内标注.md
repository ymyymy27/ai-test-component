# 二期架构02：源码定位与行内标注

版本：3.2  
更新日期：2026年9月23日  
文档类型：工程设计文档

定位源为IssueRecord/EvidenceRef/TraceNode已有位置，绑定source_snapshot_id、内容修订、项目相对路径、行/符号及来源。无实际采集位置保持未知，不从图布局或AI猜测补造。

## 1 用例与状态

application/locations经SourceSnapshotPort读取目标元数据/冻结内容，绝不直接文件I/O。resolve_location默认选择可复取历史快照；若用户要求当前文件，先比较目标记录的路径/大小/mtime。mtime比较快照中该文件的mtime，不能比较快照创建时间。

| 状态 | 含义与动作 |
| --- | --- |
| unknown | 定位来源或校验不足，说明原因，不当成当前一致 |
| snapshot_verified | 已取得并校验冻结内容，可在只读快照按原位置打开；不证明当前文件相同 |
| metadata_match | 元数据相同，仅候选一致；可打开历史快照，当前文件需显式校验 |
| current_verified | 用户显式verify_current_file完成磁盘摘要与干净编辑器文档一致性核对，且目标/文档版本未变，才允许按原行跳当前文件 |
| stale | 当前内容不一致，提示重新固定源码或打开原快照，不错指新内容 |
| missing | 必要快照/路径不可用，明确缺口 |

同大小同mtime仍可能异内容。行内标注按文件批量校验，同一文件共享结果，不把一个文件的结论用于所有文件。读内容仅在用户显式校验目标时发生，不递归全仓；面板打开/切页/进度/历史查询不触发该读取。

### 模块职责

本册负责"从记录回到代码"：把问题、证据与链路节点上的定位信息在编辑器里打开并标注。定位是**记录的投影**，不产生新事实。

### 不在本册的范围

- 图形化依赖与链路视图：[依赖与链路图](03-依赖与链路图.md)。
- 跨语言静态影响分析：不在二期，也不在一期。

## 2 跳转与安全

输出LocationDTO：schema_version、project_id、binding_revision、snapshot_revision、relative_path、line_hint、symbol、location_state、reason、target_kind（snapshot/current）、verified_digest、document_version、verification_request_id、editor_instance_id、document_id、display_digest。line_hint为可空正整数；symbol为可空定位提示；reason为稳定原因码及可读说明，无异常为null。verified_digest仅在内容已核实后填写；document_version仅在当前编辑器文件已核实后填写。宿主仅消费DTO调用编辑器只读打开/装饰器。当前文件需先满足第4节干净缓冲区守卫；若校验前已有未保存编辑、校验期间/之后文档变化或无法证明显示内容对应磁盘，均不得标current_verified；绑定切换迟到响应不进入当前视图。

路径归属、链接逃逸、缺文件和权限错误经端口校验；无法复取历史快照如实报错。若需要历史只读虚拟文档，由宿主能力声明并通过核心分块取冻结字节，不把存储裸路径暴露成任意文件访问。

验收P2-AC03/04：正常旧mtime、同元数据异内容、修改/缺失文件、多文件批次、校验后再编辑、目录切换等均不误跳；标注不改业务事实。

### 跳转与标注

| 动作 | 行为 | 边界 |
| --- | --- | --- |
| 跳转 | 打开对应文件并定位到函数或行 | 只读打开；不修改文件 |
| 行内标注 | 在本行展示相关的问题、Mock 声明与证据缺口 | 展示层行为，不改变断言、缺陷或档位 |
| 缺口提示 | 该行关联的证据缺失或未采集时显式标出 | 不隐藏缺口，不用推断补全 |

技术约束：

- 编辑器装饰器与跳转 API 由入口适配实现，应用层只输出"路径 + 行号 + 标注内容 + `location_state` + `reason`"的投影结果；**`location_state` 与 `reason` 是 DTO 必需字段**，否则面板无法区分"能跳"与"只能提示"。
- 标注内容由 `application/locations.py` 统一投影，多个编辑器共用同一份数据，避免各自拼装。
- 标注更新不得阻塞编辑；大文件或大量标注按可视区按需渲染。
- **迟到的跳转响应**按一期规则处理（[编辑器接入](../../一期/架构文档/05-Trae接入.md)第2节）：只更新原目录的缓存并标注"非当前视图"，不进入已切换项目或已切换快照的视图。

### 验收映射

| 验证主题 | 关键检查 | 场景 |
| --- | --- | --- |
| 可跳转 | 相对路径与行号正确打开（`target_kind=current`且`location_state=current_verified`；冻结内容使用`target_kind=snapshot`且`location_state=snapshot_verified`） | 二期 P2-AC03 |
| 不编造 | 无法确认的定位保持未知并说明原因（`reason` 非空） | 二期 P2-AC03 |
| 变更保护 | 文件已变时返回 `stale` 并提示重新固定，**不指向变化后的内容**；快照缺失返回 `missing` | 二期 P2-AC03 |
| 标注只读 | 行内标注只做展示，不修改代码、不触发新工具、不改变断言与缺陷状态 | 二期 P2-AC04 |

## 3 来源字段与调用顺序

| 来源 | 可用位置 | 不能推断的内容 |
| --- | --- | --- |
| IssueRecord | 明确采集的相对路径、函数/行号、源码快照 | AI候选根因不是已核实位置 |
| EvidenceRef | 采集位置、关联节点与来源修订 | 日志提及路径不自动成为允许读取路径 |
| TraceNode | 实际节点附带位置 | 同函数多次调用不是同一节点 |

resolve_location先核对项目/绑定/来源，再校验受限路径；target_kind=snapshot读取可复取冻结内容。用户选current时先返回目标元数据状态，明确verify_current_file后只读取目标文件计算内容摘要。返回DTO携目标、绑定修订及第4节request/document身份；宿主再次核对dirty状态、显示内容摘要和版本后才跳转。校验期间或之后变化则标失效，不使用旧行号继续装饰。

同一文件可视区标注共用一次目标校验；不同文件各自有结果，不能整张图用一个current_verified。缺虚拟文档能力时展示位置/原因和可用证据，不暴露任意对象库路径。批量装饰只聚合显示，不产生新的源码分析或业务执行。

### 定位数据的来源

定位信息只来自一期已经保存的记录字段：

| 来源记录 | 定位字段 |
| --- | --- |
| `IssueRecord` | 相对代码路径、函数或行号；无法确认时记为未知及原因 |
| `EvidenceRef` | 采集位置与关联节点 |
| `TraceNode` | 节点对应的代码位置（若已采集） |

约束：

- 路径一律使用**相对本地项目根目录**的路径，不写机器绝对路径。
- 定位必须绑定 `SourceSnapshot`（源码快照）与内容修订；快照缺失或文件已变更时提示"重新固定源码"，不指向变化后的内容。
- **不得编造定位**：无法确认时保持未知，并写明原因（例如"缺少后端采集"）。

### 定位校验：元数据候选与显式内容验证

"文件是否已变、定位能否打开"必须有唯一的判定归属，否则不是面板违反"视图不读文件"、就是编辑器插件被迫自行判断源码是否已变。因此新增一个**只读用例**，走一期已经定义好的增量比对路径：

| 项 | 约定 |
| --- | --- |
| 用例 | `application/locations.py::resolve_location(project_id, binding_revision, snapshot_revision, relative_path, line_hint, target_kind, editor_context=None)` |
| 返回 DTO | `{schema_version, project_id, binding_revision, snapshot_revision, relative_path, line_hint, symbol, location_state, reason, target_kind, verified_digest, document_version, verification_request_id, editor_instance_id, document_id, display_digest}` |
| 失败降级 | 元数据不可读时返回 `reason`，界面显示"无法确认位置"，**不探测内容也不猜测** |

## 4 当前编辑器文档与校验请求

document_id为宿主分配的不可复用文档会话编号，真实URI仅在宿主本地映射；核心只接收项目相对路径，不因此引入绝对路径字段。

首版不对未保存缓冲区作源码一致性证明。用户选择当前文件时，宿主提供editor_context：editor_instance_id、document_id、document_version、dirty、request_id、binding_revision及干净文档的display_digest。文档dirty即返回unknown、reason=UNSAVED_BUFFER；若另有可信内容不一致事实可为stale。默认提供“打开冻结快照”及“自行保存后重新校验”，插件不自动保存、回滚或改写用户代码。确认“按磁盘版本运行”不等于允许对不同的编辑器缓冲区贴旧行号。

verify_current_file携同一editor_context，核心只经SourceSnapshotPort读取受限目标文件原始字节并计算摘要/身份，同时保留编码、BOM、换行方式和可供显示内容核对的display_digest（按确定编码解码、去编码标记BOM后的显示字符取UTF-8，不折叠换行或Unicode；原始字节摘要仍含BOM）。核心对比宿主请求所带display_digest、目标显示摘要和冻结原始摘要，缺字段、不符、无法可靠解码或目标读取中变化均不给current_verified。宿主在响应后再次核对同一已打开的干净文档：文档会话ID、项目绑定、editor_instance_id、document_version未变，重新取得的显示文本摘要仍与display_digest一致；满足全部条件才应用current_verified和原位置。宿主计算的是文档事实摘要，不读取任意文件或另算业务结论。

LocationDTO增加verification_request_id、editor_instance_id、document_id、display_digest；current_verified时document_version及这些字段必填，snapshot_verified不套用当前缓冲区身份。当前文件的验证结果必须携完整请求身份由宿主二次确认后消费；任何二次核对失败立即降为unknown或已证明的stale、移除装饰并列原因，不继续展示current_verified。旧客户端没有干净文档摘要能力时通过能力协商只提供历史快照或位置文字，不用磁盘相同假装显示文本相同。

后续编辑、文档重新加载、关闭重开、磁盘变化通知、项目/绑定/宿主切换均使当前验证缓存失效；不以document_version数字恰好相同跨文档复用结果。未保存缓冲区内容无需发送到核心，首版只处理干净文档及其事实摘要。六态枚举由第1节唯一维护，未知枚举降为unknown和能力不足原因，不能当“忽略未知字段”继续定位。

P2-AC03/04覆盖校验前dirty、校验中编辑、迟到响应、关闭重开、不同编辑器版本号碰撞、CRLF/UTF-8/BOM、磁盘相同但显示不同、六态与旧客户端。未知和已证明变化分开，不用stale掩盖没有核实。
