# C包一期实施计划

版本：0.1  
日期：2026-09-24  
分支：feat/package-c-execution  
状态：草案，代码骨架已开始  
依据：一期架构文档《02-执行与证据》、一期实施方案第3节《只冻结四类跨包合同》

## 1. 目标

C包完成一期“执行与证据”纵向切片：

1. 定义Run、Step、Attempt及执行来源验证的纯领域模型。
2. 定义Evidence、TraceNode、MockDeclaration、Verification及缺口模型。
3. 冻结ExecutionFacts v1.0跨包合同和成功、失败、未知三类夹具。
4. 后续实现runner、recovery、evidence_review和七类执行适配器。
5. 始终保持“执行事实”和“业务判定”分离。

本计划采用单机Mock模式推进，不因D包暂时无法同步而阻塞。跨包枚举先由C包按文档语义推导，D包确认后再做兼容修订。

## 2. 边界

C包负责：

- L1、L2、L3执行调度和串行依赖处理。
- 暂停、取消、重试和恢复的执行事实。
- spool、输出块、游标、ExitFact和检查点。
- 源码实际执行来源验证。
- EvidenceRef、TraceNode、MockDeclaration和Verification证据事实。
- ExecutionFacts快照。

C包不负责：

- 最终业务结论、用例聚合、E/R/V/P/F/U/H和统计。
- 连接重试资格、次数和间隔；该项归A包connectivity。
- 计划来源的创建和定义；该项归B包，C只记录实际验证事实。
- 报告、面板和入口实现。
- 凭据正文、未过滤输出和不可逆敏感材料。

## 3. 目录与产物

- domain/execution/runs.py：执行状态、Run、Step、Attempt及执行事实。
- domain/execution/sources.py：源码快照、源码检查和ExecutionSourceVerification。
- domain/evidence/evidence.py：证据、真实性、链路、Mock和核验。
- contracts/execution_facts.py：版本化ExecutionFacts合同。
- contracts/schemas/ExecutionFacts.json：由合同源码生成，不手工编辑。
- tests/contracts/fixtures/execution_facts：成功、失败、未知三类夹具。
- 后续application/execution和infrastructure/adapters/execution按纵向用例分片实现。

## 4. 实施阶段

### 阶段1：领域词汇和合同冻结

产物：枚举、纯领域对象、ExecutionFacts v1.0。

完成条件：领域层不依赖Pydantic；合同层不直接绑定领域对象；Schema可由脚本重新生成。

### 阶段2：启动、采集和终态

产物：ExecutionRequest、ExecutionHandle、输出块、游标、ExitFact、检查点、ExecutionPort类型协议和SerialRunner调度骨架。

当前状态：类型协议、结果对象、串行调度、Spool输出块持久化、假适配器、Mock串行闭环、真实CommandAdapter及Spool前敏感信息过滤已完成；多流独立游标、对象库发布、检查点持久化和崩溃恢复尚未实现。

完成条件：意图先于执行；未核实句柄不得伪造未执行；退出码和采集完整性分离。

### 阶段3：恢复和依赖失效

产物：句柄重关联、spool抢救、pending_verification、依赖失效事实。

完成条件：重启不重复业务命令；未知副作用不自动重放；新Attempt不继承旧授权。

### 阶段4：证据与核验

产物：EvidenceRef、TraceNode、MockDeclaration、Verification和缺口。

完成条件：调用链只使用实际关系；独立核验不拼接原调用树；Mock声明不可原地覆盖。

### 阶段5：适配器和集成

产物：PythonChecks、Command、Http、Verification、ManualEvidence、Agent、ExternalResult。

完成条件：适配器只返回结构化事实；业务判定由统一领域规则执行。

## 5. 验证策略

- 领域单元测试：状态边界、attempt_index、源码验证、依赖消费和证据不可变性。
- 合同测试：成功、失败、未知三类ExecutionFacts夹具。
- Schema测试：JSON Schema和Pydantic源码一致。
- 架构测试：domain不得导入Pydantic、contracts、application或infrastructure。
- 恢复测试：核心退出、包装器失效、进程先退出、恢复再次中断。
- 安全测试：跨块凭据、HTTP回显、模型响应、异常终止和导出投影。
