## 4 ExecutionFacts跨包合同

主要文件：

- src/aitest/contracts/execution_facts.py
- src/aitest/contracts/schemas/ExecutionFacts.json

设计：

- 合同版本：aitest.execution-facts/1.0。
- 一个ExecutionFacts对象只表示单个Run的一致快照。
- 顶层包含Run、Step、Attempt、当前Attempt、证据、源码验证、独立核验、Mock、依赖失效、未知原因、缺口和覆盖摘要。
- 包含准确修订、commit和游标。
- 不包含最终E/R/V/P/F/U/H。
- 不包含凭据、未过滤内容或完整大对象。
- Pydantic模型使用frozen和extra forbid。
- retry_count必须等于attempt_index减1。
- step_revision必须与step_revision_ref一致。

成功、失败和未知夹具：

- tests/contracts/fixtures/execution_facts/success.json
- tests/contracts/fixtures/execution_facts/failure.json
- tests/contracts/fixtures/execution_facts/unknown.json

## 5 应用层实现

主要文件：

- src/aitest/application/ports.py
- src/aitest/application/execution/runner.py

ExecutionPort：

- start(request) -> ExecutionHandle
- inspect(handle) -> ExecutionInspectionResult
- collect(handle, cursor) -> ExecutionCollectionResult
- request_stop(handle) -> StopRequestResult

SpoolStore：

- persist_blocks(blocks) -> SpoolManifest
- read_manifest(attempt_id) -> SpoolManifest

SerialRunner：

- 计算ready、blocked、waiting和terminal步骤。
- 串行启动Attempt。
- 轮询inspect直到终态或达到max_polls。
- collect输出、ExitFact和结构化结果。
- 将封口捕获块保存到SpoolStore。
- 回写Attempt和Step状态。
- 上游失败只阻塞依赖它的下游。
- pending_verification保持下游waiting。
- 校验Step、Attempt、ExecutionRequest身份一致。

## 6 基础设施实现

### 6.1 FileSpoolStore

文件：

- src/aitest/infrastructure/file_store/spool.py

功能：

- 只接受complete为true的封口块。
- 按spool/<attempt_id>/保存块和manifest。
- 正文按不可变文件写入。
- 摘要使用sha256。
- 读取时重新验证长度和摘要。
- 拒绝路径穿越。
- 同位置同内容幂等，不同内容报冲突。
- 清单原子写入。

## 9 关键决策

- D包未同步时先采用C包推导状态，合同冻结后再做兼容修订。
- 内部使用纯领域对象，Pydantic只用于跨包合同。
- ExecutionSourceVerification只记录实际验证事实，不复制B包源码定义。
- 当前Mock模式允许适配器返回CapturedOutputBlock，由Runner写SpoolStore。
- 最终真实包装器必须先过滤和封口写spool，核心只读取封口块。
- 退出码只表示执行事实，不直接派生业务通过。
- Spool保存成功前不得更新为completed。
- 未实现或无法确认的路径保持pending_verification或缺口。
