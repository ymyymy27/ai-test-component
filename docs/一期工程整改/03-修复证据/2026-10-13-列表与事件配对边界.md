# 列表与事件配对边界（2026-10-13，第二十八批）

来源任务：本轮目标第 8 项「问题/报告详情读取环」中"视图快照与配对游标"的可落地部分。

## 1. 冻结原文与缺陷定位

| 出处 | 原文要点 |
| --- | --- |
| 架构 06 §4 | 「`SnapshotEnvelope` 同时返回 view、workspace_id、instance_id、writer_epoch、generation、commit_seq 和 `snapshot_cursor`。核心从同一已发布清单读取视图及其有效事件边界，**不能先读视图再取"此刻最新"游标**」 |
| 架构 06 §136 | 「报告/问题/运行列表使用有限 QuerySpec…**列表返回 commit 配对摘要**，不展开全部修订或附件；索引恢复状态与"没有记录"分开」 |
| 架构 06 §8 | 「响应含 IssueListProjection、**commit_id**、实际筛选摘要、next_cursor 和可用动作」 |
| AC-001 §147 | `query()` 返回 `RecordQueryResult(status, items, next_cursor)`（三字段形状冻结） |

**缺陷定位**：存储层 `IndexQueryResult` **已有** `commit_id`/`event_cursor`/`generation`/`index_version`（`query_spec` 同一次读取产出），但：
1. `FileRecordRepository.query` 把它转成三字段的 `RecordQueryResult`，**丢弃了 commit_id 与 event_cursor**；
2. 应用端口 `RecordPage` 只有 `items`/`next_cursor`；
3. `query` 动作响应因此只有 `items`/`next_cursor` —— 面板无法把"这一页"与"事件续读游标"配对，只能退化成"先读列表再取此刻最新游标"，正是 §4 明令禁止的做法。

## 2. 本批落地（不改冻结形状）

| 项 | 说明 | 触点 |
| --- | --- | --- |
| `RecordQueryPage` | 存储合同的 `RecordQueryResult` 三字段**原样保留**，边界由新结构并行返回（含 `replace_boundary` 保留边界不漂移） | `src/aitest/infrastructure/file_store/records.py` |
| `FileRecordRepository.query_page` | 一次索引读取同时产出结果与边界；`query` 改为 `query_page(...).result`（行为不变） | 同上 |
| `RecordPage` 边界字段 | `commit_id`/`event_cursor`/`generation`/`index_version` 可选；取不到即 `None`（未知），**不退回"此刻最新"水位** | `src/aitest/application/planning/substrate.py` |
| 适配层透传 | `substrate_adapter.query` 优先调用仓库的 `query_page` 并只取**同一页**的边界（类型严格：非 int/空文本一律 None） | `src/aitest/application/planning/substrate_adapter.py` |
| 入口响应 | `query` 响应新增 `commit_id` 与 `event_cursor`（架构 06 §8/§136） | `src/aitest/application/usecase_registry.py` |
