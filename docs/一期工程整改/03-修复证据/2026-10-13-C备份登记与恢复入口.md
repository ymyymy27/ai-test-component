## 1. 交付内容

| 项 | 说明 | 触点 |
| --- | --- | --- |
| `backup mode=create`（默认） | 既有受控备份；回执新增 **`backup_id` = 清单摘要**（内容寻址身份：不新增记录类别、不可能"同名不同内容"） | `application/maintenance/backup.py` |
| `backup mode=inspect` | 读回备份登记（`backup_id`／目标／类型／创建时校验与完整性／文件数／字节数／缺失清单／目标是否仍存在）；`verify=true` 时**现场复核闭包**（含"备份后塞入未登记文件"这类破坏）；可按 `backup_id` 过滤；**只读**，任何受控会话可用 | 同上 + `infrastructure/file_store/maintenance.py::backup_facts` |
| `backup mode=restore` | 按登记的 `backup_id` 恢复到**新的空目标**：先现场复核源（不信任创建时结论），再调用存储端口恢复（逐文件摘要核对、越界清单整体拒绝、非空目标拒绝）；回执如实登记**尚未完成的后置条件** | 同上 |
| 后置条件如实登记 | `next_steps=["open the restored copy with a core so startup recovery and index rebuild run before any business read"]`、`gaps=["index_rebuild_not_performed", "active_attempts_pending_verification_via_startup_recovery", "double_takeover_check_not_performed"]`——本动作**不假装**完成了索引重建、活动步骤待核实标记与双接管检查 | 同上 |
| 端口扩展 | `BackupStorePort` 增 `restore(*, backup, target)`；`BackupAuditPort` 增 `backup_facts()` | `application/ports.py` |
| 边界 | 恢复目标同样必须**工作空间之外的绝对路径**；恢复不覆盖、不删除任何既有材料；源复核不通过时**不创建目标目录** | 同上 |

## 3. 未做与为什么

- **恢复副本的索引重建**：本动作只做恢复与完整性核对；索引是投影，重建需要打开副本的核心装配流程（架构 04 §13「索引损坏或缺失时重建受影响分片」）。回执把"必须先经启动恢复再业务读取"写成 `next_steps`，没有把它算作已完成。
- **活动/未知步骤仅恢复为待核实**：备份闭包本身不复制在途 spool/事务（`excluded_active` 已登记）；attempt 记录在 `records.json` 里，其"待核实"化由打开副本时的启动恢复流程负责（`RECOVERY_REQUIRED` 路径）。本动作不重写恢复副本的记录（那需要冻结的恢复语义，不在本批）。
- **不允许双工作空间接管同一 Attempt** 的检查未实现（回执登记为缺口）。
- 迁移前的备份位置参数（§9 独立存储）、跨进程维护态、`return_stage`、`request_regression` 仍未做；真实主机与真实掉电未验收。
