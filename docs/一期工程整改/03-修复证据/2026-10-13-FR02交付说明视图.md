## 1. 本轮核对到的合同原文（决定"能不能自己写投影"）

| 出处 | 原文要点 |
| --- | --- |
| AB-001 §1.27 / CORE-001 §1.40 | `submit_delivery` 参数**严格**为 `project_revision`、`expected_revision=0`、`submission_id`、`delivery_ref{delivery_id,record_revision}`、`source_ref{snapshot_id,record_revision}`——**没有 run 引用**；「**新正式提交拒绝历史自填 `verified_in_scope`；所有验收项初始仍未验证，不从自述推导结论**」；末句「**实际新执行与独立核验的交付验证投影**、面板及真实宿主验收**仍待接通**」 |
| BC-001 §374/§481 | 「`verified_in_scope` 只能来自执行事实，自述非空不会使其非空」 |
| BD-001 §7.2 | 自述与验证**分列两处**；`verified_in_scope` 为空而 `self_report.completed` 非空 ⇒ 显示**待验证**；AI 草稿不是完成证据 |
| 功能 §14 | `verification_state` ∈ {必要核验未完成, 材料无效, 核验有效} |
| 功能 §4/§401 | 「开发自述完成、实际测试完成和未验证范围**分别展示**」 |

**结论**：
1. 「所有验收项初始仍未验证 + 拒绝历史自填」是**已冻结**的写侧语义，**既有实现与用例已覆盖**（`submission_content` 拒绝调用方自填与已存非空值；正式提测回执 `verified_in_scope=[]`、`unverified_scope=acceptance_item_ids`、`verification_state=required_verification_incomplete`）；
2. **投影写入点仍未冻结**——合同自己写明该投影「**仍待接通**」，且载体（`DeliverySubmission`）**没有 run 引用**，无法从提测记录唯一定位"哪次运行"的验证事实。按"不猜"原则不自行选一种解释（否则宿主/面板/迁移各写一套口径）。
