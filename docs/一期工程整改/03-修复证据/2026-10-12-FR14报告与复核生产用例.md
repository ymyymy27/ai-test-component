## 1. 交付内容

| 项 | 说明 | 触点 |
| --- | --- | --- |
| 报告修订持久化 | 新聚合类型 `report`（schema `aitest.report/1.0`），按内容修订追加、不可变；`report_intent` 同意图幂等 | `application/review/saved_reports.py` |
| 判定由事实派生 | `create_report` 用**已提交执行事实**（`build_decision_facts` + `evaluate_review`）求唯一业务结论/等级/缺口/覆盖；调用方只能给 `report_id`／`run_id`／`issue_ids` | 同上 |
| 冻结输入由仓储派生 | 范围修订与名称（读准确 `acceptance_scope` 修订）、来源身份、环境、规则、验收、模板与计划修订引用均取自已保存准备与范围；报告**不接收**这些参数 | 同上 |
| 依据确认只在权威路径核对 | 抽出 `application/review/authoritative_basis.py`：`SavedCaseBasisCheck` 读已保存准备 + `SavedCaseBasisReader` 受控确认链，问题关闭与报告共用**同一实现** | `authoritative_basis.py`、`saved_defects.py`（改为复用） |
| 问题修订冻结 | 报告的 `issue_revisions` 按仓储**当前修订**冻结（只收标识），并据此派生阻塞问题集合传入判定上下文 | `saved_reports.py` |
| 本地复核持久化 | 新聚合类型 `local_review`（schema `aitest.local-review/1.0`）：绑定**准确报告修订**，复核人取受控会话身份；钉住错误修订即显式冲突 | 同上 |
| `reports.list`／`reports.by_id` 摘要 | payload 带 `report_id`／`run_id`／`business_outcome`／`content_revision`／`published_sequence`，使固定目录查询可命中 | 同上 + 既有 `infrastructure/file_store/index.py` |
| 动作接入默认装配 | `create_report`／`record_local_review` 真实可派发并由 doctor 广告；默认可派发动作 46 → **48** | `interfaces/local/d_registration.py`、`bootstrap.py` |

## 3. 未做与为什么

- **`export_report` 未实现**：导出键（`ReportExportKey`：报告修订 + 复核集合 + 导出类型 + 脱敏策略版本 + 附件引用）、幂等复用同一制品、Markdown 摘要与可携带证据包的 manifest 摘要/排除原因仍未落地；`infrastructure/exports.py` 仍是占位，`ReportArtifactPort` 仍无实现。这是下一批的主目标。
- **`copy_repair_brief` 未实现**：分册定义了内容与脱敏顺序，但未定义是否持久化与幂等键。
- **`request_regression` 未实现**：三分册未定义输入/记录类型/幂等键（合同缺定义，非实现遗漏）。
- **判定中的断言结果仍为空**：生产端尚无 `AssertionOutcomeFact` 生产者（D-02 未闭合），因此报告如实为 `incomplete` 且带缺口，**不伪造 passed**；`policy_version` 取单一现行标签 `1.0`（分册没有带版本的策略来源）。
- **面板/MCP 对报告与复核的展示未接**，真实 Trae 端到端未验收。
