## 1. 逐项修复与关闭证据

### C-15 默认快照身份/字段/执行目录错接

| 项 | 修复前 | 修复后 |
| --- | --- | --- |
| 业务来源 → 技术固定清单 | 解析器把业务 `source-*` 直接交 `StartMaterializer`/`FileSourceSnapshotStore`，报 `SnapshotError: pinned source snapshot identity is invalid` | `SavedActionResolver` 经注入的 `pinned_snapshot_ref`（`SourceAnalysisService.verify_saved`：按准确修订读回业务记录并逐 blob 复核）取技术 `snap-*`；缺映射即失败关闭 |
| provider 字段 | 读 `snapshot.snapshot_id`（合同里没有该键） | 读 `snapshot.source_snapshot_id` + `record_revision`；技术清单无 `content_identity`，内容身份改为按唯一口径**重算** |
| 实际执行目录 | `ExecutionRequest.materialized_snapshot_ref` 填 snapshot_id，默认注册入口把它当 cwd | 填**实际固定 workdir**（`workdirs/<run_id>`） |

### C-15 同族新暴露缺陷（修复过程中发现，原报告未列）

1. **冻结步骤截止读取错位**：截止声明在环境记录（`environment.step_timeout_seconds`），而冻结 `EnvironmentRefFact` 投影不带该字段。解析器只读投影得到 `None`，授权侧读环境记录得到真实毫秒数，默认链必在 `ApprovalRequired: resolved execution must use the frozen step timeout` 处阻塞。现由注入的 `read_step_timeout` 从**同一权威来源**读取。
2. **夹具 `cwd_mapping` 语法过时**：`tests/support/prepared_run_factory.py` 用自由文本 `<project-root> -> workdirs/run-1`，而裁定 1A（AB-001 1.35 / DEC-011）要求 `workdir:<安全相对路径>`，准入必须拒绝前者。夹具与由它生成的四份功能夹具已改为 `workdir:.`（重新生成，不手改夹具）。

### C-16 来源核验丢弃失败事实、SYNTAX 未实际检查

| 关闭条件 | 落地 |
| --- | --- |
| 语法必须实际检查 | 探针子进程在**登记解释器**下逐个 `.py` `compile()`；有错即 `mismatch` + `source_syntax_error:<path>` |
| 全部登记模块 | 逐模块核对实际加载文件（必须在固定 workdir 内）与字节摘要；导入失败/无文件保留 `unverified` 缺口；命名空间包按"无文件且无错误"处理，若反而加载出文件即 mismatch |
| 入口与解释器事实 | 入口取冻结参数指向的物化实际路径；解释器取探针自报 realpath 与冻结值比对（不再回声冻结值） |
| 失败分类 | 探针起不来 → `BLOCKED`/`environment_unreachable`（受控阻塞，不再泄漏未处理的 `RuntimeError`）；语法/摘要/越界 → `mismatch` |
| 永久原始输出 | 探针 stdout 经内容寻址对象库保存，引用写入核验记录的 `evidence_refs` |

仍未实现并如实保留为缺口：`APPLICABLE_BUILD` 与显式 `MINIMAL_START`（合同未冻结其字段来源）。

### D-10 事实适配守卫

- `_source_state`：同一快照内**集合级**判定；任一 `verified` 之外的状态或带 `gap_ids` 的核验 → `unverified`。
- `_case_executed`／`_case_pending`：只认当前 Attempt（`is_current=False` 不再计 E／pending）。
- `_required_evidence_valid`：当前 Attempt 必须存在、为当前尝试、已完成、采集完整；声明必需证据的步骤要求该 Attempt 下**每条**证据通过完整性/脱敏/投影/缺口校验，且有效证据数不少于声明项数。

### A-19 锁定安装

`uv lock` 按声明范围重新解析：`requires-python = ">=3.11, <3.14"`（原 `==3.13.*`），新增 97 行跨版本 wheel/解析标记。`uv lock --check` 退出 0；在**全新**环境（`UV_PROJECT_ENVIRONMENT=.runtime/uv-locked-venv`）执行 `uv sync --locked` 退出 0，CPython 3.13.13 下真实导入 `aitest`／`pydantic`／`portalocker`。3.11/3.12 的**运行**复核与 CI 锁定门禁仍未做。
