## 1. 冻结原文（架构 04 §12「查询索引与按需读取」）

> 对象发布时流式计算完整摘要；**分块清单记录总大小、固定顺序块ID/长度/摘要和完整对象摘要**，块清单纳入已提交引用。**按需范围读取先校验归属及块清单，再读取并验证触及块**；没有受信分块清单的旧对象须先**完整校验并建立可复用结果**，不能每个分页重复哈希整个对象。仅mtime/大小相同不能证明内容不变；**校验缓存绑定实际内容摘要、已提交块清单及受控对象身份，发现对象变化或异常立即失效**。

> 效率核对以访问范围为准：列表只读取摘要页、**详情只读取所选对象块**……观察实际读写路径和重复计算以发现退化。

## 2. 本批落地（代码）

| 项 | 说明 | 触点 |
| --- | --- | --- |
| `ChunkRef` / `ChunkManifest` | 固定顺序块（块号/偏移/长度/摘要）+ 总大小 + 完整对象摘要；构造即校验：块号顺序、偏移从 0 连续、块长不超声明块大小、长度和等于总大小、空对象无块 | `src/aitest/infrastructure/file_store/object_chunks.py` |
| 严格 payload | `aitest.object-chunk-manifest/1.0`：未知字段、缺失字段、非映射条目、非法摘要一律拒绝（不可信清单不得用于范围读取） | 同上 |
| `read_range` | 先校验归属（项目/摘要/大小/相对路径与 `read_bytes` 同一套底线），再取**受信清单**（必须与 `ref.digest`/`ref.size`/块大小一致），**只读取并逐块验证触及块**；块摘要不符即删除清单并拒绝；无清单的旧对象先 `read_bytes` 完整校验并**建立可复用清单** | `src/aitest/infrastructure/file_store/objects.py` |
| 路径复用 | 把归属/路径校验提取为 `_object_path`，`read_bytes` 与 `read_range` 共用（行为不变） | 同上 |
| 缺失对象 | 范围读取时对象字节不存在 ⇒ 结构化 `ValueError("object bytes are unavailable")`，不泄漏 `FileNotFoundError` | 同上 |

**没有改动**已冻结的 `StoredObjectRef` 形状（清单是读取侧建立、按对象摘要绑定的校验缓存），因此不触碰 AC-001 与公开 DTO/Schema。
