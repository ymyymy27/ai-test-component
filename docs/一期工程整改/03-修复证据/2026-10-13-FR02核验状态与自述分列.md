## 1. 改判依据（分册原文）

| 出处 | 原文要点 |
| --- | --- |
| 功能 §14 状态分类 | 「**`verification_state` 表示必要核验未完成、材料无效或核验有效**。三个状态不能由一个'待核实'布尔值替代」 |
| BD-001 §7.2 | 「开发自述完成与测试验证完成**分列两处**，不得合并为一个'完成'字段」；「`verified_in_scope` 为空而 `self_report.completed` 非空时，必须显示为**待验证**，不得显示为已完成」；「AI 草稿不作为完成证据」 |
| BC-001 §374/§481 | 「`verified_in_scope` 只能来自执行事实，自述非空不会使其非空」 |
| 功能 §736 / 需求 P1-FR02 | 报告分别展示开发交付状态、测试验证状态及未验证范围 |

## 2. 修了什么

| 项 | 说明 | 触点 |
| --- | --- | --- |
| 冻结词汇 | 新增 `VerificationState`（`required_verification_incomplete` / `material_invalid` / `verification_valid`），与功能 §14 逐字一致 | `domain/project/context.py` |
| 权威派生 | `Delivery.verification_state`：有已验证范围 ⇒ 核验有效，否则 ⇒ 必要核验未完成；`material_invalid` 由材料检查决定，本对象不推断 | 同上 |
| **修掉硬编码** | `submit_delivery` 回执此前写死 `"verification_state": "unverified"`（既不在冻结词汇内，也让"自述称完成、实际无验证"看起来只是一个中性状态）；现从**已保存交付说明**读出并派生，`verified_in_scope` 同样从记录读出 | `application/controlled_write.py` |
| 分列回执 | 回执同时给出 `self_reported_completed`/`self_reported_incomplete` 与 `verification_state`/`verified_in_scope`/`unverified_scope`，满足"分列两处"；自述内容不进入 `is_verified` | 同上 |
| 载荷标识校验 | 读取交付说明前校验 `delivery_id`/`delivery_record_revision`/`project_id` 存在且形状正确，缺失即 `ApprovalRequired`（不猜） | 同上 |
