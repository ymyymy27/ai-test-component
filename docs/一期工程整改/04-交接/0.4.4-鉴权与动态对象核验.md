# 0.4.4 鉴权与动态对象 ID 操作

本版本接续 [0.4.3 计划发布至报告指南](0.4.3-计划执行核验报告操作.md)，发布、准备、确认、执行、独立核验、报告及导出动作不变。本页补充查询配置和依据写法；独立核验不得用程序输出的 paid/结果字段代替重新查询。

核心安装包为 `dist/ai_test_component-0.4.4-py3-none-any.whl`，扩展包为 `integrations/trae/dist/aitest-trae.vsix`；沿原安装步骤使用本版制品，安全排空旧核心后重启。ZIP 附件采用摘要文件名，manifest.json 的 attachments.evidence_id 保留业务编号映射。

## HTTPS 鉴权登记

在宿主指定的 AITEST_BUSINESS_QUERIES 文件（Trae 设置 aitest.businessQueriesFile）中只填写引用，不填写令牌正文：

```json
{
  "schema_version": "aitest.business-queries/1",
  "queries": [{
    "query_method": "your-project:read-order",
    "target_deployment_ref": "your-deployment",
    "url_template": "https://service.example/orders/{business_object_id}",
    "object_id_field": "object_id",
    "credential_reference": "order-read"
  }]
}
```

默认 SecretManager 通过 Windows 凭据管理器读取通用凭据目标 `aitest/http/order-read`（UTF-8 凭据正文）。须由宿主/运维按已有凭据工具登记；不要把正文放进此 JSON、命令参数、源码或聊天。环境变量来源只有宿主显式登记 `(http, reference) → 环境变量名` 后可用，设置任意名称不会自动生效。未指定 credential_reference 保持原匿名查询方式。

请求使用 HTTPS Bearer，保留系统证书和主机名校验；不关闭 TLS 校验，不把令牌放 URL。引用用途不符、凭据缺失或 401/403 均不能获得 matched；缺失时不回退匿名。查询配置在核心装配时冻结，更改配置后应正常结束旧核心再重新启动；不要终止尚有未知副作用的业务操作。

## 动态对象依据

在待发布用例的 assertion_basis.text 保存以下完整 JSON，之后按该依据摘要重新确认、发布和准备；不要修改已冻结计划：

```json
{
  "schema_version": "aitest.business-query-basis/2",
  "business_object_source": {"stream": "stdout", "json_path": ["created", "id"]},
  "query_method": "your-project:read-order",
  "target_deployment_ref": "your-deployment",
  "expected_facts": {"paid": true},
  "query_interval": "configured",
  "deadline_condition": "immediate"
}
```

被测入口生成真实业务对象后，在 stdout 输出一份 JSON，例如 `{"created":{"id":"actual-order-id"}}`；其他日志写 stderr。ID 必须为非空字符串，不能包含令牌。核心重建当前 Attempt 的永久 stdout 分块，检查归属、顺序、偏移、长度、摘要、过滤状态和最终捕获字节数，提取实际 ID 后再独立 GET。同一 ID 的响应对象字段必须一致，paid 预期来自已确认依据。

stdout 限 1 MiB，路径限 1—16 个对象键；当前不支持数组索引、JSON Lines、文本正则、stderr、外部任意文件或从另一个 Attempt 找 ID。缺失、重复 JSON 键、输出未完成/被过滤、摘要损坏、过期尝试均阻塞。必要字段被过滤时应改用非敏感对象编号，不能放松过滤。固定 ID 仍用 /1，无需迁移旧记录。

## 操作与恢复

1. 配置真实目标及凭据引用；项目编号、目标部署引用与依据逐字匹配。
2. 保存并确认依据，发布计划，按准确记录准备并登记运行。
3. 解析、授权、执行步骤；取得当前 Attempt 和执行快照编号。
4. verify_pending 只提交原运行/步骤/Attempt/快照，不额外提交对象 ID、凭据或 URL。
5. 查看独立查询事实，再保存报告及导出 ZIP；未执行步骤仍显示 incomplete。
6. 正常重启后同一核验意图回读已保存结果，不重复 GET 或业务执行。若原查询中断、凭据解析失败或结果未知，按现有协议用新的查询意图再查询；不能重跑创建对象业务来“补结果”。

## 证据边界

[本批检查](../../validation/p1-query-auth-20261015/README.md)区分真实 TLS/子进程/文件提交与受控人类事件夹具。Windows 凭据管理器现场登记、真实业务部署、真实 Trae 点击、完整一期与故障恢复仍须实际验收；静态和组件结果不更新 AC 为 verified。
