# 0.4.6 实际进程来源与完整报告链

本版补普通 Python 文件入口的实际来源采集。安装 wheel/VSIX 后，从准确保存的源码、环境和计划重新准备动作；旧动作不自动获得新采集策略，旧 incomplete 报告保持原事实。

升级后请按面板“准备运行 → 登记运行”建立新的运行，再逐步授权执行；可以使用仍有效的已发布计划与准确依据确认。新准备/登记使用新的业务意图，不能重传旧意图来冒充新运行。仅在旧运行中重试步骤，不会补写缺失的冻结断言引用，也不会自动改变旧报告。

1. 登记真实 Python 解释器及文件入口，例如 `python main.py`；文件及项目 Python 模块须在选定快照中。支持直接 `.py` 文件及冻结业务参数；`-m`、`-c`、原生程序和任意自定义工具暂不提供本策略的完整来源证明。
2. 按适用模板发布计划，确认准确断言依据，完整模式保留必测范围。纯函数独立预期使用 `aitest.pure-function-basis/1` 的 `expected_facts`；业务查询继续使用登记的独立 GET 与准确对象 ID，不能把运行输出当作预期。
3. 准备并确认新执行动作。保存的动作包含 `python-script/1`、载体摘要与源码文件摘要；隔离载体不读取用户 PYTHONPATH/用户 site。载体升级后重新准备，不能拿旧许可运行新载体。
4. 执行所有步骤后分别核验，创建报告。来源观察与输出、核验、报告是独立事实；来源通过不能代替断言确认、独立核验、真实关键链路或完整必测范围。
5. 按准确报告修订正式提测，查看 verified_in_scope 与 unverified_scope；导出证据 ZIP。重启只回读原观察和报告，不重放未知业务。

本版实际来源证据包括入口、解释器、原执行句柄与实际解释器进程出生身份、已加载项目文件摘要和采集缺口。Windows 虚拟环境的解释器子进程须在执行前证明属于本次独占 Job。业务 stdout 不能伪造来源记录。

未纳入冻结范围的第三方包、自定义不透明加载、未声明动态代码（包括动态构造函数和替换代码对象）、子进程/原生执行、活跃后台线程、超时/强停或证据缺失仍保留来源缺口。策略先覆盖可证明的 Python/标准库文件执行边界，不提供恶意同用户进程隔离。`passed` 只适用于满足全部判定条件的本次运行，不能外推为一期验收完成。

实际检查命令、结果、首次失败及产物见[本批证据](../../validation/p1-runtime-source-20261015/README.md)；产品状态以[项目现状](../../现状.md)为准。

隔离载体显式保持 UTF-8 输出。新加载原生扩展即使来自标准库，也保留来源缺口；普通纯 Python 模块须能逐项核对实际代码与冻结文件。
