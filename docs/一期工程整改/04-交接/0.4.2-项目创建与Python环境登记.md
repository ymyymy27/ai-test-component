# 0.4.2 项目创建与 Python 环境登记

> 后续操作入口见[0.4.3 指南](0.4.3-计划执行核验报告操作.md)；本页保留原批次配置与历史验证范围。

本版补上默认装配缺少可信环境登记入口的断点，并把项目名称/实际测试目标改为表单输入。完整计划/执行向导、独立业务核验和真实 Trae 端到端验收仍未完成；不要将环境探测成功当业务测试通过。

## 安装和项目创建

安装同批 [0.4.2 wheel](../../../dist/ai_test_component-0.4.2-py3-none-any.whl) 和 [VSIX](../../../integrations/trae/dist/aitest-trae.vsix)。其他配置与核心确认步骤沿用 [预览安装说明](0.4.1-受控入口预览安装与操作.md)。在面板填写“项目名称”和“实际测试目标”，点击“填写新建项目”，再请求核心确认；空输入拒绝，不保存示例目标。已有项目不以首写覆盖。

## 生成真实虚拟环境的宿主登记

先按被测项目需要创建隔离环境并安装实际依赖。以下是一个新环境的操作模板：项目编号必须与已保存项目相同，环境编号必须与随后受控保存的环境声明相同。生成工具只核对指定文件和配置，不运行候选解释器、不保存业务环境声明，也不授予执行许可。

```powershell
$basePython = (py -3.13 -c "import sys; print(sys._base_executable)").Trim()
$venvRoot = Join-Path $env:LOCALAPPDATA 'AITest\tested-python'
& $basePython -m venv --without-pip $venvRoot
$testedPython = Join-Path $venvRoot 'Scripts\python.exe'
$dependencyRoot = Join-Path $venvRoot 'Lib\site-packages'
$configFile = Join-Path $env:LOCALAPPDATA 'AITest\python-carriers.json'
py -3.13 -m aitest.interfaces.tools.cli python-carrier `
  --project '<实际项目编号>' --environment '<实际环境编号>' `
  --python $testedPython --base-python $basePython `
  --venv-root $venvRoot --dependencies $dependencyRoot --output $configFile
```

需要依赖的项目应按真实锁文件安装到这个被测环境。不要为了通过探测而删除已有 `.pth` 或改用空依赖目录；当前不支持的加载映射会明确阻塞。配置生成不扫描依赖并宣告通过，prepare/start 仍重新核对真实版本、解释器摘要、虚拟环境配置和依赖内容。`--output` 只创建新文件，不覆盖既有配置；更新时另存新文件并核对。多环境可在同一 schema 的 carriers 列表登记，项目/环境组合不能重复。

## 让新核心读取登记

在编辑器的机器级设置填写 `aitest.pythonCarriersFile` 为 `$configFile` 的绝对路径，随后连接新核心。终端启动也可显式设置：

```powershell
$env:AITEST_PYTHON_CARRIERS = $configFile
py -3.13 -m aitest.interfaces.tools.cli ensure-core --workspace '<专用用户数据目录>'
```

该路径是操作者管理的宿主配置，不从被测源码、Command 参数或模型输出中自动发现。不要把未经核对的项目文件作为宿主登记。

已运行的核心不会热更登记；确认活动执行已排空后，按原有受控关闭流程重启，不能直接杀核心或删发现文件。新配置文件损坏、重复键、重复登记、相对路径或解释器摘要不匹配均拒绝；坏配置只阻塞依赖环境的动作，不阻断读取已有结果。

## 后续步骤与边界

仍须通过现有受控入口保存准确源码绑定和环境声明、发布计划、准备、授权和执行。宿主载体登记不替代这些事实，也不设置“用户已确认”。核心实测环境可供默认准备和启动核对，但动态复用资格和独立业务核验仍须相应真实材料。
