# 当前代码分析与一期工程对比

复核：2026-10-12；代码取证基线 `develop@845e6978d522def651d5fec5a0b046126ffaaadd`，输出推送 `fix`。工作区起始无他人未提交改动；远端不存在 `devlop`，按已有 `develop` 复核。详细规模/门禁/验收总数只记录在[项目现状](../../现状.md)。

## 1. 当前结论与默认调用链

核心与默认命令执行链已有可运行实现；主要阻断集中在 D 的权威发布/业务 UI、C 的默认业务核验与复用保存、A 的未知发布产品恢复和干净安装。旧“只有 B 动作”“解析器未注入”“扩展无消息桥”“空 full 返回通过”等说法已失效。

1. `bootstrap.assemble_workspace_core` 持生命周期锁，恢复/迁移并核对 current 发布后装配 UOW、仓储、凭据与按动作能力门。
2. B 受控保存/发布 → `prepare_run` 冻结准确计划/源码/环境 → C `register_run` 保存 Run/Step/正文与初始事实。
3. `prepare_execution` 默认 `SavedActionResolver` → `StartMaterializer`/路径映射 → 冻结入口逐字核对、解释器 realpath、`SourceVerificationService`/真实 LOAD 来源核对 → 独立动作许可。
4. 授权/占用/意图/检查点同提交 → `RegisteredEntryExecutionAdapter` 在事务外真实启动（argv 数组、shell=False）→ spool 写前过滤/增量采集 → 永久对象/准确事实保存 → 有界调度/控制/恢复。
5. C→D 的 `build_decision_facts` 与 `DecisionDTO` 已存在，但未接默认报告发布。报告/问题门面无 UOW，`exports.py` 无实际制品实现。`verify_pending` 默认缺可信业务 resolver/port，整用例复用只有 inspect，没有保存动作。
6. CLI/stdio MCP 接同核心；MCP 七类普通保存不授予人工确认。Trae 经 `core-bridge`/既有 CLI 只读派发，面板业务操作仍禁用。

**核对边界**：静态枚举所有 Python 源码及公开符号、阅读默认装配和上述 A/B/C/D 调用链、核对四包旧条目与现行合同、运行专项/完整套件，并保存新增反例。未声称逐行审计所有历史脚本、真实 Trae 或每个真实供应方。本轮不修产品代码。
