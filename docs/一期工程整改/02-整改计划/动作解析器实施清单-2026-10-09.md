## 1. 默认调用与职责

`ExecutionAuthorizationService.prepare` → `SavedActionResolver.resolve` → `StartMaterializer`/`StartSourceBindingResolver` → 冻结入口、实际解释器、来源核验 → 自洽 `ResolvedExecutionAction` → 应用保存与授权占用 → `SavedStepExecution` → `RegisteredEntryExecutionAdapter`。

解析器不写业务记录、不启动被测命令；物化通过注入快照端口发生在事务外。默认实际解释器/来源核验和执行端口开启；显式关闭或自定义端口仍按真实能力处理，不能把它们宣传成全类型业务执行已配置。

## 2. 字段唯一来源

| 字段 | 来源与核对 |
| --- | --- |
| snapshot/source_content_identity | 已保存准备快照；物化后逐个 blob 重核并核对准确内容身份 |
| environment_content_identity/解释器 | 准备环境 EnvironmentResolutionFact；核心登记/观测载体，自报 realpath 比对 |
| registered_entry/arguments/adapter_version | Step 已登记入口或冻结绑定/环境派生；最终参数逐字，adapter_versions 唯一键及版本，不从模型正文猜命令 |
| cwd | workdir:<安全相对路径>，固定 workdirs/<run_id> 内，拒绝越界/链接/硬链接材料 |
| resolved_input_digest | B 在 prepare 冻结的输入摘要，不用 start 映射摘要替换 |
| source_binding_digest | start 的期望→实际路径映射重算摘要，与 prepare 摘要是不同事实 |
| attempt_index | FactsAttemptIndex 读取准确已保存步骤尝试历史，下一序号，不按客户端填值 |
| timeout_ms | 冻结 step_timeout_seconds×1000，未声明仍 None；Attempt/Request 必须一致 |
| side_effect_class | DEC-013；缺冻结类别保守 UNKNOWN，禁止未知副作用自动重放 |
| Attempt/authorization 身份 | 解析占位由 authorization.prepare 按工作空间/项目/意图替换为权威 ID，并复核完整关系 |

`ResolvedExecutionAction` 构造核对 Attempt/Request 的 Run/Step/intent、两摘要、截止、适配器、计划/步骤/授权修订；未占用授权和 intent_recorded 的事实不能被伪造为已执行。

## 3. 实际来源核验与范围缺口

`bootstrap._source_verification_provider` 调 `verify_pinned`，根据准确项目修订/模块 source_paths 与物化根推导导入名，`PythonLoadSourceProbe` 真的导入并通过 `SourceVerificationService` 核对加载路径。推导不是通用 Python 包布局证明，真实 src 布局/editable/PYTHONPATH 仍需用具体输入实测。

默认 provider 有 LOAD 路径，但 C-15 阻断真实默认材料；C-16 丢弃部分导入失败且 fallback 未真正做语法检查，不能声称已覆盖有效 LOAD/SYNTAX；APPLICABLE_BUILD 和需要显式脚本的 MINIMAL_START 尚无完整默认配置/实现证据。FR08 不因旧交接的“决定不实现”而缩减；按主责合同补配置、授权与正常/失败/来源不符证据。
