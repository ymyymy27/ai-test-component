# 可信动作解析器实施清单（下一会话可直接开工）

日期：2026-10-09，基线 `f1998e4`，分支 `fix`。本清单把"实现生产 `ExecutionActionResolver`、打通默认执行链"拆成**可直接执行**的步骤、触点与反例；不含实现本身。

## 1. 目标

在 `bootstrap.assemble_workspace_core` 注入一个**生产**解析器，使 `prepare_execution` 不再返回"无可信解析器"，而是把冻结绑定变成 `ResolvedExecutionAction(attempt, request, environment_content_identity, source_content_identity)`。它只**构造对象**：不写业务记录、不启动进程、不落证据。

## 2. 必读触点（按依赖顺序）

| 触点 | 作用 |
| --- | --- |
| `application/ports.py` `ExecutionActionResolver.resolve(run, step, intent_id, prepared, step_content)` | 端口签名与返回类型 |
| `application/execution/authorization.py` `prepare` 与 `_actual` | 现有准入核对：环境/源码内容身份、Run/Step/intent 一致性、冻结步骤截止（`_require_frozen_step_deadline`）、`attempt.timeout_ms == request.timeout_ms` |
| `application/execution/step_content.py` `StepContent.checked_case()` | 步骤正文与用例/计划修订链的自证 |
| `contracts/prepared_run.py` `ExecutionSourceBinding`（1.35 语义） | 冻结入口/参数/工作目录映射/适配器版本/`resolved_input_digest` |
| `domain/execution/runs.py` `Attempt`/`ExecutionRequest`/`RegisteredEntryRef` | 要构造的字段；截止、身份、副作用类别 |
| `application/execution/start_source_binding.py` `admit_start` | **新准入**：物化映射六处 + cwd/参数/适配器 + 入口/解释器一致 + 来源核验必须 verified |
| `contracts/execution_facts.py` `EnvironmentRefFact.resolution` | 实际解释器/载体/依赖摘要 |
| `bootstrap.py` `execution_action_resolver=` | 注入点；同时把"默认不可用"的期望改为"缺具体动作依赖" |

## 3. 实现约束（已裁定，AB-001 1.35）

1. `cwd_mapping` 只接受 `workdir:<安全相对路径>`（拒绝绝对/盘符/`..`/越界/逐段链接）；
2. `entry_arguments` **逐字**为最终参数，任何代入即拒绝并要求重新 prepare；
3. 适配器由 `adapter_versions` 的**唯一键**决定；
4. 截止取冻结环境的 `step_timeout_seconds`（准入点已强制），`attempt.timeout_ms == request.timeout_ms`；
5. 四类来源失败（入口缺失/来源不符/环境未登记/物化失败）返回不可重试阻塞并登记 `source_unverified` 缺口；
6. 构造请求时 `source_binding_digest` 应取 start 物化映射摘要（BC-001 §6），**不要**复用 B 在 prepare 冻结的 `resolved_input_digest`。

## 4. 反例清单（实现时必须逐条覆盖）

伪造/缺冻结绑定键；`adapter_versions` 多键或空值；参数被改写/截断/追加；`cwd_mapping` 绝对路径、盘符、`..`、越界、链接祖先；观察入口或解释器与冻结不符；来源核验非 `verified`；物化映射摘要与已保存值不符；截止与冻结声明不符（已由准入点覆盖，仍应加回归）；四类失败各自给出 `retryable=False` + `source_unverified`。

## 5.5 构造不变量（2026-10-09 从代码读出，实现时必须逐条满足）

`domain/execution/authorization.py::ResolvedExecutionAction.__post_init__` 强制下列等式，**不满足即 `ValueError`**（写实现时按此逐条校验，不要只看字段名）：

1. `environment_content_identity`、`source_content_identity` 非空；
2. `attempt.state is AttemptState.INTENT_RECORDED`、`attempt.execution_handle_ref is None`、`attempt.intent_digest` 为**假值**（执行前不留指纹）、`request.authorization_ref.consumed_by_attempt_id is None`（未占用）；
3. `attempt.authorization_ref == request.authorization_ref`；
4. 身份/摘要字段在 attempt 与 request 间逐一相等：`attempt_id`、`run_id`、`step_id`、`intent_id`、`resolved_input_digest`、`source_binding_digest`、`side_effect_class`、`timeout_ms`、`expected_plan_revision_ref`，且 `attempt.adapter_kind == request.registered_entry.adapter_kind`；
5. 授权引用一致：`authorization.intent_id == request.intent_id`、`authorization.step_id == request.step_id`、`authorization.resolved_input_digest == request.resolved_input_digest`、`authorization.step_revision_ref == attempt.step_revision_ref`、`authorization.plan_revision_ref == attempt.expected_plan_revision_ref`。

**据此推出的实现要点**：先按 §3 算出 `source_binding_digest`（start 物化映射摘要）、`resolved_input_digest` 用 B 的冻结值（不得替换），再从**同一组输入**一次性构造 `Attempt` 与 `ExecutionRequest`，最后以 `ResolvedExecutionAction` 自身当校验器（构造成功即证明一致性）；`adapter_kind` 只能来自 `registered_entry`（§3 唯一键），`timeout_ms` 只能来自冻结步骤秒数。

**字段来源已从现有夹具解析器读出**（`tests/unit/test_execution_authorization_origin.py::FixtureActionResolver`，它是当前唯一可用的"可信解析器"样例；生产实现按同口径改为真实读取）：

| 目标字段 | 来源 |
| --- | --- |
| `materialized_snapshot_ref` | `prepared["snapshot"]["source_snapshot_id"]` |
| `source_content_identity` | `prepared["snapshot"]["content_identity"]` |
| `environment_content_identity` | `prepared["environment"]["resolution"]` → `EnvironmentResolutionFact.content_identity` |
| `environment_ref` / `project_id` / `run_id` / `plan_revision_ref` | `run.*` |
| `step_id` / `step_revision_ref` | `step.*` |
| `Attempt.attempt_index` | 该 Run/Step 现有 Attempt 数 + 1（生产实现从保存事实派生；夹具用固定模板） |
| `resolved_input_digest` | B 在 prepare 冻结的值（`ExecutionSourceBinding.resolved_input_digest`），**不得重算替换** |
| `source_binding_digest` | start 物化映射摘要（本会话 `StartSourceBindingResolver`；夹具用固定值） |
| `adapter_kind` / `arguments` | 冻结绑定的**唯一** `adapter_versions` 键与 `entry_arguments`（裁定 3A/2A）；`entrypoint` 取解析后的入口/工作目录 |
| `adapter_version` | 上表唯一键对应的值 |
| `timeout_ms` | 冻结环境的 `step_timeout_seconds × 1000`（夹具示例为 120 000） |
| `authorization_ref` | 该 intent/step 的**已保存授权**（`authorization_id`/`target_ref`/`credential_scope_ref` 来自授权记录），`intent_id`/`step_id`/`step_revision_ref`/`plan_revision_ref` 按上表填 |
| `side_effect_class` | 冻结计划/步骤的副作用类别 |
| `expected_plan_revision_ref` | `run.plan_revision_ref` |

**生产实现仍需先解决的两件事**：① 解析器需要**注入依赖**（工作单元/记录读取/快照端口）才能读授权、Attempt 计数、物化映射——不能像夹具那样用固定模板；② `attempt_index`、`adapter_version`、`entrypoint` 的准确派生规则要与 `authorization.py::prepare` 的核对保持一致（避免"解析成功但准入拒绝"）。

## 5.6 实施状态（2026-10-09）

**已实现（未接入默认装配）**：[`application/execution/action_resolver.py`](../../../src/aitest/application/execution/action_resolver.py) 的 `SavedActionResolver.resolve(run, step, intent_id, prepared, step_content)`：

- 从冻结载荷读取：`execution_source`（`ExecutionSourceBinding` 严格校验）、`snapshot.source_snapshot_id/content_identity`、`environment.resolution`（`EnvironmentResolutionFact`）、`environment.step_timeout_seconds`（→ 毫秒，`None` 表示未声明）；
- 入口取 `step.registered_entry_ref`，并**强制**其 `adapter_kind` 等于冻结绑定的唯一 `adapter_versions` 键（裁定 3A）、其 `arguments` 与冻结参数**逐字**一致（裁定 2A）；
- `attempt_index` 与 `side_effect_class` 由**注入提供者**给出（这两项无法从冻结数据推出），start 准入结果由注入的 `admission` 提供并核对 `snapshot_id` 与 `sha256:` 摘要；
- `authorization_id`/`attempt_id` 用**明确占位**（`resolved-pending-grant`/`resolved-pending-attempt`），`prepare` 返回后按（工作空间, 项目, intent）替换为权威标识；
- 最后以 `ResolvedExecutionAction` 自身作为自洽校验器（构造成功即证明 9 条不变量成立），任何失败统一抛内部 `ActionResolutionBlocked`（**未登记为协议错误码**）。

证据：[test_action_resolver.py](../../../tests/unit/test_action_resolver.py) **14 passed**（1 正 + 13 反：入口适配器不符、绑定多键、缺绑定/快照/环境、缺准入、准入快照或摘要不符、冻结截止非正、尝试序号或副作用类别非法、步骤内容与意图越界），连同 start 绑定/合同/来源核对套件共 **271 passed / 1 skipped**；Ruff 通过、Mypy 226 文件通过。

**仍未做（有意留到最后一步）**：① 用**真实**提供者装配（`attempt_index` 读已保存尝试历史、`side_effect_class` 来自冻结计划/步骤、`admission` 来自真实 `admit_start` 物化）；② 注入默认装配并把默认期望从"缺可信解析器 ⇒ 执行不可用"改为"缺具体动作依赖"。这两步会改变默认执行语义，必须在真实端到端可见时一次完成，避免出现"有准入无执行"或伪造能力。



## 5.7 start 物化组件（同日实现）

[`application/execution/start_materialization.py`](../../../src/aitest/application/execution/start_materialization.py) 的 `StartMaterializer`：

- `workdir(run_id)`：固定 `workdirs/<run_id>`（架构01 第12节），拒绝空标识、`.`/`..`、含 `/`、`\`、`:` 的标识，并核对解析后仍在 `workdirs` 内；
- `materialize(snapshot_id, run_id, binding)`：**先纯校验**（适配器唯一键、参数逐字），**再**调 `SourceSnapshotPort.materialize`，随后完成映射六处核对与 `cwd` 受限解析，返回 `workdir`/`paths`/`source_binding_digest`/`cwd`/`adapter_kind`/`arguments`；
- 期望清单取自 `read_pinned` 的冻结 `files`，映射必须**恰好覆盖**；非空目标由端口既有语义拒绝，本组件不覆盖已有 workdir。

**测试发现并修复的真实缺陷**：初版在校验适配器键**之前**就落盘，导致"被拒绝却留下半份物化产物"；现改为**校验先于写盘**，由 `test_ambiguous_adapter_key_blocks_before_writing` 固定（断言 workdir 不存在）。

证据：[test_start_materialization.py](../../../tests/unit/test_start_materialization.py) **5 passed**；连同解析器/start 绑定/合同套件共 **273 passed / 1 skipped**；Ruff 通过、Mypy 227 文件通过。
