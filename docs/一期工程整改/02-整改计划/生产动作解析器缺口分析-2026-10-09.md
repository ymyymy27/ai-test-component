# 生产动作解析器缺口分析（A-02/A-08/A-10/C-02/C-12）

日期：2026-10-09，分支 `fix`，基线 `b689048`。本文只做**缺口与裁定点分析**，不含实现，也不改变任何现行合同。

## 1. 现状核对（源码事实）

- 端口：[`ExecutionActionResolver.resolve(run, step, intent_id, prepared, step_content)`](../../../src/aitest/application/ports.py#L95) 只声明返回 `ResolvedExecutionAction(attempt, request, environment_content_identity, source_content_identity)`。
- 默认装配：[`assemble_workspace_core(..., execution_action_resolver=None)`](../../../src/aitest/bootstrap.py#L299) 默认不注入；全 `src/` 无任何调用点传入实现。
- 结果：[`ExecutionAuthorizationService.prepare`](../../../src/aitest/application/execution/authorization.py#L392) 在 `action_resolver is None` 时抛 `ExecutionResolutionUnavailable("a trusted actual execution resolver is not configured")`。
- 既有期望：[test_default_execution_authorization.py::test_default_capabilities_and_missing_resolver_are_honest](../../../tests/unit/test_default_execution_authorization.py) 把"没有可信解析器 ⇒ 诚实不可用"当作正确行为。因此"默认执行不可用"是**已登记的剩余缺口**（A-02 行的"完整业务动作仍缺"、A-08 行的"实际入口/加载来源消费"、C-12 行的"默认业务执行截止"），不是回归。

## 3. 必须先裁定的规则（当前无主责位置可依）

1. **步骤 → 适配器与入口的映射**：`adapter_kind` 与 `RegisteredEntryRef.entry_id` 从哪条冻结字段派生？`execution_source.registered_entry` 是入口标识还是适配器标识？`adapter_versions` 是映射还是单一版本？
2. **参数代入**：`entry_arguments` 与用例输入（`case.inputs`/步骤参数）如何合并？占位符语法与转义由谁定义？
3. **工作目录**：`cwd_mapping` 的解析规则（相对被测根？多项目？路径越界拒绝）以及目标 Windows 目录耐久。
4. **实际载体核对**：`entrypoint` 是否必须等于 `environment.resolution.executable_path`；editable/PYTHONPATH 与自定义解释器如何登记（A-08）。
5. **失败回执**：解析不可用/入口缺失/来源不匹配/环境未登记分别对应哪一类 `CapabilityUnavailable`/`ApprovalRequired`，以及是否降级为"仅本地查询/保存/模板"（A-10 动作级依赖）。

## 4. 建议实施顺序

1. 按 DEC 方式裁定第 3 节五项，同步 AB/CORE 现行合同与公开 Schema；不得只改代码选一种解释。
2. 实现生产 resolver（纯应用层，仅消费冻结记录）；补"入口/解释器/参数/cwd 与冻结声明一致"的组件反例（缺字段、换入口、换解释器、越界 cwd、版本不符）。
3. 在 `assemble_workspace_core` 注入，并按第 3.5 节把"缺解析器"的默认期望改为"缺具体动作依赖"而不是"整个执行不可用"。
4. 接真实命令端到端（真实 Windows 进程/Python 3.13）与真实宿主（Trae）证据；缺证据保持未验证，不用组件通过代填 AC。

## 5. 与整项的关系

实现本项同时触及 A-02（完整业务动作与受控移交）、A-08（实际解释器/入口/加载来源）、A-10（动作级能力依赖与失败回执）、C-02（默认授权与执行同意图一次）、C-12（默认业务执行截止与宿主恢复）。任一项完成条件不止于本组件，故本轮**不移动任何检查表条目**，ABC 仍 21 整项，真实 AC 仍 0 verified。
