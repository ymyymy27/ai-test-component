# 生产动作解析器缺口分析（A-02/A-08/A-10/C-02/C-12）

日期：2026-10-09，分支 `fix`，基线 `b689048`。本文只做**缺口与裁定点分析**，不含实现，也不改变任何现行合同。

## 1. 现状核对（源码事实）

- 端口：[`ExecutionActionResolver.resolve(run, step, intent_id, prepared, step_content)`](../../../src/aitest/application/ports.py#L95) 只声明返回 `ResolvedExecutionAction(attempt, request, environment_content_identity, source_content_identity)`。
- 默认装配：[`assemble_workspace_core(..., execution_action_resolver=None)`](../../../src/aitest/bootstrap.py#L299) 默认不注入；全 `src/` 无任何调用点传入实现。
- 结果：[`ExecutionAuthorizationService.prepare`](../../../src/aitest/application/execution/authorization.py#L392) 在 `action_resolver is None` 时抛 `ExecutionResolutionUnavailable("a trusted actual execution resolver is not configured")`。
- 既有期望：[test_default_execution_authorization.py::test_default_capabilities_and_missing_resolver_are_honest](../../../tests/unit/test_default_execution_authorization.py) 把"没有可信解析器 ⇒ 诚实不可用"当作正确行为。因此"默认执行不可用"是**已登记的剩余缺口**（A-02 行的"完整业务动作仍缺"、A-08 行的"实际入口/加载来源消费"、C-12 行的"默认业务执行截止"），不是回归。

## 3. 主责合同已经确定的部分（源自现行分册）

核对[执行来源与物化边界](../../项目文档/一期/架构文档/01-项目与计划.md#12-执行来源与物化边界)与[执行与证据第4/7节](../../项目文档/一期/架构文档/02-执行与证据.md)后，下列内容**不需要新裁定**，实现应直接遵循：

- `ExecutionSourceBinding` 在 prepare 冻结：解释器/可执行文件身份、project 模块范围、**工作目录映射**、已登记入口与参数、允许的环境变量键（含 SecretRef）、测试配置引用、依赖集合与适配器版本；`resolved_input_digest` 覆盖这些来源约束。
- **实际路径在 start 解析**：合同原文为"start 在固定 workdir 中解析实际路径，保存期望→实际路径映射和 source_binding_digest，跨入口重传读取同一冻结结果"。因此解析/映射发生在物化之后，而不是 prepare 时；这也解释了为什么 `ExecutionActionResolver` 目前只被 prepare 调用时无法完成来源核对。
- `ExecutionRequest` 的组成（架构02第7节）：项目/Run/Step/Attempt、intent 与输入摘要、已登记入口/参数、物化快照、环境修订、`ExecutionSourceBinding`/`source_binding_digest`、授权引用、副作用类别。
- start 前来源不符阻塞；执行后无法证明则保存事实并形成 `source_unverified` 缺口（P1-AC13/25）。

## 4. 仍需裁定或补齐的部分

1. **工作目录映射语法**：`cwd_mapping` 的相对根、多模块项目、占位符与越界拒绝规则（配合目标 Windows 目录耐久）。
2. **参数代入**：`entry_arguments` 与用例输入/步骤参数的合并与转义；不得把模型或正文拼成 shell（架构02第15行）。
3. **适配器选择**：一个步骤可能对应 Python/命令/HTTP/导入等适配器，选择依据是 `adapter_versions` 的键还是入口类型字段；决定 `RegisteredEntryRef.adapter_kind`。
4. **失败回执**：入口缺失/来源不符/环境未登记/物化失败分别映射到哪类错误，并按 A-10 的"按实际动作依赖降级"保留本地查询/保存/模板。
5. ~~**`source_binding_digest` 的派生**~~ **（更正：已由接口台账定义，不是待裁定项）** [BC-001 §6](../../接口对接/进行中/BC-001-PreparedRun/contract.md) 明确：`resolved_input_digest` 由 **B 在 prepare** 冻结（覆盖解释器身份、模块范围、工作目录映射、已登记入口与参数、允许环境变量键、测试配置引用、依赖集合与适配器版本）；`source_binding_digest` 由 **C 在 start** 计算，是"在固定 workdir 中解析出的**期望 → 实际路径映射**摘要"；两者**不可合并、不可互相替代**（前者证明计划使用的来源，后者证明实际加载的来源）。因此实现顺序应是：先有 start 的物化与实际路径解析，再由其产生映射摘要；`prepare` 侧不应校验 `source_binding_digest`（那时它还不存在）。
6. **`materialize` 返回值与 AB-001 §3.4 的差异**：**已解决**——合同先行澄清（AB-001 1.34）新增 `paths`/`content_digest`（既有键不变、拒绝时不返回摘要），A 侧实现完成，拒绝分支反例已补（见[记录](../../修改日志/袁/2026-10-09-接口合同澄清materialize返回路径映射与摘要.md)）。
7. **`source_checks` 的期望摘要字段语义（已定性为确认的命名/口径不一致）**：[`SourceCheckRequest.expected_source_binding_digest`](../../../src/aitest/application/execution/source_checks.py) 在 `_derive_state` 中与探针的**单个** `observed_source_digest` 比较；但 [BC-001 第 6 节](../../接口对接/进行中/BC-001-PreparedRun/contract.md) 已把 `source_binding_digest` 定义为 **C 在 start 计算的"期望→实际路径映射"摘要**。复核（2026-10-09）确认：全仓文档/合同检索 `SourceCheckRequest`、`expected_source_binding_digest`、`observed_source_digest` **零命中**——这两个类型是**代码内类型、无合同条目**，而字段名**复用了合同术语**。处理方案与影响面见[待裁定草案第 5 项](待裁定项草案-2026-10-09.md)；现状 `SourceCheckRequest` **只有测试构造、无生产装配**（`src/` 内无构造点），接线前改动成本最低。
8. **默认执行链仍缺可信动作解析器**：`assemble_workspace_core(execution_action_resolver=None)` 不注入实现，故 `prepare` 返回"无可信解析器"的诚实不可用。本会话已实现并验证 start 侧的**输入核对与准入**（`admit_start`：物化映射六处 + 裁定 1A/2A/3A + 入口/解释器一致 + 来源核验必须 `verified` + 4A 回执），但**把冻结绑定变成 `Attempt`/`ExecutionRequest` 的解析器本身**仍未实现，属 A-02/C-02/C-12；在此之前不注入默认装配、不改写"缺解析器 ⇒ 执行不可用"的默认期望。

## 5. 建议实施顺序

1. 先实现 **start 时的物化与路径解析**（期望→实际映射 + `source_binding_digest`），这是合同已定但尚未实现的部分，也是解析器的前置。
2. 再实现解析器：从冻结绑定 + 实际映射构造 `Attempt`/`ExecutionRequest`，截止取自冻结环境步骤超时（准入点已强制）。
3. 在 `assemble_workspace_core` 注入，并把默认期望从"整个执行不可用"改为"缺具体动作依赖"。
4. 补真实命令端到端（Windows + Python 3.13）与真实宿主（Trae）证据；缺证据保持未验证，不用组件通过代填 AC。

## 6. 与整项的关系

实现本项同时触及 A-02（完整业务动作与受控移交）、A-08（实际解释器/入口/加载来源）、A-10（动作级能力依赖与失败回执）、C-02（默认授权与执行同意图一次）、C-12（默认业务执行截止与宿主恢复）。任一项完成条件不止于本组件，故本轮**不移动任何检查表条目**，ABC 仍 21 整项，真实 AC 仍 0 verified。
