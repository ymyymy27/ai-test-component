## 1 导航与首次使用

主导航保留：当前检查、项目与计划、工作台、报告与问题、设置。首次默认快速检查；有历史时显示上次明确选择，不自动升级为完整。

| 阶段 | 必填与操作 | 不阻塞项 |
| --- | --- | --- |
| 选择目录/目的 | 确认单模块草稿或实际模块；选择快速/按需/完整 | Git远端、平台账号不是本地前提 |
| 入口/环境 | 登记实际入口、解释器及本次所需环境 | 纯函数不要求数据库；关闭AI不要求模型凭据 |
| 内容准备 | 显式分析选定项目内容，或人工/模板草稿 | 无Plan也能分析；不自动执行命令 |
| 计划摘要 | 查看范围、检查项、预期、未覆盖项；确认发布 | 快速/按需不强制完整交付表；正式提测仍要求 |
| 准备/授权 | 固定源码和输入，集中逐项确认动作 | 相同有效授权不重复问；未知输入待解析后确认 |

分析展示选定范围与排除项，未保存缓冲区提示保存或明确按磁盘版本。无模板指向自建/导入，不执行猜测命令。必需能力未支持不能标不适用。

full先定义AcceptanceScope：业务目标、模块/业务范围、依赖闭包、排除理由、适用模板。只有实际全项目范围才写全项目完整通过；不允许运行中缩减范围隐藏失败。

## 2 运行前

```text
操作区：[切换检查目的] [查看计划] [查看环境事实] [逐项查看并确认]
检查目的：快速检查
验收对象：工单状态修改 / 订单服务及相关依赖
操作区：[运行快速检查]
最近固定源码：abc1234 + 差异8f3c…
当前目录尚未重新核实；准备运行时重新固定
依赖环境：本机已登记环境
本次：适用L1、变更模块关键L2、适用独立核验
结论范围：本轮覆盖，不作完整验收结论
待授权动作2项
▸ 驱动及高级选项
```

主按钮随目的为“运行快速检查/运行所选检查/运行完整验证”。按需先选检查集；快速由规则确定、完整包含范围内全部适用必测，不提供删减必测勾选。plain显示文件清单摘要，省略仓库字段。主屏不自动扫描源码。

授权清单逐项列实际目标、影响、输入与凭据范围，分别保存确认；没有全部永久信任。未解析变量待执行前确认；变化只使受影响授权失效。

### 当前检查·运行前（准备）

信息区回答一个问题：**这次到底要检查什么。**

| 动作 | 行为 | 边界 |
| --- | --- | --- |
| ▶ 开始检查 | 按"要跑什么"显示的档位与驱动发起一次运行 | 计划未确认或关键输入缺失时不发起，就地显示阻塞原因 |
| ⚡ 快速检查 | 一键按**快速检查**档发起：L1 ＋ 改动模块关键 L2 ＋ 按模板适用的独立核验（纯函数预期比对或业务数据核验） | **不打分**（只给覆盖摘要），不判完整通过 |

要点：

- **代码版本是重点**：显示最近固定的基准提交、差异摘要及当时的未提交改动；相对上次的变化只引用已完成的源码核实结果。尚未重新核实时显示“当前目录尚未核实”，不由面板查询扫描源码或猜测是否已变。
- 未提交改动必须显式写出（`+ 2 个文件未提交`），因为结论只对这份内容有效。
- 有副作用步骤提前告知数量，执行时会单独确认。
- **信息区里不放按钮**：不需要"重新固定源码"入口——发起检查本身就会重新固定源码快照；要改环境去"配置"页签。
- **动作区在本段不含"暂停／取消"**，那两个属于运行时段。
- **执行方式只列已知事实**：是否引用有效复用、是否启用模型、哪些步骤需要人工操作。运行前不预测消耗或执行时长；实际授权动作由工作台逐项呈现。

## 3 运行时与生命周期

自动进度、待人工操作与阻塞分开显示；完整输出在工作台按需读取。原因说明紧邻操作区：

| 情形 | 主动作 | 行为 |
| --- | --- | --- |
| 断言失败 | 查看证据/处理问题 | 事实与假设分开 |
| 环境阻塞 | 配置该环境 | 定位具体字段，遵守运行修订边界 |
| 依据未确认 | 核对依据 | 确认不替代执行 |
| 停止未确认/副作用未知 | 核实执行状态 | 不给直接重复副作用快捷动作 |
| 待人工操作 | 继续当前步骤 | 到工作台执行并关联证据 |

暂停中、已暂停、取消中、待核实分别显示；已暂停提供恢复。活动运行常驻提示“关闭编辑器后继续”；宿主支持时退出前再提示，不依赖退出回调。重开回到同一运行，关窗口不等于取消成功。正在执行步骤不可改，后续修订仍经核心守卫。

### 当前检查·运行时（执行）

信息区回答一个问题：**现在到哪了，发现了哪些缺漏。**

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│  当前检查  项目与计划  工作台  报告与问题  设置                                        │
├──────────────────────────────────────────────────────────────────────────────┤
│  [ ⏸ 暂停 ]   [ ■ 取消 ]   [ 查看步骤详情 ]                                 │
├──────────────────────────────────────────────────────────────────────────────┤
│  正在执行                                                                    │
│                                                                              │
│  进度   ███████████░░░░░░░░░  8 / 12                                         │
│         ✓ L1 语法与入口          已完成                                      │
│         ✓ L2 模块：工单创建      已完成 · 断言通过 · 真实                    │
│         ▶ L2 接口：查询分页      执行中 · 第 2 个请求                        │
│         □ L3 业务：状态修改      待你操作第 3 步                             │
│         □ L3 业务：最终持久化    未开始                                      │
│                                                                              │
│  缺漏   阻塞 1 · 未执行 3 · 跳过 0 · 缺证据 0 · 真实性未知 1                 │
│                                                                              │
│  最近   202 · 分页返回20条 · 证据已保存                                    │
└──────────────────────────────────────────────────────────────────────────────┘
```

| 动作 | 行为 | 边界 |
| --- | --- | --- |
| ⏸ 暂停 | 请求在步骤边界暂停，按钮先显示"暂停中"，生效后为"已暂停" | 暂停不改变结论上限 |
| ■ 取消 | 先登记取消意图，确认执行器停止后才显示已取消 | 未确认时保持"取消中／待核实"，**不伪造已取消** |
| 查看步骤详情 | 跳到测试工作台的当前步骤 | 面板不做逐步执行 |

要点：

- **人工步骤不显示进度条**，显示"待你操作第 N 步"；只有语法、命令、接口串联这类自动步骤进进度。
- **缺漏五类计数常驻**（阻塞／未执行／跳过／缺证据／真实性未知），点击进详情——这一屏的核心价值就是让"还差什么"一眼可见。
- **原始输出只显示最近一条**（避免变成终端窗口），完整日志在工作台详情里。
- 需要"确认后才能继续"的步骤（副作用、新凭据、扩大范围）由工作台弹确认，面板只显示当前状态。

## 4 运行后

```text
工单状态修改 / 完整验证
本轮未完成
原因：状态持久化尚未核验
[去核验] [查看报告] [导出]
适用12 · 完成11 · 失败0 · 阻塞1
▸ 证据充分性：C，关键链路3/4（查看全部缺口）
▸ 环境事实：依赖环境、数据来源/复位、目标版本
▸ 计划、授权与源码修订
▸ 上次已完成结果（仅历史参考）
```

有当前有效决定性失败（H_S非空）明确失败，不用待处理隐藏；“已确认失败用例”读取decisive_failure_count，“整用例已验证失败”读取failed_count，两者不相加。H可与未验证U重叠：前步有效失败而后步阻塞时显示失败1、整用例验证0、未验证1及阻塞原因，不显示没有失败。full才有等级，quick/按需未打分；A可对应充分失败证据。未用venv不自动降级；数据污染导致核验失效时显示具体缺口。环境与证据详情分开，主要缺口允许为无。

当前结果与报告快照注明来源修订；旧结果不回退为当前绿灯。重跑新意图，导出冻结报告/复核集合/格式/策略。

### 当前检查·运行后（结论）

信息区回答一个问题：**这次结论有多硬，缺口在哪。** 顺序固定：业务结论与本轮范围 → 执行/复用/验证统计 → 证据等级与全部缺口 → 环境和修订详情。图联动仅二期提供。

| 动作 | 行为 | 边界 |
| --- | --- | --- |
| ↻ 重跑 | 按同一档位与驱动再发起一次运行 | 产生新运行，旧运行保留为历史 |
| 导出报告 | 选择Markdown摘要或含脱敏附件的可携带证据包 | 导出不含密钥；字段与编号统一 |
| 查看报告 | 打开报告预览（含快照字段与证据索引） | 报告内容不可变，变化生成新修订 |
| 去处理问题 | 跳到问题记录列表 | 面板不关闭缺陷、不改判定 |

要点：业务结果、证据等级和环境事实分列；当前结果不得回退旧通过，完整统计和全部缺口均可展开，详细字段见第8.3节。

## 5 报告、问题与留存

一期报告按项目/业务结果/完整运行或报告编号筛选，同运行多修订折叠。隐藏项目仅默认列表偏好，可恢复，不删除、不停止活动任务。二期才增加高级源码分组。

导出选择Markdown摘要或可携带证据包。摘要说明不随附证据；包预览包含/排除/缺失附件，生成相对路径文件与清单。不能安全投影的材料排除并说明，不宣称证据完整。

问题详情“复制修复说明”含来源修订、预期/实际、脱敏证据、事实/假设、位置或未知原因、复测入口。用户自行交给Trae/人工，不假定聊天API；新实际证据才能关闭问题。

设置显示空间组成和备份/迁移入口，无业务删除入口。报告存在不保证外部源码永远可复取，详情显示复现范围。

## 6 模型与可用性

设置独立显示模型接收地址、项目、材料类别、源码片段开关（默认关）；首次出站展示脱敏摘要并确认，变目标或扩大范围重新确认。关闭AI阻止后续发送，已发请求可能返回；人工与报告可用。模型策略不授权平台上传源码。

字段有文字标签、主操作可键盘完成；抽屉关闭后焦点返回触发按钮。窄面板折叠次要详情，不隐藏范围、结论和主动作。无记录、无模型、不可写目录分开提示。P1-AC26/27与P1-AC30—35验证完整路径；最终需真实Trae验证，不用线框代替产品证据。

### 不做什么

- **信息面板不执行动作**：信息区不能发起运行、不能修改计划与用例、不能改配置、不能关闭缺陷。（动作只在动作区与二级视图里。）
- **不新增判定**：等级、通过条件、统计分母仍由一期领域层唯一实现，界面不重算、不四舍五入。
- **运行前与运行时段不显示时间**；**不显示分数或百分比**——覆盖率写成"必测 12/12 已执行""关键链路 3/4"，不写"100%"，避免把等级与覆盖变成刷分对象（一期 5.3："不输出百分比或分数"）。
- **不做成大日志窗口**，不显示完整请求体与原始堆栈（详情里按需查看）。
- **不做排行榜、通过率看板**。
- **不替代报告**：报告是内容修订快照，面板是运行期视图。
- **不引入服务端**：仍是编辑器内嵌视图，不新增网络面。
- **不在一期铺开**：多目录并行检查、批量批注、跨项目看板均不在本册范围。

## 7 页面清单、布局与返回路径

本节把前述流程展开为可实施的页面合同。以下线框只用于说明信息层级，数值是相互一致的示例，不是产品实测结果。业务编辑位于子视图，当前检查信息区只读；查看详情与控制按钮放独立操作区。

```text
当前项目：工单系统（可切换）    活动运行提示
当前检查 | 项目与计划 | 工作台 | 报告与问题 | 设置
-----------------------------------------------------
操作区：随当前流程显示主动作、次动作和阻塞原因
-----------------------------------------------------
信息区：运行前 / 运行时 / 运行后，三者之一
范围名称与本轮状态始终可见，细节可展开
-----------------------------------------------------
状态条：核心连接 · 当前目录形态 · 模型辅助状态
```

| 页面/子视图 | 入口与主要内容 | 返回与保存 |
| --- | --- | --- |
| 当前检查 | 默认入口；准备、进度、结果三段 | 从工作台返回保留所选运行，当前/历史清楚标明 |
| 项目概览 | 项目与计划；目标、模块、任务、变化与阻塞 | 保存上下文修订，不重置已有运行 |
| 任务/交付 | 项目概览→任务；验收、完成/未完成、运行方式、依赖/Mock | 草稿与正式提测分别校验，缺字段就地定位 |
| 规则/模板/计划 | 项目与计划→内容；版本、来源、适用性、用例、范围及依据 | 保存草稿和发布是两个动作，发布后修订不可变 |
| 执行授权 | 准备运行后→逐项清单；实际目标、影响、输入与凭据用途 | 每项单独确认，未知变量显示待解析；返回不自动授权 |
| 工作台 | 当前检查→步骤详情；步骤、当前尝试、执行/证据/分析/意见 | 回到当前检查保留步骤和尝试引用 |
| 证据/链路详情 | 工作台或缺口操作区；原输出、关联对象、节点和缺口 | 一期为记录列表，无图也可完成核验 |
| 问题详情 | 报告与问题→问题；复现、证据、级别/责任人、修复与回归 | 同issue_id留历史；复制修复说明不关闭问题 |
| 报告预览/导出 | 运行后或报告列表；精确报告修订、独立复核与附件 | 查看不改正文，选择摘要/证据包并预览范围 |
| 设置/维护 | 环境、模型出站、目录绑定、空间、备份/迁移 | 展示当前有效配置，修改形成修订，运行冻结值不随之改写 |

一期不显示不可用的二期历史/图或三期账号空页签。报告列表已能查历史报告，不把永久留存访问推迟到二期。

### 面板总体结构

面板是编辑器内的主界面：顶部页签，页签下方动作区，中间信息区，底部状态条。一次检查的生命周期里，信息区按"运行前 → 运行时 → 运行后"自动切换。

```text
┌──────────────────────────────────────────────────────────────────────────────┐
│  当前检查  项目与计划  工作台  报告与问题  设置                                        │
├──────────────────────────────────────────────────────────────────────────────┤
│  [ 动作区：随三段整行替换 ]                                                  │
├──────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│   << 信息面板（只读）：运行前 / 运行时 / 运行后 三者之一 >>                   │
│                                                                              │
├──────────────────────────────────────────────────────────────────────────────┤
│  依赖环境：venv    模型：可用 ✓    当前仓库：demo-app（main ↑1）         │
│  （非 Git 目录时：本地目录模式 · 无版本库 · 代码版本按文件清单摘要）          │
└──────────────────────────────────────────────────────────────────────────────┘
```

### 面板与工作台的分工

```text
   面板（发起与控制）                      测试工作台（逐步执行）
   ┌──────────────────┐                  ┌──────────────────────────┐
   │ 当前检查          │  查看步骤详情 →  │ 步骤列表 / 执行区         │
   │  运行前/运行时/后 │  ← 返回面板      │ 原始证据 / AI 分析 / 意见 │
   │ 项目计划/报告/设置│                  │ 暂停取消重试补证退回      │
   └──────────────────┘                  └──────────────────────────┘
```

- **面板负责**：看清要跑什么、一键发起、看进度与缺漏、看结论与等级、改最少几项配置。
- **工作台负责**：一步步执行、看原始证据、处理阻塞、改尚未执行的步骤、暂停取消重试。
- 面板不做逐步执行；工作台不做配置与历史。

### 分期页面能力

### 8.2 运行时布局与动作

```text
操作区：[暂停] [取消] [查看步骤详情] [查看缺漏详情]
说明：关闭编辑器后当前运行仍由本地核心管理
-----------------------------------------------------
工单状态修改 · 执行中
自动步骤：已完成3/5（按实际执行完成计数）
L1 语法与入口      已完成 / 断言通过
L2 创建与查询      已完成 / 断言通过 / 真实
L2 状态修改        执行中
L3 页面刷新        待人工操作第4步

```

进度条只表示自动步骤；人工等待不伪装为正在自动执行。执行完成和业务已验证计数分开，五类缺漏可重叠，不能把它们相加当未完成总数。界面只显示脱敏最近输出，完整输出到证据详情按需读取。

| 状态 | 动作区 | 防误操作 |
| --- | --- | --- |
| 执行中 | 暂停、取消、步骤/缺漏详情 | 不允许编辑正在执行步骤 |
| 暂停中 | 查看详情、可行时取消 | 不显示已暂停，不重复发暂停请求 |
| 已暂停 | 恢复、取消、编辑未执行步骤 | 恢复前重新核对修订与授权 |
| 待人工/待授权 | 进入当前步骤/逐项确认 | 不以确认文字代替执行证据 |
| 取消中/待核实 | 查看停止状态、核实执行 | 不提供直接重复副作用快捷动作 |
| 执行结束 | 查看报告、处理问题、重跑、导出 | 新重跑新意图，保留旧记录 |

### 8.3 运行后字段

顺序为“范围与业务结果→主要原因和主动作→实际统计→证据充分性→环境/来源详情”。A/B/C/D不是放行按钮；full才显示等级，其他档显示未打分。

| 字段 | 展示要求 |
| --- | --- |
| 本轮结果 | passed/failed/incomplete/not_applicable对应通过/失败/未完成/不适用；partial清楚说明仅本轮选定检查 |
| 主要原因 | 由核心主缺口/失败原因提供，全无缺口可写无；还有其他缺口时给查看入口 |
| 覆盖 | 本轮S与完整M分别显示执行E_X/X、复用R_X/X、有效验证V_X/X、有效通过P/失败F及未验证U、阻塞/跳过、关键链路核验、依据确认，各自分母与单位明确 |
| 证据充分性 | full显示字母及中文含义；可以“业务失败，A证据充分” |
| 环境事实 | 依赖方式、数据来源/复位、目标部署与源码对应；与等级分栏 |
| 来源 | 当前投影来源、报告修订、旧报告/依据过期和证据可用性缺口 |

同一夹具示例：适用12、执行完成11、有效验证11、失败0、阻塞1，分别显示执行完成11/12和有效验证11/12；关键链路3/4且缺必要核验为C、业务未完成。另一例全部有效执行但一个必测断言失败，可以业务失败且A级证据。全不适用显示不适用，不显示100%。

## 9 计划编辑与测试工作台

计划页按业务目标分组用例，技术字段在详情中展开。每条展示层级、前置、输入、预期、断言依据三态、核验方法、允许Mock、必测/关键链路关联及适用性原因。已发布状态与依据是否确认分别显示，不能共用一个勾选框。full范围内适用必测没有删除勾选；运行中编辑仅对未执行步骤开放。

```text
工作台：运行R1 / 计划修订3 / 当前步骤S4 / 尝试2
左侧步骤列表          右侧步骤详情
L1 / L2 / L3          目的、前置、已解析输入、预期、执行方式
每步状态              执行状态 | 断言 | 真实性 | 人工复核
当前尝试和历史        原始证据 | AI分析（假设） | 人工意见
-----------------------------------------------------
操作区：按状态提供执行/继续、暂停、取消、补证、核实、重试
编辑未执行步骤、退回阶段均显示影响范围和修订原因
```

补证表单要求步骤/尝试、采集来源、实际操作、业务对象ID、附件与说明；无法获取的项可写未知原因，但必需证据仍是缺口。退回阶段先展示下游需重跑，不让用户误以为已有继承证据本轮已执行。失败卡片提供原始证据和问题入口，AI分析独立标签且可驳回留痕。

面板的动作把用户送到这两个地方，它们本身不是"信息面板"：

| 视图 | 从哪进 | 主要区域 |

| 测试工作台 | 运行时段"查看步骤详情"；计划页 | 步骤列表、执行区、原始证据、AI 分析、人工意见、暂停取消重试补证退回 |

### 配置

按所选检查展示必填字段；其他信息仅在可靠已有记录可确定时自动填入并标来源，无法确定保持未知。实际入口、预期和授权仍须按门禁确认，不猜测命令执行。**这一屏是重量最容易反弹的地方**：一旦长出十几个字段，轻量就没了。

要点：

> **配置页的动作不是"信息面板动作"**：`重新绑定`、`测试连接`、`空间占用查看`、`重新检查环境` 调用的是一期已有的维护用例（绑定、`MaintenancePort`、`connectivity`），经接口层动作名暴露、由应用用例执行；视图层只消费 DTO，不直接读文件、不直接调用适配器。信息面板（三段只读区）本身仍然**不含任何动作**。

### Git 与非 Git 两种形态

被检查目录**不一定是 Git 仓库**。非 Git 时，所有与仓库、分支、提交、远端相关的内容**一律不出现**——不是显示"未知"，而是整块不渲染。

### 差异对照

| 位置 | Git 仓库 | 非 Git 目录 |
| --- | --- | --- |
| 状态条 | `当前仓库：demo-app（main ↑1）` | `本地目录模式 · 无版本库` |
| 运行前·代码版本 | `基准提交 abc1234 · 分支 main ↑1` + 未提交改动数 | `文件清单摘要 8f3c…` + 文件数与最近修改时间 |
| 运行前·仓库／目录行 | 显示仓库名、路径、仓库状态 | **整行不显示** |
| 配置页 | `仓库／目录：demo-app · main · 已绑定 Git 仓库 [重新绑定]` | `目录：/path/to/dir · 本地目录模式 [重新绑定]` |
| 二期历史分组键 | 完整source_identity（基准提交＋未提交差异摘要），同组按conclusion_key区分 | 文件清单摘要与快照身份，同组按conclusion_key区分 |
| 检查时间与统计 | 不变 | 不变 |
| 报告 | 记录仓库、基准提交、分支与差异摘要 | 记录目录、文件清单摘要、排除规则与差异摘要；**不出现仓库与提交字段** |
| 依赖与链路图 | 不变 | 不变 |
| 三期提交 | 提交含仓库与提交标识 | 提交只含本地目录标识与文件清单摘要；平台侧按项目汇总，不按仓库 |

> **本地永久保存**：不设保留期、不做自动清理、不提供删除入口，报告与证据都永久保留。面板的历史记录页因此**不提供删除入口**——历史不是"可清理的缓存"，而是结论的依据；空间不足时显示组成、实际缺口及已有备份/迁移入口；活动执行先受控收尾，禁止引导用户删除永久记录腾空间。

### 共同点（两种形态都不变）

- **快照与判定完全一致**：一样固定源码内容、一样排除凭据与产物、一样支持检查复用。
- **代码是否变化的判断**：Git 用提交标识＋未提交差异；非 Git 用文件清单摘要（大小与内容摘要）＋排除规则。
- **结论口径不变**：档位、结论上限、证据等级、必测与关键链路判定都不区分是否有 Git。
- **不可回退**：目录从 Git 变为非 Git（或反之）时保留原绑定记录，生成新绑定修订并提示重新确认，旧结论不改写。

### 实现约束

- 界面按**绑定形态**渲染：`LocalProjectBinding` 是否含仓库标识决定是否渲染仓库相关区块；不靠"取不到值"来判断。
- 非 Git 时**不发起任何 Git 调用**（不探测远端、不查分支），避免无谓的失败与等待。
- 报告与提交流程共用同一份"形态无关"字段集：形态特有的字段作为可选扩展，缺失时报告不显示空行。

## 13 空态、刷新和措辞

| 触发 | 显示与下一步 |
| --- | --- |
| 首次无项目 | 选择目录，进入最小向导，不显示虚构统计 |
| 有草稿无发布 | 显示缺项和“去确认计划”，保留已填内容 |
| 开始成功 | 进入运行时段，操作区换控制动作 |
| 有保存中的输出 | 不抢先计入已完成；持久提交事件到达后更新 |
| 待授权/人工/阻塞 | 显示原因及准确步骤入口，不自动跳过 |
| 运行终止 | 展示真实结果、未完成范围及报告入口，不自动回退旧通过 |
| 连接中断 | 最近确认状态+连接原因；重新连接查原Run，不自动重跑 |
| 查看旧报告时新记录产生 | 标新修订可用，仍保留用户正在看的快照 |
| 配置/绑定改变 | 新修订提示，历史来源不改；相关授权重新核对 |
| 模型不可用 | AI辅助不可用，保留人工计划、原证据与导出 |
| 数据目录不可写 | 查询可读记录，阻止新写动作；新导出登记也不可用 |

按钮采用“运行快速检查、查看证据、核实执行、复制修复说明”等明确动作，错误提供可执行下一步。通过、失败、未完成、未知、暂停/取消均有文字，不仅依赖颜色；证据等级始终带中文含义。宽面板可左右分栏，窄面板堆叠且保留范围/结果/主动作；表格可进入详情，不隐藏缺口。

### 状态与刷新

| 时机 | 面板行为 |
| --- | --- |
| 打开面板 | 读当前已提交记录，按最近一次运行的状态显示对应段（无运行记录→运行前空态） |
| 开始运行 | 自动切到运行时段，动作区整行切换为暂停／取消 |
| 运行中 | 按事件增量刷新进度与缺漏计数；原始输出只滚动最近一条 |
| 运行结束 | 自动切到运行后段，先显示业务结果与范围，再显示适用等级及动作区（重跑／导出／报告／问题） |
| 计划未确认就点开始 | 不发起，就地显示阻塞原因与"去计划页确认"的跳转 |
| 源码或规则变化 | 仅已核实变化时提示“依据已变，需重新验证”；未核实显示未知；不修改已有结论 |
| 报告已生成后又发生变化 | 运行后段标注"报告快照为旧版本"，不覆盖报告正文 |
| 记录缺失（首次使用） | 三段各自显示空态与原因，不显示推测值 |
| 图件生成失败 | 仍展示统计与失败原因 |
| 仓库或目录变更 | 运行前段与配置页提示重新确认绑定；保留原绑定记录，已有结论不改写 |

### 图标与配色约定

| 符号 | 含义 |
| --- | --- |
| ✓ | 通过／已满足／可用 |
| ● | 缺口／需处理（运行后缺口清单、链路图缺口节点） |
| ⚠ | 警告（必测覆盖率警告、证据级别基础） |

## 14 交互验收路径

键盘能完成首次向导、发布、逐项授权、工作台补证、问题确认、复核与导出；抽屉/弹层关闭焦点回到触发入口。阻塞原因和状态变化应可被辅助技术读取。重开/刷新恢复核心状态，项目切换不串缓存。P1-AC26/27验证只读信息与快照口径，P1-AC30—35覆盖最小配置、范围、分析、修复交接、可用性和证据包。线框及夹具不代替真实Trae验收。

## 15 确认、问题处置与恢复呈现

人工确认弹层显示核心冻结的动作、目标、已解析输入、凭据用途与修订；实际点击后提交所属会话的挑战，不提供AI代点、永久信任或无交互自动确认。MCP请求未获授权时，面板显示待用户确认来源和准确动作；确认后重复传输不重复询问。输入变化使旧挑战不可用，返回保留草稿但不授权。

问题详情分别提供“登记修复并复测”“核实为非缺陷”“归并到主问题”“暂缓”。非缺陷须填依据、理由并人工确认；重复须选择同项目主问题，显示关联范围、确认级别及阻塞影响，拒绝循环/自指。结果分别标修复关闭、核实非缺陷、重复跟随主问题、暂缓仍阻塞；不能统一显示“修复通过”。处置撤销和主问题重开重新显示有效阻塞，原失败证据仍可查看。

结果卡片与报告分列执行完成、有效验证及有效通过/失败：12项均执行、2项依据未确认时为“执行完成12/12；有效验证10/12；未验证2”，结果未完成。自动步骤进度与用例分母分开，不用一个“完成率”混用。确认依据后由核心重检实际证据，页面不自行加计数。

网络重传显示原Attempt的传输恢复；“重新执行”创建新Attempt，副作用重新确认。连接恢复按快照配对游标重建，订阅间提交仍显示，不先跳最新游标。维护页明确“已提交状态备份”的边界、活动未纳入材料和永久历史缺口；完整迁移备份须先收尾，缺口存在不显示“可完整迁移”。

## 16 复用、按需范围与缺口迁移呈现

结果分别显示“本轮所选3项，验证3/3”和“完整必测12项，验证0/12”，主结论为所选检查通过、未打分。有效复用显示来源运行/尝试、核验依据与本次未重跑；新尝试后不回退旧绿灯。迁移入口提供完整迁移与保留已知缺口迁移，后者在确认前逐项展示现存A/缺口G、影响报告、原目录保留位置及禁止新增损失；成功仍显示缺口。复制中新丢对象时停在失败详情，不能把新丢失自动加入确认清单。

## 17 来源、依赖与采集边界的呈现

| 情况 | 呈现与允许操作 |
| --- | --- |
| 凭据过滤或材料无法安全保存 | 日志/证据详情注明已应用采集策略及具体缺口；不展示过滤前字节，完整日志仍为允许保存的捕获流。不能把过滤完成等同全部核验通过 |
| 执行来源不符/无法核实 | 区分“启动前阻塞”与“执行后来源待核实”，显示安全原因与重新准备入口；不把复制成功显示成实际加载来源已核实 |
| 重试上游步骤 | 操作前列出受影响下游，发布新Attempt后立即将其标为需重跑/依据过期；旧通过在历史中可查，当前结果不回退，副作用下游不自动执行 |
| 多步骤用例统计 | 读取核心E/R/V和逐步来源；本轮部分执行加跨运行继承单列待补执行，不能因几个步骤完成把整用例计为已验证 |
| 用例与依据确认 | 按钮分为“确认发布用例”和“确认断言依据”；已发布且依据待确认可执行但显示未验证，补确认不伪造新执行 |
| 关窗与重新打开 | 有活动/可推进执行时提示关闭后继续；暂停/人工待办可持久化休眠，重开恢复原状态；界面断连不显示已取消或自动恢复 |
| 列表索引暂不可用 | 显示恢复原因与刷新入口，不显示空列表冒充无历史；按有限QuerySpec查询，不由面板扫描业务文件 |

具体规则从[执行采集](../架构文档/02-执行与证据.md#13-采集安全与原始证据语义)、[用例聚合](../功能文档/01-功能文档.md#15-用例执行聚合与依赖失效)和[生命周期](../架构文档/05-Trae接入.md#11-核心保活与退出合同)读取，面板不另算判定。P1-AC19/21/24/27/32/34/35沿同一DTO夹具与真实接入核对。

## 18 报告筛选的固定入口

项目为查询作用域，业务结果为可选枚举，编号输入标“完整运行/报告编号（精确匹配）”。默认列表调用reports.latest；输入完整编号调用reports.by_id，可同时限定业务结果；展开历史修订调用reports.revisions，展示每修订自身结果，不沿用列表过滤隐藏历史。查询来自[固定QuerySpec](../架构文档/04-存储与恢复.md#页面控件与queryspec固定目录)，条件变化刷新游标，缺索引与暂无报告分别提示。

## 19 问题列表筛选与复核显示

问题列表使用“未解决/全部”范围切换、“筛选维度＋值”控件和独立“严重程度”控件。维度包括模块、层级、人工复核、处理进度、处置、阻塞；一次一个主维度，可叠加级别。“不筛选”和“未知”分别显示；清除筛选保留当前项目并从第一页读取。没有结果与索引需维护分开展示。核心返回query_id、条件、commit和游标；界面不二次计算权威状态或筛选当前页冒充全部匹配项。

列表列出问题编号、级别、模块、层级、人工复核、处理进度、处置、阻塞及缺口；窄屏把次要列放详情，不删筛选能力。人工复核显示“当前事实已核对/未核对/历史信息未知”，详情展示确认依据；不得把报告复核、处理完成或上传成功当作问题核对。主问题关闭/重开导致重复问题变化时，按核心事件提示刷新，已打开的旧快照标明历史版本。P1-AC08按需求补充场景验收。
