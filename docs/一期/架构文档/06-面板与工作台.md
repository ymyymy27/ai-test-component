# 一期架构06：面板与工作台

版本：3.4  
更新日期：2026年9月23日  
文档类型：工程设计文档

覆盖P1-FR17及各业务入口。界面由[一期设计](../设计文档/01-面板与工作台.md)维护，业务规则只引用[一期功能](../功能文档/01-功能文档.md)。

resources/panel拆shell、current_check、planning、workbench、issues、reports、settings；是视图模块而非独立服务。接口提供PanelDTO/PlanDTO/RunDTO/DecisionDTO/ReportDTO，视图不直接读文件、调用适配器或重算判定。

| 数据 | 唯一来源 |
| --- | --- |
| 最近固定源码/绑定 | SourceSnapshot、LocalProjectBinding；一期不自动检查当前目录 |
| 运行环境事实 | EnvironmentRef与已保存ConnectionState |
| 范围、必测、未执行 | Plan/RunPlanRevision与领域CoverageDTO |
| 进度/待人工/待核实 | Run/Step/Attempt当前修订 |
| 业务结果、证据等级与缺口 | 同一DecisionDTO，等级仅full |
| 报告与复核 | 固定ReportSnapshot和独立LocalReview |

信息三段只读；开始、控制、导出和跳转在动作区。计划编辑/发布、按需范围选择、逐步执行、问题确认/关闭、设置分别调用既有用例；“只读信息区”不等于整个产品不能写。

首次向导→选择检查目的与必需配置→显式分析或人工/模板草稿→确认范围和计划摘要→发布→prepare_run→集中逐项授权→start；未发布就地给出计划入口。运行时暂停中/已暂停/取消中/待核实分开，已暂停有恢复按钮；待核实先核实，不直接重跑副作用。结束后重跑创建新意图，导出冻结报告与复核集合。prepare尚未建立Run时，逐项授权绑定intent及计划步骤，start再关联运行，不提前伪造run_id。

历史报告通过项目报告列表和精确ID查询可用，不提供二期按版本分组历史页。证据缺口一期跳已保存证据/链路详情；图节点、源码行标注是二期，不引用二期模块。面板与报告按来源修订区分实时/快照，旧报告不覆盖。

验证：P1-AC26/27、一键到计划确认、按需选择、暂停恢复、人工补证、问题回归和报告复核入口。线框示例由测试夹具的DTO生成，关键链路3/4为C、适用12完成11阻塞1显示11/12，不允许手写不一致状态。

主屏使用primary_action及原因DTO导航到现有用例；业务结论/范围优先，证据等级、环境和覆盖可展开。增加ModelOutboundPolicyDTO、ExportPreviewDTO、RepairBriefDTO与ProjectViewPreference；不在页面判等级或决定授权。复制仅通过已脱敏文本，证据包复用核心导出用例。

一期报告列表有项目/状态/编号筛选与修订折叠，二期高级源码分组仍独立。宿主支持时退出提示活动任务，否则显示常驻提示；重开恢复同一运行。键盘导航、窄面板布局、焦点恢复纳入P1-AC34。

## 1 DTO字段与动作归属

| DTO | 必需字段组 | 生产方 |
| --- | --- | --- |
| PanelDTO | 项目/绑定/运行上下文、当前段、源修订、信息区、primary_action/原因、可用动作 | 应用查询与interfaces/dto.py |
| PlanDTO | scope_revision、计划/规则/模板/验收修订、适用必测/关键链路、未覆盖/不适用原因 | planning用例 |
| RunDTO | Run/Step/currentAttempt、自动步骤完成/总数、用例S/M两组E/R/V/P/F/U、待人工步骤、阻塞/待核实、有效驱动与修订 | execution查询 |
| DecisionDTO | 范围、业务结果、结论上限、可选等级、主要/全部gap、真实分母与来源 | 纯领域判定，经应用投影 |
| ReportDTO | 固定报告修订、证据索引、独立复核集合、可用性及当前/历史标记 | reporting查询 |
| ExportPreviewDTO/RepairBriefDTO | 已脱敏内容、来源修订、附件包含/排除/缺失及安全复制文本 | reporting/defect_management经投影端口 |

页签、展开状态和焦点是界面状态；运行、授权、复核与问题是核心记录；隐藏偏好经既有项目配置保存。只保留重建界面必要的选择引用，不在localStorage复制一份业务结论。

### 模块职责

本册负责"把已经发生的事按一次检查的生命周期读出来"，并固定面板的动作边界：运行前看要跑什么、运行时看跑到哪、运行后看结论有多硬。**信息面板只读；独立操作区及各业务子视图调用已登记的核心动作。**

### 子域结构

```text
resources/panel/src/shell/    # 页签、动作区、状态条（面板骨架，一期交付）
resources/panel/src/current_check/    # 信息面板三段（运行前／运行时／运行后），只读，一期交付
resources/panel/src/reports/        # 一期报告列表与修订详情；高级历史分组二期增加
application/review/reporting.py      # 一期报告与证据详情查询；图投影二期按能力加载
interfaces/local/editor_host.py      # 动作调用、只读查询与事件续读
integrations/<editor>/src/           # 各编辑器的面板宿主与装饰器适配
```

约束：一期启动与打包不依赖locations/diagrams模块；二期能力存在时才加载增量视图与动作。面板源码共用，数据均经应用查询，业务修改调用统一用例。

### 三段视图

运行前看要跑什么，运行时看跑到哪，运行后看结论有多硬。**每段的布局、显示项、图标、空态与刷新时机由[检查面板设计](../设计文档/01-面板与工作台.md)维护**，本册只固定下面的实现边界：

| 段 | 实现约束 |
| --- | --- |
| 运行前 | **信息区**只读呈现；发起检查的动作在动作区（调用已有运行用例），信息区内不放动作 |
| 运行时 | 进度按事件增量刷新；原始输出只保留最近一条，完整日志按需读取；暂停与取消走已有执行控制用例 |
| 运行后 | 先展示业务结论和范围，再显示统计、等级与缺口；一期缺口跳证据/链路详情，二期才跳图节点；必要追溯时间仅运行后展示；重跑与导出调用已有用例 |

### 实时值与快照值

- 面板展示**实时值**（由当前已提交记录派生）；报告展示**快照值**（随报告内容修订冻结，见[报告与缺陷](03-报告与缺陷.md)第1节）。
- 两处必须分别标明，且口径一致：等级、主要缺口、断言可信度只能来自领域判定器，界面层不得重算或"四舍五入"。
- 源码或证据变化导致实时值与报告快照不同时，面板标注"报告快照为旧版本"，不覆盖报告正文。

### 数据来源（全部只读，无新增写路径）

| 面板内容 | 来源记录 | 说明 |
| --- | --- | --- |
| 已固定代码版本与核实状态 | `SourceSnapshot`、`LocalProjectBinding` | 复用快照编号与基准提交，不新建快照 |
| 计划与跳过项 | `Plan`、`SkippedScope` | 读冻结版本，不在此修改 |
| 进度与分项状态 | `Run`、`Step`、`Attempt` | 只读；进度仅对自动步骤有意义 |
| 缺漏分类计数 | 断言结果、依赖真实性、证据完整性 | 按现有五维状态聚合，不新增状态 |
| 等级与主要缺口 | `CredibilityGrade`（见[一期功能](../功能文档/01-功能文档.md#3-判定与统计唯一口径)第3节） | 派生值，不落新记录 |
| 断言可信度 | `effective_assertion_basis_state`（核心由冻结Case/依据修订与有效ConfirmationRecord派生） | 只统计state=confirmed／参与本轮判定的用例数 |
| 检查时间 | `Run` 开始与结束时间 | **三段内仅运行后段展示**；二期的历史记录页按需求 P2-FR06 另行展示每次运行时间（见本节时间字段约束） |
| 二期依赖与链路图增量 | 按能力加载 `application/diagrams.py` 投影 | 一期不加载；二期缺口标记与链路节点同源 |

**信息面板自身不新增任何业务记录、不新增字段、不写文件。** 面板需要的字段全部来自一期已存在的记录；二期新增的两类**只读**记录（`CapabilityState`、图定义/图修订）由各自唯一写入者落盘，面板只读取。字段与报告的分工见[检查面板设计](../设计文档/01-面板与工作台.md)第12节（字段归属和数据来源）。

### 边界

- **信息区只读，动作有边界**：信息面板不修改计划、用例、断言、缺陷与环境配置；面板动作只允许"发起与控制检查＋导出＋跳转"，且必须复用已有用例。
- **不新增判定**：证据等级、通过条件、统计分母仍由一期领域层唯一实现。
- **不替代报告与工作台**：报告是内容修订快照，工作台负责逐步执行与证据明细；面板是发起与运行期视图。
- **不引入服务端**：面板仍为本地编辑器内嵌视图，不新增网络面。

## 2 事件消费与视图重建

打开→读取同一已提交边界的视图快照及snapshot_cursor→从该游标之后订阅/重放→按对象修订更新相关视图。相同对象的显示更新可以合并，但不能丢弃业务事件或用客户端时间决定谁更新。遇SNAPSHOT_REQUIRED重新取快照；项目切换、旧绑定或旧实例的响应不进入当前视图。

执行中离开工作台再返回仍选同一步/尝试；用户正在看历史时新事件更新当前运行提示，不无提示切走历史内容。断开只显示最后确认状态和连接原因，不把运行改成失败/取消。重开后以核心记录重建，页面禁用按钮不是业务幂等保障。

## 3 界面合同夹具

至少覆盖无项目、草稿未发布、自动执行、待人工、已暂停、取消待核实、业务失败且A级证据、未完成且C级证据、quick未打分、全不适用、旧报告证据缺失、plain、无模型及数据不可写。每个夹具同时用于面板和导出字段对照；统计来自核心，页面不能手写“12/12完成但另有阻塞1”的矛盾组合。布局及字段表见一期设计分册。

## 4 快照与事件衔接

SnapshotEnvelope同时返回view、workspace_id、instance_id、writer_epoch、generation、commit_seq和snapshot_cursor。核心从同一已发布清单读取视图及其有效事件边界，不能先读视图再取“此刻最新”游标。视图查询可在固定不可变清单上完成，不为序列化大对象持有长写事务。

events(after=snapshot_cursor)先重放该边界之后的已提交事件，再衔接实时流；快照生成期间或订阅建立前的提交也必须进入重放。游标采用(commit_seq,event_index)或等价不透明编码，同一提交多个事件不可只收第一个就跳过整次提交。无关项目过滤仍保留扫描位置；客户端仅在应用完对应批次后推进确认游标。

断开续读可重复投递，按事件身份及对象修订去重；显示更新可合并但不丢语义事件。实例/epoch变化或游标无法继续时返回SNAPSHOT_REQUIRED，重新取得成对的快照与游标；不能从当前最新位置静默续接。历史报告仍固定原修订，事件只更新新记录提示。P1-AC27验证快照与订阅间提交、同提交多事件、重复投递和重启重建。

## 5 统计投影增量

运行DTO含selected_case_ids(S)、required_case_ids(M)、executed_count、reused_count、verified_count、passed_count、failed_count、unverified_count及各自denominator；分别返回selected_summary与required_summary，缺字段显示未知，不以步骤数推算。ReuseReference可展开来源；当前新Attempt优先。仍按SnapshotEnvelope的同提交边界及配对游标获取，不改变事件重放合同。

## 6 来源与依赖的视图守卫

RunDTO/DecisionDTO暴露source_binding_status、过期依赖及待执行步骤的安全摘要，CoverageDTO仍由领域按[用例聚合](../功能文档/01-功能文档.md#15-用例执行聚合与依赖失效)计算。视图不能从单个Step完成推断整个Case完成，也不能在新上游Attempt后保留旧下游的当前通过。日志对象仅来自[安全采集](02-执行与证据.md#13-采集安全与原始证据语义)，未持久化提示不允许绕开凭据过滤。

报告/问题/运行列表使用[有限QuerySpec](04-存储与恢复.md#13-有限查询与索引键)，列表返回commit配对摘要，不展开全部修订或附件；索引恢复状态与“没有记录”分开。宿主断开后的行为以[核心生命周期](05-Trae接入.md#11-核心保活与退出合同)为准，视图关闭不变更业务状态。

## 7 有效失败与确认字段呈现

直接消费CoverageDTO.selected_summary/required_summary中的decisive_failure_count/decisive_failures，分别显示“已确认失败用例”和“整用例已验证失败”；H与U可能重叠，不把两类失败相加。H_S非空时主结论failed，后续阻塞仍列未完成范围；旧DTO缺H显示该统计未知，不补零。依据确认使用核心派生effective_assertion_basis_state和对应分母，不直接统计冻结Case原字段，也不在UI重算。快照与当前投影分别显示source_commit、policy_version及报告修订。

### 报告查询动作

报告列表、完整编号查询和修订展开分别转发reports.latest、reports.by_id、reports.revisions，界面标业务结果且编号精确匹配；字段及索引唯一遵循[有限查询目录](04-存储与恢复.md#页面控件与queryspec固定目录)。核心固定commit和筛选条件，入口不全扫或仅筛当前页。

## 8 问题查询DTO与动作

问题列表唯一调用issues.list；请求、14种掩码、OPEN/ALL、稳定排序和游标沿用存储分册。响应含IssueListProjection、commit_id、实际筛选摘要、next_cursor和可用动作；索引维护错误不伪装空列表。处理进度、人工事实复核、处置和阻塞分别呈现。现有update_issue及受控人工确认动作经领域守卫后更新记录/索引；不另建问题确认服务，不允许MCP自称人工已确认。主问题变化的受影响投影由核心更新，UI只按事件失效当前列表并重新查询。所有可见筛选均须有对应QuerySpec，P1-AC08覆盖其端到端路径。
