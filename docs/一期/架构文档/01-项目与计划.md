## 1 项目、绑定和环境

LocalProject用稳定local_project_id（对外DTO名称project_id，二者为同一值而非两个编号），路径规范化仅作为绑定属性，显示名/路径变化不改变历史身份。LocalProjectBinding含binding_id/revision、目录、binding_form、环境引用；git形态扩展仓库/分支，plain完全省略仓库字段，不用空值假装存在。移动或形态变化创建新修订，重确认后使用。

Module登记职责、输入输出、接口、实现状态；Dependency为使用者→提供者，可有循环，传播须去重。Task/AcceptanceItem/Delivery登记目标、范围、验收、版本与来源；交付自述和验证事实独立。

EnvironmentRef包含依赖环境方式、解释器/版本、依赖集合摘要、业务数据来源/隔离/复位、目标服务身份/部署版本、请求与步骤超时配置、网络目标及按用途的SecretRef。默认venv，明确不隔离需确认；这些是运行冻结属性。环境缺载体阻塞，但显式不隔离不是缺配置。模型/HTTP/数据库核验/GitHub凭据分用途，不能只允许模型密钥。

### 模块职责

本册负责"测试开始之前"的一切：本地项目如何建立与标识、上下文与依赖如何登记、检查内容与用例如何生成并发布、运行模式如何冻结。执行、证据、报告与落盘分别见其他分册。

### 本地项目与标识

| 记录 | 核心字段与约束 |
| --- | --- |
| `LocalProject` | `local_project_id`、名称、目标、`workspace_id`、创建与更新时间 |
| `LocalProjectBinding` | `binding_id/revision`、规范绝对路径、**本地 Git 仓库与当前分支（可选）**、最近提交、环境引用、本地责任人。**注意**：三期另有平台侧的 `PlatformProjectBinding`，两者同名不同义，实现与落盘时不得混用 |
| `Module` | 模块编号、职责、输入输出、接口说明、实现状态、所属项目 |
| `BindingForm` | 绑定形态：`git`（目录是 Git 仓库）或 `plain`（普通目录，无版本库）；由 `LocalProjectBinding` 是否含仓库标识决定，**界面按形态渲染，不靠"取不到值"判断** |
| `Dependency` | 使用者模块 → 提供者模块；有向边，允许传递与循环标记 |

约束：绑定与项目身份分离；路径移动创建新绑定修订，历史记录仍归同一项目。plain不需要Git字段，模块依赖循环仅影响传播遍历，不能阻止建立项目。

## 2 快照和物化

SourceSnapshot：snapshot_id、形态、选定范围/依赖闭包、排除规则、逐文件相对路径/大小/mtime/内容摘要、内容引用、Git基准与diff或plain清单摘要、复取依赖和可复取范围。

显式analyze_project、计划确认和启动运行读取选定范围源码；首次固定建立完整必要摘要。元数据仅是变化提示；启动按实际复制流计算摘要，复制前后变化有限重取或阻塞，不沿用未经核对摘要证明执行身份。未保存缓冲区先由用户保存或明确以磁盘版本运行，决定入记录。

物化始终在workdirs/<run_id>，包含所选模块依赖闭包、入口、共享配置和必要资源，排除凭据/生成物，拒绝路径穿越与链接逃逸。对venv用原位复用或重建，不直接搬移现有环境；本项目editable/.pth、入口参数与导入路径必须通过第12节来源核对。物化副本不进入永久对象库，执行停止且证据保存后回收。

Git提交标识复取依赖仓库对象可用性，不保证删除仓库后永久恢复；记录LFS/子模块依赖。需离线复现的选定内容按摘要留存；plain保留必要文件及差异，缺复取范围显式报告。报告与运行证据仍按永久留存规则保留。

一期面板只读最近固定快照并说明当前目录未重新核实。二期SourceSnapshotPort新增受限目标元数据和显式目标哈希；其语义见二期定位分册。

### 源码快照与检查有效性

| --- | --- |
| `SourceSnapshot` | `source_snapshot_id`、**仓库与基准提交（`git` 形态）或文件清单摘要（`plain` 形态）**、工作目录范围、**排除规则**、文件清单摘要、差异摘要、内容引用、创建时间 |

## 3 模板、规则与用例

发布状态与断言依据确认状态分别校验：草稿未发布不能执行；已发布且依据present_unconfirmed可以按规则执行但不计V；已发布且依据confirmed仍须实际证据/核验有效才计V。确认依据使用既有ConfirmationRecord绑定准确Case/依据修订与摘要，不改写冻结Plan或原Case字节；应用读取该精确依据的有效确认记录派生effective_assertion_basis_state，生成新的判定/报告修订，不能将文本已改变的旧确认带到新依据。

resources/templates为唯一模板来源，TemplatePack版本化包含适用条件、检查、必测ID和关键链路要求（必须真实的依赖、不可省核验）。缺清单阻塞，明确不适用才记录空集合及依据。GeneratedContent保存实际依赖修订集合、生成策略/提示模板版本、来源、确认和过期状态；人工编辑不被重生成覆盖。

RuleDraft发布RuleVersion不可变。Case保存预期、前置、输入、步骤、层级、Mock、重要性、断言依据文本及三态、独立核验方式；CaseLink关联验收项、模块、环境、关键链路。缺依据禁止full必测；已填未确认可执行并保留分母，不计已验证。Plan冻结用例/规则/模板/验收与必测集合。

缓存键由每个派生物的实际依赖决定：源码、上下文、验收、规则、模板、环境及生成策略发生相关变更才定向失效。迟到模型结果只挂原来源并标过期，不覆盖当前人工版本。模型输出只草稿，不自动增加工具/入口/断言或改变结果。

### 内置模板与检查内容生成

```text
resources/templates/
  <template_id>/                        # 六个ID见能力与模板清单
    manifest.json                       # 模板版本、适用性、必测/关键链路集合
    steps/ · issues/ · reports/          # 本模板步骤、问题和报告片段
# template_id: python-library / python-service / http-workflow /
#              manual-web-workflow / agent-workflow / ticket-workflow
```

| 记录 | 核心字段 |
| --- | --- |
| `TemplatePack` | 模板编号、版本、适用业务与技术栈、段落结构、必填字段、示例 |
| `GeneratedContent` | 生成编号、模板版本、项目上下文修订、生成来源（AI／人工）、确认状态、过期标记 |
| `CaseLink` 增项 | 用例 ↔ 关键链路条目、用例的**独立核验方式**（发布必填；缺失时该用例不得计入已验证） |
| `RuleDraft` → `RuleVersion` | 规则编号、版本、适用范围、步骤、证据要求、启用状态 |

流程：选取模板 → 读取项目上下文 → 生成草稿（规则条目／验收项／用例／检查项）→ 用户增删改 → 确认发布为不可变版本。

约束：模板必须明确适用性、稳定条目ID及必测/关键链路集合；缺字段阻止发布，空集合须有不适用理由。人工修改不能被再次生成覆盖。

### 计划与用例

| 记录 | 核心字段 |
| --- | --- |
| `AcceptanceItem` | 验收项编号、目标、范围、验收条件（可观察、可验证）、版本、本地责任人、状态（草稿／已确认／待验证）；是关联链的起点 |
| `Case` | 编号、层级、前置条件、输入、步骤、预期结果、验证方法、允许的 Mock 范围、重要性、发布状态、**断言依据确认状态**（`assertion_basis_state`：missing/present_unconfirmed/confirmed，是该Case修订保存时的状态；当前有效状态使用核心派生effective_assertion_basis_state，依据文本与人工确认记录分别保存，AI仅可起草） |
| `Plan` | 计划编号、修订、冻结的规则版本与用例修订、必测项集合、档位、驱动、结论上限 |
| `CaseLink` | 用例 ↔ 验收项、**用例 ↔ 模块**、用例 ↔ 检查内容、**用例 ↔ 适用环境** |

约束：计划发布固定精确用例与规则修订；缺断言依据不能进入full必测，依据已填未确认与草稿未发布分别处理。CaseLink覆盖适用模块/验收项，缺映射保持缺口，不能用新增无关用例抵消。

## 4 意图与运行修订

prepare_run解析真实源码和环境、检查已发布计划与full适用下限，产生intent_id和canonical payload_hash。start_run在工作单元内按(project_id,action,intent_id)建立一次run；同意图异输入冲突。重跑明确新建意图；不能用计划号永久锁死重跑。启动前的物化清单逐项匹配prepare冻结摘要，缺失或变化则旧意图不可执行；重新prepare生成新意图，并按新输入核对授权。若运行记录已建立则追加启动阻塞事实，不能悄悄改payload_hash。用户随后继续编辑源目录不改变已固定副本；实际执行也不读回原目录须同时满足第12节执行来源核对。

Run保留initial_driver、effective_driver与DriverChange列表；RunPlanRevision保存生效边界/差异/原因/操作者；StepRevisionRef固定实际执行计划。planned→stepwise只能收窄，不能反向扩大。full修改不得删必测/弱化断言，范围与输入不兼容则新建运行。受影响已完成依据标OutdatedBasis，历史断言不改但不可参与当前通过。

### 运行档位与驱动

| 记录 | 说明 |
| --- | --- |
| `RunTier` | `quick`（快速检查）／`on_demand`（按需自测）／`full`（完整验证）；冻结在 `Run` 上 |
| `ConclusionCeiling` | 由档位派生的结论上限：`partial`（仅所选范围）／`passable`（可判通过） |
| `RunDriver` | `planned`（计划驱动，默认）／`stepwise`（逐步驱动）；冻结在 `Run` 上 |
| `ScopeSelection` | 按需自测所选层级、模块或环节清单 |
| `SkippedScope` | 未选中与未执行的步骤及其原因，进入报告 |
| `PlanRevisionRef` | 基础计划修订；冻结在 `Run` 上，不再改动 |
| `RunPlanRevision` | 运行中修订：序号、生效步骤边界、变更内容、原因、操作人、时间；只作用于尚未执行的步骤 |
| `StepRevisionRef` | 每个 `Step` 绑定其执行时的计划修订；继承的已完成步骤额外标记「沿用上次证据，本次未重跑」 |

档位与结论上限的对应由领域判定器计算，界面与报告只读取结果：

| 档位 | 覆盖范围 | 结论上限 | 证据等级 |
| --- | --- | --- | --- |
| `quick` | L1 ＋ 本次改动涉及模块的关键 L2 ＋ 按模板适用的独立核验（纯函数预期比对或业务数据核验） | `partial`：只代表所选范围，不判完整通过 | **不打分**（覆盖摘要） |
| `on_demand` | 运行时自选集合，允许只选下层（如只跑 L2） | `partial`：不判完整通过，未执行与跳过项逐条列出；缺少独立核验的项显示未验证 | **不打分**（覆盖摘要） |
| `full` | 冻结范围内全部**适用**必测项（模板下限按适用性过滤后计算），跳过项必须为 0；**无选择项，用户只能增补** | `passable`：证据与 P0／P1 条件满足时可判通过 | **`A`—`D`**（**唯一打分档**；全部条件满足时 `A`） |

**结论上限只由档位派生**：`on_demand` 即使把冻结范围全部选上也仍为 `partial`，判定入口只接受 `ConclusionCeiling`，不接受"覆盖了多少"作为放宽依据；需要 `passable` 结论时须新建一次 `full` 运行。

**证据等级派生规则**与结论上限独立，唯一引用[一期功能“判定与统计”](../功能文档/01-功能文档.md#3-判定与统计唯一口径)。A可对应可信的业务失败，quick/按需不打分。

编排规则：prepare冻结输入、start按持久意图取得同一Run；修改只作用未执行步骤并校验full下限；暂停/驱动收窄在边界生效，扩大输入或副作用重新授权。

## 5 变更与有效性

反向依赖传播覆盖传递、循环、重复、删除、重命名，保留匹配依据与图版本；缺CaseLink不能当无影响。单模块不做跨模块传播，但仍识别本模块变化。首次或映射缺失的quick使用已发布保守范围；无法安全确定时阻塞确认。

已有检查复用须源码、环境动态状态、入口参数、范围、规则及适配器版本一致，检查结束且证据可读取。环境状态不能证明未变时重新核验，不只比名称。继承证据标本次未重跑，不能满足必须新执行的缺陷关闭要求。

## 6 最小配置、分析与范围

analyze_project在尚无Plan时可调用，经SourceSnapshotPort读取用户选定路径，创建purpose=analysis快照；不执行项目入口。已有模板/人工配置可以绕过模型分析。PlanBuilder按检查类型校验必需字段，不把模型、GitHub、数据库配置统一设为所有运行前置条件。

AcceptanceScope作为Plan修订的一部分保存目标、模块/业务范围、排除原因、依赖闭包、适用性及模板修订；Run引用scope_revision。生成来源、计划确认和执行快照分别保存，分析后相关源码变化提示草稿过期，不能默默发布为当前适配。必要的首次信息由单模块草稿与模板提供，仍须用户确认登记入口及期望。

ModelOutboundPolicy由project配置用例保存，ModelProvider只接收应用层通过策略校验的脱敏投影；不要把代码分析授权等同于允许发送代码。模型请求绑定项目、策略和来源修订，配置变化后尚未发出的请求重新校验。源代码片段默认不外发。

### 子域结构

```text
domain/project/            # 本地项目编号、模块、依赖边、任务、交付、绑定
  context.py
domain/planning/           # 模板版本、检查内容、规则版本、用例、冻结计划、运行模式
  templates.py
  rules.py
  plans.py
application/project/
  context.py               # 建立项目、登记模块、目录与仓库绑定、上下文汇总
application/planning/
  plan_builder.py          # 内置模板 + AI 生成检查内容、一次确认
  run_mode.py              # 档位与驱动、结论上限与范围冻结
  regression.py            # 变更影响与回归范围
application/ai_assistance.py   # 模型调用的用例侧：统一请求、草稿边界、迟到响应过期
```

依赖方向：`application → domain`，外部能力一律经 `application/ports.py` 的端口。本册不直接读写业务文件，记录落盘统一走[存储与恢复](04-存储与恢复.md)的工作单元。

## 8 发布、准备与启动的调用次序

1. project/context保存项目、绑定与最小环境；任务/交付按当前操作所需校验，正式提测和full分别施加对应门禁。
2. 用户可显式analyze_project：先固定analysis来源，再按ModelOutboundPolicy投影；也可完全人工选择模板和编辑草稿。
3. plan_builder读取已保存上下文、验收和模板修订，生成草稿；用户修改不被后续生成覆盖。发布校验CaseLink、适用性、预期、核验方式和范围，写不可变Plan。
4. prepare_run解析已发布计划/环境/所选源码，保存intent与payload_hash；集中逐项授权只确认已解析动作。输入依赖前步结果的动作暂留未授权。
5. start_run先按意图去重，再核对物化字节与冻结摘要；启动阻塞如实保存，不能换输入复用原意图。运行/授权/意图关联经同一工作单元发布；实际外部执行由执行分册接管。
6. 新需求/源码/环境产生相关新修订；未执行步骤可按守卫修订，已完成依据过期单独标记，不追认旧执行。

跨用例必须比对expected_revision；来源过期或并发编辑冲突返回当前修订和差异提示，不自动覆盖用户编辑。发布、授权、执行、复核分别持久化，不合并成一个确认标记。

## 9 复用、回归与模型任务矩阵

| 派生物/任务 | 实际依据 | 失效或失败后 |
| --- | --- | --- |
| 上下文摘要 | 所选资料/源码analysis快照、模块/接口/依赖、生成策略 | 相关来源变化标过期，保留人工修订 |
| 检查与用例草稿 | 上下文、验收、模板、规则、源码及实际使用环境条件 | 仅重新生成受影响草稿；未变部分可复用 |
| 已执行检查复用 | 内容身份、入口参数、范围、环境动态状态、规则和适配器版本、可读证据 | 任一不可证明一致则不复用；复用标本次未执行 |
| 回归范围 | 模块/用例关联、依赖图修订、变更来源 | 循环去重，保留缺映射警告；人工增减形成范围修订 |
| 证据分析 | 指定Attempt/证据/断言修订、被允许的脱敏材料 | AI只产生假设；迟到响应归原来源、不覆盖新结论 |

模型任务区分上下文摘要、检查内容、验收建议、交付草稿、用例建议与证据分析。任务类型限定可选字段；source_snippets默认关闭，不能通过日志或另一字段夹带源码。供应方输入限制导致材料截断时记录排除范围；模型配置切换由用户明确操作，不在失败重试中暗换供应商。

用例经SourceSnapshotPort/SourceControlPort取真实来源，经ProjectionPort生成安全投影，经ModelProvider请求草稿；SecretPort只按用途解析引用，Clock只提供记录和控制所需时间；写入统一WorkspaceUnitOfWork。GitHub只读为可选，不是本地Git或plain运行前提。

### AI 调用边界

`application/ai_assistance.py` 负责模型调用的用例侧，适配器见[执行与证据](02-执行与证据.md)第4节与[存储与恢复](04-存储与恢复.md)第4节。

- 统一请求：任务类型、脱敏消息、输入记录编号与修订、模板版本、输出 Schema。
- `task_type` 与固定模板对应：上下文摘要、检查内容草稿、验收项建议、交付说明、用例建议、证据分析。
- 返回内容只写草稿与证据引用，不能直接修改断言、关闭缺陷或作出结论。
- 迟到响应核对来源内容修订，变化后标记过期，不覆盖新分析。
- 模型不可用时展示错误，由用户选择并验证新配置，不在失败重试中暗中切换供应商。

## 10 合法复用与当前尝试的衔接

用例复用与步骤继承必须按[用例聚合与依赖失效](../功能文档/01-功能文档.md#15-用例执行聚合与依赖失效)区分。新Attempt使对应整用例的R资格撤销，并使实际依赖旧输出的下游依据过期；仅保留历史引用不能绕过本轮聚合守卫。无依赖的本轮已完成步骤可继续有效。

ReuseReference登记target_run/case_id、source_run/step/attempt、来源计划与源码/环境/入口参数/规则/适配器修订、证据引用、validity_checked_at_commit及验证依据。它是已有运行记录的引用关系，不创建虚假Attempt，不增加执行器或独立服务。

准备运行时逐项验证来源已完成、内容身份/范围与实际环境状态一致、证据仍可读、断言依据有效；不能证明环境未变则不复用。原失败可作为失败依据保留，不得借复用转成通过。首次启动本轮新Attempt即撤销对应有效复用资格并保留其引用历史，新Attempt失败/取消/阻塞不回退旧结果。复用来源发生损坏或失效，生成新判定/报告修订，旧报告不原地修改。

E仅为本轮执行、R为有效复用、V来自当前有效E/R；本轮S与完整必测M分别投影，唯一公式见一期功能第3节。P1-AC21/27覆盖10次新执行加2项复用、新Attempt失败/取消以及按需只选补充项。缺陷修复关闭只接受新实际执行，不能用复用补齐关闭条件。

## 11 准备请求与业务身份合同

接口建立持久client_id，并为用户一次明确“准备运行”生成prepare_request_id。客户端在收到响应前保存该请求号；重连、重传及取回丢失响应继续使用原号。应用在工作单元内按(project_id, client_id, prepare_request_id)登记PreparationRecord及intent_id；输入摘要不同返回冲突。同一次准备的客户端取消只记录取消，不自动创建新意图；明确“重跑/新准备”才生成新请求号。

准备需执行的源码读取与摘要计算在短事务外完成；提交时校验项目、绑定、计划、规则、模板、环境修订及准备请求是否仍有效。并发完成同一准备请求时只能发布一条PreparationRecord，其余取得已发布结果。同请求期间源码已变则返回原意图及“依据需重新准备”，不能把新字节塞进旧意图。跨入口恢复通过intent_id或准备查询取得已有意图，不用新入口的request_id替代业务身份。

| 身份 | 创建与范围 | 冻结/恢复规则 |
| --- | --- | --- |
| client_id / prepare_request_id | 客户端持久身份 / 一次明确准备请求 | 重传不变，明确新准备换请求号 |
| intent_id | 应用创建，绑定项目/动作/实际输入摘要及各来源修订 | 与准备记录同提交；跨入口启动沿用 |
| run_id | start_run按(project_id, action, intent_id)取得或创建 | 与启动意图、授权关联及幂等结果同提交 |
| attempt_id / attempt_index | 应用在步骤中登记真实业务尝试，序号从1起 | 网络恢复不增加业务尝试；新副作用尝试重新授权 |
| request_id | 接口一次传输尝试 | 只用于传输去重及响应匹配，不代替intent |

prepare/start响应丢失通过同键查询返回原结果；外部执行前先发布启动事实。源码物化与意图不匹配则拒绝启动，重新准备并核对逐项授权。以上守卫由P1-AC19及既有意图/重跑相关验收联合覆盖，不新增业务功能编号。

## 12 执行来源与物化边界

物化摘要证明已固定的文件内容，执行来源合同再证明已登记入口使用该范围。两项同时满足，才能声称“源目录后续编辑不影响本次执行”；venv仅隔离依赖包，不承担源码来源或安全沙箱保证。

ExecutionSourceBinding作为Run/Attempt已有输入的组成保存，不新增服务。prepare冻结解释器/可执行文件身份、project模块范围、工作目录映射、已登记入口与参数、允许的环境变量键及非敏感值/SecretRef、测试配置引用、依赖集合与适配器版本；resolved_input_digest包含这些来源约束。start在固定workdir中解析实际路径，保存期望→实际路径映射和source_binding_digest，跨入口重传读取同一冻结结果。

| 来源 | 核对与失败处理 |
| --- | --- |
| 解释器与工具 | 核对真实可执行文件、版本及环境身份；复用环境的相关依赖发生变化则原绑定失效，不能只检查进程能启动 |
| 项目editable/.pth与导入配置 | 识别属于本项目的开发目录引用、PYTHONPATH、site配置和测试配置；映射到冻结物化范围，无法映射或验证则阻塞该入口 |
| 绝对命令参数与cwd | 源码/配置路径必须位于允许物化范围；必要外部资源单列依赖及内容/版本身份，不能将原仓库路径当固定副本 |
| 实际加载来源 | 在适配器支持的加载/执行边界记录本项目模块实际来源、入口和来源核对结果；动态加载或自定义工具无法证明的部分标source_unverified并形成证据缺口，不宣称完整源码对应 |
| 写入位置 | 运行缓存、测试输出与生成物写明确输出子目录，不把它们作为冻结源码；命令需要改写输入源码时须显式登记，改变后停止沿用原来源判定，重新固定并准备运行 |

每个步骤启动前核对它实际依赖的来源与环境状态，验证方式可复用受控且仍有效的内容身份，不能只看mtime。source_verified只覆盖已证明的来源范围，不承诺追踪恶意同用户进程或未声明任意动态代码。普通依赖包与本项目源码分开记录；项目模块不能靠外部包同名覆盖而获得通过。

预期绑定不符时拒绝启动，保存阻塞事实；已经执行后发现实际来源不符则保留执行和输出、标source_unverified/OutdatedBasis并重新判定，不冒充未执行或改写旧报告。扩大范围、修改输入或重新安装导致绑定变化时重新prepare并按现有逐项授权守卫核对。

合同验证覆盖src布局editable安装、PYTHONPATH/绝对测试路径、配置中的原仓库引用、动态导入未知、启动后原仓库修改、物化输入被改写与合法输出生成。预期是“实际加载来源对应”或明确阻塞/缺口，而不是“复制成功即通过”。
