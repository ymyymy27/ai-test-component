# 一期架构04：存储与恢复

版本：2.6  
更新日期：2026年9月21日  
状态：修订基线，待实现与实测；文档不代表产品已通过验收。

覆盖所有本地写入与P1-FR16。文件后端保持轻量专用，不实现通用数据库、消息队列或事件溯源框架。记录不可变、索引可重建、证据按项目和内容摘要寻址。

## 1 布局

```text
workspace.json / writer.lock / current.json
generations/<generation>/records/ manifests/ indexes/ events/
objects/<project>/<sha256>/
transactions/<transaction_id>/
spool/<attempt_id>/
workdirs/<run_id>/
checkpoints/ migrations/ diagnostics/
outbox/                           # 三期启用，保存意图和投影引用
```

generation用于结构版本迁移，不为每个步骤复制全量世代。项目.aitest仅放共享配置/模板，不存凭据或执行证据；工作空间放OS用户数据目录，禁止同步/网络盘。路径和符号链接解析后仍须检查实际范围，检测无法可靠确认时给出不可用原因。

## 2 单写与提交

portalocker取得真实OS排他锁，文件存在/mtime不代表锁有效，不删活进程锁。一个核心持锁；无响应时监督器先阻止新动作并尝试结束旧核心，确认退出且真正取得锁后才接管；否则NOT_READY。writer_epoch递增，迟到写入核对epoch、项目、意图与expected_revision。

事务步骤：校验→写不可变记录/变化索引/对象至transactions→校验长度摘要引用并刷新→对象入库、不可变清单含幂等和事件有效边界→同卷原子发布current并按文件系统语义刷新→发布成功后确认/推送。保留前一有效指针，损坏清单不可当有效状态。外部网络/执行不持事务，写入队列有界，拒绝时明确可重试。

普通查询从清单和项目摘要分页，不扫描全部附件；提交只改相关分片，不重写全部历史。对象读取检查项目归属、引用、大小和摘要。流式导入/物化校验实际字节，空间不足明确失败，不能假报保存成功。

## 3 输出抢救与恢复顺序

spool与transactions不同：前者承载执行器已产生的输出及归属元数据，后者承载未发布事务。块须含Run/Step/Attempt、块序号、长度、摘要、完整性；执行检查点引用块与真实进程启动身份，不只存PID。

1. 取得锁并更新epoch，验证current/有效清单，确定最后已提交状态。
2. 核实活动进程/句柄及其workdir，标明仍活/结束/未知；未知副作用禁止自动重放。
3. 先检查spool及transactions中的输出候选，验证归属、摘要和完整性；部分块只转为部分证据；未知类别保留待处理。
4. 经工作单元发布恢复事实、块引用和待核实状态，恢复动作可重复且幂等。
5. 确认无活动执行器引用、必要证据已保存后，才回收workdir、纯临时副本、空对象与无有效输出的未发布事务残留。
6. 从已提交事件边界续读，忽略无效尾部；缺索引重建，缺原始证据明确报缺口。

不得先清空staging/transactions再抢救；非空不等于完整证据；无清单引用不等于可删业务材料。恢复期间再次崩溃不重复认领证据或重放业务。正常启动检查增量恢复状态；完整历史扫描由明确维护动作执行。

## 4 永久保留

运行证据、所有报告修订、导出、诊断、业务元数据、本地复核以及已发布世代永久保存：无保留期、无自动清理、无业务删除入口。用户外部删除/磁盘故障造成缺口时如实标记，不篡改旧结论、不宣称完整。

例外不变：执行停止且证据保存后的源码物化副本和运行临时材料、上传结束的冗余临时副本可回收；崩溃空对象与确认无有效内容的事务残留可回收；已经产生的输出先保留为证据。不可判类别不删。非Git必要源码和Git差异对象按快照记录保留，临时物化不等于永久源码对象。

去重和可逆压缩可减少重复保存，原始逻辑内容摘要与压缩字节摘要分开。容量检查预留实际已知收尾材料空间，不能保证任意无限输出；若保存不能继续则暂停/请求停止并记录缺口。只展示组成与剩余空间，不静默驱逐历史。

## 5 凭据、诊断与重试

SecretPort在工作空间外用OS凭据设施管理正文；模型、被测HTTP、独立核验数据库、GitHub只读分用途命名空间，三期增加账号令牌。面板/配置/MCP/导出只显示引用。无可用后端明确不可用，不降级写明文工作空间；受控环境变量引用可作为显式选择。

适配器归一错误，connectivity唯一决定重试/降级。可重试只读操作或符合执行分册第10节的原请求幂等恢复沿用一次失败周期最多3次自动重试，间隔2/5/10秒；新副作用Attempt不由连接层自动创建，须重新授权；周期状态持久化，重启不清零。UNKNOWN优先查询也受相同周期约束；网络控制超时用于识别失联和结果未知。日志必须脱敏并永久保存。

## 6 备份与迁移

备份冻结一个已提交历史根及其可达的全部永久记录、历史世代/清单与对象闭包、版本/epoch/事件边界和摘要，清单最后完成，校验后才可恢复；不自动轮换删除，位置独立于活动目录。恢复到新目录，校验关联和对象后切换，活动步骤必须重新核实。

aitest migrate inspect/plan/apply/resume/rollback保持维护入口；迁移前必须有对应模式的可校验备份（完整迁移或第11节已知缺口迁移），进入维护状态停止新业务，允许受控收尾写入直至冻结边界。新generation保存转换结果和检查点，校验后原子切换；切换前可保留原代，切换后有新写入不允许丢弃式回滚。旧来源未知不推测，旧解析集中迁移模块。只有实际格式升级才实现对应迁移器，不预先设计任意格式转换平台。

## 7 目录责任与对象生命周期

| 路径 | 内容 | 使用边界 |
| --- | --- | --- |
| workspace.json | 工作空间ID、结构版本和后端信息 | 不含凭据正文 |
| writer.lock | OS锁载体及诊断身份 | 存在/修改时间不代表锁有效 |
| current.json | 当前有效清单指针与世代 | 同卷原子切换，保留前一有效指针 |
| generations/.../records、manifests | 不可变记录、对象引用、提交/幂等信息 | 已发布内容永久保留 |
| indexes、events | 查询分片、JSONL事件及已提交有效边界 | 索引可重建；事件无效尾部不得广播 |
| objects/<project>/<sha256> | 已校验附件、必要源码、冻结投影等 | 读取校验归属/摘要，不因跨项目同摘要而授权读取 |
| transactions/<id> | 未发布记录与文件提交材料 | 恢复检查输出候选，不能无条件清空 |
| spool/<attempt> | 原始输出块及归属/完整性元数据 | 采集成功先保存字节，再推进可确认游标 |
| workdirs/<run> | 专用源码物化和运行临时副本 | 无活动引用且证据发布后回收 |
| checkpoints、migrations | 句柄身份、块引用、恢复/迁移进度 | 恢复动作必须可重复，不据游标重放业务 |
| diagnostics | 脱敏诊断、维护与恢复记录 | 永久保留，不轮换删除业务诊断 |
| outbox/<account_key> | 三期提交记录关联及脱敏投影 | 唯一冻结材料永久保留，令牌不在此保存 |

逻辑记录、内容对象和可重建索引分开；一次小提交只写变化记录和相关索引，不复制历史世代。源码物化副本与永久保存的必要源码对象虽可能字节相同，生命周期不同，不能按目录名笼统回收。

## 8 提交故障点与恢复结果

| 中断点 | 可认定事实 | 恢复动作 |
| --- | --- | --- |
| 写临时记录前 | 原current仍有效 | 原事务未生效；业务副作用需另按Attempt核实 |
| 对象写入中 | 可能只有部分字节 | 校验归属/完整性，保留可识别输出为部分证据 |
| 对象已入库、清单未发布 | 无新业务可见性，但可能有执行输出 | 抢救候选、幂等认领；无引用不等于可删除 |
| 清单已写、current未切换 | 原current仍是已提交状态 | 核对记录/对象；不能仅凭完整清单擅自广播成功 |
| current已发布、响应未返回 | 事务已成功 | 由持久幂等记录返回原结果，不重复执行 |
| 事件发送中 | 只认已提交事件边界 | 客户端按游标去重续读或SNAPSHOT_REQUIRED |
| 恢复再次中断 | 部分抢救可能已发布 | 按原块身份/摘要认领，不产生重复证据或提前清理 |

完整性检查区分清单损坏、对象损坏、缺索引和缺原始字节；索引重建不能修复丢失证据。普通启动只检查必要恢复状态，用户显式完整检查才扫描全部历史引用。任何自动回收先核对执行器状态与数据归属，无法判断的材料保留待处理。

## 9 备份、迁移和维护的具体步骤

1. 备份选择一个已提交历史根，记录workspace/generation/epoch/事件边界；按第10节复制全部永久历史闭包，而非仅最新对象，最后生成带摘要的备份清单，校验成功才标可恢复。
2. 备份不包含密钥正文，不自动轮换删除；恢复凭据按OS后端流程另行处理，换机缺凭据明确显示不可用。
3. 恢复写入新目录，校验项目归属、数量、引用与对象摘要后再切换；历史活动运行重新核实句柄，不恢复成已完成。
4. 迁移inspect检查实际结构与缺口，plan给出转换范围；进入维护模式停止新业务，网络或活动执行完成受控收尾/核实并发布输出；随后冻结最终边界，验证对应模式备份后apply。
5. 迁移写新generation，记录逐对象转换与摘要；resume核对检查点再续写；完成后对比编号、引用、记录数及内容再切换。
6. 切换前失败原代继续可用；切换后接受了新写入时，rollback不得丢弃新增记录，须先受控导出或转换。未知旧来源保持未知，旧解析只在迁移模块。

MaintenancePort不含删除业务记录能力。维护记录给出检查范围、已完成项、错误类别、材料缺口与下一步；可重建索引与不可复原证据分别报告。能力不可用时拒绝相关动作，不为了完成维护绕过单写锁。

## 10 备份历史闭包与活动材料

current指向的提交历史根须能经不可变历史目录/前驱清单遍历该边界之前的全部已发布世代与记录修订，而非仅最新记录索引。BackupManifest登记root_commit、全部历史清单/世代、记录与对象的数量/大小/摘要、永久诊断与导出引用、已知缺失清单和备份类型。使用内容引用去重复制，不逐提交复制全量对象。该历史可达性合同也适用于结构迁移，索引不能作为唯一历史来源。

| 备份范围 | 处理 |
| --- | --- |
| 已发布永久历史 | 全部项目、Run/Attempt、旧报告修订、问题/处置、本地复核、导出、诊断及二期图定义/修订；三期含候选/游标、提交、唯一投影、控制决定与回执 |
| 引用闭包 | 递归纳入上述记录引用的证据、必要源码、投影、图件与导出产物；外部导出副本不作唯一保存来源，成功登记前将永久产物存入受控对象库 |
| 凭据与可复取外部源码 | 不复制密钥正文；Git仓库/LFS等未保存的复取依赖列外部前置，不伪装成已备份源码 |
| 未发布活动材料 | 普通已提交状态备份不复制正在变化的spool/workdir/transactions；记录活动Attempt、材料位置和未纳入原因，不宣称完整运行备份 |

在线备份可覆盖其root_commit之前全部已提交历史，后续提交不混入同份清单。诊断等永久文件须有可冻结的段/对象及提交引用；活动段只复制已提交字节边界，不能复制过程中变化的文件并宣称一致。发现应在闭包中的记录/对象缺失，标为有缺口备份，保留材料但不得作为完整迁移备份验收通过；可按第11节显式选择已知缺口迁移，不能自动降低模式。

完整停机/迁移备份先进入维护模式，停止接纳新业务执行与新发送，现有执行和在途请求受控收尾/核实；仍允许收尾写入。抢救并发布spool/事务输出后，冻结最终历史根再复制。仍有未核实活动执行器或无法归属的材料时阻止迁移切换，不提前清理，也不把它们排除后称完整备份。完整迁移前须验证完整历史闭包及摘要；携带已知缺口迁移按第11节验证可枚举历史、现存字节与已知缺口，无新增损失才可切换。

恢复到新目录，重建索引后核对最早报告、被替代修订、全部尝试、复核、诊断、图件和上传历史；备份中活动/未知步骤仅恢复为待核实，不自动执行。若原工作空间尚有活动执行，恢复副本先只读隔离，不允许双工作空间接管同一Attempt。恢复引用和凭据不可用时如实显示缺口。P1-AC28/35以及P3-AC03验证永久历史完整性与活动材料边界。

## 11 携带已知缺口的受控迁移（2.6）

完整迁移仍要求永久历史闭包完整。历史附件已被外部删除/损坏且无法恢复时，可显式选择preserve_known_gaps模式；它是既有MaintenancePort/migrate的模式，不是删除或修复证据能力。不能自动从完整模式降级。

1. 进入维护模式、核实活动执行及在途请求并收尾，发布可抢救输出后固定source_root。任何未知活动执行器或归属不明材料仍阻止切换。
2. 遍历全部可识别历史，冻结可用材料清单A和既有缺口清单G。G记录稳定引用、类型、应有摘要、缺失/损坏类别、实际可读字节摘要及受影响报告/运行；缺口不能以移除引用消失。历史根/关键记录无法读取、无法可靠枚举范围时，不允许启用迁移目标，只能另存现存字节为只读抢救副本。
3. 展示A/G及范围，用户通过既有人工作用入口确认mode、source_root、目标目录和manifest_digest；源边界或清单变化必须重检并重新确认。制作包含全部现存材料、历史元数据、G和模式的可校验备份，不能把它称为完整无缺口备份。
4. 复制到新空目录并逐项核对A：源端能读取的每项字节都须保存，包括损坏但仍可读的原材料；损坏字节按原实际摘要隔离保全，保留原预期摘要和损坏状态，不挂成有效证据。读取中新增错误、源内容变化、目标缺项或摘要不一致均停止切换，不能临时把新增损失加入G放行。
5. 需要格式转换时保存原始字节及逐项转换关联；验证记录ID/修订/引用不丢失，目标G与已确认G逐引用对应且没有新增缺口。现存证据不得被标为缺失来绕过复制；缺失证据也不得填造空文件冒充恢复。
6. 校验通过才允许目标成为活动工作空间；原目录永久保留为非活动来源，禁止两处同时接管同一运行。结果标“已迁移，保留原有缺口”，恢复报告保存A/G摘要、确认记录、校验和切换结果。失败保留原工作空间，目标仅待处理，不删除来源或重写旧报告。

已知缺口在目标当前有效性投影中继续显示；历史报告正文、评级和接收回执原样保留。只有后来真正取得有效材料才按原补证规则生成新修订。无新增损失不是声称修复全部历史，未确认活动执行、无法枚举的损坏和迁移中新损失均不可通过此模式豁免。
