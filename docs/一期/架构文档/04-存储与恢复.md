## 1 布局

```text
workspace.json / writer.lock / current.json
generations/<generation>/records/ manifests/ indexes/ events/
objects/<project>/<sha256>/
transactions/<transaction_id>/
spool/<attempt_id>/
workdirs/<run_id>/
checkpoints/ migrations/ diagnostics/
outbox/                           # 三期启用，保存意图和投影引用
```

generation用于结构版本迁移，不为每个步骤复制全量世代。项目.aitest仅放共享配置/模板，不存凭据或执行证据；工作空间放OS用户数据目录，禁止同步/网络盘。路径和符号链接解析后仍须检查实际范围，检测无法可靠确认时给出不可用原因。

### 模块职责

本册负责所有记录如何可靠落盘：文件布局、单写协调、原子提交、对象管理、检查点、崩溃恢复、迁移与备份。其他分册一律经本册的工作单元写记录，不自行操作文件。

### 文件布局

项目 `.aitest/` 只放可共享配置和模板，不放模型密钥或运行证据。本地工作空间位于当前操作系统用户的数据目录；工作空间属于单个操作系统用户，跨用户或跨主机不共享活动目录。

```text
workspace/
├── workspace.json                 # 工作空间标识、后端与结构版本
├── writer.lock                    # 操作系统锁载体
├── current.json                   # 原子切换的当前已提交状态指针
├── generations/<generation_id>/
│   ├── manifests/                 # 不可变提交清单
│   ├── records/                   # 项目、运行、问题、报告等修订
│   ├── indexes/                   # 按项目及对象类型生成的摘要分片
│   └── events/                    # JSONL 事件，按已提交边界读取
├── objects/<project>/<sha256>     # 已验证不可变附件与源码对象
├── transactions/<transaction_id>/ # 未发布事务文件
├── spool/<attempt_id>/            # 可恢复输出、块清单及终态标记
├── workdirs/<run_id>/             # 活动源码物化与临时运行文件
├── outbox/                       # 三期冻结提交与安全投影引用
├── checkpoints/                   # 执行句柄、采集游标、恢复状态
├── migrations/                    # 迁移清单及检查点
└── diagnostics/                   # 脱敏日志、最近健康状态
```

## 2 单写与提交

portalocker取得真实OS排他锁，文件存在/mtime不代表锁有效，不删活进程锁。一个核心持锁；无响应时监督器先阻止新动作并尝试结束旧核心，确认退出且真正取得锁后才接管；否则NOT_READY。writer_epoch递增，迟到写入核对epoch、项目、意图与expected_revision。

事务步骤：校验→写不可变记录/变化索引/对象至transactions→校验长度摘要引用并刷新→对象入库、不可变清单含幂等和事件有效边界→同卷原子发布current并按文件系统语义刷新→发布成功后确认/推送。保留前一有效指针，损坏清单不可当有效状态。外部网络/执行不持事务，写入队列有界，拒绝时明确可重试。

普通查询从清单和项目摘要分页，不扫描全部附件；提交只改相关分片，不重写全部历史。对象读取检查项目归属、引用、大小和摘要。流式导入/物化校验实际字节，空间不足明确失败，不能假报保存成功。

### 单写协调

- 一个工作空间只由一个核心进程持有操作系统级排他锁；使用 `portalocker` 建立锁，启动时有界等待；已有进程仍持锁时返回 `WORKSPACE_IN_USE`。
- 锁文件存在不代表锁仍有效；不根据文件时间强行删除或解锁活进程。
- 进程退出后操作系统释放实际文件锁，新进程取得锁后执行恢复扫描；锁文件内的进程信息、启动标识与心跳仅用于诊断。
- 写入协调者取得锁后更新 `writer_epoch`，旧异步结果提交时核对 epoch 与预期记录修订。
- 进程无响应时，本地监督器先停止接收新动作并尝试结束该核心；确认旧进程退出且取得真实锁后才启动恢复。若不能终止旧进程则显示 `NOT_READY`，不允许第二写入者绕过锁。
- 网络调用、模型请求与业务测试在提交事务外执行；协调者只串行处理短事务，队列有界；暂不能接受时返回可重试错误。

### 原子提交

`WorkspaceUnitOfWork`接收命令、持久业务键、预期修订及writer_epoch。大文件采集、摘要计算、模型/网络及被测执行在写事务外完成，短事务仅发布已准备材料。

1. 在唯一写入队列校验epoch、业务键/payload_hash、项目归属及expected_revision。已提交同键返回原结果，异输入冲突。冻结base_commit和待发布的变化集合。
2. 在同卷transactions写不可变记录、受影响索引页、事件段及业务幂等结果；新证据对象须有长度/摘要/归属验证，既有对象复用引用。写失败保留旧current，按第3节识别实际输出，不粗暴清空。
3. 完成材料写入并刷新用户态及文件缓冲，检查每一步返回结果；将文件发布到不可变目标位置。已有同名对象必须校验一致，不覆盖不同字节。对象的有效业务归属仍以提交清单可达性为准。
4. 写CommitManifest，包含commit_id、generation、writer_epoch、parent_commit、变化记录引用、index_root、event_range、幂等结果引用和文件摘要；持久化成功后才准备current候选。
5. 将current候选及此前有效指针写入带摘要的恢复材料并持久化；同卷发布current，校验其指向清单及关键引用。发布边界前查询只见base_commit；边界后只见新完整提交。替换返回不确定时停止新写入，先核实实际current，不盲目宣称失败或再次执行业务。
6. 只有后端报告发布与所要求的持久化完成，才确认成功并广播该commit的已提交事件。响应丢失由持久业务键取回；事件可重复传输但不可先于提交。恢复不能仅凭一个未发布清单就认定业务提交成功。

current包含schema_version、workspace_id、generation、commit_id、manifest_digest、index_root及event_cursor。CommitManifest是历史事实，current与索引是定位入口；历史根不可只通过会覆盖的“最新记录”索引保存。

#### Windows文件后端

后端封装write_and_flush、publish_immutable、replace_current、inspect_publication，不让应用层调用平台文件API。Windows文件写入先刷新语言缓冲，再使用可写文件句柄执行FlushFileBuffers并检查结果；现有current采用同卷ReplaceFileW及备份路径，初次初始化使用同卷创建发布，期间不接纳业务写入。遇共享冲突、权限或替换中间状态，按错误码核实current/候选/备份实际内容；不能先删除current再复制。恢复只接受身份、摘要及完整引用通过的已发布根，降回旧根时必须标记待核实与可能的提交缺口，不能把已确认结果静默抹去。

ReplaceFileW不支持REPLACEFILE_WRITE_THROUGH标志，不能把该标志当耐久保证。文件刷新和名字替换是不同步骤；支持矩阵分别记录进程中断一致性与目标文件系统/设备的掉电恢复证据，未经实测不宣称已满足掉电耐久性。普通桌面运行不通过管理员整卷刷新兜底。后端不能达到声明的保存语义时阻止新写入并提供诊断，已有记录可读。

技术依据：[FlushFileBuffers](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-flushfilebuffers)、[ReplaceFileW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-replacefilew)。具体实现仍须在目标Windows与本地文件系统执行第8节故障点验收。

## 3 输出抢救与恢复顺序

spool与transactions不同：前者承载执行器已产生的输出及归属元数据，后者承载未发布事务。块须含Run/Step/Attempt、块序号、长度、摘要、完整性；执行检查点引用块与真实进程启动身份，不只存PID。

1. 取得锁并更新epoch，验证current/有效清单，确定最后已提交状态。
2. 核实活动进程/句柄及其workdir，标明仍活/结束/未知；未知副作用禁止自动重放。
3. 先检查spool及transactions中的输出候选，验证归属、摘要和完整性；部分块只转为部分证据；未知类别保留待处理。
4. 经工作单元发布恢复事实、块引用和待核实状态，恢复动作可重复且幂等。
5. 确认无活动执行器引用、必要证据已保存后，才回收workdir、纯临时副本、空对象与无有效输出的未发布事务残留。
6. 从已提交事件边界续读，忽略无效尾部；缺索引重建，缺原始证据明确报缺口。

不得先清空transactions或spool再抢救；非空不等于完整证据；无清单引用不等于可删业务材料。恢复期间再次崩溃不重复认领证据或重放业务。正常启动检查增量恢复状态；完整历史扫描由明确维护动作执行。

### 检查点与崩溃恢复

| 检查点内容 | 用途 |
| --- | --- |
| 最后已提交阶段、当前尝试 | 判断从哪里继续 |
| 执行句柄、输出游标 | 重新关联或补取输出 |
| **已落盘的输出块引用与块序号** | 句柄失效时按块重建证据（见[执行与证据](02-执行与证据.md)第2节） |
| 输入摘要、副作用分类 | 决定可否安全重试 |

## 4 永久保留

运行证据、所有报告修订、导出、诊断、业务元数据、本地复核以及已发布世代永久保存：无保留期、无自动清理、无业务删除入口。用户外部删除/磁盘故障造成缺口时如实标记，不篡改旧结论、不宣称完整。

例外不变：执行停止且证据保存后的源码物化副本和运行临时材料、上传结束的冗余临时副本可回收；崩溃空对象与确认无有效内容的事务残留可回收；已经产生的输出先保留为证据。不可判类别不删。非Git必要源码和Git差异对象按快照记录保留，临时物化不等于永久源码对象。

去重和可逆压缩可减少重复保存，原始逻辑内容摘要与压缩字节摘要分开。容量检查预留实际已知收尾材料空间，不能保证任意无限输出；若保存不能继续则暂停/请求停止并记录缺口。只展示组成与剩余空间，不静默驱逐历史。

## 5 凭据、诊断与重试

所有spool、transactions、永久对象、诊断和备份只接纳满足[采集安全合同](02-执行与证据.md#13-采集安全与原始证据语义)的材料。原始输出指凭据过滤后的捕获流，过滤前字节不能用“原始证据”名义保存。过滤摘要元数据与对象引用同时发布；正文、大小、摘要及游标均以实际安全字节为准。恢复只认领具有相应策略与安全状态的材料；旧材料安全状态不明时保留受控隔离、标待核实并禁止展示/外发，不假定已过滤，也不自动删除永久历史。凭据边界与一般业务敏感信息的导出投影分别校验。

SecretPort在工作空间外用OS凭据设施管理正文；模型、被测HTTP、独立核验数据库、GitHub只读分用途命名空间，三期增加账号令牌。面板/配置/MCP/导出只显示引用。无可用后端明确不可用，不降级写明文工作空间；受控环境变量引用可作为显式选择。

适配器归一错误，connectivity唯一决定重试/降级。可重试只读操作或符合执行分册第10节的原请求幂等恢复沿用一次失败周期最多3次自动重试，间隔2/5/10秒；新副作用Attempt不由连接层自动创建，须重新授权；周期状态持久化，重启不清零。UNKNOWN优先查询也受相同周期约束；网络控制超时用于识别失联和结果未知。日志必须脱敏并永久保存。

### 凭据与连接

| 组件 | 职责 |
| --- | --- |
| `connections.py` | 连接类型、配置版本、最近自检时间、错误类别、恢复周期与下次尝试时间 |

- 换机器无密钥时标为不可用并明确提示，不静默失败。
- 只读查询最多自动重试 3 次，间隔 2、5、10 秒；失败周期持久化，重启不重置次数。
- 重试周期的实现只在本册与[编辑器接入](05-Trae接入.md)的连接自检处，界面层不得各自再写循环。

## 6 备份与迁移

备份冻结一个已提交历史根及其可达的全部永久记录、历史世代/清单与对象闭包、版本/epoch/事件边界和摘要，清单最后完成，校验后才可恢复；不自动轮换删除，位置独立于活动目录。恢复到新目录，校验关联和对象后切换，活动步骤必须重新核实。

aitest migrate inspect/plan/apply/resume/rollback保持维护入口；迁移前必须有对应迁移模式的可校验备份，进入维护状态暂停新写入。新generation保存转换结果和检查点，校验后原子切换；切换前可保留原代，切换后有新写入不允许丢弃式回滚。旧来源未知不推测，旧解析集中迁移模块。只有实际格式升级才实现对应迁移器，不预先设计任意格式转换平台。

### 数据结构迁移

提供 `aitest migrate inspect`、`plan`、`apply`、`resume` 与 `rollback`：

- 迁移器按版本注册；先检查源结构、引用与目标写入空间，再预演生成报告；迁移在维护状态进行，暂停新写动作。**迁移前必须先完成一次可校验的备份（或完整导出）**：切换后不允许回滚丢弃新写入，没有备份就没有退路；备份缺失时迁移拒绝开始并说明原因。
- 迁移写入新 generation，源代保持不变；检查点记录已转换对象及摘要，中断后核对结果再续写。
- 完成后检查编号、关联、记录数与内容摘要，原子切换当前 generation。
- 切换前失败保留原代；切换后如已接受新写入，不允许直接回滚而丢弃新数据，须先导出或转换新增记录。
- 旧解析逻辑集中在迁移模块，不散布到业务用例；业务读取只消费当前结构。
- 缺失的旧来源标识保留未知，不能由显示名推测；旧结论未经当前证据核验不自动变为有效。

## 7 目录责任与对象生命周期

| 路径 | 内容 | 使用边界 |
| --- | --- | --- |
| workspace.json | 工作空间ID、结构版本和后端信息 | 不含凭据正文 |
| writer.lock | OS锁载体及诊断身份 | 存在/修改时间不代表锁有效 |
| current.json | 当前有效清单指针与世代 | 同卷原子切换，保留前一有效指针 |
| generations/.../records、manifests | 不可变记录、对象引用、提交/幂等信息 | 已发布内容永久保留 |
| indexes、events | 查询分片、JSONL事件及已提交有效边界 | 索引可重建；事件无效尾部不得广播 |
| objects/<project>/<sha256> | 已校验附件、必要源码、冻结投影等 | 读取校验归属/摘要，不因跨项目同摘要而授权读取 |
| transactions/<id> | 未发布记录与文件提交材料 | 恢复检查输出候选，不能无条件清空 |
| spool/<attempt> | 凭据过滤后的原始捕获块及归属/完整性/过滤元数据 | 采集成功先保存字节，再推进可确认游标 |
| workdirs/<run> | 专用源码物化和运行临时副本 | 无活动引用且证据发布后回收 |
| checkpoints、migrations | 句柄身份、块引用、恢复/迁移进度 | 恢复动作必须可重复，不据游标重放业务 |
| diagnostics | 脱敏诊断、维护与恢复记录 | 永久保留，不轮换删除业务诊断 |
| outbox/<account_key> | 三期提交记录关联及脱敏投影 | 唯一冻结材料永久保留，令牌不在此保存 |

逻辑记录、内容对象和可重建索引分开；一次小提交只写变化记录和相关索引，不复制历史世代。源码物化副本与永久保存的必要源码对象虽可能字节相同，生命周期不同，不能按目录名笼统回收。

## 8 提交故障点与恢复结果

| 中断点 | 可认定事实 | 恢复动作 |
| --- | --- | --- |
| 写临时记录前 | 原current仍有效 | 原事务未生效；业务副作用需另按Attempt核实 |
| 对象写入中 | 可能只有部分字节 | 校验归属/完整性，保留可识别输出为部分证据 |
| 对象已入库、清单未发布 | 无新业务可见性，但可能有执行输出 | 抢救候选、幂等认领；无引用不等于可删除 |
| 清单已写、current未切换 | 原current仍是已提交状态 | 核对记录/对象；不能仅凭完整清单擅自广播成功 |
| current已发布、响应未返回 | 事务已成功 | 由持久幂等记录返回原结果，不重复执行 |
| 事件发送中 | 只认已提交事件边界 | 客户端按游标去重续读或SNAPSHOT_REQUIRED |
| 恢复再次中断 | 部分抢救可能已发布 | 按原块身份/摘要认领，不产生重复证据或提前清理 |

完整性检查区分清单损坏、对象损坏、缺索引和缺原始字节；索引重建不能修复丢失证据。普通启动只检查必要恢复状态，用户显式完整检查才扫描全部历史引用。任何自动回收先核对执行器状态与数据归属，无法判断的材料保留待处理。

## 9 备份、迁移和维护的具体步骤

1. 备份选择一个已提交历史根，记录workspace/generation/epoch/事件边界；按第10节复制全部永久历史闭包，而非仅最新对象，最后生成带摘要的备份清单，校验成功才标可恢复。
2. 备份不包含密钥正文，不自动轮换删除；恢复凭据按OS后端流程另行处理，换机缺凭据明确显示不可用。
3. 恢复写入新目录，校验项目归属、数量、引用与对象摘要后再切换；历史活动运行重新核实句柄，不恢复成已完成。
4. 迁移inspect检查实际结构与缺口，plan给出转换范围；apply前验证备份并进入维护模式，暂停新写动作，网络或活动执行须完成受控收尾/核实。
5. 迁移写新generation，记录逐对象转换与摘要；resume核对检查点再续写；完成后对比编号、引用、记录数及内容再切换。
6. 切换前失败原代继续可用；切换后接受了新写入时，rollback不得丢弃新增记录，须先受控导出或转换。未知旧来源保持未知，旧解析只在迁移模块。

MaintenancePort不含删除业务记录能力。维护记录给出检查范围、已完成项、错误类别、材料缺口与下一步；可重建索引与不可复原证据分别报告。能力不可用时拒绝相关动作，不为了完成维护绕过单写锁。

## 10 备份历史闭包与活动材料

current指向的提交历史根须能经不可变历史目录/前驱清单遍历该边界之前的全部已发布世代与记录修订，而非仅最新记录索引。BackupManifest登记root_commit、全部历史清单/世代、记录与对象的数量/大小/摘要、永久诊断与导出引用、已知缺失清单和备份类型。使用内容引用去重复制，不逐提交复制全量对象。该历史可达性合同也适用于结构迁移，索引不能作为唯一历史来源。

| 备份范围 | 处理 |
| --- | --- |
| 已发布永久历史 | 全部项目、Run/Attempt、旧报告修订、问题/处置、本地复核、导出、诊断及二期图定义/修订；三期含候选/游标、提交、唯一投影、控制决定与回执 |
| 引用闭包 | 递归纳入上述记录引用的证据、必要源码、投影、图件与导出产物；外部导出副本不作唯一保存来源，成功登记前将永久产物存入受控对象库 |
| 凭据与可复取外部源码 | 不复制密钥正文；Git仓库/LFS等未保存的复取依赖列外部前置，不伪装成已备份源码 |
| 未发布活动材料 | 普通已提交状态备份不复制正在变化的spool/workdir/transactions；记录活动Attempt、材料位置和未纳入原因，不宣称完整运行备份 |

在线备份可覆盖其root_commit之前全部已提交历史，后续提交不混入同份清单。诊断等永久文件须有可冻结的段/对象及提交引用；活动段只复制已提交字节边界，不能复制过程中变化的文件并宣称一致。发现应在闭包中的记录/对象缺失，标为有缺口备份，保留材料但不得作为迁移前完整备份验收通过。

完整停机/迁移备份先进入维护模式，停止接纳新业务执行与新发送，现有执行和在途请求受控收尾/核实；仍允许收尾写入。抢救并发布spool/事务输出后，冻结最终历史根再复制。仍有未核实活动执行器或无法归属的材料时阻止迁移切换，不提前清理，也不把它们排除后称完整备份。完整迁移前须验证完整历史闭包及摘要；确有历史缺口时仅可按第11节显式无新增损失模式办理。

恢复到新目录，重建索引后核对最早报告、被替代修订、全部尝试、复核、诊断、图件和上传历史；备份中活动/未知步骤仅恢复为待核实，不自动执行。若原工作空间尚有活动执行，恢复副本先只读隔离，不允许双工作空间接管同一Attempt。恢复引用和凭据不可用时如实显示缺口。P1-AC28/35以及P3-AC03验证永久历史完整性与活动材料边界。

### 备份与恢复

- 备份固定一个已提交清单及其引用对象，记录工作空间、generation、writer epoch、事件有效边界与各文件摘要；**备份不做自动轮换或删除**（本地永久保存），复制期间不会删除任何引用对象。
- 备份清单最后写入，校验完成才标为可恢复；备份位置由用户配置在独立于活动目录的存储上。
- 恢复先写入新目录，验证清单、对象与本地项目关联，成功后才切换工作空间。
- 运行中的步骤按检查点核实，不能恢复成已完成。
- 报告完整性与结论当前有效性重新计算，不能用历史汇总掩盖缺失证据。
- 诊断记录包含备份及恢复时间、清单校验结果与缺失内容；密钥按凭据设施流程备份恢复，不写入普通文档。

## 11 已知缺口下的无新增损失迁移

完整迁移仍要求全部永久历史闭包和摘要验证通过。原工作空间已有截图/对象丢失时，可由用户明确选择“保留已知缺口迁移”，不得把它称为完整恢复。

1. 进入维护模式，停止接纳新执行/发送但允许收尾写入；核实全部活动执行器，抢救并发布可归属spool/事务输出。仍有未核实活动执行器或无法归属材料时阻止切换，此门禁不因选择缺口模式而取消。
2. 在固定历史根枚举全部应有记录及对象，形成现存且可读集合A、已知缺失/损坏集合G。记录每项ID、路径、大小、摘要或损坏情况、引用关系、已知影响、旧历史根及结构版本。清单经人工确认并冻结，不把外部凭据或未保存Git对象冒充本地丢失对象。
3. 为A及G清单生成可核对备份，保留原目录；已损坏但可读的字节也按原状保留并标损坏，不用其支持有效证据。结构不可解析、无法完整枚举关联或转换不能保真时拒绝此模式。
4. 逐项复制/转换A，验证内容、编号、全部历史修订及引用。G在目标显式保留缺口记录与原关联；不能删去引用、补造字节、标成不适用或自动使旧结论有效。
5. 切换前证明A全部已保存、G与用户确认的清单一致且没有新损失；若复制中再丢失/损坏一项，立即拒绝切换，不能追加到G蒙混通过。用户重新评估后须重新inspect/确认/备份，不在原事务内扩大豁免。
6. 满足上述条件后原子切换，保留原目录和备份以及MigrationManifest中的mode、A/G摘要、确认引用、逐项结果。resume验证冻结清单及进度后续行；切换后新增写入仍受原有禁止丢弃式rollback约束。

界面区分“完整迁移完成”和“按已知缺口迁移完成”，显示受影响报告、证据及可复现范围。P1-AC28验证旧截图已缺但现存材料可迁移，以及复制中新丢对象必须拒绝切换。

## 12 查询索引与按需读取

索引仅支持已有列表和ID查询，不提供任意查询语言。IndexRoot记录commit_id及项目/记录类型目录页引用；目录页按固定前缀分片指向有界数据页，数据页包含record_id、最新revision、状态、排序键和摘要引用。分页游标绑定查询条件、commit_id和最后排序键；翻页继续该快照，用户刷新才换根。小提交复制受影响页及其目录路径，不复制全项目索引或全部历史。历史修订通过对象自身的前驱引用与分页索引读取。

索引损坏或缺失时重建受影响分片并明确暂不可用；普通查询不能偷偷遍历全历史来伪装索引正常。显式完整检查/备份允许遍历永久历史闭包，二者与日常读取分开。已发布索引可重建不代表可以删除其引用的业务材料。

对象发布时流式计算完整摘要；分块清单记录总大小、固定顺序块ID/长度/摘要和完整对象摘要，块清单纳入已提交引用。按需范围读取先校验归属及块清单，再读取并验证触及块；没有受信分块清单的旧对象须先完整校验并建立可复用结果，不能每个分页重复哈希整个对象。仅mtime/大小相同不能证明内容不变；校验缓存绑定实际内容摘要、已提交块清单及受控对象身份，发现对象变化或异常立即失效。

诊断按不可变段及已提交字节边界保存，活动段不当作完整冻结对象；永久段不轮换删除。日志追加不重写历史总文件。物化/导入/压缩在事务外流式完成，发布只登记引用。实际输出先进入spool，写队列饱和时暂停新步骤并保留已产生材料；物理空间不足按现有收尾守卫处理，不能承诺无限输出。

效率核对以访问范围为准：列表只读取摘要页、详情只读取所选对象块、小提交只更新相关页、正常恢复只检查活动/未发布材料。观察实际读写路径和重复计算以发现退化，不新增费用、资源或总执行时限指标。

## 13 有限查询与索引键

固定前缀分页只限制单页大小，不能单独保证筛选或排序不扫全项目。IndexRoot在同一commit_id下登记以下查询目录；每类索引按其完整组合键排序分片，不能只按record_id前缀存数据后全扫过滤。索引值保存最小摘要和精确记录引用，不复制证据正文。稳定末尾ID用于消除排序相同项的歧义。

| 已承诺查询 | 组合键与排序 | 更新边界/读取范围 |
| --- | --- | --- |
| 项目当前运行、运行列表及状态筛选 | project_id、可选execution_state、recorded_sequence、run_id；未筛状态与按状态各有对应范围入口 | Run新增/状态变更更新受影响页；只读匹配范围页 |
| 报告列表、编号查询及某报告修订 | reports.latest与reports.by_id按下文QuerySpec；另有project_id、run_id、report_id、content_revision修订索引 | 新修订同步维护最新报告摘要及其业务结果索引，列表折叠；精确编号直达，展开后按修订分页 |
| 二期源码身份分组历史及筛选 | history.groups与history.runs按下文QuerySpec；保留project_id、source_identity、conclusion_key、run_sequence、run_id | 新Run/当前判定仅更新所属组和受影响筛选键；组摘要与组内运行分别分页 |
| 问题列表及模块/层级/复核/处理/处置/阻塞/级别筛选 | issues.list；project、view、facet、facet_value、可选severity、updated_sequence、issue_id | 下文固定14种筛选掩码及OPEN/ALL范围；受影响问题在同一提交更新旧/新键 |
| 对象ID及其历史修订 | project_id、record_type、record_id、revision | ID点查与该对象修订范围，不扫描其他对象 |
| 三期当前账号/目标的待发送项 | 精确account_key、target_id、控制状态、接收状态、next_retry_at、submission_id | 许可、接收与控制变化更新相关索引；按有限允许状态范围合并，沿既有Clock/退避守卫，不读其他账号正文 |

QuerySpec是contracts中的有限查询定义，保存query_id/schema_version、允许筛选组合、排序键、页大小参数及目标索引；API不接收任意表达式。页大小按实现需要验证为正且有界，不在此新增资源预算指标。分页游标固定query_spec版本、条件摘要、commit_id、最后完整排序键；不同条件不可复用游标。查询目录版本变化的旧游标明确要求刷新，不能悄悄换根。范围索引缺失/损坏返回INDEX_REBUILD_REQUIRED并重建目标分片，不隐式扫描全部历史伪装正常。

同一业务工作单元同时发布记录和全部受影响索引页；删除旧状态键只是可重建索引投影更新，不删除永久业务事实或历史索引根。新索引的全量构建是显式维护成本，不混入普通面板查询。没有对应QuerySpec的筛选不提供界面入口，也不自动走全表扫描；新增已承诺界面查询时先补对应有限索引合同。

效率验证记录读取/写入路径、涉及对象与索引页：无关历史增长不应使一次固定范围分页或小提交遍历全部证据。同时验证同commit翻页、更新后刷新、相同排序键、组内新修订、状态迁移及索引损坏。该检查不设费用、资源预算或总执行时限；永久记录、对象和历史可达闭包仍保留。

### 上传扫描与业务提交

三期候选游标只随实际候选登记提交，不因扫描回执、候选或游标自身生成纯游标提交。使用[候选扫描边界](../../三期/架构文档/02-结果上传.md#13-候选扫描的停止与提交边界)固定高水位及连续前缀，经business_change_index_root对允许业务类型seek并合并读取。无业务增量不提交检查点；恢复不遍历纯上传/诊断事件尾部，队列满仍不越过未登记业务。该索引是本地文件存储的通用业务变更目录，不由上传适配器写入，不依赖账号、网络或发送许可。

### 页面控件与QuerySpec固定目录

以下query_id由contracts统一定义；所有查询固定project_id及commit_id，输入字段缺失与显式枚举值严格区分。报告“状态”明确指业务结果business_outcome，不是execution_state或有效性；界面分别标注，不合并为一个不透明status。编号首版精确匹配并标“输入完整运行/报告编号”，不暗示模糊检索，也不只过滤当前已加载页。

| query_id/页面 | 允许筛选与排序 | 索引与更新 |
| --- | --- | --- |
| issues.list，一期问题列表 | project必填；view=OPEN/ALL；facet为NONE/module/layer/review_state/workflow_state/disposition/blocking之一；可叠加severity，固定14种掩码；updated_sequence降序、issue_id升序 | 按project、view、mask、类型化筛选值、sequence、issue_id建范围入口；模块多值展开；详见下方问题查询合同 |
| reports.latest，一期报告列表 | project必填；business_outcome可选；按最新报告发布sequence降序、report_id稳定补序；同Run修订折叠 | report_latest按project、业务结果或ALL、sequence、report_id建范围入口；保存当前最新修订引用；新修订原子替换该报告旧/新状态键 |
| reports.by_id，一期完整编号查询 | project＋run_id或report_id精确查；可附business_outcome过滤 | 独立ID目录直达最新报告摘要，Run与Report编号有明确类型；不扫描文本；未匹配返回空，不混为索引损坏 |
| reports.revisions，展开历史修订 | project＋report_id；按content_revision降序；不继承列表业务结果过滤 | 精确报告修订范围读取，展示每个历史修订自身结果与policy_version |
| history.groups，二期源码组 | project必填；source_identity可选；按组最新run_sequence降序、source_identity补序 | project组摘要/最近序号索引；源码精确查有独立入口；不对全部组回放运行 |
| history.runs，二期筛选后的运行 | project必填；source_identity可选；scope_revision、environment_revision、tier、business_outcome任意组合；run_sequence降序、run_id补序 | 为此有限四字段集合建立16种筛选掩码入口，各自有跨源码与限定源码两种范围；键为project、source范围、mask、按固定字段顺序的实际筛选值、run_sequence、run_id |

history.runs无筛选时mask=0；缺省维度不使用业务字符串作通配值，source范围用Schema区分ALL与准确源码。仅这四个字段的16种掩码可用，不开放任意表达式、任意排序或其他字段组合；项目与源码范围入口共32种有限投影。此处为满足现有全部筛选组合承担明确索引写放大，未来如要减少组合须先改产品合同，不能静默删控件或全扫兜底。筛选生效时按运行分页，页内按源码加组标题并标“筛选结果分页”，不假称列出了整个源码组；无过滤浏览使用history.groups后按组读取history.runs。

历史运行摘要包含冻结source_identity、scope_revision、environment_revision、tier，以及该commit下该Run最新有效判定business_outcome、policy_version、报告引用。运行尚无可判定结果时使用独立unknown索引值，不补passed。同Run有新报告/确认/依赖失效时，在同一工作单元移除受影响旧筛选键、加入新键，旧commit索引根仍保留。scope/environment使用稳定ID＋修订，界面显示名称并可核对修订；conclusion_key仍用于当前结论选择，不拿它替代独立维度查询。

每个QuerySpec固定schema_version、过滤字段类型、排序、索引入口和有界页参数。游标绑定query_id/版本、条件摘要、commit_id和末尾完整排序键；改变条件即刷新，同键并列不漏不重。初次补建索引为显式维护；INDEX_REBUILD_REQUIRED不回退全历史扫描。P1-AC34/P2-AC07检查每种允许掩码、跨源码筛选、状态迁移、同commit翻页、新修订、损坏索引和无关历史增长后的实际访问范围。

### 业务变更稀疏索引的发布与维护

CommitManifest新增business_change_index_root，纳入同一清单摘要和提交闭包。file_store对可追踪业务记录按record_type保存有序索引，键为(commit_sequence, origin_workspace_id, project_id, record_id, content_revision)，值为已提交记录引用；每类根保留最大业务序号。所有业务类型均由存储Schema明确分类，上传候选另按其白名单选择类型；上传状态、候选、游标、回执、纯诊断不属于候选业务类型。一个业务提交中的多条记录分别入索引，不能仅留最后一条。

索引页在原子提交步骤中与记录/事件一起准备，步骤4写入同一CommitManifest，步骤5发布current之后共同可见；不允许先发布业务事实再异步补业务变更索引。纯上传、诊断及维护提交复用原根，不为“已扫描到当前commit”制造索引写入。根与当前清单绑定表示完整覆盖至该清单，不要求每个根的最大业务序号等于当前commit序号。平台模块缺失或候选登记失败不妨碍本地业务和索引同事务保存；存储自身无法可靠写入则按既有本地写入故障处理。

旧库缺少该索引时返回INDEX_REBUILD_REQUIRED，由显式维护从可信已提交历史构建，持久保存维护进度；固定构建高水位并补齐其后业务增量，发布前校验所用根和完整性。维护发布仅换索引根，不重放被测业务、不生成上传候选递归事件。候选发现暂缓，已有本地读取和具备可靠写路径的业务可继续；若底层清单本身损坏仍按恢复规则处理。白名单或索引Schema变化必须显式迁移并从可证明完整的起点补建，不能沿用不兼容游标跳过旧材料。备份保留根、引用页和历史；重建是索引维护，不删除旧业务记录。

维护首次全量读取的成本单列；日常扫描目标为索引定位成本加实际相关业务项读取成本，不作未经测量的毫秒承诺。P3-AC03通过访问计数验证无关尾部增长不导致等量顺序读取，并注入索引/记录发布前后崩溃和候选批次阻塞。

### issues.list固定Schema与索引合同

query_id=issues.list，schema_version=1。project_id必填，view只允许OPEN或ALL（默认OPEN）；facet只允许NONE、module、layer、review_state、workflow_state、disposition、blocking之一，非NONE须给一个类型匹配的facet_value；severity可选且只允许现行业务级别或独立UNKNOWN值。固定排序为updated_sequence降序、issue_id升序。模块筛选用稳定module_id，层级用既有L1/L2/L3及UNKNOWN；其余枚举见[报告与缺陷](03-报告与缺陷.md#14-问题查询投影与复核语义)。NONE时禁止传facet_value。首版一次选择一个主筛选维度，可再叠加级别；不承诺模块与层级等任意多维组合。

掩码为NONE、severity、module、module+severity、layer、layer+severity、review_state、review_state+severity、workflow_state、workflow_state+severity、disposition、disposition+severity、blocking、blocking+severity，共14种；各支持OPEN/ALL，共28种索引入口形态。ALL为显式Schema分支，不用业务字符串充当通配符。每个问题在一个commit下只返回其当前修订；历史修订从详情读取，不混入列表分页。OPEN包含尚需处理的问题：active/deferred，以及解析到仍未解决主问题的duplicate；fixed/non_defect及主问题已解决的duplicate不进入OPEN，均保留在ALL。无法解析的重复关联保留OPEN并显示缺口，不静默隐藏。

索引保存最小列表投影和记录引用，不复制证据正文。一个问题可关联多个module_id，对每个准确模块建立模块键；其他掩码仅一份，单一模块查询不得重复返回该issue_id。模块未知使用独立UNKNOWN分支而非空字符串通配。每次问题/有效复核/处置/归并关系或关联主问题变化，计算所有受影响投影，在同一业务工作单元移除旧键、写入新键和记录；重开与级别变化同样处理。updated_sequence取最后一次改变该列表投影的已提交序号，主问题引起的派生变化也更新此序号；不使用客户端时间排序。多问题更新在锁外准备、锁内核对依赖修订并原子发布；反向归并依赖索引列出受影响项，不能只更新主问题而遗留重复问题的旧OPEN/阻塞键。旧根和历史事实永久保留。

有m个已知模块的单条问题最多产生4m+24个入口记录；无模块按一个UNKNOWN分支计。这是明确的写放大上界（OPEN不适用时更少），不是新增实体或数据库。若需减少入口，先修订产品查询合同，不在实现中偷偷改成全表过滤。游标绑定query_id/schema、条件摘要、commit_id及末尾完整排序键；跨条件/版本重用返回QUERY_CURSOR_MISMATCH。非法组合返回QUERY_UNSUPPORTED_FILTER；缺失/损坏索引返回INDEX_REBUILD_REQUIRED。前端不得只过滤已加载页，也不全扫历史兜底。页大小沿用既有正且有界参数。
