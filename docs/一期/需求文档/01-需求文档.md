## 1 产品目标

建设一个可嵌入 Trae、**本地执行与存储、可选模型出站**的 AI 辅助测试插件：理解项目上下文、组织测试、调用模型 API 辅助分析、收集原始证据、形成问题清单并跟踪修复。

一期不依赖插件平台服务端：不部署服务、不登录、不上传结果、不做跨账号协作。全部记录保存在本机文件工作空间。

插件以 Python 核心包、Trae 扩展和轻量面板交付。链路检查是插件的一项能力；项目上下文、测试规范、分层执行、问题反馈与本地报告导出共同组成完整产品。

需要解决的问题：

- 模块合并后缺少整体检查，测试者不了解依赖。
- Mock 或假成功掩盖实际结果，成功响应被当作业务正确。
- 问题信息不完整，缺少可复现的证据与版本。
- AI 结论与实际执行事实混在一起，无法区分。

产品目标：

- 用相同规范组织测试，使验收项、用例、执行、证据和问题可相互追溯。
- 分别表达源码可运行、模块功能正确和用户完整业务流程通过。
- 将实际执行结果与开发说明、Mock 声明、AI 候选分析分开保存。
- 模型接口不可用时仍能保留证据并继续人工处理。

### 2.2 一期支持环境

| 使用形态 | 环境 | 必需接入 |
| --- | --- | --- |
| 编辑器本地自测 | Windows 11 x64、Trae 稳定版、Python 3.13 | 工具与面板、源码检查、模块与业务流程、证据与本地导出 |
| 模型接口 | 由客户端发起的出站调用 | 模型标识、密钥引用、超时与错误分类 |
| 源码控制 | 本地 Git；可选 GitHub 只读出站 | Git 本地版本识别不依赖远端；非 Git 不建立 Git 连接；无远端或非 GitHub 仓库仍可完成本地测试 |

### 2.3 一期不做

- 不部署服务端，插件自身不监听任何网络端口。
- 不登录、不接入统一账号，不做结果上传、回执、共享查询与跨账号审核。
- 不做自动操作录制与回放、可视化流程图绘制、任意语言自动插桩。
- 不做自动处理合并冲突、无人确认自动修复发布、生产部署管理。
- 不修改被测仓库：GitHub 接入为只读，不通过 GitHub 自动发起测试、不处理 PR；本地测试由用户授权后执行。

### 2.4 单模块、无仓库与多模块

一期必须支持"被测代码只有一个模块"的情形：可完成该模块的 L1／L2／L3 适用检查并形成报告。

**一期必须支持"被测目录不是 Git 仓库"的情形**：全部检查、证据、报告与导出均可完成；凡与仓库、分支、提交、远端相关的内容一律不出现（不显示为空值、不显示"未知"），源码变化改以文件清单摘要与差异快照判定，结论口径不变。

跨模块依赖传播仅在登记两个及以上模块时适用；单模块仍须进行本模块变更映射、回归建议与快速检查，仅跨模块传播显示不适用，不作为失败或缺失。

### 2.5 试点

试点采用工单管理示例，验证创建、查询、分页、详情和状态修改的真实业务结果。三层测试分别评价，不能用 GitHub 绿色状态、接口成功响应或 AI 文字说明替代完整证据。

### 2.6 复用与读取边界

复用与增量处理用于减少重复工作，不得牺牲证据与判定口径。

- **复用优先**：各派生物保存实际依赖的源码、上下文、验收项、规则、模板、环境及生成策略修订集合；仅在实际依赖全部未变时复用，不重新调用模型。只重算受影响部分；单模块仍检查本模块变化，跨模块传播才是不适用。首次或映射不明使用已发布保守检查集合；无法确定时提示确认计划。
- **分析材料最小化**：模型只接收当前任务选定的脱敏结构、差异、证据摘要及必要代码片段，不发送全仓源码或整份日志。材料因供应方输入限制被截断时，标注“基于部分材料”及缺口。
- **源码读取边界**：一期在用户显式“分析选定项目内容”、计划确认与发起运行时读取所选范围源码；分析不要求已有计划，不等于发布或执行。面板、历史和进度读已保存记录，不自动扫描当前目录；运行前展示最近固定版本并提示“当前目录尚未重新核实”。二期显式跳转可先查目标元数据；打开历史快照优先，用户请求校验当前文件时允许只哈希目标文件，不遍历整仓。
- **源码固定**：首次固定须建立真实内容摘要。元数据只提示可能变化，不证明内容相同；物化时对实际复制字节计算摘要并核对复制期间变化。按所选模块、依赖闭包、配置和入口物化，运行副本为临时产物，执行停止且证据落盘后回收。
- **完整验证不可通过删减变轻**：同一已发布验收范围内的适用必测项不得通过运行中删减规避（见 P1-FR07）。
- **红线**：优化不得抬高通过结论、跳过独立核验、把未知当已知或少写证据。

## 4 功能要求

### P1-FR01 本地项目与模块上下文

- **建立与标识**：建立本地项目并生成稳定的本地项目编号；绑定本地项目根目录，**仓库绑定是可选的**——目录可以是 Git 仓库，也可以是**普通目录（无版本库）**；路径解析为规范绝对路径。
- **上下文内容**：登记模块职责、输入输出、上下游依赖、接口说明与实现状态；汇总为项目上下文。
- **源码快照**：Git 保存基准提交、未提交新增/修改/删除内容及排除规则；非 Git 保存文件清单内容摘要、必要内容和差异。物化内容与执行身份一致。提交号不等于永久可复取：记录仓库、LFS/子模块等复取依赖和可复取范围，缺失则明确缺口；需离线复现的选定内容按摘要去重保存，不重复整仓留存。
- **异常**：目录移动或仓库变更时提示重新确认绑定，并保留原绑定记录；上下文缺失项保持可见。**不得因为"不是 Git 仓库"而拒绝建立项目或降级检查范围。**工作空间若位于**同步盘／网络盘**（OneDrive、网盘映射、SMB 等），启动时检测并**拒绝在该位置建立工作空间**并说明原因——同步器会破坏排他锁与原子替换语义，导致单写保护与崩溃一致性失效。

### P1-FR02 标准交付说明

- **输入**：原任务、完成与未完成项、变更模块、接口变化、运行方法、数据、依赖、Mock、已知问题和自测证据。
- **要求**：按模板填写或由 AI 生成草稿，用户确认后提测；开发自述完成与测试验证完成分别展示。
- **异常**：必填字段或可识别版本缺失时提示补齐；AI 文字不能作为完成率依据。

### P1-FR03 变更影响与回归建议

- **前提**：依赖边定义为「使用者 → 提供者」，依赖来自 P1-FR01 的登记；**用例与模块的关联**在 P1-FR06 发布用例时登记，是确定性匹配的最小依据。
- **要求**：需求、代码、接口或规则变化时，按已登记依赖做确定性匹配，列出待回归用例及其变更依据；由用户启动测试。
- **单模块**：保留本模块变更映射与回归检查，仅跨模块传播显示不适用并说明原因。
- **异常**：映射缺失不能解释为没有影响；仅靠依赖图推导的影响须标注「推导结果，可能不完整」；跨语言静态影响分析不在一期。

### P1-FR04 内置模板与检查内容生成

- **模板**：随插件提供版本化的通用模板包，按业务类型与技术栈组织。
- **最小必测项与关键链路**：模板除检查内容外，还必须给出该业务类型与技术栈下的**最小必测项清单**与**关键链路清单**（哪些依赖必须真实、哪次核验不可省）；模板条目必须标注**适用条件**（层级、模块类型、是否需要前端等）；应用模板时先按项目实际过滤出**适用必测项**（不适用项给出原因、不计入分母），低于适用下限的必测项或未覆盖的关键链路必须在报告中显示"必测覆盖率警告"，并在**完整报告**的证据等级上体现。
- **生成**：AI 结合项目上下文生成检查内容草稿，包含规则条目、验收项、用例与检查项。
- **确认**：草稿未确认发布不生效；生成内容与人工编写内容分别标注来源；人工修订不被生成结果覆盖。
- **异常**：无匹配模板时提示自建或导入；项目上下文缺失时列出缺口并阻塞，不编造依赖与结论。

### P1-FR05 测试规范与规则版本

- **内容**：面向人的步骤说明、AI 检查规则、证据要求与输出格式。
- **要求**：分类、修订、绑定项目；支持导入／导出 Markdown；确认后发布为不可变规则版本，新测试用新版，历史保留原版。
- **异常**：导入规则未确认发布不生效；文档正文不能自动触发新工具或补造上下文。

### P1-FR06 测试计划与用例生成

- **用例字段**：层级、前置条件、输入、步骤、预期结果、验证方法、允许的 Mock 与重要性。
- **要求**：AI 建议范围与用例，用户编辑、删除、补充后发布；覆盖正常、边界、异常、依赖失败与会话差异等适用情况。发布时必须把用例关联到适用关键链路条目，并登记该用例的**独立核验方式**；纯逻辑用例按其实际验证方法核验，不强行要求数据库。缺失关键链路清单会阻塞完整验证，确认无适用链路的显式空清单须附理由。
- **断言依据**：区分缺失、已填写未确认、已确认。缺失时不可进入完整验证必测项；已填写未确认可执行并保留在分母，标为断言未核实、不得计入已验证，完整报告降低证据等级；适用必测项仍有未确认依据时不能给完整通过。独立核验结果另存；确认依据不替代执行。
- **异常**：未确认发布的用例保留草稿；断言依据是否确认单独记录，不与发布确认混同；没有预期结果或前置条件不得标为可直接验收的完整用例。

### P1-FR07 运行档位与驱动配置

一次运行分别确定档位与初始驱动并冻结：**档位**决定检查范围和结论上限；**驱动**决定怎么推进。有效驱动仅可按下述规则单向切换，变化追加留痕，不覆盖初始值。

- **快速检查**：固定执行适用 L1、改动模块关键 L2 与适用的独立核验；无需逐项勾选，不判完整通过、不派生等级。无持久化业务时按实际验证方法核验，不强行要求数据库。
- **按需自测**：运行时由用户自选检查集，可只选某一层、某个模块或某个环节；只覆盖所选范围，**不判完整通过**，未选与未执行项逐条列出，**同样不打分**。**三档之中只有本档允许在已发布验收范围内选择本轮执行子集；计划发布前定义AcceptanceScope不受此限制。**
- **完整验证**：开始前纳入模板全部适用必测项与关键链路，用户只能增补。冻结档位与适用下限；运行中不得删除必测项、弱化断言或变更适用性来规避门禁。跳过、失败、取消、阻塞不会把档位改成按需，仍保留完整验证意图并如实报告未通过或未完成；禁止获得完整通过。
- **结论上限只由档位决定，不由覆盖多少或执行方式决定**：快速检查与按需自测即使把冻结范围全部勾满并跑完，也不能判完整通过；需要完整通过结论时必须新建一次完整验证运行。未选与未执行项保留未执行事实及原因，不能当作不适用；经核实的有效复用另标“本轮未新执行，已有效复用”，不与无证据的未执行混为一类。
- **驱动**：计划驱动（默认，确认一次计划后连续执行，内容来源标记为计划生成）与逐步驱动（每步确认后执行，可查看中间结果、随时补证或退回）；两种驱动使用同一套三层判定标准、模板版本与问题清单。逐步驱动的确认只表示允许进入下一步，**不重新判定断言、不改变结论上限**；有副作用的步骤必须单独确认。
- **运行中可改计划**：只修改未执行步骤，生成运行修订并保留原因，已执行事实不回改。完整验证修改须维持必测集合和断言要求；影响已完成依据时暂停、标记过期，当前结论不得使用失效依据。重跑需新运行或新的实际尝试，不伪装继承为本轮执行。
- **驱动单向切换**：运行中允许从计划驱动切到逐步驱动（收窄授权）；不允许反向切换，需要放宽授权时新建运行。
- **需求或验收项变更**：一律生成新修订，不改写冻结中的计划与已完成记录；受影响的当前运行暂停并提示，报告中标注受影响步骤的依据已过期并列出需重跑的用例。
- **约束**：任一驱动下遇到扩大范围、新凭据、明显副作用等情形都必须暂停等待用户确认；每次运行固定展示档位、驱动与覆盖范围及跳过项。
- **同意图去重与明确重跑**：准备运行生成持久 intent_id，绑定项目、源码、环境、计划、规则、模板和动作。跨入口提交同 intent_id 返回同一运行；用户明确重跑生成新 intent_id 和 run_id。同键不同输入冲突；启动物化必须匹配准备意图冻结的源码摘要，不一致须重新准备并核对授权，不能执行新源码却沿用旧意图。导出按报告修订、复核集合、格式和脱敏策略去重。
- **证据等级与业务结论分离**：仅完整验证派生 A证据充分／B局部不足／C关键证据不足／D无有效依据。业务结论单列通过、失败、未完成或不适用；A 可以对应有充分失败证据，不表示可放行。未知向下取最严重等级，不平均；快查和按需显示未打分。
- **隔离与等级**：默认虚拟环境；显式选择不隔离冻结于运行，源码仍强制物化。依赖环境、业务数据隔离/复位、目标部署版本分别记录，venv 不代表外部数据隔离。依赖环境方式作为独立事实，不因未使用虚拟环境自动降级；只有具体环境问题使所需证据无效/缺失或不满足验收条件时，才按对应规则降级或阻塞。等级主要缺口可为“无”，全量缺口仍保留。

### P1-FR08 源码可运行性检查（L1）

- **检查项**：语法检查、适用构建／编译、模块加载、最小启动；纯库或命令工具检查可调用入口。
- **支持范围**：一期自动适配 Python；其他技术栈按标准格式导入，标明外部来源与未核实范围。
- **判定**：L1 与业务结果分开判定；不适用子项给出原因；无成功证据不能声称可运行。
- **异常**：区分源码错误、依赖缺失、环境不可达、工具失败与通过。

### P1-FR09 引导式测试工作台

- **执行**：逐步查看与执行，记录人工操作、工具结果与 AI 分析。
- **控制**：暂停、取消、重试、补证、退回阶段；暂停在步骤边界生效；取消需确认执行停止后才置为已取消。
- **历史**：新尝试保留旧尝试并立即成为当前尝试；旧通过结果不因新尝试失败而回退显示。
- **异常**：缺少环境、凭据、依赖或数据时显示阻塞及原因，不能跳过后汇总为通过。

### P1-FR10 函数与模块测试（L2）

- **输入**：项目既有测试命令／入口、输入、断言、上下游与允许的 Mock。
- **要求**：运行函数／模块测试；AI 检查测试逻辑、建议补充用例并解释失败。
- **判定**：Mock 结果只覆盖声明的局部范围，具体业务效果必须独立核验。
- **异常**：成功提示或非空返回不能替代内容检查；真实依赖未接通时保留未验证范围。

### P1-FR11 接口与集成测试（L2）

- **输入**：接口、环境参数、凭据引用、请求数据、响应断言与核验方式。
- **要求**：按业务顺序串联请求，提取上一步输出作为下步输入；核对响应、字段、业务规则与适用的数据结果。
- **判定**：响应成功但字段错误或数据未写入时判为业务断言失败；缺独立核验能力时显示未完成。
- **证据与数据**：执行前必须明确并记录**测试数据的来源、隔离与复位方式**；数据被上一轮污染时不得作为本轮结论的依据。
- **证据链前置条件**：完整证据链要求被测应用提供请求标识与关键节点结构化日志；缺失时降级为人工关联证据并**显式标注证据级别与缺口**，不视为产品缺陷，也不因此判为通过。
- **异常**：不将接口状态等同于业务正确。

### P1-FR12 Mock 声明与真实性核验

- **输入**：开发声明、运行配置、静态候选、依赖清单与实际运行证据。
- **要求**：登记允许的 Mock；核对固定返回、内存替代持久化、测试替身、模拟接口与未接通依赖。
- **判定**：静态检查只给出候选；不能因出现 mock 字样判假，也不能因没有该字样判真。真实、Mock、混合与未知由本次环境与证据决定。
- **异常**：未声明 Mock、关键节点真实性未知或缺真实证据时，不给该范围真实链路通过。

### P1-FR13 用户操作与业务场景测试（L3）

- **输入**：用户业务目标、操作清单、测试数据、预期结果与证据要求。
- **要求**：人工按步骤操作并关联证据；覆盖按钮、分页、跳转、表单、滚动、适用鼠标操作、异常提示与展示数据。
- **判定**：必需步骤失败、跳过或关键依赖未知时不能全流程通过；每个业务目标至少一条完整 L3；工单固定流程见功能文档。
- **异常**：操作正常但展示错误仍可建立缺陷；异常路径另按验收项验证。

### P1-FR14 测试报告与本地导出

- **报告**：固定范围、源码与环境、规则版本、各层当前尝试、证据索引、问题修订与计算策略；报告正文不可变，变化生成新内容修订。
- **定位**：本地报告是过程记录与自检依据，不构成防篡改的组织结论；平台如何审核不属于插件交付承诺。
- **结论取用**：以项目、源码身份（含未提交差异）、适用范围、环境、规则/验收、模板及判定策略修订为结论键。最新完整验证开始即显示重新验证；取消、未知不回退旧绿灯。旧报告仍可查但标为历史；快查和按需为补充，不覆盖完整验证。
- **报告字段**：完整验证包含证据等级、主要/全部缺口、断言依据确认数；快查和按需标未打分并列覆盖摘要。保留本机采集、事件和复核时间用于追溯。
- **导出**：支持Markdown摘要与可携带证据包（ZIP内含report.md、manifest.json和脱敏附件）；摘要明确附件不随文件交付，证据包使用相对路径、摘要与缺口清单，在新目录解压可用；两者均不含密钥。
- **复核**：本地复核是**独立记录**（复核人、结论、说明、所依据的报告内容修订、时间），不写入报告正文、不改变正文内容修订；复核不改变测试事实。
- **异常**：源码、证据、当前尝试或问题影响结论时产生新报告修订，旧结论留在旧版。

### P1-FR15 缺陷管理与修复回归

- **问题清单**：人和 AI 使用同一编号与字段；缺失信息标为未知。
- **流程**：草稿 → 待确认 → 已确认 → 处理中 → 待复测 → 已关闭；不属于缺陷、重复、暂缓保留原因，不直接删除。
- **关闭依据**：修复关闭必须有新的实际执行证据；修复说明或 AI 判断不能替代。核实非缺陷、重复归并是独立处置，按一期功能第12.2节处理，不把原失败断言改为通过；暂缓仍保留有效阻塞。
- **修复交接**：问题详情提供“复制修复说明”，包含精确问题/尝试修订、预期/实际、脱敏证据、已知位置或未知原因、AI待验证假设与复测入口；不自动调用编辑器聊天、不修改被测代码。
- **异常**：先区分产品、环境、数据与脚本原因；复测失败重新进入处理流程并保留原失败记录。

### P1-FR16 永久保留与临时材料回收

- **永久保留**：**业务记录与证据**——运行证据、报告修订、导出文件、诊断日志，以及业务元数据与复核记录——**一律永久保存**；插件**不设保留期、不做自动清理、不提供删除入口**。运行期临时产物不属于本清单（见下一条）。
- **不做清理**：插件不计算"可删除集合"、不因时间到期删除任何业务记录或证据、也不提供一键清理入口。**唯一的例外是运行期临时产物**：隔离物化副本、运行中的临时文件、上传完成后的临时冗余副本，在运行结束或终止且证据已落盘后回收（它们不是业务记录，不需要用户处理）；崩溃恢复先核实执行器与引用，区分事务目录、执行器 `spool` 与物化 `workdir`；抢救可验证输出并发布恢复记录后，才回收无活动引用的空对象及临时目录。非完整输出标为部分证据；存活执行器的目录与归属不明材料不得抢先清理。
- **一致性**：材料缺失只可能来自外部破坏（用户手动删除、磁盘故障、迁移失败）或未完成提交；此时报告如实显示证据缺口、不宣称完整，**插件不得以"腾空间"为由改写结论**。
- **时间来源**：记录时间取本机时间（经 `Clock` 端口）；因为不涉及到期判定，修改系统时间不触发到期删除；事件先后依单调提交序号，显示时间只用于本机溯源，不作为可信外部时间证明。
- **空间与体积**：**记录与证据**只增不减，占用以证据为主（日志、截图、附件、原始输出，随运行轮次增长）；**源码不整仓复制**——Git 目录保存提交标识、未提交差异与复取依赖；离线复现所需的选定内容按摘要去重保存，外部仓库不可用且无保存对象时明确不可复取；非 Git 目录没有版本库可回取，需保留差异内容与必要文件内容（这是主要体积来源，报告会标注不可复取范围）。运行期物化副本用完即回收，不累积。插件只如实报告占用与缺口，业务记录与证据的清理由用户在插件之外自行处理。
- **异常**：无法判断材料类别时**不删除**（本就不做自动清理）；发现材料缺失时按缺口如实呈现。

### P1-FR17 检查信息面板

- **定位**：面板是插件主界面，**可操作**；其中的**信息面板**是只读信息区，把一期已经产生的事实按一次检查的生命周期分三段呈现（运行前／运行时／运行后）。**信息面板不新增判定、不写任何记录、不在信息区内放动作**；面板的动作限于发起与控制检查（开始检查／快速检查／暂停／取消／重跑／导出）与跳转，逐步执行仍在测试工作台，配置修改仍在配置页。
- **运行前**：展示本次要检查什么（代码版本、隔离环境、计划与必测项、跳过项），**信息区只呈现，不放操作入口**；计划发布、范围选择与发起运行由独立操作区或工作台承载。
- **运行时**：展示进度与发现的缺漏统计，可进入详情查看逐步状态与原始输出。
- **运行后**：单独展示业务结论、证据等级（非完整运行未打分）、断言依据确认数及真实覆盖/缺口；一期跳转已保存的证据或链路详情，二期再增加图节点跳转。
- **约束**：信息面板只读；展示的等级与统计必须与领域判定器的结果一致，不得在界面层另算；面板为实时值、报告为快照值，两处分别标明且口径一致。界面结构、每段显示内容、动作位置与空态由[检查面板设计](../设计文档/01-面板与工作台.md)维护。
- **目录形态**：目录不是 Git 仓库时，面板与配置页不出现仓库、分支、提交、远端相关内容，改为"本地目录模式"与文件清单摘要。
- **异常**：记录缺失时三段各自显示空态与原因，不显示推测值；模型不可用时 AI 辅助显示为不可用，不影响本地信息与导出。

## 6 整体验收与交付

整体交付应证明：

- 三层测试可闭环执行，问题可复现并回归。
- 按需自测不产出完整通过结论，并如实标注未执行范围与原因；完整验证确认计划后推进，遇副作用、新凭据或范围扩大仍需对应授权；只有完成全部门禁才给完整通过。
- 被测代码只有一个模块时仍可完成适用检查。
- 本地证据与版本可相互追溯，报告可在本地导出且不含密钥。
- 仅完整验证给证据等级与主要缺口，快查和按需未打分。业务结果与证据等级分别展示，面板读取同一判定 DTO，报告冻结来源修订。
- 快速检查可在一次改动后给出可判定的结论与覆盖摘要（**不打分**），且不伪装成完整验证；完整验证的**适用**必测项覆盖不低于模板给出的适用最小必测项与关键链路清单。
- 断网与重复运行不产生错误结论；模型不可用不影响原始证据查看与人工处理。
- **永久保留可验证**：全部记录、证据与报告永久保存、界面无删除入口、无到期清理；材料缺失时如实显示缺口（见 P1-AC28）。
- **本地复核独立**：复核不写入报告正文、不改变报告内容修订，也不改变测试事实（见 P1-AC29）。
- 本地核心、记录、人工处理与导出不依赖插件平台服务或平台登录；模型、可选GitHub与被测远端环境分别依赖其已配置的网络及凭据。


技术侧完成模块契约、来源核验、文件一致性、崩溃恢复与真实编辑器接入验证。

功能规则由一期功能文档维护；模块与接口实现由一期架构分册维护；插件账号关联与结果上传属于三期；跨账号审核属于平台项目，不在插件各期验收范围。

P1-FR17 的界面细则由一期设计文档维护；信息区只读、不新增判定，动作位于动作区和业务子视图。

## 7 产品使用合同（2.2）

- **最小首次输入（P1-FR01/04/06/08/17）**：选择目录、检查目的、登记实际入口/解释器及该检查必需环境，确认计划摘要后运行。可由目录创建单模块草稿；仅快速/按需检查时，不要求填写无关上下游、完整交付表、数据库或模型凭据；正式提测仍遵守P1-FR02，full仍须完整验收依据。首次默认快速检查，范围由适用模板保守生成，人工也可配置；无可用模板进入自建/导入，不擅自执行猜测命令。首发能力与模板见[清单](../功能文档/02-能力与模板清单.md)。
- **验收范围（P1-FR06/07/14）**：计划发布前明确验收目标、包含/排除模块或业务目标及原因、依赖闭包、适用条件、模板修订；生成不可变AcceptanceScope修订。full覆盖该范围全部适用必测，不表示自动覆盖整个项目；只有范围确为全项目才能如此展示。发布后不通过删必测或缩范围修饰原结论，范围变化建立新基线和运行。结果标题、复核与导出均带范围。
- **逐项授权（P1-FR07/09）**：集中列出待授权动作，可在启动前逐项确认，分别绑定本轮动作、输入、目标、凭据范围与计划修订；未知运行时输入必须待解析后再确认。相同未执行动作的有效授权不重复询问；新尝试不自动继承副作用授权。不给集合授权或永久信任开关。
- **模型出站（P1-FR04/06/17）**：模型配置独立于平台上传。首次出站确认项目、供应方/接收地址和材料类别，源码片段默认关闭；只发送显式选定脱敏材料，范围或目标变化重新确认。开启源码片段也不发送全仓。关闭AI阻止后续模型发送，已发请求不宣称已撤回；人工配置、证据和报告可用。
- **主流程（P1-FR17）**：主按钮标明“运行快速检查/运行所选检查/运行完整验证”；首屏展示范围、业务结果/未完成原因与下一步，等级/覆盖详情可展开。驱动为高级配置。动作区紧邻说明并调用核心用例；未知副作用先核实。
- **历史查找（P1-FR14/16/17）**：一期按项目/状态/运行或报告编号筛选，修订折叠；隐藏项目仅默认列表偏好，可恢复，不删除、不影响活动任务。空间不足给组成和既有备份/迁移入口。二期才增加按源码分组的高级历史页。

## 8 边界补充合同（2.5）

- 人工确认须来自核心认可的用户交互，MCP/非交互入口不能自报角色完成授权、发布、依据确认、处置或复核；重复确认幂等，输入变化重新确认。具体入口权限见一期架构05第9节。
- 重新执行业务与原请求恢复分开；新副作用Attempt重新授权，同号幂等恢复须有端点合同且不产生第二次业务执行。
- 问题修复关闭需要新回归证据；核实非缺陷、重复归并为独立处置，不改变原断言，暂缓继续阻塞。BlockingRule按一期功能第12.2节计算有效问题。
- 本轮检查S与完整验收必测M分开；执行完成E、有效复用R、有效验证V、通过P分列，E∩R=∅、R⊆V⊆E∪R⊆S，full另须M⊆S。合法复用不冒充本轮新执行，新Attempt不能回退旧复用结果。唯一集合定义见一期功能第3节。
- 视图快照与事件游标固定同一提交边界，订阅从其后重放，不能在两次读取之间跳过已提交事件。
- 备份覆盖所选边界前全部永久历史及引用闭包；在线备份明确活动材料不在范围，迁移须先受控收尾并验证对应模式备份；已知缺口可显式确认后在无新增损失条件下迁移，完整模式仍要求无缺口。历史报告不依赖最新索引或外部导出副本才能恢复。

以上补充既有功能与验收子场景，仍为17项FR、35项AC；不增加平台服务或改变永久留存与产品分期。

## 9 复用、选择集合及迁移模式（2.6）

quick/on_demand的所选检查结果以S计算，完整验收必测M始终单列；本轮选中的补充项同样参与结果，未选项不算不适用，partial不升级为full。full必须覆盖M，且S全部有效通过并满足原门禁才可完整通过。

只有经源码/环境/断言等一致性核实并明确采纳的历史证据才计有效复用R；它可以参与本轮有效验证但不计本轮实际执行。必须新执行的修复回归不允许复用，新Attempt不退旧通过。原始来源和计数在界面与报告分别展示。

永久留存不要求无法恢复的旧缺口阻断所有换盘；完整迁移与携带已知缺口迁移区分。后者人工确认现存材料/缺口清单、复制到新目录且逐项证明无新增损失、保留原目录和原缺口；未知活动执行、不可遍历历史及新损失仍阻止启用目标。详细规则以功能第3节和存储第11节为准。
