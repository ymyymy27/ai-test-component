## 2. 文档分层与维护边界

| 层级 | 目录/文件 | 维护方式 |
| --- | --- | --- |
| 现行规范 | `项目文档/` | 产品主责合同；按[阅读索引](项目文档/阅读索引.md)修改，不在本索引重复定义字段或口径 |
| 现行状态 | [`现状.md`](现状.md)、四包检查、[接口台账](接口对接/README.md) | 只写当前事实与未验证边界；代码/合同变化后同步更新 |
| 实施与交接 | [`一期工程整改/`](一期工程整改/README.md) | 现行交接与操作指南保留在 `04-交接/`；历史批次在归档 |
| 现行记录 | [`修改日志/`](修改日志/README.md)、[`validation/`](validation/README.md) | 只追加新记录；不追溯改写旧记录 |
| 归档 | [`归档/`](归档/README.md) | 已完成、被替代或只用于追溯的材料；不写入新工作 |
| 学习材料 | [`学习讲义/`](学习讲义/README.md) | 概念解释，不作为验收或合同依据 |

历史记录中的数字、结论和链接只证明其所属版本。现行判断以 `现状.md`、四包检查和接口台账为准；不得用旧记录覆盖现行规范，也不得把历史失败“修文”成通过。

## 4. 历史记录与归档的使用边界

1. **归档不腐化**：归档文件保留当时输入、命令、结果、失败与未验证范围；不追加新结论，不追溯改写。
2. **新结论去现行文档**：修复、验收或状态变化写入 `现状.md`、四包检查、接口台账或新的修改日志/验证批次，并引用原记录。
3. **路径迁移说明**：2026-11-03 的整理把历史目录移入 `归档/`，只更新了 Markdown 链接目标与相对深度，未改正文结论；少数指向未入库构建产物、临时日志或本机绝对路径的断链保留原状。
4. **原文恢复**：优先按归档中的 `documents-before.json`、`restore_commit` 或 Git 历史取回，不凭记忆重写。

## 5. 新增文档约定

| 类型 | 路径 | 最低要求 |
| --- | --- | --- |
| 修改日志 | `docs/修改日志/<作者>/YYYY-MM-DD-主题.md` | 完成项、验证命令/结果、未验证边界、影响文件 |
| 验证批次 | `docs/validation/p1-<主题>-YYYYMMDD/README.md` | 版本/提交、输入、命令、预期/实际、证据文件、未验证原因 |
| 交接/操作指南 | `docs/一期工程整改/04-交接/<版本>-主题.md` | 适用版本、前置条件、步骤、失败处理、不宣称未验收项 |
| 四包问题 | `docs/一期工程检查-<包>包.md` | 稳定编号、当前实现、剩余关闭条件 |
| 接口材料 | `docs/接口对接/{进行中,已完成,待裁定,归档}/` | 按[接口对接 README](接口对接/README.md)的合同与生命周期规则 |

通用要求：

- 现行文档使用相对路径链接；新增/修改后检查目标存在，不把构建产物或本机绝对路径写成现行依赖。
- 不手工编辑生成的 Schema、面板构建物或项目文档中的主责字段。
- 不把“目录存在”“模拟器通过”“历史批次通过”写成真实宿主或完整 AC 验收。
- 涉及数字（模块/行数/测试节点/动作数）时，以 `scripts/check_docs_facts.py` 的实际结果为准。
