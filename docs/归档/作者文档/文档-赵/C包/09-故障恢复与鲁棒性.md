# 故障恢复与鲁棒性

日期：2026-09-27

分支：feat/package-c-execution

## 1 RecoveryCheckpoint恢复

新增application/execution/recovery.py。

recover_attempt执行：

- 校验checkpoint与Attempt的run/step/attempt身份。
- 调用SpoolStore抢救未封口尾部。
- 恢复块引用、stdout/stderr独立游标和采集完整性。
- 进程仍活且身份匹配时返回REATTACH。
- 进程已退出/停止时从Spool恢复收集事实。
- 进程失联时有副作用Attempt返回PENDING_VERIFICATION。
- 只读或幂等步骤返回SAFE_RETRY，但旧Attempt标记INVALIDATED，必须创建新Attempt。
- 不因checkpoint存在而推断执行成功。

## 2 输出抢救

FileSpoolStore新增salvage_streams。

恢复规则：

- 以最后一个已封口块或已确认游标为起点。
- 扫描stdout.log和stderr.log中已经追加但未进入清单的尾部字节。
- 生成complete=false的恢复块。
- 摘要和长度从实际抢救字节计算。
- 恢复块保留capture_source=recovery。
- 不推进最后已确认游标，避免把未核实尾部当成完整证据。
- 再次恢复时按已有块和偏移幂等处理。

## 3 上游依赖失效

invalidate_downstream_attempts只在计划修订确实变化时执行。

失效条件：

- Attempt处于intent_recorded、starting、running、stop_requested或collecting。
- Attempt的consumed_outputs或consumed_conditions精确引用受影响的上游Attempt。
- 只失效匹配的依赖分支。
- 无精确依赖、无关分支、已完成Attempt和相同plan revision保持不变。
- 失效Attempt标记invalidated和upstream_plan_changed，不自动重放。

## 5 极端输出

已验证：

- 空stdout/stderr：无块、无游标，但进程退出事实完整。
- 大输出：按行流式生成多个输出块，重新拼接内容与原始字节一致。
