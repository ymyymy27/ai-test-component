# C包待冻结枚举与跨包字段确认表

版本：0.1  
日期：2026-09-24  
状态：由C包按一期架构文档直接推导，D包后续异步确认  
策略：单机Mock推进，不等待外部确认

## 1. RunControlState草案

- not_started：Run已建立，尚未开始调度。
- running：正在调度或执行，允许部分步骤待核实。
- pause_requested：已登记暂停意图，当前步骤继续到边界。
- paused：已在步骤边界暂停，不启动新步骤。
- cancel_requested：已登记取消意图，尚未确认停止请求。
- cancelling：已请求停止，等待停止确认。
- recovering：核心重启后进行句柄重关联、输出抢救或依赖重建。
- pending_verification：没有可继续推进的步骤，但存在结果未知或有副作用未知。
- completed：执行事实已收齐，业务结论仍由D计算。
- cancelled：停止已确认，采集和终态事实已落盘。
- execution_error：调度器或执行基础设施错误，不表示业务断言失败。

建议终态：completed、cancelled、execution_error。pending_verification可在恢复或核实后回到running、completed或cancelled。

## 2. StepState草案

- pending：尚未满足开始条件。
- ready：依赖和前置条件满足，等待执行。
- running：存在当前执行Attempt。
- blocked：上游依赖失败或不满足，不是业务断言失败。
- pending_verification：当前执行结果或有副作用结果未知。
- completed：步骤执行事实和要求的证据已收齐，业务结论仍由D计算。
- cancelled：停止已确认，步骤未完成。
- invalidated：输入、来源、上游Attempt、条件或修订变化使当前事实失效。
- execution_error：工具、适配器或环境错误，不表示业务断言失败。

允许的后期变化：completed可因依赖或修订变化进入invalidated；execution_error可通过新Attempt重新进入ready，但旧Attempt保留。

## 3. AttemptState草案

- intent_recorded：执行意图已持久化，尚未开始。
- starting：已请求启动，句柄未确认。
- running：真实进程或远端请求已确认运行。
- stop_requested：已请求停止，尚未确认停止。
- collecting：执行体已结束，正在采集输出、退出和响应事实。
- completed：执行终态和采集事实已收齐或明确记录缺口。
- cancelled：停止已确认，终态事实已落盘。
- pending_verification：结果未知或副作用是否发生未知。
- execution_error：工具、适配器、环境或协议错误。
- invalidated：该Attempt被明确判为不再作为当前依赖依据。
- unknown：解析或恢复时无法归入已知状态的兜底值，必须同时产生未知原因。

超时不属于AttemptState，使用timed_out布尔值；超时不等于停止或回滚。

## 4. 状态组合验收条件

### 成功夹具

- RunControlState：completed
- StepState：completed
- AttemptState：completed
- ExitFact：存在且记录真实退出码
- CaptureCompleteness：complete
- ExecutionSourceVerification：verified
- EvidenceIntegrity：complete
- 未知原因：无
- 解释：只表示执行事实完整，不表示业务通过。

### 失败夹具

- 上游AttemptState：execution_error
- 上游StepState：execution_error
- 下游StepState：blocked
- 下游current_attempt_id：空
- dependency_invalidations：按实际依赖写入
- 解释：blocked不是断言失败；execution_error也不是最终业务结论。

### 取消未确认夹具

- RunControlState：cancelling或pending_verification
- AttemptState：stop_requested或pending_verification
- 禁止值：cancelled
- 未知原因：stop_confirmation_unavailable
- 解释：网络断开、窗口关闭或控制超时不作为取消完成证明。

### 未知副作用夹具

- RunControlState：pending_verification
- StepState：pending_verification
- AttemptState：pending_verification
- ExitFact：允许缺失
- CaptureCompleteness：partial或gap
- 未知原因：unknown_side_effect
- 解释：必须核实业务状态，不允许自动重放。

### 依赖失效夹具

- StepState：invalidated
- DependencyInvalidationFact：存在并指出上游Attempt或修订变化
- 旧Attempt和旧证据：保留
- current_attempt_by_step：指向新Attempt或明确为空
- 解释：不得回退旧绿灯，不得用最新成功拼接。

## 6. 关键嵌套对象

- RunFact：Run控制状态、档位、驱动、结论上限、证据等级、范围、环境和修订。
- StepFact：层级、修订、用例、依赖、断言引用、证据要求、当前Attempt和失效状态。
- AttemptFact：尝试序号、重试次数、执行状态、副作用、依赖消费、句柄、输出块、结构化结果引用、ExitFact和未知原因。
- EvidenceFact：项目、来源、Run/Step/Attempt、代码身份、摘要、完整性、脱敏和投影状态。
- SourceVerificationFact：预期来源摘要、物化快照、实际来源摘要、验证状态、缺口和证据。
- VerificationFact：被核验操作、业务对象、查询策略、截止条件、观察结果和关键链路覆盖。
- MockDeclarationFact：稳定ID、内容修订、声明来源、替换对象、范围、核实状态和证据。
- DependencyInvalidationFact：受影响步骤、上游Attempt、原因、源修订和是否传递。
- UnknownReasonFact：主体、未知原因、是否需要核实、建议动作和证据。
- EvidenceGapFact：缺口类型、主题、原因、是否关键和是否需要用户处理。

## 7. 待D包异步确认

- RunControlState的recovering是否进入持久状态，或仅作为操作事件。
- pending_verification是否允许Run级汇总状态。
- execution_error是否统一为执行事实，不参与业务失败判定。
- blocked下游和incomplete范围的报告投影。
- DependencyInvalidationFact的reason固定值集合。
