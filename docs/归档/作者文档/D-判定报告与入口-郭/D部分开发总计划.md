## 2. D 部分核心职责

### 2.1 唯一判定与问题闭环

负责 `domain/review/`：

- S/M/E/R/V/P/F/U 及有效失败 H 的唯一判定。
- 业务结论 `passed / failed / incomplete / not_applicable`、证据等级和失败优先级。
- `IssueRecord`、人工复核、处置/阻塞、问题归并、重开和修复回归关闭守卫。
- 当前问题列表投影及 `issues.list` 的业务过滤语义。
- 业务结论只根据冻结计划、执行事实和有效证据计算；退出码、HTTP 成功、界面提示或“已发送”不能单独作为业务通过依据。

### 2.2 报告、复核与导出

负责 `application/review/`：

- 依据固定事实冻结报告和报告修订历史。
- 记录本地复核、修复登记、回归请求和问题关闭事实。
- 生成 Markdown 摘要和证据包导出。
- 在导出前应用脱敏与可携带附件规则。
- 将导出产物交由报告用例登记，A 负责永久对象保存和索引提交。
- `LocalReview` 不回写报告正文；历史报告不可变，新增结论形成新修订。

### 2.3 唯一用户入口

负责以下入口的唯一实现：

- `interfaces/dto.py` 及 D 需要的稳定 DTO。
- CLI。
- stdio MCP relay。
- `integrations/trae/`。
- `resources/panel/`。

面板覆盖运行前、运行时、运行后三段，以及计划、工作台、问题、报告和设置。面板只消费核心 DTO；所有写操作经统一命令入口。MCP 不能代表人工确认，也不能绕开应用用例。

### 2.4 有限查询与索引输入

D 向 A 一次性提供报告和问题的查询字段、枚举、组合掩码、排序和游标需求。A 负责编码索引和物理查询；D 不另写全表查询，不在前端进行伪装成完整数据的局部筛选，也不在索引缺失时静默全扫。

## 6. 四类冻结合同

- `LocalCommand/Query/Response/Event`：A 维护 Schema；D 实现入口消费；B/C/D 注册用例。
- `WorkspaceUnitOfWork/RecordRepository/ObjectStore/IndexMutation`：A 维护端口和文件实现；D 只调用。
- `PreparedRun`：B 产生，C 读取；D 仅作展示和判定输入。
- `ExecutionFacts`：C 产生，A 保存，D 按一个 commit 的一致快照读取。

D 的接口需求分别记录在：

- `D部分与A核心底座对接说明.md`
- `D部分与C执行证据对接说明.md`

## 7. 技术选型建议

### 7.1 面板

沿用当前 `resources/panel/` 的 TypeScript + Web Component + Shadow DOM 路线，使用现有 esbuild 构建、Playwright 测试。第一阶段不引入新的前端框架或第二份面板源码，避免在核心 DTO 未冻结前做框架迁移。

### 7.2 核心接入

使用现有 `aitest.local/2.0` 协议和 A 的统一命令/查询入口。D 只做 DTO 映射和交互状态管理，不以页面状态推导业务结论。

### 7.3 CLI

沿用 Python `argparse` 入口，通过同一核心 API 调用应用用例。CLI 不直接访问文件存储，不自行实现问题关闭或报告判定。

### 7.4 MCP relay

采用 stdio relay 连接已验证的本地管道，不监听 TCP，不建立第二个核心进程，不自行合成人工确认。宿主或 relay 只能转发核心响应与能力错误。

### 7.5 Trae

Trae 适配层保持薄封装，只负责宿主注册、命令转发、面板加载和快照/事件续读。真实 Trae API 版本、扩展打包和兼容性以选定发行版的实测为准，当前不宣称已完成。
