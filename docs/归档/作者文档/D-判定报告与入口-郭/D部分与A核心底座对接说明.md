# D部分与A核心底座对接说明

版本：0.1（草案）  
日期：2026-09-28  
提出方：D包（判定、报告与用户入口）- 郭  
接收方：A包（本地核心底座）  
状态：待 A 确认；本文只提出需求，不修改 A 的所有权文件

## 1. 目的

D 是统一用户入口，但不拥有文件存储、工作空间事务和物理索引。本文说明 D 需要 A 提供的统一命令、查询、事件、保存和恢复能力。所有 D 写操作必须经 A 的应用用例与工作单元，不允许面板、CLI、MCP relay 或 Trae 适配直接读写业务文件。

## 2. 必须共同遵守的边界

- D 不创建第二套存储、数据库、服务或全表查询。
- D 只消费 A 的稳定 DTO，不按错误文案猜状态。
- 写入必须支持 `request_id`、业务 `intent_id`、`expected_revision` 和幂等结果。
- 保存成功必须在同一提交边界内包含记录、索引、事件和引用，不能出现保存成功但索引漏项。
- 读取报告、问题和历史修订必须支持按准确修订读取；列表读取摘要，详情按引用读取。
- 凭据和已知秘密不进入 DTO、日志、面板、报告或导出。A 提供底线脱敏投影。
- 能力未实现时返回结构化错误，不伪造空列表、默认通过或“无问题”。

## 3. A 需要提供的统一协议

### 3.1 命令

D 的入口至少需要以下二期基础协议中已保留的动作；实际能力以 A 协商后的版本为准：

| 动作 | D 用途 | 写入边界 |
| --- | --- | --- |
| `update_issue` | 更新问题处置或阻塞状态 | 人工动作，需 revision |
| `record_fix` | 登记修复 | 人工动作，需 revision |
| `request_regression` | 请求回归 | 需准确问题/运行引用 |
| `close_issue` | 关闭问题 | 人工动作，必须校验关闭依据 |
| `record_local_review` | 记录本地复核 | 人工动作，绑定事实修订 |
| `create_report` | 冻结报告修订 | 由 D 用例生成，A 原子保存 |
| `export_report` | 登记报告导出产物 | 先完成脱敏和附件校验 |
| `copy_repair_brief` | 生成修复摘要 | 只读投影，不产生业务结论 |

`Command` 冻结字段至少包括：

- `protocol_version`
- `request_id`
- `action`
- `project_id`
- `binding_revision`
- `target`
- `expected_revision`
- `intent_id`
- `parameters`

### 3.2 查询

D 需要 A 提供统一 `query` 入口，至少支持：

- `issues.list`：模块、层级、级别、人工复核、处理/处置/阻塞、OPEN/ALL、组合掩码、排序和分页。
- `reports.list` / 报告详情：项目、业务结果、完整运行或报告编号、修订折叠。
- 当前快照和后续增量事件：用快照游标和事件序号续读。

`QuerySpec` 需要冻结：

- 允许查询字段及类型。
- 枚举值和未知枚举行为。
- 可组合过滤、排序白名单和稳定排序键。
- 游标格式、分页上限、总数字段是否存在。
- 索引缺失、索引损坏和查询不可用时的结构化错误。
- 同一 commit 分页不得漏项、重复或混入未提交修订。

### 3.3 响应和错误

D 需要 A 冻结以下响应组成：

- `protocol_version`
- `request_id`
- `instance_id`
- `workspace_id`
- `project_id`
- `binding_revision`
- `result` 或结构化 `error`
- 错误 `code`、安全 `message`、`retryable`、`next_step`

D 至少需要区分：版本不兼容、能力不可用、参数非法、项目/对象不存在、修订冲突、工作空间被占用、索引缺失、对象损坏、存储不可写、人工确认缺失和可重试连接错误。最终错误码由 A 冻结，不在 D 侧自造。

### 3.4 事件和续读

D 需要：

- 事件序号和快照 commit 使用同一提交边界。
- 从快照游标之后续读，不跳过已提交事件。
- 事件包含事件类型、对象 ID、准确修订、提交序号和可安全投影的载荷；若载荷只含引用，A 需明确详情查询方式。
- 窗口重连、重复事件和游标过期都有固定行为。
- D 的页面刷新不能造成问题、报告或运行状态回退。

## 4. A 需要提供的工作单元和仓储能力

### 4.1 逻辑记录

D 需要保存或读取以下逻辑事实，具体记录名由 A 冻结：

- 报告修订及报告冻结引用。
- 本地复核记录。
- 问题记录及问题投影。
- 修复登记、回归请求和关闭依据。
- Markdown 摘要、证据包清单及导出产物对象引用。
- 查询结果摘要、稳定游标和索引修订。

### 4.2 工作单元要求

- 同一事务保存业务记录、索引变更、事件和对象引用。
- 支持 `expected_revision`，冲突不自动覆盖。
- 支持稳定 ID、幂等 `intent_id` 和重复请求结果复用。
- 提交前不可见，提交后一次可见。
- 不可变历史保留；报告修订不覆盖旧修订。
- 对象以摘要和引用登记，D 不依赖文件路径猜内容。
- 失败、部分提交、恢复和对象缺失必须返回明确结果。

### 4.3 A 提供的测试替代

为让 D 不等真实 Windows 文件后端完成即可开发，A 需要提供符合同一端口合同的假仓储/假工作单元。假实现只能用于并行开发，不能作为永久保留、崩溃恢复或真实拆分的验收证据。

## 5. D 向 A 提供的输入

D 将提供：

- 报告和问题 `QuerySpec` 的允许字段、枚举、组合掩码及排序建议。
- D 需要的 DTO 投影字段和脱敏展示要求。
- D 的应用用例注册表，由 A 在唯一组装点注册。
- 成功、失败、未知和索引异常夹具。
- 与 B、C 合同的兼容性和回归测试。

D 不修改 `application/ports.py`、`interfaces/local/api.py` 或 `bootstrap.py` 的所有权；需要签名时通过本文档提出并由 A 合并。
