# A包基础设施存储层设计

## 背景/目的

为 A 包提供 Windows 文件后端上的单写事务、不可变历史、有限索引、备份和故障恢复能力。

## 设计边界

存储层只保存业务事实、对象引用、提交清单、索引和恢复元数据，不生成计划、不执行被测业务、不判定业务结论。永久业务材料只追加保存，不提供删除接口；仅允许对明确标记为临时且无业务引用的材料执行受控回收。

## 工作空间与锁

工作空间根目录保存 `workspace.json`，其中包含 `workspace_id`、schema 版本和单调递增 `writer_epoch`。每个核心进程通过操作系统排他锁取得写资格；同一根目录存在活动锁时返回 `WORKSPACE_IN_USE`。锁取得后才递增 epoch，失败不得改变身份文件。

## 事务

事务为非嵌套短事务，状态为 `active`、`committed`、`rolled_back` 或 `failed`。`request_id` 是传输请求身份，用于同请求重试去重；`intent_id` 由上层创建并随业务记录保存。活动事务使用临时快照目录和事务日志，提交以临时文件、刷新、原子替换发布根清单；提交前的材料对读取者不可见。提交或回滚均追加日志，IO 失败保留上一有效根。

## 不可变历史与对象

记录键为 `(aggregate_kind, record_id, revision)`，revision 只追加、不覆盖；详情读取必须提供准确 revision。对象按项目和 sha256 摘要寻址，重复摘要必须字节一致，冲突或摘要不一致显式失败。

## 索引与查询

索引按已提交根增量更新，固定排序和游标分页。索引缺失、损坏或版本不兼容返回 `INDEX_REBUILD_REQUIRED`，禁止隐式全表扫描。重建从已提交根读取并通过临时文件原子发布，不修改业务记录。

## 备份、完整性与恢复

备份包含当前清单可达的完整对象闭包、记录、索引和事务日志，并写入摘要清单。恢复前检查活动事务和活动执行；先校验身份、摘要与引用，再替换当前指针。提交中断时只接受完整已发布根，未发布材料保留并登记缺口，不自动重放未知副作用。

## 假存储

内存假存储实现同一事务、不可变记录、意图去重和有限查询接口，仅用于 B/C/D 并行开发，不能作为 Windows 文件后端验收证据。

## 验证计划

覆盖单写锁、同请求去重、崩溃前后恢复、不可变历史、备份闭包、索引分页、缺失对象、不可写介质和替换失败注入。真实 Windows 文件系统结果须记录 Python/核心版本、故障注入点和证据位置。
