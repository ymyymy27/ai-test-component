# 存储与恢复

> **已废止（2026-11-16）**：本文属于系统级方案，不作为轻量插件重构的实现依据。现行基线见[轻量 Trae 插件修改计划](../../../修改日志/ymy/2026-11-16-轻量Trae插件重构计划.md)。新文档就位后移入 `docs/归档/`。


本册覆盖 P1-FR16 的落盘部分：所有记录如何可靠写入、如何被有限查询、如何备份迁移、崩溃后如何恢复、哪些材料永久保留。文件后端专用，不实现通用数据库、消息队列或事件溯源框架；记录不可变、索引可重建、证据按项目和内容摘要寻址。

**有限查询与索引合同只在 §4 展开**，其他分册（报告、面板、MCP）只引用本节，不另立掩码、排序或游标口径。

## 1 布局与身份

```text
workspace.json                  # workspace_id、schema_version、writer_epoch
writer.lock                     # portalocker 排他锁载体
current.json                    # 唯一发布指针（aitest.current-commit/2）
manifests/<sha256>.json         # 不可变提交清单
record-store/<sha256>.json      # 权威记录的不可变内容寻址节点
records.json / commit.json      # 旧版权威文件 / 提交清单投影（可重建）
indexes.json + indexes/         # 查询根、分片、服务端游标、indexes/business/
event-log/journal.jsonl + staging/ + boundaries/ + position.json
event-log/pages/                # 有序事件页
events.json + events/           # 旧版事件路径（迁移过渡）
objects/<project>/<sha256hex>   # 已过滤凭据的不可变对象
snapshots/                      # 源码快照对象
checkpoints/<attempt_id>.json   # 每 Attempt 一份恢复检查点
spool/<attempt_id>/{manifest.json,capture-*.json,artifacts/}
workdirs/<run_id>/              # 源码物化与运行临时文件
execution-handles/ model-responses/
transactions/{active.json,publication.json,publications/,results/}
diagnostics/ maintenance/ core/ migrations/
artifacts/reports/<report_id>/<kind>-<digest16>.<md|zip>
exports/ outbox/ generations/   # 白名单预留目录，本期无写入者
```

- 工作空间位于当前操作系统用户可写目录，一个工作空间属于单个 OS 用户，跨用户或跨主机不共享活动目录；运行时数据不放进安装包、被测源码或 `src/`。
- 打开或创建工作空间时探测位置：网络盘与同步盘（OneDrive、Dropbox 等）以 `WORKSPACE_LOCATION_REJECTED` 拒绝并给出原因（`network_drive`/`sync_folder`）；可移动盘不拒绝；路径链上的符号链接与 junction 一律拒绝。
- `workspace.json` 只保存标识、结构版本与 `writer_epoch`；打开时校验标识与字段形状，损坏即拒绝，不猜测。
- `current.json` 是唯一的业务发布点；`manifests/`、`record-store/`、`indexes/`、`event-log/` 都是可核对的不可变材料或可重建投影，不能反过来当作提交事实。
- 凭据正文不在工作空间：`SecretPort` 使用 OS 凭据设施；已登记凭据在**落盘前**过滤，spool、对象、诊断与备份只接纳过滤后的字节。
- 项目目录下的 `.aitest/` 只放可共享配置与模板，不放模型密钥、凭据或运行证据；证据、报告、问题与导出只属于用户数据工作空间。

## 2 单写、事务与提交

### 单写协调

- 核心装配时取得覆盖恢复、服务到退出的**生命周期排他锁**（`LifetimeWriterLock`，`portalocker` `LOCK_EX|LOCK_NB`）；同进程二次准入或他进程已持锁抛 `WorkspaceInUse`（`WORKSPACE_IN_USE`）。
- 新核心准入时 `writer_epoch` 加一并写回 `workspace.json`，随后绑定到生命周期锁；短事务取锁后用该 epoch 校验，epoch 变化拒绝发布。
- 短事务在当前进程已持生命周期锁时不再重复申请同一 OS 锁区域，改用进程内串行（队列上限 32，等待 2 秒），跨进程互斥仍由 OS 锁保证；队列满或超时返回可重试的“工作空间忙”。
- 锁文件存在或时间戳不代表锁有效；不按时间删除或解锁活进程。释放生命周期锁要求没有在途事务。
- 网络调用、模型请求与被测执行都在事务外；事务只发布已准备好的短材料。

### 提交步骤

| 步骤 | 代码事实 |
| --- | --- |
| 1 准备 | 暂存记录时校验 `expected_revision`（新记录为 0，旧记录必须等于当前修订），`guard_value` 过滤已知凭据后再暂存；带内容指纹的载荷必须先过滤，否则拒绝 |
| 2 校验 | 加载当前根的权威记录；逐条校验载荷引用的对象存在且归属正确，源码引用可核对；同一 `intent_id` 与同一业务输入已提交时直接返回原结果，输入不同抛 `INTENT_CONFLICT` |
| 3 预生成 | 在内存中生成记录修订、受影响索引页、事件段与业务变更索引，全部写成内容寻址的不可变材料：`record-store/`、`indexes/`、`event-log/pages/`、`transactions/results/` |
| 4 写清单 | 生成 `manifests/<sha256>.json`，包含父清单、记录根、索引根、事件根、文件摘要与幂等结果引用；清单字节与摘要先校验，已存在同名不同字节则拒绝 |
| 5 发布 | 用 `current.json` 原子替换把业务事实变为可见（Windows 用 `ReplaceFileW` 加备份路径）；替换后重新读取并核对指向的清单、记录根与索引根 |
| 6 确认 | 只有后端报告发布与所需刷新完成才确认成功并广播该提交的已提交事件；响应丢失由持久业务键/幂等结果取回 |

- 发布边界前查询只见旧根，边界后只见完整新根；不存在“部分记录可见”的中间态。
- 替换返回不确定时停止新写入，先核实 `current.json` 实际内容，不盲目声称失败或重放业务；再次准入时按权威边界判定“已提交”或“未提交”。
- Windows 后端封装 `write_and_flush`、`publish_immutable`、`replace_current`、`inspect_publication`；写入先刷新语言缓冲，再用可写句柄 `FlushFileBuffers` 并检查结果。`ReplaceFileW` 不支持 `REPLACEFILE_WRITE_THROUGH`，不把该标志当耐久保证；刷新与改名是两步，掉电一致性须按目标文件系统实测。
- 发布失败保留旧根；若退回旧根，必须标“未知/可能的提交缺口”，不得把已确认结果静默抹去。

### 幂等与重跑

- 持久业务意图由（动作、项目、`intent_id`、业务输入指纹）确定：同一意图与同一输入跨入口、跨重启重传时返回原提交结果，不产生第二个修订；同意图不同输入抛 `INTENT_CONFLICT`。
- 明确重跑必须创建新意图；不允许借“重试”改写已提交记录，也不允许用新的 `request_id` 冒充新业务。
- 提交结果未知时只允许核实或回滚；回滚会重新准入并按权威边界判定实际状态，已提交的业务事实不可回滚。
- 同一业务工作单元同时发布记录与全部受影响索引页；删除旧状态键只是索引投影更新，不删除永久事实或历史索引根。

## 3 不可变记录与索引

- 记录权威是内容寻址节点树：节点文件名即其字节 sha256，节点形状只有 `{"value"}`、`{"entries"}`（≤32 项）与 `{"children"}`（≤16 路十六进制分支）；单节点上限 16 MiB，路径链上不允许链接。修订只追加，旧修订由节点可达性保留。
- 旧版 `records.json` 仍可读，迁移后由 `current.json` 的 `record_header` 指向新权威；`commit.json`、`indexes/`、`events.json` 都是可从权威边界重建的投影。
- `CommitManifest` 基础字段：`schema`、`workspace_id`、`generation_id`、`writer_epoch`、`commit_sequence`、`parent_manifest`、`operation`（business/migration/maintenance）、`request_id`、`intent_id`、`project_id`、`record_header`、`index_root`、`event_root`、`migration_source`、`created`（含每修订 `body_sha256`）。完整版 v2 另含 `commit_id`、`generation`、`parent_commit`、`changed_records`、`event_range`、`instance_id`、`idempotency_result_ref`、`file_digests`、`business_change_index_root`，可选 `source_material_files`。
- `current.json` 指针字段：`schema_version`、`workspace_id`、`generation`、`commit_id`、`manifest_digest`、`index_root`、`event_cursor`；旧版指针可读，但只接受身份、摘要和完整引用都通过的已发布根。
- `IndexRoot`（`aitest.index-root/3-tree`，version 3）记录 `generation`、`last_commit_sequence`、`snapshot_root`、`snapshot_sha256`；分片目录族为 `records-rev`、`reports`、`reports-byid`、`issues` 与各排序族。
- 报告与问题目录按业务身份折叠：每个报告/问题在同一提交下只暴露最新修订，新修订原子替换旧键；其他记录保留全部修订，历史修订通过点查目录读取。
- 业务变更稀疏索引在 `indexes/business/<sha256(kind)>/`，键为 `(commit_sequence, origin_workspace_id, project_id, record_id, content_revision)`，每个业务类型保留最大业务序号；`diagnostic`、`submission*`、`upload_candidate`、`candidate_cursor` 等管理类型不进入候选业务索引。
- 事件日志：一个事务一个 boundary（`commit_sequence` 等于该事务最后一条记录的提交序号），事务内每条记录一个事件；事件先写 `event-log/staging/`，边界封口后才可读；事件身份由实例、提交序号、类型、项目、记录与修订确定，可重复传输但不可先于提交。
- 一次业务提交把**全部**查询目录（含本提交没有新增行的族）推进到同一发布边界：只重写有界元数据，空族返回空页而不是 `INDEX_REBUILD_REQUIRED`。

### 对象与按需读取

- 对象发布时流式计算完整摘要；分块清单记录总大小、固定顺序块编号/长度/摘要与完整对象摘要，清单纳入已提交引用。
- 按需读取先校验项目归属与块清单，再读取并验证触及的块；没有受信分块清单的旧对象须先完整校验并建立可复用结果，不每个分页重复哈希整个对象。
- 仅 mtime 与大小相同不能证明内容不变；校验缓存必须绑定实际内容摘要、已提交块清单与受控对象身份，发现变化立即失效。
- 普通列表只读摘要页，详情只读所选对象块，小提交只更新相关页，正常恢复只检查活动与未发布材料；无关历史增长不应使一次固定范围分页或小提交遍历全部证据。
- 效率核对只观察实际读写路径与重复计算，不新设费用、资源预算或总执行时限指标。

## 4 有限查询与索引键

`QuerySpec` 是 contracts 中的有限查询定义，不接收任意表达式。字段与边界：

| 字段 | 约束 |
| --- | --- |
| `project_id` | 必填，所有查询固定项目 |
| `sort` / `descending` | `sort` ∈ `aggregate_kind`、`record_id`、`revision`、`commit_sequence`、`published_sequence`、`updated_sequence`；`descending` 默认假 |
| `limit` / `cursor` | `limit` 1—500，默认 50；`cursor` 为服务端签发的令牌，不能跨条件复用 |
| `aggregate_kind` / `record_id` / `revision` | 类型化身份查询；`revision` 必须同时给出前两者 |
| `business_outcome` / `run_id` / `report_id` | 报告列表与报告编号查询 |
| `view` / `facet` / `facet_value` / `severity` | 问题列表：`view` ∈ `OPEN`/`ALL`，`facet` ∈ `NONE`/`module`/`layer`/`review_state`/`workflow_state`/`disposition`/`blocking` |

查询目录（每类按完整组合键排序分片，值只存最小摘要与精确记录引用）：

| query_id / 目录 | 前缀与排序 | 更新边界与读取范围 |
| --- | --- | --- |
| `issues.list` | `(project, view, mask, facet_value\|ALL, severity\|ALL, updated_sequence, issue_id, revision)`，按整键降序扫描（`updated_sequence` 为主序） | 问题、有效复核、处置或归并变化时在同一提交移除旧键、写新键；只读匹配前缀页 |
| `reports.latest` | 前缀 `(project, business_outcome\|ALL)`，排序 `(published_sequence, report_id)`；方向由 `descending` 决定（报告列表调用方传降序） | 每份报告折叠到最新修订；新修订原子替换旧状态键 |
| `reports.by_id` | 前缀 `(project, "report"\|"run", id)`，排序 `(published_sequence, content_revision)`，可叠加 `business_outcome` 过滤 | 编号直达最新摘要，不扫文本；未匹配返回空，不当作索引损坏 |
| 记录点查（含 `reports.revisions`） | 前缀 `(project, aggregate_kind, record_id)`，排序 `revision`，可按修订过滤 | 单对象修订范围，不扫其他对象；历史修订在这里展开 |
| 通用有序列表 | 前缀 `(project[, aggregate_kind])`，排序 `(排序值, record_id, revision)` | 按所选排序族分页；小提交只更新相关页 |

14 种问题掩码（数值由 facet 编码与是否叠加级别派生）：

| facet | 不叠加级别 | 叠加 `severity` |
| --- | --- | --- |
| `NONE` | 0 | 1 |
| `module` | 2 | 3 |
| `layer` | 4 | 5 |
| `review_state` | 6 | 7 |
| `workflow_state` | 8 | 9 |
| `disposition` | 10 | 11 |
| `blocking` | 12 | 13 |

- 每个掩码都支持 `OPEN` 与 `ALL`，共 28 种入口形态；`ALL` 是显式 Schema 分支，不用业务字符串充当通配符。
- 索引入口数上界：`4(m+l)+20`（`m` 已知模块数、`l` 已知层级数；含 OPEN/ALL 两视图与“有/无 severity”两分支）；关闭问题只有 `ALL`，减半。这是明确的写放大上界，不是新实体；减少入口必须先改本查询合同。
- `OPEN` 定义：`active`/`deferred`，以及解析到仍未解决主问题的 `duplicate`；`fixed`/`non_defect` 与主问题已解决的重复不进入 `OPEN`，只保留在 `ALL`；无法解析的重复保留在 `OPEN` 并显示缺口。
- 模块筛选用稳定 `module_id`，一个问题可关联多个模块，每个准确模块建一条键，单模块查询不得重复返回同一 `issue_id`；未知模块与未知层级用独立 `unknown` 分支，不用空串通配。
- 游标：令牌只含 `schema`、`spec`、游标编号、`qid`、索引代次与 `commit_id`；完整末尾排序键、快照根与摘要保存在服务端 `indexes/.cursor-<id>.json`。绑定条件为 `project_id`、`aggregate_kind`、`record_id`、`revision`、`sort`、`descending`、`business_outcome`、`run_id`、`report_id`、`view`、`facet`、`facet_value`、`severity`；页大小不参与绑定。
- 错误口径：游标代次/`qid`/提交或快照根不符 → `invalid_cursor`（问题领域对应 `QUERY_CURSOR_MISMATCH`）；索引缺失/损坏 → `maintenance_required`（`INDEX_REBUILD_REQUIRED`）；非法组合 → `unsupported_filter`（`QUERY_UNSUPPORTED_FILTER`）。
- 问题领域另有同等语义的本地查询实现：`page_size` 1—200，默认 50；条件指纹由 `query_spec_version`、项目、`view`、`facet`、`facet_value`、`severity` 计算，游标同时绑定 `commit_id`，跨条件或跨提交复用抛 `QUERY_CURSOR_MISMATCH`。
- 非法组合（任一即拒绝）：`facet = NONE` 带 `facet_value`；非 `NONE` 缺 `facet_value`；问题选择器与记录/报告选择器混用；`report_id` 与 `run_id` 同时给出；`revision` 无类型化记录身份；`business_outcome` 用于非报告目录。
- 索引缺失或损坏只重建目标分片并明确暂不可用；不回退全历史扫描伪装正常。
- 没有对应 `QuerySpec` 的筛选不提供界面入口，也不自动走全表扫描；新增已承诺的界面查询时先补有限索引合同与索引写放大说明。
- 同 commit 翻页、更新后刷新、相同排序键并列、组内新修订、状态迁移与索引损坏是查询验证的必测面；无关历史增长不得让一次固定范围分页访问等量增长的对象。

## 5 备份与迁移

### 备份

入口是受控动作 `backup`，模式 `create`/`inspect`/`restore`，需要受控交互会话；Agent 中继会话一律拒绝。

- 目标必须是绝对路径、位于活动工作空间之外、非链接；目标非空拒绝覆盖；不能把工作空间自身当备份目标。
- `create`：先用落盘事实探测活动（活动事务标记、非空事件暂存、未封口 spool、未核实执行句柄）；有活动时**排除 `spool/`** 并在清单写 `excluded_active`，其余永久闭包照常复制。
- 闭包按白名单：根文件 `workspace.json`、`records.json`、`indexes.json`、`current.json`、`commit.json`、`events.json`、`transactions.json`；目录 `objects`、`checkpoints`、`transactions`、`events`、`manifests`、`event-log`、`snapshots`、`diagnostics`、`exports`、`migrations`、`reports`、`generations`、`core`、`maintenance`、`indexes`、`execution-handles`、`model-responses`、`record-store`。缺目录跳过，缺文件登记缺口。
- 逐文件复制并核对摘要；路径链含链接或已登记凭据即拒绝，不靠脱敏改写备份字节。
- `backup.json` **最后写入**，字段只有 `schema`（`aitest.backup/1.0`）、`files`（相对路径→sha256）与 `excluded_active`。
- `verify` 做双向闭包核对：清单内每项摘要必须一致，备份目录中出现未登记文件也算失败。只有校验通过才标“可恢复”。
- `restore` 只恢复到新的空目录：清单路径逐项限界，拒绝绝对路径、盘符、`..`、链接与非空目标；写完后按清单重新核对摘要，再在恢复副本上重建查询索引（`index_rebuilt`，失败则记 `index_gap`，材料仍可用但不得声称已就绪）。
- 结果字段：`root_commit`、`verified`、`complete`（校验通过且无已知缺失）、`restorable`、`file_count`、`total_bytes`、`manifest_digest`、`known_missing`、`gaps`、`excluded_active`；`complete=false` 时不得作为迁移前完整备份。
- 备份不自动轮换或删除，不复制密钥正文；凭据按 OS 后端另行恢复。本入口只做在线备份，明确拒绝“停机/维护模式完整备份”这类它无法保证的类型。
- 在线备份覆盖其 `root_commit` 之前的全部已提交历史，之后的提交不混入同一份清单；活动段只复制已提交字节边界，不复制过程中变化的文件并宣称一致。
- 迁移前的备份有效性只看“校验通过且 `known_missing` 为空”：必需永久文件缺失即 `complete=false`，只能报缺口，不能当作迁移前完整备份；没有“带已知缺口的迁移模式”捷径。

### 迁移

- 入口是受控动作 `migrate`，模式 `inspect`/`plan`/`apply`/`resume`/`rollback`；`plan`/`apply`/`resume`/`rollback` 需要受控交互会话并进入维护窗口（暂停新写入），`inspect` 只读。
- `apply` 前置：计划必须按迁移编号升序、唯一、已注册；存在未核实活动（执行句柄、活动事务标记、非空暂存、未封口 spool）直接 `blocked`；业务水位必须可读，不把不可读当成空工作空间。
- **第一个真实步骤之前**必须完成可校验备份：备份写入 `migrations/backups/<plan_id>[-随机后缀]`（配置外部根时写入其命名空间），校验通过后把清单摘要冻结进 `migrations/cycles/<plan_id>.json`；复用既有备份前重新核对闭包与摘要，不一致拒绝。
- 每步在 forward 之前写 `migrations/steps/<plan_id>/<migration_id>.json`：记录计划、受跟踪文件的顶层键前态与记录提交水位；步骤失败进 `journal.jsonl` 并保留前态；注册表 `registry.json` 只登记已成功步骤。
- 迁移是**原位**受控改写（工作空间版本字段、记录意图容器、记录分片、有界查询目录、`current.json` 指针），不是写一份新世代后切换；`resume` 按检查点续跑，`rollback` 逆序回滚，存在不可逆步骤时整体拒绝，存在未核实活动时拒绝回滚。
- 旧解析逻辑集中在迁移模块，业务读取只消费当前结构；缺失旧来源标识保留未知，不推测。
- 迁移前强制备份同时登记到维护审计，`backup inspect` 能看到实际位置与清单摘要；未配置独立存储时仍是工作空间内旧位置，不能谎称“独立存储”验收通过。
- 迁移失败按 `MIGRATION_FAILED` 结构化拒绝；计划身份、步骤检查点或周期状态损坏时拒绝续跑与回滚，不沿用未知前态。

## 6 恢复与抢救

启动恢复分两级，默认只做增量：

- **增量（startup）**：确认 `current.json` 已刷新（`confirm_current`）→ 读取当前根 → 若存在 `transactions/active.json`，仅当已发布根证明该事务已提交时核实并清除残留标记；不扫描完整历史，报告 `full_history_checked=false` 与已核对的高水位。
- **显式完整检查**：Phase A 完整性核对（顶层白名单、对象摘要、spool 清单）→ 核实活动标记归属 → Phase B 以权威记录台账重建落后或缺失的投影（`commit.json`、`indexes/`、事件边界）→ Phase C 事件日志逐项对账；出现孤儿暂存、事件身份或字节无法核实时整体 `blocked`。结果 `healthy`/`repaired`/`blocked`。

崩溃点与可认定事实：

| 中断点 | 可认定事实 | 恢复动作 |
| --- | --- | --- |
| 暂存阶段 | 未发布，旧根有效 | 旧事务不生效；暂存事件隔离留证，业务副作用另行核实 |
| 对象写入中 | 可能只有部分字节 | 校验归属与完整性，保留可识别输出为部分证据 |
| 材料已写、`current` 未换 | 无新业务可见性 | 不凭清单擅自宣布成功；抢救输出、等幂重试 |
| `current` 已换、响应未返回 | 事务已成功 | 由幂等结果返回原提交，不重放 |
| 发布后投影未更新 | 业务事实存在 | 从权威边界重建投影 |
| 恢复再次中断 | 部分抢救可能已发布 | 按原块身份与摘要认领，不重复造证据 |

- 核心退出前补封未封口的 spool 输出：只处理已有 `manifest.json` 且有 `.log` 字节的 Attempt；句柄仍活、身份不符或取证失败时不夺取输出；连清单都没有的 Attempt 不猜测身份，留给启动恢复。
- spool 与 transactions 是两类材料：spool 承载执行器已产生的输出块与归属元数据，transactions 承载活动标记、发布标记与幂等结果；不得先清空任何一方再抢救。
- 输出块必须带 Run/Step/Attempt、块序号、长度、摘要与完整性；执行检查点引用块与真实进程启动身份，不只存 PID。
- Attempt 级恢复依据 `checkpoints/<attempt_id>.json`、执行句柄与 spool 块清单：已终止且有可靠终态的事实原样保留；可重连续跑（`REATTACH`）；已退出或已停止的从 spool 恢复；身份不符或停止未确认进入 `PENDING_VERIFICATION`。未知副作用不自动重放；只读类别也只进入“需新 Attempt”的安全重试，不就地重发。
- 备份恢复只恢复到隔离目录，**不替换活动工作空间**；失败按 `blocked` 上报，不谎报已修复。
- 索引行级不一致（提交号一致但索引行与权威摘要不符）不属于增量恢复能推断的情形：由显式维护 `aitest rebuild-index --workspace <dir>` 在核心未运行时按权威边界全量重建全部查询目录，并晋升索引代次使旧游标失效；不重放业务、不改写记录。
- 完整历史扫描只属于显式完整检查、备份闭包与索引重建三类动作，日常启动与列表查询不得借扫描全历史“修复”视图。
- 恢复结论写入 `diagnostics/recovery/`，维护、备份与迁移动作写入 `maintenance/` 审计；两者都是永久诊断材料，不是业务记录。

## 7 保留与回收

- **永久保留**：业务记录与全部修订、证据对象、报告修订、复核、导出登记、诊断与维护审计、提交清单、事件边界、源码快照、检查点。`MaintenancePort` 没有删除业务记录的入口；不设保留期、不做到期清理、不提供一键清理。
- 外部删除或磁盘故障造成的缺口如实显示，不篡改旧结论、不宣称完整；插件不以“腾空间”为由改写结论。
- 备份是另一份永久闭包，不是回收对象；备份位置独立于活动目录，不自动轮换。
- 受控回收只处理**已证明可安全删除的临时遗留**，且默认 dry-run：

| 可回收形态 | 判定事实 |
| --- | --- |
| 零字节空暂存 | `event-log/staging/` 顶层 0 字节文件 |
| 带 PID 的启动暂存 | `core/.<base>.<pid>.tmp` 且该 PID 已不可见 |
| 原子发布遗留 | `.<name>.tmp` 或 `.<target>.<8位尾>`，正式目标已发布且候选不新于目标 |

- 任何候选只要字节摘要仍被永久记录或台账引用就不回收；存在不可读的永久引用文件时整体阻塞回收（未知引用不等于无引用）。
- `spool/` 与 `workdirs/` **永不进入回收扫描**，`transactions/` 不是无条件清空对象；`spool` 输出先保存为证据，未核实活动存在时禁止迁移与回收。
- 空间诊断只报告业务、临时、备份与其他四类组成及剩余空间，或一致地报告缺口；不静默驱逐历史，也不承诺无限输出。
- 容量检查只为已知收尾材料预留空间；输出继续增长而空间不足时暂停新步骤并保留已产生材料，按现状记录缺口，不把“写不下”报成“保存成功”。
- 恢复只认领具有相应安全策略与安全状态的材料；旧材料安全状态不明时保留受控隔离、标未知并禁止展示或外发，不假定已过滤，也不自动删除永久历史。

## 8 偏差记录

| 旧说法 | 代码事实 |
| --- | --- |
| 布局为 `generations/<gen>/{records,manifests,indexes,events}` 加 `transactions/<tx>/` | 权威记录在 `record-store/` 内容寻址节点，清单在 `manifests/`，索引在 `indexes/`，事件在 `event-log/`；`generations/` 无写入者，仅在备份/完整性白名单中出现 |
| 提交先写事务记录，再索引、清单，最后换 `current` | 先把记录节点、索引根、事件根、清单与幂等结果全部准备为不可变材料，再以 `current.json` 替换作为唯一发布点；`transactions/` 只存活动标记、发布标记与 `results/` 幂等结果 |
| `writer_epoch` 有独立载体 | 保存在 `workspace.json`，由生命周期锁准入时加一并绑定，无独立 epoch 文件 |
| 迁移“写新 generation，源代保持不变” | 原位 forward + `migrations/` 下 plans/steps/cycles/registry/journal 检查点，未创建新 generation |
| 迁移入口为 `aitest migrate inspect/plan/apply/resume/rollback` | 实际是受控动作 `migrate` 的 `mode` 参数；CLI 子命令是 `aitest rebuild-index --workspace` |
| `BackupManifest` 登记 root_commit、generation、epoch、事件边界、记录/对象数量与摘要 | `backup.json` 只有 `schema`、`files`、`excluded_active`；root_commit、complete、known_missing 等在应用入口的备份结果与维护审计中 |
| 备份闭包含活动 `spool`/`workdirs` | 有活动时排除 `spool` 并记 `excluded_active`；`workdirs` 从不备份；`transactions` 按永久目录复制 |
| 运行期临时材料、空对象、无有效内容事务残留都可回收 | 回收只覆盖零字节空暂存与隐藏原子临时遗留；`spool`/`workdirs` 永不扫描，无空对象或事务残留回收，无业务删除入口 |
| 查询目录含 `history.groups`、`history.runs`、独立 `reports.revisions` | 一期只有 `issues`、`reports`、`reports-byid`、`records-rev` 与排序族；历史报告修订走点查目录，`history.*` 未实现 |
| `query_id` 是固定字符串目录名 | `QuerySpec` 无该字段；存储层把完整条件绑定派生成 `qid`（sha256 前 16 位），游标绑定 `qid`/代次/提交；`issues.list` 的版本串是 `aitest.issues-list/1.0` |
| 游标固定 query_spec 版本、条件摘要、commit_id 与末尾排序键 | 令牌只含 schema/spec/游标编号/`qid`/代次/提交；条件摘要由 `qid` 承担，末尾排序键与快照根在服务端游标文件 |
| 问题索引键为 `(project, view, mask, 类型化筛选值, sequence, issue_id)` | 实际键为 `(project, view, mask, facet_value\|ALL, severity\|ALL, updated_sequence, issue_id, revision)` |
| 单条问题最多 `4m+24` 个入口（m 为模块数） | 实际上界 `4(m+l)+20`；只有 `ALL` 视图的关闭问题减半 |
| 问题排序为 `updated_sequence` 降序、`issue_id` 升序 | 索引族按整键降序扫描（`issue_id`、`revision` 也降序）；领域 `query_issue_list` 目前按 `(updated_sequence, issue_id)` 升序分页，两处顺序未统一；本册以索引顺序为合同，领域实现列为待修 |
| 备份白名单与完整性顶层白名单是同一份目录清单 | 二者不一致：`model-responses/`、`artifacts/` 有写入者但不在完整性顶层白名单；备份含 `model-responses` 不含 `artifacts`（交付副本不作唯一副本） |
| 存在“已知缺口下的无新增损失迁移”模式（A/G 清单、用户确认、冻结清单） | 代码无该模式：迁移只要求迁移前备份校验通过且无已知缺失，缺口备份只报 `complete=false`，不提供受控豁免流程 |
