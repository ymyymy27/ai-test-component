# 2026-09-29-A包基础设施实现

## 背景/目的

实现 A 包 Windows 文件后端存储层，支撑后续应用用例和 B/C/D 并行开发。

## 核心改动

- 已生成 `docs/文档-LU/A包基础设施存储层设计.md`，明确工作空间、事务、不可变历史、索引、备份、恢复和假存储约束。

## 对接情况

端口类型沿用 `src/aitest/application/ports.py` 与 `aitest.local/2.0` contracts；尚未宣称真实 Windows 故障验收通过。

## 遗留问题/下一步

按文件实现 `src/aitest/infrastructure/file_store/`，每完成一个文件追加一条文件级变更记录。

## 文件级修改记录

### `src/aitest/infrastructure/file_store/workspace.py`

- **改动：** 增加 workspace identity 校验和受根目录约束的路径解析。
- **实现能力：** 防止跨工作空间写入和路径逃逸，为锁与事务层提供稳定边界。
- **约束：** 锁取得成功后才更新 epoch；不提供业务材料删除接口。

### `src/aitest/infrastructure/file_store/records.py`

- **改动：** 增加基于 intent 的幂等追加和冲突检测。
- **实现能力：** 保证同一业务意图重传复用既有 revision，输入摘要变化显式失败。
- **约束：** 历史修订只追加、不覆盖；详情读取必须指定 revision。

### `src/aitest/infrastructure/file_store/fake.py`

- **改动：** 新增内存事务、记录、意图去重和分页查询替身。
- **实现能力：** 支持 B/C/D 并行开发和协议联调。
- **约束：** 不模拟真实 Windows 文件语义，不作为 A 包验收依据；不提供删除接口。

### `src/aitest/infrastructure/file_store/integrity.py`

- **改动：** 新增 JSON 结构和内容寻址对象完整性检查。
- **实现能力：** 检测损坏清单和对象摘要不一致并返回结构化报告。
- **约束：** 检查只读，不修复、不覆盖历史材料。

### `src/aitest/infrastructure/file_store/backup.py`

- **改动：** 新增工作空间文件、对象、spool 和检查点闭包备份及摘要校验。
- **实现能力：** 备份后可验证每个文件摘要。
- **约束：** 不删除源数据；恢复前必须先完成校验和活动事务检查。

### `src/aitest/infrastructure/file_store/recovery.py`

- **改动：** 新增保守恢复扫描。
- **实现能力：** 识别活动事务和完整性缺口。
- **约束：** 不自动重放未知副作用，不依据单个临时文件宣称提交成功。

### `src/aitest/infrastructure/file_store/unit_of_work.py`

- **改动：** 增加 `begin`、request_id 所有权校验及结构化 `commit`/`rollback` 结果。
- **实现能力：** 提供非嵌套短事务边界，防止其他请求提交或回滚当前事务。
- **约束：** 事务外部调用不持有工作单元；永久业务记录只追加，不提供删除或覆盖。

### `src/aitest/interfaces/local/api.py`

- **改动：** 将本地 API 从只读骨架扩展为统一路由适配器，增加事务生命周期分发、连接重试、异常归一和可注入脱敏投影。
- **实现能力：** `begin/commit/rollback/recover` 仅调用事务端口；`test_connection` 使用有界重试策略；处理器结果可经过投影器后再返回；未装配工作空间时 doctor 返回 `NOT_READY`。
- **约束：** API 不计算业务通过/失败，不解析业务结果；重试只用于只读或已证明幂等的连接动作；错误消息截断且去除换行，凭据必须由注入的投影器在落盘/返回前过滤。

### `src/aitest/bootstrap.py`

- **改动：** 增加 `CoreBootstrap`、`CoreInstance` 和受控 `UseCaseRegistry`，统一创建工作空间、文件事务端口和 `LocalAPI`；提供全局 `register_use_cases()` 与 `create_api()` 入口。
- **实现能力：** B/C/D 通过包名注册自己的可调用用例表；A 负责唯一装配、实例缓存和工作空间隔离；注册表对外只提供快照，既有路由不可覆盖或删除。
- **约束：** 注册表只接受 B/C/D 包名；不导入或实现 B/C/D 业务逻辑；外部包不能替换事务端口、工作空间身份或 API 装配流程；A 不计算业务结论。
