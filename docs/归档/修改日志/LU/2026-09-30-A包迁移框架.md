# 2026-09-30-A包迁移框架

## 1. 本次实现概述

补齐 `infrastructure/file_store/migrations.py` 占位模块，实现受控格式迁移框架：`inspect / plan / apply / resume / rollback` 全套命令，apply 前强制可校验备份，迁移状态以注册表为事实来源、审计事件追加到 JSONL。

## 2. 新增/修改文件清单

- `src/aitest/infrastructure/file_store/migrations.py`
  - 新增 `FileMigrationManager`：
    - `inspect()`：扫描工作空间/记录文件版本、已应用与可用迁移、待执行项及漂移（未知已应用迁移）。
    - `plan(ids)`：校验迁移存在、唯一、按 id 升序，冻结计划文件并生成确定性 `plan_id`。
    - `apply(plan_id)`：已应用步骤跳过，首个真实步骤前调用 `FileBackupStore` 创建可校验备份，逐步骤执行并持久化注册表，审计事件入 JSONL。
    - `resume(plan_id)`：状态来自注册表，apply 逐步骤幂等，天然支持崩溃后续跑。
    - `rollback(plan_id)`：逆序处理，任一迁移不可逆则整体阻塞（先检查后执行），逐步逆向并清除注册。
  - 新增 `Migration` 版本化迁移定义（前向/逆向回调）与 `PlanResult`、`ApplyReport`、`RollbackReport`、`MigrationError`。
  - 内置两个真实可回滚的保守归一化迁移：`0001-workspace-schema-version`（补 schema_version）、`0002-records-intents-container`（补 intents 容器）。
- `tests/unit/test_a_migrations.py`
  - 新增 10 项单元测试：inspect、plan 校验（未知/空/乱序/重复）、计划持久化、apply 全执行与备份、重复 apply 幂等、崩溃 resume 仅补未执行步骤、rollback 逆序、未知计划报错、两个迁移的真实文件效应与回滚。

## 3. 落地的约束清单

- apply 在执行任何变更前必须存在可校验备份（backup.json 清单）。
- 迁移注册表（registry.json）是应用状态唯一事实来源；journal.jsonl 仅为审计。
- 计划必须按迁移 id 升序、迁移唯一，禁止跨序执行。
- 回滚为 all-or-nothing：任一不可逆则不执行任何回滚。
- 逆向回调只撤销本迁移引入的变更（值不匹配则保留，不做破坏性移除）。
- 顶层 JSON 不是对象时拒绝迁移，不猜测结构。
- 仅复用已有 `atomic` 与 `backup` 模块，未引入新依赖。
- 不改动 B/C/D 包任何代码。

## 4. 重要备注

- 内置迁移在已初始化的现代工作空间上为幂等 no-op；价值在于对历史/残缺材料的安全归一。
- resume 依赖“前向操作可安全重入”；未来新增不可逆迁移须显式标记 `reversible=False`。
- 尚未做真实掉电中断 apply 中途的物理故障注入（逻辑级崩溃续跑已测试）。
