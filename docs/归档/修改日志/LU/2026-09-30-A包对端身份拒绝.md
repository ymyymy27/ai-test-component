# 2026-09-30 A包对端身份拒绝

## 触发原因

补齐上一轮自测报告列出的"已知未验证项"之一：
跨会话/跨用户物理拒绝测试未做真机验证。
本轮在代码层面补齐物理拒绝逻辑的可独立测试覆盖——
把对端身份判定从 NamedPipeServer.validate_peer 抽成纯函数
`check_peer_identity`，并在 Windows 集成测试之外补充单元测试覆盖。

## 改动文件

### 修改

- [src/aitest/interfaces/local/pipe.py](file:///c:/Users/Lenovo/Desktop/zhiyin/ai-test-component/src/aitest/interfaces/local/pipe.py)
  - 抽出 `check_peer_identity(client_session_id, expected_session_id,
    client_user_sid, expected_user_sid)` 纯函数：
    * 不依赖 Windows kernel32 调用结果，便于单元测试；
    * 会话不一致 → `PeerRejected`（含 client/expected 双侧信息）；
    * 用户 SID 不一致 → `PeerRejected`（含双侧 SID，便于审计）；
    * 会话检查先于用户，跨会话+跨用户时优先报跨会话。
  - `NamedPipeServer.validate_peer` 重构为调用 `check_peer_identity`：
    仍负责取 client_pid、client_session、client_sid、local_sid，
    判定逻辑委托给纯函数，行为等价但可测；
    错误消息更丰富（双侧 SID 都进日志）。
  - `__all__` 导出 `check_peer_identity`。

### 新建

- [tests/unit/test_a_pipe_peer_rejection.py](file:///c:/Users/Lenovo/Desktop/zhiyin/ai-test-component/tests/unit/test_a_pipe_peer_rejection.py)
  - 22 个测试（参数化扩展后总数）：
  * `test_check_peer_identity_accepts_same_session_same_user`：同会话同用户通过。
  * `test_check_peer_identity_rejects_cross_session`：跨会话拒绝。
  * `test_check_peer_identity_rejects_cross_user`：跨用户拒绝。
  * `test_check_peer_identity_rejects_both_cross_session_and_user`：
    会话+用户都跨，先报跨会话。
  * `test_check_peer_identity_rejects_empty_sid`：空 SID 视为跨用户。
  * `test_check_peer_identity_message_contains_both_sids_for_audit`：
    错误消息含 client/expected 双侧 SID。
  * `test_validate_workspace_id_rejects_illegal_characters`（参数化 6 项）：
    拒绝路径穿越、空格、斜杠、空串、冒号、反斜杠。
  * `test_validate_workspace_id_accepts_legal_ids`（参数化 5 项）：
    合法字符（字母数字 - _）通过。
  * `test_connector_returns_none_for_invalid_workspace_id`：
    make_pipe_connector 对非法 workspace_id 返回 None（不抛错给上层）。
  * `test_connector_returns_none_for_invalid_workspace_id_path_traversal`：
    路径穿越字符 / 让连接器拒绝。
  * `test_named_pipe_server_rejects_non_windows`（monkeypatch sys.platform=linux）：
    非 Windows 实例化 NamedPipeServer 抛 PipeUnavailable。
  * `test_named_pipe_client_rejects_non_windows`（monkeypatch sys.platform=darwin）：
    非 Windows 实例化 NamedPipeClient 抛 PipeUnavailable。
  * `test_validate_peer_uses_check_peer_identity`：
    monkeypatch 替换 check_peer_identity 验证委托路径。

## A-C 接口契约对齐

- `validate_peer` 公开方法签名不变，仅重构内部判定逻辑；
  外部调用方行为等价（错误消息更详细，但仍是 `PeerRejected`）。
- 新增 `check_peer_identity` 是**新增导出**，不破坏既有接口。
- 与 [aitest/interfaces/local/pipe.py](file:///c:/Users/Lenovo/Desktop/zhiyin/ai-test-component/src/aitest/interfaces/local/pipe.py) docstring 中"接受连接后用 GetNamedPipeClientProcessId/SessionId
  及进程令牌 SID 校验对端必须是同会话同用户"语义一致。

## 已验证

- 纯函数 `check_peer_identity` 全部拒绝/通过路径覆盖；
- `validate_workspace_id` 非法字符拒绝（含路径穿越、空串、斜杠等）；
- `make_pipe_connector` 在非法 workspace_id 时优雅返回 None（不抛错）；
- 非 Windows 平台 `NamedPipeServer`/`NamedPipeClient` 实例化拒绝；
- `validate_peer` 通过 monkeypatch 验证委托调用路径。

## 未验证（沿用约束）

- 真机跨会话/跨用户 SID 不匹配的物理场景（不在本轮范围）；
- 客户端伪造 SID 字符串通过 ConvertSidToStringSidW 返回值的攻击场景
  （依赖 Windows kernel32 安全保证，非 A 包可覆盖范围）。
