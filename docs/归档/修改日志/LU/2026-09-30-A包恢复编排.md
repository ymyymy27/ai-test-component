# 2026-09-30-A包恢复编排

## 1. 本次实现概述

补齐备份安全恢复与完整事务恢复编排：备份在原有“创建+完整性校验”基础上新增 `restore`（先校验、只恢复到空目标、恢复后按清单字节级核对）；新增 `RecoveryOrchestrator` 实现完整性核对、活动标记与提交清单对账、事件日志核对及从备份隔离恢复的完整闭环。

## 2. 新增/修改文件清单

- `src/aitest/infrastructure/file_store/backup.py`
  - 新增 `FileBackupStore.restore(backup, target)`：校验备份 → 目标必须不存在或为空 → 按清单复制 → 恢复后逐文件重算 SHA256 核对，失败即报错。
  - 新增 `RestoreReport` 数据类与 `BackupError`。
- `src/aitest/infrastructure/file_store/recovery.py`
  - 新增 `RecoveryOrchestrator`：
    - `inspect()`：只读巡检完整性、活动标记、已确认提交序列。
    - `run()`：Phase A 完整性（失败即 blocked）；Phase B 活动标记与 commit.json 对账（已提交 → 清残留标记；未提交 → 只清标记不重放）；Phase C 事件日志 reconcile（提交清单为事实来源）。
    - `restore_backup(backup, target)`：经 FileBackupStore 恢复到隔离目录并核对，不替换活动工作空间。
  - 新增 `RecoveryState`、`RecoveryBlocked`；保留既有 `recover_workspace` 函数语义。
- `tests/unit/test_a_backup_recovery.py`
  - 新增 11 项单元测试：恢复复制与再核对、非空目标拒绝、损坏备份检测、旧函数检查、inspect、healthy、已提交崩溃清标记、未提交清标记不重放、完整性失败 blocked、隔离恢复、损坏备份恢复阻断。

## 3. 落地的约束清单

- 恢复从不覆盖非空目录；目标必须显式提供。
- 恢复前校验备份，恢复后按同一清单字节级再核对，形成闭环。
- 完整性失败即阻塞，不做猜测性修复。
- 活动事务是否真实存在只以 commit.json 为事实来源；未形成提交的外部效果绝不自动重放。
- 备份恢复落到隔离目录，不自动交换活动工作空间。
- 事件日志核对以已确认提交序列为准，孤立暂存只登记不重放。
- 不改动 B/C/D 包任何代码。

## 4. 重要备注
