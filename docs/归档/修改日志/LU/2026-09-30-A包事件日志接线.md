# 2026-09-30 A包事件日志接线

## 触发原因

补齐上一轮自测报告列出的"已知未验证项"之一：
records 仍写旧版 `events.json` 非正式事件日志（接线未做）。
本轮在 A 包内将 `FileRecordRepository.commit_transaction` 与
`FileEventJournal` 接线，增量切换到正式事件日志 `aitest.event/2.0`。

## 改动文件

### 修改

- [src/aitest/infrastructure/file_store/records.py](file:///c:/Users/Lenovo/Desktop/zhiyin/ai-test-component/src/aitest/infrastructure/file_store/records.py)
  - `FileRecordRepository.__init__` 新增可选 `journal: FileEventJournal | None`

    与 boundary 一致，与 records 内部记录级别 commit_sequence 解耦。
  - `zip(created, new_events, strict=True)` 保证一一对应，ruff B007 把
    未使用的 `kind` 改为 `_kind`。

## A-C 接口契约对齐

- `FileRecordRepository.__init__` 新增的是**可选关键字参数**
  `journal=None`，老调用方无需修改；不破坏既有接口。
- `FileUnitOfWork.__init__` 同上，可选 `journal=None`。
- 事件日志 `aitest.event/2.0` 与 [aitest/contracts/events.py](file:///c:/Users/Lenovo/Desktop/zhiyin/ai-test-component/src/aitest/contracts/events.py) 的 `Event` 模型对齐；
  Event 字段（event_id/request_id/intent_id/instance_id/workspace_id/
  writer_epoch/commit_sequence/event_sequence/project_id/record_id/
  revision/event_type）全部由 FileEventJournal 填充。
- 与 [aitest/infrastructure/file_store/recovery.py](file:///c:/Users/Lenovo/Desktop/zhiyin/ai-test-component/src/aitest/infrastructure/file_store/recovery.py) `RecoveryOrchestrator.run` 的 Phase C
  （`journal.reconcile(committed_sequences=...)`）对齐：
  接线后 commit.json 的 commit_sequence 直接是事件日志 boundary
  的 commit_sequence，reconcile 可正确识别已提交 boundary。

## 已验证

- 注入 journal 后 commit_transaction 写 event-log/journal.jsonl，
  不写 events.json；
- boundary.commit_sequence 与 commit.json commit_sequence 一致；
- journal.read() 能读到事件；
- 未注入 journal 时旧路径行为不变（向后兼容）；
- 已 committed boundary 不可二次 begin（幂等保护）。

## 未验证

- 多事务并发写入（A 包单核心单 writer，串行场景已覆盖）；
- 崩溃后 reconcile 的真实物理场景（不在本轮范围）；
- 旧版 events.json 数据迁移到正式日志的迁移脚本（迁移是后续工作）。
