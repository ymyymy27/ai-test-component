## 1. 问题根因

### 1.1 pytest 收集错误（61 个）

`pyproject.toml` 中 `[tool.pytest.ini_options]` 的 `pythonpath = ["."]` 仅将项目根目录加入 `sys.path`。测试文件统一使用 `from aitest... import ...`，而 `aitest` 包位于 `src/` 下，根目录上只有 `src.aitest` 可导入，直接导入 `aitest` 失败，导致所有测试文件收集时报 `ModuleNotFoundError`。

### 1.2 EditorHost 测试失败（8 个）

`src/aitest/interfaces/local/editor_host.py` 在之前的 mypy 修复中被误改为全 `raise NotImplementedError` 占位桩（与 `pipe.py` 同一轮误改），`CoreEndpoint` 也被降为空类。`test_a_pipe_host.py`、`test_a_bootstrap_acquire.py` 中 8 个测试调用 `EditorHost.acquire` 时直接抛 `NotImplementedError`。

### 1.3 事务测试断言失败（1 个）

`FileUnitOfWork.begin()` 和 `rollback()` 的返回字典始终包含 `"intent_id": None`，而测试 `test_workspace_allows_only_one_active_write_transaction` 期望 `intent_id` 为 `None` 时省略该字段（与 `commit()` 的返回风格一致）。

### 1.4 core_worker.py 核查结论

用户重点要求检查 `src/aitest/interfaces/local/core_worker.py`。经核查：

- `python -m py_compile` 通过，无语法错误
- `argparse`、`sys` 均已导入；`pipe` 模块在 `main()` 内延迟导入，无缺失
- 所有变量在使用前定义
- `pipe` 模块无 `aitest` 反向导入，无循环依赖

**core_worker.py 本身无问题，无需修改。**

## 2. 修改内容

### 2.1 `pyproject.toml` — pytest 路径配置

```diff
- pythonpath = ["."]
+ pythonpath = [".", "src"]
```

同时保留项目根目录（使 `import src.aitest` 可用）和 `src` 目录（使 `import aitest` 可用），测试文件无需手动 `sys.path.insert`。

### 2.2 `unit_of_work.py` — `intent_id` 字段按需返回

`begin()` 和 `rollback()` 仅在 `intent_id is not None` 时将其加入返回字典，`None` 时省略，与 `commit()` 风格和测试预期一致。未改变方法签名，未新增业务逻辑。

### 2.3 `editor_host.py` — 恢复 EditorHost 实现

从 git 历史 `commit 276b56c` 恢复 `EditorHost` 的完整实现：

- `CoreEndpoint` 恢复为 `@dataclass(frozen=True, slots=True)`，含 `workspace_id`、`instance_id`、`connection`
- `EditorHost.__init__` 保存 `connector`、`launcher`、超时与轮询间隔
- `EditorHost.acquire` 实现"先连现有 → 不存在则启动 → 轮询等待 → 校验实例身份 → 超时/不匹配则 `WorkspaceInUse`"
- `WorkspaceInUse` 沿用 `aitest.application.errors` 中已有定义（未在本模块重复定义）
