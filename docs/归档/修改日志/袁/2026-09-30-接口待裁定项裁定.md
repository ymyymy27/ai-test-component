## 2. 裁定结论

### 2.1 `SourceSnapshot`

采用“规则主责与代码位置分离”：规则、身份算法和失效判据归 B；`SourceSnapshot` / `SourceFile` 类唯一保留在 `domain/execution/sources.py`；A 实现端口、物化与持久化适配；C 消费冻结事实并核对实际执行来源。禁止复制第二套模型。

### 2.2 `application/ports.py`

采用 A 维护唯一文件、业务包负责语义的方式。业务包提交完整签名草案并确认业务含义，A 确认基础设施可实现性、写入协议文件并处理冲突。当期端口必须当期冻结；A 无法及时处理时由项目负责人指定代维护人，不得另建同名 Protocol。

`Clock` 和 `ProjectionPort` 作为横切合同由总体架构第 12 节与 `application/ports.py` 唯一定义。准备意图的同键幂等、异摘要冲突及与 `intent_id` 同次提交属于一期，可复用通用工作单元原语，不强制专用方法名。

### 2.3 Git 与 GitHub

本地仓库身份和工作区变更清单是一期 `git` 形态必需能力；远端领先/落后及检查状态是一期可选 GitHub 能力。前者使用受控 `git` CLI 并做实际命令能力探测；后者统一走 HTTPS API，不依赖 `gh` CLI，凭据经 GitHub 用途的 `SecretPort`。

本地 Git 不可用会阻塞依赖 Git 身份的动作且不得静默转为 `plain`；远端未配置、未认证、限流、网络或服务失败只降级远端状态，不阻塞本地闭环。远端状态只展示，不直接产生 L1 或业务通过。
