## 完成

### 证据正文只读视图（#125 的读侧）

实现来源：A 包 2026-11-01 的《证据正文只读视图》方案；本批按该方案在 develop 上落代码，
下面的改动点与方案一致（视图枚举、门控规则、白名单、dispatch 路由、bootstrap 注入）。

- `contracts/read_views.py`：`view` 枚举加入 `evidence`（三处：`json_schema_extra` 的
  `oneOf`、`Literal`、`validate` 分支），`schemas/ReadViewQuery.json` 同步重新生成。
- `interfaces/local/view_queries.py`：新增 `evidence_view`，按 `evidence_id + revision` 读
  `evidence_ref` 记录；白名单元数据（显式剔除 `code_identity`），安全态附带正文。
- `bootstrap.py`：`CommittedViewReader` 注入 `objects=FileObjectStore(root)`；未注入时降级为只返元数据。

正文门控（逐层短路，与方案一致）：

| 条件 | `body_omitted_reason` |
| --- | --- |
| `redaction_state` 非 `redacted` / `not_required` | `redaction_unsafe` |
| 对象仓未注入 / digest 不是 `sha256:` / size 非法 | `object_unavailable` |
| size > 4MB | `body_too_large` |
| 读取失败 | `object_unreadable` |
| 字节长度与登记不符 | `object_corrupted` |
| 非 UTF-8 | `binary_content` |

### 运行视图带出证据编号（#125 的"列"侧）

`RunStepDTO` 新增 `evidence_ids` 与 `evidence_revisions`（一一对应，来自当前尝试的
`EvidenceRef`）；面板不必再自己猜记录编号。

### 面板消费（由面板侧另行对接）

`RunStepDTO` 带出 `evidence_ids` / `evidence_revisions` 之后，面板可直接按精确编号读
`view=evidence`；正文渲染由面板负责，本批不含面板改动。

## 边界

- 只返回已脱敏的文本正文；二进制材料只给元数据，需走附件引用路径。
- 证据正文来自对象仓，落盘前已过不可关闭的凭据过滤；视图层不做二次加工。
- 来源真实性（待核实 / 已核实）字段在 `EvidenceRef` 里不存在，仍未引入。
