## 1 本次做了什么

### 1.1 规则版本（`src/aitest/domain/planning/rules.py`）

现有骨架只有 4 个字段的 `RuleDraft` 与 `RuleVersion`。本次按需求 P1-FR05 与架构文档第 3 节重写：

| 对象 | 内容 |
| --- | --- |
| `RuleDraft` | 补齐 `revision`、`scope`、`steps`、`evidence_requirements`、`enablement`、`confirmed`、`unknown_extension_fields` |
| `RuleVersion` | 补齐 `scope`、`steps`、`evidence_requirements`、`source`、`digest`；冻结内容 |
| `RuleRevisionRef` | 按**准确修订**引用，带 `digest` |
| `validate_draft_publication()` | 发布门禁：草稿必须已确认，且发布须绑定确认记录 |

**关键约束的落点**：

- **未确认发布不生效**：`enablement=ENABLED` 且 `confirmed=False` 构造即拒绝。
- **未知执行字段不得静默启用**：`executable_steps()` 只返回已识别步骤；未知字段与步骤重叠即拒绝。
- **不提供自动发布路径**：`RuleDraft` 上没有任何发布方法，有测试断言。

### 1.2 断言依据、用例与计划（`src/aitest/domain/planning/plans.py`）

在既有运行词汇表与 `AcceptanceScope` 基础上扩展：

| 对象／函数 | 内容 |
| --- | --- |
| `AssertionBasisState` | `missing` / `present_unconfirmed` / `confirmed` |
| `CaseLayer` / `CaseImportance` / `PlanPublicationStatus` | 新增枚举 |
| `AssertionBasis` | 依据修订、三态冻结值、文本与摘要 |
| `ConfirmationRecord` | 绑定**准确的依据修订与文本摘要** |
| `effective_assertion_basis_state()` | **派生函数**：不写回冻结对象，不返回计数 |
| `CaseLink` | 验收项、模块、环境、关键链路 |
| `Case` | 需求 P1-FR06 的九个字段 + 断言依据 |
| `CaseRevisionRef` | 按准确修订引用用例 |
| `TemplateVersionRef` | 按准确版本引用模板 |
| `Plan` | 冻结范围、用例与规则修订、模板版本、档位与驱动 |
| `validate_case_publication()` | 用例发布五条门禁 |
| `validate_plan_publication()` | 计划发布门禁 |

`AcceptanceScope` **扩展而未重命名**既有字段，新增：`objective`、`excluded_case_ids`、`exclusion_reasons`、
`dependency_closure_ids`、`applicability_exclusions`。

**关键约束的落点**：

- **派生值不回写**：`effective_assertion_basis_state()` 不修改入参，有测试断言。
- **依据文本变化后旧确认失效**：修订或摘要任一不匹配即回到 `present_unconfirmed`。
- **补充确认不增加已验证数**：派生函数只返回状态，不返回任何计数。
- **`missing` 依据不阻止发布，只阻止进入 full 必测**（见第 3 节）。
- **计划不含结论上限字段**：结论上限只由档位派生，有测试断言 `not hasattr(plan, "conclusion_ceiling")`。
- **计划上无自动发布方法**：有测试断言。

## 3 两处需要留意的判断

### 3.1 `missing` 依据不阻止发布

需求原文："缺失时不可进入完整验证必测项"，且"发布状态与 `assertion_basis_state` 独立，
已发布但依据待确认不退回草稿"。

因此本实现：`validate_case_publication()` **不检查**依据状态；
`validate_plan_publication()` 才拒绝"冻结必测集合中含依据缺失的用例"。

**这是易错点**，已在设计说明第 3.3 节与第 4 节决定 3 中记录。

### 3.2 `present_unconfirmed` / `confirmed` 的聚合不由 B 实现

施工清单第 5 节中两条（`present_unconfirmed` 保留分母不计 V、`confirmed` 仍须实际证据）
涉及**分母与 V 的聚合**，其唯一口径属 D 的判定规则。**B 只提供三态与派生函数**，
因此这两条保留未勾选，并注明归属。
