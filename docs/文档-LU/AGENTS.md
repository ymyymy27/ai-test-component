## 1. 核心原则
- **严禁越权：** 仅修改我指定的模块代码，禁止修改其他模块（A/B/C/D包）的逻辑，除非我明确要求。
- **文档先行：** 在编写任何复杂功能代码前，必须先与我讨论并生成/更新对应的“接口文档”或“设计文档”。不要直接堆砌代码。
- **专业风格：** 解释技术问题时使用专业术语，禁止使用生活化比喻。代码注释需简洁专业。
- **分支管理：** 所有的代码修改必须基于 `develop` 分支的功能分支进行，禁止直接操作 `main` 分支。

## 2. 文件结构与命名规范
- **文档存放：** 所有生成的文档必须存放在 `docs/文档-LU/` 目录下。
  - 子目录分类：`docs/文档-LU/数据库/`，`docs/文档-LU/知识库/`，`docs/文档-LU/接口对接/`。
  - 命名要求：必须使用**中文命名**，例如 `用户模块接口定义.md`。
- **代码存放：** 测试脚本放入 `tests/`，工具脚本放入 `scripts/`，禁止散落在根目录。
- **日志记录：** 每次修改代码后，必须在 `docs/修改日志/LU/` 下更新日志。
  - 格式必须是： YYYY-MM-DD-A包[核心关键词].md 

-日期使用今天的日期。

关键词要简练，参考示例： A包骨架 、 A包接口定义 、 A包与B包契约对齐 。

请给我提供 2-3 个备选文件名，让我选一个最合适的。

Git Commit Message：

必须符合 Conventional Commits 规范。

格式： type(A-package): 简短描述 

type 只能是： feat  (新功能),  docs  (纯文档),  fix  (修复),  refactor  (重构)。

描述部分不要超过 50 个字。

Markdown 文档正文内容：

标题：使用上面选定的文件名（去掉 .md）。

背景/目的：一句话说明为什么要做这个（例如：为了支撑 B 包的调用...）。

核心改动：列出具体改了哪个文件（如  src/a_package/ports.py ），实现了什么逻辑。如果是代码逻辑，请用伪代码或简单的文字描述，不要贴大段代码。

对接情况：说明是否和 B/C 包确认过接口（例如：已与 B 包负责人确认 intent_id 字段）。

遗留问题/下一步：如果有没做完的，或者明天要做的，写在这里。

## 3. 开发与对接流程
1. **需求分析：** 当我提出需求时，先确认是否涉及跨模块对接。
2. **接口定义：** 若涉及对接（如 A 包调用 B 包），先生成一份《接口对接文档》供我确认，确认后再写实现代码。
3. **上下文管理：** 如果对话过长，请主动提醒我开启新对话，并总结当前的进度和关键约束，避免 Token 溢出导致幻觉。
4. **自我检查：** 输出代码前，自查是否符合 `一期实施方案.md` 中的架构要求（如：A包负责统一装配，B/C/D包只负责注册）。

## 4. 特别禁忌
- 不要随意删除 `contracts/` 和 `application/ports.py` 中的定义。
- 不要在业务代码中硬编码路径，使用配置或常量。
- 遇到不懂的架构细节，先查阅 `docs/项目文档/一期工程四部分拆分与低对接实施方案.md`，不要瞎猜。

## 5. A包（本地核心底座）专属约束

1. **可修改范围：** 只能修改 A 包相关代码：`contracts/`、`application/ports.py`、`infrastructure/file_store/`、`interfaces/local/api.py`、`bootstrap.py`。
2. **跨包边界：** 禁止修改 B、C、D 包的任何代码文件。
3. **职责边界：** A 包不负责生成计划、执行被测业务、判定业务结论或编写 Trae 页面。
4. **A 包职责：**
   - 维护 `contracts` 协议和 `aitest.local/2.0` 协议，处理 `request_id`、`intent_id`。
   - 负责 `file_store` 存储层：工作空间身份、单写锁、不可变记录、备份和完整性校验；永久业务材料不提供删除接口。
   - 负责本地 API、`bootstrap` 统一装配，接收 B/C/D 注册用例。
   - 负责重试策略、连接错误归一和 `QuerySpec` 增量索引；禁止全表全扫查询。
5. **变更前置：** 输出代码前先输出变更清单；重大改动先输出设计文档，再编写代码。
6. **文档与记录：** 所有新增文档放在 `docs/文档-LU/`；修改记录写入 `docs/修改日志/LU/`。
7. **分支要求：** 代码修改必须基于 `develop` 新建功能分支 `A包-LU`，禁止直接修改 `main` 或 `develop` 分支。
