# 授权当前动作陈旧夹具修正与套件耗时边界

基线 `b9db44f`，`fix`。本条**不修改产品代码**：修正两个在当前 HEAD 上已经失败的陈旧测试夹具/期望，并记录完整套件在本机的真实耗时边界。

## 1. 发现（宽切片回归）

受限沙箱解除后对收集序号 850–910 的切片（60 项）做真实运行，得到 `58 passed / 2 failed / 1 error`：

- `test_authorization_current_action.py::test_current_attempt_replacement_blocks_grant_and_occupation`（FAILED + ERROR）
  失败原因：`ValueError: checkpoint reference has no saved warehouse revision`
  （`checkpoint_refs.build_checkpoint_map`）。测试在同事务里暂存了 `execution_checkpoint`，却调用 `_stage_snapshot(...)` 时**没有传 `checkpoint_refs`**，于是快照构建器读不到该 Attempt 的检查点引用。生产路径（`commit_checkpoint`）会显式传入，因此这是夹具用了与现行合同不一致的内部调用方式。
- `test_authorization_current_action.py::test_saved_step_revision_change_cannot_consume_prepared_challenge`（FAILED）
  失败原因：期望 `exact current material`，实际 `legacy runtime revision needs controlled new preparation`。两者都是拒绝；安全断言（不提交、授权修订 0、挑战保持 pending）本就成立。

同一批失败在 `bfe93b6/0048bb9` 的**基线源码**（`.runtime/baseline-src`，字节精确副本）上以相同计数复现，因此不是本会话任一修改引入的。

## 2. 修正

- 夹具改为把本事务已暂存的检查点显式传给快照构建器：
  `checkpoint_revision = unit.stage_record(...)`，`_stage_snapshot(..., checkpoint_refs={attempt.attempt_id: (checkpoint_revision, payload)})`。
- 期望改为接受“准确当前材料”或更早的受控来源拒绝原因，并注明安全断言不变。

修后 `tests/unit/test_authorization_current_action.py`：**3 passed（370.67s）**。
