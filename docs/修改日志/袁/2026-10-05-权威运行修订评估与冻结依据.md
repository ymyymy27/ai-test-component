# 权威运行修订评估与冻结依据

基线：已推送的 `fix/1f08d3cf78a3dc0aee3384a0cb52981067cfa422`。涉及 B-05/B-15、C-05/C-06，P1-FR06/07/09、AC20/24/31。项目文档只读，先更新 BC-001 0.14、CORE-001 1.8，再实施代码；接口仍 reviewing/partial/not_run。未新增公开动作或改变 Schema。

## 根因与修复

1. 原纯值入口按 Case ID/修订核对，不验证调用方传入旧用例的正文。用相同 ID/修订替代原独立核验或验收关联后，原入口接受删除核验、替换必测关联；使用真实冻结正文时两者分别被 `independent_verification_removed`、`applicability_weakened` 拒绝。这说明纯规则的输入来源缺少权威应用入口，不能把纯规则接受算作材料已核实。
2. 新 `SavedRuntimeRevisionAssessment.assess` 从 C 保存的当前引用读取运行事实，再按其冻结 PlanRevisionRef 读准确计划，核对项目与完整正文摘要。Plan 只作为待核对视图，要求显式仓储修订；Case 从计划准确引用回读，核对正文/仓储配对、内容摘要及依据正文摘要，Scope 回读后核对完整内容和 M/S/档位。新版计划、用例不替代运行的旧冻结材料。
3. 确认只接受 ID，读取 `case_link@1` 的实际保存记录，核对准确用例、依据、正文摘要、持久意图派生标识和输入摘要；对应的 Case 也必须按准确修订可读且正文一致。引用存在不表示适用新依据；省略确认时如实保留待确认。拟议正文自报错误摘要直接拒绝。
4. 原 C 当前读取只验证快照内部身份，未逐项核对当前检查点。新增 `read_runtime_revision_facts` 回读每个当前 Attempt 的权威检查点并比较完整投影，缺失、跨项目、执行状态/输入依据不同均拒绝。补查又发现 `expected_plan_revision_ref` 没有进入公开投影：真实保存的错误计划检查点仍能通过初版读取，反例 1 failed（46.91秒）已单独封存。现单独核对它与 Run 冻结计划完全相等，缺失也拒绝。当前 Attempt 仍执行时，即使 Step 状态滞后仍不能修改它；历史材料不用于冒充当前状态。
5. 原 `_stage_snapshot` 冻结字段遗漏计划、环境、规则与结论上限。五个反例全部可被暂存接受；现在连同既有 workspace/intent/tier/M 逐项冻结，拒绝在当前指针及快照暂存前发生。认领新 Attempt 的 `allow_current_change` 也不能改写这些初始依据，拒绝后准确旧快照不变。
6. 检查点读完、冻结材料读完均再次核对当前完整事实；中途变化拒绝。既有非空 runtime_revision_refs 尚无可读权威序列记录，明确阻塞，不按字符串条数自签下一修订。
7. 后续又确认普通发布允许同一Step静默换用例归属、必需性、层级、序号、断言及依赖，六项反例都被接受。现逐项冻结步骤集合及执行内容字段，包括准确StepRevisionRef、入口和证据要求；普通发布与新Attempt认领都不能改写。状态、当前Attempt、失效与缺口等进度仍可更新，未来运行修订必须经独立权威保存/应用入口，不能借布尔标记绕过。

## 剩余边界

评估返回的是绑定快照的预览，没有保存运行修订或发出执行许可。返回后仍可能过期，后续保存必须在同一短事务内重读并重评估；不能直接消费预览 accepted。仍须实现准确 RunPlanRevision/StepRevisionRef 持久序列、步骤边界实际应用、暂停/实际依赖失效、默认入口与 D 双序列呈现。

当前检查点核对不替代真实执行句柄 inspect/collect、加载来源核实、未知输出抢救、可信人工及实际环境验收。第17节半程夹具仍待 C 确认；本次受控 paused/Attempt 投影不代签该草案或真实半程运行。22项 A/B/C 产品完成条件仍开放，真实一期保持 0verified/7not_verified/1blocked/27untested，35项证据路径空。
