# MCP普通保存入口与原回执保留

涉及A-02/B-01，ABC整项仍A7/B7/C7共21，真实AC仍0/35。

根因：stdio只有诊断/有限读取，不能把核心已有普通业务保存接到agent入口；仅凭supported_actions也不能判断旧核心是否具有持久原意图合同。doctor现由默认可信装配声明intent_contracts，MCP只对准确1.0合同与注册动作交集开放七类aitest_dispatch。输入派生Command，保留原意图/期望修订/参数及可选目标，独立分配传输号，项目/绑定/工作空间/入口来源固定。未知写合同只降级写入，有限读取保留；四个既有保存名补入传输写身份校验目录。人工/事务/任意动作和上下文覆盖在核心派发前拒绝。

[薄入口与回执保留](../../../src/aitest/interfaces/tools/agent_relay.py)、[诊断合同映射](../../../src/aitest/interfaces/local/api.py)、[可信装配](../../../src/aitest/bootstrap.py)、[共同传输写身份](../../../src/aitest/contracts/commands.py)调用上一批[持久原结果](../../../src/aitest/application/record_write.py)，不另写业务文件。绑定派发前漂移不发送；准确Response收到后即使绑定变化/不可读，保留原成功/失败回执并附上下文重选信息。结果未知不自动重发/换意图，人工环境豁免继续核对真实核心会话。CORE-001先更新1.61，reviewing/partial/not_run，公开Schema未改。

验证：[MCP写入52节点](../../../tests/unit/test_mcp_stdio_write.py)与原读取34节点。旧入口两实际工具缺口反例失败；最终含架构/合同/普通保存351通过（64.72秒），Mypy211/Ruff与wheel/sdist通过。真实Windows节点13.57秒通过：同一stdio写两次只新增一批两记录，CLI原意图回读、干净EOF后核心仍在，换核心重启后回原修订；客户端自称human_ui/点击/非默认隔离仍AWAITING_USER_CONFIRMATION，未新增环境。绑定变化/丢回执等异常为受控传输夹具，不标为真实故障；真实节点使用最小已存绑定，不标为真实Trae/源码确认或业务AC。隔离wheel核对五模块准确字节，86节点通过（25.83秒），实际stdio/CLI/核心子进程也通过PYTHONPATH加载该安装制品。原始输出见[验证目录](../../validation/p1-abc-remaining-20261004/README.md)。
