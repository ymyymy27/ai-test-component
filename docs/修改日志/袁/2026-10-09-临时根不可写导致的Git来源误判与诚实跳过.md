# 临时根不可写导致的 Git 来源误判与诚实跳过

基线 `fa8008c`，`fix`。本条**不修改产品代码**：三处失败经核对是环境前提不成立（临时目录落在被测仓库工作树内），改为带原因的如实跳过，并把本机临时目录边界登记下来。

## 1. 发现

宽切片回归（收集序号 440–520、520–610）得到 3 处失败：

- `tests/unit/test_a_source_control.py::test_is_repository`：`assert control.is_repository(plain) is False` → `True is False`
- `tests/unit/test_a_source_control.py::test_describe_plain`：`describe(plain)` 返回了 `branch=fix`、`head_commit=fa8008c…`
- `tests/unit/test_a_a10_connection_recovery.py::test_git_source_works_without_any_credentials`：同一断言

失败路径显示 `plain` 的实际位置是 `C:/Users/y'm'y/Desktop/ai-test-component/pytest-of-y'm'y/pytest-3/plain0` —— **在检出目录内部**。

根因：本机 `TEMP`/`TMP` 指向的目录不可写（`PermissionError [WinError 5]`），`tempfile.gettempdir()` 按 CPython 的回退顺序最后取 `os.getcwd()`，于是 pytest 的临时根落在仓库里，`git rev-parse --is-inside-work-tree` 对其中任何目录都返回 true。

已探测不可写：`%USERPROFILE%\AppData\Local\Temp`、`%USERPROFILE%\aitest-tmp`、`Desktop\aitest-tmp`、`C:\Windows\Temp`、`C:/aitest-tmp`、`D:/aitest-tmp`、`E:/aitest-tmp`、`F:/aitest-tmp`；唯一可写位置就是工程目录本身。

## 2. 核对结论：产品语义正确，不改产品

[GitSourceControl](../../../src/aitest/infrastructure/adapters/source_control.py) 的 `is_repository` 语义是"该路径是否位于某个工作树内"（`--is-inside-work-tree`），`describe` 同时返回 `--show-toplevel` 作为 `root`，`changes` 也按工作树解析。子目录属于工作树时返回 true 是其既定语义；测试的前提是"普通目录在任何仓库之外"，本机环境使该前提不成立。

## 3. 处理：前提守卫 + 如实跳过

- `test_a_source_control.py` 增加 `_require_plain_directory_outside_a_repository`：若该目录实际已被判定为仓库（前提不成立），`pytest.skip` 并给出原因；环境正常时断言照旧执行。
- `test_a_a10_connection_recovery.py` 在同一断言前加同样的守卫。
- 跳过**不计通过**，与既有的两项 symlink 权限跳过同类。

修后：

```powershell
# 22 passed, 3 skipped
```

Ruff 通过。

## 4. 边界

- 本机可写临时位置只有工程目录，因此"仓库外普通目录"类断言的测试在本机只能跳过；这不是产品缺口，也不能写成通过。
- 完整套件（收集 4749 项）在本机仍无法跑完：真实文件事务类单项 setup 常需 30–110 秒。后续批次继续用轮转分块 + 每块日志定位失败，而不是宣称全量通过。
- 产品字节未改，ABC 仍 21 整项，真实 AC 仍 0 verified。
