# 冻结执行来源绑定的形状校验

基线 `d1f7596`，`fix`。加固 prepare 冻结的 `ExecutionSourceBinding` 形状校验；不改变任何字段语义、不定义映射语法。

## 1. 问题

[ExecutionSourceBinding](../../../src/aitest/contracts/prepared_run.py) 是 prepare 冻结的**预期执行来源**，也是 start 时"期望→实际"核对与 `source_binding_digest` 的依据。原模型只对 `registered_entry`/`cwd_mapping`/`test_config_ref`/`resolved_input_digest` 做了 `min_length=1`，而：

- `allowed_env_keys` / `secret_refs` 允许空白项与重复项——空白键不是真实约束，重复项让"允许集合"含义不明；
- `adapter_versions` 允许空键或空值——空的适配器版本无法用于来源核对。

这类绑定一旦落盘，会在 start 核对时表现为"看起来有约束、实际不可核对"。

## 2. 修改

[contracts/prepared_run.py](../../../src/aitest/contracts/prepared_run.py) 增加 `model_validator`：

- `allowed_env_keys`、`secret_refs`：每项必须是非空文本，且**唯一**；
- `adapter_versions`：键与值都必须是非空文本；
- 明确**不**限制 `entry_arguments`：空字符串是合法命令行参数值（如 `-c ""`），形状校验不得把它当缺失。

## 3. 验证

新增 [tests/unit/test_execution_source_binding.py](../../../tests/unit/test_execution_source_binding.py)：

- 合法绑定精确往返；
- 允许集合：空白项、重复项、混合空白、非文本值全部拒绝；
- 适配器版本：空键、空白键、空值、空白值、非文本值全部拒绝；
- `entry_arguments` 含空字符串仍合法（显式记录该选择）；
- 未知字段拒绝；四个必需标识仍要求非空。

连同 `tests/contracts`、`test_prepare_run`、`test_prepare_run_flow`、`test_substrate_adapter` 共 **306 passed**；`ruff check src tests`、`mypy`（224 文件）通过。

## 4. 边界

- 本批**不**定义 `cwd_mapping` 语法、参数代入规则、适配器选择依据与失败回执分类；这些仍是[生产动作解析器缺口分析](../../一期工程整改/02-整改计划/生产动作解析器缺口分析-2026-10-09.md)中的待裁定项。
- 新发现并记入该分析：**`source_binding_digest` 的派生方式未在合同中明确**——`prepare` 目前只核对解析结果的 `environment_content_identity`/`source_content_identity`/身份与修订，并**不**校验 `resolved.request.source_binding_digest` 是否等于冻结绑定的规范摘要；在裁定前不擅自加这条检查（会改变既有夹具语义）。
