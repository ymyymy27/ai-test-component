# 模型材料JSON严格解码与编码变体过滤

基线 `bfe93b6`（产品代码 `2567bf9` + 文档整理），`fix`；A-09/B-03，主责[采集安全合同](../../项目文档/一期/架构文档/02-执行与证据.md#13-采集安全与原始证据语义)与[AI 调用边界](../../项目文档/一期/架构文档/01-项目与计划.md#ai-调用边界)，涉及 FR16/FR04 及 AC07/16/32/35；ABC 仍 21 整项。

## 1. 规范核对（不改合同口径）

主责合同要求过滤**已解析凭据的精确值、策略明列的编码变体及标准认证字段**，且过滤前字节不得落盘、展示或出站；无法安全处理的材料登记缺口，不伪造完整。JSON 键或值里的 `\uXXXX` 转义是同一凭据的另一种编码变体，旧投影器只在**原文本字节**上匹配登记值，因此转义文本既不命中也不登记缺口，合同被违反。本次按现行主责合同实现，不新增/改义字段、枚举或 AC，无需新裁定；沿用 DEC-007/008/009（仓储修订读取、`scope_id` 冻结、快照 `content_identity`），未触及 `docs/项目文档/` 只读内容。`ProjectionPort.project` 签名、返回 DTO、公开 Schema 与接口口径均未变化，CORE-001/AB-001/台账版本无需递增；仅实现侧策略修订由 `POLICY_REVISION` 承接。

## 2. 根因（交接已复现）

1. [旧投影](../../../src/aitest/infrastructure/projections.py)先用宽松 `json.loads` 解析、只按通用标记/模式过滤；无标记变化时**保留原转义文本**，随后只在文本上做已知凭据精确匹配 → 转义凭据被标 `complete` 并出站。
2. 重复键、`NaN/Infinity`、`1e9999` 数值溢出、孤立代理字符及破损结构都没有可靠拒绝；只检查输入 256KiB，替换膨胀后的字节可以超过单项预算。

## 3. 源码修改

- [guard_json_text](../../../src/aitest/infrastructure/security.py#L241)（新增，`security.py`）：仅 `{`/`[` 开头的文本按结构化处理，其余交回纯文本底线；复用 domain 的[严格解码](../../../src/aitest/domain/json_material.py#L36)（重复字段、非 JSON 数值、溢出、孤立代理、破损结构、递归耗尽全部拒绝）；在**解码后的键与值**上走 `guard_value` 同一底线（已知精确值、敏感键、明列模式），命中即重新序列化为安全文本；无法严格解析或过滤后键名碰撞一律抛 `UnsafeMaterialError` → 登记缺口。未命中时返回原文本与 `False`，不制造新摘要。
- [SafeMaterialProjector.project](../../../src/aitest/infrastructure/projections.py#L102)：疑似结构化材料不可严格解析 → 整项缺口（不投影原文）；命中凭据 → 保留安全投影并登记缺口；纯文本路径语义不变；单项上限改按**过滤与重序列化之后的最终 UTF-8 字节**复核，替换膨胀不再突破预算；缺口登记去重。[POLICY_REVISION](../../../src/aitest/infrastructure/projections.py#L44) 3 → 4。
- [scrub_secret_text](../../../src/aitest/contracts/redaction.py#L63)：幂等判定同时接受带引号的 JSON 值（`"[REDACTED]"`），已脱敏的结构化材料不再被二次改写成非法 JSON。

**行为变化（有意收窄）**：以 `{`/`[` 开头但**不是**严格 JSON 的材料（例如 `{a=1}`、截断的 `[1,2,`）从“按纯文本过滤后投影”改为“登记材料缺口”，与交接反例要求的破损结构拒绝一致（安全优先：无法证明其中没有编码变体凭据）。不以这两个字符开头的纯文本路径不变；默认链路遇到缺口按既有规则阻塞请求（`OUTBOUND_BLOCKED`），不把可疑材料送给供应方。
