# 既有工作空间CLI转发与客户端可取消IO

涉及A-02/10及ABC默认入口；整项仍21，真实AC仍0/35。

根因：CLI始终离线，客户端同步WriteFile无截止、close不能可靠取消活动IO；普通成功回执漏intent、错误漏workspace、连接成功漏项目/绑定/意图，Windows控制台代码页又会输出非UTF-8 JSON。现两端共用准确句柄的可取消IO，读写各共享整帧截止（默认10秒），取消完成再释放OVERLAPPED/缓冲区/句柄；不自动重传未知动作。API补准确原身份，客户端严格核对，不靠接受坏回执绕过问题。

新增doctor --workspace与dispatch --workspace（stdin一份完整Command JSON，EOF结束）。只先读取既有workspace身份，不创建缺失路径、不把被测源码目录猜作数据工作空间；经bootstrap发现/连接同一排他核心。有界严格JSON拒绝歧义、控制帧及自报来源，回执核对协议/request/instance/workspace/project/binding/intent，异常关闭连接。Python CLI仍为agent_relay，人工动作返回AWAITING_USER_CONFIRMATION。输出明确UTF-8。原无workspace离线doctor/模板保留，stdio MCP与真正交互CLI仍继续。
