## 2. 根因：三处都是"改了代码、旧断言未同步"

### 2.1 `boolean_revision`

`6951674`（B 包准确读取身份与项目归属）给底座身份守卫加了布尔拒绝：

```python
# src/aitest/application/planning/substrate.py::require_record_identity
if (
    (record.aggregate_kind, record.record_id, record.revision) != (aggregate_kind, record_id, revision)
) or type(getattr(record, "revision", None)) is not int:
    raise ValueError("record reader returned another warehouse identity")
```

测试注入 `replace(saved, revision=True)`，`True == 1` 让元组比较相等，但 `type(True) is not int` 使守卫拒绝 → `read_scoped_record` 抛 `ValueError` → `handle_model_draft`（`usecase_registry.py:1815-1832`）把它归一为 `B_INVALID_PARAMETER`（"saved outbound policy is unavailable"），**流程根本走不到策略来源证明**，所以拿不到 `ApprovalRequired` / `AWAITING_USER_CONFIRMATION`。

该守卫引入于 `6951674`，比写下该断言的 `97b6518` **晚 186 个提交**。

**产品行为是对的，修的是断言。** 依据两条：

1. 同类注入在 `tests/unit/test_runtime_publication_origin.py` 中就以 `with pytest.raises(ValueError)` 期望同一底层拒绝；
2. 项目既定口径是**不以等待确认替代非法输入**（[AB-001 1.38 受控发布条目](../../接口对接/进行中/AB-001-端口与保存/contract.md)、[2026-10-06 记录](2026-10-06-非默认隔离环境受控确认与持续消费.md)）。

安全性质（被拒、`calls == []`、提交序号不变）在修前修后都成立，未放宽。
