# 原活动命令停止归属与句柄互斥

涉及C-04/12及A-02；ABC整项仍A7/B7/C7，共21项，真实AC仍0/35。

根因：此前跨核心停止已核对原Job，但原适配器取消/超时/启动失败仍用taskkill按PID停止，存在poll后进程退出/PID复用窗口；超时与采集还可同时终止/关闭原Job，操作系统句柄可能被重复使用。现在Windows原活动取消/超时/收尾统一使用本次持有Job；尚未加入Job的悬挂启动用Popen实际进程句柄清理。取消/超时与采集共用collection_lock；迟到超时不改已取消或自然退出。无法核实组停止继续unknown，不退回PID猜测、不登记confirmed。

源码：[CommandAdapter](../../../src/aitest/infrastructure/adapters/execution/command.py)的start、_abort_launch、request_stop/_stop_runtime、_timeout_runtime及_collect_runtime；[12项专项](../../../tests/unit/test_live_command_stop_ownership.py)含取消/超时/启动清理、句柄互斥、迟到回调、失败保持未知及实际Windows命令/保存失败。Windows Job按实际句柄终止关联进程，见[微软接口说明](https://learn.microsoft.com/en-us/windows/win32/api/jobapi2/nf-jobapi2-terminatejobobject)；启动失败使用Popen的Windows进程终止能力，见[Python说明](https://docs.python.org/3.13/library/subprocess.html#subprocess.Popen.terminate)。

验证：修前9个反例全部失败；首组61通过。扩展首轮及第一次夹具更正均318通过/1失败，原因是新Mock.load未显式FileNotFound而触发防重复启动，生产守卫未放宽；更正夹具后12专项通过。最终受影响319 passed（25.68秒）。Ruff/Mypy205、Schema/准备夹具/0.4.0、wheel/sdist及隔离安装准确源码/真实命令取消/超时/启动失败/定时截止冒烟通过。原始日志及可重复范围见[验证目录](../../validation/p1-abc-remaining-20261004/README.md)。CORE-001 1.50保持reviewing/partial/not_run。

边界：不是实际PID复用事故复现，也未声称强杀/物理掉电/Trae或业务回滚验收。没有改变冻结执行来源/授权、历史事实或超时设置。默认业务核验与交付派生、可信宿主及整项剩余条件继续。
