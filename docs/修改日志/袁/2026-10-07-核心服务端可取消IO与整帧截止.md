# 核心服务端可取消IO与整帧截止

基线：fix `20754b2a4948f3b7ebbee88378bac76395227f86`；一期A-02/C-12，FR09/10/17，AC19/26/34。先更新CORE-001为1.46、总台账2.40，状态继续reviewing/partial/not_run。业务与协议字段不变，ABC整项仍A7/B7/C7，共21。

根因是核心唯一主线程直接阻塞ConnectNamedPipe/ReadFile/WriteFile：未连客户端、半帧或不读取响应能占住主循环；仅客户端截止不能释放服务端。原20754b2的真实Windows空帧读取在300ms后仍等待，只有关闭原客户端才结束，见[原实际反例](../../validation/p1-abc-remaining-20261004/server-pipe-actual-before.txt)。最早新增测试包含两处不存在的私有写方法及线程警告，不计为完整根因证明；已改为实际WriteFile字节夹具。

修复在[NamedPipeServer._operation](../../../src/aitest/interfaces/local/pipe.py#L295)：创建独立手动重置事件和OVERLAPPED，连接/读/写均使用重叠IO；超时或回调异常先取消并等待该操作实际完成，再释放事件/缓冲区。跨线程close只申请取消，最后一个操作收尾后关闭管道；看门狗仅调用cancel_wait。[NamedPipeServer.read_message](../../../src/aitest/interfaces/local/pipe.py#L418)与[NamedPipeServer.write_message](../../../src/aitest/interfaces/local/pipe.py#L430)各共享整帧单调时钟截止（默认10秒），分段不续期。有效旧长度前缀与私有字节夹具保持兼容；只断当前连接，已提交业务仍按原意图核对，不伪造停止、取消或回滚。等待钩子在调用主线程执行，仅是运输能力，尚未接持久活动库存或业务后台续行。

验证：真实Windows专项17 passed/12.86秒；最终受影响回归347 passed/75.64秒，包含专项、对端/SID、实际核心跨进程派发/重连/退出、发现/epoch、架构及合同。原回归1 failed/345 passed是私有_write_all签名不兼容，已恢复默认参数后全部通过，未改弱原断言。默认worker子进程在半帧截止后主动断开客户端；保持旧客户端打开仍可连接同一实例、doctor可读且业务提交序号不变。Ruff、Mypy200、7份Schema/4份准备夹具无差异、0.4.0版本通过；一次误用不存在的Schema模块命令已保留错误日志并改用实际模块。wheel/sdist及隔离安装验证另见同前缀日志。

重复验证：`.venv/Scripts/python.exe -m pytest tests/unit/test_server_pipe_deadlines.py --override-ini addopts= -q`。日志：[最终专项](../../validation/p1-abc-remaining-20261004/server-pipe-deadlines-final-tests.txt)、[最终回归](../../validation/p1-abc-remaining-20261004/server-pipe-deadlines-final-regression.txt)。
