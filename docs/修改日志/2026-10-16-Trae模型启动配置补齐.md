# Trae 模型启动配置补齐

基线 fix@d129c24。用户要求安装插件并以实际 DeepSeek 凭据检查真实功能。

发现模型适配器虽然支持显式装配，但 Trae 标准启动没有传递端点与凭据引用。增加宿主机器级配置文件路径、桥接环境变量与默认核心装配读取；只接收有界严格 JSON、HTTPS 端点及凭据引用。无配置保持旧行为；坏配置只降级模型，不阻断本地核心。

配置不含密钥；实际密钥保存到 Windows 凭据管理器，模型策略、材料投影及动作确认保持原约束。真实官方模型列表与适配器调用通过；只发不含私有项目内容的固定提示。

新增配置/既有接线测试 28 项通过，首次扫描被写锁拒绝的测试已修并保留原失败。发布检查与安装回执见[本批证据](../validation/p1-trae-live-20261016/README.md)。真实 Trae 全功能操作尚待用户解锁，不代填 P1 验收。

0.4.7 进一步修复一次性 ensure-core 的生命周期所有者：原进程将 CLI 自身作为父进程，退出后核心也退出，下一次 doctor 会启动不同实例（真实 0.4.6 反例已保存）。宿主启动改用 OS 返回的 CLI 父进程，即真实编辑器/宿主进程；不是业务请求自报 PID。普通进程内启动仍按原自身生命周期，活动/未知执行的退出守卫保持。新增跨进程延迟读取必须保持同一实例的回归。
