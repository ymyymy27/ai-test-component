# 2026-09-29-A包H1锁泄漏修复

## 1. 本次实现概述

修复 P2 项 H-1：`FileUnitOfWork.commit()` 在 `commit_transaction()` 抛出异常时不释放 OS 单写锁，导致锁泄漏至进程退出或调用方显式 `rollback()`。为 `commit()` 增加 `try/finally`，保证无论正常返回还是异常抛出都兜底释放事务锁。

## 2. 新增/修改文件清单

- `src/aitest/infrastructure/file_store/unit_of_work.py`
  - `commit()` 方法：将 `self.repo.commit_transaction(...)` 调用包裹在 `try/finally` 中，`finally` 块调用 `self._release()` 释放锁。
  - 状态清理（`project` / `pending` / `request_id` / `intent_id`）保留在成功路径，失败后仍保留事务状态，供调用方通过 `rollback(request_id)` 显式回滚。

## 3. 落地的约束清单

- 锁释放兜底：`commit()` 无论成功或异常均释放 OS 单写锁。
- `_release()` 内部已有 `if self._lock_context is not None` 守护，重复调用安全。
- 失败后事务状态保留：调用方可通过 `rollback(original_request_id)` 完成回滚并获取 `rolled_back` 响应。
- 仅修改锁释放逻辑，不改动提交、校验、状态清理等业务逻辑。

## 4. 重要备注

- `begin()` 方法已有 `try/except` 在 `open()` 异常时释放锁，本次未改动。
- `rollback()` 方法本身即调用 `_release()`，无需调整。
- 修复后行为：`commit()` 失败 → 锁立即释放 → 另一事务可 `begin()`；原事务状态保留 → 调用方 `rollback()` 清理状态。
