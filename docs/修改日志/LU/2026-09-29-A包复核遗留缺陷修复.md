# 2026-09-29-A包复核遗留缺陷修复

## 1. 本次实现概述

修复复核发现的三项遗留缺陷：存储层索引缺失不再抛出原始异常而返回结构化 `maintenance_required` 状态；事务提交保证 intent 记录、业务记录、提交清单、索引和事件在同一原子发布边界内要么全部成功要么全部回滚；标记 `create_api(handlers=...)` 为过时兼容接口并明确警告 B/C/D 禁止使用。

## 3. 落地的约束清单

- 索引缺失、损坏或版本不兼容时返回结构化 `status=maintenance_required`，不抛出原始异常。
- 查询绝不隐式读取记录文件或对象文件做全表补偿。
- 无效游标返回 `status=invalid_cursor`，不静默归零。
- intent 记录、业务记录、提交清单、索引、事件在同一事务内原子发布，要么全部成功要么全部回滚。
- 业务记录（`records.json`）作为事实来源最后写入；投影写入失败时旧提交边界保持有效。
- 活动事务标记 `transactions/active.json` 在提交前写入、成功后清除，供恢复流程识别并清理陈旧投影。
- `create_api(handlers=...)` 触发 `DeprecationWarning`，B/C/D 上层包禁止使用该参数。
- B/C/D 必须通过 `register_use_cases` 注册用例，由 `create_api(workspace_root)` 装配。
- 不改动已修复完成的 P0-1、P0-3、P1-2、P1-3、P1-4。
- 不改动 B/C/D 包任何代码。

## 4. 重要备注

- `RecordQueryResult` 与 B 侧 `RecordPage` 在 `items` / `next_cursor` 字段上保持鸭子类型兼容，现有调用方不感知类型变更。
- `append_batch` / `append_intent` 保留不变，供非事务路径和现有测试继续使用。
- 提交失败后锁仍由活动事务持有，调用方须显式 `rollback` 释放；活动标记保留供恢复。
