# 2026-09-30 A包跨进程装配

## 触发原因

补齐上一轮自测报告列出的"已知未验证项"之一：
bootstrap 未装配真实系统进程启动器与 NamedPipeClient 到 EditorHost。
本轮在 A 包内实现真实子进程启动器、管道连接器、跨进程装配入口，
完成 EditorHost 与 SystemProcessLauncher/NamedPipeClient 的接线。

## 改动文件

### 修改

- [src/aitest/bootstrap.py](file:///c:/Users/Lenovo/Desktop/zhiyin/ai-test-component/src/aitest/bootstrap.py)
  - 在保留 `CoreBootstrap` 进程内装配路径与 `create_api` 兼容入口的前提下，
    新增 `SystemProcessLauncher`、`make_pipe_connector`、`make_editor_host`、
    `acquire_endpoint` 四个对外装配 API。
  - `SystemProcessLauncher.start(workspace_id)`：
    * 写入 `.core-instance-id` 文件供 connector 探测（原子替换）；
    * 用 `subprocess.Popen` + `DETACHED_PROCESS | CREATE_NEW_PROCESS_GROUP`
      启动 `python -m aitest.interfaces.local.core_worker`；
    * 子进程 stdin/stdout/stderr 全部丢弃，`close_fds=True`，
      避免占用父进程资源；env 透传可注入。
  - `make_pipe_connector(workspace_root)`：
    * 函数式连接器，按 `.core-instance-id` 文件确定目标实例；
    * 文件缺失/读取失败/管道未就绪均返回 `None`（让 host 轮询或启动）；
    * 连接成功返回 `(NamedPipeClient, instance_id)`，调用方持有连接。
  - `make_editor_host` 与 `acquire_endpoint`：装配 EditorHost 入口；
    缺省 launcher 时使用 `SystemProcessLauncher`，缺省 workspace_id 时
    从工作空间 identity 读取。
  - `__all__` 与模块 docstring 同步更新。

- [src/aitest/interfaces/local/pipe.py](file:///c:/Users/Lenovo/Desktop/zhiyin/ai-test-component/src/aitest/interfaces/local/pipe.py)
  - 修复 `NamedPipeClient.connect` 遇 `ERROR_PIPE_BUSY` 时递归调用自身、
    并发场景下 `RecursionError` 的 bug：改为基于 `time.monotonic`
    的有限循环，超时抛 `PipeUnavailable`。
  - 增加 `import time`。

### 新建

- [src/aitest/interfaces/local/core_worker.py](file:///c:/Users/Lenovo/Desktop/zhiyin/ai-test-component/src/aitest/interfaces/local/core_worker.py)
  - 长生命周期核心子进程入口，由 `SystemProcessLauncher` 启动。
  - 命令行参数：`--workspace-root --workspace-id --instance-id --max-clients`。
  - 非 Windows 直接返回 2；启动管道失败返回 3；对端被拒（PeerRejected）
    不致命，继续接受下一连接；客户端断开后 served += 1，达 max_clients 退出。
  - 真正业务 dispatch（解析 Command、调用 UseCase、返回 Response）
    留作后续接入；本入口只承担"实例身份可见、唯一核心可连接"的语义。

- [tests/unit/test_a_bootstrap_acquire.py](file:///c:/Users/Lenovo/Desktop/zhiyin/ai-test-component/tests/unit/test_a_bootstrap_acquire.py)
  - 8 个测试：纯单元（6）+ 真实子进程集成（2，`@win_only`）。
  * `test_launcher_writes_instance_id_file`：拦 Popen，校验 id 文件原子写入。
  * `test_connector_returns_none_when_no_id_file`：无 id 文件 → None。
  * `test_connector_returns_none_when_pipe_unavailable`：mock NamedPipeClient
    抛 PipeUnavailable → None。
  * `test_connector_returns_client_when_connect_succeeds`：mock 客户端
    连接成功 → 返回 (client, instance_id)。
  * `test_make_editor_host_injects_launcher_and_connector`：注入桩
    launcher，校验 EditorHost 调用顺序。
  * `test_make_editor_host_uses_default_launcher_when_none`：launcher=None
    时 EditorHost 内置 launcher 为 SystemProcessLauncher 实例。
  * `test_acquire_endpoint_with_real_subprocess`（@win_only）：端到端
    启动 core_worker 子进程，acquire_endpoint 返回 CoreEndpoint，
    connection 为 NamedPipeClient 实例。
  * `test_acquire_endpoint_starts_new_core_after_close`（@win_only）：
    关闭连接后子进程退出，再次 acquire 应启动新核心（instance_id 不同），
    验证 connector 无状态不复用既有连接。

## A-C 接口契约对齐

- 不修改 `CoreBootstrap.create()` / `create_api()` 行为：B/C/D 进程内
  装配路径不变，旧 `handlers` 参数仍是 DeprecationWarning。
- 新增 `acquire_endpoint` 是**新增**入口，不破坏既有接口。
- `SystemProcessLauncher` 实现 `CoreLauncher` 协议
  （`start(workspace_id) -> str`），与 `editor_host.CoreLauncher` 对齐。
- `make_pipe_connector` 返回 `Connector` 类型
  （`Callable[[str], tuple[object, str] | None]`），与 `editor_host.Connector`
  类型签名对齐。

## 已验证

- 纯单元测试：mock Popen/NamedPipeClient，6 项全过；
- 集成测试（Windows）：真实 `python -m aitest.interfaces.local.core_worker`
  子进程启动、连接、EOF 退出闭环，2 项全过；
- `acquire_endpoint` 成功返回 `CoreEndpoint`，身份核对通过。

## 未验证

- 非 Windows 平台 core_worker 行为（`sys.platform` 判断已返回 2）；
- 多次 acquire 复用既有连接（设计上 connector 无状态，不复用，
  已用测试 `test_acquire_endpoint_starts_new_core_after_close` 显式声明）；
- 子进程崩溃/卡死的真实物理场景（不在本轮范围）。
