## 2. 修改内容

### 2.1 文件最开头增加路径注入

按用户要求在文件最开头增加：

```python
import sys
from pathlib import Path

sys.path.insert(0, str(Path(__file__).parent.parent))
```

把 `tests/` 目录注入子进程 `sys.path`，解决 Windows 环境下 `python -m pytest` 或直接运行测试文件时找不到 `aitest` 模块的 `ModuleNotFoundError`。

后续 `import errno / json / subprocess / pytest / aitest.*` 因为位于 `sys.path.insert` 语句之后，使用 `# noqa: E402` 显式抑制 ruff `module-import-not-at-top-of-of-file` 告警，符合 PEP 8 与 ruff 默认规则。

### 2.2 `test_real_second_process_cannot_acquire_writer_lock` 增加调试打印与断言稳定化

**原代码**：

```python
with writer_lock(path):
    blocked = subprocess.run([sys.executable, "-c", code, str(path)], capture_output=True)
    assert blocked.returncode != 0
    assert b"WorkspaceInUse" in blocked.stderr
recovered = subprocess.run([sys.executable, "-c", code, str(path)], capture_output=True)
assert recovered.returncode == 0
```

**修改后**：

```python
with writer_lock(path):
    blocked = subprocess.run([sys.executable, "-c", code, str(path)], capture_output=True)
    # 调试：观察 WorkspaceInUse 异常类名实际输出位置（stderr traceback 或 stdout）
    print(f"[debug-blocked] returncode={blocked.returncode}")
    print(f"[debug-blocked] stdout={blocked.stdout!r}")
    print(f"[debug-blocked] stderr={blocked.stderr!r}")
    assert blocked.returncode != 0
    # 子进程未捕获的异常默认走 stderr traceback；部分环境/重定向场景可能落到 stdout，
    # 因此同时检查两个流以提升跨环境稳定性。
    assert (
        b"WorkspaceInUse" in blocked.stderr
        or b"WorkspaceInUse" in blocked.stdout
    )
recovered = subprocess.run([sys.executable, "-c", code, str(path)], capture_output=True)
# 调试：恢复后子进程输出，便于核对锁释放路径
print(f"[debug-recovered] returncode={recovered.returncode}")
print(f"[debug-recovered] stdout={recovered.stdout!r}")
print(f"[debug-recovered] stderr={recovered.stderr!r}")
assert recovered.returncode == 0
```

**修改要点**：

1. 在 `blocked` 与 `recovered` 两个 `subprocess.run` 后增加 `print` 调试语句，输出 `returncode / stdout / stderr` 三个字段的原始字节，便于在任意环境直接观察 `WorkspaceInUse` 异常类名实际落在 `stderr`（traceback）还是 `stdout`。
2. 断言从 `b"WorkspaceInUse" in blocked.stderr` 放宽为 `b"WorkspaceInUse" in blocked.stderr or b"WorkspaceInUse" in blocked.stdout`，提升跨环境稳定性（部分场景子进程 stdout/stderr 重定向、CPython 异常输出策略差异等）。
3. 保留原 `assert blocked.returncode != 0` 与 `assert recovered.returncode == 0` 不变，业务语义不变。

## 3. 实际输出验证

在本机 Windows 11 + Python 3.14.7 + `PYTHONPATH=src` 环境下执行 `pytest -v -s` 实测输出：

```
[debug-blocked] returncode=1
[debug-blocked] stdout=b''
[debug-blocked] stderr=b'Traceback (most recent call last):
  ...
  File "...\\aitest\\infrastructure\\file_store\\locking.py", line 20, in writer_lock
    raise WorkspaceInUse("workspace already has a writer") from error
aitest.application.errors.WorkspaceInUse: workspace already has a writer\r\n'
[debug-recovered] returncode=0
[debug-recovered] stdout=b''
[debug-recovered] stderr=b''
```

**结论**：

- `WorkspaceInUse` 异常类名实际出现在子进程 `stderr` 的 traceback 中（因为子进程通过 `python -c` 执行未捕获的异常，CPython 默认把 traceback 写到 stderr）。
- 原断言 `b"WorkspaceInUse" in blocked.stderr` 在本环境已正确通过。
- 修改后的双流断言（`stderr or stdout`）不改变本环境的通过结果，但兼容子进程 stdout/stderr 被重定向或异常输出策略差异的其他环境。
