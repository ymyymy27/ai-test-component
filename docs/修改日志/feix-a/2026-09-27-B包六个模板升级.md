## 1 本次做了什么

### 1.1 合同层

`src/aitest/contracts/templates.py`：

- 新增 `TemplateImplementationStatus`（`draft` / `released` / `deprecated`）
- `TemplatePack.implementation_status` 由 `Literal["scaffold"]` 改为该枚举

**改动原因**：原类型把模板状态锁死为单一取值，模板永远无法标记为已定稿，
"安装后可列真实版本"这一要求无法表达。

**边界未变**：`released` 只表示模板**内容**定稿、可用于生成项目草稿；
**不表示**项目草稿已确认，也**不表示**可以执行。这写进了枚举的 docstring 与设计说明第 2.1 节。

### 1.2 六个模板内容升级

六份 `1.0.0.json` 全部重写内容，**未改任何 `item_id`**：

| 模板 | 条目 | 升级要点 |
| --- | --- | --- |
| `python-library` | 4 | 无持久化时数据库核验不适用，但独立预期比对仍为必测；保留空关键链路及理由 |
| `python-service` | 4 | 仅服务项目适用，库项目不强套；启动必须是真实进程事实，进程存在不等于服务就绪；状态变化经独立只读核验 |
| `http-workflow` | 4 | 鉴权/会话/持久化按适用条件；必须真实链路不以 Mock 顶替；成功 HTTP 状态码不代替持久化证据 |
| `manual-web-workflow` | 3 | 无页面不适用；**尚不支持不等于不适用**，两者不得混用；刷新与重新进入后复核 |
| `agent-workflow` | 3 | 评价规则执行前发布；工具事件必须实际采集，不得以文字自述补造；随机输出默认三次分别留存与评价 |
| `ticket-workflow` | 6 | 同一工单 ID 贯穿创建→分页寻回→详情→改状态→刷新→独立持久化核验 |

每个模板的 `applicability` 现写明**适用条件**与**不适用条件**；
每条 `critical_paths` 现写明**真实依赖**与**不可省核验**。

### 1.3 一处保持不动的设计（记录备查）

六个模板的 `assertion_basis` 仍是"待用户补齐并确认，模板不是断言依据"。

**这不是占位缺失**：需求 P1-FR04 要求模板只能生成草稿，断言依据由用户对准确修订确认。
本次**新增回归测试防止后来者误将该字段"补全"**为具体业务断言。

### 1.4 漏项拒绝案例的处理

需求要求每个模板提供漏项拒绝案例。本次**未在模板 JSON 中新增字段**，理由：

1. `TemplatePack` 的 `extra="forbid"` 会拒绝未知字段，新增需改合同；
2. 需求把该项列在"草稿样例"行，指校验行为而非模板数据；
3. 已有校验测试覆盖，本次**由仅验一个模板扩展为六个模板逐个验**五类非法输入。

该处理与需求字面表述不同，已记录在设计说明第 4 节。

## 5 改既有断言的说明

`tests/contracts/test_templates.py` 原断言：

```python
assert all(p.implementation_status == "scaffold" for p in packs)
```

**改为锁定 `released`，未删除该断言。** 原意图是"模板尚未定稿，不得当完成依据"；
本次升级后该前提不再成立。同时新增"未知状态值被拒绝"的断言，
保留"状态必须是合法值"的校验意图。
