## 1 问题（实测）

`prepare_run` 的失效提示写明 `snapshot_revision` 对应"**source bytes changed**"，
而 `decide_preparation()` 是**按值比对**修订号的。但实测：

- A 的源码快照按**内容寻址**，其元数据**不含 `revision`**（同一 `snapshot_id` 的清单不可变）；
- B 的快照记录**每次固定（pin）都是 `@1`**。

**结果**：源码内容变化时该修订号不变，**"源码变化须重新准备"永远触发不了**。
既有夹具里的 `source_revision=9` 是测试自行构造的值，真实链路不会产生。

## 2 改法

沿用 `DEC-005` 已定下的手法（**观察结果不进摘要、只参与准备判定**）：

| 位置 | 改动 |
| --- | --- |
| `application/planning/preparation.py` 的 `PreparationRequest` | 新增 **`observed_snapshot_identity: str \| None`**（观察到的源码内容身份），与既有 `observed_resolved_input_digest` 同一处理方式 |
| 同文件 `decide_preparation()` | 与旧记录不同即报 `NEEDS_REPREPARE`；**报出的名字沿用 `snapshot_revision`**，失效提示与 `changed_inputs` 形状不变 |
| 同文件的落盘与读回 | 该值随准备记录落盘、可重建；**老记录缺该键不报错**（否则历史记录会被一律判成需重新准备） |
| `application/planning/prepare_run.py` | 两处构造 `PreparationRequest` 时填入 `inputs.snapshot.content_identity` |

**未改的部分**：

- `InputRevisions.snapshot_revision` **字段与类型未动**；本次**没有**为它定义新语义；
- **`PreparedRun` 外部字段与跨包 Schema 字节未改**；
- `ExecutionFacts.snapshot_revision` **未涉及**——它是运行事实的权威修订，
  与准备身份不是一回事，两者不互相替代、不互相推导。

**新增 3 项回归测试**：

1. **`test_changed_snapshot_identity_needs_reprepare_even_with_the_same_revisions`**——
   **八个修订号全都相同、只有内容身份不同时仍判 `NEEDS_REPREPARE`**。
   这是"源码变化须重新准备"在修订号口径下**无法触发**、在内容身份口径下**可以触发**的可执行证据；
2. `test_an_unchanged_snapshot_identity_reuses`——内容身份相同即复用（对照，避免一律重新准备）；
3. `test_historical_records_without_the_identity_are_not_forced_to_reprepare`——
   新增字段之前的记录缺该值时不判变化。
