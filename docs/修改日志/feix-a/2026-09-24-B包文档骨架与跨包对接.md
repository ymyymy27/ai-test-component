## 关键发现

1. **`conclusion_ceiling` 取值错误**（B-C C-01）：C 的三份夹具均写作 `"full"`，
   而规范取值只能是 `partial`（quick/on_demand）或 `passable`（full）。因该字段在 C 侧为裸 `str`，
   校验不报错，**错误会静默传播到 D 的报告聚合**。
2. **`driver` 与 `conclusion_ceiling` 类型未闭合**：C 侧为 `str`，应为枚举。
3. **`intent_id` 在 Run 级缺失**：仅存在于 `AttemptFact` 且可为 `None`，
   无法从一次运行追溯到产生它的准备意图（架构文档第 11 节要求 `intent_id` 为业务身份）。
4. **CI 在 `develop` 上不触发**：`ci.yml` 仍写 `devlop`（改名前的旧分支名），
   导致向 `develop` 提的 PR 完全没有自动化检查。
5. **`SourceSnapshot` 归属冲突**：架构文档第 7 节记录表把它放在 C 的目录
   （`domain/execution/sources.py`），但第 1、2 节与需求 P1-FR01 都把源码快照定为 B 的职责；
   C 已修改该文件。已提请 A/组长裁定。
6. **模板目录布局与架构文档不符**：架构文档写 `manifest.json` + `steps/ issues/ reports/`，
   仓库实际为 `<id>/1.0.0.json`，且三处代码（合同、合同测试、打包配置）一致依赖单文件布局。
7. **本机环境**：`py -3.13` 可用（3.13.3），但默认 `python` 是 3.10，而代码使用 `StrEnum`（3.11+），
   直接用默认解释器会 `ImportError`；`uv` 未安装。另：直连 GitHub 需 `git -c http.sslBackend=openssl`。
