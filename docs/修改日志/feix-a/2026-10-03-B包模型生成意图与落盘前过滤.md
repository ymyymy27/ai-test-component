## 1 B-10 生成意图与重复出站

### 缺陷（检查文档原文对应）

`request_model_draft` 缺持久业务请求号及原结果复用分支：**完全相同的入参两次调用
共用同一出站 `request_id`，却调用模型 2 次、保存 2 份草稿、出站记录到修订 4**
（反例 `B-MODEL-04-repeat-intent`）。稳定记录 ID 没有去重外部副作用；
当前无法区分"重传"与"明确重新生成"。

### 修法

| 项 | 做法 |
| --- | --- |
| 持久业务身份 | `request_model_draft()` 新增 `generation_request_id`；`outbound_request_id()` 在该参数存在时按**（项目, 业务请求号）**稳定。**省略时沿用旧口径**（项目, 策略修订, 任务），既有行为仍可复现 |
| 输入身份 | 新增 `generation_identity`（任务类型、策略/来源/基准修订、材料类别、条数、投影摘要、端点、模型）——**不含 `requested_at`**：时间不同不构成"异输入"，否则重传会被误判为冲突。身份随**意图**一起落盘，重传不必重新推导 |
| 复用 | 最新修订为 `state=outcome` 且身份相同 → 按引用读回**原草稿**返回，**不再调用模型**；`OutboundOutcome.reused_from` 让调用方区分"新调用"与"复用" |
| 冲突 | 同键**异输入** → `ModelGenerationConflictError`（不覆盖、不静默换输入） |
| 未决 | 同键已有意图、结果未提交（响应丢失）→ 新状态 **`OUTBOUND_UNRESOLVED`**，**不盲目重发**，交调用方核对原出站事实 |
| 已失败 | 上次调用已失败并落盘 → 返回**原失败**，调用次数不增加（需求 §7 不自动重试、不暗换供应方） |
| 明确重新生成 | 用**新的** `generation_request_id`，自然是一次真实的新调用 |

### 为什么"未决"必须是独立状态

外部调用**不可撤销**。如果把"有意图、无结果"直接当成"没发生过"而重发，
崩溃恢复路径就会制造第二次副作用；如果直接报失败，又等于替调用方断言"调用没成功"。
两者都是编造事实。因此本模块只如实报告"原出站事实不完整"，
把处置权留给调用方——与"未知副作用不自动重放"的既有口径一致。

## 2 B-03 落盘前凭据过滤

### 缺陷（检查文档原文对应）

`B-MODEL-03-response-before-save`：合成模型返回 password 正文，经当前编排
**原样进入 `generated_content` 记录**；协议出口过滤不等于落盘前安全。

### 修法

1. `request_model_draft()` 新增 `known_credentials`（本项目已知凭据值）。
2. 模型响应在写进 `generated_content` **之前**按**精确值**剔除，替换为
   `CREDENTIAL_PLACEHOLDER`；**长值优先**替换，避免短值先替换后留下长值残片。
3. **过滤事实落盘**：草稿 payload 与出站结果 payload 各带
   `credential_filter = {policy, replacements, filtered}`。
   只有计数与策略版本（`known-values@1`），**不含凭据原值，也不含其摘要**——
   摘要同样会泄露"这个值出现过"的可比对信息。
4. **摘要与落盘字节一致**：`content_digest` 按**过滤后**的正文计算。
5. **短凭据 fail closed**：值短于 `MIN_FILTERABLE_CREDENTIAL_LENGTH`（4）时
   **在调用之前**拒绝。过短的串无法被可靠识别，与其"假装过滤干净"，不如不调用。
6. 模板路径不传该参数，payload 里不出现该键，两条生成路径仍可区分。

### 已知边界（如实登记）

- **"哪些值算凭据"仍由调用方给出**：凭据解析与投影归 A（`SecretPort` /
  `ProjectionPort`），本模块不猜来源。因此 `known_credentials` 不全时，过滤必然不全。
- **存量记录不回填**：旧 `generated_content` 没有 `credential_filter` 键，
  按"未登记过滤事实"处理，不做历史迁移。
