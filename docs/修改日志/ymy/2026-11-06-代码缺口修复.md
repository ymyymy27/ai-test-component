# 2026-11-06 代码缺口修复（工作空间位置、HTTP 捕获完整性）

## 背景

对照 `docs/现状.md` 与当前源码复核时发现两处与“P1 后端代码缺口清零”不一致的代码事实：

1. **P1-FR01 的同步盘/网络盘启动拒绝只有领域策略，没有接入生产创建/启动路径。**
2. **HTTP 工作流把 `capture_completeness` 固定为 `COMPLETE`，且丢弃适配器产生的 `gaps` / `observation`。**

同时发现 `AttemptFact.structured_result_ref` 字段在契约中存在，但投影函数从未填充。

## 代码修改

### 1. 工作空间启动位置守卫（P1-FR01）

- 新增 `src/aitest/infrastructure/workspace_location.py`：
  - `detect_drive_kind()`：Windows 用 `GetDriveTypeW` 识别网络盘（`DRIVE_REMOTE`）与固定/可移动盘；UNC 路径直接判为网络；识别 `OneDrive`/`Dropbox`/`GoogleDrive`/`iCloudDrive`/`Nextcloud` 环境根与 `~/OneDrive` 回退为同步目录。
  - `require_supported_workspace_location()`：把探测结果交给领域 `workspace_location_rejection()`，同步盘/网络盘抛 `WorkspaceLocationRejected`（带 `rejection` 原因）。
  - 非 Windows 平台仅对明确的网络路径分类，其余保持 `UNKNOWN`；领域规则不对 `UNKNOWN` 擅自阻塞。
- 领域 `src/aitest/domain/project/context.py` 抽出 `workspace_location_rejection(drive_kind)`，`reject_workspace_location()` 继续校验规范路径后委托同一规则，避免两处判定漂移。
- `Workspace.__init__` 在 `mkdir` 与写 `workspace.json` 之前调用守卫；创建和打开都检查，拒绝时不留下半成品工作空间。

### 2. HTTP 工作流捕获完整性

- `src/aitest/application/execution/http_workflow_execution.py`：
  - 新增纯函数 `http_workflow_outcome()`：
    - 无 gaps + 有 exchange → `COMPLETED / COMPLETE`；
    - 有 gaps + 有 exchange → `COMPLETED / PARTIAL`（E 不再计入）；
    - 无 exchange（含凭据不可用、请求无法构造）→ `EXECUTION_ERROR / GAP`，带 `StructuredExecutionError`，不伪造完成；
    - 防御性处理无 exchange 且无具名 gap 的情况，落 `http_workflow_no_exchange`。
  - `http_workflow_gaps()` 统一有效缺口列表；每个缺口写入 `EvidenceGapFact`（`kind=http_workflow`、原因码、安全说明、是否需用户处理），并同步 `CoverageSummary.evidence_gap_count/critical_gap_count`。
  - 证据完整性按实际捕获：`body_complete=false` 或存在传输错误时记 `PARTIAL`，不再一律 `COMPLETE`；相关 `gap_ids` 绑定到证据与 TraceNode。
- `src/aitest/application/execution/facts.py`：`project_attempt_fact()` 补 `structured_result_ref` 投影（契约字段已存在，只是此前一直为 `None`）。
- `src/aitest/application/execution/current.py`：`COMPLETED` 但捕获完整性非 `COMPLETE` 的步骤映射为 `PENDING_VERIFICATION`，避免部分捕获被显示为已完成步骤。
- `EvidenceGapFact`：捕获失败类缺口为 `critical`；`http_assertions_missing` 仍落缺口并降低捕获完整性，但不单独标为关键缺口（独立核验仍是断言依据）。

### 3. 未修改的边界

- Agent 工具调用的 `arguments_digest` / `result_digest` 仍只在输入文档校验和调用身份中使用，不进入冻结 `ExecutionFacts`；证据引用是权威材料，Agent 自述不升格为独立核验。未修改 CD-001 冻结字段。
- 未修改跨包合同版本、Schema、动作集合（仍为 62）。

## 新增测试

- `tests/unit/test_http_workflow_outcome.py`（8 项）：完整/部分/无交换/无具名缺口与缺口错误分类。
