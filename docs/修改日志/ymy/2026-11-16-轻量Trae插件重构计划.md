# 轻量 Trae 测试插件修改计划

日期：2026-11-16
范围：一期插件 MVP；不含产品设计稿与界面细化。
状态：执行计划；完成情况以提交、测试与真实 Trae 验收为准。

## 1 目标

把当前“系统级本地测试平台”收敛为**轻量 Trae 插件**：

```text
Trae 扩展（薄 UI）
  → 本地 Python CLI（按命令调用，无常驻核心）
    → 少量核心模块
      project / plan / run / evidence / issue / report
    → 简单文件：JSON / Markdown / 证据文件 / zip 备份
```

不是系统：

- 无常驻核心、命名管道、后台守护服务；
- 无数据库、提交根、manifest、分片、索引、事件日志；
- 无格式迁移/回滚/注册表；
- 无计划许可账本、逐动作授权、A—D 等级、功能×维度覆盖契约；
- 账号、上传、共享审核不进入插件内核。

目标规模：

| 项 | 目标 |
| --- | ---: |
| Python 核心 | 9,000—14,000 行 |
| Trae 扩展/面板 | 4,000—6,000 行 |
| 测试 | 11,000—16,000 行 |
| 模块 | 26—35 个 |
| 默认快测 | ≤20 秒 |
| 全量测试 | 3—5 分钟 |

## 2 已确认决策

| 主题 | 决策 |
| --- | --- |
| 宿主 | 一期 Trae；其他编辑器后置 |
| 运行形态 | 扩展调用 Python CLI；无常驻核心 |
| 模型 API | **必需**（AI 主导测试）；DeepSeek 兼容 HTTP API |
| GitHub | **一期必需薄适配器**：只读提交/PR/检查/部署版本 |
| 链路 | **一期必需薄适配器**：请求→日志→模块→DB→断言 |
| 存储 | 项目目录 JSON/Markdown/证据文件 + 原子写 + zip 备份 |
| 数据升级 | 只支持当前格式；备份后转换或拒绝/重建 |
| 账号/上传/共享审核 | 不做，后续外部集成 |
| 计划确认 | 一次范围确认 + 简单动作日志 |
| 覆盖与等级 | 显示状态与计数；不做 A—D 等级 |
| 模板 | 保留为规则预设清单，不做模板子系统 |
| 保留期 | 文件永久保留；用户自行清理，插件不做自动清理 |
| Python | 3.11+；验证 3.11/3.13，3.14 未验证 |
| 本地边界 | 模型/GitHub/链路是必需外部依赖，不是严格“纯本地” |

## 3 MVP 范围

### 3.1 功能（16 FR）

| 编号 | 功能 | 最小内容 |
| --- | --- | --- |
| FR01 | 项目与模块 | 目录、目标、模块、依赖、负责人、实现状态 |
| FR02 | 任务与验收项 | 目标、范围、验收条件、执行/验收人 |
| FR03 | 交付说明 | 完成/未完成、变更、运行方式、Mock、自测证据 |
| FR04 | 规则与模板预设 | 规则版本、预设清单、Markdown 导入导出 |
| FR05 | 计划与用例 | 分层用例、验收项关联、预期、Mock 许可 |
| FR06 | L1 源码可运行性 | 语法、入口加载/最小启动 |
| FR07 | L2 函数与模块 | pytest/命令、断言、输出、日志、Mock |
| FR08 | L2 接口与集成 | HTTP 串联、业务断言、存储核验 |
| FR09 | L3 用户场景 | 人工步骤、截图/请求关联、最终持久化 |
| FR10 | Mock 与证据 | 真实/Mock/混合/未知；证据文件引用 |
| FR11 | 问题与回归 | 草稿、分级、修复版本、复测 |
| FR12 | 报告与导出 | Markdown、状态计数、证据索引 |
| FR13 | Trae 接入 | 面板/命令、项目绑定、运行状态、导出 |
| FR14 | GitHub 变更与检查 | 只读提交/PR/检查/合并状态/部署版本 |
| FR15 | 链路采集 | 请求标识、日志、模块调用、DB 结果、节点顺序、缺口 |
| FR16 | 链路断言与定位 | 节点断言、首个异常、上下游、代码位置或未知范围 |

### 3.2 薄适配器边界

**GitHub**：

- 一个私有仓库；手动刷新；只读提交、PR、检查、合并状态、部署版本；
- 不写 GitHub、不接 Webhook、不自动发起测试；
- 网络/认证失败明确显示，不伪造检查结果。

**链路**：

- HTTP 执行器自动记录请求 + 人工页面请求编号；
- 导入后端日志、模块调用、DB 查询结果；
- 展示节点顺序、状态、输入输出、证据来源、缺口；
- 节点断言与首个异常定位；首错不一定是根因；
- 不装浏览器扩展、不自动捕获、不做跨服务/函数级追踪。

两者失败时不影响本地测试、证据与报告；但作为一期验收项，需覆盖成功与不可用两种路径。

### 3.3 不做

- 账号、登录、项目成员、上传、共享审核、接收端；
- 常驻核心、命名管道、MCP 多协议；
- 自定义提交/索引/事件/迁移；
- 计划许可账本、逐动作授权、证据等级、覆盖契约；
- 自动浏览器捕获、回放、跨服务/函数级追踪；
- 多编辑器、多操作系统；
- 生产部署、合并冲突处理、无人审核自动修复。

## 4 目标代码结构

```text
src/aitest/
  cli.py                 # 唯一入口：JSON 命令、JSON 输出
  core/
    projects.py          # 项目/模块/绑定
    tasks.py             # 任务/验收项/交付
    rules.py             # 规则/模板预设
    plans.py             # 计划/用例
    execution.py         # L1/L2/L3 结果与状态
    evidence.py          # 证据引用与真实性
    issues.py            # 问题/回归
    reports.py           # 报告/导出
  storage/
    workspace.py         # 目录、原子写、备份
    files.py             # JSON/Markdown 读写
  runners/
    python_runner.py     # pytest/命令
    http_runner.py       # HTTP 串联
    playwright_runner.py # 可选前端 L3
    manual.py            # 人工步骤
  adapters/
    model.py             # 必需：DeepSeek 兼容 HTTP API
    github.py            # 必需：只读
    link_evidence.py     # 必需：日志/DB 证据导入
  models.py              # 共享数据模型
```

扩展：

```text
integrations/trae/
  src/extension.ts       # 命令与面板入口
  src/bridge.ts          # 调用 Python CLI
  src/panel/             # 或复用共享面板
```

存储布局：

```text
workspace/
  projects/<project_id>/
    project.json
    tasks/<task_id>.json
    plans/<plan_id>.json
    runs/<run_id>/run.json
    runs/<run_id>/evidence/<files>
    issues/<issue_id>.json
    reports/<report_id>.json
  backups/<timestamp>.zip
```

规则：

- 单文件原子写：临时文件 + rename；
- 可选简单 `.lock` 防同一项目并发写；
- 查询靠目录扫描；
- 证据只存文件引用与摘要，不嵌入正文；
- 报告/导出从文件读取，不维护全局索引。

## 5 大型项目与多框架支持

插件不按框架写内核，按“外部 runner + 项目配置 + 证据聚合”支持前后端项目。

| 层 | 插件做法 | 项目需提供 |
| --- | --- | --- |
| L1 | 调构建/启动命令 | 入口、依赖、环境 |
| 前端测试 | 调 npm test/vitest/jest，导入 JUnit/JSON | 测试命令 |
| 前端 L3 | Playwright 适配器或人工步骤 | 前端、账号、选择器 |
| 后端测试 | pytest/Maven/Gradle/npm test + JUnit | 命令、环境、数据 |
| 接口/集成 | HTTP 串联 + 独立 DB 查询 | 地址、鉴权、DB 只读入口 |
| 链路 | 导入请求 ID、日志、DB 结果 | 请求标识与结构化日志 |
| 证据 | 保存日志/JUnit/截图/请求引用 | 文件或查询结果 |

大型项目必须有：

- 构建/测试/启动命令；
- 前端/后端地址；
- 测试账号与凭据引用；
- DB 查询入口；
- 模块/目录映射与忽略规则；
- 单次用例数、证据体积上限。

范围与性能：

- 按模块/目录/变更文件/验收项选范围；
- 不默认全仓扫描、不逐文件语义分析；
- 长任务后台执行 + `run.json` 状态；
- 结果流式写、证据按文件引用；
- 超边界明确提示，不假装能测。

一期支持一个试点组合：一种前端 + Playwright、一种后端 + 测试命令/JUnit、一种数据库只读查询。

不承诺：

- 任意框架零配置自动适配；
- 任意前端自动操作；
- 自动插桩/跨服务追踪；
- 自动准备测试数据；
- 自动解决登录、验证码、权限；
- 全仓全量语义分析。

## 10 风险

| 风险 | 控制 |
| --- | --- |
| 删除系统级代码影响旧数据 | 只支持当前格式；备份后重建；旧格式拒绝 |
| 轻量存储查询变慢 | 数据量小；超阈值再评估可选 SQLite 索引 |
| GitHub/链路重新变重 | 固定薄适配器；禁止 Webhook/自动追踪/平台化；失败不阻塞本地 |
| 模型 API 不可用 | AI 步骤失败/阻塞；人工、证据、导出继续 |
| 大项目性能 | 范围选择、后台执行、结果流式写、证据文件引用 |
| 测试删得过多 | 质量门禁：变异/覆盖/审计回归；关键路径不可删 |
| 需求再次膨胀 | MVP 16 FR 冻结；新增功能走适配器，不改核心 |

## 11 系统级红线（不得越过）

以下机制一旦引入，视为回到系统级，必须单独评审：

1. 常驻核心进程、命名管道、后台守护服务；
2. 数据库或自建提交根、manifest、分片、索引、事件日志；
3. 格式迁移/回滚/注册表框架；
4. 多入口并发、单写引擎、跨进程会话；
5. 计划许可账本、逐动作授权、A—D 证据等级、功能×维度覆盖契约；
6. 账号、上传、共享审核、平台接收端进入插件内核；
7. MCP 多协议、自动浏览器捕获、跨服务/函数级追踪；
8. 为一个实现预建多层 Protocol/Factory/Adapter。

允许的外部依赖：

- 模型 API：必需；
- GitHub：一期必需薄适配器（只读）；
- 链路：一期必需薄证据导入（不做自动追踪）；
- 失败时降级，不阻塞本地核心。

新增功能时先判断：

1. 能否只加一个适配器？
2. 是否必须改核心数据模型？
3. 是否引入上述任一红线？
4. 是否有第二个真实实现，值得抽接口？

越线即暂停，先回到 MVP 边界讨论。

## 12 完成定义

1. 插件只依赖 Trae 扩展 + Python CLI + 文件工作空间；
2. 无常驻核心、数据库、提交引擎、迁移框架、许可账本、证据等级；
3. MVP 16 FR 可用，核心闭环、GitHub 关联与链路证据在真实 Trae 中跑通；
4. 默认快测 ≤20 秒，全量 3—5 分钟，质量门禁通过；
5. 旧系统级文档与代码归档，不再出现在现行路径；
6. 未完成/未验证项明确标注，不写成通过。
