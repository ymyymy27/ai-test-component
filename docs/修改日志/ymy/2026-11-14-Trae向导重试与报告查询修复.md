# 2026-11-14 Trae 向导重试与报告查询修复

## 问题

真实 Trae 面板在首次向导“生成计划”步骤报：

```
saved policy approval material is unavailable (AWAITING_USER_CONFIRMATION)
```

## 根因

1. **重试修订未推进**：向导模型阶段固定发送 `policy.revision=1` / `expected_revision=0`；第一次已把策略保存到修订 1 后，任何重试都会被判“修订已变化”。
2. **可操作错误被吞掉**：`SavedModelPolicyApprovalResolver.resolve` 与 `SavedControlledWriteResolver.resolve` 在 `try` 内抛出的 `ApprovalRequired` 是 `ValueError` 子类，被 `except (OSError, ValueError, …)` 覆盖成通用文案，用户看不到“策略已变化，请核对当前修订”。
3. **报告查询白名单缺项**：面板「问题与报告」页在未选运行时会发 `query {aggregate_kind:"report"}`，但用例层有限查询白名单没有 `report`，核心直接返回 `unknown aggregate_kind: report`；索引层其实已有 `reports` / `reports-byid` 分区。

## 修复

- `application/project/onboarding.py`：模型阶段按 `revisions["model-policy:<project>"]` 生成下一修订，`expected_revision` 同步推进；同一修订也写入 `generate_draft` 的 `policy_revision`（此前写死 1，第二次重试会得到 `stale_outbound_policy`）。
- `integrations/trae/src/onboarding.ts`：model 阶段也查询 `model_outbound_policy` 当前修订并传入向导命令，和 commit 阶段的做法一致。
- `application/planning/model_policy_confirmation.py`、`application/controlled_write.py`：先 `except ApprovalRequired: raise`，保留精确原因。
- `application/usecase_registry.py`、`application/planning/substrate.py`：`report` 纳入有限查询类别。
- `infrastructure/capabilities.py`：新核心对**瞬态 connectivity 降级**重新探测（重置为 `not_configured`，随后由真实配置置 `ready`）。此前 `degraded(connectivity)` 会持久化，能力门又拒绝所有模型动作，无法再产生成功事实，形成永久锁死。人工暂停与 auth/限额等非传输降级仍按原样保留。

## 补充：提案重复模板项错误可读性

真实 Trae 向导在按需自测下再次生成计划时，模型提案把同一个 `template_item_id` 用在了两个用例上，面板显示：

```
计划结构未通过校验：$: Value error, duplicate template item IDs；$: Value error, duplicate template item IDs
```

- `PlanProposal` 的拒绝是对的（一个模板提醒项只能对应一个用例），但消息没有说**哪一个**模板项、**哪几个**用例；
- `PlanProposalError.message` 本身就是 issues 的连接串，面板又把 `message + issues` 拼一次，导致同一原因显示两遍。

修复：

- `contracts/plan_proposal.py`：重复用例/模板项时列出具体身份，例如 `duplicate template item IDs: syntax (cases: case-syntax, case-normal)`；
- 面板 `proposalErrorText`：有结构化 issues 时不再重复拼接 `message`；
- 新增回归 `test_duplicate_template_item_ids_are_reported_with_their_cases`。
