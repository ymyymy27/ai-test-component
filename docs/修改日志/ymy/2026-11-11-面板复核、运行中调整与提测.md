# 面板复核、运行中调整与提测（2026-11-11）

## 1 范围

在面板重写基础上补齐仍只存在于 CLI/MCP 的一组产品闭环，并保持所有业务判定由核心产生：

- 本地复核历史的有限查询、只读视图与导出引用；
- 运行中修订（`revise_pending_steps`）和驱动收窄（`narrow_driver`）；
- 尚未执行步骤的批量授权；
- 历史运行复用核对与选择；
- 任务/交付草稿与正式提测；
- 运行视图补完整快照内容身份，供复用核对使用。

未改变领域判定、FR/AC 编号或验收登记；真实 Trae 全流程、主题/缩放和原生确认窗口仍未复验。

## 2 变更

### 2.1 本地复核历史

- 后端
  - `_AGGREGATE_KINDS` 增加 `local_review`，`ReadViewQuery` 与 `view_queries.dispatch` 允许只读视图；
  - `record_view` 以 `review_id` 作为本地复核身份，只返回复核公开字段。
- 面板
  - 报告详情的“读取历史复核”按需查询 `local_review` 并读取精确记录；读取到的复核编号并入导出 `review_ids`。
  - 不自动查询，避免打开报告时产生额外读请求；历史复核仍需报告视图存在。

### 2.2 运行中修订与驱动收窄

- 后端
  - `plan_confirmation_state` 返回 `cases`，逐项给出 `case_id`、冻结 `case_revision` 与 `basis_confirmation_id`（缺失时为 `null`）。
- 面板
  - 工作台新增“运行中修订”：读取计划确认状态，选择用例、填写已保存的新用例修订并勾选未执行步骤，提交 `revise_pending_steps`；确认编号来自核心状态，不在面板猜测。
  - 拒绝改写已完成/正在执行的步骤；计划确认未 `ready` 时禁止提交。
  - 新增“收窄为逐步执行”，提交 `narrow_driver`。
  - 两种动作都走 `controlledDispatch`，由核心原生窗口确认。

### 2.3 批量授权

- 面板先对选中的未执行步骤逐个 `prepare_execution`，再通过宿主 `nativeBatch` 在一个原生窗口中逐项确认 `authorize_step`。
- 只把回执中 `state=confirmed` 且返回授权编号的项标为已授权；未确认项明确显示，不伪造授权。
- 宿主/扩展已有的批量入口保持不变；面板不直接调用核心批量协议。

### 2.4 复用核对与选择

- 后端
  - `RunViewDTO` 增加 `snapshot_ref`（commit/cursor/facts digest），复用核对只接受完整快照身份；
  - 查询允许 `reuse_decision`，只读视图返回目标运行、状态与引用，面板据此取当前选择修订。
- 面板
  - 工作台新增“复用历史结果”：输入来源运行，读取来源与当前运行快照，调用只读 `inspect_case_reuse`，原样展示拒绝/未证实原因。
  - 仅当核对状态为 `unverified`（未发现不兼容）时允许 `select_case_reuse`；登记后资格仍由核心按执行事实重新派生，界面不写成通过。

### 2.5 任务、交付与正式提测

- 问题与报告新增“提测”子页：
  - 新建任务草稿（验收项按 `编号 | 可观察结果 | true/false` 录入）；
  - 新建交付说明：自述完成/未完成与未验证范围分开保存，`verified_in_scope` 固定为空，不允许面板自述已验证；
  - 读取 `delivery` 视图展示自述、未验证范围、核验状态与已提测信息；
  - 正式提测先读取项目记录修订与源码快照，再以 `controlledDispatch` 提交 `submit_delivery`，只引用已保存记录。
- 正式提测仍受核心校验：交付、任务、源码快照、目录绑定和内容身份必须精确一致。

### 2.6 高级动作通道

- 诊断页高级动作按 `CONTROLLED_ACTIONS` 选择派发通道：人工动作走 `controlledDispatch`（核心原生确认），只读动作走只读通道，其余普通写动作走 `writeDispatch`。
- 修复了此前高级动作把 `publish_rules`、`create_plan_grant`、`revoke_approval` 等人工动作误走普通写通道的问题；面板测试新增断言。

### 2.7 规则编辑（P1-FR05）

- 后端
  - `ReadViewQuery` 与 `view_queries` 增加 `rule_draft` / `rule_version` 只读视图；身份使用 `rule_id`；草稿正文不返回本地确认/启用状态。
  - 合同白名单补齐 `export_rules_markdown`（只读）与 `import_rules_markdown`（普通写），宿主、面板高级动作和向导白名单同步，避免宿主以“动作未允许”拒绝。
- 面板
  - “本次测试”新增“规则”子视图：草稿/已发布版本列表、规则编辑表单、保存草稿、确认发布、Markdown 导入、单版本 Markdown 导出、版本复制为新草稿。
  - 保存草稿恒为未确认、未启用；发布走 `controlledDispatch`，由核心原生确认；发布后只读，历史版本保留。

### 2.8 宿主 Python 环境隔离

- 真实宿主桥核对时发现：宿主进程若继承外部 `PYTHONHOME`（例如 uv 的 3.13），配置的 3.11 核心会在 `-m` 启动前失败。
- `integrations/trae/src/core-bridge.ts` 在 `ensure-core`/`restart-core` 与普通派发启动子进程时删除 `PYTHONHOME`，但保留 `PYTHONPATH`（打包入口与测试夹具可能依赖它）。
- 扩展测试新增回归：设置无效 `PYTHONHOME` 时，真实 CLI 夹具仍能 `ensureCore` 成功。

### 2.9 测试

- 面板 Playwright 由 21 项增至 28 项：本地复核历史、运行中修订、驱动收窄、批量授权、复用核对/选择、交付保存与正式提测、规则草稿保存与发布。
- Python 定向：`test_view_queries.py`、`test_run_view_dto.py`、`test_plan_confirmation_publication.py`、保存报告/导出、生成 Schema 与交付相关测试。
- 新增只读视图断言：本地复核使用 `review_id`、复用选择不带同名身份、运行视图快照摘要非空。
