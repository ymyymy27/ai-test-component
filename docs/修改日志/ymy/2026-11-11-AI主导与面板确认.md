# AI 主导向导与面板确认（2026-11-11）

## 1 范围

按 `03-AI主导与非开发者体验设计草案` 收敛默认路径，并解决真实 Trae 测试中暴露的原生确认弹窗问题：

- 默认 AI 主导：项目分析后先展示目标候选，用户点选后再生成计划；
- 计划确认按钮改为“确认并开始”，一次确认后继续准备/登记；
- 计划页展示覆盖收据、已知限制、执行方式与当前运行入口；
- 新增 `panel-confirmation/1`：核心仍持有 challenge，面板显示冻结摘要并回传用户点击，不再打开 Tk 原生窗口；
- 模型 Key 仍只填一次，但去掉“安全凭据”术语和独立安全步骤，失败提示改为可操作文案。

未改变 AC 编号与验收登记；真实 Trae 全链路仍未完成。

## 2 变更

### 2.1 面板确认通道

- 核心
  - `native_confirmation.py` 增加 `prepare_panel_confirmation` / `confirm_panel_confirmation`；准备阶段保留 HUMAN_UI 会话，120 秒后过期并撤销未消费挑战。
  - 核心 worker 支持 `panel-confirmation/1` 控制帧，doctor 广告该能力；原生 `native-confirmation/1` 仍保留给 CLI。
  - `CoreClient.send_panel` 与 CLI `dispatch-panel` 支持 prepare/confirm 两阶段。
- 扩展
  - `dispatchControlled` 增加面板确认回调；prepared prompt 通过 `confirmationPrompt` 发到面板，用户点击后发回 `confirmationResult`，再完成 confirm。
  - 面板不提交 challenge/摘要/角色；核心仍校验 challenge、输入摘要、会话和修订。
- 面板
  - `HostClient` 接收 `confirmationPrompt`；新增面板对话框显示标题、note、事实、技术细节和“确认并继续/取消”。
  - 取消、Escape、关闭或超时都回传 false，不提交操作。
  - 工作台“逐项授权”不再调用宿主 `nativeBatch`，改为逐项 `controlledDispatch`；每一步都在面板内确认，不再打开原生批量窗口。

### 2.2 AI 主导默认流程

- 项目分析成功后增加“选择一个验证目标”阶段：展示 `goal_candidates` 的 statement/why/risk，点选后填入目标并生成计划。
- 目标候选为空时保留原来的直接生成；手工四项检查移入“高级回退”折叠。
- 计划确认页按钮改为“确认并开始”，发布后自动进入准备/登记。
- 模型配置只保留一次 API Key 入口和“高级：模型地址与超时”；不再把“安全凭据”作为独立步骤突出。

### 2.3 计划页

- 读取计划记录中的 `coverage_contract`。
- 增加覆盖收据：业务功能、必要维度、已证明 claim、不支持项；
- 增加已知限制（模板项不适用/不支持与原因）；
- 增加执行方式与执行影响；
- 增加“查看当前运行”或“开始准备测试”按钮。

### 2.4 测试

- 核心：面板 prepare/confirm、错误 challenge 不写入、核心 worker 控制帧。
- 面板：确认对话框回传准确 requestId/confirmed；向导按钮文案；全量 Playwright 29 项。
- 扩展：`dispatch-panel` 夹具覆盖 prepare/confirm，全量 39 项。
