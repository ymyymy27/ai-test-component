# 2026-11-14 代码 P0 缺陷修复（第一批）

## 背景

对 `src/aitest` 275 个文件、面板与扩展做了全量阅读后，先修 5 个会静默出错或越权的缺陷；面板确认通道的完整加固需要协议变更，单列待办。

## 完成项

### 1. `save_binding` 补进一期动作表

`contracts/commands.py` 的 `PHASE_ONE_ACTIONS` 缺 `save_binding`，而它是 `HUMAN_ACTIONS` 且实际可派发；`Command` 的写身份校验（`project_id + intent_id + expected_revision`）对它为空档。已补入，并删除 `native_confirmation.py` 里手工 `| {"save_binding"}` 的补丁。

### 2. 报告索引误分类

`file_store/index.py::_is_report_row` 只看 `report_id` 是否存在，`local_review` 载荷同样带 `report_id`，会被写进 reports 族；读取侧按 `aggregate_kind != "report"` 校验后永久 `maintenance_required`。改为同时要求 `aggregate_kind == "report"`。

### 3. 备份闭包包含旧备份

`FileBackupStore.create` 只排除本次目标，没有排除 `migrations/backups` 下的旧备份；每次备份会把上一次备份再打包。新增 `backup_root` 参数与默认跳过规则，迁移管理器与 bootstrap 装配传入真实备份根。

### 4. 恢复缺完成标记

`restore()` 逐文件复制并核对，但崩溃在中途时目标目录与完整恢复无法区分，调用方仍可能当成就绪。现在全部复制与索引重建后最后写 `diagnostics/restore-complete.json`（`aitest.restore-complete/1.0`），并提供 `restore_completion(target)` 读取；标记缺失即“非完整恢复”。

### 5. 来源探针继承完整环境

`PythonLoadSourceProbe.probe` 用 `dict(os.environ)` 启动子进程，被测项目代码可读取进程内全部凭据。改为只透传解释器启动必需的 13 个白名单变量，固定 `PYTHONPATH` / `PYTHONIOENCODING` / `PYTHONDONTWRITEBYTECODE`，不传 `PYTHONHOME`。

### 6. `RunTier` 两份定义合并

`domain/planning/plans.py` 与 `domain/execution/runs.py` 各定义一次 `RunTier`，值相同但成员对象不同，`is` 比较静默为假。抽出 `domain/run_vocabulary.py` 作为唯一来源，两个模块 re-export，`RunTier is RunTier` 与 `FULL is FULL` 已验证为真。
