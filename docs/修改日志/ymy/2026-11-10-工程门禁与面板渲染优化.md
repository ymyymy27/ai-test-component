# 工程门禁与面板渲染优化（2026-11-10）

## 1 范围

本轮只做低风险、可独立验证的工程优化，不改变领域语义、FR/AC 编号或验收登记：

- CI 增加现行文档事实快检，新增 nightly 全量回归工作流；
- 补齐 `pytest-xdist` 开发依赖，修正 README、CI 与现状页的过时口径；
- 修复测试模块同名导致的默认收集冲突；
- 面板全量重渲染时保留焦点、选区和滚动位置；
- 诊断页按 doctor 真实回执展示依赖状态与可能被拒的动作。

未包含：后端超大模块拆分（`usecase_registry.py`/`bootstrap.py` 等）、按契约自动生成任意动作表单、性能基准脚本。这些需要独立批次和更长回归窗口。

## 2 变更

### 2.1 门禁与依赖

- `.github/workflows/ci.yml`
  - 新增 `uv run python scripts/check_docs_facts.py`：现行状态文档与代码事实不一致时直接失败；
  - 更正“完整回归约 16 小时”的过时注释，改为记录 `-n 8` 历史结果与 nightly 分工。
- `.github/workflows/nightly.yml`（新增）
  - 每日 18:00 UTC（北京时间次日 02:00）回归 `develop`，也支持手动指定 ref；
  - 使用 `--import-mode=importlib -n 8 --dist loadfile` 跑全量并上传 JUnit 诊断。
- `pyproject.toml` / `uv.lock`
  - 开发可选依赖增加 `pytest-xdist>=3.8,<4`，使 README/现状页记录的全量命令可在 `uv sync --extra dev --locked` 后直接复现。
- `scripts/check_docs_facts.py`
  - 测试节点统计改用 `--import-mode=importlib`，与全量回归命令一致；
  - 收集失败时返回 `None`，不再把部分收集结果当成节点总数。
- `tests/unit/test_generated_schemas.py` → `tests/unit/test_generated_schemas_models.py`
  - 与 `tests/contracts/test_generated_schemas.py` 同名，默认导入模式下收集冲突；改名后 `pytest --collect-only` 恢复退出 0。
- `README.md`、`docs/现状.md`
  - Python 口径统一为产品支持 3.11+、开发/CI 使用 3.13；
  - 规模数字按实际代码更新：271 模块、89,415 行、400 个测试文件、94,535 行、6,104 节点、65 个可派发动作。

### 2.2 面板

- `src/aitest/resources/panel/src/index.ts`
  - `render()` 在 `replaceChildren()` 前记录 shadow DOM 内的焦点路径、输入选区与 `window.scrollY`，重建后恢复；路径失效时安全跳过。顶层 `main` 的父节点是 shadow root，路径记录使用 `parentNode`，避免漏掉根级索引。
  - 诊断页新增“依赖状态（真实回执）”：按 doctor 的 `dependencies` 展示依赖键、状态与原因，并按 `action_dependencies` 列出当前可能被拒的动作；不推断未声明能力。
- `src/aitest/resources/panel/tests/panel.spec.ts`
  - 扩展 doctor 回执用例，覆盖依赖状态与受影响动作。
- `src/aitest/resources/panel/tests/view-state.spec.ts`（新增）
  - 覆盖整页重渲染后的输入焦点与草稿保留；
  - 覆盖长详情页重渲染后的滚动位置保留。
