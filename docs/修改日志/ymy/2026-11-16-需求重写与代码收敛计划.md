# 需求重写与代码收敛修改计划

日期：2026-11-16
范围：一期；不含产品设计方案与界面设计。
状态：执行计划；完成情况以提交记录、测试结果与验收台账为准。

## 1 目标

把仓库从“旧 17 FR + 多次 AI 扩写”收敛到已确认的一期基线：

- **21 FR / 26 条验收草案**（旧 35 AC 仅历史）；
- Trae 一期、账号/上传后置；
- GitHub 与链路工具纳入一期；
- 永久保留；
- 一次范围确认 + 动作日志；
- 保留覆盖、删除 A—D 证据等级；
- 只支持当前存储格式 + 备份；
- 模板保留为规则预设。

完成标准：

1. 需求、架构、设计、验收、代码使用同一套 FR/状态/字段；
2. 旧设计（许可账本、证据等级、迁移框架、账号/上传一期范围）不再出现在现行合同与代码路径；
3. GitHub 与链路有一期最小实现与验收场景；
4. 每阶段有可复核的验证记录，不用“文档一致”代替真实执行。

## 5 执行顺序

1. **WP1**：先冻结需求与验收，避免后面继续按旧 AC 改。
2. **WP2**：先改架构合同，再改代码；设计只改对象/状态部分。
3. **WP3**：按“许可 → 等级 → 迁移 → 死代码 → 统一/性能”顺序，每步独立提交。
4. **WP4**：GitHub 与链路先做最小试点实现，不等全部清理完。
5. **WP5**：最后压台账、折叠规划、收敛文档与测试。

依赖关系：

- WP3-01/02/03 依赖 WP2-01/02/03 的合同先定。
- WP1-03/04 依赖 WP1-01。
- WP4-01/02 依赖 WP2-04/05。
- WP5-05 可在任何阶段并行准备，但不阻塞功能。

## 6 验证门禁

每个工作包完成时必须：

1. `ruff check .`、`mypy` 通过；
2. 受改动路径的既有测试通过；
3. 合同/架构/恢复测试按影响范围通过；
4. 文档链接、`check_docs_facts --full` 通过；
5. 删除类改动额外验证：无生产引用、启动/恢复路径可用；
6. 新增能力：至少有组件级真实进程/文件测试，并明确未做真实 Trae/真实仓库验收。

全量 `pytest tests` 只在 nightly 或明确验证批次执行；不以分块结果冒充全量。

## 7 风险与控制

| 风险 | 控制 |
| --- | --- |
| 删除许可/等级影响旧记录读取 | 只支持当前格式；升级前强制备份；旧格式拒绝并提示导出/重建 |
| 删除迁移框架导致旧工作空间不可用 | 明确提示，不静默改写；提供导出/重建说明 |
| 新 26 AC 与旧证据无法对应 | 旧 35 AC 全部标历史；新场景重新执行，不继承 verified |
| GitHub/链路引入新复杂度 | 先做最小试点：一个仓库、一条业务链路、只读/手工关联 |
| 测试债拖慢验证 | 分层 marker、受影响模块优先、全量 nightly |
| 模板与规则漂移 | 模板只作预设清单，不设第二套门禁；定期对照规则版本 |

## 9 完成定义

一期收敛完成需同时满足：

1. 21 FR 在需求、架构、设计（非界面部分）、功能清单中编号与语义一致；
2. 新 26 条验收场景全部有明确状态；`verified` 必须有真实环境证据；
3. 代码中不再存在许可账本、证据等级、迁移框架的现行路径；
4. GitHub 与链路有一期最小实现和验证记录；
5. 模板保留但不再形成第二套发布门禁；
6. `ruff`、`mypy`、合同/架构/恢复测试、文档检查通过；
7. 真实 Trae、GitHub、链路试点中未完成的部分明确标“未验证”，不写成通过。
