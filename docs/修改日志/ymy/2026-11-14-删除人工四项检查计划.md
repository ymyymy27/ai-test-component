# 2026-11-14 删除人工四项检查计划路径

## 背景

真实 Trae 中连续两次被模型/网络问题挡住计划生成后，产品决定不再保留“改用手工四项检查”的人工计划回退，计划只走 AI 提案路径。

## 改动

- 面板：移除「改用手工四项检查」入口（目标候选页与模型页）、`manualStep` 四项检查表单、`WizardCheck`/`checks` 状态与 `startManual`；`runStage` 不再接受 `plan` 阶段；非 pytest 模式不再显示“用 AI 生成”开关（计划固定走 AI），pytest 模式保留手工测试范围选择。
- 向导命令：删除 `OnboardingForm.checks`/`CheckForm` 与 `wizard_commands(stage="plan")`；`plan` 阶段现在返回“未知向导阶段”。
- 文案：`structured_output_invalid` 与设置页不再提示改用手工检查。
- 合同：需求 P1-AC30 预期改为“计划由 AI 提案生成，无模型时明确阻塞而不提供手工四项检查”；功能/架构/设计分册同步删除“人工建计划/手工路径”表述；`tests/acceptance/p1/status.json` 的 AC30 镜像同步并重置为 `untested`（旧验证记录只对旧预期有效）。
- 测试：删除面板 `manual four-check plan reaches prepare and register` 与向导 `test_wizard_project_and_plan_use_real_core_contracts`；`test_wizard_never_invents_snapshot_or_confirmation_receipts` 改为断言 `plan` 阶段被拒绝；表单断言改为不再包含 `checks`。

## 保留

- `save_plan`/`publish_plan` 核心动作仍在，供 AI 提案与已保存提案的编辑发布使用。
- pytest 测试模式的手工测试范围选择未受影响。
- 人工补证、问题处置、报告复核等其它人工能力未改。

## 验证

- `tests/unit/test_onboarding.py`、`test_acceptance_status*.py`、`test_plan_proposal.py` 共 98 项通过。
- 面板 `tsc` 与 `npm run build` 通过；`ruff`、`mypy`（290 文件）、`check_docs_facts` 通过。
- 面板与 VSIX 已重建并安装；核心包已重装。

## 未验证

- 未在真实 Trae 中按新合同重跑“无模型时计划生成明确阻塞”的验收；AC30 保持 `untested`。
- 面板 Playwright 全量未跑，仅做了类型检查与构建（删除的用例已同步移除）。

## 边界

- 这是合同级删减：无模型时不再能通过面板/向导建立计划。旧验证记录 `2026-11-14-p1-ac30-new-project-analysis` 证明的是旧预期，不再对应当前合同。
