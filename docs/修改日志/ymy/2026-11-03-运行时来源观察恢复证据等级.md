## 完成

### 运行时来源观察写回来源核实（#127）

修复证据等级恒为 C 的两处事实装配问题：

- `application/execution/commit.py`：运行时来源观察此前只在尝试仍是当前尝试时写回
  `source_verifications` 与 `source_check_results`，但运行时证据本身无论是否当前都会落盘。
  现在只要本次提交带有运行时观察，就发布对应事实与新快照；历史尝试的来源事实不再停留在
  准入探针的降级状态。
- `application/review/execution_decision_adapter.py`：判定只使用当前来源事实。
  - 来源核验按证据引用归属到尝试；无证据引用的探针按规范编号
    `source-verification:<attempt_id>` 归属，归属到已失效尝试的探针不再参与判定；
  - 同一尝试同时存在已验证的运行时观察与带 `actual_execution_load_source_unverified`
    缺口的准入探针时，以运行时观察为准，避免准入探针的降级缺口把整轮封顶为
    `source_identity_unverified`。

判定口径不变：没有运行时观察、运行时观察自身带缺口、或来源不一致时仍为
`UNVERIFIED` / `MISMATCHED`；本次只移除已被运行时观察取代的准入探针，不把未核实升格为已匹配。
