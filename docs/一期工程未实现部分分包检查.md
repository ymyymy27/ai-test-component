## 3. A 包：本地核心底座

### 3.1 已有基础

已有工作空间身份、写锁、不可变记录、内容寻址对象、有限查询、基础备份、事务路由和统一装配骨架。

### 3.2 尚未实现或尚未闭合

- `infrastructure/file_store/events.py` 仍是占位，缺少提交边界、快照游标、事件续读和重复事件处理。
- `migrations.py`、`maintenance.py` 仍是占位，缺少迁移的 `inspect / plan / apply / resume / rollback`、空间诊断和受控临时材料回收。
- 当前恢复只能检查完整性和活动事务，尚未形成完整恢复编排；备份只有创建和校验，没有安全恢复闭环。
- `credentials.py`、`projections.py`、`connections.py` 尚未实现，真实凭据解析、安全投影和连接适配缺失。
- `SourceSnapshotPort`、`SourceControlPort`、`ModelProvider`、`ProjectionPort`、`SecretPort`、`VerificationPort` 等端口只有职责说明，没有完整方法签名或正式实现。
- Windows 命名管道与唯一核心生命周期未实现；`interfaces/local/pipe.py`、`editor_host.py` 均为占位。
- 当前底座质量门没有通过：Schema 未同步、架构依赖、事务返回合同和对象篡改测试存在失败，ruff/mypy 也未通过。
- P1-AC28 尚未完成前置条件分析，更没有真实 Windows 多进程、掉电、权限拒绝、备份恢复和永久历史验收。

### 3.3 需要其他包配合

- D 提供报告和问题查询字段、排序及投影合同。
- B/C/D 通过正式用例注册表接入唯一 `bootstrap.py`，不得绕过工作单元直接写文件。
- C 提供活动执行与 spool 的恢复事实，D 核对恢复后的可见性。

### 6.1 当前基础

现有实现主要是 Coverage 集合关系、IssueRecord 基础状态、覆盖计数 DTO、CLI 骨架、静态面板导航和候选 Trae Webview。

### 6.2 尚未实现或尚未闭合

- S/M/E/R/V/P/F/U/H 唯一判定、业务结果、证据等级和失败优先规则没有实现。
- 报告冻结、内容修订、历史报告、LocalReview、Markdown 摘要和可携带证据包导出未实现。
- IssueRecord 只有基础状态模型，重复问题归并、确认、处置、重开、修复登记和“必须有新执行才能关闭”守卫未实现。
- `application/review/reporting.py` 和 `defect_management.py` 都是占位。
- DTO 目前基本只有覆盖计数，缺少项目、计划、运行、证据、报告、问题、连接状态和维护状态的稳定投影。

- `issues.list`、报告查询、精确编号匹配、历史筛选和导出登记均未接通 A 的索引。
- D 负责的 16 项 AC 目前全部为 `untested`。

## 7. 尚未完成的跨包闭环

1. A 的真实存储替换 B/C 的内存或临时底座。
2. B 的真实 PreparedRun 通过统一用例交给 C，而不只是测试夹具。
3. C 的真实 ExecutionFacts 交给 D 完成判定、报告和问题闭环。
4. D 通过 A 的统一通道接通 CLI、MCP、Trae 和面板。
5. 在单模块 Git 项目和 plain 项目上完成完整链路，再扩展到 P1-AC01—35。

## 8. 建议实施顺序

1. A 先修复现有质量门，补齐正式端口、事件和本地通道，形成可替换假底座的稳定核心。
2. B 接入 A 的真实存储，完成源码身份、Git/GitHub 和真实模型出站。
3. C 补齐 L1/L2/L3 执行类型、授权、独立核验和恢复装配，产出可提交的真实 ExecutionFacts。
4. D 完成唯一判定、报告、问题闭环及统一入口。
5. 四包完成两次业务交接和一次入口贯通后，再执行真实环境 P1-AC01—35。

本报告是基于当前仓库的静态实现与已有自动化结果进行的分包检查，不把合同、夹具、模拟器或单元测试写成真实产品验收。未执行真实 Trae、GitHub、模型服务、掉电恢复及人工业务场景的部分均保持“未验证”。
