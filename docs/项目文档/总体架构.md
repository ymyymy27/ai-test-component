# AI 辅助测试插件总体架构

版本：3.4  
更新日期：2026年9月23日  
文档类型：工程设计文档

## 1 范围与导航

一期在 Windows 11 x64、Python 3.13、Trae 上交付本地测试闭环；二期扩展展示、编辑器与操作系统；三期只增加平台账号关联和结果上传。插件不部署服务、不监听 TCP 端口，不实现平台接收、审核、共享查询、宿主加载或远程 MCP。

[一期需求](一期/需求文档/01-需求文档.md) · [二期需求](二期/需求文档/01-需求文档.md) · [三期需求](三期/需求文档/01-需求文档.md) · [阅读索引](阅读索引.md)

### 架构边界

本册是架构总览：一次讲清分层、模块清单、期次边界、端到端流程、运行形态、工程结构与演进方式。各子域的详细设计在各期分册；一期为01—06（含面板与工作台），二期为01—06，三期为01—02；本册不做重复，只做全局拼图与跨子域约定。

### 设计边界

插件是**可安装的本地工具**，不是服务：

| 项 | 一期 | 二期 | 三期 |
| --- | --- | --- | --- |
| 服务端 | 无 | 无 | 依赖外部平台，插件不提供 |
| 网络端口 | 不监听，只发出站请求 | 同一期 | 增加平台账号与结果上传出站调用 |
| 账号与登录 | 无 | 无 | 统一账号 |
| 交付形态 | Python 核心包 + Trae 扩展 + 面板 + CLI/MCP | 增加多编辑器与操作系统 | 增加出站平台适配器、账号与上传界面 |

一句话原则：**一期把"测"做完并留在本地；二期把"用得上"做开；三期把"传得出去"接上平台。** 三期的能力不改变一期已经定下的判定与记录规则。

## 2 分层与职责

| 层 | 模块 | 约束 |
| --- | --- | --- |
| 入口 | integrations/trae、其他编辑器、CLI、stdio relay、面板 | 提交命令、读DTO，不直接写业务文件，不保存凭据正文 |
| 接口 | interfaces/local、contracts、dto | Schema校验、版本/能力协商、路由、传输请求去重 |
| 应用 | project、planning、execution、evidence、review、connectivity | 编排、授权、事务边界、持久意图、恢复与统一重试策略 |
| 领域 | 项目/计划/运行/证据/报告/问题及纯判定函数 | 无I/O；通过、证据等级、覆盖、缺陷关闭各只有一处规则实现 |
| 基础设施 | 文件后端、进程、HTTP、模型、凭据、源码适配器 | 实现端口；供应方错误归一化，不自行决定业务通过 |

入口→接口→应用→领域。应用经端口访问基础设施；bootstrap注入实现。基础设施可以依赖端口协议和领域数据类型，不能导入应用用例。新增编辑器复用核心，不复制状态机。

### 架构原则

1. **依赖单向**：入口 → 接口适配 → 应用用例 → 领域模型；外部能力实现端口并被注入，不反向依赖应用用例。
2. **端口集中**：全部外部能力接口定义在 `application/ports.py`，实现放 `infrastructure/`；新增外部系统只加适配器。
3. **规则单一**：判定、统计分母、不适用、结论上限、缺陷关闭依据只由领域层实现一次，界面与适配器只读取结果。
4. **记录不可变**：业务记录改动一律产生新修订；报告正文、规则版本、提交记录都不可原地覆盖。
5. **先落盘后动作**：需要恢复的动作先可靠保存；网络与测试在提交事务外执行。
6. **不谎报**：缺失、未执行、未验证、结果未知都是合法状态；任何层级不得用成功提示替代证据。
7. **期次可插拔**：后续期次可新增用例、记录类型、字段和适配器；保持已有判定语义与已发布字段兼容，新动作经能力协商暴露，格式升级经受控迁移。

### 各层模块与职责

**入口层**

| 模块 | 职责 | 不负责 |
| --- | --- | --- |
| `integrations/trae/src` | 命令注册、工作目录事件、面板宿主、MCP 工具登记 | 业务状态、重试、密钥 |
| `resources/panel` | 展示与明确的用户操作输入；按需拉取附件引用 | 计算通过条件与统计 |
| `interfaces/tools/cli.py` | 命令行入口：`doctor`、`migrate`、显式动作 | 交互式业务判断 |

**接口适配层**（端口与实现文件的对应关系见本节末表）

| 模块 | 职责 |
| --- | --- |
| `interfaces/local/api.py` | 同进程统一 API；把动作名映射到应用用例；组装返回 DTO |
| `interfaces/local/pipe.py` | 命名管道消息编解码、实例发现、会话与绑定核对 |
| `interfaces/local/editor_host.py` | 扩展连接、本地进程生命周期、事务外长动作的 `run_id` 返回 |
| `interfaces/tools/agent_relay.py` | stdio 转发；只依赖 DTO，不写业务文件、不持写锁 |
| `interfaces/dto.py` | 领域对象 → 稳定 DTO 的投影；字段与编号口径统一 |
| `contracts/`（属接口契约） | DTO 定义与生成的 JSON Schema；版本协商常量 |

接口层的共同约束：**同一批动作在面板、CLI、MCP 上使用相同 DTO 与相同错误结构**，不允许某入口私自扩展字段或改变语义。

**应用用例层**

| 模块 | 职责 | 关键约束 |
| --- | --- | --- |
| `project/context.py` | 建立本地项目、登记模块与依赖、绑定目录与仓库、上下文汇总 | 只使用本地标识，不依赖账号 |
| `planning/plan_builder.py` | 模板读取、AI 生成检查内容草稿、确认发布 | 未发布草稿不执行；已发布但依据未确认的用例仍留分母，按规则执行且不计有效验证 |
| `planning/run_mode.py` | 档位与驱动冻结、结论上限派生、范围与跳过项 | 结论上限只由档位决定 |
| `planning/regression.py` | 变更影响与回归范围 | 单模块仍计算本模块变化与回归，仅跨模块传播不适用 |
| `execution/runner.py` | 依赖图调度、层级执行、暂停取消重试 | 上游失败只阻塞依赖项 |
| `execution/recovery.py` | 检查点、句柄重关联、安全重试与待核实 | 有副作用且结果未知不重放 |
| `execution/source_checks.py` | 源码固定、隔离物化、检查复用判定 | 句柄只读快照目录 |
| `evidence/evidence_review.py` | 证据定位、链路关联、独立核验、真实性判定 | 不凭时间或推断建立调用 |
| `review/reporting.py` | 报告快照、内容修订、Markdown 导出 | 报告正文不可变 |
| `review/defect_management.py` | 问题更新、分级、修复登记与复测 | 关闭必须有新证据 |
| `ai_assistance.py` | 模型请求组装、草稿边界、迟到响应过期 | 只写草稿与证据引用 |
| `connectivity.py` | 四类连接自检、错误分类、恢复周期 | 重试周期唯一实现处 |

应用用例层统一承担：**事务边界**（调用 `WorkspaceUnitOfWork`）、**编排顺序**、**重试策略**、**幂等键生成**。

**领域模型层**

| 子域 | 负责的对象与判定 |
| --- | --- |
| `project` | 本地项目编号、模块、依赖边、任务、交付、绑定；依赖图的传递与循环规则 |
| `planning` | 模板版本、检查内容与确认状态、规则版本、用例、冻结计划、档位与结论上限 |
| `execution` | 运行、步骤、尝试、断言结果、暂停／取消状态机、源码快照与检查有效性 |
| `evidence` | 证据定位、链路节点与缺口、Mock 声明、真实／Mock／混合／未知判定、独立核验结论 |
| `review` | 报告快照与统计判定、唯一问题记录与缺陷状态机、回归关联 |

领域层的共同约束：**纯计算**，无 I/O、无框架依赖；同一判定只有一处实现，供应用层、报告与面板共同读取。

**外部能力层**

| 模块 | 实现的端口 | 关键约束 |
| --- | --- | --- |

| `credentials.py` | `SecretPort` | 只解析引用，密钥正文不外泄 |

## 4 端口清单

端口定义位于 application/ports.py，实现由 bootstrap 注册。只冻结当期实际需要的合同；后续期次不以空接口制造提前兼容承诺。

| 端口 | 用途 | 实现与期次 |

## 5 关键合同

- 计划确认、动作授权、结果复核独立；计划驱动不提前确认未来结果。
- full/quick/on_demand档位冻结；只有full派生证据等级。业务通过与证据充分性独立，A不表示业务成功。
- 当前结论键包含项目、源码身份、范围、环境、规则/验收/模板修订和判定策略版本；新完整运行不回退旧绿灯。
- 跨入口同一持久intent_id不重复执行，明确重跑创建新意图；传输重试不等于业务新执行。
- 源码物化强制、运行依赖隔离可选；按实际复制字节确认源码身份；venv不证明数据隔离或远端部署一致。
- 记录、证据引用和幂等结果同一提交可见。外部执行和网络请求不占事务；执行意图先保存。
- 恢复先核实活动执行器、抢救输出，再发布恢复记录，最后清理无活动引用的临时材料。
- 永久保留业务记录、证据、报告、导出和诊断，不设保留期、不自动删除、不提供删除入口。临时材料沿既定回收例外处理。
- 复用、流式读取和按需投影避免重复工作；超时用于发现失联、取消和结果未知。

## 6 运行形态

一个核心进程管理一个用户数据工作空间，持操作系统排他锁。Trae、面板、CLI和MCP relay共用核心；第二入口连接现有核心或报WORKSPACE_IN_USE，不启动第二写入者。Windows使用受当前用户/登录会话限制的命名管道；二期用平台本地IPC适配。

一期先用串行调度完成全部已承诺功能；隔离无依赖步骤可后续增加并行。若启用并行，控制和计划修订在并行组共同边界生效，共享写环境仍串行。关闭编辑器不等于业务取消。

三期发送循环位于同一核心的可选组件，网络操作与本地执行通道分离，不引入独立Worker/数据库/消息队列。平台不可用、队列拒绝新提交不阻断本地保存与导出；未发送候选通过提交游标恢复。

### 运行形态与并发

| 形态 | 期次 | 进程 | 并发与隔离 |
| --- | --- | --- | --- |
| 本地 | 一期 | 一个核心进程管理一个文件工作空间；扩展、面板、CLI、MCP relay 复用 | 一个工作空间一个写锁；不同工作空间互不共享活动目录 |
| 多编辑器 | 二期 | 同上，入口增多 | 同一核心服务多个入口；面板与 CLI 不产生双写 |

## 7 安全与信任

被测代码、项目文档、日志和模型输出均为数据，不能追加执行入口、改变授权或关闭问题。命令只用已登记入口和参数数组；凭据按用途解析且不进入面板、MCP配置、日志或导出。只读源码、不可写数据目录与不受信任工作区分别处理。默认不在不受信任项目启用MCP配置。

脱敏底线不可关闭；日志、报告与上传使用投影，“原始输出”指经过落盘前凭据过滤的捕获流，后续投影仍须脱敏；过滤前凭据字节不得以原始证据名义落盘。其他允许保存的源内容只在受控本地引用。路径边界、项目归属、符号链接逃逸和对象摘要须校验。工作空间禁止同步盘/网络盘；未能确认文件系统语义时拒绝建立活动工作空间并给出迁移位置提示。

### 安全与数据保护

| 主题 | 约定 |
| --- | --- |
| 密钥 | 只存凭据引用；插件配置及解析的凭据正文不进工作空间、日志、导出、面板与 MCP 响应；输出落盘前过滤与未知敏感值边界见一期执行分册“采集安全与原始证据语义” |
| 令牌 | 三期引入；按账号分区保存与清除，**退出只清令牌、不清除待发送材料**；`outbox` 材料不做应用层加密 |
| 导出 | 使用脱敏投影；原始源码对象仅本地受控保留 |
| 只读接入 | GitHub 只读：不改仓库、不发起测试、不处理合并冲突；**目录不是 Git 仓库时该接入整体不适用**，不建立连接 |
| 输入信任 | 项目文档、日志、代码注释与模型输出都是待分析内容，不能自动改变插件行为或增加工具 |
| 目录形态 | 绑定形态分 `git`（有版本库）与 `plain`（普通目录）；两者判定口径一致，`plain` 下以文件清单摘要代替提交标识，且不出现任何仓库字段 |
| AI 边界 | 只产出草稿与证据引用；不改断言、不关缺陷、不作出结论 |
| 溯源 | 每条记录带本地项目编号、来源、内容修订与时间；不同工作空间不串用 |

## 9 产品约束

本地执行与存储，可选模型出站；ModelOutboundPolicy与三期SendPolicy相互独立。显式代码分析可在Plan建立前通过SourceSnapshotPort进行，生成analysis快照，仅作草稿依据。AcceptanceScope冻结计划的验收范围并进入结论键；证据等级不以是否使用venv直接决定，EnvironmentFacts独立呈现。

新能力复用现有project/planning/review/collaboration用例，不增加服务：集中逐项ActionAuthorization、修复说明复制、报告筛选/隐藏偏好、Markdown摘要/证据包、冻结上传预览和覆盖状态。一期模板清单给出实际能力交付界限，未实现/未测试不能宣称支持。

## 10 技术基线与交付制品

以下为目标工程技术基线。精确依赖以实际工程锁文件及兼容验证为准，不在文档填未经实测的最新版本。

| 部分 | 基线与用途 | 制品/边界 |
| --- | --- | --- |
| 核心 | Python 3.13，pyproject.toml与src布局，uv.lock锁依赖 | 可安装核心包，提供aitest CLI；本地业务不依赖平台 |
| 输入/记录合同 | Pydantic 2做边界校验，记录含schema_version | 框架不进入纯领域计算；JSON Schema由合同定义生成 |
| 本地存储 | JSON/JSONL/Markdown、内容寻址附件、portalocker、同卷原子发布 | 单核心持锁；业务和证据永久留存，索引可重建 |
| 出站网络 | HTTPX及项目连接配置 | 适配器归一错误，connectivity统一重试策略，不各自循环 |
| 模型 | ModelProvider适配，DeepSeek可作默认配置方向 | 不硬编码未验证模型名；ModelOutboundPolicy约束发送 |
| 执行 | Python检查/既有命令、HTTP、独立核验、人工证据、智能体记录、外部导入 | 能力与模板以一期功能02为准，自动/人工/导入分开 |
| 面板 | TypeScript与共享原生Web Component；单一源码构建 | 由编辑器Webview承载，仅消费DTO；静态资源随包交付 |
| 编辑器 | Trae薄扩展，VSIX作为拟交付方式 | 选定Trae发行版的安装、命令、Webview与VSIX能力须实测，不假定其他编辑器API存在 |
| 本地工具 | MCP官方Python SDK与stdio relay | 转发到同一核心；没有远程Streamable HTTP服务 |
| 二期图件 | 包内静态渲染资源、自包含HTML导出 | 图是记录投影，不增加业务事实，不依赖外部CDN |
| 三期平台 | AccountPort/ResultSubmitterPort出站适配 | 平台提供会话/接收/查询合同；插件不交付ASGI宿主或接收服务 |

Python包、Trae扩展与面板制品记录各自版本/摘要及兼容关系。扩展不能捆绑一套不同业务规则；共享面板只构建一次再用于各宿主。发行前核对实际兼容组合，不把本表作为通过证据。

### 11.1 分包与唯一归属

1. 子域按变化原因划分，单文件足够的locations/diagrams不机械拆子包；图中每个叶子是职责落点，不要求预先创建全部文件。
2. domain与application尽量同名；账号对象在identity、上传对象在delivery、协作用例在collaboration是显式例外，不另建同义服务。
3. application/ports.py是协议唯一来源；基础设施可引用协议和纯数据类型，但不得导入应用用例。bootstrap是将实现交给用例的组装点。
4. contracts维护边界Schema，interfaces/dto.py负责投影；domain保持纯对象/规则。不能在三处独立维护同一业务判定。
5. projections.py与exports.py经端口注入；应用用例不能直接导入它们。新增ProjectionPort、ReportArtifactPort仅封装现已承诺的脱敏与导出I/O，不新增通用规则引擎。
6. permanent业务记录不设retention.py删除策略；maintenance.py只做空间/完整性、既定临时回收及备份迁移入口。应用recovery.py决定可恢复/待核实状态，file_store只执行文件提交和受控清理。
7. 面板共享代码只在resources/panel，宿主扩展不复制页面或状态机；resources/panel/dist与contracts/schemas属于生成产物。

### 11.2 代码目录不等于运行数据目录

真实记录放OS用户数据工作空间，不能写进安装包、被测源码或上述src目录。运行数据包含current/清单、不可变records/objects、spool、transactions、workdirs、diagnostics，三期增加outbox；布局与抢救顺序由[存储与恢复](一期/架构文档/04-存储与恢复.md)维护。上传文件和Git差异可能含敏感内容，源码树的examples只能放脱敏样例。

| 关注点 | 唯一归属 | 其他层的行为 |

## 13 端到端调用流程

### 调用规则

以「用户在面板点击运行 → 执行一个 L2 步骤并保存证据」为例，一次跨层调用经过六跳，每跳的职责边界固定：

1. **面板 → 接口层**：以 DTO 提交动作与参数；面板不组装业务命令，不判断能否执行。
2. **接口层 → 应用层**：校验参数结构、核对传输request_id、映射到用例方法；持久业务意图由应用层生成并登记；接口层不做业务判断。
3. **应用层 → 领域层**：读取计划与档位，调用判定器确认可执行与结论上限；领域层只返回结论，不发起 I/O。
4. **应用层 → 端口 → 适配器**：经 `ExecutionPort` 启动步骤；应用层不 import 具体适配器。
5. **适配器 → 外部系统**：在隔离环境执行命令或请求；采集输出与游标，不写业务记录。
6. **应用层 → 工作单元 → 文件后端**：把证据对象、记录与幂等记录在同一提交中落盘；成功后返回 DTO。

每跳都可独立替换：换编辑器只改第 1 跳；换执行方式只改第 4、5 跳；换存储实现只改第 6 跳；领域判定在三种情况下都不变。

### 本地测试闭环（一期主线）

```text
① 建立项目     入口 → 项目与计划用例 → 领域
                绑定本地目录与 Git 仓库，登记模块与依赖，生成源码快照
② 准备交付     模板 + AI 生成检查内容草稿 → 用户确认发布
                交付说明区分"开发自述完成"与"测试验证完成"
③ 确认计划     用例与必测项冻结；选定档位与驱动；派生结论上限
                计划生成确认未通过前不进入执行
④ 分层执行     runner 按依赖图调度 → ExecutionPort → 执行适配器
                L1 语法/构建/加载 · L2 模块与接口 · L3 端到端
                游标与句柄落检查点；失败/阻塞只影响依赖它的步骤
⑤ 采集证据     EvidenceRef + TraceNode + 独立核验
                证据按内容摘要存入对象库；脱敏投影供导出
⑥ 形成问题     领域判定 → 唯一 IssueRecord → 草稿待确认
                关闭必须有新的实际执行证据
⑦ 本地报告     报告快照（内容修订）→ Markdown 导出（脱敏）
                记录证据等级与主要缺口、必要追溯时间戳；档位决定结论上限
```

每一步结束时经 `WorkspaceUnitOfWork` 原子提交：记录、引用、幂等记录在同一提交中可见。

### 一次检查的数据流

```text
用户动作 → 接口层校验与投影 → 应用用例组装命令
        → 领域判定是否可执行（计划已确认、范围合法、档位上限）
        → ExecutionPort.start(request) → 适配器执行
        → 采集游标 → 输出块写入spool并核验后转为永久证据 → 原子提交
        → 领域计算断言结果与真实性 → 更新当前尝试
        → 报告投影 → 面板/CLI 读取 DTO
```

### 三期协作流程（平台具备后）

三期的三条要求沿用一期机制：提交不外带身份、判定不由上传改变、失败与取消同样保存。

### 13.1 一期本地流程

```text
Trae面板 / CLI / MCP relay
  → interfaces：结构校验、实例/绑定核对、动作路由
  → project/planning：最小配置、可选显式分析、草稿、范围与计划发布
  → prepare：固定源码/环境/计划，保存intent_id与payload_hash
  → authorize_step：逐项确认已解析动作输入（未知值待解析）
  → start：唯一创建Run，物化字节匹配冻结摘要
  → runner：保存Attempt意图 → 事务外执行 → 记录真实句柄
  → spool采集 → 工作单元发布证据/引用/游标
  → 领域判定业务结果、证据充分性与覆盖
  → 问题/回归 / 报告精确修订 / 独立本地复核
  → 投影/导出器生成摘要或证据包 → 应用登记导出 → DTO展示
```

新尝试/明确重跑保留原事实；执行结果未知先核实，不自动重放副作用。恢复先查真实进程身份、抢救输出、发布恢复记录，最后清理无活动引用的临时材料。环境事实独立，full只对已发布范围给完整结论。

### 13.2 二期展示与适配

新宿主上报能力→核心用例写CapabilityState→共享面板读DTO；定位从冻结记录出发，当前文件只在显式校验后哈希。图用实际业务节点ID投影，人工仅改布局/注释；重新布局不自动改报告。所有存储仍经同一工作单元，不增加第二写入者。

### 13.3 三期发送

```text
本地事实已提交
  → 按业务记录筛选DeliveryCandidate，与游标同事务登记
  → 核实账号/目标/SendPolicy（默认manual）
  → 白名单投影，冻结Submission/manifest_hash/业务证据覆盖
  → 预览与相同摘要确认；已批准自动策略按其边界发送
  → 事务外出站请求；未知先查原号，按原对象补缺
  → 完整回执核对，记录接收状态＋业务证据上传缺口
```

候选不订阅上传自身写入；本地保存不依赖发送成功。ACKNOWLEDGED不等于业务通过或全部原始证据齐全。退出、暂停、放弃、关闭自动同步保留材料和真实在途回执，各自语义见[三期功能](三期/功能文档/01-功能文档.md)。

## 17 复用、发送与迁移的模块职责

E/R/V与S/M由domain判定器唯一计算，复用引用存于现有Run/规划用例；报告与面板消费同一DTO。暂停控制、SendPolicy与单份SubmissionDeliveryGrant由现有delivery模块处理，只有明确放弃才AbandonDecision。已知缺口迁移由既有migrations/backup/maintenance处理，冻结A/G并验证无新增损失。上述修订不增加服务、数据库、消息队列或执行引擎；仍为25项功能、52项验收。

## 18 实现收敛与按需处理

物理工程树以第11节为唯一来源：面板为resources/panel/src下的shell/current_check等模块；模板为resources/templates/<template_id>/manifest.json及该模板的steps/issues/reports片段。其他分册只列其负责的子路径，不建立views/panel_shell或builtin业务分类的平行实现。locations负责位置解析，diagrams负责图投影；图导航调用位置动作，二者共享来源引用，不互相接管判定。

SourceControlPort按本地Git与可选GitHub分方法，SourceSnapshotPort负责实际源码内容固定/物化/目标哈希；plain完全不注册Git能力。安全采集、执行来源、依赖失效、核心生命周期、有限查询分别由相应一期分册主责，不为新增记录另建服务。界面和报告只消费同一判定结果。

首期按项目计划、执行证据、结论问题、基础设施、接口视图五个逻辑边界组织，仍为一个本地核心，不拆服务或通用事件溯源平台。按实际用例建立端口和仓储，不为每条记录机械创建完整服务层。Python与既有命令共享进程执行器；HTTP与核验共享受控传输但保持独立证据语义；人工/智能体/外部导入共享结构校验与证据保存。

首次实现采用串行步骤调度，保留依赖阻塞与运行修订；通用并行调度不作为首期前置。网络、模型、物化、投影和大对象摘要在短事务外处理，结果经唯一工作单元发布。已承诺首期能力不能因内部里程碑而省略。

列表读摘要分片，详情按引用读取，图按源修订按需投影；布局修订不自动刷新报告。同一导出键复用安全产物。普通启动检查活动和未完成材料，完整历史扫描仅由维护发起。三期一个有界本地发送循环复用connectivity，不新增独立Worker或消息队列；候选只存来源引用，冻结提交只生成一次安全投影。永久记录、证据和历史修订完整保留，不用清理历史换取轻量。

接口动作、统计字段、LocationDTO、提交协议分别由其主责分册定义，其他模块引用同一合同。效率验证核对实际触及的数据范围与重复处理，不设新的费用、资源预算或执行时限要求。

## 19 判定、查询与后台活性的统一合同

整用例E/R/V/P/F/U不变；当前有效决定性失败H由领域统一派生，H_S非空即failed并保留未完成范围，失败断言必须具有有效依据/核验/来源/依赖。ConfirmationRecord与冻结Case/依据修订派生effective_assertion_basis_state，原Case及报告不回写；DTO及报告字段以一期报告架构为准。

报告与历史控件使用一期存储架构的有限QuerySpec目录，报告状态明确business_outcome；二期四维16种掩码及两种源码范围只为现有筛选承诺服务，不开放任意查询。动作降级按实际核心、存储、执行及凭据依赖判断，核心不可用不承诺插件查询/新导出。

三期候选扫描固定高水位，经同事务维护的业务变更稀疏索引读取允许类型；无候选增量不提交纯游标，重启不回放纯上传/诊断尾部。发送使用持久总轮次和连续无进展周期，可信块确认偏移增长属于进展，HTTP成功本身不是进展；总轮次覆盖正常剩余块/控制请求加有限恢复额度。问题查询固定issues.list的14种掩码及OPEN/ALL范围，字段、索引与UI同步。无可推进任务允许核心收尾退出，不增加Worker或常驻服务。二期仅依赖图和链路图为必交，问题关联图仍为后续探索。
