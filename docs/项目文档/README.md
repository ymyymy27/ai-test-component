# 项目文档

本目录是产品合同层：按期次分（一期、二期、三期），每个期次内部按文档类型分六类。文档解释字段、状态、时序与验收预期；命令名与对外字段以 `src/aitest/models.py` 和注册表为准，冲突时以代码为准。验收结论只以 `tests/acceptance/p1/status.json`、`p2/status.json`、`p3/status.json` 为准。

## 1 期次与文档

| 期次 | 状态 | 目录 |
| --- | --- | --- |
| 一期 | 当前交付范围 | [一期](一期/README.md) |
| 二期 | 后置占位；未按轻量基线重写 | [二期](二期/README.md) |
| 三期 | 后置占位；平台合同未定 | [三期](三期/README.md) |

## 2 文档类型

每期使用相同的分类；二期、三期没有 `06-发布运维`，因为尚未实现。

| 类别 | 一期内容 | 回答什么 |
| --- | --- | --- |
| `01-项目` | 项目简报、技术评估、交付计划、遗留问题与风险 | 为什么做、范围、成本、交付与风险 |
| `02-需求` | 业务方案、需求规格、功能清单 | 角色与流程、FR/AC、判定与统计唯一口径 |
| `03-设计` | 产品方案与界面设计、CLI 与数据契约 | 页面、动作、字段、命令与交互状态 |
| `04-架构` | 架构总览与分册 | 形态、依赖方向、进程模型、模块划分与一次运行的调用链 |
| `05-测试验收` | 测试计划、验收台账 | 怎么验、每条 AC 的状态 |
| `06-发布运维` | 发布方案、恢复预案、安装操作、运维手册、效果检测 | 怎么发、怎么回、怎么用、怎么排障 |

## 4 维护约定

- 新增或修改合同，先改对应期次的 `02-需求` 或 `04-架构`，再同步 `03-设计`、`05-测试验收`。
- 验收状态只登记在 `tests/acceptance/{p1,p2,p3}/status.json`；文档不另写一套状态数字。
- 文档分类与编号可以调整，调整后同步各期 `README.md` 与相关链接。
- 二期、三期当前只保留后置场景骨架；平台合同与新增宿主确定后，按轻量基线重写后再作为实现依据。
