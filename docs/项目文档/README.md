## 3 编号与职责

功能编号采用P1/P2/P3-FR，验收编号采用P1/P2/P3-AC。一期包含17项功能、35项验收，二期包含6项功能、9项验收，三期包含2项功能、8项验收。

需求文档定义范围与验收；功能文档定义输入、操作、输出与业务规则；架构文档定义模块、数据、接口与恢复机制；设计文档定义页面、字段、动作和交互状态。各入口和界面消费同一核心规则，不自行计算另一套结论。

## 4 文档整改与实现验证状态

现行文档的范围和编号保持25项FR、52条AC；安全采集、执行来源、依赖聚合、定位、生命周期、有限查询及上传预览的主责入口见[阅读索引](阅读索引.md#5-边界合同主责与维护)。[2026-09-23整改记录](../../一致性与轻量化整改记录-2026-09-23.md)列出修改、备份及静态验证结果。根目录评审报告保留为整改前基线，不把旧问题位置当现行行号。

文档修订不代表软件已经实现或验收。真实Trae/新增宿主、操作系统、命令执行来源、凭据过滤、提交/恢复/掉电与平台回执对拍，均须用实际版本、输入和证据登记结果；未执行保持未验证。
