# 项目简报（一期）

> 期次：一期；状态：轻量插件重构中，未验收；主责：范围与目标对齐。
> 事实基准：本页只做干系人对齐，不定义字段、判定口径或验收标准；执行基线见[轻量 Trae 插件修改计划](../../../修改日志/ymy/2026-11-16-轻量Trae插件重构计划.md)。

## 1 背景

在 Trae 里做本地自测，常见四个问题：

- 模块合并后不清楚依赖关系，不知道该回归什么；
- Mock 或“假成功”掩盖真实业务结果；
- 失败缺可复现证据与版本，修复和回归对不上；
- AI 的判断与实际执行事实混在一起，分不清“能跑”“模块对”“业务通”。

## 2 定位

**Trae 里的轻量 AI 测试插件**：扩展负责界面与命令，本地 Python CLI 负责执行与数据，文件工作空间保存记录。

不是系统：不常驻、不建数据库、不做提交引擎/迁移框架/许可账本/证据等级，也不做账号、上传与共享审核。

## 3 目标用户

- 在 Trae 里开发、需要自测或提测前验证的开发者；
- 需要快速拿到分层结果、证据与问题清单的测试人员；
- 需要看懂“这次测了什么、结果如何、哪里没测”的项目负责人。

## 4 一期范围

18 FR，完整清单见[需求规格](../02-需求/02-需求规格.md)：

- 项目与模块、目标候选、任务与验收项、交付说明、规则与模板；
- 范围选择、计划与用例、L1/L2/L3 执行；
- Mock 判定、证据、问题与回归、报告与导出；
- Trae 接入、环境诊断与修复；
- GitHub 只读、链路采集与定位、备份恢复、AI 失败分析。

验收场景 26 条，状态登记在 `tests/acceptance/p1/status.json`。

## 5 不在一期

- 常驻核心、命名管道、数据库、迁移与许可；
- 账号、上传、共享审核、平台接收端；
- 自动影响分析与回归推荐（二期）；
- 智能体入口 L3、其他编辑器与操作系统（后置）。

## 6 成功标准

1. 正常路径上人只做三件事：选目录、给目标、执行前确认；
2. 从选目录到导出报告可完整走通，证据可复查；
3. 模型、GitHub、链路不可用时，本地测试与导出仍可用；
4. 未执行、未知、阻塞如实显示，不写成通过；
5. 真实 Trae 与试点项目验收有证据。

## 7 约束

- Windows 11 x64、Python 3.11+、Trae；
- 模型 API 必需；GitHub 与链路是一期必需薄适配器；
- 数据保存在用户级工作空间，项目仓库内不留插件数据；
- 凭据不落盘、不进日志与导出。
