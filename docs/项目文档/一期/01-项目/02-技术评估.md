## 1 评估范围与方法

- **对象**：一期轻量 Trae 插件，即“扩展 + 本地 Python CLI + 用户级文件工作空间”。
- **依据**：执行基线为[轻量 Trae 插件重构计划](../../../修改日志/ymy/2026-11-16-轻量Trae插件重构计划.md)；契约见[CLI 与数据契约](../03-设计/03-CLI与数据契约.md)；代码事实取 `src/aitest/`、`integrations/trae/`、`tests/` 与 `pyproject.toml`。
- **能估的**：技术栈、模块相对复杂度、外部依赖、失败时的阻塞点。
- **不能估的**：人天、日历工期与成本；本册不给日期承诺。
- **不评估**：单个 FR 的字段与状态机、二期/三期实现、任意框架的零配置适配。
- **方法**：只引用可核对事实（模块数、行数、测试节点、命令与依赖），相对复杂度是判断而非测量值。

## 2 技术栈

| 层 | 选型 | 用途 | 现状 |
| --- | --- | --- | --- |
| 语言 | Python 3.11+ | CLI、worker、领域规则、适配器 | 验证 3.11/3.13；3.14 未验证 |
| 数据模型 | pydantic 2.x | 文件模型、枚举、字段校验 | 已用于 `models.py` |
| 文件锁 | portalocker 3.x | 工作空间短锁 | 已用于 `storage/workspace.py` |
| 构建 | hatchling + uv | wheel、sdist | `pyproject.toml` 已配置 |
| 宿主扩展 | TypeScript + esbuild | 命令、面板桥、运行环境发现 | `integrations/trae/` |
| 扩展打包 | vsce | VSIX | `npm run package` |
| 面板 | Webview（共享面板源码） | 项目/计划/运行/证据/报告 | 面板存在；`2026-11-17-trae-panel/` 与 `2026-11-17-trae-panel-v2/` 两个真实 Trae 证据目录覆盖目标选择、结果、调整范围、报告、计划文档、历史、问题与设置 |
| 测试 | pytest + node:test + Vitest | 单元、合同、集成、扩展、面板 | 节点数由 `scripts/check_docs_facts.py` 与入口 README 核对，具体数以最近一次全量 pytest 输出为准 |

不引入额外存储服务、消息队列、常驻进程、索引或迁移框架。这是形态约束，不是当前实现进度。

## 3 运行形态

```text
Trae 扩展（UI / 命令）
   │  JSON over stdio（每次命令一个新进程）
   ▼
Python CLI（进程结束即退出）
   ├─ core        范围、结论、计数、Mock 与问题规则
   ├─ storage     工作空间、原子写、锁、证据、zip 备份
   ├─ runners     pytest/命令、HTTP、Playwright、人工
   └─ adapters    模型、GitHub、链路
        │
        ▼
用户级工作空间（JSON / Markdown / 证据 / zip）
```

- 没有常驻进程、进程间管道或后台服务；长任务由一次性 worker 承担，运行结束即退出。
- 扩展不直接读写业务文件，所有写入走 CLI，锁与原子写集中在一处。
- 业务结论由 core 派生，扩展与适配器只展示或返回结果，不重算。
- 工作空间位于用户数据目录，项目仓库内不留插件数据。

## 4 外部依赖

| 依赖 | 是否必需 | 用在哪 | 不可用时 |
| --- | --- | --- | --- |
| 模型 API（DeepSeek 兼容 HTTP） | 必需 | 目标候选、验收项、计划、脚本、Mock、分析、摘要 | AI 步骤标未生成；测试、证据、报告继续 |
| `gh` CLI | GitHub 只读所必需 | 提交、PR、检查、部署版本 | 关联标缺口；本地测试不受影响 |
| 链路日志与只读查询命令 | 链路所必需 | 请求 ID、日志、模块、DB 结果 | 写 `gaps`；不阻塞用例 |
| Python 3.11+ | 必需 | CLI 与 worker | 扩展提示缺项，不启动业务命令 |
| Node/npm | 仅构建期 | 面板与 VSIX | 不影响已安装插件运行 |

- 模型密钥只从环境变量或用户级配置读取，不进入工作空间、日志、证据与导出。
- GitHub 复用 `gh` 登录态，插件不保存 token；只发 GET，不写 GitHub。
- 链路只导入已有证据，不插桩、不接 APM、不内置查询驱动。

## 6 主要风险与取舍

| 风险 | 取舍 | 控制 |
| --- | --- | --- |
| 文件存储查询变慢 | 不引额外存储，按目录直接列 | 数据量小；真到瓶颈先分页/缓存 |
| 多入口并发写坏文件 | 只允许一个 CLI 写业务文件 | 短锁 + 原子写；运行目录由 worker 独占 |
| 后台服务把安装变重 | 每次命令一个进程，运行一个 worker | 锁与心跳接管；不引入常驻服务 |
| 模型不可用导致主流程停摆 | AI 是必需依赖，但只影响 AI 步骤 | 失败标未生成；本地记录与报告继续 |
| AI 生成脚本有破坏性 | 生成到运行目录，不写仓库 | 危险操作扫描；执行前确认；失败保留脚本 |
| 证据体积失控 | 永久保留，不自动删除 | 单文件 20MB 截断；媒体软上限 500MB |
| Trae 版本差异 | 只承诺一期 Trae | 面板主路径已在 Trae CN 1.107.1 验证；其他版本与其他宿主未验 |
| 运行环境准备缺失 | 先发现已有 Python，不静默换解释器 | 已实现便携运行时下载与离线 wheel 安装；真实宿主未验证 |

## 7 未验证边界

- 真实 Trae 的安装、激活与项目绑定尚无逐项记录；面板主路径（目标选择、生成计划、执行前确认、运行、结果、报告、历史、问题、设置）已有两个真实 Trae 证据目录。
- 导出、错误态、轮询异常与关闭问题等宿主动作链没有真实宿主实测。
- 面板主路径之外的失败路径（默认工作空间目录不可写、Python 缺失、模型未配置、取消与恢复）未在真实 Trae 中逐项验证。
- AI 生成测试脚本、Mock 判定的依据与预算控制未在真实项目上验证。
- 链路导入已用真实日志文件与只读查询命令取得 `real_cli` 证据（P1-AC27）；GitHub 只读关联的真实账号与私有仓库成功路径未验证。
- 大项目性能、证据体积与中断恢复只有代码路径，没有压测或故障注入报告。
- Python 自动准备（下载便携运行时、离线安装 wheel）已在 `runtime.ts` 实现，但未在干净机器与真实 Trae 上验证。

## 8 结论

技术路线与形态约束一致：依赖少、安装轻、数据可直接查看与备份。当前主要不确定性不在技术选型，而在完整宿主闭环、试点项目、GitHub 成功路径与真实宿主备份恢复的验收证据；面板主路径、链路与备份恢复已有真实证据，但在上述缺口补齐前，本册不把完整闭环写成“已通过”。
