# 技术评估（一期）

> 期次：一期；主责：技术路线、规模与资源依赖；状态：评估基于 2026-11-12 代码事实

本册回答三件事：技术路线选了哪条、现有规模多大、跑起来依赖什么。它不定义判定口径、不复制字段合同、不做工期承诺；功能行为见[功能清单](../02-需求/03-功能清单.md)，范围与验收预期见[需求规格](../02-需求/02-需求规格.md)，当前状态与问题以[项目现状](../../../现状.md)为准。

## 1 评估范围与方法

- **评估对象**：一期（P1-FR01—17 / P1-AC01—35），即当前唯一交付范围。二期、三期不在本次评估范围。
- **事实来源**：规模与门禁取[项目现状](../../../现状.md)第 4 节（标注 2026-11-12）；能力现状取同页第 3、6、7、10 节；分层、端口、模块与工程树取[总体架构](../04-架构/01-架构总览.md)第 2—4、6、10、11 节；能力与适配器取[能力与模板清单](../02-需求/03-功能清单.md)；交付依赖链取[一期架构总览](../04-架构/01-架构总览.md)；工程配置取 `pyproject.toml`、`.github/workflows/ci.yml`、`src/aitest/` 目录结构与两个 `package.json`。
- **能估的**：技术路线、模块相对复杂度、外部与工具依赖、缺依赖时阻塞到哪一步。
- **不能估的**：人天、日历工期、成本。原因见第 4 节，不由本册补推定。
- **不评估的内容**：单个 FR 的字段与状态机（属功能分册与架构分册）、验收预期（属需求规格第 6 节）、二期与三期实现。
- **方法**：只引用可核对事实（模块数、行数、测试节点、可派发动作数、合同版本、模板与适配器个数），不按模块拆分重算行数；相对复杂度是判断，不是测量值。

## 2 技术路线

**分层与依赖方向。** 入口 → 接口适配 → 应用用例 → 领域规则，单向向下：入口只提交命令、读 DTO，不写业务文件、不持密钥；判定、覆盖、证据等级、复用资格与问题关闭只在领域层计算一次；应用用例经端口访问外部能力，`bootstrap.py` 注入实现。入口包括 Trae 扩展、共享面板、CLI 与 stdio MCP relay，四者使用同一批动作、同一 DTO 与同一错误结构。

**核心与存储。** 一个用户数据工作空间由一个核心进程持排他写锁；第二入口连接现有核心或报工作空间占用，不启动第二写入者。业务变更由工作单元提交不可变记录、引用、索引与幂等结果，外部执行与网络调用在事务外。存储形态是本地 JSON／JSONL／Markdown 加内容寻址附件，同卷原子发布，索引可重建。

**宿主接入。** Trae 侧是薄扩展（VSIX）加共享原生 Web Component 面板，面板只有一份源码、只消费 DTO。本地通道为命名管道与同进程 API，MCP 走 stdio 转发到同一核心。宿主、面板与 CLI 不得各自重算结论。

**本地优先。** 无本地 HTTP 服务、无数据库、无消息队列、无独立发送 Worker；一期不登录、不上传、不跨账号协作。模型是客户端发起的可选出站能力，被测 HTTP／数据核验属已登记环境访问。

**已否决的方案。** 不部署服务端与账号体系；不做自动操作录制回放；不做远程 Streamable HTTP MCP；不为六个模板各建一套执行引擎；不为每条记录机械复制一套服务层；不允许第二个写入者或插件侧接收服务。

**未纳入本次评估。** 二期（多编辑器、多系统、源码定位、依赖与链路图）与三期（账号关联、结果上传与回执）只有合同草案，仓库无可执行实现。

关键选择及其代价如下；代价是所选方案自带的约束，不是待修缺陷。

| 技术选择 | 具体做法 | 换来什么 | 自带的代价 |
| --- | --- | --- | --- |
| 单核心排他写锁 | 一个工作空间一个核心进程，第二入口连接或报占用 | 无并发双写，记录与幂等结果同源 | 多入口依赖核心存活；重启须受控并核对活动执行 |
| 不可变记录 | 改动一律产生新修订，索引可重建 | 历史与证据可追溯，报告不原地覆盖 | 存储只增不减，读取须按修订与引用 |
| 端口注入 | 外部能力只在 `application/ports.py` 定义，`bootstrap.py` 装配 | 新增外部系统只加适配器，应用层不反向依赖 | 端口与 DTO 变更须同步六主题合同与生成 Schema |
| 共享面板单一源码 | 面板只构建一次，各宿主承载同一 Web Component | 判定与呈现不分叉，避免第二套规则 | 宿主能力差异只能在面板内降级，不能靠分叉绕过 |
| stdio MCP relay | 转发到同一核心，不开放 HTTP 服务 | 无需监听端口、无远程攻击面 | 长动作只能返回引用，调用方须按 `run_id` 续读 |
| 本地文件存储 | JSON／JSONL／Markdown 加内容寻址附件 | 无数据库与运维依赖，用户可直接备份 | 大项目读取须做有限查询与摘要投影，不能整库扫描 |

## 3 模块与规模

`src/aitest` 共 **310** 个模块 / **93,788** 行；测试 **407** 个 Python 文件 / **95208** 行，收集 **6,075** 个节点；默认可派发动作 **68** 项；`mypy` strict 覆盖 325 文件通过；六主题合同为 CORE-001 1.96、AB-001 1.51、BC-001 0.55、CD-001 1.29、AC-001 1.10、BD-001 0.12，均 frozen / fixture_passed。以上数字全部取自[项目现状](../../../现状.md)第 4 节（2026-11-12），本册不重算、不拆分。

| 模块 | 职责 | 规模事实（可核对） | 复杂度判断 |
| --- | --- | --- | --- |
| 核心与存储 `infrastructure/file_store` | 单写、不可变提交、对象、索引、事件、备份与迁移 | 计入 310 模块 / 93,788 行总量；本模块行数未单独统计 | 高：恢复与迁移合同最密，另有独立故障注入目录 |
| 领域规则 `domain/` | 项目／计划／执行／证据／报告／问题的纯判定 | 同上；纯计算、无 I/O | 高：判定、覆盖、等级、关闭各只有一处实现，直接绑定 35 项 AC |
| 应用用例 `application/` | 编排、事务边界、授权、幂等、恢复 | 同上；外部能力集中在 `ports.py` | 高：跨入口幂等与"事务外执行"是主要约束 |
| 执行适配器 `infrastructure/adapters/execution/` | 命令、Python、HTTP、独立核验等执行方式 | 7 个适配器（总体架构第 3 节） | 中高：共用调度、授权、采集与落盘前过滤 |
| 接口与工具 | 同进程 API、命名管道、DTO 投影、CLI、stdio relay | 默认可派发动作 65 项 | 中：只做校验、路由、投影，不重算判定 |
| 面板与 Trae 扩展 | 共享面板 Web Component、薄扩展宿主 | 面板与扩展各一个 npm 包；面板单一源码 | 中高：真实宿主兼容与人工确认链路未验收 |
| 测试与验收资产 | 合同、架构、恢复、验收、单元与集成 | 407 文件 / 95208 行 / 6,075 节点 | 高：测试行数高于产品行数，成本重心在契约与真实验收 |

规模判断：产品代码已接近十万行、测试代码超过产品代码，一期的主要成本不是"再写多少功能"，而是把已有能力逐项做成可核对证据。测试侧另有两条口径须分开读：`tests/unit` 与 `tests/integration` 当前收集 5,758 个节点；2026-11-11 的全量为 6,104 节点（6,101 passed / 3 skipped / 0 failed，`-n 8 --dist loadfile`，1:14:58，退出 0），该结果只证明组件与集成层，不替代真实宿主与 AC 验收。收集数、分块结果与历史全量都不能顶替当前全量。

## 4 工作量与时间

本册**无法给出人天估算**，原因有三：仓库没有可靠的工时或人天记录，任何数字都只能是编造；[需求规格](../02-需求/02-需求规格.md)第 3.2 节明确"合同不设定总执行时限，也不以工期推定完成"，待定事项第 5 条进一步要求工期须另立条款；剩余工作以真实验收为主，单项 AC 的成本取决于现场发现多少缺陷——2026-11-12 的真实执行就在过程中修掉 4 个判定／证据缺陷，这类工作量在事前不可枚举。

| 工作块 | 已落地事实 | 复杂度 | 主要未知 |
| --- | --- | --- | --- |
| 核心与存储 | 唯一核心、排他锁、不可变提交、索引重建、备份／迁移入口已接 | 高 | 物理掉电、未知活动执行、迁移中途与跨核心重启 |
| 执行 | 命令／Python／HTTP 执行、L1／L2／L3、暂停恢复取消、重试退回补证 | 高 | 真实 Trae 全步骤、退出与强杀、editable／PYTHONPATH |
| 判定与报告 | 业务结论、证据等级、覆盖与缺口、报告修订、复核、导出 | 高 | 真实业务端到端、C-17 真实复用、权威证据完整性 |
| 面板 | 流程优先面板：向导、工作台、报告／问题、规则、诊断 | 中高 | 完整 AI 计划／执行／核验／报告／提测、主题与缩放、webview 焦点 |
| Trae 接入 | 薄扩展与 VSIX，隔离 profile 中启动并连接核心 | 中 | 宿主版本兼容、退出拦截、CPU／内存与读取超时 |
| CLI／MCP | 同核心 dispatch、doctor、ensure-core／restart-core、只读 read_view | 中 | 逐动作能力对拍、宿主上下文与迟到回执 |
| 验收登记 | 17 FR／35 AC；当前 4 verified / 5 not_verified / 1 blocked / 25 untested | 高 | 每项都需真实输入、软件版本与证据路径 |

可给出的只有相对量级：核心与存储、判定、验收三块复杂度最高；面板与 Trae 接入的剩余量集中在真实宿主；CLI／MCP 的剩余量集中在逐动作对拍。排期依据以[项目现状](../../../现状.md)第 8 节的六步主线为准，每步留下真实证据后才能估下一段。

要形成可信估算，至少还需要三类数据，目前都不存在：每个工作块的明确完成清单与真实剩余项；真实执行中暴露的缺陷密度（首轮真实执行常伴随判定缺陷修正）；宿主侧重试与故障恢复的实际次数。补齐后再按单位工作的实际耗时折算，才能得到有区间的排期；在本册直接写人天只会得到无法核对的数字。

## 6 能力缺口与前置条件

- **六个模板**：`src/aitest/resources/templates/` 下有 python-library、python-service、http-workflow、manual-web-workflow、agent-workflow、ticket-workflow 六个目录。能力只有在"适配器 + 模板 + AC 证据"三者齐备时才可标支持；每个模板还缺真实可执行成功样例、证据不足样例与不支持输入样例，缺任何一类，AC17／24／30 就不能成立。
- **适配器**：缺真实服务或页面登记时，对应模板保持"尚不支持/缺口"，不能写成不适用；静态 Mock 候选只作疑点，不证明真实或 Mock。
- **模型（可选但已成为计划链单点）**：关闭模型或模型失败时，人工证据、规则编辑、报告与导出仍可用；但 2026-11-14 已删除面板"改用手工四项检查"入口，计划只走 AI 提案，因此无可信端点／凭据／策略时"生成计划"明确阻塞。这是当前链路上最硬的前置条件。
- **测试执行前置**：工作空间环境必须含 pytest；此前真实宿主曾因 setup 环境无 pytest 而阻塞，环境准备属于首次向导的必过步骤。
- **真实 Trae**：缺当前构建的 VSIX 安装、宿主身份核对与隔离 profile 复装，真实全流程与故障恢复就没有证据，只能保持未验证。
- **平台与数据库**：一期对平台零依赖；数据库不属于一期要求，C-03 的剩余项不含数据库。

## 7 主要技术风险

| 风险 | 触发 | 影响 | 缓解 |
| --- | --- | --- | --- |
| 真实 Trae 全流程未验收 | 宿主版本变化、CPU／内存与读取超时、webview 焦点 | 交付不能承诺，面板链路只有局部证据 | 隔离 profile 重装当前构建，按 AC 逐项留输入、版本与证据 |
| 恢复与迁移未闭环 | 物理掉电、未知活动执行、迁移中途、跨核心重启 | 可能留下中间态或重复写 | 故障注入目录固定用例；未知副作用不自动重放；先核实再发布 |
| 来源与环境事实不可核对 | editable／PYTHONPATH、宿主退出或强杀、依赖探测失败 | 结论依据不可信，证据等级虚高 | 运行时观察写回；来源无法证实时保留"待核实"；探测失败不授予复用 |
| 真实复用资格被误授 | 目标依赖探测失败、旧记录、跨运行继承 | 把复用当成本轮执行，抬高通过面 | 探测失败仍为 `None`；`E∩R=∅`；新 Attempt 撤销旧复用资格 |
| 全量回归耗时长 | 6,075 节点、本机需数小时 | 回归不完整却被称为通过 | 分块覆盖被改动路径；nightly 跑全量；不以收集数代替通过 |
| 模型不可用即无法生成计划 | 端点或凭据失效、策略变更、限额 | 新项目停在计划阶段 | 阻塞提示写清原因与处理方向；已保存提案与本地能力不受影响 |
| 六模板缺真实业务样例 | 无真实服务、页面或智能体采集 | 能力只能标未验证，验收口径落空 | 逐模板提供成功、证据不足、不支持三类样例，版本写入兼容清单 |
| 宿主兼容差异 | 非 Trae 宿主或不同 Trae 版本 | 面板命令、确认窗口与退出拦截行为不同 | 一期只承诺 Trae；其他组合留待二期实测，不用推断代替 |
| 敏感材料随证据外泄 | 未识别敏感值、过滤前字节被当成原始证据、导出未走投影 | 泄露凭据，或证据整体不可用 | 落盘前过滤、导出走脱敏投影；无法安全处理的材料登记缺口 |

以上与[项目现状](../../../现状.md)第 7 节的八项未验证边界对应，另补一条采集安全风险；第 6 节 27 项开放问题中没有任何一项因本册的存在而关闭。

## 8 结论与不做的事

- **技术路线成立**：本地唯一核心、端口隔离、共享面板、stdio MCP、无服务端的选择已经落到可运行实现（310 模块 / 93,788 行、68 个可派发动作、六主题合同冻结），不存在待定的架构选型；三期平台合同除外。
- **风险重心在验收而非设计**：当前 35 项 AC 只有 4 项 verified，其余为 not_verified、blocked 或 untested。能否交付取决于真实宿主、真实业务、故障恢复与跨机证据，不取决于新增模块。
- **不给工期**：没有可靠工时记录，需求规格也不设总执行时限；先按六步主线推进并留证，再谈日期。文档一致、单元与合同通过、组件级真实进程通过，都不能写成完成。
- **不做的事**：不部署服务端、不登录、不上传结果；不引入本地 HTTP 服务、数据库、消息队列或独立发送 Worker；不做录制回放、可视化流程绘制、任意语言插桩与跨语言静态影响分析；不启动第二个写入者；不为六个模板各建执行引擎；不在一期实现二期／三期能力，也不为其预建空模块。
