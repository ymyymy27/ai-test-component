本文包含**问题清单**和**风险登记册**。问题清单记录具体缺陷、待确认事项和验证缺口；风险登记册记录“哪些失败模式会让未验证能力被当成通过、让证据失效，或让返工范围扩大”。单条场景的结论、阻塞与未验证原因仍只登记在[tests/acceptance/p1/status.json](../../../../tests/acceptance/p1/status.json)。

## 1 口径

| 项 | 规则 |
| --- | --- |
| 验收登记 | 只认 `status.json` 的 `result` 与 `evidence.path`；`verified` 必须同时有非空证据与真实环境标记 |
| 代码事实 | 命令、字段、状态、限制回读 `src/aitest/` 与 `integrations/trae/`；文档冲突以代码为准 |
| 触发信号 | 可观测事实：登记变化、命令失败、真实操作失败、证据缺失，不写“感觉有风险” |
| 更新方式 | 风险不因单测或夹具通过而降级；关闭须给出证据位置并同步登记 |
| 编号 | `R-nn` 只在本文件内稳定，不与 FR/AC 编号混用 |

风险等级按“影响面 × 可发现性”粗分：**高** = 可能让未验证能力被当成通过；**中** = 会让返工扩大或证据不可用；**低** = 有替代路径但需人工处置。

## 4 重点风险说明

### R-01 真实 Trae 完整闭环未验收

- **为什么高**：安装、绑定、导出与恢复是产品主路径的宿主侧事实；CLI 能跑不能替代宿主记录。面板主路径已走通，但导出与逐项安装/绑定记录仍缺。
- **当前能确认的**：扩展有 `aitest.openPanel`、`aitest.checkEnvironment`、`aitest.runStatus` 三个命令；bridge 每次调用一个 CLI 进程；未设置 `aitest.workspacePath` 时使用默认工作空间目录；Trae CN 1.107.1 上面板主路径已走通（新增项目、目标选择、生成计划、执行前确认、运行、结果、报告）。
- **不能确认的**：其他 Trae 版本兼容、Webview 焦点、运行中轮询异常、导出路径、宿主内备份恢复、逐项安装与绑定记录。
- **关闭条件**：同一提交构建的 VSIX 在目标 Trae 安装并激活；完整闭环每步有宿主侧证据；证据路径写入 `status.json`。

### R-02 宿主动作链仍不完整

- 面板只消费 CLI 输出，不重算结论；这条设计降低了“第二套判定”的风险。真实 Trae 主路径已经走通，但主路径之外的宿主动作仍缺证据。
- 已覆盖：真实 Trae 中新增项目、目标选择、生成计划、执行前确认、运行、结果、调整范围、报告、历史、问题与设置。
- 需要覆盖：导出、错误态（默认工作空间目录不可写、Python 缺失、模型未配置）、运行中轮询异常、取消失败、关闭问题、宿主内备份与恢复。
- 关闭条件：上述状态各至少一次真实宿主记录；失败时面板显示错误码与下一步，而不是空白或“成功”。

### R-03 AI 生成脚本与 Mock 判定的试点缺口

- 生成脚本放在 `runs/<run_id>/generated/`，不写被测仓库；执行前扫描 `rm -rf`、`DROP TABLE`、`git push` 等危险操作。
- 脚本自身语法/导入错误应标 `blocked` 或 `error`，不能算产品失败；缺依赖需在执行确认页列出。
- Mock 判定必须带文件路径与行号或证据引用；给不出依据只能 `unknown`，`unknown` 不能获得“真实链路通过”。
- 关闭条件：真实项目上各完成一次“有依据判定、无依据判定、超预算、模型不可用”记录。

### R-04 GitHub 成功路径与链路生产数据未验收

- GitHub 只读、只发 GET、不保存 token；`gh` 缺失或未登录要显示缺口，不能用缓存冒充最新。
- 链路只导入配置的日志与只读查询结果；请求 ID 缺失、日志找不到、DB 无结果都要写 `gaps`。
- 关闭条件：一个真实私有仓库、一份真实 JSON lines 日志、一次只读查询，成功与失败路径各留证据。

### R-05 大项目性能

- 现有设计按验收项选范围、后台执行、证据按文件引用，避免全仓扫描；但没有压测。
- 观测项：用例数、单次运行时长、面板轮询延迟、证据总量、磁盘占用。
- 超边界时提示“范围过大/证据超限”，不假装能测；真到瓶颈先分页或缓存，不引额外存储。

### R-06 证据体积

- 单文件超过 20MB 截断并写“原始大小”；单次运行媒体软上限 500MB；失败用例证据不降级。
- 历史运行不自动删除；磁盘不足时停止写入并报错，不驱逐已有证据。
- 关闭条件：制造一次截断、一次软上限、一次磁盘不足，核对报告与错误码。

## 5 观察、升级与关闭

| 动作 | 条件 | 落点 |

| 升级为阻塞 | 真实环境已出现，且影响 AC 结论 | 先改 `status.json`，再改交付计划与本文 |

| 关闭 | 证据路径非空且真实环境已验证 | 同步 `status.json` 与交付说明 |

- 风险不因“代码已写”关闭；只认真实输入、真实环境与可定位证据。
- 同一风险连续两个批次未处置，在提交说明与验证批次里点名，不沉默积累。
