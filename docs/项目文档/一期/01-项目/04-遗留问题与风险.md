# 遗留问题与风险

本文是**风险登记册**，不是问题清单。单个缺陷、缺失能力与关闭条件仍登记在 `docs/现状.md` 与 `tests/acceptance/p1/status.json`；本文不复制那批明细，也不另立第二套编号。这里只回答：哪些风险会让“已完成”判断失真、用什么信号能提前发现、现在有什么代码或台账依据、下一步怎么处置。

## 1 口径

| 项 | 规则 |
| --- | --- |
| 问题明细 | 以 `docs/现状.md` 第 6 节与 `tests/acceptance/p1/status.json` 为准；本文只做风险归并 |
| 验收登记 | 只认 `status.json` 的 `result` 与 `evidence.path`；`verified` 必须同时有非空证据路径与真实环境验证 |
| 代码事实 | 字段、动作名、命令、超时、白名单一律回读 `src/aitest/` 与 `integrations/trae/`；与文档冲突按代码 |
| 触发信号 | 可观测的事实（台账变化、回归红灯、真实操作失败），不是“感觉有风险” |
| 更新方式 | 风险不因新增单测或夹具通过而降级；关闭需给出依据位置，并同步回 `status.json` 或现状页 |
| 编号 | `R-nn` 只在本文件内稳定，不与 A/B/C/D 包编号或 AC 编号混用 |

风险等级按“影响面 × 可发现性”粗分：**高**＝可能让未验证能力被当成通过；**中**＝会让返工范围扩大或证据不可用；**低**＝有替代路径但需人工处置。

本文的“当前事实”列都可回查：给的是文件名与符号名，不是转述。文件内不出现版本段落，版本与提交以台账和验证记录为准。

分工上保持三份材料各司其职：

- `tests/acceptance/p1/status.json`：机器台账，管“每条 AC 现在是什么结论、证据在哪”。
- `docs/现状.md`：唯一问题清单，管“哪一块能力还缺什么、关闭条件是什么”。
- 本文：管“哪些失败模式会同时污染多个 AC 或让证据失效”，因此只写跨条目风险。

出现下列情况才新增风险项：同一失败模式可能命中两条以上 AC；某类证据天然不可复现（掉电、跨机、真实宿主）；某个契约尚无代码落点（如平台合同、兼容清单）；文档与代码已经出现事实冲突。单个功能没做完不在此登记。

### 2.1 使用方式

- 每次真实环境批次开始前，先看本表里与目标 AC 相关的行，把“触发信号”当作批次的前置检查项。
- 批次结束后，若触发信号出现，先记失败事实（输入、命令、原始输出），再决定是修代码、补证据还是改登记；不得先改预期。
- 同一风险连续两个批次都未处置时，在提交说明里点名，避免“沉默积累”。

### 2.2 升级与降级

| 动作 | 条件 | 落点 |
| --- | --- | --- |
| 升级为阻塞项 | 触发信号已在真实环境出现，且影响 AC 结论 | 先在 `status.json` 改该 AC 结论，再回现状页补关闭条件 |
| 降级为观察 | 有真实环境证据证明失败模式不再出现 | 移入第 3 节，写明证据路径；不删除历史结论 |
| 合并 | 两条风险同一根因、同一应对 | 保留编号较早的一条，另一条写“并入 R-nn” |
| 拆分 | 一条风险对应两种独立处置 | 新编号追加，不复用旧编号 |

## 3 已关闭但需保留观察

以下条目在代码层已修，**不等于真实环境通过**，因此不再作为开放缺陷，但仍是风险观察点：

| 项 | 关闭依据 | 需观察什么 |
| --- | --- | --- |
| HTTP 工作流缺口与完整性 | 现状页记录按实际 `capture.gaps` 落 `PARTIAL/GAP`，未完成捕获不进 E | 真实服务样例中缺口是否被误判为完整 |
| 运行时来源观察写回 | 现状页记录 `ExecutionFacts` 与报告消费同一来源事实 | 退出/强杀后来源事实是否仍可核对 |
| 报告/问题证据修订配对 | 现状页记录新记录可直接打开证据正文，旧记录缺修订号时提示缺口 | 旧记录读取是否被静默当成空 |
| 证据正文只读视图 | 现状页记录单测覆盖，正文经过滤与显示态路径投影 | 真实宿主里大文件与二进制是否正确省略 |
| 旧代码反例 | 现状页列出 A-19、A-20、B-12、C-15、C-16、C-18、D-08—D-14 已修 | 任一项回归时回到现状页登记，不在本文续写 |
| 迁移与备份闸门 | 现状页记录 `prepared`／`rollback_pending` 跨核心重启闸门与独立备份位置已补 | 真实迁移中断、坏备份与恢复后索引重建仍须观察 |

保留观察的原则：这些项一旦在真实批次中失败，先改 `status.json` 与现状页，再把对应风险从“观察”升级为正式登记项；不得用“代码已修”抵掉失败证据。

观察项不设固定复查周期，而是挂在对应批次上：做真实 Trae 批次时复查宿主相关项，做恢复批次时复查来源与证据项，做导出批次时复查路径与脱敏项。没有对应批次就不写“已复查”。
