## 一、死守正确率与零假通过（最核心）

### 1. 写测双盲预期核对（反“照着 Bug 代码抄断言”）
- **复用模块**：`src/aitest/core/blind_expectation.py`
- **做法**：生成检查预期时强制仅从需求描述、接口定义和验收原文独立推导，不读取被测实现分支；引不上原文的直接标为「预期待核实」，运行后最多算阻塞，绝不顺着有 Bug 的代码生成必过断言。

### 2. Git 改动行级命中核对（防“绿了一堆但没跑到新代码”）
- **复用模块**：`src/aitest/core/git_engine.py`、`src/aitest/core/code_graph.py`
- **做法**：运行期顺手收集本次执行的实际调用轨迹或行覆盖数据，与 `git diff` 改动行比对。结果页明确展示本轮修改的关键分支是否真的被执行命中；用例全绿但根本没跑到改动代码时直接提示“未覆盖改动分支”。

### 3. 核心写接口「三方事实对账」
- **复用模块**：`src/aitest/core/service_logs.py`、`src/aitest/runners/http_runner.py`
- **做法**：对涉及创建、支付、状态变更的关键接口，不单凭返回 `200 / ok` 就判通过；同时核验「接口响应体 + 目标文件或本地存储前后状态变化 + 同时间窗服务端日志无未捕获异常」，任一矛盾即判失败。

### 4. 严格隔离「产品真缺陷」与「脚本 / 环境误报」
- **复用模块**：`src/aitest/core/script_linter.py`、`src/aitest/core/judge.py`
- **做法**：执行前加强语法、导入与入口存在性检查；运行失败后按异常来源明确区分「被测源码异常」与「生成脚本语法 / 选择器过期 / 缺少依赖」，后者统一归为阻塞，绝不污染真实问题清单。

### 5. 沿实际调用链定向聚焦判 Mock（缓解大库全 `unknown`）
- **复用模块**：`src/aitest/core/code_graph.py`、`src/aitest/ai_features.py`
- **做法**：替代按目录平铺读文件很快耗尽文件预算的做法（参见已知限制 `I-02`），沿着本次用例实际可达调用链定向读取核心上下游文件做 Mock 真实性判定，显著减少复杂项目的 `unknown` 盲区。

### 6. 用 Seeded Bug 基准集锁定插件自身准确率
- **复用模块**：`tests/fixtures/benchmark_suite.py`、`tests/unit/test_seeded_bug_benchmark.py`
- **做法**：持续往基准集补充典型真实 Bug 样本（假 Mock 通过、返回成功未落盘、跨层接口字段错、金额丢精度），每次改提示词、代码图或裁判逻辑都跑一遍，确保真 Bug 检出率不退化、误报不升高。

## 二、实在地减少人工操作（零新存储）

### 7. 结果页突出「与上次运行的差分」
- **复用模块**：既有 `runs/` 历史快照
- **做法**：结果页无需翻长表，默认在摘要下方优先列出对比上一次运行变化的条目：**新增失败**、**刚修好通过**、**连续多次未修**、**结果波动（疑似不稳定）**。

### 8. 运行通过后提示「一键附带证据关闭历史问题」
- **复用模块**：`src/aitest/core/issues.py`
- **做法**：运行结束后用新通过用例的失败签名自动匹配当前未关闭问题；命中后在结果页顶栏弹出确认条，用户填简短理由点确认，直接附带本次运行真实证据完成问题闭环。

### 9. 失败用例一键复制「精准修复上下文」给 Trae AI
- **复用模块**：`src/aitest/core/reports.py`、`integrations/agent-bridge/`
- **做法**：除已有“复制最小复现”外，增加复制结构化修复摘要（验收原文 + 期望与实际 + 关键堆栈 + 前后端源码行号 + 最近 Git 改动），直接贴进 Trae 对话框即可让编码助手精准修 Bug。

### 10. 执行前确认页「高亮本次变化」+ 人工贴图 `Ctrl+V`
- **复用模块**：`ConfirmationPanel.vue`、`EvidenceDialog.vue`
- **做法**：确认页对比上次已确认快照高亮本次新增用例/依赖/命令变化，减少盲勾；人工记录结果和补充证据弹窗支持 `Ctrl+V` 直接粘贴剪贴板截图，省掉选文件步骤。

## 三、把已有亮眼能力真正串起来（最小改动）

### 11. 架构图支持「点选模块 / 受影响节点 → 直接新建测试」
- **复用模块**：`CodeGraphViewer.vue`、`NewTaskComposer.vue`
- **做法**：在现有架构图上直接多选 1~3 个模块卡片或点击「选受 Git 影响节点」，底部动作条直达预填好对应范围的新建测试抽屉，把架构视图从“看一看”变成最高效的发起入口。

### 12. 报告补充「单文件自包含 HTML」导出
- **复用模块**：`panel/src/services/exportService.ts`
- **做法**：在现有 Markdown 导出之外增加单文件自包含 HTML 导出（内置轻量样式、四值结论、`S/M` 覆盖率与脱敏关键截图），双击浏览器即可阅读，方便转发给不装编辑器或非技术的产品/测试负责人验收。

## 四、明确不做（反过度设计边界）

为防止产品越来越重、偏离「轻量本地文件插件」定位，以下复杂设想明确**不纳入规划**：

1. **不做**带上下文状态机与变量传递的自定义测试编排 DSL / 工作流引擎；
2. **不做**本地数据库/文件数据测前自动快照与回滚框架；
3. **不做**内置新手演示沙盒工程与引导教程体系；
4. **不做**可编程自定义业务不变量规则引擎与多套测试账号密码变量槽管理系统；
5. **不做**HTML 报告离线批注并回传 JSON 批注同步的一套离线审批流；
6. **不做**大计划全自动变异测试双跑（负面探测仅作轻量可选项或回归集内使用）；
7. **不做**跨多仓库项目聚合监控大盘，以及主界面拆成双套 UI 视图模式（保持现有一套干净紧凑工作台即可）。
