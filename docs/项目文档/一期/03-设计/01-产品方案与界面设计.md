# 产品方案与界面设计（一期面板）

> 适用期次：一期；主责：页面、动作、文案与交互状态；状态：开发基线，真实 Trae 全流程未验收

本册描述面板"用户看到什么、能点什么、点完发生什么"。字段来源、DTO、事件续读与视图守卫由开发阶段的架构分册 `docs/02-开发阶段/07-面板与工作台.md` 维护；结论、等级与统计口径只在功能分册中定义，面板不重算、不四舍五入。面板是编辑器内嵌视图，不引入本地服务、数据库或账号体系。

## 1 设计目标与信息架构

三条目标贯穿全册：

1. **一个入口回答一个问题。** 概览回答"这次要检查什么、跑到哪、结论有多硬"；步骤回答"这一步怎么推进"；报告回答"已经存下来的结论是什么"。
2. **只读事实与人工动作分离。** 事实卡片只展示核心 DTO；写动作只出现在明确的按钮上，分别走普通写入或核心确认，信息区自身不落记录。
3. **每个阻塞都带下一步。** 不出现只置灰不给原因的按钮；缺口给出中文说明与处理方向，可点的行直接带到对应步骤。

| 一级入口 | 子视图 | 用户在这里完成 | 关键约束 |
| --- | --- | --- | --- |
| 本次测试 | 概览 / 步骤 / 计划 / 规则 | 看要跑什么、逐步执行与核验、读已发布计划、编辑规则草稿 | 概览不做业务写入；计划只读 |
| 问题与报告 | 报告 / 问题 / 提测 | 保存与复核报告、导出证据、处理问题、正式提测 | 不关闭缺陷、不改判定 |
| 设置 | 模型 API / 核心连接 / 本地数据边界 | 配置模型与凭据引用、连接与受控重启核心 | 无删除入口，不写业务结论 |

页头固定显示项目名，并提供"连接核心 / 设置 / 诊断"三个图标；底部状态条只显示核心连接状态与"诊断"入口。诊断不是第四个一级入口，也不占一级页签。

```text
页头（项目名 · 连接核心 · 设置 · 诊断）
├─ 本次测试 ── 概览 / 步骤 / 计划 / 规则
├─ 问题与报告 ─ 报告 / 问题 / 提测
├─ 设置 ────── 模型 API / 核心连接 / 数据边界
├─ 页头诊断 ── 核心能力 / 依赖状态 / 已提交事件 / 高级动作
└─ 全局 ────── 首次向导 · 确认对话框 · 提示条
```

一级入口收敛为三个的理由：运行前、运行时、运行后是同一份运行事实的三个段落，不是三个页面；计划与步骤只是"本次测试"的子视图，拆成一级页签会让同一状态在多处各算一次，也会让"开始执行"出现在两个地方。旧版"当前检查 / 项目与计划 / 工作台 / 报告与问题 / 设置"五页签布局已废弃，不再作为实现依据。

页面状态分两类，不得混用：**业务状态**（项目、计划、运行、步骤、尝试、报告、问题、提测）只来自核心记录；**界面状态**（当前入口、子视图、展开项、选中项、焦点）只属于面板，重开时按已提交记录重建，不复制一份业务结论到本地。因此"点了什么"永远不能替代"核心记录了什么"。

## 2 首次向导

向导在"还没有可推进的运行"或"需要重新准备"时进入，也是唯一的项目创建入口。每一步只生成受控命令：写入仍过核心守卫，发布与授权仍由核心确认，面板不代签、不自动继续。

| 步骤 | 输入 | 产出 | 失败处理 | 可否返回 |
| --- | --- | --- | --- | --- |
| 选择项目 | 宿主目录选择、测试入口文件 | 会话身份（项目、源码目录、入口、项目名）与已保存的模型设置 | 取消选择不写任何记录，停留原处；身份无效报"项目选择没有返回有效的项目身份" | 可重选项目 |
| 准备环境 | 项目名称、验证目标或额外关注点、确认这是本地测试入口 | 独立 Python 3.11+ 环境与 Python 载体、模型配置写入磁盘 | 缺字段就地提示；核心只在启动时读取环境与模型配置，写入后执行受控重启 | 可重选项目或重新开始 |
| 模型辅助（同屏卡片） | 一次 API Key、是否允许模型读取入口源码、API 地址 / 模型名 / 超时（10–120 秒整数） | 安全凭据引用、模型出站设置 | 未填凭据、超时越界就地拒绝；密钥正文不进入面板、记录与日志 | 与上一步同时提交 |
| 分析源码 | 已保存的绑定与环境 | 项目上下文、目录绑定、环境登记、源码快照与项目理解、目标候选 | 分析失败显示错误与"重试本阶段"；续跑不重复写项目、绑定或环境 | 可重试本阶段（不可跳过） |
| 生成计划 | 选中的验证目标，或 pytest 测试模式下的测试清单勾选 | 计划提案草稿与覆盖预览（用例、必测、未知项、能力缺口） | 无模型时计划生成明确阻塞；提案为空提示重试或核对模型配置 | 可换目标、重新生成 |
| 核对并发布 | 覆盖收据、功能 × 维度、逐条用例与断言依据、业务功能目录完整确认、可选的机器可读验证预期 | 一次确认冻结计划、覆盖契约与计划级执行许可 | 确认窗口关闭或超时只表示结果未核实，按原意图核对并给"重试发布"；缺确认不得发布 | 可重新校验、编辑提案 JSON；发布后计划不可改 |
| 准备并登记运行 | 已发布计划、依据确认引用、源码与环境快照 | 准备记录与运行编号；登记本身不执行任何步骤 | 缺准备回执或登记失败给"重试本阶段" | 不可跳步；完成后进入工作台或概览 |

- 每一步都说明"将要保存什么、仍由人决定什么"；失败时保留已填内容，不静默回到第一步。
- 写入通道固定：登记环境、保存提案、准备运行等走普通写入；发布计划、保存模型材料范围、确认断言依据等走核心确认。
- 重复进入向导不重复写记录：已有项目时只重新核对源码快照与项目理解；同一失败阶段重试沿用同一意图，不产生第二份项目、绑定或环境。
- 换项目后清空上一个项目的提案、依据回执与覆盖确认，避免用旧目标的计划发布到新项目。
- pytest 测试模式额外看到"发现测试"步骤与手工测试范围选择（勾选文件、显示测试数与收集错误）；列表为空或未勾选时拒绝生成，提示"至少选择一个测试文件"。
- 完成态显示计划号、运行号与步骤数，提供进入测试工作台与回到本次测试概览两个出口。
- 步骤条固定显示六段：选择项目、准备环境、发现测试、生成计划、核对发布、准备运行。非 pytest 流程不经过"发现测试"，"选择验证目标"也未单列，这两处偏差登记在第 8 节，不在此处粉饰。

## 3 本次测试

### 3.1 概览

概览是默认入口，按运行状态切换显示，不并存多套主屏。

| 状态 | 主区显示 | 可点动作 |
| --- | --- | --- |
| 独立预览（无宿主） | "未连接编辑器宿主，这个页面运行在独立预览中" | 无写入；仅说明在 Trae 中打开 |
| 连接中 | 加载态"正在连接本地核心…" | 无 |
| 核心未连接 | 未连接原因 + 核心自检未通过提示 | 连接核心、打开设置 |
| 无项目 | 三步引导（选择项目与入口、生成并核对计划、执行核验并保存报告）+ 流程说明 | 开始准备测试、连接核心 |
| 项目已就绪、未登记运行 | 项目、范围、核心状态，"还差一次运行准备" | 继续准备测试、刷新本次状态 |
| 运行已登记但视图未取得 | 说明刚打开或核心刚恢复，给出刷新与诊断 | 读取 / 刷新本次运行、打开诊断 |
| 已取得运行视图 | 运行主卡 + 本轮范围 + 缺口 + 需要你处理 | 见下表 |

运行主卡固定顺序：项目名、阶段说明、状态标签（控制状态、档位、驱动、业务结论）、五段步进（准备 / 计划 / 执行 / 核验 / 报告）、主动作。

| 运行段 | 阶段说明口径 | 主动作 |
| --- | --- | --- |
| 准备 | 计划与环境已保存，开始后按步骤显示进度 | 开始执行（仅控制状态为未开始、且有运行号与快照提交号）、打开工作台、刷新 |
| 运行中 | 核心按计划推进，需确认或补证的步骤会提示 | 暂停或继续（按控制状态二选一）、打开工作台、刷新 |
| 运行后 | 执行已结束，查看报告、证据与未完成范围 | 查看报告、打开工作台、刷新 |

- **本轮范围**：必测分母、已执行、已验证、未验证四项常驻；已确认失败大于 0 时才追加该项。自动步骤单独显示完成数与总数及进度条，与用例分母分开。
- **缺口**：核心返回的缺口码转中文并附一句处理方向；核心未登记缺口时显示"没有登记缺口。真实结果仍需以报告和证据为准"，不写"全部通过"。
- **需要你处理**：待人工操作、阻塞步骤、待核验、已过期四类按数量成行，点击即进入步骤视图并选中该步；四类都没有时只保留"打开工作台"。
- 概览只显示状态与入口，不执行步骤、不改计划、不改配置；运行期不显示时间，也不显示百分比或分数。

### 3.2 步骤

步骤视图是工作台，把"解析动作 → 授权 → 执行 → 核验 → 读证据"拆成不同事实，一次只推进一项。

| 区块 | 内容 | 动作与边界 |
| --- | --- | --- |
| 运行摘要 | 运行短号、档位、驱动、计划修订、控制状态；已验证 / 未验证 / 待人工 / 自动步骤四数 | 暂停（仅运行中）、继续（仅暂停中或已暂停）、取消（未开始、运行中、已暂停、暂停请求中、待核验）；进度条只表示自动步骤 |
| 运行中修订 | 需先读计划确认状态，列出冻结用例修订与依据确认编号 | 提交运行中修订：勾选未执行且尚无当前尝试的步骤、填已保存的新用例修订号与原因；完整验证运行拒绝改写，提示只能收窄驱动或新建运行 |
| 逐项授权 | 未执行且未开始记录的步骤清单 | 先逐项解析执行动作，再逐项确认；未确认项不写成已授权，取消不提交 |
| 复用核对 | 选择用例与来源运行编号 | 核对复用资格只读；核对未发现不兼容才允许登记复用选择，登记不改写源运行或目标运行历史 |
| 回归建议 | 变更文件（每行一个） | 计算影响面只读，输出影响模块、未登记模块与建议用例；不改计划、不自动执行 |
| 步骤轨与详情 | 步骤状态、当前尝试、核验结论、依据是否过期、已解析动作编号、缺口 | 按状态给唯一主动作，见下表 |
| 证据 | 当前尝试的证据编号与修订 | 按精确修订只读打开正文 |
| 执行不顺利 | 重试、退回、补录、导入外部结果 | 每种都产生新尝试或新材料，旧尝试与旧证据保留 |
| 失败测试 | 失败节点、可疑源码位置、失败签名簇、与上次同范围的新增 / 既有 / 已修复计数 | 打开源码行、生成问题草稿（草稿只落到问题页处理） |

步骤主动作按状态递进，同一时刻只出现一个主按钮：

| 步骤状态 | 主按钮 | 说明 |
| --- | --- | --- |
| 尚无已解析动作 | 查看将执行的操作 | 只解析，不授权、不执行 |
| 已解析未授权 | 确认并授权 | 核心确认；不确认不执行 |
| 已授权未执行 | 执行已确认的操作 | 执行请求返回不等于业务通过 |
| 已执行、有当前尝试 | 核验这次执行结果 | 独立核验，不沿用执行自述 |
| 已完成 | 无主按钮 | 显示"该步骤已完成并取得有效核验" |

- **证据正文**：正文可读时以只读文本展示；不可读时分别说明脱敏不安全、对象仓不可用、超过 4MB、对象读取失败、摘要不一致、二进制内容，不留失效链接假装可用。
- **重试 / 退回**：先确认对话框列出步骤、当前尝试与后果，再重新解析动作并创建新尝试；随后展示核心回执中的下游需重跑清单，旧尝试与证据保留。
- **补录证据**：仅在当前尝试已完成时可用；表单要求操作类型、操作目标、实际结果、业务对象编号，输入摘要可选；缺项就地拒绝，不伪造完整证据。
- **导入外部结果**：作为替代路径记录实际操作、输出与断言值，提交后由核心判定缺口，不自动写成通过。
- **运行中修订**：正在执行的步骤不可改；只对未执行且无尝试的步骤开放，且必须给出已保存的用例修订与依据确认编号。
- 从概览进入步骤保留所选运行与步骤；刷新或重开不重置选择，也不切走用户正在看的历史内容。

刷新与恢复按已提交记录重建，不靠界面推断：

| 时机 | 面板行为 |
| --- | --- |
| 打开视图 | 读取当前已提交视图与配对的游标，按最近状态显示；无运行记录时进入运行前空态 |
| 开始运行 | 切到运行时段，动作区换成暂停或继续 |
| 运行中 | 按事件增量刷新进度与缺口计数；最近输出只保留一条，完整内容到证据正文读取 |
| 运行结束 | 切到运行后段，先显示业务结论与范围，再显示统计、等级与动作 |
| 连接中断 | 保留最后确认状态与连接原因；重新连接查原运行，不自动重跑，也不把运行改写成已取消 |
| 重开面板或换窗口 | 按核心记录恢复原运行与原步骤；关闭窗口不等于取消成功 |
| 用户正在看历史时来了新记录 | 新修订提示可见，但不无提示切走正在看的内容 |
| 切换项目 | 清空上一个项目的运行、计划与详情缓存，不串用视图 |

### 3.3 计划

计划子视图只读：列表按记录修订列出已保存计划，打开后按精确修订读取详情——计划编号、范围、业务目标、驱动、模板版本、用例数、必测数、运行档位；覆盖收据列出功能 × 维度的覆盖承诺与已知限制；用例与依据逐条显示层级、重要性、核验方式与断言依据状态。

- 动作只有"读取计划列表""返回计划列表""查看当前运行"或"开始准备测试"。
- 计划发布后不可变，修订生成新版本；本页不提供编辑、发布、复用既有计划直接准备运行的入口，页内如实声明"本版未开放"。

### 3.4 规则

规则子视图区分草稿与已发布版本，两者不共用勾选框。

| 区域 | 字段或内容 | 动作 |
| --- | --- | --- |
| 草稿列表 | 规则编号、草稿修订 | 打开草稿、新建草稿、刷新规则 |
| 草稿详情 | 适用范围、正文说明、步骤、证据要求、来源、正文修订、未知扩展字段 | 保存草稿（普通写入）、确认并发布（核心确认）、返回规则列表 |
| 已发布版本 | 规则编号、正文修订、记录修订、适用范围、来源、确认编号、摘要、正文与步骤、证据要求 | 导出 Markdown、以此新建草稿、返回规则列表 |
| Markdown 导入 | 文档正文与来源 | 导入只创建草稿，不执行命令、不自动发布 |

- 未确认的草稿不能发布；发布后不能原地修改，需要变化时新建草稿并再次发布。
- 历史运行仍引用原发布版本，规则变化不回溯改写已有结论。

## 4 问题与报告

三个子页签共用页头"刷新"，各自独立加载，互不推断对方状态。

### 4.1 报告与复核

| 区域 | 内容 | 动作与边界 |
| --- | --- | --- |
| 报告列表 | 报告编号与内容修订；同一运行的多份报告保留各自修订 | 保存本次报告（需有当前运行且核心广告该能力）、读取报告修订、打开精确修订 |
| 报告详情 | 业务结论、范围 / 已执行 / 已验证 / 未验证、证据等级（未评级显示"本轮未评级"）、分层结果、证据引用数、关联问题、阻塞问题、执行快照 | 只读；当前投影与冻结快照分别标明 |
| 失败测试与缺口 | 报告冻结时的失败节点与源码位置、缺口中文说明 | 打开源码行 |
| 证据索引 | 证据编号与修订 | 按精确修订只读打开正文 |
| 本地复核 | 复核结论、复核说明；已有复核的复核人与结论 | 保存本地复核（绑定报告修订）、读取历史复核；复核不改报告正文 |
| 导出 | Markdown 摘要或证据包 | 导出后只给回执编号与制品信息，并提示"不要把导出成功当作证据完整"；本次会话复核编号随导出引用 |
| 项目级运行汇总 | 按运行列出环境、计划修订与 S / E / V，按验收项展开 | 只读；不重算判定，不合并不同解释器的结果 |

- 旧报告不改写：结论、等级、缺口都以该修订冻结值为准，新记录只提示"有更新修订可用"。

### 4.2 问题处理

问题列表只列开放问题（编号与记录修订），详情按精确修订读取：严重度、处置、责任人、运行、用例、步骤、尝试、描述、预期与实际、事实与假设、关联证据正文、pytest 失败簇（可勾选节点拆分为新草稿）。

| 处理动作 | 需要填写 | 结果口径 |
| --- | --- | --- |
| 确认问题 | 严重度、责任人 | 待确认 → 已确认；确认人不改写执行事实 |
| 开始处理 | 无 | 已确认 → 处理中；不执行测试、不关闭问题 |
| 记录修复 | 修复版本、回归方式、关闭条件 | 记录修复，不等于关闭 |
| 请求回归 | 说明（可选） | 只登记回归安排，新执行仍由步骤视图产生 |
| 关闭问题 | 原用例、回归运行、回归尝试、断言引用、断言结果（可选） | 必须是原用例上的新回归尝试与已确认依据；旧尝试不能充当本轮回归，由核心守卫判定是否关闭 |
| 处置 | 处置类型（非缺陷 / 重复 / 推迟）、原因、证据编号，重复时填主问题编号 | 非缺陷、重复跟随主问题、暂缓分别标记；拒绝循环或自指 |

- 详情提供"复制复测简报"（来源修订、预期与实际、脱敏证据、事实与假设、复测入口），复制不关闭问题、不执行修复。
- 报告复核、处理完成、上传成功都不是问题人工核对，界面分别标注。
- 失败时就地显示原因并保留原详情，不把列表刷新成"没有开放问题"。

### 4.3 提测

| 区域 | 内容 | 动作与边界 |
| --- | --- | --- |
| 交付说明列表 | 交付编号、任务、版本、是否已提测 | 读取交付说明、新建任务草稿、新建交付说明 |
| 交付详情 | 核验状态、运行方式、自述完成 / 自述未完成、已验证范围 / 未验证范围、关联任务与提测回执 | 自述与验证分列，页面不把自述复制到已验证范围 |

## 6 状态、空态与文案

| 场景 | 显示 | 禁用原因 | 不得出现的措辞 |
| --- | --- | --- | --- |
| 尚未连接核心 | 未连接原因 + "连接核心""打开设置" | 一切写入与读取 | "离线可用""稍后自动同步" |
| 无项目 | 三步引导 + 流程说明 | 运行、报告、问题相关动作 | 虚构统计或示例结论 |
| 项目已就绪、未登记运行 | "还差一次运行准备"，给继续准备入口 | 开始执行 | "项目已完成""可以验收" |
| 运行视图未取得 | "刚打开面板或核心刚恢复"，给刷新与诊断 | 步骤、报告相关动作 | "运行已丢失""已取消" |
| 无已保存计划 | "还没有已保存的计划" | 计划详情、复用核对 | "计划为空"当作无风险 |
| 步骤已完成 | "该步骤已完成并取得有效核验" | 重复授权、重复执行 | 把完成写成"已通过验收" |
| 步骤无当前尝试 | 重试、退回、补证置灰 | 无尝试可回退 | "失败""未通过" |
| 当前尝试未完成 | 补证置灰并提示"当前尝试尚未完成" | 补证只能绑定已完成尝试 | 允许先补证后执行 |
| 无证据 | "当前尝试还没有可读取的证据" | 正文、导出 | 用空列表冒充证据完整 |
| 证据正文不可读 | 按六类原因分别说明（脱敏不安全、对象不可用、超过 4MB、读取失败、摘要不一致、二进制） | 只读正文 | "证据已损坏"而不给原因 |
| 无报告修订 | "还没有报告修订"，提示运行告一段落后保存一次 | 详情、导出、复核 | 用空列表冒充"没有失败" |
| 无开放问题 | "没有开放问题"，说明问题从报告或运行登记 | 问题处理动作 | "全部修复""零缺陷" |
| 无交付说明 | 引导新建任务与交付说明 | 正式提测 | 把未提测写成"已交付" |
| 依赖未就绪 | 列出具体条件与可能被拒的动作 | 依赖这些动作的按钮 | 把单点故障写成"核心不可用" |
| 模型不可用 | 说明 AI 生成不可用，保留人工补录、已有证据与导出 | 依赖模型的动作 | "无法继续测试" |
| 数据目录不可写 | 显示可读记录，阻止新的写入 | 保存、导出、登记等写入 | 把写入失败写成"没有记录" |
| 连接中断 | 最后确认状态 + 连接原因 + 重连入口 | 写入与实时刷新 | "已取消""已失败" |
| 完整验证运行提交修订 | 提示"不允许改写计划内容，只能收窄驱动或新建运行" | 运行中修订 | 允许静默缩小范围 |
| 复核或导出刚完成 | 只给回执编号，并声明不构成证据完整或业务通过 | — | "复核通过""导出即证明" |

文字与呈现约定：

- 业务结论只用通过、失败、未完成、不适用；证据等级始终带中文含义或"本轮未评级"；等级不是放行按钮。
- 不写百分比、分数、完成率或通过率；覆盖写成"必测 12 项，已执行 11 项"这类带分母的计数。
- 执行完成、有效验证、有效通过 / 失败分列，不合并成一个"完成率"。
- 按钮使用明确动词（开始执行、确认并授权、核验这次执行结果、复制复测简报）；错误必须给可执行的下一步。
- 状态不只用颜色表达；按钮有文字标签，主要动作可键盘完成；对话框可用 Escape 关闭，关闭后焦点回到触发按钮。
- 窄面板折叠次要详情，不隐藏范围、结论与主动作；列表读摘要，详情按引用读取。

## 7 动作清单与确认方式

通道口径：

- **普通写入**：面板提交业务意图与预期修订，核心守卫后落记录；幂等由意图编号保证。
- **核心确认**：核心生成确认材料（challenge），面板展示冻结摘要（动作、目标、已解析输入、凭据用途、修订），由用户点击"确认并继续"后回传；面板不代签、不自动继续、不提供永久信任。CLI 不提供人工确认，人工动作只能从面板完成。
- **只读**：查询或视图读取，不产生业务写入。
