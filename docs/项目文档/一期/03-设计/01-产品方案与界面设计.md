# 产品方案与界面设计（一期）

> 状态：2026-11-17 任务台账设计基线。契约见[CLI 与数据契约](03-CLI与数据契约.md)；需求见[需求规格](../02-需求/02-需求规格.md)。
>
> 本版替换 2026-11-16 的“单页测试单三相位 + 抽屉”结构；旧结构不再作为实现依据。

## 1 设计原则

1. **主对象是任务**：任务是“这次要验证什么”，计划是任务的合同，运行是合同的一次尝试。计划、运行、历史都挂在任务下。
2. **一个台账，不换页**：计划、运行、结果共用同一张验收项台账；状态变化只改变头部、行状态和底部操作。
3. **分母一直可见**：本次范围、适用项、未覆盖、未核实始终与结论同屏；主台账只列本次纳入的验收项，未纳入项收在台账底部折叠摘要里，展开只读。
4. **计划是合同**：先选范围，再按范围生成计划；运行不能超出计划。范围变化生成新计划，计划内改用例生成新版本。
5. **确认是人的动作**：执行前确认绑定计划版本、范围、环境、凭据来源、副作用和依赖；任一项变化就重新确认。确认区向人展示范围、计划号/修订、依赖和副作用；环境和凭据摘要进入确认指纹，但不在确认区逐项展开。人勾选后，面板以 `--confirm` 调用 CLI；CLI 也接受同计划版本、同范围、同指纹的可复用确认记录。
6. **证据优先，解释是脚注**：失败先给预期/实际/证据；AI 解释默认折叠，标题写明“不改变结论”。
7. **面板只读 CLI 事实**：不重算结论、覆盖、Mock 真实性；不直接写业务文件。
8. **界面说产品语言**：不出现冒烟、L1/L2/L3、S/M、Mock、plan_id/run_id、失败签名等内部词；专业词如副作用、凭据、验收项、用例、阻塞保留。

## 2 信息架构

项目内导航固定在侧栏：概览 / 问题 / 运行记录 / 设置；任务列表挂在当前项目下。

```text
测试面板
├─ 项目侧栏         项目选择、搜索、新增；概览 / 问题 / 运行记录 / 设置；任务列表
├─ 测试             项目与任务的工作区；任务“切换目标”是自绘菜单
│  ├─ 无项目         登记项目
│  ├─ 有项目         开始测试，三个同级入口
│  │     ├─ 按目标   输入目标或点选候选（不默认选中）→ 自动建任务和计划
│  │     ├─ 按范围   AI 项目测试地图 → 范围页 → 自动建任务
│  │     └─ 快速检查 项目级 L1，不建任务、不选验收项
│  ├─ 有任务无计划   确认范围 → 生成计划（唯一主操作）
│  ├─ 计划过期       提示原因 → 重新选范围 → 重新生成计划
│  ├─ 有计划         只读台账 + 执行前确认 + 开始测试（唯一主操作）
│  ├─ 运行中         同一台账就地更新 + 停止（唯一主操作）
│  └─ 已完成         同一台账显示结论、失败、证据、问题
│     ├─ 底部动作    查看计划 / 调整范围 / 报告 / 导出 / 重跑未通过项或再次运行
│     ├─ 计划文档    目标与交付 / 验收项 / 用例 / 检查模板 / 模块建议 / 环境与依赖
│     └─ 报告文档    结论 / 覆盖 / 验收项 / 用例 / 证据 / 问题 / 意见；版本为自绘菜单
└─ 项目分区         概览 / 问题（待确认 / 处理中 / 待复测 / 已关闭）/ 运行记录 / 设置
```

计划、报告、问题详情都是完整文档页，不是抽屉或局部面板。项目与任务切换在侧栏，报告版本用按钮组，不用原生 `select`。

**任务 → 计划 → 运行**：

- 任务修订只包含标题、目标、验证方式、验收项；
- 计划记录计划序号、任务修订、任务契约摘要、范围、用例、来源签名；
- 运行启动时冻结计划快照和任务快照；后续任务/计划修改不影响旧运行；
- 任务验收项、可观察性、所属模块或验证方式变化 → 任务契约变化，旧计划过期；只改标题/目标描述/执行人/评审人不使计划过期；
- 计划生成后，项目修订、交付提交、规则版本、`services`/`l1`/`runners` 配置或项目根目录变化 → 来源签名变化，`run.start` 判 `PLAN_STALE`；`plan.show` 的 `stale` 只比对任务契约，这类变化要到开始运行时才暴露；
- 旧计划没有任务契约时视为过期，不静默迁移；
- 范围变化 → 生成新计划；计划内改用例 → 生成计划新版本。

## 3 关键流程

### 3.1 首次使用与测试入口

```text
[选择/登记项目]
 → 环境自检（Python / 模型 / GitHub / 代理）
 → 开始测试
    ├─ 按目标：输入目标或点选候选（不默认选中）→ 自动建任务和计划
    ├─ 按范围：项目测试地图 → 范围页 → 自动建任务和计划
    └─ 快速检查：项目级 L1，不建任务
 → 生成计划
 → 执行前确认
```

入口与范围细节见[项目流程](04-项目流程.md)。

### 3.2 一次测试

```text
确认范围 → 生成/复用计划 → 台账检查计划 → 勾选“我已确认范围、依赖和副作用”
 → 开始测试（面板带 --confirm；CLI 也接受可复用的同版本、同范围、同指纹确认记录）
 → 运行中：同一台账更新，固定显示已完成数、停止
 → 结束后：结论 / 本次范围 / 适用项 / 未覆盖 / 失败 / 未完成
 → 证据、问题、解释、报告、导出
```

### 3.3 结果阅读顺序

```text
头部：结论（通过 / 失败 / 未完成 / 不适用）+ 本次范围；覆盖条给通过/失败/阻塞/未纳入计数
项目级检查：单独一行，不计入范围；失败/阻塞仍影响运行结论
台账：只列本次纳入的验收项，按最差结果；失败项默认展开
  └─ 用例：预期 / 实际 / 证据 / 问题 / 解释
未纳入：收在台账底部摘要，展开只读，不混进主台账
底部：已完成 X / Y 条检查、未核实、未完成、待人工
      + 查看计划 / 调整范围 / 报告 / 重跑未通过项或再次运行
```

### 3.4 失败后

```text
失败用例 → 证据 → 问题（自动归并或新建）
        → 重跑未通过项（新建运行，按未通过验收项收窄）
        → 人工记录（仅人工检查，运行结束后）
        → 修复后在新运行里验证，再关闭问题
```

### 3.5 历史与恢复

```text
重开面板
 → 读取项目 / 任务 / 计划 / 运行
   ├─ running：同一台账显示运行中；关闭面板不中断
   ├─ interrupted：显示运行已中断，保留已完成结果；没有恢复/续跑
   ├─ cancelled：显示已取消，已完成结果仍有效
   └─ completed：显示结果
```

历史运行使用运行目录里的计划快照和任务快照；旧运行没有任务快照时回退当前任务并明确提示来源缺口，不把回退文字伪装成原文。

## 4 页面与文档

| 页面/文档 | 目的 | 主要动作 | 空态 / 失败态 |
| --- | --- | --- | --- |
| 无项目 | 登记项目 | 填目录、登记 | 无宿主：提示从编辑器打开 |
| 目标选择 | 确认这次验证什么 | 选候选、改目标、开始验证 | 模型不可用：仍然可以手写目标 |
| 范围与计划 | 定本次范围并生成计划 | 勾选验收项、生成计划 | 范围为空：不能生成 |
| 测试台账 | 计划/运行/结果共用 | 展开验收项/用例、看证据、记录人工、重跑 | 失败/阻塞/未运行分状态显示 |
| 计划文档 | 改任务、验收项、用例、交付 | 保存任务、保存计划新版本、保存交付、应用检查模板、采用模块建议 | 计划过期：禁用改用例 |
| 报告文档 | 看完整报告与意见 | 生成/重新生成、切版本（自绘菜单）、导出、写意见 | 无报告：生成入口 |
| 问题 | 项目级问题处置 | 列表、完整详情页、状态迁移、关闭门禁 | 无问题：说明问题从失败归并 |
| 历史 | 项目级运行回放 | 列表、打开只读台账 | 无运行：说明完成一次后保留 |
| 设置 | 环境与配置 | 自检、低风险修复、列出/查看/绑定规则、读取 GitHub 变更、编辑并折叠项目配置、主题、备份 | 缺项分条列出 |

设置页顺序固定为环境自检、项目规则、GitHub 变更、项目配置（默认折叠）、外观、备份。项目规则支持列出、查看、新建版本、绑定；`rules.import`/`rules.export` 仍只走 CLI。

## 5 状态与反馈

| 状态 | 展示 |
| --- | --- |
| 运行中 | 已完成 X / Y 条检查；当前/下一条用例展开；停止常驻 |
| 已中断 | “运行已中断”，保留已完成结果；不提供恢复 |
| 已取消 | 结论 + “已取消”；已完成失败仍参与结论 |
| 计划过期（任务契约） | “验收项或验证方式已变化，需要生成新计划”；禁用开始 |
| 计划过期（来源签名） | 开始运行时由后端拒绝并说明项目、交付、规则、服务/项目级检查/运行器或项目根目录已变化；重新生成计划后重试 |
| 旧计划无任务契约 | 直接按过期处理，提示重新生成；不静默迁移 |
| 范围已改 | “当前计划基于 N 项；生成新计划后才按新范围运行”；由面板比较本地选择与 `plan.scope` 得出，CLI 不新增字段 |
| 未纳入验收项 | 不出现在主台账；底部摘要写“未纳入本次 N 项”，不计入本次结论 |
| 未核实预期 | 用例标“预期未核实”，执行通过也按阻塞计 |
| 证据缺失/截断 | 文件名旁标“已缺失/已截断”，不假装完整 |
| 模拟数据未知 | 显示“无法判断”，不写“真实” |
| 旧运行无任务快照 | 明确提示历史文字可能来自当前任务 |

## 6 文案规则

- 不出现内部词：冒烟、L1/L2/L3、S/M、Mock、plan_id/run_id、失败签名、错误码；
- 状态词：运行中 / 已完成 / 已取消 / 已中断 / 执行出错；结论：通过 / 失败 / 未完成 / 不适用；
- 用例结果：通过 / 失败 / 阻塞 / 出错 / 未运行 / 待人工；
- 验证方式：项目快速检查 / 按验收项验证；检查方式：项目级检查 / 自动检查 / 人工检查；
- 计划版本：计划 2 · 第 1 版；范围：本次 3 项 / 共 8 项；
- 数字带分母；未覆盖、未核实、失败、未完成分开写；
- 不把“未执行”写成通过；不把“没选”写成不适用；
- 解释必须标“不改变结论”，不放在结论上方。

## 7 交互细节

- 界面统一使用“运行记录”；本文与需求中的“历史”指同一功能，不改 FR/AC 编号。
- 目标候选不默认选中，展示标题、依据、预计范围与不确定项；人选择候选或自定义目标后才自动建任务，不静默建任务；
- 快速检查不建任务、不选范围；开始测试先选三种方式之一，范围页支持推荐/自己勾/完整测试；
- 范围只在“按范围测试”“有任务无计划”“计划过期”或显式“调整范围”（含结果页）时勾选；计划/结果台账只读，不显示可勾选方块；
- 从结果页进入“调整范围”后，只保留“生成新计划”主操作（可取消调整），不在旧结果上直接开始运行；
- 范围变化不修改旧计划，而是生成新计划；旧计划和旧运行保留；
- 任务/验收项/交付在计划文档里保存；任务契约变化会使旧计划过期；
- 计划内改用例生成新版本；旧运行仍引用旧版本；
- 确认区固定在台账底部；人勾选确认并开始后，面板带 `--confirm` 调用 CLI，CLI 生成确认记录写入 `confirmations/<id>.json`，`run.json` 只引用；
- 界面停止只写取消请求；worker 在检查点终止当前命令进程树并停在用例边界，不杀 worker 进程；已完成结果保留；
- 失败用例默认展开首条；解释在证据之后、默认折叠；
- 问题关闭必须选择一次新运行；候选运行不合规时由后端拒绝并说明原因；
- 证据查看器在运行结束后提供“补充证据”，登记到当前运行；报告文档提供“导入调用链日志”，链路只提供定位与证据展示，不改变结论；需要重验时新建运行；
- 报告默认打开最近一份；版本切换用自绘菜单；重新生成产生新版本，旧报告保留；验收意见可沿用；
- 人工检查只在运行结束后记录；记录后重新读取运行结论。

## 8 面板与 CLI 边界

- 面板只通过 `window.aitestHost` 调用 CLI；不直接读写工作空间文件；
- 结论、覆盖、未覆盖、未核实、问题状态、报告内容均来自 CLI；
- 面板不实现判定、计数、真实性与范围计算；只做展示与触发；
- 运行中 2 秒轮询 `run.status`；结束后刷新历史、问题、报告版本；
- 关闭面板不取消运行；重开以 `run.status` 为准；
- 旧运行没有任务快照时，面板只展示后端返回的回退事实并提示缺口。

## 9 历史缺口（2026-11-18）

> 本节只保留重构前状态，不再作为当前能力清单。2026-11-19 起，面板已补齐：三个同级测试入口、项目地图与业务功能编辑、范围三模式、快速检查、候选预计范围、规则导入/导出、链路导入/断言、交付读取、报告导出和窄屏/键盘路径。

仍存在的后端边界：

- 不提供运行恢复、续跑或单用例重跑；重跑未通过项会新建运行并按验收项收窄；
- `run.manual` 只允许 L3 人工用例在运行结束后记录；自动用例不提供人工改结果入口；
- 备份恢复、数据清理和任意路径操作仍以 CLI 为准；
- 旧计划没有任务契约时判为过期，不静默迁移。
