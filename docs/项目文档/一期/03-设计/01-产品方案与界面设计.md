# 产品方案与界面设计（一期）

> 状态：2026-11-16 设计基线（D3）。契约见[CLI 与数据契约](03-CLI与数据契约.md)；需求见[需求规格](../02-需求/02-需求规格.md)。

## 1 设计原则

1. **正常路径少点击**：选目录 → 选目标 → 确认执行 → 看报告，四步内完成。
2. **AI 先给结果，人再改**：不让人从空白表单开始。
3. **事实与判断分开展示**：结论、覆盖、Mock、AI 分析各有位置，不混成一句话。
4. **不知道就写不知道**：缺证据、未执行、判不出，都用明确文案，不用绿色掩盖。
5. **面板只读 CLI**：不重算结论、不直接写业务文件。

## 2 信息架构

Trae 侧边栏一个入口，主视图只有一张“测试单”，不再分项目页、计划页、运行页和结果页：

```text
测试面板
├─ 顶栏       项目切换、项目详情、历史、环境、设置
├─ 测试单     建议 → 运行 → 结果，三个相位在同一张单子里切换
│  ├─ 建议    目标与依据、范围 S/M、验收项、环境/副作用/耗时、开始测试
│  ├─ 运行    分段用例进度、当前用例、实时验收项、实时证据、取消
│  └─ 结果    结论记分牌、失败/阻塞、AI 解读、遗留问题、证据/报告、意见
├─ 历史抽屉   每次运行的时间、状态与回放
├─ 调整抽屉   验收项增删改、范围、交付说明、模板、模块建议
├─ 项目抽屉   只读项目事实、模块、最近运行
├─ 证据抽屉   本次运行的证据清单、打开与复制引用
└─ 设置屏     环境自检、模型、工作空间、GitHub、高级配置
```

正常路径只有两个人工动作：首次选择目录、点击“开始测试”。历史上一次运行存在时，打开面板直接回放该次结果（运行中则显示进度）。

界面是全宽控制台而不是网页卡片：顶栏为 `AITEST` 字标、项目选择与 `READY` 状态，主体直接铺在石墨地面上，用 1px 规则线与铜色编号分节，底部固定 `LOCAL / NO NETWORK` 状态线。顶栏和设置提供 Console / Paper 两套皮肤切换，只改变本机视觉。

## 3 关键流程

### 3.1 首次使用

```text
[选择项目目录]
   → 检测环境（Python / 模型 / gh）
       ├─ 缺低风险项：自动修复并显示结果
       └─ 缺高风险项：显示命令，等人处理
   → 生成目标候选与验收标准（AI 不可用时退回通用目标）
   → 默认全选，点“开始测试”即确认范围并生成计划
```

### 3.2 一次测试

```text
目标与依据
 → 范围（默认全部适用；可点掉单条或自选）
 → 开始测试（一次点击完成范围确认、计划生成、执行授权）
 → 运行中（分段进度、当前用例、实时证据、取消）
 → 结果（结论记分牌、分区明细、失败证据、AI 解读、问题）
 → 报告（导出 / 验收意见）
```

### 3.3 结果阅读顺序

```text
结论记分牌
 ├─ 验收项 S/M、按状态着色的刻度
 ├─ 用例通过/失败/未完成/待人工计数
 ├─ 范围内未完成、待人工、AI 假设、范围外条目
 ├─ 01 失败用例（默认展开首条，其余折叠）
 ├─ 02 阻塞与未完成（manual_pending 可在此记录人工结果）
 ├─ 03 AI 解读（只解释事实，不改结论）
 ├─ 04 遗留问题（跨运行累积，不改变本次结论）
 ├─ 05 证据与报告
 ├─ 06 验收意见（自由文本，不改变结论）
 └─ 07 全部用例（默认折叠）
```

### 3.4 失败后

```text
失败用例 → 证据（输出、截图、日志、请求）
        → 只重跑这条（新建运行意图）
        → 人工补证 / 记录 L3（写入运行，重新读取结论）
        → 处置问题（状态更新/关闭，关闭依据是新运行证据）
```

### 3.5 中断与恢复

```text
重开面板
 → 读取 run.json
   ├─ running：显示分段进度、当前用例与心跳时间
   ├─ interrupted：显示“执行中断”，保留已完成用例
   ├─ cancelled：显示取消时间与未完成范围，已完成失败仍参与结论
   └─ completed：进入结果相位
```

## 4 页面清单

| 页面/浮层 | 目的 | 主要动作 | 空态 / 失败态 |
| --- | --- | --- | --- |
| 无项目 | 选目录 | 选择项目文件夹 | 无宿主：提示从编辑器打开 |
| 建议测试单 | 确认目标与范围 | 换目标、调整、开始测试 | 无验收项：提示调整补一条 |
| 运行 | 看进度与控制 | 查看实时证据、取消 | 心跳丢失：标中断 |
| 结果 | 看结论与未验证范围 | 只重跑、记录人工、处置问题、导出、意见 | 无失败：不渲染空失败区；无证据：标缺口 |
| 历史抽屉 | 回放 | 刷新、打开某次运行 | 无运行：说明完成一次后保留 |
| 调整抽屉 | 改范围与辅助信息 | 编辑验收项、范围、交付、模板、模块建议 | 无任务：先生成验收标准 |
| 项目抽屉 | 看只读事实 | 打开最近运行、进入设置 | 无模块：提示调整里建议 |
| 证据抽屉 | 查看证据 | 打开、复制引用 | 缺失：标缺失并禁用打开 |
| 设置 | 环境与配置 | 自检、修复、保存高级配置 | 缺项：分项列出 |

## 5 状态与反馈

| 状态 | 展示 |
| --- | --- |
| AI 生成中 | 骨架屏 + “AI 正在生成”，可取消 |
| AI 不可用 | 黄色提示 + “改用手动”，不阻塞后续 |
| 运行中 | 分段用例进度 + 当前用例 + 心跳时间 + 实时证据 |
| 中断 | 红色标记 + “执行中断，已完成部分保留” |
| 已取消 | 灰标 + 取消时间 + 未完成范围；记分牌说明已完成失败仍参与结论 |
| 证据截断 | 文件名旁标“已截断” |
| Mock 未知 | 真实性列显示“未知”，悬浮显示原因 |
| 模型分析不合格 | 显示“分析不合格”，不展示半截内容 |

## 6 文案规则

- 不用“完成”描述未验证的事；用“已执行”“已生成”“待验证”；
- 数字必须带分母：`6/8 验收项`，不写“大部分通过”；
- 失败与阻塞分开写；
- 缺少能力时写“未配置/未安装/未验证”，不写“暂不支持”了事；
- 结论词只出现在结论记分牌，AI 摘要里不出现。
- 未验证分四类写：范围内未完成、待人工、AI 假设未验证、范围外；不合并成一个“未验证”。

## 7 交互细节

- 范围默认全部适用，点掉即排除；不把模块标记当作后端过滤条件；
- “开始测试”一次点击即确认范围并生成计划，不再出现单独确认页；
- 运行中取消需二次确认，说明“已完成的用例会保留”；
- 结果页失败用例默认展开首条，其余折叠；阻塞/待人工可展开记录；
- 人工记录写回运行后重新读取结论，不在前端本地改结论；
- 报告导出前提示是否包含证据；
- 所有长操作显示可取消，取消后说明停在哪一步。

## 8 面板与 CLI 边界

- 面板通过 CLI 取数与触发动作，不直接读写工作空间文件；
- 面板展示的结论、覆盖、Mock 状态均来自 CLI 输出；
- 面板不实现判定、计数、真实性与范围计算；
- 轮询运行状态：运行中 2 秒、空闲 10 秒。

## 9 待细化

- 具体控件与布局在实现时按 Trae Webview 能力调整；
- 深色模式、缩放、键盘导航按宿主能力补齐；
