# 项目流程（一期）

> 状态：2026-11-19 设计；后端入口命令已实现，面板已在真实 Trae 打开并走通一次任务→报告流程；AC28—32 已完成真实 Trae 走查并登记；主责：从首次使用到报告、复测和备份的完整流程。本文细化[产品方案与界面设计](01-产品方案与界面设计.md)，不改变需求规格的 FR/AC。

## 1 总览

```text
首次配置
→ 项目
→ 开始测试
   ├─ 按目标测试
   ├─ 按范围测试
   └─ 快速检查
→ 任务（自动生成）
→ 交付 / 规则 / GitHub / 链路上下文
→ 计划
→ 执行前确认
→ 运行
→ 结果 / 报告
   ├─ 导出
   └─ 问题 / 复测
→ 历史 / 备份
```

项目、任务、计划、运行、报告、问题都保存在用户级工作空间；模型、GitHub、链路不可用时，本地记录、证据和报告仍可用。

## 2 首次使用

```text
安装扩展与运行时
→ 设置工作空间
→ 配置模型（可选，缺省时 AI 步骤标未生成）
→ 配置 GitHub（可选，只读）
→ 环境自检
→ 开始使用
```

- 环境自检检查 Python、包、工作空间、模型、GitHub、代理和项目配置；
- 低风险问题可一键修复，高风险只给命令；
- 没有可用 Python 或工作空间不可写时，不能开始测试；
- 模型不可用不阻塞本地测试，只关闭目标候选、代码分析和脚本生成等 AI 步骤。

## 3 项目

```text
选择目录
→ 登记项目
→ 识别模块（可编辑）
→ 项目配置
```

- 一个目录一个项目；根目录与子目录重叠时要求明确选择；
- 模块可由 AI 起草，用户确认后生效；
- 项目配置保存服务、项目级检查、运行器、证据、链路、模型和测试数据设置；
- 凭据不写入项目配置，不进入日志、证据或导出。

## 4 测试入口

```text
项目
└─ 开始测试
     ├─ 按目标测试：输入目标或点选候选（不默认选中）
     ├─ 按范围测试：进入范围页选择业务功能与验收项
     └─ 快速检查：项目级 L1，不建任务
```

### 4.1 快速检查

- 只做项目级 L1：构建、入口、最小测试；
- 不选业务功能，不生成验收项，不进入 `S/M`；
- 仍是一次正式运行，需要执行前确认；
- 结果单独展示，报告不把它算成验收项通过；
- 适合刚接手项目、只想确认“能不能跑”。

### 4.2 开始测试

项目概览只提供一个“开始测试”入口，进入后并列三个同级方式：

- 按目标测试：输入目标或选择候选，自动生成任务和计划；
- 按范围测试：进入范围页选择业务功能和验收项，再生成计划；
- 快速检查：只做项目级 L1，不建任务。

不在入口预选某一种方式，也不要求用户先理解内部概念。

## 5 按目标测试

```text
输入目标或选择候选
→ 自动生成任务（目标 + 验收项）
→ AI 分析相关代码，参考规则与模板
→ 生成计划
→ 执行前确认
→ 运行
```

AI 候选目标必须包含自定义入口，并展示：

- 目标标题；
- 推荐依据；
- 预计测试范围（涉及的业务功能、验收项数量）；
- 不确定项。

目标路径不单独选范围；任务的验收项就是本次范围，默认全部选中。

模型不可用时：

- 目标候选标“未生成”；
- 保留自定义目标输入；
- 项目信号不足时给通用目标“验证项目能否启动并跑通主流程”，并说明依据不足。

## 6 按范围测试

### 6.1 项目测试地图

AI 分析项目后生成测试地图：

| 内容 | 说明 |
| --- | --- |
| 业务功能 | 用户能理解的名称，例如“下单”“支付”“库存扣减” |
| 涉及模块 | 对应代码模块或目录 |
| 入口与测试命令 | 可执行入口、已有测试、构建方式 |
| 可测内容 | 该功能下可验证的验收项或检查点 |
| 依据与把握 | README、路由、测试、配置或推断 |
| 未知项 | 无法识别、没有入口、没有测试或证据不足的部分 |

业务功能是第一层，模块是第二层，用于下钻和定位。地图可编辑、可合并、可忽略；未知项必须列出。

### 6.2 范围页

```text
本次范围
├─ 推荐范围（AI 预选）
├─ 自己勾选（按业务功能，展开可看模块和验收项）
└─ 完整测试（当前理解范围内全选）
```

- 默认展示推荐范围，用户可以直接修改；
- 勾选单位首先是业务功能，展开后可细到验收项；
- 模块用于筛选和下钻；
- 选完显示“本次 N 项 / 当前理解 M 项”和未选项清单；
- 空范围不能生成计划。

“完整测试”表示当前项目理解范围内的全部可测内容。未识别或无法判断的部分不计入通过，报告中单独列出。

### 6.3 没有可测内容

- 地图为空：提示没有识别到可测业务功能，允许手动添加功能或改用目标输入；
- 只有模块：按模块展示，并标明业务功能识别不足；
- AI 分析失败：保留手动选择路径，不阻塞本地测试。

## 7 任务与上下文

| 入口 | 任务生成方式 |
| --- | --- |
| 按目标测试 | 选定目标后自动生成任务，目标即任务目标，验收项由 AI 提取 |
| 按范围测试 | 选定范围后自动生成任务，验收项来自所选内容 |
| 从已有任务进入 | 复用该任务，只调整本次范围 |

任务包含：

- 目标、验收项、执行人、验收人；
- 交付说明；
- 规则版本；
- GitHub 提交、PR、检查、部署版本（可选）；
- 测试数据与依赖。

任务规则：

- 用户不需要先建任务；任务列表用于回看、改名和继续测试；
- 只改标题、描述、执行人，不使计划失效；
- 改验收项、可观察性、模块或验证意图，旧计划过期；
- 本次范围变化生成新计划，旧计划和旧运行保留。

### 7.1 交付说明

- AI 可从提交和脚本起草；
- 缺运行方式或版本时标“交付信息不完整”，不阻止保存；
- 不完整时，依赖构建的用例在运行中阻塞并说明原因。

### 7.2 规则与模板

- 项目可绑定规则版本；
- 计划生成时引用规则与模板；
- 规则或模板变化会使旧计划过期，需要重新生成。

### 7.3 GitHub 与链路

- GitHub 只读提交、PR、检查和部署版本，用于固定被测提交；
- 链路在运行后导入日志和查询结果，标出节点、缺口、首个异常和位置；
- 两者不可用时标缺口或未生成，本地测试和报告继续。

## 8 计划

```text
范围
→ AI 按验收项生成用例
→ 引用验收项原文
→ 校验验证方式、依赖和 Mock 许可
→ 发布计划
```

计划记录：

- 计划编号、序号、修订；
- 任务修订与任务契约摘要；
- 范围、验收项、用例；
- 规则版本；
- 来源签名（项目、交付、规则、服务、项目级检查、运行器、项目根目录）；
- 依赖与副作用。

规则：

- 每个选中验收项至少一条用例；
- 预期必须引用验收项原文；引用不上标“预期未证实”，执行后最多算阻塞；
- 用例必须可执行；不合法返回错误并指出用例；
- 计划发布后冻结；范围或验收项变化生成新计划，不修改旧计划；
- 旧计划缺任务契约或来源签名变化时，运行前拒绝并提示重新生成。

## 9 执行前确认

```text
展示：范围、计划修订、依赖、副作用
→ 人勾选确认
→ CLI 带 --confirm 启动
```

- 确认必须由人完成，AI 不能代替；
- 确认绑定计划修订、范围、环境、凭据来源、副作用和依赖；
- 任一项变化重新确认；
- 没有确认时返回 `CONFIRMATION_REQUIRED`；
- 同一项目已有运行时不启动第二个运行。

## 10 运行

```text
项目级检查（L1）
→ 启动服务（如有）
→ 按计划顺序执行用例
→ 记录证据
→ 结束或按边界取消
```

- L1 不计入验收项覆盖；失败阻塞 `depends_on=build` 的用例，服务失败阻塞 `depends_on=service` 的用例；
- 用例按 L1/L2/L3 执行；L3 可自动化的跑脚本，不可自动化的标 `manual_pending`；
- 证据永久保留；单文件超限截断并标记；
- 取消在用例边界生效，保留已完成结果；
- worker 被杀且 PID 不在、心跳超时，标 `interrupted`；
- 运行结束后同步生成分析、问题和报告；后处理失败不改变运行状态，错误单独记录。

## 11 结果

结果页展示：

- 结论：`passed / failed / incomplete / not_applicable`；
- 本次范围 `S`、适用项 `M`、未覆盖清单；
- 通过、失败、阻塞、未完成的计数；
- 项目级检查单独一行，不进 `S/M`；
- 失败用例的预期、实际、证据；
- 人工用例的待记录状态；
- 报告、导出、调整范围、再次运行入口。

规则：

- 结论只对本次范围成立；
- `S < M` 只说“本范围通过”，不出现“全部通过”；
- 未执行、未知、阻塞不汇总成通过；
- 空分母不显示 100%。

## 12 报告与导出

### 12.1 报告

```text
运行结束
→ 生成报告
→ 结论 / 覆盖 / 验收项主表 / 用例明细 / 项目级检查
→ 问题 / 分析 / Mock 判定 / 链路 / 证据索引
→ 验收意见
```

- 结论段由核心生成：四值、所选范围、未覆盖数、失败数；
- 主表按验收项取最差结果，用例明细附表；
- AI 摘要只写事实，出现结论词整段不采用；
- 验收意见由人填写，AI 不代填；
- 每次运行生成报告；显式重新生成产生新版本，旧报告保留；
- 报告默认读最近一份，可切换历史版本。

### 12.2 导出

```text
选择报告版本
→ 填写保存路径
→ 导出 Markdown
→ 返回路径、字节数、行数、sha256
```

导出内容：

- 结论、运行 ID、范围、未覆盖数、失败数、源码提交、规则版本；
- 环境、服务、GitHub 提交与部署版本；
- 范围与覆盖、验收项主表、未覆盖清单、未验证清单；
- 分层计数、项目级检查、用例明细；
- 问题、分析、Mock 判定、调用链、证据索引；
- 验收意见；未填写时显示“未填写”。

规则：

- 从当前报告或历史报告版本导出；导出格式是 Markdown，不生成 ZIP，不打包证据；ZIP 属于备份；
- 目标目录不存在时自动创建；
- 导出前按项目配置脱敏，凭据正文不进入导出；
- 导出失败只提示路径或权限问题，不改变报告和运行结论；
- 导出成功后返回实际路径与摘要，用户可据此复查。

## 13 问题与复测

```text
失败用例
→ 按失败签名去重建问题
→ 同一签名追加发生记录
→ 待确认 → 处理中 → 待复测 → 已关闭
```

- 问题关闭必须有新运行的实际通过证据；
- 新运行必须晚于最后发生时间，且包含该用例；
- 复测按验收项新建运行，旧运行完整保留；
- 两次结果不一致标“疑似不稳定”，两次都保留；
- 非缺陷、重复、延期必须写理由。

## 14 历史与备份

- 历史按项目列出运行：任务、计划、时间、范围、结论、计数、耗时；
- 历史运行只读，使用运行时的计划/任务快照；
- 备份包含业务记录，证据可选；恢复后核对记录与引用；
- 未包含的证据标“证据未包含”；
- 旧格式拒绝并提示转换或重建，不静默迁移。

## 15 降级与异常

| 情况 | 行为 |
| --- | --- |
| 模型不可用 | AI 步骤标“未生成”；本地测试、证据、报告继续 |
| GitHub 不可用 | 提交/检查标缺口，不用缓存冒充最新 |
| 链路缺口 | 标未采集或无法关联，不拼接为同一次调用 |
| 服务启动失败 | 依赖服务的用例阻塞，保留日志 |
| 脚本自身错误 | 标阻塞或错误，不算产品失败 |
| 磁盘不足 | 停止写入并报错，不删除已有证据 |
| 计划过期 | 拒绝运行，要求重新生成计划 |
| 同一项目已有运行 | 拒绝第二个运行，返回现有运行 ID |

## 16 状态关系

```text
项目
└─ 任务（可多修订）
   └─ 计划（可多版本）
      └─ 运行
         ├─ 用例 / 证据
         ├─ 问题
         └─ 报告
```

- 运行引用计划快照和任务快照，不随后续修改变化；
- 报告引用运行快照；
- 问题挂项目，关联失败用例与运行；
- 删除项目或任务不级联删除历史；清理必须显式确认。

## 17 边界

- 不常驻、不建数据库、不做账号、上传、共享审核；
- 不做格式迁移；旧格式拒绝并提示重建；
- 不自动修复高风险环境问题，只给命令；
- 不做跨命令的逐步驱动和暂停会话；
- 快速检查不进入验收项覆盖；
- “完整测试”只表示当前项目理解范围内的全部可测内容，不等于项目全部业务功能已证明。

## 19 后端能力与面板流程补全（2026-11-19）

> 背景：原型与旧流程只覆盖“建项目 → 任务 → 范围 → 计划 → 运行 → 结果 → 报告”的主干；CLI 已注册的项目配置、模块与地图、交付说明、规则与模板、GitHub、链路、人工用例、证据、分析、备份/清理缺少完整用户入口。
>
> 本节补齐这些能力的**用户动作、入口、状态和边界**。命令、字段与错误码仍以[CLI 与数据契约](03-CLI与数据契约.md)为准，不新增第二套契约。
>
> 状态：设计补全；面板先用 LocalStorageRepository 实现同一领域行为，真实 CLI 宿主接线后按同名字段映射。

### 19.1 补全原则

1. **命令有入口，能力有边界**：后端已注册的命令要么有面板入口，要么在设置/文档里明确“仅 CLI”或“未接入”，不留下看不见的能力。
2. **不伪造外部事实**：模型、GitHub、真实文件系统、真实测试执行不可用时，显示未连接/未生成/模拟，不用缓存或演示数据冒充最新或通过。
3. **计划仍是合同**：任务资料、交付说明、规则、模板、项目配置的修改，要么不使计划过期，要么明确提示“生成新计划后生效”；面板不改写已发布计划的用例。
4. **覆盖不扩散**：模板、链路、分析、证据、人工记录、GitHub 和备份都不进入 `S/M`；它们只提供上下文、定位、说明或附件。
5. **本地先行**：本期用 LocalStorageRepository 实现可测试的完整行为；组件不直接读写存储，业务判定集中在领域层，后续替换 Host/HTTP Repository 时页面不改。

### 19.2 命令覆盖矩阵

| 能力域 | CLI 命令 | 面板入口 | 目标行为 | 本次边界 |
| --- | --- | --- | --- | --- |
| 环境自检 | `doctor` | 设置 › 环境 | 展示 Python、包、模型、GitHub、工作空间、代理、项目配置、引用；缺项分条列出并给修复命令 | 浏览器环境按真实可用能力显示；模型/GitHub 标未接入；不自动修复 |
| 项目 | `project.add/list/show/update` | 建立项目、侧栏、设置 › 项目资料 | 登记、重名/重叠校验、改名/目标、归档过滤 | 本地仓库实现；目录存在性/可写性由本地校验模拟，不读磁盘 |

### 19.3 补全后的流程

#### 19.3.1 登记项目与理解项目

```text
建立项目
→ 校验目录/名称/重叠
→ 项目写入本地仓库，状态=分析中
→ 本地分析：模块、业务功能、可测项目录、目标候选、未知项
→ 概览显示候选摘要与项目理解
→ 可重新分析；模块可新增/编辑；业务功能只读
```

- 地图刷新失败不覆盖旧地图；没有可测内容时保留手写目标路径。
- 未知项必须列出，不能静默丢弃。
- 模块编辑属于任务契约的一部分；已有计划时提示“生成新计划后生效”。

#### 19.3.2 任务资料、验收项与交付

```text
任务资料
├─ 基本信息：标题、目标、意图、来源、执行人/评审人、范围、输入/输出、前置条件
├─ 验收项：新增/编辑/可观察性/所属模块
├─ 交付说明：草稿 → 人工修改 → 保存；缺运行命令/提交标不完整
└─ 检查模板：列出 → 逐项处置 → 摘要
```

- 只改标题、目标、执行人、评审人、输入/输出、前置条件：不使计划过期。
- 改验收项文本/可观察性/模块/意图：任务契约变化，计划过期，必须重新生成。
- 交付信息不完整不阻止保存；依赖构建/服务的用例在运行中按阻塞处理并写入报告“项目级检查”。
- 模板处置不进入必测分母；已有计划时模板只影响下一版计划。

#### 19.3.3 规则与项目配置

```text
设置
├─ 项目规则：列表 → 查看 → 新建版本/导入 → 绑定 → 导出
└─ 运行配置：常用项表单 + 高级 JSON → 校验白名单 → 保存
```

- 规则有版本，绑定只影响新计划；旧运行保留自己的规则版本。
- 配置允许 `model / services / link / runners / evidence / l1 / data`；含密钥样式的键拒绝保存。
- 修改 `services/l1/runners` 或项目根目录会改变计划来源签名；开始运行时提示重新生成计划。

#### 19.3.4 计划、确认与运行

```text
范围（推荐/自己勾/完整测试）
→ 生成计划（事实签名 + 用例 + 未选模块提示）
→ 计划只读检查
→ 人工勾选确认（计划版本、范围、依赖、副作用、环境/凭据摘要）
→ 发布计划并启动运行
→ 运行中：L1 单独展示、当前用例、进度、停止
→ 结束：取消/中断/完成 → 结果 → 报告
```

- 确认绑定计划 ID/修订、验收项集合、环境摘要、凭据来源、副作用和依赖；任一变化重新确认。
- 同一项目只允许一个运行；运行中不能切换任务、新建任务或快速检查。
- 人工用例在运行结束后记录；自动用例不提供人工改结果入口。
- 停止在用例边界生效：当前用例按阻塞，剩余未运行，已完成保留，仍生成报告。

#### 19.3.5 结果、证据、分析与链路

```text
结果
├─ 结论 / 本次 N / 共 M / 未覆盖 / 未核实
├─ 验收项台账（最差结果排序、失败默认展开）
├─ 待人工用例 → 记录结果与证据
├─ 证据 → 补充/查看元数据/缺失截断标记
└─ 报告
   ├─ 失败分析（本地分析，不改变结论）
   ├─ 调用链（导入 JSON / 节点断言）
   ├─ 报告版本 / 重新生成 / 验收意见 / 导出
   └─ 来源与环境 / GitHub 快照 / 模板处置 / 证据索引
```

- 证据只展示引用、类型、大小、sha256、存在/截断状态；浏览器内不内嵌大图。
- 分析状态 `generated / not_generated / invalid` 必须显示原因；无失败时标“无失败可分析”。
- 链路缺口、首错节点、定位必须分开写；导入失败不改报告结论。
- 重新生成报告产生新版本，旧版本只读；验收意见由人填写。

#### 19.3.6 问题与复测

```text
失败用例
→ 失败签名去重
→ 新问题（待确认）或追加发生记录
→ 待确认 → 处理中 → 待复测 → 已关闭
→ 关闭必须绑定新运行：晚于最后发生、包含该用例、通过且有证据
```

- 处理中/待复测/已关闭/重开必须写理由；非缺陷/重复/延期也必须写理由。
- 关闭门禁不满足时禁用按钮并解释缺什么；提供“去重跑这一项”。
- 两次结果不一致标“疑似不稳定”，两次都保留。

#### 19.3.7 历史、备份与清理

```text
历史
├─ 今天/昨天/更早分组
├─ 任务/结果筛选
├─ 旧运行只读快照（计划/任务/结论/计数/用例）
└─ 中断运行：不提供恢复、没有报告

设置 › 备份
├─ 创建备份（本地 JSON，含业务记录，可选证据元数据）
├─ 从备份恢复（校验 schema、清单、缺口）
└─ 清空本地面板数据（二次确认）

设置 › 数据边界
└─ 工作空间、运行锁、凭据、清理命令说明
```

- 备份恢复后核对记录与引用；缺失证据标“证据未包含”。
- 旧格式拒绝并提示重建，不做静默迁移。
- 真实 ZIP 备份、任意路径恢复、按运行清理命令仍由 CLI 完成；面板不执行 shell。

#### 19.3.8 环境与 GitHub

```text
设置 › 环境
→ 自检项逐条显示
→ 缺项给命令
→ 重新检查（不自动修复高风险）

设置 › GitHub
→ 未连接：说明只读能力不可用，本地测试不受影响
→ 有缓存：显示仓库/提交/文件/检查/读取时间，标“未确认最新”
→ 读取失败：保留旧缓存并标缺口，不冒充最新
```

- 模型不可用只关闭目标候选、代码分析、脚本生成、失败分析等 AI 步骤，不阻塞本地测试。
- GitHub 不可用只关闭提交/检查/部署上下文，不阻塞运行与报告。
