# 一期架构05：Trae接入

版本：3.3  
更新日期：2026年9月23日  
文档类型：工程设计文档

覆盖一期真实编辑器接入；基线Windows 11 x64、Python 3.13和实测确定的Trae发行版/版本。国际版与中国版须在兼容清单区分，不把同名产品当同一接口保证。

## 1 接入方式

integrations/trae承载命令注册、目录事件与面板宿主；interfaces/local承载本地API、管道与生命周期，resources/panel是唯一面板源码。扩展可用的命令/面板API必须在选定Trae版本实测，不假设任何其他编辑器专有注册API存在。

Trae官方文档提供MCP设置中的手动JSON配置和stdio服务方式；一期MCP基线采用固定程序入口的本地stdio relay，接入同一核心，不另起写入者。安装指引给出配置供用户确认，不自动覆盖项目已有配置；项目级配置启用遵守宿主信任提示。

```json
{
  "mcpServers": {
    "aitest-local": {
      "command": "aitest",
      "args": ["mcp-relay", "--binding", "<binding_id>"]
    }
  }
}
```

此处aitest命令与参数是拟实现的插件CLI合同，须随制品提供并验收，不代表机器已安装。command应是可解析可执行文件，参数单列；有空格安装路径的行为必须按实测处理，不能拼接shell字符串。配置不放令牌/密钥/私有正文，env只允许必要非敏感值。

参考：[Trae官方MCP添加说明](https://docs.trae.cn/ide_add-mcp-servers)。官方配置能力与扩展Webview/生命周期能力分别验收；文档没有确认可用的Trae自动注册API，因此不编造其名称或签名。

### 子域结构

```text
interfaces/
  local/
    api.py             # 同进程统一 API
    pipe.py            # 命名管道消息与实例发现
    editor_host.py     # 扩展连接与本地进程生命周期
  tools/
    cli.py             # 命令行入口（含 aitest doctor、migrate）
    agent_relay.py     # 本地 stdio 转发；只依赖 DTO，不写业务文件
  dto.py               # 出参投影：领域对象 → 稳定 DTO
contracts/             # DTO 与生成的 JSON Schema
resources/panel/       # 唯一一份面板源码及构建资源
integrations/trae/   # 编辑器事件、面板宿主、MCP 工具登记
```

### Trae 接入

本地进程关系：

```text
面板 → Trae 扩展 ───────────────────┐
                                    ↓
Trae AI → stdio MCP relay → 本地命名管道 → editor-host 核心
CLI 转发 ────────────────────────────┘       │
                                          同一文件工作空间
```

- 一个本地文件工作空间只有一个核心进程。relay 只转发消息，不持有业务写锁、不保存业务状态，也不启动第二个调度器。
- 多个目录绑定使用同一核心，按本地项目隔离记录。
- 第二窗口访问时可连接已验证的现有核心；发现不一致或无法接入时返回 `WORKSPACE_IN_USE`，不能另建写入者。
- Windows 命名管道限定当前操作系统登录会话并拒绝远程客户端；发现信息包含工作空间、随机实例、PID、启动标识与 writer epoch。
- 客户端核实进程及实例，消息核实会话与绑定；原生实现封装在可选 `editor` 安装项。
- **本地业务不监听 TCP 端口**；命名管道、stdio 与 Webview 传递结构化记录与附件引用，附件按需分块获取。

## 2 核心与本地通道

面板→扩展→命名管道→核心；Trae AI→stdio relay→同一管道；CLI同样转发。发现信息含workspace_id、随机实例、PID/启动身份、writer_epoch。限制本机当前用户/登录会话，拒绝远程客户端；核对实例/进程/项目绑定，不能仅看锁文件存在。

多个目录在同一核心按项目隔离。第二窗口核实既有核心后连接，不能接入则报WORKSPACE_IN_USE。卸载不依赖停用回调必执行：外部维护命令仅清无效发现/本插件登记，不删除业务数据或活锁。编辑器退出不等于取消测试。

## 3 接口与动作

协议aitest.local/2.0，命令含request_id、action、project_id、binding_revision、target、expected_revision、intent_id（业务写动作适用）、参数。响应含相同请求、实例/工作空间、项目/绑定、对象修订、run_id或结果/结构化错误。事件含实例、workspace、writer_epoch、单调提交/事件序号、项目、修订和类型。

| 动作组 | 最小动作 |
| --- | --- |
| 项目/内容 | bind_project、save_context、save_delivery、save_acceptance、analyze_project、save_model_outbound_policy、save_project_view_preference、save_rules、publish_rules、generate_draft |
| 计划 | save_plan、publish_plan、prepare_run、start_run、revise_pending_steps、narrow_driver、authorize_step |
| 执行 | pause_run、resume_run、cancel_run、retry_step、attach_evidence、verify_pending、return_stage |
| 问题/报告 | update_issue、record_fix、request_regression、close_issue、create_report、record_local_review、export_report、copy_repair_brief |
| 查询/维护 | query、events、doctor、test_connection、storage_usage、backup、migrate |

Schema定义字段和错误：code、脱敏message、retryable、相关记录及下一步。协议主版本不兼容拒绝写动作；后续新增动作通过能力声明，旧语义不变。传输同request_id异参数冲突；业务intent在应用层持久去重。

## 4 面板、安全和降级

Webview仅包内资源，CSP、Schema消息校验、净化文本；不直接模型请求/任意文件读取/凭据解析。事件只发增量摘要，大对象按需分块，分页查询。游标失效SNAPSHOT_REQUIRED，重新取得同边界快照与游标后续读（见面板架构第4节）；项目切换迟到响应只更新原缓存，不污染当前视图。

缺MCP登记可以手动配置或用面板/CLI，不影响核心。面板API缺失时命令/CLI作为诊断和临时替代，但一期面板交付承诺仍须在选定Trae实测通过，不能用CLI成功替代全部面板验收。源码只读允许物化运行，数据目录不可写拒绝新写操作，未信任工作区不执行项目入口。

### 视图同步与调试

- 面板只做展示与明确操作输入，业务状态由核心计算；列表分页、链路按需展开，事件推送发送增量摘要。
- 相同对象的可合并更新可合并，原始业务事件不丢弃。
- 按「实例、工作空间、事件编号」去重；游标失效时返回 `SNAPSHOT_REQUIRED`，重新查询已提交快照后续读。
- 每次响应携带本地项目与绑定修订；目录切换后的迟到响应只更新原记录缓存，不进入当前视图。
- 断网显示最近确认状态与时间；恢复时先核对本地项目再查询原运行。
- 重试策略统一使用功能文档第4节（暂停、重试与恢复）的规则，周期与错误分类由 `connectivity` 统一实现，不由 Webview、扩展与 Python 各自重复启动重试循环。
- 面板可在独立开发壳中使用契约夹具调试，再在真实 Trae 验证接入。

## 5 验证与兼容清单

doctor统一返回READY/DEGRADED/NOT_READY及原因，检查核心/锁/提交指针、索引/证据可用性、环境和可选连接；模型失败只降AI。完整扫描为显式维护，不为面板刷新扫描全部历史。

compatibility.json是将来实现时维护的实测制品，不用文档推测填pass。字段：os/os_version/runtime/editor/editor_distribution/editor_version/core_version/adapter_versions/artifact_digest/evidence_path/verified_at/result。覆盖安装、面板、命令、stdio MCP、目录切换、停用升级卸载、管道权限/实例校验、进程停止、文件系统刷新和恢复；未测untested。

P1-AC01—35全部按需求执行；提交中断、同意图/明确重跑、同元数据异内容、密钥不外泄、双入口单写等专项分别由本册和存储、项目分册规定。

## 6 安装、连接与生命周期

| 阶段 | 实现步骤 | 失败与保留 |
| --- | --- | --- |
| 安装/启用 | 核对Trae发行版、运行时、核心/扩展制品和协议；注册本插件命令，加载共享面板 | 不兼容明确提示，未测不宣称可用；不覆盖其他扩展配置 |
| 目录绑定 | 规范化当前目录、选择/建立稳定项目，取得binding_revision | 多目录显式选择，显示名不是键；未信任项目不执行入口 |
| 发现核心 | 读取发现信息→核实实际进程/启动身份/实例/工作空间→能力握手 | 旧发现可清理但活锁不可删除；无法核实不另开写入者 |
| 配置MCP | 展示固定command和分离args，用户确认宿主配置；绑定编号为参数 | 不假设Trae有其他编辑器私有API；MCP stdout只用于协议，诊断写stderr |
| 面板订阅 | 同一提交边界返回快照与snapshot_cursor，从该游标之后重放并订阅；附件按需分块 | 重复事件去重；失效游标重建快照再续读 |
| 目录切换 | 取消旧视图订阅，获取新绑定快照；保留旧项目活动运行事实 | 迟到响应只归原缓存，不能把旧run显示在新目录 |
| 停用/升级 | 断开本入口订阅，注销自己确实创建的宿主登记；保存所需检查点 | 不把编辑器退出当取消；维护/迁移不得绕过活动执行保护 |
| 卸载准备 | 展示数据保留位置，提供无效发现/本插件配置的维护说明 | 不依赖停用回调；不删除业务材料或其他插件配置 |

任何自动注册增强必须有该Trae版本的实际能力证据；手动JSON是既定基线，不能把文档示例当作已安装能力。扩展版本、核心版本与面板资源摘要共同进入兼容记录。

### 诊断、安装与维护

- `aitest doctor`、面板诊断与健康检查使用同一健康模型，返回 `READY`、`DEGRADED` 或 `NOT_READY`、检查时间及原因；检查核心生命周期、写入就绪、索引与对象完整性、模型连接、GitHub 只读接入、最近备份结果，以及**工作空间是否位于同步盘／网络盘**（命中即 `NOT_READY` 并给出"移出同步目录"的下一步）。
- 模型失败只降级 AI，不将全部本地功能标为不可用。
- 结构化日志记录请求、运行、尝试、本地项目、错误分类及相关修订；本地写 stderr 与诊断文件。诊断不返回私有正文、敏感地址参数或模型密钥。
- 自检使用配置的截止时间，超时返回已完成阶段及具体卡点。
- 停用或升级先保存检查点与未保存材料，注销本插件的 MCP 登记与视图订阅；升级执行结构兼容检查，迁移失败保持可诊断的只读状态。
- 卸载准备展示未保存材料与保留位置；**直接卸载不依赖编辑器一定执行停用回调**，提供外部清理命令清除登记及无效进程发现记录，业务数据保留。
- 旧进程仍存活时不得通过清理命令删除其真实锁。
- `docs/compatibility.json` 为工程接入证据清单，**最小字段集**为：`os`、`os_version`、`runtime`（Python 版本）、`editor`、`editor_version`、`core_version`、`adapter_versions`、`artifact_digest`、`evidence_path`、`verified_at`、`result`（`pass`／`fail`／`untested`）；未实测组合必须显式登记为 `untested`，不得声明通过。

## 7 消息字段与恢复语义

| 消息 | 最小内容与守卫 |
| --- | --- |
| 命令 | protocol_version、request_id、action、project_id、binding_revision、target、expected_revision、适用的intent_id与参数；校验类型及项目归属 |
| 响应 | 原request_id、实例/工作空间、项目/绑定、对象修订、run_id或结果；错误含code/message/retryable/关联记录/下一步 |
| 事件 | 实例/workspace/epoch、单调序号、项目、对象修订与类型；只发送已提交事件 |
| 能力 | 协议主版本、核心/适配器版本、支持动作与执行入口类型、对象分块能力；不暴露凭据 |
| 对象获取 | 项目、受控对象引用、请求范围与来源修订；校验归属，不能传任意路径要求核心读取 |

主版本不兼容拒绝写动作，新增字段允许旧客户端忽略，但未知关键动作明确报能力不足。request_id只去重传输；intent_id在应用层与业务结果原子保存。主版本/能力/业务修订冲突分别提示，不靠页面无限重试掩盖。

连接错误至少区分核心未就绪、地址/DNS/代理/TLS、认证、限流、能力缺失、修订冲突、摘要不符、材料不完整、结果未知和存储不可写。日志带请求/项目/Run/Attempt及相关修订，敏感正文不进入日志。重试策略只由connectivity执行。

### 统一动作与接口契约

| 契约 | 必需字段 |
| --- | --- |
| 命令 | 协议版本、`request_id`、动作、本地项目与绑定修订、目标对象、`expected_revision`、幂等键、参数 |
| 响应 | 请求编号（`request_id`）、实例、工作空间、本地项目、对象修订、执行编号（`run_id`）、错误或结果 |
| 事件 | 实例、工作空间、单调事件编号、本地项目、对象修订及事件类型 |
| 能力 | 协议、核心与适配器版本、支持动作、执行入口类型、模型来源、对象传输能力 |

- 所有动作参数经 Schema 验证；命令文本与文档内容不能动态增加工具。
- **最小实现范围（一期）**：能力协商包含主版本兼容及当前支持动作集合，主版本不兼容拒绝动作、未知动作返回能力不足，事件续读只做"单调编号 + `SNAPSHOT_REQUIRED` 重建"，幂等键只覆盖面板／CLI／MCP 实际暴露的动作；其余字段（能力清单细化、多实例路由、事件压缩）在后续期次按需启用，不得在一期为其设计分支。
- 业务幂等记录与业务结果在同一工作单元持久化，业务键为(project_id, action, intent_id)，冻结payload_hash；同键异输入冲突。request_id仅去重传输，不将临时核心实例或新请求号当成新业务意图。prepare_run以持久client_id、prepare_request_id取得同一意图，详见项目与计划的准备请求合同。
- 错误结构包含 `code`、脱敏 `message`、`retryable`、相关记录与可执行下一步；至少区分进程未启动、地址／DNS／代理／TLS、能力缺失、版本冲突、摘要不符、材料不完整与结果未知。

| --- | --- |
| 能力握手 | 协议与能力协商，不暴露密钥 |
| 查询与事件 | 本地项目、运行、证据、问题及报告查询与事件续读 |
| 动作 | 发布计划、执行控制、问题更新、导出及明确的用户操作 |

| 问题闭环 | 页面异常生成可编辑缺陷草稿；复测失败重开并保留原记录；AI 根因只作待验证假设且可被驳回留痕 | P1-AC08、P1-AC10、P1-AC11 |
| 模型接口 | 真实请求与输出 Schema；注入失效密钥、超时、限流、无效与迟到响应；模型失败不阻塞人工处理 | P1-AC10、P1-AC15 |
| 执行控制 | 暂停在步骤边界生效并区分暂停中／已暂停；未确认停止时不伪造已取消；重试产生新尝试且旧通过结果不回退；退回阶段使下游需重跑 | P1-AC19 |
| 运行中修订 | 修改只影响尚未执行的步骤；正在执行的步骤拒绝修改；驱动只允许单向切换；依据失效时暂停、列出需重跑用例并在报告中标注依据已过期 | P1-AC20 |
| 档位边界与必测下限 | **只有完整验证打分**（可达 A），快速检查与按需自测不打分、只给覆盖摘要；勾满范围也不判完整通过；适用必测项低于模板下限或关键链路未覆盖时报告"必测覆盖率警告"，完整报告据此下调等级；缺独立核验方式的用例不计已验证；无请求标识与日志时降级为人工关联并标注证据级别 | P1-AC23、P1-AC24 |
| 目录形态 | 目录不是 Git 仓库时可完成全部适用检查与导出；以文件清单摘要判定代码是否已变；界面与报告不出现仓库、分支、提交、远端内容，也不显示空值；不建立任何 Git 连接 | P1-AC25 |
| 复核独立 | 复核不写入报告正文、不改变报告内容修订；证据或问题变化时生成新的报告内容修订，旧修订可追溯 | P1-AC29 |

编辑器安装、停用／升级／卸载与能力探测的验证方法见第6节；无外网可用与缺能力报错由 P1-AC13（环境阻塞）与 P1-AC02／P1-AC07（执行与证据）覆盖下的自检项承载。

## 9 入口权限与人工确认来源

共享核心动作不表示每个入口可调用全部动作。核心握手区分human_ui、interactive_cli和agent_relay；通道类别由受控入口注册与会话上下文确定，不接受消息参数自报角色。此处防止把智能体工具调用误当用户确认，不承诺隔离同一OS用户下的恶意进程。

| 入口 | 允许行为 | 人工确认边界 |
| --- | --- | --- |
| 面板/受控扩展 | 查询、编辑、请求执行及展示核心确认挑战 | 仅实际用户操作可提交确认；Webview消息校验所属会话、挑战及动作摘要 |
| 交互CLI | 同一核心用例，展示待确认目标/输入并取得用户交互 | 无交互终端不提交人工确认；不提供--yes或正文user_confirmed替代 |
| MCP/agent_relay及非交互调用 | 查询、提交草稿/执行请求、使用已有有效授权启动或续行 | 不暴露或代理人工确认动作；未授权返回AWAITING_USER_CONFIRMATION及面板/交互入口 |

人工确认动作包括authorize_step、计划/规则发布确认、断言依据确认、问题级别与处置确认、本地复核、模型出站策略确认，以及三期发送策略和提交确认。AI可准备草稿或发起请求，不得替代用户作这些决定。共享用例仍在核心校验权限，不能只从MCP工具列表隐藏名称。

核心生成ApprovalChallenge：challenge_id、action、project/intent或submission、target、input_digest、credential_scope、相关修订、origin_session、状态。用户查看冻结摘要后确认；核心以同一工作单元校验当前修订、消费挑战并保存ConfirmationRecord/ActionAuthorization及幂等结果。同一确认请求重传返回原记录；另一个动作或改动后的输入不能复用挑战。挑战不经relay转发，不以nonce存在本身认定用户同意。切换项目、输入改变或确认通道失效时旧挑战不可用；尚未执行且内容不变的既有有效授权不重复询问。

ConfirmationRecord保留核心分配的入口/会话、用户交互来源、动作和冻结摘要、对象修订、提交序号；客户端提供的姓名仅为展示，不作授权凭据。不新增平台账号、服务或授权微服务。P1-AC31/32及P3-AC07覆盖伪造来源、挑战错配、重复确认与实际用户确认路径。

## 10 接口类型与兼容处理

当前动作目录由第3节维护；新增动作通过能力协商暴露，已发布动作不改变既有语义。CoverageDTO以[报告与缺陷](03-报告与缺陷.md#11-coveragedto字段合同)为唯一字段定义；Attempt使用attempt_index、retry_count、transport_retry_count。旧retry_index仅在已知Schema明确为从1起的尝试序号时转换，不能把未知字段默认为0。

项目/工作空间的持久身份不等于core_instance_id或writer_epoch。prepare请求按[项目与计划](01-项目与计划.md#11-准备请求与业务身份合同)恢复，同intent跨入口仍同Run。二期LocationDTO由定位分册定义；兼容层可将旧line/anchor_symbol/unknown_reason映射为line_hint/symbol/reason，旧文本原因包装为明确原因码和说明。旧snapshot_state=current不能证明内容一致，仅在确有元数据核验依据时转换为metadata_match，否则unknown；不得直接转为current_verified。当前Schema仅输出主责定义的字段。

Schema合同样例使用同一判定输入生成面板与报告DTO：正常、失败、阻塞、依据未确认、有效复用、未知副作用和缺字段。缺关键字段返回不完整/未知原因，不靠页面推断或重复计算补齐。编辑器支持与平台存储能力仍须实际版本验收，文档示例不代表运行通过。

## 11 核心保活与退出合同

core由既有bootstrap/editor_host按工作空间发现和启动；所有入口执行同一流程。启动协调锁保护“查找—启动”竞争，候选核心取得真实业务写锁并公布实例身份后才就绪，失败候选退出；客户端不得仅因发现文件陈旧就杀掉原进程。核心生命周期不隶属于编辑器/CLI的临时会话或其退出作业组，具体启动、进程组和句柄继承必须按目标系统实测；不安装常驻系统服务或新增守护进程。

| 工作空间状态 | 核心行为 | 后续唤醒/停止 |
| --- | --- | --- |
| 有客户端连接 | 保持服务；长动作在事务外，事件按既有游标续读 | 入口退出只断本入口，不取消业务 |
| 无客户端，有活动执行/包装器、待收尾输出或可按有效授权继续的步骤 | 保活并继续原计划；关闭编辑器不暂停整条计划 | 等待收尾或新客户端；取消只能经既有控制守卫 |
| 无客户端，仅暂停、人工待办、无已知本地活动执行器的待核实结果 | 持久化状态及恢复入口，写入收尾后可正常退出 | 用户打开面板/交互CLI触发同一发现启动流程；不靠后台空轮询假装解决未知结果 |
| 无客户端，有已许可的发送/查询/补缺或有限退避 | 保活完成本轮有界循环，失败次数/下次可尝试条件持久化 | 许可撤销或本周期完成后按其他条件退出；重启不清次数、不自动再授权 |
| 无客户端，仅无许可候选或需人工恢复的上传 | 保存候选/许可状态后可退出 | 用户明确进入上传/确认流程；登录不自动恢复许可 |
| 无客户端、无活动工作、无未提交收尾 | 正常退出，退出前发布必要检查点，停止接纳新动作并排空写队列 | 后续入口重新发现/启动，业务记录不变 |
| 活动执行器状态不明，可能仍占用workdir | 先完成有限核实；无法证明停止时保留目录和待核实记录，可在安全持久化后退出，但禁止维护切换/回收 | 重启再次核实，不把进程退出当业务停止 |

退出与新连接串行裁决：进入draining后拒绝新写动作并返回可重连原因；新入口等待发现信息和真实锁状态确认后重连或启动，不夺活锁。核心只清理自己的发现登记，不删除其他实例登记或业务材料。正常退出不得主动杀掉仍需保活的执行组；维护退出必须先满足执行与输出收尾门禁。

客户端重开按workspace/run取得既有事实，既不新建Attempt也不改变暂停/待核实/上传许可。P1-AC19/34覆盖关窗、宿主崩溃、CLI先退出、双窗口退出、draining期间重连、暂停无人连接、失联执行器和上传退避。未通过某系统生命周期验证，不得在该组合宣称“关闭后继续执行”；二期新增系统沿同合同逐组合取证。

### 上传空闲与生命周期

三期无候选业务增量不提交纯游标记录，不以游标追逐自身或长期UNKNOWN维持核心活跃。发送/查询服从同一持久有界失败/无进展周期，耗尽后暂停；无其他可推进工作时按本节收尾退出。实际算法见[候选扫描](../../三期/架构文档/02-结果上传.md#13-候选扫描的停止与提交边界)与[接收进展](../../三期/架构文档/02-结果上传.md#14-传输成功与接收进展)，入口不另启轮询。
