# 一期架构03：报告与缺陷

版本：3.4  
更新日期：2026年9月23日  
文档类型：工程设计文档

覆盖P1-FR14—15。domain/review/reports负责业务结果、证据等级、覆盖与BlockingRule；defects负责问题状态和关闭守卫。应用reporting/defect_management经同一工作单元写入，UI只读DecisionDTO。

## 1 判定输入与输出

输入固定：档位、源码核实、计划及运行修订、模板/适用必测集合、当前尝试、证据完整性、关键链路要求/独立核验、依据确认、环境事实、问题修订、过期依据及policy_version。输出业务结论、结论上限、仅full的证据等级、主要/全部缺口、覆盖计数、来源修订。规则直接遵守[功能§3](../功能文档/01-功能文档.md)，不在界面或适配器复制。

A证据充分可以证明业务失败；P0/P1阻止业务通过但不让充分失败证据变D。无有效依据/快照不一致D；关键缺口C；局部缺口B；只有显式完整守卫满足才A，未知不得默认A。全通过且无缺口允许主要缺口“无”。

### 模块职责

本册负责"执行之后"的结论：报告如何快照与导出、问题如何统一编号与流转、关闭依据如何校验。

## 2 报告和当前结论

ReportSnapshot保存报告ID/内容修订、Run、基础/运行中计划修订、当前Attempt引用、源码/环境/规则/验收、证据/问题精确修订、策略版本、业务结论、证据等级及覆盖。OutdatedBasis保存原依据/原因/来源，不改原断言，但不能作为当前通过依据。

当前结论键=project_id＋source_identity＋scope＋environment_revision＋rule/acceptance/template_revisions＋policy_version。源码身份包含Git未提交差异或plain内容清单及排除规则；同提交不同diff不合并。新full启动显示重新验证，终止或未知不回退旧通过；quick/on_demand只补充。历史分组与当前结论键是不同用途。

报告不可变。新的有效证据、当前尝试或问题修订改变结论时创建新报告修订，不重写旧Run执行事实。外部损坏只标旧材料可用性缺口并产生当前有效性投影，不能篡改历史正文或仍称完整。永久保存不保证外部删除永不发生。

### 报告快照与导出

| 记录 | 核心字段 |
| --- | --- |
| `ReportSnapshot` | 报告编号、内容修订、范围与冻结计划引用、基础计划修订与运行中修订序列、各层当前尝试、证据清单、问题修订、计算策略、源码与环境引用、**证据等级与主要缺口（仅完整验证报告；快速检查与按需自测标注"未打分"并附覆盖摘要）、断言可信度（已确认／总数）、必要追溯时间戳（开始、结束或采集时间）** |
| `OutdatedBasis` | 判定对象（步骤／断言／问题）、原依据修订、失效原因（需求或验收项变更、运行中修订、源码或规则变更）、标记时间；在报告中与"未验证"并列展示，不改变已完成步骤的原始结论 |
| `LocalReview` | 复核人（本地责任人）、结论、说明、报告内容修订、时间 |
| `ReportExport` | 导出编号、格式、内容修订、脱敏策略、生成时间与路径 |

规则：正文引用精确来源并保持不可变；当前有效性与历史事实分别呈现。导出按正文、复核集合、格式和脱敏策略取唯一产物，不把页面当前值直接覆盖报告快照。

## 3 本地复核与导出

LocalReview独立记录review_id、复核人、结论、说明、report_revision、本机记录时间。复核不改正文修订、不改事实，也不能把失败/缺证据改通过。

ReportExport冻结report_revision、附带review_ids、格式、脱敏策略版本、产物摘要和位置；相同冻结输入复用产物，新增复核需要新导出记录而非改旧正文。导出密钥底线不可关闭，附原始证据索引，不能仅提供不可访问链接。

二期可在附件索引引用diagram_definition_revision＋diagram_revision。布局更新只提示可选新图，不自动刷报告；用户明确选新图生成新的报告修订，旧版不变。

## 4 问题闭环

IssueRecord统一issue_id和内容修订，关联验收、用例、Run/Step/Attempt、复现版本环境、事实/假设、证据、级别/责任人、修复版本和回归；缺陷单只是表单视图。无法核实位置保留未知。

草稿→待确认→已确认→处理中→待复测→已关闭；复测失败回处理中。确认级别与责任人由用户；暂缓/重复/非缺陷保留原因。修复关闭守卫要求新的实际执行证据，且按原关闭标准验证；继承旧证据、修复说明或AI判断不能关闭。BlockingRule唯一按一期功能第12.2节计算有效P0/P1阻塞：active/deferred未解决问题阻塞，duplicate沿主问题归并，核实non_defect不作为产品缺陷阻塞；任何处置都不改原断言。

### 缺陷状态与关闭依据

```text
草稿 → 待确认 → 已确认 → 处理中 → 待复测 → 已关闭
                          ↑           │
                          └─ 复测失败 ─┘
不属于缺陷 / 重复 / 暂缓：保留原因与记录，不删除
```

| 迁移 | 校验条件 |
| --- | --- |
| 草稿 → 待确认 | 来源为失败步骤或人工记录，且带证据引用 |
| 待确认 → 已确认 | 用户确认级别与本地责任人；未确认不得进入处理 |
| 已确认 → 处理中 | 记录处理开始时间 |
| 处理中 → 待复测 | 登记修复版本与回归方式 |
| **待复测 → 已关闭** | **必须存在新的实际执行证据**，证明满足关闭条件；修复说明或 AI 判断不作为替代 |
| 待复测 → 处理中 | 复测失败时保留原失败与修复记录，重新进入处理 |

约束：修复关闭须新的实际证据；非缺陷、重复和暂缓沿一期功能第12.2节分别记录，不改原断言。归并拒绝自指/循环，撤销处置或主问题重开重新计算有效阻塞。

## 5 范围、环境和可携带导出

DecisionDTO与ReportSnapshot独立包含scope_revision/名称、EnvironmentFacts和证据缺口；环境类型本身不触发等级降级，按具体证据有效性和验收条件计算。报告页首固定范围名称与本轮结果，不能把局部验收描述成全项目已通过。

ReportExport的kind为markdown_summary或evidence_bundle。前者声明附件未随文件交付；后者为ZIP，含report.md、manifest.json、evidence/相对路径附件。manifest记录包格式版本、报告/复核精确修订、范围、投影策略、每项路径/大小/SHA-256及缺失/排除原因；摘要按实际导出字节计算，与本地原始对象摘要区分。导出键还包含kind、所选附件引用和策略。附件投影与正文均脱敏；不可安全处理的材料排除并说明。

导出器只写到事务临时位置；所有包路径必须为规范相对路径，拒绝绝对路径、盘符、穿越、重复覆盖与符号链接引用。完成清单和对象校验后发布产物并登记；失败不暴露为成功包。迁移到空目录检验相对链接，不要求安装插件才能阅读Markdown与普通附件。包是只读交付物，本期不新增导入恢复或可执行安装功能。

copy_repair_brief复用已有报告脱敏器，从指定Issue/Attempt投影文本，附可解释的复测指引；位置未知保持未知。不直接把原始日志或密钥复制到剪贴板。

## 6 工程落点

reporting与defect_management位于application/review。脱敏经application/ports.py中的ProjectionPort调用，导出制品经ReportArtifactPort生成并校验，由bootstrap注入infrastructure/projections.py与exports.py；应用用例不直接导入基础设施。制品完成后再登记成功导出，跨目录写入不假定与工作空间同一原子事务。完整目录及职责见[总体架构§11—12](../../总体架构.md)。

## 8 关闭、导出与有效性验证

| 边界 | 实现检查 |
| --- | --- |
| 修复关闭问题 | 读取指定新回归Attempt及可读证据，核对原验收/关闭条件与实际修复版本；文本说明不作凭据 |
| 生成新报告 | 新有效证据或问题修订改变结论，保存新内容修订；原报告及其LocalReview保留 |
| 新增本地复核 | 只新增LocalReview；带复核的导出改变复核集合时创建新导出，不改正文 |
| 证据外部损坏 | 保留历史正文，增加可用性缺口；当前有效性投影不能继续称证据齐全 |
| 导出失败/中断 | 完整校验临时产物后才发布并登记；未登记成功不得对用户报成功。恢复核对文件摘要后幂等登记或保持失败 |
| 跨目录导出 | 分别核对目标产物发布和工作空间登记，不假设两者同一原子事务；出现孤立文件时不当作已成功导出记录 |
| 报告与图 | 只引用用户选择的精确图修订；布局变化不自行改报告或结论 |

证据包验收将包解压至新空目录，检查report.md相对附件链接、manifest全部摘要、排除/缺失原因与复核集合；普通Markdown和附件应脱离插件可读。报告只是可追溯的本地过程记录，不引入签名、防篡改组织认证或平台审核保证。

## 9 处置、统计与报告输入补充

IssueDisposition引用issue_id/revision、disposition、确认记录、理由、证据、canonical_issue_id及被替代处置；update_issue调用领域守卫完成非缺陷、重复、暂缓与撤销，close_issue仅用于新实际回归支持的修复关闭。重复归并校验同项目、无环、可解析主问题和原确认级别/范围，报告冻结该次解析所依据的精确问题及处置修订，不用当前主问题覆盖旧报告。

BlockingRule输出blocking_issue_ids、归并关系及原因。处置变化触发当前投影/新报告修订；原失败断言不被处置覆盖。主问题重开、重复关联变更、非缺陷处置撤销均重新计算当前阻塞。AI只提供处置建议，实际生效需核心人工确认记录。

CoverageDTO和ReportSnapshot分别保存S/M摘要的denominator、executed_count、reused_count、verified_count、passed_count、failed_count、unverified_count及独立decisive_failure_count/decisive_failures和明确的层级/统计单位，集合定义唯一引用一期功能第3节。E是执行完成集合、V是有效验证集合、P是V中的通过集合，V_X⊆E_X∪R_X，E_X∩R_X=∅，分别对X=S/M统计。计划补充项可另列，不能抵消必测遗漏。确认依据后须重检实际核验证据，不能只改verified_count。

成功导出的永久制品先由对象库保存并纳入已提交引用，用户选择目录中的文件只是交付副本。跨目录复制失败不报交付成功，已保存对象按恢复规则处理；备份不依赖用户导出目录仍然存在。

## 10 S/M与复用的报告合同

DecisionInput冻结M、S、当前Attempt与ReuseReference及有效性、源码/环境/验收/模板/规则/策略修订。DecisionOutput同时包含本轮S的执行/复用/有效验证/通过/失败/未验证，以及完整M覆盖；报告标题保留AcceptanceScope名称和partial上限。补充用例参与S的业务结论；历史复用不伪造本轮执行，修复关闭必须新证据。新Attempt失效不回退旧R；公式唯一正文见一期功能第3节。

## 11 CoverageDTO字段合同

CoverageDTO.schema_version固定定义selected_summary与required_summary两个同构摘要，分别对应S和M；两者含scope_kind、case_ids_revision、denominator、executed_count、reused_count、verified_count、passed_count、failed_count、unverified_count、decisive_failure_count、decisive_failures、source_commit、policy_version。适用总数在该摘要中就是denominator，不额外维护另一份计数。报告快照冻结相同字段和输入引用，RunDTO直接复用该类型。

count字段为非负整数，verified_count=passed_count+failed_count，unverified_count=denominator−verified_count；executed_count与reused_count对应互斥集合，verified_count不大于两者之和。步骤进度另存automatic_step_progress，不能作为用例计数。字段或来源缺失时返回unknown及reason，不将缺失补零；旧统计别名只在明确版本兼容适配器转换，当前Schema只输出上述名称。独立的断言依据确认数有明确分母，不冒充verified_count。decisive_failures为H的准确用例及Step/Attempt/断言/依据/证据引用，decisive_failure_count按case_id去重等于H大小，failed_count≤decisive_failure_count≤denominator，但H不要求属于V。两类失败计数不可相加；同一用例可同时在H与U。DecisionOutput.business_outcome以H_S优先输出failed并保留缺口；failed_count仅为整用例已验证失败数。DTO新版本明确声明这些字段；旧版本缺H时不能补零或由F推导，应标已确认失败统计未知，保留原结论及原policy_version。

同一正文修订、所附复核集合、格式与脱敏策略的导出复用已有受控产物；新集合/策略生成新导出。列表按项目/业务结果/完整编号读取摘要及分页游标，证据只在详情中按引用获取。永久诊断和导出引用纳入存储历史闭包，不用外部下载目录作为唯一副本。

## 12 当前依赖与安全证据的报告投影

DecisionInput除各Step当前Attempt外，还冻结其消费的上游Attempt/对象/条件事实、OutdatedBasis和ExecutionSourceBinding有效性；ReportSnapshot引用准确的这组输入。上游新Attempt发布后，当前判定不能继续读取旧下游通过，新报告修订列出受影响步骤和原因；历史报告与原断言不改。CoverageDTO仍由领域按[用例聚合](../功能文档/01-功能文档.md#15-用例执行聚合与依赖失效)给出，报告不将部分跨运行继承伪装为本轮用例执行或完整验证。

EvidenceRef附采集安全策略与过滤/完整性摘要；导出投影从[安全捕获材料](02-执行与证据.md#13-采集安全与原始证据语义)生成。来源未核实、凭据过滤影响必需核验、依赖过期分别列明缺口；不能将执行退出成功、投影成功或证据文件存在当成业务通过。校验对应P1-AC19/20/24/27/35以及现有缺口场景。

## 13 确认投影与失败快照

DecisionInput显式冻结每份准确Case/依据修订与有效ConfirmationRecord集合；effective_assertion_basis_state由核心派生，并与实际核验和来源共同参与V/H。ReportSnapshot保存相同输入、H及失败引用。补确认产生新的判定/报告修订，旧Case、旧报告和旧确认不改；失效依据不继承旧confirmed。面板与导出读取该结果，不自行合并Case字段。P1-AC19/21/27核对失败后阻塞、后补确认、依据变更和重启后的同一投影。

## 14 问题查询投影与复核语义

IssueListProjection从同一commit下的IssueRecord、ReproduceContext、人工确认和IssueDisposition派生，字段包括project_id、issue_id、content_revision、module_ids、layer、severity、workflow_state、review_state、disposition、blocking、canonical_issue_id、updated_sequence及缺口原因。投影用于查询，不替代事实记录，不另建AI问题库。module_ids来自已保存的模块关联，未知显式表示，不从文件名或AI猜测补齐。workflow_state沿用草稿/待确认/已确认/处理中/待复测/已关闭；disposition沿用active/fixed/non_defect/duplicate/deferred；blocking由既有BlockingRule和精确依赖修订生成，不能简单等同P0/P1或处理状态。

review_state为UNREVIEWED、REVIEWED、UNKNOWN，含义限定为“当前问题事实是否已有有效人工核对记录”，独立于流程、报告LocalReview和平台审核。问题人工确认复用现有受控确认记录，保存issue_id、所依据事实修订/字段摘要、核对人和来源引用；AI建议、打开详情、上传送达或关闭标签不自动创建核对事实。新草稿为UNREVIEWED；旧材料无法确定是否核对则UNKNOWN。已有有效人工确认覆盖当前事实时REVIEWED；标题/现象/预期实际/模块层级/关联证据等被核对事实变化使当前投影重新UNREVIEWED，原确认永久保留。仅责任人、处理进度等非事实字段更新不自动使事实核对失效；覆盖字段集合由Schema固定，不由界面猜测。

issues.list的OPEN/ALL与14种筛选掩码唯一见[存储与恢复的查询合同](04-存储与恢复.md#issueslist固定schema与索引合同)。列表DTO直接带当前投影，人工确认、处置、级别和归并主问题变化均更新受影响索引；报告继续冻结其原精确修订。查询投影变化不自动修改断言或关闭问题，UNKNOWN阻塞事实按已有判定守卫显示缺口，不伪造不阻塞。
