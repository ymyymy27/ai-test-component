# 一期架构02：执行与证据

版本：3.3  
更新日期：2026年9月23日  
文档类型：工程设计文档

覆盖P1-FR08—13。runner编排，recovery恢复，evidence_review组装核验输入；领域执行/真实性/断言判定按[功能文档](../功能文档/01-功能文档.md)唯一计算。

## 1 调度与适配器

Python/命令适配器按[执行来源与物化边界](01-项目与计划.md#12-执行来源与物化边界)核对入口、导入路径与实际来源；start前不符阻塞，执行后发现未知则保存事实并形成source_unverified缺口。工作目录复制正确不能替代实际来源验证；适配器不自行放宽full判定。

Run包含意图、冻结输入、源码/环境、档位、驱动及修订。Step含依赖、登记入口、输入、断言和证据要求。Attempt含attempt_id、attempt_index、句柄及进程启动身份、输出游标/块引用、副作用类别和状态。attempt_index从1起，retry_count=index-1。

ExecutionPort=start(request)/inspect(handle)/collect(handle,cursor)/request_stop(handle)。只返回实际句柄、结构化结果和停止确认，不写业务记录。命令使用登记入口及参数数组，禁止把模型或正文拼成shell。

| 适配器 | 功能 |
| --- | --- |
| PythonChecks | 语法/适用构建/加载/最小启动，保存SourceCheckResult及failure_class |
| Command | 既有pytest/命令入口、输出和退出结果 |
| Http | 登记目标、凭据引用、请求关联、变量提取；输出事实供领域断言 |
| Verification | 同对象独立只读接口或可选数据库驱动，不作为插件存储 |
| ManualEvidence | 页面操作类型、人工来源、步骤、截图附件与业务对象 |
| Agent | 实际采集工具调用和逐次业务评价，不接受文字自述替代 |
| ExternalResult | 格式、来源、附件、幂等校验及可独立重算的断言 |

一期先串行；上游失败只阻塞依赖步骤。若启用并行，无共享写冲突且无依赖才并行，暂停/修订/驱动切换在全组边界。适配器不另建调度或重试循环。

### 模块职责

本册负责"测试执行"这一步：三层如何调度、适配器如何执行、暂停取消与恢复如何处理、证据与链路如何采集、Mock 与真实性如何判定。

### 子域结构

```text
domain/execution/          # 运行、步骤、尝试、断言、层级与依赖图
  runs.py
  sources.py               # 源码快照与检查有效性（与 01 共用）
domain/evidence/           # 证据、链路节点、Mock 声明、真实性判定
  evidence.py
application/execution/
  runner.py                # 依赖图调度、层级执行、暂停取消
  recovery.py              # 检查点、句柄重关联、安全重试与待核实
  source_checks.py         # 固定源码与检查复用
application/evidence/
  evidence_review.py       # 证据核验、链路关联、独立核验、真实性
infrastructure/adapters/execution/
  python_checks.py · command.py · http.py
  verification.py · manual_evidence.py · agent.py · external_result.py
```

### 三层调度

| 记录 | 核心字段 |
| --- | --- |
| `Run` | 运行编号、`origin_workspace_id`、档位、驱动、结论上限、**证据等级与主要缺口（仅 `full` 派生；`quick`／`on_demand` 为空并附覆盖摘要）**、`PlanRevisionRef`、运行中修订序列、所选范围、开始与结束时间、环境引用（含是否隔离）、规则版本、结果 |
| `Step` | 步骤编号、所属运行、层级、输入、依赖、执行入口、断言、证据要求、`StepRevisionRef`（含是否继承） |
| `Attempt` | 尝试编号、所属步骤、**尝试序号 `attempt_index`（该步骤内第几次尝试，从 1 起）**、句柄、输出游标、状态（含 `pending_verification`）、副作用分类、开始与结束时间、适配器与版本、超时设置与是否超时 |

| 层级 | 适配器执行 | 结果处理 |
| --- | --- | --- |
| L1 | 语法、适用构建、加载或最小启动 | 分开记录源码失败、环境阻塞、工具异常和不适用子项 |
| L2 | 模块命令、串联 HTTP、业务断言和独立只读核验 | 响应、持久化结果、Mock 范围分别判定 |
| L3 | 人工页面步骤，或接口／命令／智能体的连续业务步骤 | 绑定同一业务对象，保存完整流程与最终状态证据 |

调度规则：首发串行；上游失败只阻塞依赖项，不把阻塞当断言失败。自动步骤进度与人工待办分开，L1通过不能替代L2/L3业务核验。并行仅在明确实现并验证全组暂停/修订守卫后启用。

## 2 意图、启动和控制

启动前提交Attempt意图、输入摘要、幂等和副作用类型；提交后调用外部执行，返回句柄再记录。意图到句柄间崩溃不能推断未执行，有副作用必须查业务或人工核实。关闭编辑器不改变执行归属。

暂停在边界，恢复从未执行步骤继续；取消先保存取消意图再请求停止，未确认保持取消中/待核实。超时仅表示等待截止，继续核实执行和业务结果，不宣称回滚。重试新建Attempt立即成为当前，失败不退回旧通过。

## 3 采集和恢复

输出流写spool/<attempt>，块元数据含运行/步骤/尝试、序号、长度、摘要、完整标志及采集来源；检查点保留句柄启动身份、块引用、游标和最后已提交阶段。按第13节完成凭据过滤后的捕获内容保存后才确认采集游标推进，不能仅存游标。

恢复在单写锁下先检查进程身份和存活：存活可重关联，已完成可补取，未知副作用进入pending_verification。只读或业务端保证幂等且已核实状态才允许重试。先抢救spool/事务候选输出并校验归属和摘要，再提交恢复事实；不可归属材料保留待处理。执行停止且必要证据发布前不得清理workdir。完整顺序见[存储恢复](04-存储与恢复.md)。

## 4 证据与真实性

EvidenceRef绑定项目/来源、Run/Step/Attempt、类型、代码身份、内容摘要、完整性、脱敏状态。TraceNode使用实际节点ID/父子关系，不用时间近似编造链路；独立核验记录VerificationOf、同业务对象、查询策略与实际证据，不拼到原调用树。MockDeclaration不可变修订，声明、静态候选和实际核实结论分开。

无请求ID或关键结构化日志时人工关联并保留证据级别与缺口；不能判真实链路通过，也不自动判产品缺陷。业务数据来自明确隔离与复位流程；HTTP/L3确认目标部署与源码身份对应。虚拟环境不证明外部数据隔离。

## 5 模型、外部导入和错误

模型默认提供方可用DeepSeek配置，但不硬编码未经实测的模型名/响应头。ModelProfile冻结供应方、地址、模型、凭据引用、输出Schema与参数；请求只包含选定脱敏材料。保存来源修订、按第13节过滤后的原始响应、返回模型与供应方请求号（无则未知，不冒用本地号）。模型失败不阻塞人工处理；未知请求不盲目完整重发。

适配器把供应方错误归一到统一错误枚举，connectivity负责是否重试与降级。网络、认证、限流、输入限制、响应截断、结构错误分开；不在失败时悄悄换模型。

外部格式aitest.external-result/1.0包含层级、源码、运行尝试、输出、Mock和附件；同来源编号同内容返回原记录，异内容冲突，来源永久EXTERNAL_IMPORT。导入未知身份/快照不补造，能核验才核验。

### 外部结果导入

格式 `aitest.external-result/1.0` 包含层级、源码快照、运行与尝试、实际输出、Mock 与附件引用。

- 旧格式由迁移适配器转换；未知来源不补造身份或快照。
- 重复来源编号同内容幂等，异内容冲突；来源始终保留为 `EXTERNAL_IMPORT`。
- 导入材料永久保留外部来源，已核验、未核验与自述内容分开。

## 6 授权与编辑器生命周期

ActionAuthorization由核心逐项保存，可在运行开始前集中逐项确认，键绑定intent_id/计划步骤、已解析输入摘要、目标、凭据范围和计划修订。start创建Run时关联intent授权，实际调用前再核对；未解析输入待解析后确认，修改目标/输入或新增副作用尝试不继承原授权。计划驱动不新增集合授权。

编辑器有活动运行时持续显示运行提示；宿主支持退出提示时说明“关闭后继续”，不能依赖退出回调一定发生。重新打开按workspace/run恢复状态。取消仍请求停止并核实，不以窗口关闭生成已取消记录。此处不新增停止全部的批量授权语义。

## 7 适配器请求、结果与错误合同

| 合同 | 必需内容 | 不得承担 |
| --- | --- | --- |
| ExecutionRequest | 项目/Run/Step/Attempt、intent与输入摘要、已登记入口/参数、物化快照、环境修订、ExecutionSourceBinding/source_binding_digest、授权引用、副作用类别 | 模型正文决定新命令，或把整个原始凭据送给面板 |
| ExecutionHandle | 适配器类型/版本、真实进程或远端请求标识、进程启动身份、工作目录引用 | 只用PID认领其他进程 |
| collect结果 | 输出块序号、游标、长度/摘要、完整标志、采集来源、退出/响应事实 | 将游标当成已经持久化的内容 |
| inspect/stop结果 | 最近可核实状态、停止是否确认、结果未知原因 | 将网络断开/控制截止当成事务回滚或已取消 |
| SourceCheckResult | 检查类型/范围、快照/环境、入口参数、规则/适配器版本、failure_class、原始输出与证据 | 以源码通过代替业务通过 |

failure_class分别表示源码错误、依赖缺失、环境不可达、工具失败或检查通过；业务断言仍独立计算。HTTP适配器返回响应及提取事实，领域层执行已发布断言，适配器不直接决定报告。VerificationPort读取指定业务对象，数据库驱动不承担插件存储。

### 执行适配器

`ExecutionPort` 提供 `start(request)`、`inspect(handle)`、`collect(handle, cursor)`、`request_stop(handle)`；输入包含固定快照、登记入口、参数、环境引用、运行与尝试编号及超时；返回实际句柄、状态、输出游标与停止确认。

| 适配器 | 职责及输出 |
| --- | --- |
| `PythonChecksAdapter` | 调用预登记源码检查，生成 `SourceCheckResult` |
| `CommandAdapter` | 执行既有测试命令／pytest，保留命令、退出状态及日志 |
| `HttpAdapter` | 发出配置请求、记录关联编号并提取响应事实；已发布业务断言由统一领域判定器评价 |
| `VerificationAdapter` | 调用独立只读接口；可选数据库驱动只用于核验被测数据 |
| `ManualEvidenceAdapter` | 按操作类型清单（按钮、分页、跳转、表单、滚动、适用鼠标操作、异常提示、展示数据）保存用户提交的步骤与附件，保留人工采集来源 |
| `AgentAdapter` | 保存实际工具调用及逐次业务评价，不以文字自述代替采集 |
| `ExternalResultAdapter` | 校验导入格式、来源及附件，可重新核验断言 |

约束：所有适配器共用Attempt、授权、错误枚举和恢复守卫；仅返回实际事实与结构化结果，不直接写records、不自行改变断言规则。命令输出由下述耐久采集协议管理。

### 本册的端口

| 端口 | 唯一职责 |
| --- | --- |
| `ExecutionPort` | 启动已确认入口、查询句柄、停止及取回实际结果 |
| `VerificationPort` | 调用独立只读接口或数据库驱动核验被测数据 |
| `EvidenceObjectStore` | 不可变证据内容与引用校验（实现在[存储与恢复](04-存储与恢复.md)） |
| `ModelProvider` | 模型请求、响应归一化、错误分类（与[项目与计划](01-项目与计划.md)共用） |

## 8 控制与恢复分支

| 发现状态 | 处理次序 | 证据和后续 |
| --- | --- | --- |
| 意图已提交但句柄未保存 | 以执行身份/业务幂等关联核实是否启动 | 不能直接当未执行；有副作用未知则待核实 |
| 句柄仍活且身份匹配 | 重新关联、继续采集 | 保留原Attempt，禁止重复启动 |
| 进程已结束且输出可取 | 补取退出状态及已落盘输出 | 证据完整性与业务断言分别核对 |
| 句柄失效但spool存在 | 校验块序号、归属、摘要后发布恢复记录 | 部分内容标部分，不伪造完整输出 |
| 停止请求未确认 | 保留取消中/待核实并继续可行核实 | 不能给已取消终态或一键重放副作用 |
| 已核实未执行 | 重新核对权限与实际输入再继续 | 新Attempt语义及授权按当前合同，不复用未知结果 |
| 新尝试失败/阻塞 | 新尝试仍为当前，保留全部旧尝试 | 不回退旧绿灯 |

暂停只阻止边界后的新步骤，正在执行的步骤先收尾。恢复与重试是不同动作；恢复同一已知句柄不新造业务执行，显式重试才产生新尝试。退回阶段生成修订与下游需重跑清单，不把沿用证据记为重新执行。实施并行前必须支持全组边界，首发串行不承担并行组复杂度。

### 暂停、取消与恢复

| 动作 | 机制 |
| --- | --- |
| 暂停 | 在步骤边界生效（并行时以"并行组边界"为准）；`暂停中` 与 `已暂停` 分别记录 |
| 取消 | 先登记取消意图，再请求执行器停止；确认停止后才记录 `已取消`，未确认保持 `取消中` 或 `pending_verification`（待核实，属执行状态的正式取值，不得伪造 `已取消`） |
| 重试 | 产生新尝试并立即成为当前尝试；保留旧尝试与其结果，`attempt_index` 递增 |
| 恢复 | 对仍存活的句柄重新关联；对已完成句柄补取输出；已有落盘输出块的步骤按块恢复；明确未执行的步骤可继续 |

检查点内容：最后已提交阶段、当前尝试、执行句柄、输出游标、**已落盘的输出块引用与块序号**、输入摘要、副作用分类。

- 开始步骤前保存意图、输入摘要与幂等信息；启动后保存执行句柄；**采集中按块（大小或刷新边界）把输出写入 `spool/<attempt_id>`，由核心核实后发布到内容寻址对象库**，游标只作进度标记——句柄失效（进程崩溃、被监督器终止）时以"已落盘块 + 游标"重建证据，不依赖句柄补取。
- 只读或业务端保证幂等且状态已核实的步骤可以重试；**有副作用且无法确认结果的步骤保持 `pending_verification`**，由用户根据实际业务状态决定。
- 进程退出、编辑器关闭与网络断开均不等同于停止。
- 保存检查点不代表能安全重放任意业务操作。

## 9 证据记录与外部导入字段

| 记录 | 必需字段与检查 |
| --- | --- |
| EvidenceRef | 项目、来源实例、Run/Step/Attempt、类型、采集来源、代码身份、对象摘要/大小、完整性、投影状态；读取核对归属与摘要 |
| TraceNode | 实际节点ID、实际父节点或明确关联、类型、状态、断言、真实性、gap_id；路径/符号为附加导航 |
| MockDeclaration | 稳定ID/修订、项目、声明来源、替代对象/行为/范围、核实状态及证据引用；不覆盖旧声明 |
| Verification | verification_of、业务对象ID、查询方式/截止条件、目标部署、实际结果、关键链路条目关联 |
| 模型请求记录 | 任务类型、来源/策略/模型修订、本地请求ID、可获取的供应方请求号、返回模型、原始响应/终止原因/结构化错误 |
| 外部导入 | schema=aitest.external-result/1.0、来源号、层级、源码身份、尝试、实际输出、Mock和附件清单；缺失来源保持未知 |

同来源号同内容导入幂等，异内容报冲突。附件路径必须受控，校验长度/摘要和项目关系；未知格式拒绝或由明确迁移适配器转换。可依据原证据独立重算的断言重新核验，外部自述保持EXTERNAL_IMPORT，不升级成插件实际采集。智能体随机输出默认三次属于既定用例设计，每次必需业务断言都核验，不能取平均掩盖失败；插件AI建议质量与被测智能体业务结果分别记录。

核验截止出现“查询明确返回错误状态”与“尚无足够材料确定结果”时，分别由发布的断言规则判失败或未完成；任何一种都不证明远端写入已回滚。

### 证据、链路与真实性

| 记录 | 核心字段 |
| --- | --- |
| `EvidenceRef` | 项目、来源实例、运行、步骤、尝试、类型、内容摘要、采集来源、脱敏状态、**绑定形态（`git`／`plain`）与代码版本引用（提交标识或文件清单摘要）** |
| `TraceNode` | 节点标识、父节点、类型、状态、耗时、断言、真实性、缺口标记 |
| `MockDeclaration` | 记录编号与**内容修订**（不可原地覆盖）、**所属本地项目**与幂等键、声明来源（开发声明／运行配置／静态候选）、替代对象、行为与范围、核实状态、**核实结论与证据引用** |
| `Verification` | `verification_of` 指向被核验操作、业务对象编号、查询间隔与截止条件、结论；**是否覆盖关键链路清单条目**（未覆盖条目进入报告警告与等级判定） |

规则：

- 调用关系只有在实际采集到请求编号、trace/span 父子关系或明确业务关联时建立；**仅凭相近时间或 AI 推断不得生成已发生调用**。
- 独立查询使用本次业务对象编号与隔离测试数据，不拼接进原应用的父子调用链。
- 最终一致性场景使用配置的查询间隔与截止条件；无结果时区分「已确认断言失败」与「尚未完成验证」。
- Mock 声明、静态候选与实际依赖证据分别存储；静态特征只形成风险提示。
- 真实、Mock、混合与未知由本次环境及证据计算；**关键真实依赖缺口不被普通响应成功覆盖**；关键链路清单里未覆盖的条目必须进入报告警告，不得只做提示。
- **证据级别**：完整链路需要被测应用提供请求标识与关键节点结构化日志；缺失时降级为人工关联证据，记录证据级别与缺口，既不判为通过也不视为产品缺陷。
- 链路视图只展示已采集节点与缺口；一期不要求任意函数自动插桩。
- AI 定位写入独立分析实体，以证据编号引用事实；缺少后端采集不能确认具体函数根因。用户确认分析也不能改变原始断言。

## 10 人工确认与重试分类

ActionAuthorization引用核心ConfirmationRecord和已消费ApprovalChallenge；来源校验见[入口权限](05-Trae接入.md)第9节。预先确认的副作用授权首次创建Attempt时，在同一工作单元把授权绑定该attempt_id并标为已占用；相同Attempt的合法原请求恢复可继续核对原授权，任何新Attempt即使输入完全相同也不能复用已占用授权。runner在实际调用前核对动作摘要、目标、凭据范围及计划修订；relay可使用已有有效授权请求执行，但不能创建人工确认。

| 动作 | 身份与记录 | 授权及恢复 |
| --- | --- | --- |
| 原结果查询/已知句柄重关联 | 原Attempt；追加只读查询/采集事实 | 不新执行被测业务；查询目标和凭据仍须在允许范围内 |
| 同一业务请求的传输重试 | 原Attempt、相同业务幂等键/输入/目标；新的transport_request_id | 只有端点明确保证同号重传不产生第二次业务执行时可按有界策略恢复；先查原结果，无法证明则待核实 |
| 重新执行业务步骤 | 新Attempt立即当前，保留旧尝试 | 副作用步骤需新人工授权；只读步骤可按已登记规则和有效授权范围自动重试 |

HTTP方法名、成功响应或“通常幂等”不证明端点支持上述恢复合同。进程命令重新启动属于新Attempt，不能伪装成传输重试；连接层不得自行重发未声明恢复语义的写请求。业务幂等键在同一Attempt首次请求前持久化；各传输请求保留独立结果，transport_retry_count与Attempt的retry_count分别计数。被测智能体三次评价是计划中的三次执行，不算网络重试。

connectivity只给重试资格、次数和间隔，runner再次核对授权与实际执行身份；新副作用Attempt即使业务端支持幂等也不继承原授权。结果未知且无法核实保持待核实，不通过新增Attempt掩盖。P1-AC19覆盖原请求恢复、命令重启、新副作用授权及计数独立。

## 11 本轮执行与引用结果

Run分别保存完整验收必测M和本轮选择S；Attempt只代表本轮真实执行，不为复用创建空执行。建立新Attempt即使复用失效，失败、阻塞、取消不得退回旧R。执行器返回实际步骤事实，领域按[用例聚合与依赖失效](../功能文档/01-功能文档.md#15-用例执行聚合与依赖失效)计算E/R/V/P/F/U，面板步骤进度不拿来充当用例完成率。

## 12 命令输出与终态的耐久采集

PythonChecksAdapter与CommandAdapter共用每Attempt的轻量启动包装器，不另建常驻服务。核心先发布Attempt启动意图和启动令牌，再启动包装器；包装器核对workspace/attempt_id/token，持有该Attempt的执行互斥，写入自身及子进程的真实启动身份。重复启动令牌只能查询原执行，不能启动第二个业务命令。包装器只写本Attempt的spool事实，不持工作空间业务写锁，也不能发布业务结论。

子进程输出由包装器按第13节在内存中完成凭据过滤后，持续采集到stdout/stderr分块文件；完成块先刷新再写包含流名、序号、offset、length、digest、完整性和启动身份的块清单。核心只读取已经封口的块，仅完成采集过滤的流式尾部可展示且必须标未持久化，不提前计入完整证据。跨流不能凭采集时钟推断业务因果。每块归属与摘要由核心校验，经工作单元认领一次后成为永久证据。

包装器等待真实子进程退出，保存ExitFact：attempt_id、启动令牌、进程启动身份、真实exit_code、最后块序号、各流已保存字节数、采集完整性及终止原因；刷新后发布终态标记。退出码非零是执行事实，不直接等同业务断言失败。若被测命令产生后台子进程，必须使用已验证的受控进程组/作业机制登记其归属，不能把父进程退出等同全组停止。

| 故障情形 | 恢复规则 |
| --- | --- |
| 核心退出，包装器与子进程仍活 | 按真实启动身份重新连接，继续读取已封口块，不重启命令 |
| 核心退出期间子进程已结束，ExitFact完整 | 核对标记与输出，恢复执行终态并独立评价业务断言 |
| 包装器失效、子进程可能存活或退出码不可得 | 保存能验证的输出为部分证据，结果待核实；不声称重新获得旧匿名管道，不补造exit_code |
| 块中途写入/磁盘不足 | 保留可识别部分字节和缺口，请求受控停止；未知副作用不自动重放 |
| 回收workdir | 必须先核实全组结束、输出已认领及必要源码对象已保存，否则保留 |

其他适配器须声明inspect/collect支持的恢复级别；远端请求依赖原业务号查询合同，人工步骤依赖明确采集记录。句柄存在、PID相同或游标增大不证明终态与字节完整。验收覆盖核心中断、包装器中断、子进程先退出和恢复再次中断。

## 13 采集安全与原始证据语义

本合同覆盖命令stdout/stderr、HTTP与核验响应、模型响应、人工/外部导入及诊断。文档中的“原始输出/日志/响应”统一指经过不可关闭的落盘前凭据过滤、但未被AI总结或业务改写的捕获流；不承诺它与含凭据的外部原字节完全相同。原始源码对象另按来源排除规则处理，不能把凭据文件作为必要源码保存。

| 边界 | 必须行为 | 不允许的替代 |
| --- | --- | --- |
| 解析凭据 | SecretPort按用途在受控进程内提供所需值；包装器需要的过滤材料只走受限本地内存通道，凭据不放命令行、普通临时文件或检查点 | 先把凭据写文件再在导出时删除 |
| 采集入口 | 过滤已解析凭据的精确值、策略明列的编码变体及标准认证字段；stdout/stderr使用同一流式过滤器，匹配缓冲跨块保留 | 按封口块分别过滤导致跨块漏出；未过滤尾部直接展示 |
| 未决尾部 | 留在受控内存直到可以安全输出；异常终止时不能确认安全的尾部不落盘，保存采集缺口 | 将未决缓冲转储到spool或调试文件 |
| 封口与摘要 | 只对可保存的过滤后字节计算offset、length、digest、块序号和输出游标；与RedactionSummary一起提交 | 保存低熵密钥的独立摘要或未过滤片段以“帮助复原” |
| HTTP/模型 | 结构化移除认证头和凭据字段；响应正文仍经采集过滤，禁止整包认证调试转储 | 假设响应一定不会回显凭据 |
| 导入与二进制附件 | 导入前校验类型和已知敏感项；无法安全检查/转换的疑似敏感附件不入默认证据库，登记缺口并允许重新提供安全材料 | 原样保存后仅在上传阶段排除 |
| 后续投影 | 面板、复制、报告、模型出站、导出、上传在安全捕获流上继续按各自策略投影 | 将落盘前过滤当成所有业务隐私、路径和源码外发规则已满足 |

RedactionSummary保留policy_version、已应用规则类别、流与过滤后范围、替换数量、完整性及缺口原因；不含凭据值或可逆恢复信息。包装器只写本Attempt的安全spool事实，核心校验过滤策略、块摘要与归属后通过工作单元认领，不能因此增加第二业务写入者。凭据或过滤器不可用时暂停采集/请求受控停止，记录输出缺口，不将未过滤输出降级写盘。

保证范围是插件管理且已知的凭据值、明确的认证字段和已登记过滤模式；不能保证识别任意未知或任意变形的秘密。输入/输出合同禁止夹带未登记凭据；检测到疑似敏感但无法安全处理的内容，阻止其保存并提示安全补证，不能仅显示“已脱敏”保证不存在任何秘密。该边界不承诺隔离同一OS用户下的恶意进程。

过滤不能偷偷改变业务判定：若必要断言或真实性核验依赖被过滤字段，按已发布的非敏感验证事实判断；没有可用事实则标未核实/证据缺口，不能用替换标记判通过。ExitFact的持久化字节数表示安全捕获流字节数；执行退出与采集完整性分开。使用虚构凭据验证跨块、HTTP回显、模型响应、导入、异常终止、恢复、备份和所有外发投影；实际产品通过须保留对应制品及证据。

## 14 依赖输入与当前用例结果

Step保留case_id、required_for_case及依赖边；Attempt在外部执行前固定step_revision、resolved_input_digest、source_binding_digest、consumed_outputs（upstream_attempt_id、output_object_digest、value_ref）和consumed_conditions（上游Attempt及条件事实引用）。领域根据这些精确依赖计算有效性，runner不得仅比较步骤编号或业务对象名称。

建立上游新Attempt的工作单元同时替换该步当前引用、使依赖旧事实的下游及传递依赖失效、撤销不再匹配真实输入的未使用授权，并更新当前判定输入。新实际输入解析后再获取所需人工授权；未知副作用仍先核实，不借新尝试自动重放。未被影响的分支保留有效事实，旧报告不可变。

同一用例的E/R/V聚合及跨运行混合继承由[一期功能第15节](../功能文档/01-功能文档.md#15-用例执行聚合与依赖失效)唯一维护；执行器不另算。恢复重建当前依赖闭包，缺上游引用/对象或旧Schema无法证明关联时标待核实，不用“最新一个成功”拼接。验证包括S1(A)→S2(A)后S1(B)、只重试下游、无依赖分支、同输出新Attempt与恢复再次中断。

## 15 已确认失败与整用例完成

用例聚合同时派生E/R/V/P/F/U和H，唯一规则见[判定与统计](../功能文档/01-功能文档.md#3-判定与统计唯一口径)。上游必要断言已有有效失败、下游因此阻塞时，保留H并输出failed＋未完成范围，不能因整用例不计V/F改成只有incomplete。上游新Attempt、证据失效或依据变化只使受影响失败退出当前H；独立分支的有效失败保留。聚合与依赖失效在同一业务提交发布，调度仍不把阻塞当失败、不为消除未完成而自动重放副作用。
