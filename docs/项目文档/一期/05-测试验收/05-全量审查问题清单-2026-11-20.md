# 一、后端核心与执行

## B-01 生成脚本未执行任何断言也可判 passed

- 结论：`_run_python_script` 在 pytest 未收集到用例（exit 5）时回退为直接执行脚本；只定义 `def test_*` / `def check_*` 的脚本直接执行不会调用函数，退出码 0，被记为通过。
- 证据：`src/aitest/worker.py:898-905`、`:948-963`、`:1538-1550`。
- 影响：违反“未执行不得汇总成通过”；验收项、报告和问题门禁都会被污染。
- 建议：只对明确的可执行脚本回退；回退后无输出判 `error/not_run`；补 no-collect 正负测试。

## B-02 `run.repair` 可在运行中执行并覆盖 `run.json`

- 结论：`cmd_run_repair` 只调用 `_run()`，没有 `_ensure_settled`；pip 安装最长 600 秒，期间 worker 仍在写心跳和用例结果，repair 最后整份写回旧对象。
- 证据：`src/aitest/runtime_commands.py:2085-2098`、`src/aitest/worker.py:1363-1569`。
- 影响：运行状态被回滚、用例结果丢失、repair 记录被覆盖；违反 worker 独占运行目录。
- 建议：入口拒绝 `running`；repair 只合并依赖/环境字段；安装放到锁外并缩短持锁。

## B-03 真实失败 + 缺依赖会被判成阻塞

- 结论：worker 只要解析到缺失模块和包建议，就直接把结果改为 `blocked`，绕过 `_environment_failure` 的混合失败保护。
- 证据：`src/aitest/worker.py:1458-1511`、`:1498-1504`。
- 影响：真实断言失败被隐藏，报告从 `failed` 变成 `incomplete`。
- 建议：先识别 `FAILED/FAIL:/AssertionError/超时`；混合失败保持 failed；建议分支不得先于该判断。

## B-04 项目解释器缺少 `packaging` 时，已安装的带约束依赖被误报缺失

- 结论：探针在 `packaging` 不可用时把整个 spec 当包名查询，`pip>=1` 这类已安装包会被判缺失。
- 证据：`src/aitest/worker.py:386-404`、`:433-453`、`:909-928`。
- 影响：依赖门禁误阻塞，并多执行一次无用 pip 安装。
- 建议：先剥离 extras/版本得到发行名；`packaging` 可用时才校验 specifier。

## B-05 `run.repair` 选择的解释器与 worker 不一致

- 结论：repair 只看项目根 `.venv`，找不到就退回 `sys.executable`；worker 会向上级目录搜索 `.venv`。
- 证据：`src/aitest/runtime_commands.py:2045-2052`、`src/aitest/worker.py:91-99`、`:1228`。
- 影响：monorepo 子项目依赖装到错误环境，重跑仍缺依赖；环境指纹也记录错误解释器。
- 建议：抽出统一解释器解析函数；无法确定时拒绝安装，不回退宿主 Python。

## B-06 `run.repair` 的 pip 子进程继承全部宿主环境

- 结论：`env = dict(os.environ)`，模型/GitHub 密钥可被安装包的构建脚本读取。
- 证据：`src/aitest/runtime_commands.py:2120`；对照 `worker.py:114-124` 的密钥过滤。
- 影响：供应链风险；repair 日志脱敏也覆盖不到环境中的凭据。
- 建议：复用 `_run_env` 或最小环境；把已知环境密钥加入脱敏列表。

## B-07 声明的测试依赖带注释/marker/URL 时，repair 建议不可用

- 结论：`_requirement_specs` 只 `strip()`，保留行内注释、environment marker、direct URL；`_REPAIR_SPEC` 拒绝这些字符。
- 证据：`src/aitest/core/project_context.py:172-183`、`src/aitest/worker.py:780-794`、`src/aitest/runtime_commands.py:2038-2042`。
- 影响：`factory-boy>=3.2  # fixtures`、`pytest>=7; python_version...`、direct URL 都会给出不可执行建议。
- 建议：剥离注释/marker，解析 direct URL 的发行名；生成建议时就校验可安装性。

## B-08 项目自身模块缺失仍可能被建议安装第三方包

- 结论：依赖建议路径不检查本地顶层模块；项目打包/PYTHONPATH 问题可能被模型映射成 PyPI 包。
- 证据：`src/aitest/worker.py:809-819`、`:844` 与 `:1459-1471`。
- 影响：真实打包缺陷被隐藏；可能安装无关或仿冒包。
- 建议：生成建议前排除项目顶层模块；模型建议默认不进入可安装列表。

## B-09 `real_chain` 在失败/阻塞运行中仍可能显示“真实链路通过：是”

- 结论：`real_chain` 只判断 Mock 判定是否为 `real`，不看运行结论、用例是否执行或是否通过。
- 证据：`src/aitest/core/reports.py:503-505`、`panel/src/views/ReportView.vue:523`、`panel/src/services/exportService.ts:110`。
- 影响：失败运行也可能展示“真实链路通过：是”，与四值结论冲突。
- 建议：要求运行非 failed/incomplete 且相关用例通过；或改名为“依赖真实性判定”。

## B-10 Mock 判定在未采样文件时接受无法核验的引用

- 结论：`read_files` 为空时不过滤模型给的 `evidence_refs`，可得到 `kind=real` 并推出 `real_chain=True`。
- 证据：`src/aitest/ai_features.py:408-411`、`:421-428`；`max_files` 可配置为 0。
- 影响：AI 输出信任边界被突破。
- 建议：`read_files` 为空时所有非 unknown 判定降级为 unknown。

## B-11 报告环境指纹用的是 CLI/worker 宿主 Python

- 结论：`Report.environment` 使用 `platform.python_version()`，不是项目解释器。
- 证据：`src/aitest/core/reports.py:165-181`、`src/aitest/worker.py:1228`、`src/aitest/runtime_commands.py:2666-2667`。
- 影响：报告环境事实与实际测试环境不一致。
- 建议：报告读取 `run.environment`；导出包含解释器、venv、Node、cwd。

## B-12 验证方式可注入 shell，确认记录不展示真实命令

- 结论：`pytest:` 参数未安全引用；`playwright:` 黑名单漏换行；确认记录只写“执行 xxx 验证”。
- 证据：`src/aitest/worker.py:1016-1023`、`src/aitest/runtime_commands.py:313-334`、`:1431-1453`。
- 影响：AI 生成或用户提交的计划可借“测试验证”执行额外命令；人工确认看不到命令原文。
- 建议：参数安全引用/白名单；确认记录展示规范化命令。

## B-13 重复 scope ID / 验收项 ID 会抬高 S、M 和覆盖计数

- 结论：selected、narrowing、Scope 都不去重；`coverage_applicable` 又取 `max(S, M)`。
- 证据：`src/aitest/runtime_commands.py:127-132`、`:1679-1686`、`src/aitest/core/verdict.py:171-173`。
- 影响：出现“已选 2/2”但只有一个验收项/一个结果。
- 建议：scope 与 item ID 去重；M 使用独立冻结值。

## B-14 smoke 计划中绑定验收项的 L1 用例进入 S/M，且不出现在报告 L1 区

- 结论：`_smoke_cases` 把验收项绑到 L1 主检查，`item_outcomes` 计入 S/M；`_l1_details` 只收集无验收项的用例。
- 证据：`src/aitest/runtime_commands.py:766-787`、`src/aitest/core/verdict.py:54-67`、`src/aitest/core/reports.py:296-302`。
- 影响：若这不是有意例外，L1 会“冒充”验收项覆盖，报告 L1 区也不完整。
- 建议：明确 smoke 计数口径，或让 L1 不绑定验收项。

## B-15 重复命令合并忽略 dependencies，并可能把 `None` 写入验收项数组

- 结论：合并 key 不含 dependencies；只有 `acceptance_item_ids` 的用例会把 `None` 追加进目标数组。
- 证据：`src/aitest/runtime_commands.py:549-570`、`:135-151`。
- 影响：依赖被丢弃；`sorted()/join()` 可能抛 TypeError，返回 INTERNAL。
- 建议：dependencies 纳入 key 或取并集；追加前过滤空值。

## B-16 `plan.show` 的 stale 判断与 `run.start` 真实签名不一致，`plan.publish` 不更新签名

- 结论：`plan.show` 只看 task_contract；`plan.publish` 不重算 source_signature/task_contract；生成计划已自动 published。
- 证据：`src/aitest/runtime_commands.py:1266-1275`、`:1288-1312`、`:836-858`、`:1177`。
- 影响：面板显示“未过期”，run.start 却返回 PLAN_STALE。
- 建议：show 复用完整签名；publish 重算签名；确认该命令是否仍需要。

## B-17 repair 审计与证据不完整

- 结论：每次 repair 覆盖同一个 `repair-deps.log`；日志未加入 `run.evidence_refs`；环境历史不含包版本；证据预算失败时安装已执行但记录可能缺失。
- 证据：`src/aitest/runtime_commands.py:2148-2167`、`:2177-2189`、`src/aitest/core/evidence.py:176-182`。
- 影响：无法区分多次修复，证据索引/备份缺少 repair 证据。
- 建议：按序号生成日志；登记证据引用；把包版本写入环境历史。

## B-18 模型调用次数与工作区锁时间没有预算

- 结论：每个失败用例调用一次 `suggest_dependency`（无缓存/上限）；问题草稿逐用例调用模型；后处理与报告在 workspace 锁内。
- 证据：`src/aitest/worker.py:759-769`、`:1459-1471`、`src/aitest/core/issues.py:260-288`、`src/aitest/worker.py:1121-1130`。
- 影响：大失败集后处理可达数十分钟，其他 CLI 命令持续 WORKSPACE_LOCKED。
- 建议：模块级缓存与调用上限；模型调用移出锁；问题草稿批量/异步。

## B-19 `request_id` 幂等检查在锁外，并发重放会重复执行

- 结论：`cached_result` 在获取 workspace 锁前执行，`store_result` 在释放锁后执行。
- 证据：`src/aitest/cli.py:135-148`。
- 影响：并发重试可能重复创建任务/记录。
- 建议：检查、执行、存储放入同一临界区。

## B-20 多条落盘路径绕过已知凭据脱敏

- 结论：issue.add/自动草稿、report.opinion、module.add/update 未统一脱敏；doctor 返回 proxy 原始值；confirmation 保存 services 原文；`redact` 跳过长度 <4 的密钥。
- 证据：`src/aitest/core/issues.py:117-132`、`src/aitest/runtime_commands.py:2914-2943`、`src/aitest/commands.py:232-243`、`:709-745`、`src/aitest/security.py:141-143`。
- 影响：凭据/代理密码可进入业务记录、面板和模型请求。
- 建议：write_model 前统一脱敏；doctor 只返回是否设置与脱敏 host；短密钥也处理。

## B-21 服务日志路径可逃逸，且健康检查对非 HTTP URL 抛错

- 结论：服务名直接拼日志文件名；日志无大小上限、未登记证据；`_healthy("file://...")` 可能因 `int(None)` 抛 TypeError。
- 证据：`src/aitest/worker.py:1306-1313`、`:271-282`、`:257-268`。
- 影响：日志写出运行目录、磁盘写满、整次运行 execution_error。
- 建议：校验服务名/索引起名；日志截断；只接受 http/https。

## B-22 大输出/大文件在 cap 之前整体读入内存

- 结论：JUnit、截图、Mock 采样文件摘要都 `read_bytes()` 全量读入；失败输出多次 join/decode。
- 证据：`src/aitest/worker.py:1028`、`:1076-1082`、`:1460`、`:1507`、`src/aitest/ai_features.py:318-323`。
- 影响：单次运行可占用大量内存，或被恶意输出拖垮 worker。
- 建议：流式读 cap+1；哈希分块；JUnit 解析加大小上限。

## B-23 `ensure_run_issues` 只要有一条 issue 就不补全其余失败用例

- 结论：判断是“任意 issue 的 occurrences 含 run_id 就返回”，不是按用例检查。
- 证据：`src/aitest/core/issues.py:248-257`。
- 影响：报告可能“失败但问题列表不完整”。
- 建议：按 `(run_id, case_id)` 或失败签名逐项补全。

## B-24 AI 摘要结论词过滤只覆盖中文

- 结论：`_BANNED_SUMMARY_WORDS` 全是中文；“All tests passed / ready to release” 会作为事实摘要写入。
- 证据：`src/aitest/ai_features.py:101-118`、`:525-528`。
- 影响：AI 结论可绕过“出现结论词整段不采用”。
- 建议：增加英文结论词，或改结构化事实输出。

## B-25 损坏的 `project.config.json` 让 doctor/snapshot 整体失败，worker 却静默忽略

- 结论：doctor 经 `build_client` 读坏配置直接抛错；snapshot 也失败；worker `_project_config` 静默返回 `{}`。
- 证据：`src/aitest/commands.py:316-325`、`src/aitest/model_config.py:22-40`、`src/aitest/runtime_commands.py:919-922`、`src/aitest/worker.py:185-193`。
- 影响：最需要诊断时 doctor 不可用；worker 静默改变 services/l1/evidence 语义。
- 建议：doctor/snapshot 降级为 problem；worker 写显式告警/证据。

## B-26 `build_client` 异常会中止整次运行

- 结论：`_resolve_dependency_package` 的 `build_client` 在 try 之外；配置损坏时从 `_dependency_suggestion` 冒泡到用例循环外层。
- 证据：`src/aitest/worker.py:761-769`、`:1576-1581`。
- 影响：本应只影响 AI 建议的问题会终止全部用例。
- 建议：`build_client` 纳入 try；外层异常按当前用例 error 后继续。

## B-27 命令缓存保存的是环境归因/建议之前的结果

- 结论：`command_cache` 在 `_execute` 后立即保存 `result`，随后才做 suggestion/环境归因；重复命令可能复用未处理的 failed 结果。
- 证据：`src/aitest/worker.py:1445-1470`。
- 影响：同一命令的不同用例可能得到不一致的 blocked/failed 展示。
- 建议：在最终结果确定后再写缓存。

## B-28 计划合并/Django 脚本移除的警告被静默丢弃

- 结论：警告先追加到 `warnings`，随后 `warnings = annotate_cases(...)` 重新赋值。
- 证据：`src/aitest/runtime_commands.py:1150-1163`。
- 影响：多验收项共用一条命令时，计划和报告看不到风险提示。
- 建议：在最终 warnings 赋值后追加；补 plan.generate 级断言。

## B-29 环境指纹的 Node 来自宿主 PATH，且不含包版本

- 结论：`_environment_fingerprint` 用 `shutil.which("node")`，不是 `run_env` 的 PATH；指纹只有解释器/平台/Node/cwd。
- 证据：`src/aitest/worker.py:150-182`。
- 影响：多 Node 环境下记录错误；无法核对依赖版本。
- 建议：使用 run_env；记录关键包版本。

## B-30 一个用例只收集第一个缺失模块

- 结论：`_missing_module_from_output` 只返回第一个 `ModuleNotFoundError`。
- 证据：`src/aitest/worker.py:795-806`。
- 影响：多个缺失依赖需要多轮修复。
- 建议：收集去重后的全部缺失模块，逐项给建议。

## B-31 `run.repair` 可对同一运行重复安装，且无幂等

- 结论：只校验包在建议列表中，不检查已安装标记；面板虽隐藏已安装建议，API 仍可重复调用。
- 证据：`src/aitest/runtime_commands.py:2085-2140`。
- 影响：重复安装、重复写历史、审计噪声。
- 建议：已安装包拒绝或直接返回；面板传 request_id。

# 二、面板前端

## F-01 宿主项目分析失败后永久停在“分析中”

- 结论：`analyzeProject` 没有失败分支；`beginAnalysis` 先写 sidecar `analyzing` 再读快照，读取失败后状态已落盘。
- 证据：`panel/src/stores/workspace.ts:221-232`、`panel/src/repositories/HostRepository.ts:294-305`。
- 影响：CLI 超时/锁冲突后项目永久不可用，刷新仍“分析中”。
- 建议：失败调用 `failAnalysis`；超时 analyzing 视为失败；提供取消/重试。

## F-02 宿主模式深链到非当前项目任务会误判 404

- 结论：路由守卫拿到的项目摘要 `tasks: []`；`setCurrentProject` 只替换数组元素，局部变量仍指向旧摘要。
- 证据：`panel/src/router/index.ts:205-230`、`panel/src/repositories/HostRepository.ts:118-121`、`panel/src/host/map.ts:1125-1154`。
- 影响：书签/跨项目任务 URL 落入 404；跨项目运行锁判断也看不到任务。
- 建议：`setCurrentProject` 返回完整项目；守卫用返回值重新查找。

## F-03 目标测试在计划生成期间可重复提交

- 结论：`startBusy` 只覆盖 `create-task`；创建完成到计划生成结束之间按钮重新可用。
- 证据：`panel/src/views/NewTaskView.vue:34,42-44,105-122`、`panel/src/stores/workspace.ts:349-359,420-435`。
- 影响：计划生成慢时会创建重复任务。
- 建议：用覆盖“创建+生成计划”的单一 busy；或创建后立即跳计划页生成。

## F-04 结果页逐项状态与顶部计数/筛选使用不同来源

- 结论：顶部/筛选用 `displayItemOutcome`（宿主取 CLI `item_outcomes`），`CaseLedger` 用 `run.cases` 重算且忽略 `caseItemIds`。
- 证据：`panel/src/views/ResultView.vue:100-119`、`panel/src/components/CaseLedger.vue:45-55`、`panel/src/host/map.ts:647-660`。
- 影响：同一页出现“顶部失败、明细通过/没有用例”。
- 建议：明细统一用 `displayItemOutcome` 或 `run.items[].outcome`；按 `caseItemIds` 匹配。

## F-05 宿主快速检查失败无提示、无重试，并永久停在“正在执行”

- 结论：宿主分支先放 running 占位，再直接 await，没有 withBusy/catch/toast。
- 证据：`panel/src/stores/workspace.ts:935-966`、`panel/src/views/QuickCheckView.vue:25,59-72`。
- 影响：`run.quick` 失败或轮询失败时页面卡住，用户没有任何错误信息。
- 建议：统一 busy/错误处理；失败清除占位并提供重试。

## F-06 旧运行没有计划快照时，用例无法挂到验收项，且“预期未核实”默认成已核实

- 结论：`mapRunCase` 无 planCase 时 `itemId` 为空，`expectationVerified` 默认 true。
- 证据：`panel/src/host/map.ts:587-621`、`panel/src/host/dto.ts:416-419`。
- 影响：旧运行结果页每项显示“没有用例”，却可能继续显示通过。
- 建议：缺快照时标未核实并展示用例 ID/来源；用 CLI 逐项结论承载结果。

## F-07 旧报告/损坏本地数据缺少字段兜底

- 结论：`ReportView` 直接解引用 `layers/mock/analysis/itemDetails` 等；宿主 `mapReport` 直接读 `dto.coverage/environment`；`exportService` 直接读 `report.planWarnings.length`。
- 证据：`panel/src/views/ReportView.vue:351,363,391,522,532,563,582,594`、`panel/src/host/map.ts:815-822,880-887`、`panel/src/services/exportService.ts:61`。
- 影响：旧数据在项目加载或导出时抛错/白屏；计数回退为 0 也会误导。
- 建议：仓库边界归一化或拒绝旧格式；视图/导出对数组与计数做兜底。

## F-08 `bootstrap` 失败后“重新读取”无效

- 结论：列表加载后、完整项目读取前就设置 `initialized = true`；完整项目读取失败后再调用 bootstrap 直接返回。
- 证据：`panel/src/stores/workspace.ts:234-287`、`panel/src/views/OverviewView.vue:111-119`。
- 影响：项目可能以空摘要呈现，重试按钮无法恢复。
- 建议：失败回滚 `initialized`；提供强制 reload；区分摘要/完整项目。

## F-09 确认对话框默认聚焦危险确认按钮

- 结论：无文本输入时焦点查询命中 `.dialog-confirm`。

- 影响：删除任务/清空数据打开后直接 Enter 即执行。

## F-10 依赖安装的“我已确认”未绑定当前勾选的包

## F-11 仅 query 变化的路由会抢走键盘焦点

## F-13 依赖修复的剩余状态流问题

# 三、Trae 扩展与宿主

## E-01 面板超时短于扩展/CLI 预算

- 结论：面板统一 300 秒；扩展 `run.repair`/`backup.*` 630 秒、`report.generate` 330 秒。
- 证据：`panel/src/host/bridge.ts:45`、`integrations/trae/src/extension.ts:102-125`、`src/aitest/runtime_commands.py:47-54`。
- 影响：后台仍在执行，面板已报“结果未知”；重试重复安装/生成报告。
- 建议：按命令传超时；长命令改为启动+轮询；重试复用 request_id。

## E-02 超时只 reject，不取消，也没有在途去重

- 结论：定时器只 reject；注入桥/扩展没有取消消息或按命令去重；超时重试是新 request_id。
- 证据：`panel/src/host/bridge.ts:148-159`、`integrations/trae/src/extension.ts:564-591,711-739`、`integrations/trae/src/bridge.ts:158-161`。
- 影响：pip/备份/报告可能继续执行；任务/问题可能重复创建。
- 建议：取消消息或 request_id 去重；长任务异步化。

## E-03 扩展默认 30 秒超时等于 CLI 默认锁等待

- 结论：未单列的命令使用 30 秒默认；CLI 非自锁命令也等锁 30 秒，释放后几乎没有执行时间。
- 证据：`integrations/trae/src/bridge.ts:21,229-230`、`src/aitest/cli.py:36-37,141-145`。
- 影响：长报告/备份持锁时，写命令会在拿到锁的同一刻超时。
- 建议：扩展默认超时显著大于锁等待；按命令给“锁等待+业务预算”。

## E-04 首次便携运行时准备没有总超时

- 结论：`runtimeFor` 可能下载 512MB 运行时并安装，下载只有空闲超时；面板 300 秒先超时。
- 证据：`integrations/trae/src/extension.ts:179-203,761-773`、`integrations/trae/src/runtime.ts:533-565,604-650`。
- 影响：新机器首次使用界面不可信，后台仍安装。
- 建议：独立前置阶段、总 deadline、进度事件；面板单独放宽。

## E-05 运行时升级原地删除旧目录，无锁无回滚

- 结论：检测过期后直接删除同目录 `python/venv` 再重建；两个窗口可并发写同一目录。
- 证据：`integrations/trae/src/runtime.ts:858-877,903-913,1037-1059`。
- 影响：安装失败后从“可运行”退化为“无运行时”；并发写可能互相覆盖。
- 建议：按版本新目录 + 原子切换 + 跨进程锁 + 保留旧版本。

## E-06 侧栏 webview 与编辑器面板共用一个 `panel` 句柄

- 结论：侧栏 resolve 会覆盖编辑器句柄；侧栏 dispose 会清空全局；编辑器面板成为孤儿，openPanel 会重复创建。
- 证据：`integrations/trae/src/extension.ts:143-148,313-339,354-391,425-449`。
- 影响：两个面板只有一个收到 context；重复面板和旧状态。
- 建议：分别保存 sidebar/editor 句柄，或只保留一种面板形态。

## E-07 `openPath` 无路径约束

- 结论：只校验非空，直接 `openExternal`；证据路径可来自任意源文件。
- 证据：`integrations/trae/src/extension.ts:676-702`、`src/aitest/runtime_commands.py:2431-2485`。
- 影响：可打开工作空间外文件/可执行文件；UNC 路径可能触发凭据泄露。
- 建议：限制在 workspace/evidence 下；文件类型白名单；文本证据用 showTextDocument；拒绝 UNC。

## E-08 子进程未设置安全 cwd，且继承 `PYTHONPATH`

- 结论：`cleanEnvironment` 只删 `PYTHONHOME`；spawn 无 cwd；`python -m` 可能导入仓库内同名 `aitest`。
- 证据：`integrations/trae/src/process.ts:29-35`、`integrations/trae/src/bridge.ts:127-131,242-252`、`integrations/trae/src/runtime.ts:157-161,667-671`。
- 影响：打开不可信仓库时，仓库代码可覆盖 CLI 并被导入执行。
- 建议：安全 cwd；删除 PYTHONPATH/PYTHONSTARTUP/PYTHONUSERBASE；使用 `-P` 或 `PYTHONSAFEPATH=1`。

# 五、跨模块建议（均为重点关注）

1. **统一解释器解析**：worker、run.repair、环境指纹使用同一函数；找不到项目解释器时拒绝安装，不回退宿主 Python。
2. **统一超时模型**：面板、扩展、CLI 按命令共享预算；长任务用“启动 + 轮询”，超时只报未知，不重复提交。
3. **统一错误出口**：store 负责一次 toast；视图只回滚状态；区分安装失败与重跑失败。
4. **统一脱敏**：所有 write_model 前对已知密钥脱敏；子进程环境过滤；doctor/proxy/confirmation 不落原文。
5. **统一旧数据归一化**：报告/运行/任务在仓库边界补默认值或拒绝旧格式；视图不直接解引用可能缺失的数组。
6. **统一状态语义**：L1、S/M、阻塞、未完成、中断、取消在计数、列表、报告、导出中使用同一来源。
7. **统一审计展示**：依赖修复记录、环境变化、安装版本、确认人和证据在结果页可查。
8. **统一可访问性**：状态必须有文字；危险确认默认不聚焦确认；对比度和点击目标达标；ARIA 属性有效。
9. **统一测试策略**：新增高风险能力必须有 CLI/宿主 e2e 或 worker 级测试，不能只测辅助函数/映射。
10. **统一文档来源**：命令数、白名单数、测试数、路径由脚本或主责文档生成，避免多处手写。

- 建议：按长度降序替换或一次性多模式匹配。

### 补-B40 用户配置文件 BOM/损坏时被静默当作未配置

- 结论：`load_user_config` 对 OSError/JSONDecodeError 返回 `{}`；UTF-8 BOM 会让密钥“消失”。
- 证据：`src/aitest/config.py:26-34,46-67`。
- 影响：用户配置了密钥却无法使用，且没有诊断。
- 建议：`utf-8-sig`；解析失败作为 doctor 问题展示。

### 补-B41 同一 `INVALID_REQUEST` 可能退出 1 或 2

- 结论：handler 抛 AiTestError 退出 1；ValueError/UnicodeDecodeError 被映射为 INVALID_REQUEST 但退出 2。
- 证据：`src/aitest/cli.py:152-164`；合同 `docs/项目文档/一期/03-设计/03-CLI与数据契约.md:49-50`。
- 影响：调用方按退出码分支不稳定。
- 建议：handler 边界统一转换 ValueError，INVALID_REQUEST 固定退出 1。

### 补-B42 业务副作用完成后 `store_result` 失败，重试会重复执行

- 结论：先执行 handler 再写幂等缓存；缓存写失败返回错误，但业务文件已写入。
- 证据：`src/aitest/cli.py:141-148`、`commands.py:1594-1601`。
- 影响：task.add/rules.save 等重复记录。
- 建议：业务写入前持久化意图；关键写操作自身幂等；区分“已执行未记录”。

### 补-B43 幂等缓存以 payload 参与键，损坏缓存使重试永久失败

- 结论：同一 request_id 不同 payload 生成不同缓存并再次执行；缓存 JSON 损坏时抛 INVALID_REQUEST。
- 证据：`src/aitest/commands.py:1573-1591`、`cli.py:135-140`。
- 影响：重复副作用；缓存损坏无法恢复。
- 建议：request_id 唯一键 + payload 指纹；不一致返回冲突；损坏可恢复。

### 补-B44 JUnit XML 允许实体展开

- 结论：`ElementTree.fromstring` 未禁用 DTD/实体，恶意测试报告可指数展开。
- 证据：`src/aitest/runners/junit.py:23-28`（已复现小规模展开）。
- 影响：解析阶段耗尽资源，运行 execution_error。
- 建议：拒绝 DOCTYPE/实体，或使用 defusedxml；限制大小和 testcase 数。

### 补-B45 command_runner 先把输出无限写临时文件，读取时静默截断

- 结论：stdout/stderr 无写入上限；只读前 20 MiB，无截断标记。
- 证据：`src/aitest/runners/command_runner.py:60-71,93-96`。
- 影响：临时盘写满；证据缺尾部且无提示。
- 建议：写入侧限总量并排空；返回截断标记。

### 补-B46 HTTP runner 接受 `file:`/`data:`，读取本地文件后 TypeError

- 结论：`urllib` 默认 opener 支持非 HTTP scheme；`file:` 响应 status=None，`None >= 400` 抛 TypeError。
- 证据：`src/aitest/runners/http_runner.py:112-126,45-55`、`worker.py:1439-1448`（已复现）。
- 影响：可读取本地文件；整次运行 execution_error。
- 建议：只允许 http/https；状态整数校验；用例级 error/blocked。

### 补-B47 HTTP 3xx、状态断言和混合断言语义不一致

- 结论：未跟随 3xx 只在 expects 为空时按未完成；只有正文断言会解析重定向体；状态断言忽略 operator；混合断言把 status 当正文字段。
- 证据：`src/aitest/runners/http_runner.py:145-176,199-209`；合同 `docs/项目文档/一期/03-设计/03-CLI与数据契约.md:309`。
- 影响：合法 302+正文断言被判失败；非 equals 状态断言错误执行；混合断言无法同时验证。
- 建议：状态断言独立求值并支持 operator；3xx 未跟随统一 blocked；正文与状态分开。

### 补-B48 显式小写 `content-type` 被默认值覆盖；form+json 发送错误组合

- 结论：`headers.setdefault("Content-Type", ...)` 大小写敏感；Request 规范化为 `Content-type` 后默认值覆盖用户值；同时给 form/json 时 header 与 body 不匹配。
- 证据：`src/aitest/runners/http_runner.py:85-110`（已复现）。
- 影响：接口测试假失败。
- 建议：大小写不敏感设置；拒绝 form+json 或规定优先级。

### 补-B49 HTTP 序列没有总预算/请求数上限

- 结论：每个请求单独超时，循环无总 deadline 和最大请求数。
- 证据：`src/aitest/runners/http_runner.py:58-73`、`worker.py:978-990`。
- 影响：超长序列长时间占用 worker。
- 建议：总 deadline、最大请求数、用例预算。

## 7.3 扩展补充（补-E）

### 补-E01 显式配置的 `aitest.pythonPath` 校验失败后被静默替换

- 结论：设置项只作首个候选，失败后继续尝试 `.venv`/`py -3`/`python`，成功即返回，无用户告警。

### 补-E02 缺少 aitest wheel 时会把依赖 wheel 当安装目标

- 结论：`findBundledWheel` 无 aitest wheel 时回退任意 `.whl`，`WHEEL_MISSING` 不触发。
- 证据：`src/runtime.ts:758-772,897-901,993-1009`。

### 补-E03 已有解释器没有 aitest 版本下限/一致性校验

### 补-E04 高版本坏运行目录会让每次命令重复下载

- 证据：`src/runtime.ts:698-721,858-879,893-909`。

### 补-E05 探测超时被折叠成“没有解释器”，直接触发下载

- 证据：`src/runtime.ts:29,233-238,282-309,1037-1058`。

### 补-E06 下载压缩包不处理写盘背压

- 结论：`stream.write(chunk)` 忽略返回值和 drain。

### 补-E07 解压/venv/安装失败后不回收压缩包和解压树

### 补-E08 超时只杀直接子进程，py.exe/worker/pip 后代继续
