## 2 本轮发现

### 2.1 已修复：`src/` 布局无法导入

tomli 首次运行 5 条全部 `ModuleNotFoundError: No module named 'tomli'`。根因是 worker 执行环境没有把 `<project>/src` 加入 `PYTHONPATH`。修复后同一计划 5/5 通过，并增加 `test_run_env_adds_project_src_layout` 回归测试。

### 2.2 负例：弱信号项目上模型会猜错包名

在真实 Trae 面板用 `samplemod` 的兜底候选生成计划，模型把导入目标写成 `samplemod`，实际包名是 `sample`，导致导入用例失败；结构/测试收集两条仍通过。产品正确判为 **failed**，没有把失败算成通过。这个用例说明：

- 失败分类是可信的；
- 但“模型生成的计划”在仓库信号弱、包名未登记时需要人工复核；
- 不应把“计划生成成功”等同于“计划内容正确”。

随后用明确目标/显式根包导入命令验证，`sample` 根包在 worker 中可正常导入，1/1 通过。

## 4 投产评估

**可以进入受控试点，不建议无人工复核全量投产。**

已经证明：

- 根包与 `src` 布局、真实开源项目、大型项目均可执行；
- 失败、阻塞、取消、依赖缺失、无模型都能正确收敛到四值口径，不冒充通过；
- 备份恢复、交付读取、报告/证据链路可用；
- 备份和证据中未发现模型 key。

仍需补齐：

1. **计划人工复核门槛**：弱信号项目会出现错误包名/错误断言，正式使用前应把“计划必须人工确认”作为强制流程，或增加模型输出校验。
2. **真实 GitHub 成功路径**、真实宿主备份恢复；本轮已用真实 JSONL 日志验证 `link.import/link.assert`，并验证备份/恢复和交付读取。
3. **多项目并发/长运行/磁盘增长**；本轮是顺序执行。
4. **更多框架/布局**：已覆盖 Node 单包；Django/Flask、monorepo、前端构建链尚未覆盖。
5. **企业密钥托管/轮换/审计**：当前 key 在本机用户配置，未做企业级托管。
6. **发布回归**：把 `src` 修复纳入 VSIX 后，用同一版本做安装、执行、导出、恢复的完整回归。
