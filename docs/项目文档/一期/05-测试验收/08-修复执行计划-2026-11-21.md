## 执行原则

1. **按根因修，不按条目逐条打补丁**：同一根因（如全局 kicker、Toast 层级、12px 字号、危险确认焦点）只改一次，台账备注记录关联编号，关闭时一起更新。
2. **先底层后页面**：设计令牌与共享组件先修，页面批次不再重复处理；后端数据形状先定，面板映射后改。
3. **每条闭合必须有证据**：`已验` 必须有修复提交 + 验证证据；证据优先用测试节点，其次是 e2e 用例、截图路径、真实 Trae 记录。代码阅读不算验证。
4. **不静默丢条目**：确实与现行合同冲突的，先改合同再实现；只有产品取舍才标 `需决策`，并由用户确认后才能转 `不修`。
5. **每批独立可回滚**：一批一个主题提交，受改动路径的测试必须通过；批次间不混无关改动。

## 每批完成定义

1. 代码改动完成，新增或更新对应回归测试；测试名称或注释带台账编号。
2. 受改动路径的测试通过：
   - 后端：`pytest tests/unit tests/acceptance` 相关文件；
   - 面板：`npm --prefix panel run typecheck && lint && test`，涉及页面流程时加相关 `test:e2e`；
   - 扩展：`npm --prefix integrations/trae test`。
3. 逐条更新台账：`python scripts/audit_ledger.py --set <编号...> --status 已验 --commit <hash> --evidence <证据>`。
4. `python scripts/audit_ledger.py --check` 通过。
5. 提交，提交信息带批次与编号范围（如 `fix(panel): settings save model (PR-215 PR-216)`）。

- **视觉类条目**：以 1280/390/320 截图对照，证据列存截图路径；不接受“看起来好了”。

- **回归**：每 3 批跑一次全量 pytest 与面板 e2e；失败项回退对应台账状态并记录原因。
