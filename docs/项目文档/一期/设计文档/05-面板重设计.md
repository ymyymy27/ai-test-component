# 一期设计05：面板回迁与后端适配

版本：0.3；日期：2026-11-10  
状态：**已合并 develop #152 面板视觉，并保留当前后端 AI 流程；真实 Trae 全流程待复验**。本文件记录面板从“最小重写版”回迁到 develop 完整面板、再合并其视觉刷新后的界面与适配边界，不替代需求、功能、架构与原有设计分册。

## 1. 决策

2026-11-09 早些时候曾把旧面板整体删除并从零重写，只保留首页/运行/计划/报告/设置/诊断六个入口。该版本丢失了证据正文、问题详情、补证、批量授权、工作流 JSON 等已有能力。

同日决定：**以 develop 的完整面板为准**，回迁其源码与测试，再适配当前后端。回迁后面板保留六个详情页与原有受控入口；后端继续使用同一核心合同。

## 2. 信息架构

| 入口 | 职责 |
| --- | --- |
| 开始测试 | 选择项目、模型与环境、核对并发布计划 |
| 计划 | 范围、用例、依据确认与发布状态 |
| 测试工作台 | 步骤、当前尝试、授权、执行、核验、证据与补证 |
| 问题与报告 | 问题清单、修复回归、报告修订与本地导出 |
| 设置 | 模型配置档、材料范围、凭据引用、存储与显示偏好 |
| 诊断 | 连接能力、只读查询、事件流与原始回执 |

窄侧栏优先，宽编辑器标签页使用同一视图；视觉沿用宿主 `--vscode-*` token。

## 3. 与当前后端的适配

- **Python 版本**：向导环境说明与依赖声明改为 `Python 3.11+`；`setup` 最低版本门禁已改为 3.11。
- **向导收敛**：项目目标与数据隔离合并在第一页，模型配置第二页，减少一次跳转；手工四项检查收进“高级”入口。
- **复核可读**：默认展示用例清单与覆盖摘要，完整提案 JSON 收进“高级：编辑提案 JSON”；修改后必须重新校验。
- **AI 计划主流程**：项目阶段先保存上下文/绑定/环境并执行 `analyze_project`，把持久化 understanding 带入模型；模型阶段生成 `PlanProposal`；复核页调用 `wizardReview` 取得覆盖预览，用户可编辑提案 JSON、重新校验并勾选业务功能目录完整；发布阶段以一次 `publish_plan`（含 `plan_grant`/覆盖契约/understanding 引用）提交，随后 `prepare_run` 与 `register_run`。
- **人工回退**：保留 develop 的四项检查路径（加载/正常/边界/异常），以 `on_demand` + `stepwise` 发布；AI 提案不可用时可切回。
- **普通写通道**：`save_context`、`save_environment`、`analyze_project`、`generate_draft`、`save_case`、`save_acceptance`、`prepare_run`、`register_run` 走 `writeDispatch`，不再逐条弹原生窗口；`save_binding`、`save_model_outbound_policy`、`publish_plan` 仍走受控原生确认。
- **执行与核验**：`execute_step` 回执不再自动刷新，必须由用户点“核实执行状态”读取最新结果；`create_report` 回执不再自动重读，保存后可直接再次保存新修订。
- **宿主错误回显**：扩展返回的 `error` 字段会显示在向导状态区，不再静默卡住。
- **凭据引用**：扩展保存密钥后把引用写回当前向导会话，`wizardSetup` 不再因空引用失败。
- **测试宿主**：面板测试等待真实请求出现后再回执，并闭合运行视图后的自动面板/报告读取，避免时序性假失败。

## 4. 验证

- 扩展 35 项测试通过（含普通写通道边界）；
- `tsc --noEmit` 与面板构建通过；
- 后端 `tests/unit/test_onboarding.py` 18 项通过（含 3.11/3.12/3.13 接受与 3.10 拒绝）；
- 本机 AITest 运行时已按当前源码重装；真实 Trae 中使用回迁面板的完整向导仍需复验。

## 5. 边界

- 回迁面板默认走 AI 提案路径，同时保留四项检查的人工回退；两条路径都不在面板重算判定或授权。
- 复核页的提案 JSON 编辑只做客户端语法提示，发布前由核心重新校验；客户端不产生覆盖结论。
- 面板不重算判定、覆盖、证据等级或授权状态。
- 真实 Trae 的渲染、主题、缩放、证据正文与批量授权窗口仍待宿主复验。
