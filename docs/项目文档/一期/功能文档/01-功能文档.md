## 1 功能及入口

本文“原始输出、原始日志、原始响应”指在落盘前完成不可关闭凭据过滤、未被AI总结或业务改写的捕获材料。已知凭据、认证字段和登记模式按[采集安全合同](../架构文档/02-执行与证据.md#13-采集安全与原始证据语义)处理；无法识别任意未知秘密的限制如实声明，疑似敏感且不能安全处理的材料不保存并列证据缺口。面板、复制、导出和上传仍使用各自安全投影；过滤影响必要核验时不能用替换标记判通过。

一期17项功能，编号P1-FR01—P1-FR17；验收P1-AC01—P1-AC35。纯本地记录，不登录平台、不上传、不监听TCP。被测Git与普通目录、单模块与多模块都可完成适用检查。

## 2 档位、确认与证据语义

| 档位 | 范围与结论 |
| --- | --- |
| quick | 适用L1＋改动模块关键L2＋适用独立核验；由已发布模板与变化匹配确定，不勾选；partial且未打分 |
| on_demand | 用户选层级/模块/环节，未选记未执行而非不适用；partial且未打分，即使全选也不变 |
| full | 开始时覆盖全部适用必测与关键链路；passable但实际通过须满足§3。运行中失败/跳过/取消不改档，只影响真实结论 |

计划驱动默认，按已授权计划连续推进；逐步驱动在边界确认，可合并同类无副作用步骤。有副作用、新凭据或范围扩大必须单独确认。允许planned→stepwise，拒绝反向扩大授权；原始驱动与切换记录都保存。

三类确认不可混用：计划确认绑定Plan修订；执行授权绑定实际动作和输入；结果复核绑定已有Attempt/报告修订。计划确认不确认未来执行结果，也不自动设置人工复核。

断言依据分missing/present_unconfirmed/confirmed。missing阻止进入full必测；present_unconfirmed可运行，计入分母与未核实，不计已验证并降低证据等级。依据确认和实际独立核验各自记录。未发布用例不执行，不等于已发布但依据未确认。

### 运行档位与驱动

一次运行要定两件事，互相独立、都是运行的冻结属性：

- **档位**决定跑到什么程度，以及**这次能不能判通过**。
- **驱动**决定怎么推进，不改变范围与结论口径。

### 档位（决定范围与结论上限）

| 档位 | 跑什么 | 结论上限 | 证据等级 |
| --- | --- | --- | --- |
| 快速检查 | 固定跑 L1 ＋ 本次改动涉及模块的关键 L2 ＋ 按模板适用的独立核验（纯函数预期比对或业务数据核验）；范围来自模板的**最小必测项与关键链路清单**，不需要勾选 | 只代表所选范围，**不判完整通过** | **不打分**（只给覆盖摘要） |
| 按需自测 | 运行时自选检查集，可只选某一层（如只跑 L2）、某个模块或某个环节 | 只覆盖所选范围，**不判完整通过**；未选与未执行项逐条列出 | **不打分**（只给覆盖摘要） |
| 完整验证 | **没有选择，全部执行**：冻结计划内该范围的全部适用必测项，跳过项必须为 0 | 证据与 P0／P1 条件满足时**可判通过**；可按第11节复用有效检查 | **A—D**（**唯一打分的档位**） |

**结论上限只由档位决定，不由覆盖多少或执行方式决定。** 快速检查与按需自测即使把冻结范围全勾上也跑完，仍然只判所选范围的结果，**不能判完整通过**；需要完整通过结论时必须新建一次完整验证运行。执行方式（驱动）同样不改变结论上限。

未选与未执行项一律记为「未执行」并写明原因，**不能当作不适用**；按需自测允许只选下层（例如只跑 L2），此时上层未执行按阻塞或未验证展示，不因此阻止该范围自身的判定。缺少独立核验的检查显示「未验证」，不判通过。

### 档位、结论上限与证据等级

三者互相独立，一次运行同时固定：**档位**决定范围与能不能判通过，**结论上限**是"这次能不能判完整通过"，**证据等级**只在完整验证上回答"这个结论有多硬"。

| 档位 | 结论上限 | 证据等级 |
| --- | --- | --- |
| 快速检查 | `partial`（只代表所选范围）；范围由适用最小必测项与关键链路清单固定，不需勾选 | **不打分**（只给覆盖摘要） |
| 按需自测 | `partial`（只判所选范围，不判完整通过）；**只有本档由用户选择范围** | **不打分**（只给覆盖摘要） |

档位不足时可扩展新档位，但新增档位必须同时定义适用场景、必测范围、统计分母与结论上限，不能只增加名称。

### 驱动（决定谁推进）

| 驱动 | 行为 | 适用 |
| --- | --- | --- |
| 逐步驱动 | 每步确认后执行，可查看中间结果、随时补证、修改后续步骤或退回 | 首次接触被测系统、步骤有副作用、需要边看边判断 |

**逐步驱动的确认语义**：确认表示「允许进入下一步」，**不重新判定断言、不改变结论上限**；连续多个同类且无副作用的步骤可合并为一次确认，避免机械弹窗；**有副作用的步骤必须单独确认**。

| 规则 | 内容 |
| --- | --- |
| 生效范围 | 修改形成运行中修订，**只对尚未执行的步骤生效**，从当前步骤边界起按新修订执行 |
| 已完成步骤 | 绑定其执行时的计划修订，**不回改、不重判、不重跑**；已有证据继续引用 |
| 记录 | 运行记录同时保留基础计划修订与运行中修订序列；报告展示最终范围与每次修订的原因 |
| 重新确认 | 修改扩大范围、新增凭据或引入新副作用时，必须先暂停并等待用户确认 |
| 并发防护 | 以步骤边界为界，不允许修改正在执行的步骤；修改后当前步骤按新修订重取输入，并说明变更内容 |

**驱动可单向切换**：运行中允许在**步骤边界**从计划驱动切到逐步驱动（收窄授权）；**不允许**反向切换（逐步切计划），需要放宽授权时应新建运行。

两种驱动使用同一套三层判定标准、同一模板版本与统一问题清单。任何驱动下遇到扩大范围、新凭据、明显副作用等情形都必须暂停等待确认，不静默跳过。

每次运行固定展示三项：**档位 · 驱动 · 覆盖范围与跳过项**，例如「完整验证／计划驱动／必测 12 项，跳过 0 项」。

## 3 判定与统计唯一口径

业务结论：passed/failed/incomplete/not_applicable。存在本轮所选用例的当前有效决定性失败（H_S非空，定义如下）则failed；尚未确定、阻塞、取消或待核实不被当成失败证据，整体缺完成条件时为incomplete（若已有明确失败，failed并同时列未完成范围）。本轮S为空且无适用检查时显示不适用，不显示100%。

完整通过同时要求：full档、模板必测集合包含、所有适用必测有效通过、跳过为零、无待核实/过期依据、所需真实链路有证据、源码与执行对应、无关联有效P0/P1阻塞问题（按第12.2节处置规则）。低等级本身不改业务结论；依赖环境方式不直接决定等级或通过。环境与数据问题按具体无效证据或验收失败判定；证据完整的非虚拟环境可得A，venv也不保证证据齐全。未确认依据不能计已验证，完整通过还须确认所有适用必测项的断言依据，并有满足原验收条件的实际核验证据；补充确认不替代实际核验。

仅full计算证据等级，取命中条件最严重者；同严重度按下表顺序给主要缺口，全部缺口保留：

| 等级 | 显式条件 | 不表示什么 |
| --- | --- | --- |
| D 无有效依据 | 源码身份与执行不一致；或整轮无任何有效执行依据 | 不把可信的业务失败证据作废 |
| C 关键证据不足 | 所需源码无法核实；关键链路缺失/Mock/未知；必需证据缺失/损坏；必测阻塞、取消、未执行，或执行结果/必要核验证据待核实（不含仅断言依据确认缺失）；相关依据过期；环境问题导致必需核验缺失/失效；实际必测集合低于下限 | 不由字母替代真实业务结论 |
| B 局部不足 | 没有D/C，存在非关键局部未知、非关键核验缺口，或执行及必要核验材料齐全但断言依据已填未确认 | 不表示可提测/可放行 |
| A 证据充分 | 无上述缺口且所有适用判定有完整可追溯证据、关键真实路径已核验、依据确认、源码对应 | 可以有充分证据证明业务失败；A不等于通过 |

有效R引用的原执行证据属于有效执行依据；本轮E为空不自动判D，但R失效且无其他有效依据仍按D/C守卫处理。P0/P1控制业务放行，不把证据自动降为D。无法归类的缺口保守给C并说明原因，不进入默认A。A主要缺口为“无”。快查/按需等级为null，显示未打分和相同事实缺口。

执行完成与业务已验证分别计数；自动断言暂时通过但依据未确认时，显示未核实，不能汇总为完整通过。

设T为模板适用必测条目经冻结CaseLink映射得到的用例ID集合；缺适用条目映射阻止full启动。M为冻结验收范围内全部适用必测用例；S为本轮实际选择的用例，含被选择的补充用例。full要求M⊆S并保留模板下限T⊆M；quick由已发布保守规则确定S；on_demand由用户选择S。运行中不得通过缩减M或弱化预期美化结果。

对任一统计集合X（本轮结果取S，完整覆盖取M），E_X为X中全部必需步骤的当前有效Attempt均在本轮实际完成且输出已保存的用例；R_X为X中经完整复用守卫验证、且未被本轮新Attempt取代的复用用例，E_X∩R_X=∅。V_X⊆E_X∪R_X为依据已确认、所需证据/核验有效且断言明确通过或失败者；P_X为有效通过，F_X为有效失败，V_X=P_X∪F_X，U_X=X−V_X。失败可计入E与V；依据未确认可以在E但不在V；执行异常、取消、阻塞或待核实不计E/V。按用例统计，步骤进度独立计数。

H_X为X中存在当前有效决定性失败的用例ID集合：发布的必要业务断言已明确失败，其依据确认、所需失败核验证据、执行来源和所消费依赖均有效，足以否定该用例必要验收条件；引用准确case_id、step_id、attempt_id、断言/依据修订和证据。整用例有效失败F_X必属于H_X；后续必需步骤未完成时，H_X可以包含尚不在V_X的用例，不能因此增加E/V或移出U。合法整用例复用中仍有效的失败也按同一守卫计入H；一旦新Attempt替代复用或失败依赖过期，旧失败只留历史。普通执行异常、阻塞、取消、未知结果、未确认依据、无效证据和非必要观察均不能进入H。

H仅是现有事实的领域派生结果，不新增可手工修改的业务状态。业务失败优先以H_S判断，不以F_S为空推断没有失败；UI将H显示为“已确认失败用例”，F保留“整用例已验证失败”。H按用例去重，多条失败证据保留引用但不重复计数。S/M两组分别派生，旧报告保持当时输入和策略，不按新规则回写。

| 统计 | 规则 |
| --- | --- |
| 本轮执行/复用/验证 | 分别为count(E_S)/count(S)、count(R_S)/count(S)、count(V_S)/count(S)；复用不伪造本轮执行 |
| 完整必测覆盖 | 分列count(E_M)/count(M)、count(R_M)/count(M)、count(V_M)/count(M)及未验证count(U_M)；未选、跳过、未执行仍在M |
| 模板覆盖 | count(M∩T)/count(T)并校验T⊆M及适用条目映射；无关新增用例不能抵消遗漏 |
| 本轮用例通过 | count(P_S)/(count(P_S)+count(F_S))，仅表示整用例已验证部分；同时显示H_S与U_S，H_S非空仍业务失败，不替代完整通过门禁 |
| 关键链路覆盖 | 满足实际核验条件的适用条目/适用关键链路；缺项列明 |
| 断言依据确认 | 已确认依据的参与用例/全部参与判定用例，与独立核验分开 |
| 零分母 | 不适用或暂无有效验证，不显示100%；M为空不隐藏非空S的结果 |

本轮结果覆盖S中的全部所选项，包括补充用例；H_S非空则本轮失败并列未验证范围；H_S为空且有未验证才为未完成。full完整通过同时要求M全部有效通过、所选补充项没有失败或未验证，并满足源码、范围、关键真实路径、无过期依据及有效P0/P1等门禁。quick/on_demand无论S覆盖多少，都只显示所选范围结果、等级null，不升级full。

例：M=S共12项，本轮执行10项并有效复用2项，则执行10/12、复用2/12、有效验证12/12，其余门禁满足才完整通过。12项本轮均执行但2项依据未确认，则执行12/12、验证10/12、未验证2。按需只选3项非必测补充用例且通过、M有12项，则本轮验证3/3、必测验证0/12，不能显示全范围通过。

新Attempt一旦建立即取代该用例的旧复用资格；新Attempt失败、取消或阻塞不能回退R。复用源及失效原因保留，来源修订与证据可查；缺陷修复关闭仍要求新的实际执行证据，R不能替代。

L1/L2/L3分层统计，上层失败只阻塞依赖它的步骤；独立用例可继续。无前端仅网页操作不适用，仍应通过接口/命令完成适用L3。GitHub绿色汇总不替代原始L1证据。

### 证据等级（只有完整报告才打分）

证据等级是对五维状态的**派生投影**，不是新的事实维度：它不参与断言判定，也不改变结论上限，只回答"这次的结论有多硬"。**它只在完整验证（"完整报告"）上派生**：每次完整验证结束派生一个等级与**一条主要缺口**；快速检查与按需自测**不派生等级**，报告标注"未打分"并给出覆盖摘要。

等级条件与优先级见本节证据等级表。

### 统计与通过条件

| 统计／结论 | 计算或判定规则 |
| --- | --- |
| 真实链路通过 | 关键链路清单里的每条链路都有真实依赖证据，且关键断言通过；模块 Mock 结果不能替代。 |
| 关键链路完成率 | 已覆盖的关键链路条目数 ÷ 关键链路清单条目数；未覆盖条目必须列出，并触发"必测覆盖率警告"。 |
| 证据等级与主要缺口 | **只在完整验证（完整报告）上**由五维状态派生（见本节证据等级表）；快速检查与按需自测标注"未打分"并给覆盖摘要；报告与面板读取同一结果，不在别处另算。 |
| 分层汇总 | L1、L2、L3 分别统计；任一适用必测层级失败、阻塞或未验证，不能显示全部通过。 |
| 证据完整性 | 只纳入已可靠保存的必需证据；采集失败、缺失或待补的项不计完整。 |
| 分母为零 | 显示不适用或尚无可统计结果，不显示 100%。 |
| 单模块项目 | 仅跨模块传播项不适用并注明原因；本模块变化、用例映射和适用回归仍计入各自范围。 |
| 版本与历史 | 按冻结范围及当前版本汇总，保留全部尝试；不能删去失败尝试美化报告。 |

## 4 状态、修订与幂等

执行状态：未执行/排队/执行中/暂停中/已暂停/取消中/待核实/已完成/阻塞/已取消/执行异常。断言结果：未判定/通过/失败/不适用。依赖真实性：真实/Mock/混合/未知。人工复核与计划确认分别存储，不覆盖其他维度。

待核实为非终态，适用于取消停止未确认或副作用结果未知；只有实际核实/补证后离开，不自动重放。重试新建Attempt，尝试序号从1起，重试数=尝试数减1；新尝试立即当前，不回退旧通过。

只在步骤边界修改未执行内容；正在执行的步骤拒绝修改。full不可删必测或弱化要求，违反时拒绝或新建运行。需求/规则/输入不兼容变更须新修订，已完成事实不回改，受影响运行暂停；继续执行不意味着可用过期依据通过。退回阶段标记下游需重跑，旧证据保留并标来源，不伪造已重跑。

prepare_run冻结实际输入并产生intent_id；start同intent原子取得既有run或建立一个run。同intent异payload_hash冲突。重跑显式准备新意图，跨入口恢复同一意图不重跑。start物化摘要须匹配prepare冻结源码；变化时旧意图不可启动，重新准备并核对授权。导出键包含报告修订、所带复核集合、格式和脱敏策略；不得只用计划号去重。

### 状态分别表达

| 维度 | 状态 | 规则 |
| --- | --- | --- |
| 执行状态 | 未执行、排队中、执行中、暂停中、已暂停、取消中、**待核实**、已完成、阻塞、已取消、执行异常 | 表示运行过程；执行器异常与业务断言失败分开。**待核实**（`pending_verification`）用于"请求取消但执行器未确认停止"与"有副作用且结果无法确认"两种情形，可带子类"取消待核实／副作用待核实"；它不是终态，只能由人工核实或补证后离开，且不得被报告汇总为通过或失败 |
| 断言结果 | 未判定、通过、失败、不适用 | 不适用需要原因；未判定不计为通过 |
| 依赖真实性 | 真实、Mock、混合、未知 | 可与断言通过同时存在，不能互相替代 |
| 人工复核 | 待复核、已确认、已驳回 | 保留复核人、时间和意见 |

示例：同一次模块测试可以是「已完成／断言通过／Mock／已确认」，其真实集成验证仍未完成。一期展示执行状态、断言结果、依赖真实性、人工复核与计划生成确认五个维度。

### 暂停、重试与恢复

| 动作／情况 | 处理规则 |
| --- | --- |
| 暂停 | 在步骤边界生效（并行执行时见下一行的"并行组边界"），区分暂停中与已暂停。 |
| 取消 | 确认执行停止后才标为已取消；未确认时保持取消中或**待核实**，**不得伪造已取消**。关闭编辑器不等于停止或业务回滚。 |
| 待核实 | 由人工核实实际业务状态或补证后离开；未离开前不得被报告汇总为通过或失败，也不得自动重放有副作用的步骤。 |
| 并行组边界 | 允许并行执行时，"步骤边界"指**并行组内所有活动步骤都到达可中断点**；暂停、运行中修改与驱动切换只在组边界生效，正在执行的组内步骤拒绝修改。实现若不支持组边界，则进入并行组时禁止运行中修改与驱动切换，并在界面说明原因。 |
| 重试测试 | 产生新尝试并立即成为当前尝试；依赖旧尝试的下游依据按第15节过期并列需重跑，新尝试失败、阻塞或取消时不回退旧通过/复用。 |
| 退回阶段 | 形成新修订，将依赖下游标为需重跑，旧记录可查。 |
| 源码／输入／规则变更 | 绑定新版本并新建运行；查看历史不改变当前结论。 |
| 运行中修改后续步骤 | 在步骤边界生效，记入运行中修订；只影响尚未执行的步骤，已完成步骤不回改不重跑；正在执行的步骤拒绝修改。 |
| 需求／验收项／用例变更 | 一律生成新修订，不改写冻结中的计划与已完成记录；受影响的当前运行暂停并提示，由用户选择继续或新建运行；报告中标注受影响步骤的依据已过期，并列出需重跑的用例（复用 P1-FR03 的变更影响）。 |
| 驱动切换 | 只允许在步骤边界从计划驱动切到逐步驱动；反向切换被拒绝并提示新建运行。 |
| 进程或连接恢复 | 分别处理原句柄重新关联、可安全重试和需人工核实；有副作用且结果未知不得自动重放。 |
| 状态展示 | 保留最近确认状态、缺失材料、重试次数与人工处理记录，连接故障不伪造测试终态。 |

## 5 记录与来源

记录均带schema_version、项目、稳定编号、修订、来源、本机采集时间；业务顺序以提交序号判断，不按可调整的系统时间选最新。关键实体：LocalProject、LocalProjectBinding、Module、Dependency、Task、AcceptanceItem、Delivery、TemplatePack、RuleVersion、Case/CaseLink、Plan、Run、Step、Attempt、SourceSnapshot、EnvironmentRef、EvidenceRef、TraceNode、MockDeclaration、Verification、IssueRecord、ReportSnapshot、LocalReview、ReportExport。

用例链接验收项、模块、环境和关键链路；步骤绑定执行时计划修订；证据绑定运行/步骤/尝试、源码身份及采集来源；报告引用精确记录修订及判定策略。问题与缺陷单是同一issue_id，不另建AI副本。

生成缓存按实际依赖修订集合与生成策略版本，依赖变化定向失效。模型只输出草稿/假设，保留输入来源、模型配置修订、供应方请求标识（若有）、原始响应与错误；迟到响应核对来源修订。模型不可用时原证据、人工处理和导出继续。

其他技术栈按aitest.external-result/1.0导入，保留EXTERNAL_IMPORT；来源号同内容幂等、异内容冲突。能独立核验的重算，不能将外部自述转成真实。被测智能体只认实际采集工具调用；随机业务输出按发布规则逐次评价，默认重复三次属于测试设计，各次保留结果。

## 6 环境、真实性与L3

默认虚拟环境，显式不隔离允许且冻结，环境条件独立展示、不自动降证据等级；源码仍复制到运行目录。网络目标与凭据分别支持模型、被测HTTP、独立核验数据库、可选GitHub只读。数据来源/隔离/复位、业务对象ID、目标部署身份须可追溯；本地源码物化不证明远端版本一致。

请求ID、实际trace父子关系或明确业务关联才形成调用边；独立核验单列，不能拼成原应用调用。无请求标识/结构化日志时人工关联保留级别与缺口，不因缺采集工具直接称产品缺陷，也不因此通过。最终一致性核验使用配置的查询/截止规则，截止只表未知或核验失败，不表示事务回滚。

工单试点：创建并保存ID→查询分页找到同ID→详情一致→修改状态→刷新/重新进入并独立核验最终持久化。任一必需环节失败、跳过或关键依赖未知不能整流程通过；异常路径独立验收。

## 7 问题、报告与留存

问题字段：标题、级别、影响范围、验收项、用例/步骤/尝试、版本与环境、复现步骤、预期/实际、频率、证据、事实/假设、责任人、修复/回归与关闭依据。P0核心全面不可用或严重数据损坏；P1关键业务/结果错误；P2局部影响有替代；P3轻微体验。经确认的有效P0/P1问题按第12.2节阻止关联范围通过，暂缓不得绕过；草稿候选与已核实处置分开。

状态：草稿→待确认→已确认→处理中→待复测→已关闭；复测失败回处理中；重复/不属于缺陷/暂缓保留原因，不删除。修复关闭读取新的实际执行证据，不接受AI或修复说明替代；非缺陷与重复归并按第12.2节独立处置，不伪装为修复通过。

当前结论键=项目＋源码身份（Git基准与diff/非Git文件清单及排除规则）＋适用范围＋环境＋规则/验收/模板/判定策略修订。新full开始即标重新验证，取消/未知不回退旧通过；旧结果只作历史。快查/按需只补充。

报告正文和等级随精确输入修订冻结，变化生成新内容修订；LocalReview独立引用正文，不修改事实/正文。导出冻结所附复核集合并使用脱敏投影；摘要明确不附带证据；证据包含report.md、manifest.json及脱敏附件，相对路径在新目录可访问，缺失/排除逐项列明，不依赖原工作空间链接。缺证据时保留旧历史结论并标当前有效性缺口，不篡改旧正文。

全部业务记录、证据、报告修订、导出、诊断与复核永久保存，无保留期、无自动删除、无删除入口。只回收证据已落盘且执行停止后的运行副本/运行临时文件/上传冗余临时副本，以及经恢复确认的空对象和无有效内容的事务残留；已写入输出先抢救为部分或完整证据，不能先清空。空间统计不删除材料。

### 本地记录完整性

| 项目 | 规则 |
| --- | --- |
| 记录归属 | 每条记录带本地项目编号、本地责任人、工作空间标识与内容修订；不同目录或工作空间的记录不互相串用。 |

## 9 常用流程与增量合同

最小输入、分析时点、验收范围和模型出站以需求§7为产品合同。首次建立单模块草稿和适用计划摘要；快速/按需只校验所选检查所需信息，正式提测才要求交付表，full才要求对应范围全部验收条件。必需检查尚不支持不等于不适用。执行能力和内置模板见[能力与模板清单](02-能力与模板清单.md)。

显式analyze_project创建analysis用途SourceSnapshot，包含所选路径、排除项和内容摘要；GeneratedContent绑定其修订，不能作为已执行证据。计划发布时核对相关来源变化，启动仍物化并核对准备意图。无模型也能人工建立计划，不自动推断可信断言。

AcceptanceScope属于计划的不可变修订数据，含目标、包含/排除范围及原因、依赖闭包和模板适用性。运行冻结scope_revision，结论键的scope取该身份；标题固定“范围名称＋本轮结果”。范围变更重新发布，不得追认原运行覆盖新范围。

ActionAuthorization按动作逐项绑定intent_id/计划步骤、input_digest、target、credential_scope和plan_revision；已解析输入可提前确认，未解析值待执行前确认；start创建Run后关联原intent授权；记录清单式逐项确认，不做集合授权。重复传输不重复询问，但副作用新Attempt需新授权；执行前再核对实际输入。

ModelOutboundPolicy按项目修订，保存接收地址/供应方、允许类别、source_snippets=false默认值及确认记录。发送前核对冻结投影、当前开关与策略修订；扩大数据范围或换目标重新确认，缩小范围立即生效，不再发送被撤销类别。源码片段开关作用所有出站字段及日志/附件投影，不能通过另一类别夹带未授权源码；无法安全投影则排除并显示分析缺口。平台上传的源码禁传规则与此独立。

CopyRepairBrief从Issue/Attempt精确修订生成脱敏文本；事实和假设分段，位置未知不猜测，附复测入口。此动作不执行修复、不关闭问题、不保证可调用Trae聊天API。

查询按项目/业务结果/完整编号分页，报告修订折叠；ProjectViewPreference只记录隐藏/恢复偏好，隐藏不停止运行、不删业务数据。当前检查按原因选择下一步：断言失败到问题证据、环境阻塞到对应配置、未确认依据到依据核对、未知副作用到核实；详情继续展示全部缺口。按需和quick仍不显示完整通过。

### 三层测试标准

| 层级 | 检查目标 | 执行方式 | 必要证据 |
| --- | --- | --- | --- |
| L1 源码可运行性 | 指定源码无语法错误，适用构建和必要入口可运行 | 语法、构建／编译、模块加载或最小启动检查 | 快照、入口、原始输出、退出状态及错误位置 |
| L2 模块功能与集成 | 局部功能及连接后的业务结果正确 | 函数／模块测试、串联接口、业务断言及独立存储核验 | 输入输出、断言、日志、Mock 范围及真实数据证据 |
| L3 用户端到端 | 从业务起点完成完整目标，最终结果正确 | 连续页面操作，或接口／命令／智能体业务流程 | 同一对象编号、全流程步骤、页面或入口证据及最终持久化结果 |

| 情况 | 统一规则 |
| --- | --- |
| 开始测试前 | 先核对范围、源码与环境、依赖、数据；准备检查独立于三层测试。 |
| 某层已通过 | 只代表该层符合条件，不能替代其他层；局部 Mock 通过不能代表真实端到端通过。 |
| L1 失败或阻塞 | 阻塞依赖该入口的后续用例并说明原因；无依赖的用例可继续，但不能放行失败范围。 |
| 缺少必测证据 | 对应层不能判通过；不适用子项必须写明原因。 |
| 没有独立编译步骤 | 可将编译子项标为不适用，仍需检查语法和入口可运行性。 |
| 没有前端 | 只将网页交互子项标为不适用；仍通过接口、命令或智能体入口完成 L3。 |
| 复用已有检查 | 源码、环境、规则及检查范围一致，检查已完成、仍有效且证据可读取，才可复用。 |
| 引用 GitHub 检查 | 需与被测源码、环境和范围对应，并可读取原始结果；绿色汇总状态本身不能证明 L1 通过。 |
| 单模块项目 | 只做该模块的适用层级检查；仅跨模块传播项不适用；本模块变化检测与适用回归照常执行和统计。 |
| 一期网页操作 | 允许人工执行和关联证据；自动回放不在一期。 |

### 11.1 链路工作流

准备选定用例、环境、业务对象和Mock→人工操作或HTTP执行→采集真实请求标识与结构化日志→对同一对象独立查询→关联问题→修复后按原标准回归。HTTP执行器只采集自己实际发出的请求；被测服务的内部节点依赖实际提供的日志或trace，不承诺自动插桩。人工关联必须标来源，独立查询不画成原业务调用。

| 工单顺序 | 必须核对 |
| --- | --- |
| 创建 | 保存真实工单ID及关键字段，不能只看成功提示 |
| 查询和分页 | 在适用筛选/分页下找到同ID，检查边界、重复与遗漏 |
| 详情 | 编号、字段与创建/列表一致 |
| 修改状态 | 记录真实操作、请求、权限条件和预期状态 |
| 刷新/重新进入 | 同ID状态仍正确，独立核验最终持久化 |

文件上传/检索示例分别验证实际标识、内容一致性、无匹配和身份异常；无持久化的纯函数用例按独立期望或参考计算核验，不强制数据库。演示既要证明被测业务完成，也要证明插件完成计划→执行→证据→问题→回归→导出的本地闭环，两者不能互相替代。

| 证据/链路 | 来源、项目/Run/Step/Attempt、对象摘要/大小、完整性、节点ID/真实父子关系、真实性 | 未采集与缺失分别注明，无法确认位置写未知原因 |

执行状态、断言结果、依赖真实性、人工复核、计划发布确认分别展示。例如“已完成/断言通过/Mock/待复核”仍不证明真实集成通过。计划确认只绑定计划修订，不能确认未来结果；人工复核不覆盖原始断言。

| 草稿→待确认 | 失败证据或人工记录，事实与假设分段 |
| 待确认→已确认→处理中 | 用户核实影响、级别与本地责任人，保留确认记录 |
| 处理中→待复测 | 填修复版本、原复现入口与通过标准 |
| 待复测→已关闭 | 新的实际尝试及证据满足原关闭标准；不是重填说明 |
| 复测失败→处理中 | 继续原issue_id，保留前次修复及失败 |
| 重复/非缺陷/暂缓 | 按第12.2节保存独立处置；重复沿主问题判断、非缺陷需核实依据、暂缓仍阻塞 |

P0示例为核心全面不可用或严重数据损坏；P1为关键流程无法完成或假成功但数据未保存；P2为存在替代的局部异常；P3为不影响主要任务的轻微体验。严重程度与开发排期不同，不将P2/P3一概视为满足对应验收项。

复制修复说明与Markdown表单使用下列顺序：来源编号/修订→业务范围→版本/环境/数据→复现步骤→预期/实际→脱敏证据→已观测事实→待核实假设→位置或未知原因→修复版本与复测入口。未确认信息不猜测；非原实现人员凭材料应能复现确定性问题。摘要注明附件未随交付；需带附件时使用证据包及相对路径清单。正文不自动触发修复命令。

### 12.2 问题处置与有效阻塞

IssueRecord的处理进度与disposition分开。disposition为active/fixed/non_defect/duplicate/deferred，保存操作者确认、理由、证据及必要的canonical_issue_id。待确认草稿显示待核实风险，不因AI候选级别直接成为已确认P0/P1；已有真实失败和证据缺口仍按原规则阻止通过。

| 处置 | 必要条件 | 对BlockingRule的影响 |
| --- | --- | --- |
| active | 用户已确认问题与级别，尚未解决 | 关联范围内P0/P1阻塞 |
| fixed | 新实际回归满足原关闭标准 | 修复关闭；保留原失败与修复记录 |
| non_defect | 用户核实误报/脚本原因等，保存具体依据和处置理由 | 该问题不再作为产品缺陷阻塞；不改原执行、断言及证据有效性 |
| duplicate | 指向同项目有效主问题，核实重复依据；禁止自指、循环或悬空引用 | 沿最终主问题计算一次有效阻塞，范围取相关归并范围；不能借归并到低级别问题降低原已确认级别 |
| deferred | 用户记录暂缓原因 | 未解决P0/P1继续阻塞，不等于关闭 |

non_defect停止原修复流程并显示已核实非缺陷；duplicate停止独立修复流程并跟随主问题，原处理进度仅留作历史。撤销上述处置回到待确认并重新核对，不能自动标为修复关闭。

重复链按稳定ID去重解析；主问题仍有效则重复单显示跟随主问题阻塞，主问题修复或经核实非缺陷后不要求每张重复单另跑一次回归。原确认级别需要调整时必须另作有依据的人工确认，不能由归并隐式降级。处置撤销/主问题重开时重新派生当前阻塞，历史报告保持原修订。

误报撤销只改变问题处置；若原用例仍失败或依据失效，报告仍失败/未完成。测试脚本或断言修订后须建立新的有效执行证据才能给新范围通过，不能点击“非缺陷”使原失败变绿。修复关闭与非缺陷结案在界面、报告中分别显示，统一问题编号不删除。

## 13 入口确认与重试边界

计划确认、执行授权和结果复核均保存核心确认来源。AI/MCP可准备或请求动作，不能自填“用户已确认”完成发布、授权、依据确认、问题处置、复核或出站策略确认；需要用户决定时返回待确认并指向面板/交互CLI。确认绑定冻结摘要和修订，同一请求重传返回原确认，输入变化须新确认。具体入口矩阵见[Trae接入第9节](../架构文档/05-Trae接入.md)。

重试区分原结果查询、同一业务请求传输恢复和新的业务Attempt。前两者不重新执行业务；同号写请求恢复须有端点保证且保持原输入/目标/幂等键，不能仅凭HTTP方法推断。新副作用Attempt须重新授权；只读新Attempt仍受原允许范围与有界规则约束。传输次数与业务尝试次数分开，细则见[执行与证据第10节](../架构文档/02-执行与证据.md)。

### 用户与 AI 配合

| 环节 | 操作规则 |
| --- | --- |
| 单步流程 | 理解要求 → 提出方案 → 确认输入 → 执行 → 展示证据 → 判定 → 复核。 |
| 连续执行 | AI 可按已确认计划调用工具连续执行；用户可查看进度、暂停、补充信息或重新执行。 |
| 需要再次确认 | 扩大测试范围、使用新凭据、修改环境配置或执行明显有副作用的操作。 |
| 重复测试 | 按项目预先确认的规则执行，不为已确认的普通重复步骤机械弹窗。 |
| 结论边界 | AI 生成草稿与建议；原始断言与缺陷关闭按实际证据及用户操作处理。 |

## 14 状态分类与判定样例

execution_state表示尚未执行、执行中、完成、阻塞、取消或执行结果待核实；effective_assertion_basis_state表示基于准确Case/依据修订与有效ConfirmationRecord派生的依据缺失、已填未确认或已确认；冻结Case.assertion_basis_state只表示该修订保存时的状态；verification_state表示必要核验未完成、材料无效或核验有效。三个状态不能由一个“待核实”布尔值替代。等级和业务结论仍唯一使用第3节规则。

| 已知输入 | 执行/验证统计 | full业务结论 | 证据等级 |
| --- | --- | --- | --- |
| 12个适用必测均执行，必要核验材料齐全，其中2项仅依据确认缺失，其余有效通过 | E=12，V=10，U=2 | incomplete | B；若另有关键缺口仍取C/D |
| 11项有效通过，1项副作用执行结果未知 | E=11，V=11，U=1 | incomplete | C |
| 12项均有充分有效证据，其中1项断言失败 | E=12，V=12，P=11，F=1 | failed | A；A不代表放行 |
| 12项全部满足合法复用守卫，无本轮新Attempt，均有效通过 | E=0，R=12，V=12 | 其余full守卫满足时passed | A；复用来源可追溯 |
| 无有效执行或复用依据 | E=0，R=0，V=0 | incomplete | D |

上表统计按同一冻结必测集合举例，实际DTO仍分别返回S/M两组。quick/按需无证据等级；所选通过不能替代完整验收通过。确认依据后必须重新评价已存在的实际核验材料，不能直接给verified_count加一。

## 15 用例执行聚合与依赖失效

Attempt属于Step；用例不再以一个含糊的“当前Attempt”代表多步过程。用例聚合使用冻结的必需步骤集合、每步当前Attempt及它实际消费的上游输出。步骤输入绑定upstream_attempt_id、output_object_digest和value_ref；控制/前置依赖也绑定上游Attempt和相应条件事实，不能仅登记有数据提取的边。

上游建立新Attempt时，在同一业务提交中替换该步当前尝试，并将依赖旧尝试的下游当前依据及其传递依赖标OutdatedBasis/需重跑；结论、覆盖和新报告修订随之更新。即使新尝试后来输出同样值，也不自动让旧下游恢复有效。无依赖的分支可继续有效；旧执行、输出、断言和报告保留为历史，不伪造新失败或重跑。退回阶段与普通上游重试使用同一失效机制。首发串行；若以后支持并行，存在受影响活动下游时不得直接替换上游，须先按全组边界停止并核实。

| 当前用例事实 | E/R/V与用户提示 |
| --- | --- |
| 全部必需步骤均为本轮已完成当前Attempt，依赖关联仍有效，输出已保存 | 可计E；依据及必要核验有效且断言明确时才计V，真实失败可计F |
| 整个用例只有符合完整守卫的历史复用，且本轮未启动该用例任何新Attempt | 可计R，按原有效性判V/P/F，显示来源及本轮未重跑 |
| 已启动该用例任一步的新Attempt | 立即取消该用例R资格；失败/取消/阻塞不得退回旧R |
| 部分步骤本轮完成、其余只引用跨运行历史步骤 | 保留每步真实事实和复用来源，但不计整用例E/R/V，列出待执行步骤；不能把跨运行继承计成本轮完成 |
| 本轮先前步骤仍有效，仅重试其依赖下游 | 未受影响的本轮步骤可保持E聚合资格，不要求无关步骤重复执行 |
| 任一步执行异常、取消、阻塞、待核实或依赖过期 | 当前用例不计E/V；仍有效的决定性失败独立计H，业务结论failed并列缺口；无H才incomplete，不用旧通过补齐 |

上表只把第3节E/R互斥及新尝试取代复用落实到多步骤用例；不删掉继承记录、不禁止查看部分执行结果。完成验证需要整用例合法复用，或使必需步骤全部具有本轮有效执行；新副作用Attempt仍需新授权。模板不得把必需步骤改成可选以绕开聚合守卫。

例：S1创建订单A，S2核验A通过；重试S1建立新Attempt时，S2(A)立即作为历史保留且当前依据过期。S1得到B不能与S2(A)组合通过；需重新授权并执行适用下游核验。若另一分支S3不依赖S1，其有效事实无需重跑。P1-AC19/20及统计相关场景验证同输出、异输出、失败、取消、传递依赖、混合继承和重启恢复后的同一结论。

## 16 报告查询与目录绑定

报告列表显示业务结果筛选，完整Run/报告编号精确查询，同Run修订折叠；分别调用reports.latest、reports.by_id、reports.revisions，准确组合与索引见[有限查询目录](../架构文档/04-存储与恢复.md#页面控件与queryspec固定目录)。不把执行状态作为业务结果，不只过滤已加载页，缺索引提示恢复。

设置展示绑定状态并可发起重新绑定，宿主打开目录选择器，核心校验并提交新绑定修订；取消不写入，冻结运行仍保留原绑定。首次向导和设置共用该用例。只自动填入有可靠来源的信息，不能猜测命令、预期或授权后直接执行。

## 17 问题列表的有限查询与复核

问题页默认“未解决”，可切到“全部（含已解决）”。主筛选维度选择模块、层级、人工复核、处理进度、处置或阻塞之一，再选择其一个值；严重程度可独立筛选或叠加任一主维度。全部已承诺维度均可使用，首版不提供任意多维交叉表达式；切主维度清除上一主维度条件，保留显式级别条件并重新分页。未知是可见且可筛选的值，不混作“不筛选”。

所有入口调用issues.list，不对当前已加载页做局部筛选。核心固定14种掩码和OPEN/ALL范围、同commit游标和稳定排序；非法条件明确拒绝，索引损坏提示维护。人工复核仅指当前问题事实的有效人工核对，不等于报告复核、平台审核或问题关闭；定义见[报告与缺陷第14节](../架构文档/03-报告与缺陷.md#14-问题查询投影与复核语义)，索引唯一见[存储与恢复](../架构文档/04-存储与恢复.md#issueslist固定schema与索引合同)。

P1-AC08在既有问题记录验收中增加14种允许掩码、OPEN/ALL、未知字段、多模块不重复、跨页同序号、条件切换、级别/复核/归并主问题迁移、历史根不变和非法组合拒绝。已有P1-AC10/11/14/15/33的证据、关闭、阻塞与交接规则不变，不新增FR或AC编号。
