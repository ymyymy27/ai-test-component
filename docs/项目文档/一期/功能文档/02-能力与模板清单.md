# 一期能力与内置模板交付清单

版本：3.2  
更新日期：2026年9月23日  
状态：必须实现并验证的交付清单，非已安装能力声明。

对应P1-FR04/06/08—13，验收P1-AC17/23/24/30。模板ID为版本化数据标识，不新增FR。实际入口、目标和预期须用户确认。

## 1 能力方式

| 能力 | 一期方式 | 必需输入及边界 |
| --- | --- | --- |
| Python源码可运行 | 自动适配 | 解释器、范围、适用构建/加载/启动入口；不猜启动命令 |
| 既有Python测试 | 登记命令执行 | 入口、预期、依赖环境、参数；不自动知道全部业务需求 |
| HTTP集成 | 已配置流程执行 | 目标、凭据引用、变量、断言、独立核验；远端版本未知不冒充源码一致 |
| 页面业务 | 人工步骤及证据 | 操作与最终核验，不录制回放 |
| 智能体业务 | 登记入口执行或导入实际工具记录，逐次评价 | 输入、实际调用和业务结果；不能凭自述证明执行 |
| 其他技术栈 | 外部格式导入 | 来源、源码身份、尝试、输出、附件；保留EXTERNAL_IMPORT |
| 模型辅助 | 选定脱敏材料生成草稿/解释 | 出站策略、材料、模型；可关闭，不发布计划或伪造执行 |

## 2 首发模板

| ID | 用途 | 必测与关键核验 | 适用边界 |
| --- | --- | --- | --- |
| python-library | Python库/纯函数 | 适用语法/加载、正常/边界/异常输入、预期独立比对 | 无持久化不要求数据库 |
| python-service | Python服务 | 适用构建/加载/最小启动、健康与关键入口、依赖失败、状态变化核验 | 仅实际服务项适用，库项目不强套 |
| http-workflow | API流程 | 同对象请求串联、字段/业务断言、错误路径、持久化独立核验 | 鉴权/会话/持久化按适用条件；必须真实链路不以Mock顶替 |
| manual-web-workflow | 人工页面验收 | 业务路径及适用按钮/分页/跳转/表单/滚动/鼠标/异常提示，刷新后核验 | 无页面不应用；尚不支持不等于不适用 |
| agent-workflow | 智能体评价 | 实际输入/工具调用/结果、发布评价规则；随机输出默认重复三次分别留存 | 无采集列缺口，不采信AI自述 |
| ticket-workflow | 工单贯通示例 | 创建取ID→分页找到同ID→详情→改状态→刷新/重进→独立持久化核验 | 联调示例，不代表所有业务 |

每包含schema_version、template_id/version、适用条件、稳定条目ID、必测集合、关键链路、输入字段、核验方式及样例夹具。空关键链路须不适用理由，缺字段不是空集合。通用模板不穷尽需求，可增补、不删适用必测。

## 3 最小配置与交付验收

quick取适用L1、改动模块关键L2和独立核验；首次或映射不明用已发布保守范围，不能确定则提示配置。按需可选检查，full涵盖AcceptanceScope内全部适用必测。纯函数首次不索要无关数据库/模型/GitHub凭据，正式提测和full的附加条件在对应阶段校验。

每个模板须有版本文件、正常/边界/异常样例、适用性和漏项拒绝案例；安装后可列实际版本。能力仅在适配器、模板与AC均有证据后标支持，未测标未验证。本清单不是实测通过记录。

## 4 模板字段与适用性示例

| 字段组 | 必须表达 | 校验 |
| --- | --- | --- |
| 身份与来源 | schema_version、template_id/version、名称、来源、适用业务/技术栈 | 引用明确版本；未知结构不得自动当可执行模板 |
| 条目 | 稳定item_id、层级、目标、前置、输入字段、步骤/登记入口类型、预期/依据、验证方法、证据要求 | ID唯一、引用可解析，正文不是可执行shell |
| 适用性 | 模块/前端/持久化等条件及理由 | 未满足能力不是不适用，无法判断先列待确认 |
| 必测和关键链路 | 必测ID集合；关键链路ID、必须真实依赖和不可省核验 | 缺字段阻塞，显式空集合须有无适用项依据 |
| 草稿样例 | 正常/边界/异常输入与期望、生成来源和确认状态 | 期望不是实际结果，样例不冒充真实执行 |

python-library的纯函数没有持久化时，数据库核验条目不适用但独立预期比对仍适用；http-workflow的状态写入需要同对象独立持久化证据，成功HTTP状态不能代替；manual-web-workflow只在有页面时应用，相关按钮/分页/滚动和异常提示按业务实际覆盖；agent-workflow缺工具采集时保持证据缺口；ticket-workflow复用HTTP/人工能力贯通同一工单ID，不额外引入专用执行引擎。

## 5 发布与导入校验

安装时能列出六个模板的真实版本与实际支持方式；选择模板只创建草稿，用户补齐本项目入口/数据/预期和范围后发布。导入规则/模板保留来源与未识别扩展字段，但未知执行字段不得静默启用。相关上下文或模板变更时只使受影响草稿失效，人工修改需合并确认，不能重生成覆盖。验证缺必测字段、重复ID、悬空引用、明确不适用与尚不支持五类输入；预期及证据记录沿用P1-AC17/24/30。

## 6 首期适配器最小交付合同

| 能力 | 最小执行机制与输入 | 实际输出/不支持条件 |
| --- | --- | --- |
| Python源码检查 | 用户登记解释器及适用语法、导入、最小启动入口；通过共同命令执行器运行 | SourceCheckResult及命令、退出事实、原始输出；未登记入口不猜命令，不将缺依赖当语法错误 |
| 既有测试命令 | 明确argv、工作目录、环境修订、输入、预期及副作用授权 | Attempt和输出块；未经登记的shell正文不能因来自模型而执行 |
| HTTP流程 | 已登记目标、方法、凭据引用、字段提取、变量来源、关联业务对象与断言 | 响应事实和请求关联；领域统一评价断言，写请求恢复必须有端点幂等合同 |
| 独立核验 | 首发支持已配置只读HTTP查询及纯函数独立预期比对；输入同一业务对象标识和独立预期 | VerificationResult含来源、对象、观察值、预期引用、证据和有效性；数据库驱动仅在安装清单明确列名且实测后可用，不能声称通用数据库支持 |
| 人工页面 | 发布步骤清单、用户实际操作说明、附件及最终读取核验 | 人工来源、步骤/尝试关联和材料缺口；不包含浏览器录制回放 |
| 智能体业务 | 登记入口调用，或导入实际工具事件；预先发布评价规则，随机输出按计划三次分别执行 | 每次输入/响应、实际工具事件及业务观察；缺工具采集保持缺口，不以文字自述补造 |
| 外部结果导入 | aitest.external-result/1.0结构及受控附件包 | 验证来源、关联和摘要，始终EXTERNAL_IMPORT；未知执行字段不自动启用 |
| 可选模型 | 显式材料范围、ModelProfile与出站策略，结构化草稿Schema | 草稿/解释与来源修订；关闭或失败仍支持人工计划和报告 |

各适配器复用同一调度、授权、Attempt、采集、导入和错误处理组件。六种模板是版本化数据，不创建六套执行引擎。首发串行执行依赖顺序；运行中修订、暂停/取消、未知处理和全部一期能力仍为必交。至少为每种能力提供真实可执行成功样例、证据不足样例和不支持输入样例，版本与证据写入兼容清单；本表不表示适配器已实现。

## 7 外部结果与智能体事件结构

ExternalResult必需字段：schema_version="aitest.external-result/1.0"、source_system、source_result_id、source_revision、project_id、layer、source_identity（未知为null并填reason）、attempt_ref、execution_facts、assertions、mock_declarations、attachments。没有本地Run/Attempt映射时由导入用例创建外部记录并显式关联，不能借外部编号覆盖本地Attempt。幂等键为(project_id, source_system, source_result_id, source_revision)，冻结payload_digest，同键异内容冲突。

execution_facts含入口类型、输入摘要、真实开始/结束信息（缺失为null）、执行状态、实际退出码/响应码及输出引用。assertions包含已登记case_id、依据引用、观察值、外部自报结论与可核验材料；外部自报结论不直接成为本地有效验证。附件条目包含attachment_id、相对包内路径、媒体类型、size、digest及完整性；解包拒绝绝对路径、链接逃逸、重复ID和摘要不符，未知扩展字段保留但不执行。

智能体工具事件包含event_id、source_result_id、序号、tool_name、call_id、parent_call_id（可空）、参数安全投影、实际结果引用及采集来源。循环调用同一工具用不同call_id；缺事件的工具调用保持未知。工具调用只是证据，仍须按发布规则核验最终业务对象。正常导入、重复导入、异内容、附件缺失、未知源码和仅有自述分别作为导入合同样例。

## 8 采集与执行来源守卫

所有首发适配器共用[落盘前凭据过滤](../架构文档/02-执行与证据.md#13-采集安全与原始证据语义)；“原始输出”均为该合同允许保存的捕获材料。命令/Python共用包装器，HTTP/核验共用受控传输，模型与人工/外部导入同样不能绕过过滤。无法安全处理的附件保留缺口，不以缺少实现能力虚构不适用。

Python与命令入口遵守[执行来源核对](../架构文档/01-项目与计划.md#12-执行来源与物化边界)：venv可复用不代表项目代码来源正确；editable、路径和配置必须对应冻结范围。能力验收分别提供安全采集、加载来源不符、依赖结果过期的反例，不因此删减六个模板或已承诺执行方式。
