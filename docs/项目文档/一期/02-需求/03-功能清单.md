## 2 状态与枚举

### 2.1 运行状态

| 值 | 含义 |
| --- | --- |
| `running` | worker 正在执行 |
| `completed` | 正常结束 |
| `cancelled` | 收到取消并在用例边界停止 |
| `interrupted` | 心跳超时且 PID 不在，被接管 |
| `execution_error` | 执行异常或取消未确认停止 |

运行状态与业务结论分开：状态描述进程，结论描述本次范围的结果。

### 2.2 业务结论

| 值 | 条件 |
| --- | --- |
| `passed` | 所选范围内全部适用用例有效通过 |
| `failed` | 所选范围内存在有效失败 |
| `incomplete` | 无有效失败，但存在阻塞、未知、未执行或 L3 未记录 |
| `not_applicable` | 所选范围无适用检查 |

结论只对本次运行的 `S` 成立；未选验收项不属于本次范围。

### 2.3 用例结果

`passed / failed / blocked / error / not_run / manual_pending`。

- `blocked`：缺环境、依赖、数据，或依赖的 L1 检查失败；
- `error`：脚本自身错误、执行异常；
- `manual_pending`：L3 等待人工记录；
- 以上都不计入通过。

### 2.4 Mock 真实性

`real / mock / mixed / unknown`，由 AI 依据代码与运行证据判定并附依据；不可手工修改。

### 2.5 问题状态

```text
待确认 → 处理中 → 待复测 → 已关闭
            ↑          │
            └─ 复测失败 ┘
```

处置值：`修复 / 非缺陷 / 重复 / 延期`；后三个必须写理由；已关闭可重开并写原因。

## 3 范围与覆盖

- 选择单位是验收项，不挑用例；
- 预设：全部适用 / 自选；自选先按模块筛，可选再按层级筛；
- `M` = 当前任务适用验收项；`S` = 本次所选；`S⊆M`，空 `S` 不发布、不运行；
- 唯一例外是 `smoke` 目标且任务没有适用验收项：只做项目级 L1 检查，报告显示 `0/0` 与 L1 结果，不把项目检查算成验收项通过；
- 范围在计划发布时固定，`run.start` 可收窄到子集；运行中改范围必须新建运行；
- 覆盖固定展示 `|S|/|M|` 与未覆盖清单；`|S|<|M|` 时只说“本范围通过”。

L1：

- L1 是项目级检查，不进 `S/M`，不计入验收项计数；
- 用例标 `depends_on`：`build`、`service` 或空；
- L1 构建/入口失败只阻塞 `build` 依赖；
- 服务启动失败只阻塞 `service` 依赖；
- 阻塞原因列在报告“项目级检查”区。

## 4 计数口径

- 主表按验收项：取该验收项所有用例的最差结果，顺序 `失败 > 阻塞/未知/未执行 > 通过`；
- 覆盖、通过率、运行结论都从验收项口径派生；
- 用例明细附表：层级、所属验收项、结果、证据引用，导出也带；
- 一条用例覆盖多条验收项时，在各验收项下各计一次；用例总数只计一次；
- L1/L2/L3 数量按用例单独统计；
- 全部验收项不适用时显示“不适用”，不显示 100%。

## 5 执行

### 5.1 执行前确认

展示范围、用例数与层级分布、环境、凭据边界与明显副作用、将安装的依赖、预计耗时；确认后启动，记录 `confirmed_by`、`confirmed_at`。改范围、换环境、换凭据、明显副作用变化时重新确认。

### 5.2 运行

- 一次运行一个 worker；`run.start` 校验计划与确认记录；
- worker 独占运行目录，按计划顺序执行并刷新心跳；
- 同一项目同时只允许一个运行；第二个直接拒绝并返回现有运行 ID；
- 跨用例串行；runner 内部并行可选，需结构化输出；
- 取消写标志文件，用例边界停止；未确认停止记 `execution_error`；
- 心跳超时且 PID 不在 → `interrupted`，保留已完成部分。

### 5.3 服务与数据

- 按项目配置启动/停止；先探测健康地址，已通不接管；
- 只停止自己启动的服务；默认运行后停止，`keep_on_failure` 可保留现场；
- 测试数据带运行标记或记录业务 ID；默认不清理；`data.cleanup` 默认 dry-run。

### 5.4 测试文件与 L3

- AI 生成 pytest/HTTP/Playwright/SQL 到 `runs/<id>/generated/`，不进仓库；
- 用项目环境运行；缺依赖随执行确认安装，否则 `blocked`；
- L3 两种载体：前端 UI、接口/命令；不可自动化转 `manual_pending`；
- 人工记录逐条落盘；未记录计入未完成。

### 5.5 证据

单文件 20MB 截断；单次运行媒体软上限 500MB；超限先压缩截图、再跳过通过用例截图，失败证据不降级；视频默认关闭；不自动删除；磁盘不足停止写入。

## 6 AI 判定与边界

- 分析：四段式，缺“未验证”整条不合格、不展示；异步，不改状态；
- Mock：按需读代码，默认 40 文件/3 层，附依据，判不出即 `unknown`；
- 摘要：只写事实与计数，命中结论词不采用；
- 生成代码：仓库内容当数据；危险操作扫描命中即阻断；脚本纳入执行确认；
- 不做：判定结论、改被测代码、自动装依赖（未确认时）、代替确认、操作 UI、关闭问题。

## 7 报告

- 开头固定“结论”段：core 生成，四值 + 范围 + 未覆盖数 + 失败数；
- 范围与覆盖、版本、规则、分层结果、Mock、涉及模块、问题、分析、未验证、证据索引；
- 涉及模块由变更文件映射；未映射文件单独列出；
- 验收意见为自由文本，无流转；不填显示“未填写验收意见”；
- 导出 Markdown，凭据不出现。

## 8 人工动作

选目录、首次配置密钥、执行前确认、处理不可自动化 L3、处理坏环境、纠正明显错误（改范围或重跑）。看报告与填写验收意见可选。

## 9 维护约定

- 同一字段、状态、判定只在本册定义一次，其他文档引用；
- 枚举与口径变化时同步需求规格、设计、架构、测试与验收场景；
- 旧 21 FR / 35 AC 已废止，不再维护映射；
- 未实现或未验证的能力标“未实现/未验证”，不写成通过。
