# 功能清单（一期）

> 适用期次：一期；主责：功能行为、判定与统计唯一口径、状态、问题与模板；状态：需求重写版，未重新验收。
> 范围与验收场景见[需求规格](02-需求规格.md)；业务角色与流程见[业务方案](01-业务方案.md)；决策见[需求基线与决策](00-需求基线与决策.md)。

一期共 **21 项功能（FR01—FR21）**，验收场景见需求规格 §4。本册不复制场景正文，只定义行为、状态、判定与可观察结果。

## 2 运行档位、驱动与结论上限

- **探索自测**：选择局部用例快速取得真实结果；可关闭非必要 AI；缺少独立核验时标未验证；不能升级为完整通过。
- **完整验证**：执行冻结范围内全部适用检查；只有完整验证可以形成“完整通过/完整失败”的判断。
- 档位与登录状态无关；一期不登录。
- 驱动：`planned` 自动推进；`stepwise` 在步骤边界确认。
- 档位不因执行结果改变；需要调整范围时新建运行。
- 扩大范围、使用新凭据、修改环境、执行明显副作用动作时，必须重新确认。

## 3 判定与统计唯一口径

本节是业务结论、覆盖与计数的唯一正文；面板、报告、导出只读取核心派生结果，不另算。

### 3.1 业务结论

| 结论 | 条件 |
| --- | --- |
| `passed` | 本轮适用必测全部有效通过，无阻塞、取消、未验证或过期依据 |
| `failed` | 本轮存在当前有效决定性失败；同时列出未完成范围 |
| `incomplete` | 无有效决定性失败，但存在未完成、阻塞、取消、未知或依据未确认 |
| `not_applicable` | 本轮没有适用检查 |

失败与未完成可以并存：判 `failed` 时仍展示未完成范围；阻塞本身不算失败。

### 3.2 覆盖集合

- `S`：本轮所选范围；`M`：冻结必测范围；`E`：本轮执行完成的整用例；`R`：合法整用例复用；`V`：有效验证。
- `E ∩ R = ∅`；`V ⊆ E ∪ R ⊆ S`；完整验证要求 `M ⊆ S`。
- `P`：有效通过；`F`：有效失败；`U`：未验证。
- 一条 L3 不能代替全部层级；L1/L2/L3 分别计数。
- 未执行、阻塞、取消、未知不计入 `E` 或 `V`；失败可计入 `E` 与 `V`。
- 空分母显示“不适用”或“尚无可统计结果”，不显示 100%。

### 3.3 完整通过门禁

必须同时满足：

1. 完整验证；
2. 验收项覆盖完整；
3. 全部适用必测有效通过；
4. 无阻塞、取消、未知或过期依据；
5. 必要真实链路有证据，Mock 与真实性符合声明；
6. 源码、环境与执行对应；
7. 无未关闭 P0/P1；
8. 报告引用的证据完整可读。

### 3.4 复用与依赖

- 复用要求源码、环境动态状态、入口参数、范围、规则、适配器版本一致且证据可读。
- 新尝试立即撤销该用例的整用例复用资格；失败、取消或阻塞不回退旧通过。
- 上游新尝试使依赖旧输出的下游依据过期；旧事实保留，不自动复活。

## 4 状态

### 4.1 执行状态（10 值）

未执行 `not_started`、运行中 `running`、暂停请求 `pause_requested`、已暂停 `paused`、取消请求 `cancel_requested`、取消中 `cancelling`、恢复中 `recovering`、已完成 `completed`、已取消 `cancelled`、执行异常 `execution_error`。

- 取消需确认执行停止；未确认按执行异常记录并说明，不伪造已取消。
- 未知副作用不自动重放。
- 编辑器关闭不等于执行取消。

### 4.2 其他状态

| 维度 | 值 | 规则 |
| --- | --- | --- |
| 断言结果 | 未判定、通过、失败、不适用 | 不适用需原因；未判定不计通过 |
| 依赖真实性 | 真实、Mock、混合、未知 | 可与断言通过并存，不能互相替代 |
| 人工复核 | 待复核、已确认、已驳回 | 保留复核人、时间、意见 |
| 问题处理 | 草稿、待确认、已确认、处理中、待复测、已关闭 | 另有处置值：active／fixed／non_defect／duplicate／deferred |
| 计划 | 草稿、已发布、已撤回 | 发布后冻结；变化新建修订 |

## 5 对象与记录

主线：任务 → 验收项 → 用例 → 执行/证据 → 问题 → 修复版本 → 回归 → 报告 → 验收意见。GitHub 变更与链路节点作为证据关联对象。

- 记录带项目编号、内容修订、来源与采集时间；业务先后按提交序号，不按系统时间。
- 路径、仓库、分支是绑定属性，不是业务主键。
- 业务记录、证据、报告、问题、复核永久保留；不设保留期、不自动清理、无删除入口。
- 运行期物化副本与临时文件在证据落盘且执行停止后回收，不属于业务记录。

## 6 规则与模板

- 规则分人读步骤与 AI 规则，支持版本、项目绑定、Markdown 导入导出。
- 新测试使用新规则版本，历史记录保留原版本。
- 模板是**规则库的预设检查清单**：AI 逐项给出处置，不静默删除；`not_applicable` 需理由，`unsupported` 作为已知限制。
- 模板不是第二套发布门禁，也不替代验收项；不适用模板项不进入必测分母。

## 7 分层测试

| 层级 | 核心问题 | 必须记录 |
| --- | --- | --- |
| L1 | 源码是否可运行 | 源码快照、入口、语法/构建/加载结果、错误位置、退出状态、证据 |
| L2 模块 | 局部功能是否正确 | 命令/入口、输入、断言、输出、日志、Mock 范围 |
| L2 接口/集成 | 模块是否接通、业务结果是否正确 | 请求/响应、业务断言、模块交互、数据库结果、证据 |
| L3 用户场景 | 用户能否完成业务 | 步骤、业务对象、截图/请求关联、最终持久化、未覆盖项 |

- 上层失败只阻塞依赖它的步骤；独立用例继续。
- 任一适用必测层级失败、阻塞或未验证时，不能显示全范围通过。
- 没有前端时，L3 通过接口、命令或智能体输入输出完成；网页交互子项标不适用。

## 8 Mock 与真实性

- 状态：真实、Mock、混合、未知；绑定具体版本与环境。
- 静态检查只产生疑点：出现 mock 字样不判假，没有关键字也不判真。
- 声明外 Mock、关键节点真实性未知、缺少真实结果证据时，阻止该范围获得“真实链路通过”。
- 局部 Mock 通过只覆盖声明范围，不计真实集成通过。

## 9 GitHub

- 只读关联仓库、分支、提交、PR、已有检查、合并状态。
- 每次测试固定被测提交，并记录部署版本；不一致提示不匹配，无法取得标未确认。
- 检查通过不改变业务结论；不能用缓存冒充最新检查。
- 一期手动刷新，不接 Webhook，不自动发起测试。

## 10 链路

- 输入：页面操作记录或接口执行记录、请求标识、后端日志、模块调用、数据库结果。
- 节点：名称、父节点、类型、状态、耗时、脱敏输入输出、证据来源、真实性。
- 未采集或无法匹配的节点显示缺口，不补造；缺少关联标识提示无法可靠关联。
- 断言：请求是否到达服务、返回字段、记录是否写入并可查询。
- 定位：展示首个观测异常节点、上游输入、下游影响；首错不一定是根因，必须说明依据与未知范围。

## 11 问题与缺陷

- 失败步骤可生成问题草稿；用户确认后提交。
- 分级 P0—P3：P0/P1 阻止当前范围验收；P2 按范围安排；P3 进入优化计划。
- 状态：草稿 → 待确认 → 已确认 → 处理中 → 待复测 → 已关闭；可重开。
- 处置值：active／fixed／non_defect／duplicate／deferred；non_defect/duplicate/deferred 需理由。
- 关闭必须有新的实际执行证据；开发修复说明与 AI 判断不能替代回归。
- 一次测试失败不自动等于产品缺陷；需区分环境、数据、脚本与产品原因。

## 12 报告与验收

- 报告按项目、任务、版本生成；含范围、源码/环境/GitHub 版本、规则、L1/L2/L3 结果、Mock、问题、未验证项、证据索引。
- 测试完成与验收通过分列；AI 只能生成说明或草稿。
- 报告修订冻结输入；输入变化生成新修订，旧意见保留在原版。
- 导出 Markdown，使用统一编号；凭据等敏感信息不进导出。
- 一期验收意见为本地记录，不做跨账号共享审核。

## 13 人工确认与动作日志

- 计划发布前确认一次：范围、环境、凭据边界、明显副作用。
- 执行中有副作用或越界动作记录动作日志（动作、目标、输入摘要、结果、时间、来源），不建计划许可账本。
- 计划确认、执行确认、复核都不产生执行或核验。
- AI 与 CLI/MCP 不能代填人工确认。

## 14 维护约定

- 同一字段/状态只在需求规格或本册定义一次，其他文档引用。
- 枚举、阈值与判定变化时同步需求、架构、设计、测试与验收场景。
- 旧 17 FR / 35 AC 只作历史映射，不再作为现行编号。
- 未实现或未验证的能力必须标“未实现/未验证”，不能写成通过。
