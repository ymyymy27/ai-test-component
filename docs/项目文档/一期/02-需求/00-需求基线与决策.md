# 需求基线与决策（一期）

> **已废止（2026-11-16）**：本文属于系统级方案，不作为轻量插件重构的实现依据。现行基线见[轻量 Trae 插件修改计划](../../../修改日志/ymy/2026-11-16-轻量Trae插件重构计划.md)。新文档就位后移入 `docs/归档/`。


> 适用期次：一期；状态：决策基线，用于重写业务方案、需求规格、功能清单与验收场景。
> 本册不替代实现文档；字段、状态与代码落点由后续重写后的需求/架构分册维护。

## 1 为什么重写

此前的一期需求（17 FR / 35 AC）和开发中产生的设计已经偏离产品目标：
宿主、账号、上传、链路工具、GitHub 关联、保留期和授权模型存在互相冲突的口径。
本册把已经确认的决策固定下来，后续文档与代码按此收敛，不再维护多套编号。

## 2 已确认决策

| 主题 | 决策 |
| --- | --- |
| 产品宿主 | **一期 Trae**；二期再扩展其他编辑器 |
| 统一账号 / 结果上传 / 共享审核 | **一期不做，后置**；本地记录与导出继续可用 |
| GitHub 变更关联 | **一期做**：只读仓库/分支/提交/PR/检查/部署版本 |
| 链路测试工具 | **一期做**：请求或操作 → 后端日志 → 模块调用 → 数据库证据 → 断言/定位 |
| 需求编号 | **全部重写**；此前 17 FR 与外部 v2.0 均不作为权威编号 |
| 证据与记录保留 | **永久保留**，不设自动清理 |
| 计划确认与执行授权 | **一次范围确认 + 动作日志**；不建计划许可账本，不做逐动作授权记录 |
| 覆盖与等级 | **保留覆盖统计；删除 A—D 证据等级** |
| 文件格式升级 | **只支持当前格式 + 升级前备份**；旧格式拒绝并提示导出/重建 |
| 模板体系 | **保留**，作为规则库的预设检查清单，不形成第二套发布门禁标准 |
| Python | **3.11 及以上**；当前验证矩阵为 3.11/3.13，3.14 未验证 |

## 6 验收策略

- 旧 35 条 AC 不再作为唯一基线；重写后按 21 FR 重新组织验收场景。
- AC 只做校验器：可以合并、改写或删除；判断标准是需求是否被满足。
- 一期验收至少覆盖：GitHub 版本关联、L1/L2/L3、Mock、链路采集与断言、缺陷回归、报告、Trae 真实接入、断连恢复、备份恢复。
- 账号/上传/共享审核不进入一期 AC；保留为后续路线图。
- 任何标为 `verified` 的条目仍必须有真实环境证据；组件测试与文档一致不能升级状态。
