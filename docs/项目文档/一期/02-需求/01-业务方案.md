# 业务方案（一期）

> 适用期次：一期；主责：业务角色、处理对象、流程、规则与异常；状态：与需求规格、功能清单同源，不代表已实现或验收。

本文件从[需求基线与决策](00-需求基线与决策.md)、[需求规格](02-需求规格.md)、[功能清单](03-功能清单.md)中提炼一期业务口径。它不新增 FR/AC、不改写判定规则；出现分歧时以需求规格与功能清单正文为准。

一期是 **Windows 11 x64 上的 Trae 插件**：本地 Python 核心 + 编辑器扩展 + 面板，记录保存在本机文件工作空间。一期不登录、不上传、不做共享审核；这些能力后置。

## 1 业务角色与确认

一期不做账号体系与角色继承。同一个人可以承担多个角色，但每次确认必须指向具体操作、准确修订和来源。

| 角色 | 能做什么 | 不能做什么 |
| --- | --- | --- |
| 开发者（交付方） | 提交交付说明、登记入口与参数、修复问题并登记修复版本 | 不能把自述完成当测试通过，不能确认断言依据或关闭问题 |
| 测试执行者 | 建立项目与绑定、理解项目、编辑规则/计划/用例、选择范围、执行、核验、生成报告、处理问题、导出 | 不能绕过档位判完整通过，不能删必测或缩范围修饰结论，不能跳过独立核验 |
| 本地复核人 | 对报告修订记录复核意见 | 不能改报告正文、执行与断言事实，不能把失败改成通过 |
| AI 辅助 | 生成摘要、交付草稿、计划/用例草稿、证据分析与候选原因 | 不能自报用户确认，不能发布计划、处置问题、复核、关闭问题或改写结论 |
| 被测应用 / 外部环境 | 提供请求标识、关键节点日志、部署版本、数据库核验入口 | 缺少采集不能补造，不能以自述替代实际采集 |
| GitHub（只读） | 提供仓库、分支、提交、PR、已有检查、合并状态 | 不能替代业务测试，检查通过不等于业务通过 |

确认分三类，不能互相替代：

| 确认 | 绑定对象 | 证明什么 | 不证明什么 |
| --- | --- | --- | --- |
| 计划确认 | 计划修订 | 用户认可这一版测什么、怎么测 | 不确认未来执行结果 |
| 执行确认 | 一次范围/环境/凭据/明显副作用边界 | 允许在确认范围内执行 | 不产生执行事实或断言结果 |
| 结果复核 | 已有尝试或报告修订 | 复核人看过并给出意见 | 不改写断言、正文或结论 |

- 人工确认只能来自核心认可的 Trae 用户交互；CLI/MCP 不能代填。
- 扩大范围、使用新凭据、修改环境、执行明显副作用动作时必须再次确认。
- 一期不做跨账号协作、上传和共享审核；本地记录与导出仍可用。

## 2 处理对象

主线：**任务 → 验收项 → 用例 → 执行/证据 → 问题 → 修复版本 → 回归 → 报告 → 验收意见**。GitHub 变更与链路节点是执行证据的关联对象。

| 对象 | 身份 | 生命周期 | 关系 |
| --- | --- | --- | --- |
| 项目 | 稳定本地项目编号，不随名称/路径变化 | 建立后长期使用 | 挂任务、模块、用例、运行与问题 |
| 绑定 | 绑定修订；git 或 plain | 目录移动或形态变化新建修订并重新确认 | 引用源码快照与环境 |
| 模块 | 稳定模块编号与修订 | 研发登记，AI 推断需确认 | 负责人、依赖、接口、实现状态 |
| 任务 | 任务编号与修订 | 需求变化形成新修订 | 验收项、交付说明、用例 |
| 验收项 | 独立编号与修订 | 需求变化保留历史 | 用例、执行证据、验收意见 |
| 交付说明 | 与任务和源码版本关联 | 确认后提测；变化新建修订 | 完成/未完成、Mock、自测证据 |
| 规则版本 | 规则编号与版本 | 发布后新测试用新版本，历史保留 | 计划、执行记录 |
| 计划 | 计划编号与修订，发布后冻结 | 范围/用例/依据变化新建修订 | 运行引用；不反写历史 |
| 用例 | 用例编号与修订 | 草稿 → 发布；编辑保留修订 | 验收项、层级、前置条件、预期、Mock 许可 |
| 运行 | 运行编号 | 准备 → 启动 → 执行 → 终止 | 冻结档位、范围、源码、环境与规则 |
| 尝试 | 属于步骤，从 1 起 | 重试新建并成为当前尝试，旧尝试保留 | 输出、证据、下游依赖 |
| 证据 | 采集时间、来源、摘要、脱敏状态 | 永久保留；临时副本在证据落盘且执行停止后回收 | 绑定运行/步骤/尝试、源码与链路节点 |
| 链路节点 | 节点标识与执行编号 | 一次执行内保留 | 父节点、类型、状态、耗时、断言、证据 |
| 问题 | 统一编号与内容修订 | 草稿 → 待确认 → 已确认 → 处理中 → 待复测 → 已关闭；另有处置值 | 验收项、用例、执行、证据、修复版本 |
| 报告 | 报告编号与内容修订 | 输入变化生成新修订，旧修订保留 | 证据、问题、分层结果、验收意见 |

共同约定：

- 记录带项目编号、内容修订、来源与采集时间；业务先后按提交序号，不按系统时间。
- 记录归属单一工作空间，不跨目录/工作空间串用。
- 路径、仓库、分支是绑定属性，不是业务主键。
- 业务记录、证据、报告、问题永久保留；不做自动清理或删除入口。
- 运行期物化副本与临时文件只回收非业务材料。

## 3 目标流程

1. **建立项目与绑定**：选择目录、登记项目目标/模块/依赖；git 或 plain 均可；同步盘/网络盘拒绝。对应 FR01。
2. **建立任务与验收项**：定义目标、范围、输入输出、前置条件、验收项、执行/验收人；验收项必须可观察。对应 FR02。
3. **提交交付说明**：完成/未完成、变更模块、接口变化、运行方式、测试数据、依赖、Mock、自测证据；AI 可起草，用户确认。对应 FR03。
4. **关联 GitHub 变更**：读取仓库、分支、提交、PR、已有检查、合并状态；记录部署版本；检查通过不替代业务测试。对应 FR04。
5. **确认规则与范围**：规则版本、项目绑定、模板预设、验收范围与 Mock 许可；模板是提醒清单，不是第二套门禁。对应 FR05/FR06。
6. **生成与发布计划**：AI 建议，用户编辑后发布；计划冻结范围、用例、规则、档位与驱动。对应 FR06。
7. **分层执行**：
   - L1 源码可运行性：语法、适用构建、入口加载/最小启动；
   - L2 函数/模块与接口/集成：断言、输出、日志、独立存储核验；
   - L3 用户场景：人工操作、业务对象贯穿、最终持久化核对。
   对应 FR08—FR12。
8. **链路采集与定位**：一次操作/请求 → 请求标识 → 后端日志 → 模块调用 → 数据库结果；节点断言，首个异常节点与上下游，缺口可见。对应 FR15/FR16。
9. **AI 分析与人工复核**：事实、证据引用、候选原因、未验证内容、下一步；用户采纳/修改/驳回。对应 FR13。
10. **形成结论与报告**：按范围汇总 L1/L2/L3、Mock、未知、问题、未验证项与证据索引；报告修订保留历史。对应 FR17。
11. **处理问题与回归**：失败生成草稿，用户确认；修复版本与回归执行绑定；开发自述不替代回归。对应 FR14。
12. **变更与回归提示**：任务/源码/依赖变化提示受影响用例；人工可调整并保留理由。对应 FR18。
13. **中断与恢复**：暂停、取消、断连、重启后先核实原运行，不盲目重放；未知副作用按执行异常/阻塞记录。对应 FR20。

## 4 业务规则

- **业务结论四值**：`passed`／`failed`／`incomplete`／`not_applicable`。存在当前有效决定性失败时判 `failed` 并列出未完成范围；只有未确定、阻塞、取消或未知而无有效失败时判 `incomplete`；无适用检查时判不适用。
- **完整通过门禁**：完整验证、验收项覆盖完整、全部适用必测有效通过、无未知或过期依据、必要真实链路有证据、源码与执行对应、无未关闭 P0/P1。
- **档位**：探索自测与完整验证分开；探索不升级为完整通过，不能原地改档；完整验证新建运行。
- **覆盖**：按验收项 → 用例 → 执行/证据统计；保留 L1/L2/L3 分层计数、执行/复用/验证/通过/失败/未验证计数；不使用 A—D 证据等级。
- **零分母**：不适用或暂无有效验证时显示不适用或尚无可统计结果，不显示 100%。
- **分层**：任一适用必测层级失败、阻塞或未验证时，不能显示全范围通过；GitHub 绿色状态不替代 L1。
- **Mock 真实性**：真实／Mock／混合／未知，绑定版本与环境；静态检查只产生疑点；声明外 Mock 或关键真实性未知不能得到“真实链路通过”。
- **断言依据**：缺失不得进入完整验证必测；已填未确认可执行但不计已验证；已确认仍需实际证据。
- **确认不替代执行**：计划确认、执行确认、复核都不产生执行或核验。
- **复用**：源码、环境动态状态、入口参数、范围、规则与适配器一致且证据可读才可复用；新尝试立即撤销整用例复用资格。
- **依赖失效**：上游新尝试使下游旧依据过期，旧事实保留，不自动复活。
- **模板**：作为规则库预设检查清单；AI 逐项处置，不静默删除；不是第二套发布门禁。
- **问题关闭**：必须有新的实际执行证据；修复说明与 AI 判断不能替代回归。
- **永久保留**：业务记录、证据、报告、问题、复核永久保存；不设保留期、不自动清理、不提供删除入口。
- **GitHub**：只读关联，检查通过不改变业务结论；部署版本与提交不一致时提示不匹配或未确认。
- **链路**：未采集或无法匹配的节点显示缺口，不补造；首个异常节点不一定是根因，定位必须说明依据与未知范围。
- **Python**：产品运行支持 Python 3.11 及以上；当前验证矩阵为 3.11/3.13，3.14 未验证。

## 5 异常处理

总原则：如实呈现，先核实再继续；未知、阻塞、取消、失败都不能改写成通过。

| 异常 | 行为 | 禁止 |
| --- | --- | --- |
| 未完成 | 保留每步事实与原因；显示 incomplete，已有失败时同列未完成范围 | 把未执行记为不适用或用旧通过补齐 |
| 证据缺失/损坏 | 计缺口，保留引用，不改旧正文 | 补造证据或掩盖缺失 |
| 来源未核实 | 预期不符拒绝启动；执行后发现则标来源未核实 | 以物化成功/环境可启动冒充源码对应 |
| 依赖过期 | 标旧依据过期，列需重跑 | 自动复活旧通过 |
| 未知副作用 | 按执行异常/阻塞记录并保留未知原因，不自动重放 | 伪造已取消/已回滚 |
| 凭据/敏感材料 | 落盘前过滤；无法安全处理则排除并登记缺口 | 先保存再只在导出时过滤 |
| 模型不可用 | AI 步骤失败/未完成；原始证据、人工处理与导出继续 | 暗换供应方或把 AI 文字当执行结果 |
| GitHub 不可用 | 版本关联显示未确认或缺口，不伪造检查结果 | 用缓存冒充最新检查 |
| 链路缺口 | 未采集/无法匹配节点明确标出 | 拼接为同一次调用 |
| 环境/数据阻塞 | 阻塞步骤并说明原因；污染数据不作依据 | 跳过阻塞后汇总为通过 |
| 执行中变更 | 新建修订，暂停受影响运行并标依据过期 | 改写冻结计划或已完成记录 |
| 空间不足 | 停止接纳新增字节，保留已有材料 | 驱逐历史或删除业务记录 |

失败与未完成可以并存：存在有效失败时结论为 `failed`，同时列出未完成范围；阻塞本身不算失败，也不能让前步有效失败消失。
