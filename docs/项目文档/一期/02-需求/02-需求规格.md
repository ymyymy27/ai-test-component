# 需求规格（一期）

> 状态：2026-11-17 轻量插件重构基线。依据[轻量 Trae 插件修改计划](../../../修改日志/ymy/2026-11-16-轻量Trae插件重构计划.md)；旧系统级 21 FR / 35 AC 已废止。
> 业务语义见[业务方案](01-业务方案.md)；行为、状态与判定口径见[功能清单](03-功能清单.md)；决策与旧编号废止说明见[需求基线与决策](00-需求基线与决策.md)。

## 1 产品目标

在 Windows 11 的 Trae 中提供本地 AI 测试插件：用户给一个项目目录和一句目标，AI 完成建档、验收项提取、计划生成、测试执行、失败分析与报告；所有数据保存在本机文件工作空间。

目标：

1. 正常路径上人的核心动作只有三项：确认目标（或选候选）、选范围、执行前确认；
2. 验收项、用例、执行、证据、问题、回归、报告可相互追溯；
3. AI 的判定与事实分开：分析、摘要、Mock 判定可见依据，但不改变业务结论；
4. 模型、GitHub、链路不可用时，本地测试、证据与导出仍可用。

## 2 范围与边界

### 2.1 支持环境

| 项 | 范围 |
| --- | --- |
| 宿主 | Windows 11 x64 上的 Trae 稳定版 |
| Python | 3.11+；首批验证 3.11 / 3.13，3.14 未验证 |
| 数据 | 用户级工作空间：默认 `%APPDATA%/aitest/workspaces/default`，可用 `aitest.workspacePath` 改 |
| 模型 | DeepSeek 兼容 HTTP API；AI 功能必需，本地执行/证据/报告不依赖 |
| GitHub | 复用 `gh` CLI 登录态，只读一个仓库 |
| 链路 | 读配置的日志文件与只读查询命令输出 |
| 前端 | Playwright 脚本 |
| 后端 | pytest / JUnit / npm test / HTTP / SQL 查询命令 |

### 2.2 一期不做

- 不做常驻核心、命名管道、后台守护、数据库、提交根、索引、事件日志；
- 不做格式迁移/回滚/注册表、计划许可账本、逐动作授权、A—D 证据等级；
- 账号、上传、共享审核、平台接收端；
- 自动点击捕获、跨服务/函数级追踪、AI 临场自主操作页面；
- 其他编辑器与操作系统组合。

### 2.3 明确保留

- 验收项范围选择与覆盖展示；
- L1/L2/L3 分层；
- 证据、问题、回归、报告、备份；
- 一次执行前确认 + 简单动作日志；
- 模板作为规则预设清单。

## 3 功能需求

### FR01 项目与模块

- **输入**：项目目录；可选的目标、模块、依赖、负责人、实现状态。
- **规则**：一个目录对应一个项目；monorepo 可登记多个子项目；根目录重叠时必须明确选择；模块关系可选，AI 可起草，确认后生效，不做代码级依赖分析。
- **输出**：项目编号、模块清单、目录绑定、缺口。
- **异常**：目录无效或不可写时拒绝；路径移动后对不上时提示重新绑定。

### FR02 任务与验收项

- **输入**：项目目录；一句目标，或从 AI 候选中选择；或从项目测试地图选择范围。
- **规则**：AI 按近期提交、未关闭问题、模块依赖、README/需求文档、历史任务给 3—5 条候选，附依据、预计测试范围和不确定项；无信号时给通用目标；始终允许自定义输入；目标或范围确定后自动生成任务，记录任务来源（目标/范围）；验收项必须可观察、有独立编号。
- **输出**：任务修订、验收项清单、候选目标、任务来源。
- **异常**：写不出可观察结果的验收项标“待补充”，不进入范围；自动建任务失败时不留半条任务。

### FR03 交付说明

- **输入**：任务、提交 diff、README、启动与测试脚本、依赖清单。
- **规则**：AI 起草；内容含完成/未完成、变更模块、接口变化、运行方式、测试数据、依赖、Mock 情况、自测证据；关联被测提交。
- **输出**：交付说明修订、源码版本关联。
- **异常**：缺运行方式或版本时标“交付信息不完整”，不阻止保存；开发自述完成不等于测试通过。

### FR04 规则与模板预设

- **输入**：人读步骤、AI 检查规则、证据要求、模板预设。
- **规则**：规则有版本、可绑定项目、支持 Markdown 导入导出；新测试用新版本，历史保留；模板是预设检查清单，不是第二套发布门禁；不改写验收项。
- **输出**：规则版本、项目绑定、模板处置结果。

### FR05 计划与用例

- **输入**：所选验收项、项目测试地图、规则、交付说明、项目上下文。
- **规则**：AI 先形成项目测试地图（业务功能、模块、入口与测试命令、可测内容、依据、未知项），业务功能为第一层、模块为下钻；范围提供推荐、自己勾选、完整测试三种预选，完整测试只表示当前理解范围内全部；AI 按每个选中验收项生成分层用例并直接发布为“AI 初版”；每个选中验收项至少一条用例；用例含层级、前置条件、步骤、预期、验证方式、Mock 许可、重要性、`depends_on`；预期必须引用验收项原文，引不上标“预期未证实”；已发布计划的修改生成新修订。
- **输出**：项目测试地图、计划修订、用例、范围。
- **异常**：AI 不可用时允许人工编写或导入；地图为空时允许手动添加功能或改用目标输入；缺预期或前置条件不得发布。

### FR06 L1 源码可运行性

- **输入**：源码、构建命令、入口。
- **规则**：项目级检查；只做语法、构建、入口导入/加载和最小测试，不启动长期运行的服务；“开始测试”内提供快速检查方式，不要求先建任务或选择验收项；快速检查不进入验收项覆盖，结果单独展示；L1 结果单独统计，不计入验收项覆盖；失败时阻塞 `depends_on=build` 的用例，并令运行结论为 `failed`；L1 取消/未完成令结论为 `incomplete`。
- **输出**：L1 结果、原始输出、错误位置、证据。

### FR07 L2 函数与模块

- **输入**：测试命令或约定入口、输入、断言、环境。
- **规则**：记录命令、输入、断言、实际输出、退出状态、日志、Mock 范围；runner 内部并行需结构化输出。
- **输出**：L2 模块结果、证据、Mock 真实性。
- **异常**：缺环境/依赖/数据时标 `blocked`，不伪造通过；脚本自身写错不算产品失败。

### FR08 L2 接口与集成

- **输入**：接口、环境、凭据引用、请求数据、响应断言、存储核验方式。
- **规则**：按业务顺序串联请求；核对状态、字段、业务规则、模块交互与数据库结果；响应成功不等于业务正确。
- **输出**：请求/响应、业务断言、数据核验、证据。

### FR09 L3 用户场景

- **输入**：业务目标、验收项、环境、测试数据。
- **规则**：两种载体——前端 UI（AI 生成 Playwright 脚本）与接口/命令（AI 生成请求或命令序列并核对最终持久化）；能自动化的由 AI 生成脚本执行；不可自动化时标 `manual_pending` 转人工现场记录；不做 AI 临场自主操作，不做 stepwise 驱动。
- **输出**：L3 结果、脚本、截图/请求、最终数据、未覆盖项。
- **异常**：任一步失败或关键依赖未知，流程不得判通过。

### FR10 Mock 与证据

- **输入**：项目代码、测试配置、本次运行的请求/响应/日志/DB 结果。
- **规则**：AI 按需读业务代码判定每个依赖为真实/Mock/混合/未知，必须附文件行号或证据；读取预算默认 40 文件/3 层；给不出依据只能 `unknown`；结果不可手工修改；`unknown` 或含未识别 Mock 的用例不能获得“真实链路通过”。
- **输出**：真实性清单、依据、缺口。

### FR11 问题与回归

- **输入**：失败用例、证据、影响范围。
- **规则**：AI 自动生成问题；按失败签名（用例 + 错误类型 + 关键堆栈/断言）去重，同签名追加发生记录；状态四态：待确认 → 处理中 → 待复测 → 已关闭，可重开；处置值：修复/非缺陷/重复/延期；关闭必须有新运行证据。
- **输出**：问题记录、发生记录、修复版本、回归结果。

### FR12 报告与导出

- **输入**：运行结果、范围、变更、问题、分析、证据。
- **规则**：报告开头由 core 生成独立“结论”（四值 + 范围 + 未覆盖数 + 失败数）；主表按验收项取最差结果，用例明细附表；展示 `S/M`、涉及模块与未映射文件、Mock 真实性、未验证项、证据索引；AI 摘要只写事实，命中结论词不采用；验收意见为自由文本；导出 Markdown，凭据不出现。
- **输出**：报告修订、Markdown 导出、验收意见。

### FR13 Trae 接入与环境

- **输入**：Trae 扩展、工作空间、运行环境。
- **规则**：扩展只调用 CLI；首次准备 Python 运行时（复用或下载便携版）；`doctor` 采集环境事实，AI 解释并按风险修复（低风险自动、中风险随执行确认、高风险只给命令）；面板提供“开始测试”入口，内含按目标、按范围、快速检查三个同级方式；快速检查不要求任务；面板轮询运行状态，不重算结论。
- **输出**：项目绑定、测试入口、运行视图、环境状态、修复记录。
- **异常**：宿主不兼容、运行环境缺失、连接失败分别报告缺项。

### FR14 GitHub 变更与检查

- **输入**：仓库、分支、提交、PR。
- **规则**：复用 `gh` CLI，经 `gh api` 只读；固定被测提交；检查通过不改变业务结论；部署版本取不到标未确认；失败不用缓存冒充最新。
- **输出**：变更关联、检查结果引用、账号与主机记录。

### FR15 链路采集

- **输入**：请求标识、日志文件、只读 DB 查询结果。
- **规则**：日志支持 JSON lines 与正则两种；数据库只执行配置的只读命令；缺请求 ID 或日志时写缺口，不补造；不接 APM、不内置驱动、不插桩。
- **输出**：节点、证据引用、缺口清单。

### FR16 链路断言与定位

- **输入**：链路节点、关键节点断言。
- **规则**：断言请求是否到达、返回字段、记录是否写入并可查；展示首个观测异常节点、上游输入与下游影响；首错不一定是根因，定位须说明依据与未知范围。
- **输出**：节点断言、定位结论、未知范围。

### FR17 工作空间备份与恢复

- **输入**：工作空间、业务记录、报告、可选证据。
- **规则**：zip 备份默认含业务记录与非敏感配置，不含证据；可选完整包并显示预计大小；恢复到新目录，核对引用，缺证据标“证据未包含”；不自动迁移旧格式。
- **输出**：备份清单、恢复结果、缺口。

### FR18 AI 失败分析

- **输入**：失败/阻塞/执行异常的用例与证据。
- **规则**：运行结束自动生成（worker 退出前同步完成后处理）；输出四段——事实、证据引用、候选原因（含把握程度）、未验证 + 下一步；缺“未验证”整条不合格、不展示；只展示，不审批、不改结论、不自动建问题；模型不可用标“分析未生成”。
- **输出**：分析记录、依据、未生成原因。

## 4 验收场景

每条都需要真实输入、步骤、版本与原始证据；定义接口或截图不能代替实际执行。

| 编号 | 场景 | 预期 | 关联 |
| --- | --- | --- | --- |
| P1-AC01 | 在一个仓库根与其子目录分别登记项目 | 提示根目录重叠，要求明确选择，不重复计数 | FR01 |
| P1-AC02 | 新项目无历史数据，打开目标选择 | 给出通用目标候选，同时可直接自定义输入 | FR02 |
| P1-AC03 | 从任务描述提取验收项，其中一条不可观察 | 可观察项进入范围，不可观察项标“待补充”并排除 | FR02 |
| P1-AC04 | 提交缺少运行方式的交付说明 | 标“交付信息不完整”，不阻止保存，后续 L1 阻塞并说明 | FR03 |
| P1-AC05 | 同一项目绑定两个规则版本并分别使用 | 历史运行保留原规则版本，新运行使用新版本 | FR04 |
| P1-AC06 | 自选范围只勾部分验收项 | 显示 `S/M` 与未覆盖清单，结论只描述所选范围 | FR05 |
| P1-AC07 | AI 生成计划并发布 | 每个选中验收项至少一条用例，预期带原文引用；直接可执行 | FR05 |
| P1-AC08 | 计划发布后未确认就执行 | 拒绝启动；确认后记录确认人与时间 | FR13 |
| P1-AC09 | L1 构建失败 | 只阻塞 `depends_on=build` 的用例，其他用例继续 | FR06 |
| P1-AC10 | L2 模块测试断言失败 | 记录命令、输出、日志与证据，结果为失败 | FR07 |
| P1-AC11 | 接口返回 200 但数据库无记录 | 业务断言失败，不显示真实业务通过 | FR08 |
| P1-AC12 | 前端 L3 由 AI 生成 Playwright 脚本执行 | 脚本落盘可重放，结果与截图入证据 | FR09 |
| P1-AC13 | 后端 L3 用接口序列完成业务闭环 | 核对最终持久化，不因响应成功而判通过 | FR09 |
| P1-AC14 | 支付依赖使用本地桩，AI 读代码与请求证据判定 | 标 Mock 并给出依据；无依据的依赖标未知 | FR10 |
| P1-AC15 | 失败运行生成 AI 分析 | 四段齐全；缺“未验证”时整条标不合格、不展示 | FR18 |
| P1-AC16 | 同一失败原因连续出现在多次运行 | 同一失败签名只建一个问题，追加发生记录 | FR11 |
| P1-AC17 | 按验收项重跑 | 新建运行，范围只含该验收项，旧运行完整保留 | FR11 |
| P1-AC18 | 报告含通过、失败、阻塞、未执行 | 结论与计数准确；未执行不算通过；覆盖不全不称全部通过 | FR12 |
| P1-AC19 | 填写与不填写验收意见 | 填写时记录署名与时间；不填时导出显示未填写，不影响结论 | FR12 |
| P1-AC20 | `gh` 未安装或未登录 | 明确报告缺项，不使用缓存冒充最新；本地测试仍可用 | FR14 |
| P1-AC21 | 缺少请求 ID 或日志未采集 | 链路标缺口，不拼接为同一次调用 | FR15 |
| P1-AC22 | 同一项目发起第二个运行 | 拒绝并返回现有运行 ID；不同项目可并行 | FR13 |
| P1-AC23 | worker 被系统杀掉后重开 | 心跳超时且 PID 不在，标 `interrupted`，保留已完成证据 | FR13 |
| P1-AC24 | 备份后恢复到新目录 | 记录与引用可核对；未包含的证据标“证据未包含” | FR17 |
| P1-AC25 | 环境缺 Python 或 `gh` | 分别报告缺项；低风险项 AI 可修，高风险只给命令 | FR13 |
| P1-AC26 | 模型 API 不可用 | AI 步骤标“未生成”，测试、证据、报告照常可用 | FR18 |
| P1-AC27 | 导入一次包含请求、日志与数据库结果的完整链路 | 节点按顺序排列并标出缺口，断言显示首个异常与上下游，定位到已观测代码位置或未知范围 | FR15、FR16 |
| P1-AC28 | 新建项目后直接做快速检查 | 不建任务也能发起；只展示项目级检查结果，不进入验收项覆盖 | FR06 |
| P1-AC29 | 按目标测试 | AI 给出候选目标并显示预计范围，可自定义；选定后自动生成任务和计划 | FR02、FR05 |
| P1-AC30 | 按范围测试 | AI 给出业务功能清单，可按业务功能勾选、模块下钻，支持推荐/自己勾/完整测试 | FR05 |
| P1-AC31 | 项目地图识别不足或分析失败 | 显示未知项或回退到模块/手动选择，不把未识别内容算作通过 | FR05、FR18 |
| P1-AC32 | 导出报告 | 任意报告版本可导出 Markdown，返回路径与摘要；证据只引用不打包，凭据不出现 | FR12 |

## 5 后置与实测结果

- 账号、上传、共享审核、平台接收端：后置；
- 变更影响分析与自动回归推荐：二期；
- 智能体入口的 L3：后置；
- 其他编辑器与操作系统组合：二期；
- 真实 Trae 面板主路径、链路与备份恢复已有真实证据（明细见 `tests/acceptance/p1/status.json`）；
- 试点项目、GitHub 成功路径与完整宿主闭环：未验证，不登记通过。
