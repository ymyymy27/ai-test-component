# 开发规则

> **已废止（2026-11-16）**：本文属于系统级方案，不作为轻量插件重构的实现依据。现行基线见[轻量 Trae 插件修改计划](../../../修改日志/ymy/2026-11-16-轻量Trae插件重构计划.md)。新文档就位后移入 `docs/归档/`。


本册只写**可执行**的工程规则：怎么分层、怎么提交数据、怎么处理凭据、跑哪些命令、怎么评审、文档何时同步。状态数字、验收结论与问题清单不在此复制，以代码与 `docs/现状.md` 为准。命令若有疑问，以 `pyproject.toml` 与 `.github/workflows/` 为准。

## 1 依赖方向与模块边界

1. 依赖方向固定为 **入口 → 适配 → 应用用例 → 领域规则**；外部能力经 `src/aitest/application/ports.py` 的 `Protocol` 反向注入。
2. `application/` 不得 import `aitest.infrastructure`、`aitest.interfaces`；`infrastructure/` 不得 import `aitest.interfaces`；`domain/` 不 import 上层且不做 I/O。
3. `src/aitest/bootstrap.py` 是唯一装配点。B/C/D 只提交用例注册表（`interfaces/local/b_registration.py`、`d_registration.py` → `application/usecase_registry.py`），不得自行构造存储、端口实现或第二个核心。
4. 新增动作先进 `contracts/commands.py` 的动作表，再实现 handler、用例与端口；已发布字段语义保持兼容，破坏性变更走新版本串。
5. 入口层只做三件事：发 `Command`、读 `Response`/只读 DTO、做呈现。**不得直接写业务文件，不得重算判定、覆盖或证据等级。**
6. 面板只有一份源码（`src/aitest/resources/panel/src`），Trae 扩展只承载 Webview 与命令；任何宿主都不得复制核心逻辑。
7. 禁止为单条记录新建一套服务层，也禁止预建空模块占位。

## 2 数据与事务

1. 业务变更经应用用例确定**短事务边界**；外部执行、模型调用与网络调用一律在事务外。
2. 一个工作空间一个排他写核心：`workspace.lock` + `writer_epoch` 准入；第二个写者必须得到 `WORKSPACE_IN_USE`，不得降级为"共享写"。
3. 记录不可变。提交顺序是：准备记录节点、索引根、事件根、清单与幂等结果，最后替换唯一发布指针；**不得边写边发布**。
4. 幂等键是 `(project_id, action, intent_id)`。跨入口重传同一持久业务意图不得重复执行；明确重跑必须创建新意图，不得复用旧 `intent_id`。
5. 写动作必须携带 `project_id`、`intent_id`、`expected_revision`；`request_id` 不得复用为 `intent_id`（`Command` 已校验）。
6. 列表与队列只走有限 `QuerySpec` 与索引键，列表读摘要、详情按引用读取；不得为界面便利加全表扫描或内存排序。
7. 备份与迁移先做可校验备份再改格式；恢复先核实活动执行与可抢救输出；未知副作用不自动重放。目录与保留规则见[存储与恢复](05-存储与恢复.md)。

## 3 安全与凭据

1. 代码、项目文档、日志与模型输出都按不可信输入处理；已知凭据在**落盘前**过滤，过滤前字节不得进入 spool、对象、诊断或备份。
2. 凭据正文不进配置、日志、面板、导出或上传；需要引用时只存引用与摘要，无法安全处理的材料登记缺口，不伪造完整证据。
3. 出站材料（模型、报告导出、交付）先做白名单投影与摘要，再发送；安全预览不等于发送授权。
4. 人工确认、动作授权、断言依据确认、实际执行与独立核验是不同事实，不得互相回填。核心自有确认窗口不得自动确认。
5. 身份不明或进程映像不匹配的核心一律拒绝连接；不得为"能跑起来"放宽身份核对。
6. 临时目录、脚本与下载材料不放进被测源码或 `src/`；运行数据只写操作系统用户数据工作空间。

## 4 测试与门禁

安装与基础检查（与 CI 一致；CI 用 Python 3.13）：

```bash
uv sync --extra dev --locked
uv run python scripts/check_versions.py
uv run ruff check .
uv run mypy
uv run python scripts/generate_schemas.py
git status --porcelain --untracked-files=all -- src/aitest/contracts/schemas
uv run python scripts/check_docs_facts.py
uv run pytest --collect-only -q
```

有界检查（`ci.yml` 的 `basic-checks` 任务，改动后至少跑对应用例）：

```bash
uv run pytest tests/contracts tests/architecture tests/recovery tests/acceptance tests/integration \
  tests/unit/test_bounded_query_directory.py tests/unit/test_review_decision.py \
  tests/unit/test_query_material_identity.py tests/unit/test_finite_query_routes.py \
  tests/unit/test_query_spec_bridge.py tests/unit/test_reporting_application.py \
  tests/unit/test_saved_reports.py tests/unit/test_panel_view_dto.py \
  tests/unit/test_sharded_record_authority.py tests/unit/test_source_identity_runtime_observation.py
```

全量回归（`nightly.yml`，本机同一命令，耗时较长，期间不要并发跑其他重测试）：

```bash
uv run pytest -p no:cacheprovider --import-mode=importlib -n 8 --dist loadfile -ra tests
```

面板与扩展（面板构建含 `tsc --noEmit`，测试为 Playwright；扩展打包只在 tag 发布时由 CI 执行）：

```bash
npm --prefix src/aitest/resources/panel ci
npm --prefix src/aitest/resources/panel run build
npm --prefix src/aitest/resources/panel test
npm --prefix integrations/trae ci
npm --prefix integrations/trae run package
```

发布制品（tag 场景）：

```bash
uv build
uv run python scripts/verify_artifacts.py
uv run python scripts/smoke_wheel.py
```

门禁规则：

1. 提交前必须跑**受改动路径的既有用例**；只跑新增用例不算通过。
2. 有界检查通过不等于全量通过，也不等于真实 Trae、其他宿主、掉电恢复或平台对拍通过。
3. Schema 由脚本生成；`git status` 有差异即视为失败，不得手改 `contracts/schemas/`。
4. 断言不得只检查"调用成功"或界面提示，需校验落盘记录、修订号、幂等结果与证据引用。
5. 新风险边界要有夹具或故障注入：规则、合同形状、架构依赖、提交/恢复、真实宿主与系统组合各归其位。
6. 全量期间不并发跑其他重测试命令，避免负载导致的假失败。

## 5 提交、分支与评审

1. 长期分支只有 `main` 与 `develop`；功能/修复从 `develop` 开短分支，经 PR 合入后删除。不按成员姓名建分支或目录。
2. 提交前 `git status --short` 检查工作区，保留他人未提交的成果；不夹带无关改动。
3. 一个提交只解决一件事；提交信息写清动作与期次/FR，不写"杂项修复"。
4. 评审关注：依赖方向、幂等与重传、凭据落盘前过滤、只读投影是否越权、Schema 是否生成、测试是否覆盖改动路径。
5. 发布 tag 触发面板/扩展构建与制品校验；日常 PR 不产出制品，也不更新归档结论。

## 6 文档同步义务

1. 字段、枚举、状态迁移、FR/AC 变更必须同步对应主责分册（`docs/项目文档/一期/02-需求/`—`04-架构/`），不能只在代码中选一种解释。
2. 跨册同一含义只允许一处定义，其余引用；发现冲突先记录两处原文与影响，再按阅读索引的主责位置修正。
3. 架构、模块、端口、命令变化同步本目录 `01-架构总览.md`；规则变化同步本册。
4. 新增修改日志写 `docs/修改日志/<作者>/`，新验证批次写 `docs/validation/`；历史材料留在 `docs/归档/`，不追加新结论、不追溯改判。
5. AC 登记只写 `tests/acceptance/{p1,p2,p3}/status.json`，`scenario`/`expected`/`related_frs` 逐字取自需求文档，由 `tests/unit/test_acceptance_status.py` 对账。
6. 交付说明分开列"已实现 / 已通过静态或单元检查 / 已通过真实环境验收 / 未验证"，不得用文档一致冒充验收。

## 7 禁止事项清单

- 禁止 `application`/`domain` 直接 import 基础设施或入口层。
- 禁止第二个写核心、第二个装配点，或在适配器里各自实现去重。
- 禁止手改 `src/aitest/contracts/schemas/*.json`、`resources/panel/dist/index.js`、`integrations/trae/dist/*`。
- 禁止把业务运行数据写进安装包、被测源码或 `src/`。
- 禁止在日志、面板、导出、上传或错误消息里出现凭据正文。
- 禁止用复用、跨运行继承或部分执行拼出整用例的有效执行/验证。
- 禁止把 `quick`/`on_demand` 升级为完整通过，或在空分母上显示 100%。
- 禁止把模拟器、夹具、组件级真实进程写成真实宿主或平台验收通过。
- 禁止在 `docs/归档/` 追加新结论，或回填未入库制品。
- 禁止在 `status.json` 之外登记 AC 状态，或改写需求文档原文去迁就登记。
