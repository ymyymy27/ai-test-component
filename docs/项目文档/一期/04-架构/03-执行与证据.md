# 执行与证据（一期）

> 状态：2026-11-16 设计基线（D4）。字段见[CLI 与数据契约](../03-设计/03-CLI与数据契约.md)；运行目录见[存储与备份](04-存储与备份.md)。

## 1 运行状态

```text
run.start
  → running
      ├─ 正常结束 → completed
      ├─ 取消确认 → cancelled
      ├─ 心跳超时 + PID 不在 → interrupted
      └─ 执行异常/取消未确认 → execution_error
```

- 状态由 CLI/worker 写，面板只读；
- 业务结论在运行结束后由 core 派生，与状态分开。

## 2 启动

```text
run.start(payload)
 1. 校验计划已发布、范围非空
 2. 校验确认记录或 --confirm
 3. 校验同一项目无活动运行
 4. 创建 runs/<run_id>/
 5. 写 run.json：running、pid、started_at、heartbeat_at、frozen scope
 6. detached 启动 worker
 7. 返回 run_id
```

任一步失败即返回对应错误码，不留下可误认为有效的运行。

## 3 worker 循环

```text
for case in plan.cases:
  if cancel.requested: 剩余用例标 not_run，退出为 cancelled
  检查 depends_on：build/service 未满足 → blocked
  执行用例：
    L1 → 构建/语法/入口加载
    L2 → pytest/命令/HTTP
    L3 → 生成并执行脚本，或标 manual_pending
  写结果、证据引用、心跳
结束：
  派生结论与计数
  写 run.json completed
  异步生成 Mock 判定与 AI 分析并补写
```

- 单个用例失败不终止整个运行；
- 依赖失败的用例按 `depends_on` 阻塞；
- 每个用例结果独立写入，worker 崩溃时已完成部分可读。

## 4 服务生命周期

```text
读取 services 配置
 → 探测健康地址
   ├─ 已通：不接管
   └─ 未通：执行 start，轮询健康检查
         ├─ 通：继续
         └─ 超时：标 blocked，保留启动日志
运行结束：
  keep_on_failure=false → 执行 stop
  keep_on_failure=true 且存在失败 → 保留
```

- 只停止自己启动的服务；
- 端口冲突/启动失败不强行杀进程；
- 停止命令失败只记录，不影响结论。

## 5 测试文件

- 生成到 `runs/<run_id>/generated/`；
- 文件头标 `# generated by aitest`；
- 生成后扫描危险操作（`rm -rf`、`DROP TABLE`、`git push`、`format`、写系统目录），命中返回 `SCRIPT_REJECTED`；
- 缺依赖：执行前确认页列出；确认后安装，否则 `blocked`；
- 脚本自身语法/导入错误标 `error`，不算产品失败。

## 6 L3

| 载体 | 执行 | 证据 |
| --- | --- | --- |
| 前端 UI | Playwright 脚本 | 截图、视频（默认关）、脚本、trace |
| 接口/命令 | 请求/命令序列 + 最终查询 | 请求/响应、查询结果、脚本 |

- 不可自动化 → `manual_pending`，worker 继续后续用例；
- 人工记录逐条落盘，未记录计入未完成；
- 不做 AI 临场自主操作。

## 7 取消与中断

取消：

```text
run.cancel → 写 cancel.requested
worker 在用例边界检查
  ├─ 已停：status=cancelled
  └─ 未停：status=execution_error + 原因
```

中断：

- worker 每 2—5 秒刷新 `heartbeat_at`；
- `run.status`/`run.list`/`doctor` 发现 `running` 且心跳超过阈值、PID 不在 → 标 `interrupted`；
- 保留已完成用例、证据与未完成清单；
- 不自动重跑，不补造结果。

## 8 并发

- 同一项目同时只允许一个运行；第二个 `run.start` 返回 `RUN_ACTIVE` 与现有 `run_id`；
- 不同项目可并行；
- 运行内跨用例串行；
- runner 内部并行可选，需输出 JUnit/JSON 等结构化结果；
- 并行不改变结论与计数口径。

## 9 证据

| 类型 | 限制 |
| --- | --- |
| 单文件 | 20MB 截断，标注原始大小 |
| 单次运行媒体 | 软上限 500MB |
| 超限顺序 | 压缩截图 → 跳过通过用例截图 → 失败证据不动 |
| 视频 | 默认关闭 |
| 截图 | 失败用例全留；通过用例留最后一张 |
| 历史 | 不自动删除 |

证据只存相对路径、摘要、大小、media type；正文放证据目录。

## 10 AI 调用

| 调用 | 时机 | 失败处理 |
| --- | --- | --- |
| 目标候选 | 进入项目 | 返回空候选 + 自定义入口 |
| 验收项提取 | 建任务 | 人工填写 |
| 交付说明 | 提测 | 标未生成 |
| 计划生成 | 选范围后 | 人工编写/导入 |
| 测试脚本 | 执行前 | `blocked` |
| Mock 判定 | 运行结束 | 全部 `unknown` |
| 失败分析 | 运行结束且有失败 | 标未生成 |
| 问题起草 | 运行结束 | 不建问题，保留失败 |
| 报告摘要 | 生成报告 | 只输出事实 |

所有调用带超时、重试上限与输出校验；不合格输出不进入结果。

## 11 Mock 判定

- 输入：测试配置、测试代码、客户端初始化、地址来源、本次请求/响应/日志/DB；
- 预算：默认 40 文件、3 层；
- 输出：`real/mock/mixed/unknown` + 依据 + 读过的文件清单；
- 判不出即 `unknown`，不默认真实；
- `unknown` 或未识别 Mock 的用例不能获得“真实链路通过”。

## 12 结论派生

```text
S = 本次范围；M = 适用验收项
for item in S:
  取该验收项下所有用例最差结果
结论：
  有失败 → failed
  无失败但有阻塞/未知/未执行/manual_pending → incomplete
  全部通过 → passed
  S 无适用检查 → not_applicable
```

- 未选验收项不属于本次范围；
- 报告必须同时展示 `S/M` 与未覆盖清单；
- L1 单独统计，不计入验收项覆盖。
