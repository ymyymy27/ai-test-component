# 面板与工作台（技术合同）

本文只固定面板的技术边界：谁生产事实、谁只读、谁可以发起动作，以及快照与事件如何配对。界面布局、文案、图标、空态与刷新时机不在本文展开，见准备阶段的 `04-产品方案与界面设计.md`。业务判定口径见需求与功能合同，本文不重新定义。

旧架构分册写的是 `PanelDTO`／`PlanDTO`／`ExportPreviewDTO`／`RepairBriefDTO` 与 `shell`、`current_check` 等目录；这些名称与目录在当前源码中并不存在，实际结构见第 2、6 节。

## 1 三段职责

| 层 | 职责 | 明确禁止 |
| --- | --- | --- |
| 宿主（Trae 扩展） | 提供 Webview、把面板消息翻译成 CLI 调用、核对回执身份、回传确认提示 | 计算业务结论、代签确认、直接读写业务文件、补造身份字段 |
| 核心 | 保存与读取不可变记录、生成 DTO、派生判定与统计、持有挑战与确认记录 | 从界面读取状态、按页面需要补算业务结论 |
| 面板（`src/aitest/resources/panel`） | 展示已提交事实、收集用户输入、发起已登记动作 | 读文件、调适配器、重算等级/分母/覆盖、复制业务结论到本地存储 |

- 面板源码只有一份，构建产物 `dist/panel.js` 由 `integrations/trae` 加载；不手工编辑产物。
- 面板与扩展之间只有消息通道：`kind` 为 `dispatch`（只读）、`writeDispatch`（普通写入）、`controlledDispatch`（受控动作）、`ensureCore`、`restartCore`、`wizard*`、`confirmationResult`、`runNotification`、`openDetail`、`openSource`、`openSettings`。
- 面板不持久化业务结论。`state` 中的计划、运行、报告、问题全部来自刚才的只读回执；页签、展开状态、筛选条件属于界面状态。

### 1.1 子域结构（与源码一致）

```text
src/aitest/resources/panel/src/
  index.ts        # 自定义元素、路由、状态与动作编排
  host.ts         # 宿主消息通道、请求/回执配对、确认提示
  context.ts      # AppContext：子视图可用的读取、写入、跳转能力
  types.ts        # 消息与界面状态类型
  wizard.ts       # 向导受控动作白名单与步骤状态机
  ui.ts labels.ts icons.ts styles.ts   # 组件、文案、图标、样式
  test-tabs.ts
  views/          # home wizard plan rules workbench reports settings diagnostics delivery
```

路由取值为 `home`、`wizard`、`plan`、`rules`、`workbench`、`reports`、`settings`、`diagnostics`；主导航只保留“本次测试”“问题与报告”“设置”三项，其余按上下文进入。工作台与报告页可被扩展以 `aitest.openWorkbench`／`aitest.openReport` 单独打开，复用同一份面板代码。

### 1.2 构建与检查入口

面板用 `tsc --noEmit` 做类型检查，再由 esbuild 打包为单一 IIFE（面板包输出 `dist/index.js`，扩展构建时复制为 `dist/panel.js`）；`integrations/trae` 侧 `npm test` 运行 3 个 node 测试（`core-bridge`、`extension-context`、`onboarding`）。面板自身有 4 个 Playwright spec：`shell`、`views`、`wizard`、`workbench`，用同一套 DTO 夹具驱动。夹具与 spec 通过只证明界面与契约一致，不构成真实 Trae 验收；面板产物摘要须与核心、扩展版本一起进入兼容记录。

## 2 DTO 清单

| DTO | schema 版本 | 生产位置 | 用途 |
| --- | --- | --- | --- |
| `PanelViewDTO` | `aitest.panel-view/1.0` | `interfaces/dto.py::panel_view_dto` | 主屏：项目、`run_id`、`stage`（`pre_run`／`runtime`／`post_run`）、`control_state`、`tier`、`driver`、`conclusion_ceiling`、`business_outcome`、`decisive_failure_case_ids`、`gap_codes`、待人工与待核实步骤、`snapshot_commit_id`、`snapshot_cursor` |
| `RunViewDTO` | `aitest.run-view/1.0` | `run_view_dto` | 运行/步骤/当前尝试、`selected_summary` 与 `required_summary`、步骤级证据编号、分层计数、TraceNode 视图 |
| `DecisionDTO` | `aitest.decision/1.0` | `decision_dto` | 业务结论、证据等级、主要与全部缺口、决定性失败、`CoverageDTO`、`policy_version` |
| `CoverageSummaryDTO` | 内嵌 | `_coverage_summary_dto` | 单一口径的分母与 E/R/V/P/F/U 计数、`decisive_failures` |
| `ReportSummaryDTO` | 内嵌 | `report_summary_dto` | 报告内容修订、运行修订、范围名、结论、等级、主要缺口 |
| `IssueListPageDTO` | 内嵌 | `issue_list_page_dto` | 问题列表：`query_spec_version`、`scope`、`mask`、`items`、`next_cursor` |
| `DeliveryViewDTO` | `aitest.delivery-view/1.0` | `delivery_view` | 交付与提交事实的只读视图 |

补充事实：

- 计划不是独立 DTO，经 `read_view` 的 `view_type="plan"` 返回记录视图：`project_id`、`record_id`、`record_revision`、`record_kind`、`historical_snapshot`、`record{plan_id, revision, scope, cases, template_versions, run_tier, initial_driver, status, ...}`。
- 导出没有 `ExportPreviewDTO` 类：`export_report` 返回导出记录载荷，含 `excluded`、`missing`、`artifact_ref`、`artifact_digest`、`object_ref`、`size_bytes`、`media_type`。
- 修复说明没有 `RepairBriefDTO` 类：`copy_repair_brief` 返回 `brief`（已脱敏文本）、`issue_revision`、`run_id`、`attempt_id`、`facts_state`、`unknown_positions`、`excluded`、`redaction_policy_version`。
- `PanelViewDTO` **不提供 `primary_action`**：动作标识尚未冻结，核心只给“当前情形”事实，界面按设计分册映射到按钮，不自行发明动作名。

## 3 快照与事件

### 3.1 外层边界

`read_view` 的返回不是独立的 `SnapshotEnvelope` 类，而是同一次读取的合并结构：

```text
{ view_type, view, commit_id, event_cursor, generation, index_version }
```

- 核心在读取前后各取一次配对边界（`query(limit=1)` 的 `commit_id`／`event_cursor`／`generation`／`index_version`），不一致立即返回 `SNAPSHOT_REQUIRED`。
- 任一字段缺失或类型不符也返回 `SNAPSHOT_REQUIRED`，不返回猜测值。
- `PanelViewDTO`／`RunViewDTO`／`DecisionDTO` 里的 `snapshot_cursor` 是运行事实的提交游标（整数），与这里的外层 `event_cursor`（字符串）不是同一字段，不能相互替代或拼接。
- 记录视图（plan/report/case/issue/evidence/local_review/reuse_decision/rule_draft/rule_version）按 `record_id` + `revision` 精确读取，`historical_snapshot` 固定为 `true`；`run`／`panel` 按 `run_id` 读取；`delivery` 按 `delivery_id` 读取。
- 证据正文另有省略原因：`redaction_unsafe`、`object_unavailable`、`body_too_large`、`object_unreadable`、`object_corrupted`、`binary_content`；任何省略都如实显示，不伪造正文。

### 3.2 事件

- 面板当前是**有限拉取**，不是长连接订阅：`events` 带 `limit`（1—500）与可选 `cursor`，回执给 `events` 与 `next_cursor`。
- 去重按事件身份；`next_cursor` 只在回执给出新值时前移。`invalid_cursor` 清除游标并提示从头读取，`maintenance_required` 提示查看诊断，不伪装成空列表。
- 断开或宿主上下文变化时只显示最后确认状态与原因，不把运行改成失败或取消。
- 主屏刷新按顺序读 `panel` 再读 `run`，避免同一工作空间上的并发重读重复触发索引工作。

### 3.3 实时值与快照值

面板展示由当前已提交记录派生的实时值；报告展示随报告内容修订冻结的快照值。两者必须分别标明且口径一致；等级、主要缺口、断言可信度只能来自领域判定器。源码或证据变化导致两者不同时，面板标注“报告快照为旧版本”，不覆盖报告正文。

## 4 动作归属与写入通道

| 通道 | 允许动作 | 超时 | 关键校验 |
| --- | --- | --- | --- |
| 只读 `dispatch` | 扩展白名单：`doctor`、`query`、`read_view`、`events`、`storage_usage`、`discover_tests`、`suggest_regression`、`aggregate_project_runs`、`check_source`、`inspect_case_reuse`、`copy_repair_brief`、`plan_confirmation_state`、`export_rules_markdown` | 30 秒 | 请求项目必须等于宿主所选项目 |
| 普通写入 `writeDispatch` | 扩展 `PLAIN_WRITE_ACTIONS`：保存类、分析、准备、执行、报告与导出等无需人工手势的写入 | 180 秒 | 必须有 `projectId`、`intentId`、`expectedRevision`；`intentId != requestId` |
| 受控动作 `controlledDispatch` | 面板 `CONTROLLED_ACTIONS`（等于核心 `HUMAN_ACTIONS` 18 项） | 270 秒 | 额外核对 `contextId`；核心按 `CHALLENGE_ACTIONS` 决定是否走面板确认 |

- 面板的 `intentId` 由 `(action, target, expectedRevision, parameters)` 在页面内存中派生；同一输入在一次会话内复用同一意图，页面重载后会生成新意图。跨入口重传同一业务意图仍由核心按 `(project_id, action, intent_id)` 去重。
- 面板写入缺少项目、意图或宿主上下文时，在发给扩展之前就以 `PROJECT_CONTEXT_MISMATCH`／`INVALID_REQUEST` 拒绝，不派发。
- 宿主侧还有两道门：`contextId` 失效拒绝写入；操作期间宿主配置变化则丢弃该回执并提示“按原意图核实”。
- 页面禁用按钮不是幂等保障，也不是权限边界；所有门禁都在核心重算。

### 4.1 面板不能做的事

- 不提交角色、挑战、摘要或“用户已确认”事实；确认只来自真实点击，且由宿主回传。
- 不把只读查询当作目录绑定：项目来自宿主配置；`query` 需要显式 `project_id`，无法枚举项目。
- 不自行启动核心：每次读写前先经宿主 `ensureCore`，由 CLI 完成发现与身份核对。
- 不加载二期能力：一期启动与打包不依赖定位/图模块。

## 5 统计投影

- 运行侧同时给出 `selected_case_ids`（S）与 `required_case_ids`（M），并分别给 `selected_summary`、`required_summary`；缺字段显示未知，不以步骤数推算用例数。
- `CoverageSummaryDTO` 字段：`scope_kind`、`case_ids_revision`、`denominator`、`executed_count`、`reused_count`、`verified_count`、`passed_count`、`failed_count`、`unverified_count`、`decisive_failure_count`、`decisive_failures`、`source_commit`、`policy_version`。
- `unverified_count` 按 `scope - verified` 计算；空分母显示“不适用/无范围”，不显示 100%。
- 决定性与已验证失败分别展示：`decisive_failure_count`（已确认失败用例）与 `failed_count`（整用例已验证失败）可能重叠，不相加。
- 面板只消费核心给出的计数；重算、四舍五入或从单步完成推断整个用例完成都属于越界。
