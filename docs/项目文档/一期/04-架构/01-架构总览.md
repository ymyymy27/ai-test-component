# 架构总览

本册描述仓库**当前代码**的真实分层、模块、端口、目录与调用链，供开发阶段快速定位。字段、状态、时序与验收预期的主责合同在 `docs/项目文档/一期/02-需求/`—`04-架构/`；本册只做索引与实现事实对照，不另立口径。

判定与统计口径见[报告与缺陷](04-报告与缺陷.md)，落盘、提交、查询、恢复见[存储与恢复](05-存储与恢复.md)，宿主接入见[Trae 接入](06-Trae接入.md)，界面与 DTO 见[面板与工作台](07-面板与工作台.md)。本册不复制这些条款。

## 1 分层与依赖方向

```text
入口层      interfaces/tools (CLI、MCP relay) · interfaces/local (核心进程、LocalAPI、CoreClient)
            integrations/trae (扩展) · resources/panel (共享面板源码)
   │  只发 Command、只读 Response / 只读 DTO
适配层      interfaces.local.api.LocalAPI.dispatch（路由、生命周期、安全投影）
   │
应用层      application/*：用例编排、幂等、事务边界、证据装配
   │
领域层      domain/*：判定、覆盖、证据等级、复用资格、状态机等纯规则
   ▲
端口层      application/ports.py：外部能力 Protocol，由 infrastructure 实现
   │
基础设施    infrastructure/*：文件底座、适配器、凭据、能力探测、时钟
```

硬规则（由 `tests/architecture/test_boundaries.py` 强制）：

- `application` 不得 import `aitest.infrastructure`、`aitest.interfaces`。
- `infrastructure` 不得 import `aitest.interfaces`。
- `domain` 不 import 任何上层；`json_material.py` 是唯一允许的通用编解码辅助。
- `bootstrap.py` 是唯一装配点；B/C/D 只能提交用例注册表，不得自行构造存储或端口实现。
- 面板、MCP、CLI、报告与导出只读 DTO 或提交 Command；**不得直接写业务文件，也不得重算判定**。

进程模型：一个用户数据工作空间由**一个排他写核心进程**服务。入口通过命名管道连接已存在核心；不存在时由注入的启动器启动 `interfaces/local/core_worker.py`。管道承载 `aitest.local/2.0` 帧，`CoreClient` 只接受精确回执，不自动重传。

### 1.1 核心进程生命周期

1. 启动时经 `bootstrap.assemble_workspace_core` 完成统一装配：启动恢复 → 文件底座 → B 用例接线 → C/D 注册表叠加；恢复结论为 blocked 时拒绝服务（退出码 5），不带着未知状态对外提供写能力。
2. 在工作空间管道上只接受同会话同用户的对端；逐帧解析 `Command`，坏帧回协议错误，不吞消息、不断连。
3. 客户端断开不等于核心退出：默认 `--max-clients 0` 表示长期唯一核心，关闭旧管道后用同一实例名重建，等待重连。
4. 退出条件三选一：达到有限 `--max-clients`（测试用）、收到同管道停机控制帧、父进程消亡。父进程消亡只置退出请求并取消阻塞等待，主循环先核实活动执行与输出；仍有活动或未知执行时继续服务，核实收尾后才退出（退出码 6）。
5. 入口类型由核心依据对端**进程映像事实**判定；`interfaces/local/actor_context.py` 提供受信操作者上下文，交互宿主不能自证可信。

## 3 端口清单

以下全部来自 `src/aitest/application/ports.py`（共 58 个 `Protocol`，另有 `EnvironmentResolutionRequest`、`CollectedRedactionSummary` 两个数据类）。实现分布在 `infrastructure/` 与 `interfaces/local/`，注入点在 `bootstrap.py`。

| 分组 | 端口类 |
| --- | --- |
| 运行环境与执行 | `EnvironmentResolver`、`ExecutionActionResolver`、`ExecutionSourceProof`、`ExecutionAuthorizationProof`、`ExecutionPort` |
| 入口与运行支撑 | `LocalProtocolPort`、`CoreMessagePort`、`Clock`、`ControlledActorContext` |
| 审批与确认证明 | `ApprovalActionResolver`、`ApprovalIdentitySource`、`ApprovalRecords`、`BasisConfirmationProof`、`ModelPolicyConfirmationProof`、`ControlledWriteProof` |
| 事务与记录 | `TransactionPort`、`StoragePort`、`BackupPort`、`IndexPort`、`WorkspaceUnitOfWork`、`StageableWorkspaceUnitOfWork`、`RecordIntentOpening`、`ExactRecordStaging`、`RecordValueProtector`、`RecordRepository`、`RevisionRecordReader` |
| 查询与投影 | `QueryPort`、`RuntimeExecutionReader`、`RuntimeRevisionBasisReader`、`RuntimeRevisionOriginProof`、`ProjectionPort` |
| 证据与采集 | `EvidenceReferenceValidator`、`EvidenceObjectStore`、`ExecutionEvidenceCollector`、`ExecutionRedactionCollector`、`ModelResponseStore`、`SpoolStore`、`SpoolStreamWriter`、`SpoolRedactionInspection`、`SpoolRedactionSummaryReader`、`CheckpointPort`、`BackgroundWorkDirectory` |
| 源码 | `SourceSnapshotPort`、`SourceControlPort` |
| 验证与业务查询 | `VerificationPort`、`BusinessVerificationPort`、`ReadOnlyBusinessQueryPort`、`DeadlineBusinessQueryPort`、`BusinessVerificationCapturePort`、`BusinessVerificationResolver`、`HttpWorkflowPort`、`ModelProvider` |
| 报告、凭据与维护 | `ReportArtifactPort`、`SecretPort`、`MaintenancePort`、`BackupStorePort`、`MigrationRunnerPort`、`BackupAuditPort` |

约定：端口方法只接受已冻结的领域对象或合同 DTO，返回事实而非判定；跨入口重传由 `TransactionPort`/工作单元的幂等结果吸收，不在适配器里各自去重。

### 3.1 实现落点

`Protocol` 在 Python 中是结构化类型，实现类**不写显式继承**，因此按目录与职责归属，而不是按 `class X(Port)` 声明检索：

| 端口分组 | 主要实现位置 |
| --- | --- |
| 事务、记录、索引、对象 | `infrastructure/file_store/{unit_of_work,records,sharded_records,references,index,ordered_index,objects,object_chunks,atomic}.py` |
| 备份、迁移、维护 | `infrastructure/file_store/{backup,migrations,manifest_migration,commit_migration,maintenance,integrity}.py` |
| spool、检查点、恢复 | `infrastructure/file_store/{spool,checkpoints,recovery,continuations,execution_handles}.py` |
| 源码快照与控制 | `infrastructure/adapters/{source_snapshot,source_control}.py` |
| 执行、HTTP、业务查询 | `infrastructure/adapters/execution/*.py` |
| 模型 | `infrastructure/adapters/{model,deepseek}.py` |
| 凭据与安全 | `infrastructure/{credentials,credential_resolver,security}.py` |
| 时钟、能力、连接 | `infrastructure/{clock,capabilities,connections}.py` |
| 宿主、工作空间位置、环境 | `infrastructure/{host_lifetime,workspace_location,python_environment,environment_configuration}.py` |
| 入口协议、核心消息 | `interfaces/local/{api,core_client,core_worker,pipe,editor_host}.py` |

`infrastructure/` 内部也定义少量局部 `Protocol`（如 `connections.ConnectionProbePort`、`credentials.SecretProvider`、`adapters/model.py` 的 `HttpTransport`、`capabilities.CapabilityConditionStore`、`adapters/execution/command.py` 的 `CommandHandleStore`、`editor_host.CoreLauncher`），它们只服务于本层注入，不属于 `application/ports.py` 的对外端口清单。

## 5 端到端调用流程

```text
CLI / MCP relay / 面板 / Trae 扩展
  → CoreClient（最大命令帧、超时、精确回执）
  → 命名管道 aitest.local/2.0 → core_worker 主循环
  → LocalAPI.dispatch(command, session)
  → 身份/入口判定（editor_host、actor_context、panel_confirmation）
  → 用例注册表（B/C/D 注册的 handler）
  → application 用例（校验、幂等、事务边界）
  → domain 规则（判定、覆盖、复用、状态迁移）
  → ports → infrastructure（文件底座、适配器）
  → 工作单元提交不可变记录 + 索引 + 清单 + 幂等结果
  → Response / 只读投影 DTO 回写入口
```

1. **发现或启动核心。** `editor_host.py` 先连接工作空间管道；不存在则用注入的启动器启动 `core_worker`，有限次等待；身份不一致或连接失败即 `WORKSPACE_IN_USE`，不静默连接。
2. **帧与入口判定。** `pipe.py` 定义 `MAX_MESSAGE_BYTES` 与帧格式；`core_worker` 逐帧解析，坏帧回协议错误而不吞消息。入口类型由核心依据对端进程映像事实判定，交互宿主不能自证可信。
3. **派发。** `LocalAPI.dispatch` 只做路由、生命周期与安全投影：读动作直接走只读目录，写动作要求 `project_id`、`intent_id`、`expected_revision`，且 `request_id` 不得复用为 `intent_id`。
4. **用例与规则。** handler 在注册时闭包依赖；应用用例在事务外做外部执行与模型调用，在事务内只提交准备就绪的不可变材料。
5. **提交与读取。** `StageableWorkspaceUnitOfWork` 暂存记录、清单、索引与幂等结果后一次性发布；读取走有限 `QuerySpec` 目录，列表读摘要、详情按引用。

### 5.1 计划的执行许可（plan_grant）

`application/execution/plan_grant.py` 的 `PlanExecutionGrantService` 提供 `create_plan_grant` / `revoke_plan_grant` 两个受控动作，均属 `HUMAN_ACTIONS`。许可绑定已发布的冻结计划修订，撤销是独立事实；许可存在不等于已授权某一步，逐步授权仍由 `authorize_step` 与 `ExecutionAuthorizationProof` 判定。`usecase_registry.py` 在派发时读取命令参数中的 `plan_grant` 引用，缺引用按授权失败处理。字段与状态迁移以项目文档一期计划/执行分册为准，本册不复制。

### 5.2 pytest 原生链路

1. `application/project/test_discovery.py` 在冻结环境中执行 `python -m pytest --collect-only`，汇总范围与环境版本；收集失败或零用例是阻塞结论，不生成业务记录。
2. 执行由适配器按已保存入口跑真实命令，产物按 Attempt 存入 spool 与对象区。
3. `domain/execution/junit.py` 解析 JUnit（失败帧、跳过、测试路径）；`application/evidence/junit_artifact.py` 将其转为验证依据，方法名为 `pytest-junit`，依据版本串为 `aitest.pytest-basis/1`，且要求恰好一个已保存 Attempt。
4. `application/evidence/verification_resolver.py` 只接受 `all_pass` 与整数期望用例数；`application/planning/test_selection.py` 以同一方法名登记验证方式。解析结果只是事实，是否升级为有效验证仍由领域规则判定。

### 5.3 项目理解

`application/project/understanding.py` 的 `ProjectUnderstandingService` 与 `scan_sources` 扫描源码，产出带内容摘要的 `ProjectUnderstanding`；`domain/planning/understanding.py` 定义身份与序列化，`understanding_identity`、`understanding_content_digest` 保证同名理解可区分修订。它是草稿与计划的输入，不产生执行证据，也不替用户确认依据。

### 5.4 面板与三入口

共享面板只有一份源码 `resources/panel/src`，外壳 `index.ts` 定义三个导航入口：**本次测试**（`home`）、**问题与报告**（`reports`）、**设置**（`settings`），另有工作台、计划、规则、诊断、向导等视图。Trae 扩展通过 `aitest.openPanel`、`aitest.openWorkbench`、`aitest.openReport`、`aitest.configureEntry` 打开同一面板或配置入口。面板动作的 `intentId` 在页面内由动作、目标、期望修订与参数派生；跨入口重传仍由核心按 `(project_id, action, intent_id)` 去重。DTO 与快照/事件细节见[面板与工作台](07-面板与工作台.md)。

## 6 期次与能力对应

| 期次 | 代码事实 | 边界 |
| --- | --- | --- |
| 一期 | `contracts/commands.py` 的 `PHASE_ONE_ACTIONS` 是唯一动作表；项目/计划、L1—L3、证据、判定、报告、问题、恢复、面板、CLI、stdio MCP 均有实现 | 完成证明仍是真实输入、版本与证据；静态或夹具通过不等于验收通过 |
| 二期 | 已有源码绑定与快照链路（`domain/project/source_identity.py`、`application/project/source_analysis.py`、`SourceSnapshotPort`、`check_source`、`save_dependency_graph`）；面板为共享源码，可被其他宿主复用 | 六态定位（含 `current_verified`）在代码中**不存在**；非 Trae 宿主的实测证据未入库 |
| 三期 | 仅有本地受控交付记录（`domain/project/deliveries.py`、`save_delivery`、`submit_delivery`），属一期"正式提测"的本地交付说明 | 无平台客户端、无出站 Worker、无回执对拍；不引入本地 HTTP 服务、数据库或消息队列 |

能力降级按**具体动作**的真实依赖判断：某个适配器不可用只让相关动作返回明确错误码，不扩散为整个核心不可用。

### 6.1 动作表分组

`contracts/commands.py` 的 `PHASE_ONE_ACTIONS` 是一期全部可派发动作，另有两个子集用于入口校验：

| 子集 | 作用 | 代表动作 |
| --- | --- | --- |
| `READ_ACTIONS` | 免写事务、免 `intent_id` | `query`、`read_view`、`events`、`doctor`、`storage_usage` |
| `HUMAN_ACTIONS` | 必须由人工发起的受控动作 | `authorize_step`、`create_plan_grant`、`revoke_plan_grant`、`revise_pending_steps`、`narrow_driver` |
| 其余写动作 | 需要 `project_id`、`intent_id`、`expected_revision` | 项目/计划/准备/执行/证据/报告/问题各域动作 |

动作按域分布：项目（`bind_project`、`save_context`、`save_environment`、`save_dependency_graph`、`save_delivery`、`submit_delivery`）、理解与发现（`analyze_project`、`discover_tests`、`check_source`）、规则与草稿（`save_rules`、`publish_rules`、`generate_draft`、`request_model_draft`、`resolve_model_response`）、准备与执行（`prepare_run`、`register_run`、`prepare_execution`、`execute_step`、`start_run`、`retry_step`、`pause_run`、`resume_run`、`cancel_run`）、证据与验证（`attach_evidence`、`record_agent_evidence`、`import_external_result`、`verify_pending`）、报告与问题（`create_report`、`export_report`、`update_issue`、`record_fix`、`close_issue`）、维护（`backup`、`migrate`）。

CI 分工：`.github/workflows/ci.yml` 在 Windows 跑 `uv sync --extra dev --locked`、版本检查、`ruff`、`mypy`、Schema 生成漂移检查、状态文档检查、`pytest --collect-only` 与**有界**用例集；面板与 Trae 构建仅在 `v*` tag 上执行。`nightly.yml` 才跑全量 Python 回归。有界检查通过不得写成全量或真实宿主通过。

### 7.1 三个工作流

| 工作流 | 触发 | 实际内容 |
| --- | --- | --- |
| `ci.yml` | push/PR 到 `main`、`develop`，可被复用 | Windows `basic-checks`（20 分钟超时）：安装、版本、`ruff`、`mypy`、Schema 生成与漂移、状态文档、收集、有界用例；tag 时追加面板/扩展构建、`uv build`、制品校验与 wheel 冒烟 |
| `nightly.yml` | 定时/手动 | Windows 全量 `pytest`，`-n 8 --dist loadfile`，上传 JUnit |
| `release.yml` | `v*` tag | 先 `validate-tag`（ubuntu），再 `uses: ./.github/workflows/ci.yml` 复用检查，最后从制品发布 |

## 8 偏差记录

| 旧说法 | 代码事实 |
| --- | --- |
| 模板目录含 `manifest.json`，模板为单文件描述 | `resources/templates/<template_id>/<version>.json`，6 个模板目录各有一个 `1.0.0.json`；`contracts/templates.py` 定义模板三态与严格字段 |
| 二期、三期"代码中无可执行实现" | `save_dependency_graph`、`check_source`、`save_delivery`、`submit_delivery` 都在 `PHASE_ONE_ACTIONS` 内；二期源码绑定与三期本地交付草稿已有实现，但无六态定位、无平台客户端 |
| 端口只有 `application/ports.py` 一处定义 | `ports.py` 还从 `planning/model_ports.py` 与 `planning/substrate.py` 重导出 `ModelCall`、`Projection`、`Commit` 等类型；端口总数为 58 个 `Protocol` |
| CLI 有 `migrate`、`backup`、`rebuild` 等子命令 | 实际子命令为 `doctor`、`dispatch`、`templates`、`python-carrier`、`ensure-core`、`restart-core`、`rebuild-index`、`mcp-relay`；备份与迁移是 `dispatch` 提交的受控动作 |
| 面板由 Trae 扩展各自实现一份 | 共享面板源码在 `src/aitest/resources/panel`，三个导航入口为 `home`/`reports`/`settings`；扩展只承载 Webview 与命令 |
| 核心客户端可自动重试转发 | `core_client.py` 只做有界超时与精确回执校验，重连由 `editor_host`/入口负责，业务重传由核心幂等吸收 |
| `LocalAPI` 可直接写业务文件 | 写路径只能是注册的 handler → 应用用例 → 工作单元，`LocalAPI` 只做路由、生命周期与投影 |
| 状态文档检查覆盖全部文档 | `scripts/check_docs_facts.py` 只扫现行状态文档；`docs/归档/` 与历史 validation 不在扫描范围，本目录的事实需人工核对代码 |
