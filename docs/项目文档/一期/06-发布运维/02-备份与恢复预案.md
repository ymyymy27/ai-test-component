# 备份与恢复预案

本文件区分两件不同的事：**业务数据备份恢复**（已有实现，动作 `backup`）与**发布回滚**（没有实现，只有人工重装）。两者不能互相替代：备份能救数据，救不回已写入的新结构；重装能换回旧二进制，不能把旧版本写过的记录变回可读。

判定与持久化合同以[存储与恢复](../04-架构/05-存储与恢复.md)为准；本文件只写发布场景下的动作顺序、校验点与缺口。

## 1 发布前必须备份什么

| 类别 | 具体内容 | 依据 |
| --- | --- | --- |
| 业务数据闭包 | `workspace.json`、`records.json`、`indexes.json`、`current.json`、`commit.json`、`events.json`、`transactions.json` 与 `objects/`、`record-store/`、`manifests/`、`event-log/`、`snapshots/`、`checkpoints/`、`indexes/`、`reports/`、`exports/`、`generations/`、`core/`、`maintenance/` 等永久目录 | `infrastructure/file_store/backup.py` 的 `_PERMANENT_FILES` / `_PERMANENT_DIRS` 白名单 |
| 维护审计 | `maintenance/audit.jsonl`（备份时间、校验结果、缺失内容） | `FileMaintenanceService.record_backup` |
| 上一版分发包 | 上一版 wheel、VSIX 与 `SHA256SUMS`，放在工作空间之外的目录 | [发布方案第 4 节](01-发布方案.md) |
| 发布登记 | 提交号、版本号、产物 sha256、门禁命令与退出码 | 同上第 3 节 |
| **不备份** | 凭据正文（在 OS 凭据设施里）、被测源码的可复取依赖（Git/LFS）、活动执行中的 `spool/` 变化字节、安装包缓存 | 存储与恢复 §9、§10 |

- 备份不含密钥正文；换机后凭据缺失要如实显示"不可用"，不能用备份文件补。
- 有活动执行时 `spool/` 被排除并在回执的 `excluded_active` 里登记；此时备份是"已提交历史闭包"，不是"运行中完整快照"，不得写成完整备份。
- 备份不做自动轮换或删除，位置由操作者选定且必须独立于活动工作空间。

## 2 备份怎么做（真实动作）

动作名 `backup`，三种模式：`create`（默认）、`inspect`、`restore`。**只支持在线备份**（`kind` 固定 `online`）：维护模式下的完整停机备份没有可依赖的维护状态，传其他 `kind` 会被明确拒绝。

执行前置（由代码守卫强制）：

1. 会话必须是**受控交互会话**——核心按对端进程映像归类入口，内置只认 `trae.exe`，其余按 agent relay 处理；relay 会话调用备份会被拒绝。
2. 命令必须带 `project_id`、`intent_id`、`expected_revision`，且 `request_id` 不能等于 `intent_id`。
3. `destination` 必须是**绝对路径、位于活动工作空间之外、不存在或为空、路径链无符号链接**；目标非空直接拒绝，不覆盖。
4. 备份期间目标目录内不得被其他程序写入。

```powershell
# 1. 先确保唯一核心已在运行（该子命令不会创建目录，也不会新建工作空间）
.venv\Scripts\python.exe -m aitest.interfaces.tools.cli ensure-core --workspace "C:\aitest\data"

# 2. 在线备份：核心会弹出原生确认窗口，确认后才执行
'{"request_id":"req-20261114-01","intent_id":"intent-20261114-01","action":"backup",
  "project_id":"<项目ID>","expected_revision":0,
  "parameters":{"mode":"create","destination":"D:\\aitest-backup\\20261114-before-upgrade"}}'
  | .venv\Scripts\python.exe -m aitest.interfaces.tools.cli dispatch --workspace "C:\aitest\data" --native-confirmation

# 3. 只读回读登记并现场复核闭包（verify=true 会重算每条登记备份的摘要）
'{"request_id":"req-20261114-02","intent_id":"intent-20261114-02","action":"backup",
  "project_id":"<项目ID>","expected_revision":0,
  "parameters":{"mode":"inspect","verify":true}}'
  | .venv\Scripts\python.exe -m aitest.interfaces.tools.cli dispatch --workspace "C:\aitest\data" --native-confirmation
```

回执必须逐项记录：`manifest_digest`（即后续恢复用的 `backup_id`）、`file_count`、`total_bytes`、`verified`、`complete`、`known_missing`、`excluded_active`。`complete=false` 或 `known_missing` 非空时，保存好现场，但不得把它当"迁移前完整备份"。

**面板路径当前不可用**：面板"诊断 → 高级动作 → 备份工作空间"走普通写入通道，而 `backup` 既不在扩展的 `PLAIN_WRITE_ACTIONS` 也不在 `CONTROLLED_ACTIONS`，会被扩展以"该动作需要人工确认，不能走普通写入"拒绝；不要据此判断备份能力不存在。

## 3 恢复步骤与校验

恢复只能恢复到**新的空目标**，不在原工作空间上覆盖，避免把坏备份铺到唯一可用数据上。

1. 停写：确认没有活动执行；需要重启时用 `restart-core`（活动执行未排空会被拒绝），不强杀核心。
2. 发恢复：

```powershell
'{"request_id":"req-20261114-03","intent_id":"intent-20261114-03","action":"backup",
  "project_id":"<项目ID>","expected_revision":0,
  "parameters":{"mode":"restore","backup_id":"<清单摘要>","target":"D:\\aitest-restore\\20261114"}}'
  | .venv\Scripts\python.exe -m aitest.interfaces.tools.cli dispatch --workspace "C:\aitest\data" --native-confirmation
```

3. 核对回执：`state=restored`、`files_restored`/`bytes_restored` 与备份登记一致、`verified=true`、`index_rebuilt=true`。回执出现 `index_gap` 表示索引未重建成功，此时副本只能只读查看，不能直接当业务工作空间使用。
4. 打开恢复副本前必须让核心跑一次启动恢复（`ensure-core --workspace <恢复目录>`），由启动流程核对活动标记与提交清单；备份里的活动/未知步骤只恢复为"待核实"，不自动执行。
5. 逐项抽查：最早报告、被替代的修订、全部尝试、复核、诊断与导出引用都能按引用读到；缺失项与 `known_missing` 对齐。
6. 只有第 3—5 步全部符合，才把恢复副本当新工作空间使用；原工作空间保留不动，直到确认无用为止。

回执里两个固定的后置缺口要写进记录：`active_attempts_pending_verification_via_startup_recovery`（活动步骤靠启动恢复核实）、`double_takeover_check_not_performed`（未做双工作空间接管核对）。原工作空间仍有活动执行时，恢复副本必须只读隔离。

## 4 回滚触发条件与决策

| 触发事实 | 判定 | 动作 |
| --- | --- | --- |
| 新版本启动失败、`doctor` 长时间非 READY、核心启动诊断有明确错误 | 二进制/环境问题 | 受控停核心 → 装回上一版 wheel/VSIX → 重跑 `templates`、`doctor` → 记录版本与摘要 |
| 新版本可启动，但新建记录后旧版本读不出 | 结构前向不兼容 | **不回滚数据**；保留现场，用发布前备份恢复到新目录验证；原目录只读留证 |
| 备份 `inspect` 现场复核失败、摘要不符 | 备份不可信 | 不恢复该份；改用另一份已复核备份，或如实登记"无可恢复备份" |
| 恢复后索引重建失败（`index_gap`） | 副本不可直接使用 | 副本只读；另行执行索引重建排查，重建前不做业务读取 |
| 业务正确但宿主侧不可用（面板/扩展异常） | 宿主适配问题 | 可先降级为 CLI 操作并记录；是否回滚扩展由负责人决定，不改业务数据 |

- 发布回滚是**人工重装**：仓库没有回滚脚本、没有版本切换入口、没有"上一版自动恢复"。
- 决策顺序固定：先保数据（备份/副本），再换二进制，最后才处理宿主；不允许用删除或覆盖换取"能启动"。
- 一旦决定回滚，先冻结记录：版本、提交、命令、回执、失败现象与时间，全部写进验证批次。

## 5 数据兼容与不可回滚项

| 项 | 事实 | 后果 |
| --- | --- | --- |
| 结构版本 | `workspace.json` 记 `schema_version`；迁移只在维护窗口内前向执行 | 旧版本可能读不懂新结构，降级不保证可读 |
| 迁移回滚 | 迁移合同明确"切换后有新写入不允许丢弃式回滚" | 已写入的新记录不能靠回滚消除 |
| 索引 | `indexes/` 是可重建投影，恢复动作内会尝试重建 | 重建失败要人工处理，不能跳过 |
| 记录/报告 | 记录不可变、修订只追加；核验与报告不被改写 | 回滚二进制不会让旧报告"变回"旧结论 |
| 凭据 | 存 OS 凭据设施，不在工作空间与备份内 | 换机/重装备份后凭据需重新登记 |
| 导出与诊断 | 永久保留，不随版本回收 | 回滚后旧导出仍按原内容有效 |

**不可回滚项**：已提交的业务记录与事件、已发布计划的修订历史、已生成的报告与复核、已完成的迁移切换、备份审计记录。这些只能通过新记录或新副本处置，不能删除。

## 6 演练要求

发布前至少完成一次完整演练，并把输入、命令、回执、耗时、退出码写进批次记录：

1. 在一个**非发布用的测试工作空间**上执行 `create`，目标目录在活动工作空间之外且为空。
2. 执行 `inspect` 且 `verify=true`，要求 `verified=true`；核对 `manifest_digest` 与创建回执一致。
3. 执行 `restore` 到新的空目录，核对 `state=restored`、`files_restored`、`bytes_restored`、`index_rebuilt`。
4. 用核心打开恢复副本，抽查最早报告、被替代修订、问题与导出各一项。
5. 故意制造一次失败（目标非空、目标在工作空间内、或 `backup_id` 不存在），确认被拒绝且无半成品被当作可用备份。
6. 记录两处已知缺口：活动执行时的 `excluded_active`、恢复回执的双重接管未核对。

未完成演练的发布视为不满足[发布检查单](01-发布方案.md)第 6 节。物理掉电、真实强杀与跨机恢复没有演练证据时，只能登记为未验证，不能以单元测试或夹具通过代替。

## 7 偏差记录

| 来源表述 | 代码／脚本事实 | 处理 |
| --- | --- | --- |
| [存储与恢复](../04-架构/05-存储与恢复.md)第 6 节写迁移入口为 `aitest migrate inspect/plan/apply/resume/rollback` | `cli.py` 没有 `migrate` 子命令；迁移只能以 `dispatch` 派发 `migrate` 动作（`backup` 直接派发 `backup` 动作） | 本文件按实际子命令写，不写 `aitest migrate` |
| 合同提到"维护模式的完整停机备份" | `SavedBackupEntry._require_no_maintenance_kind` 只接受 `kind=online`，其他值明确拒绝 | 发布预案只安排在线备份 + 停写窗口，不宣称已有停机备份 |
| 合同写"恢复到新目录后切换" | 恢复动作只写入新空目标并重建索引，**没有自动切换指针或迁移入口**；切换由人把新目录当工作空间使用 | 第 3 节按实际回执与人工切换写 |
| 面板诊断页有"备份工作空间"引导项 | 面板提交走 `writeDispatch`，`backup` 不在 `PLAIN_WRITE_ACTIONS`/`CONTROLLED_ACTIONS`，会被扩展拒绝 | 明确标注面板路径不可用，操作以 CLI 原生确认为准 |
| 备份"位置由用户配置"的表述 | 实际是每次 `create` 传 `destination` 绝对路径，没有持久化配置项 | 本文件按参数写，不写"配置文件里的备份目录" |
| 旧说法"恢复到新目录会自动核验活动执行与双重接管" | 回执固定登记这两项为未完成缺口，需启动恢复与人工核对 | 第 3 节把两项列为必查后置条件 |
