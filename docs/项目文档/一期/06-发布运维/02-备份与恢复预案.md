# 备份与恢复预案

> 状态：2026-11-16 轻量插件基线，2026-11-17 按代码事实核对。恢复演练已有 CLI 证据；真实宿主备份恢复仍待验证。

本文件只处理**用户数据工作空间的 zip 备份与恢复**。它不处理发布回滚：版本回滚见[发布方案](01-发布方案.md)第 6 节，两者不能互相替代。备份能救数据，救不回已写入的新格式；换回旧 wheel 也不能把新记录变回可读。

## 1 备份什么、不备份什么

工作空间默认形态见[存储与备份](../04-架构/04-存储与备份.md)；实际打包由 `backup.create` 执行。

| 类别 | 内容 | 是否默认包含 |
| --- | --- | --- |
| 工作空间元数据 | `workspace.json` | 是 |
| 项目与任务 | `projects/<id>/project.json`、`project.config.json`、`project-map.json`、`tasks/*.json`、`tasks/revisions/**`、`deliveries/*.json` | 是 |
| 规则与计划 | `rules/*.json`、`plans/*.json`、`plans/revisions/**`、`confirmations/*.json` | 是 |
| 运行记录 | `runs/<id>/run.json`、`plan.json`、`task.json`、`manual/*.json`、`link.json`、`cancel.requested` | 是 |
| 问题与报告 | `issues/*.json`、`reports/*.json` | 是 |
| 项目配置 | `project.config.json`（只含地址、模型名、超时等非敏感项） | 是 |
| GitHub 读取缓存 | `projects/<id>/github/*.json` | 是 |
| 证据正文 | `runs/<id>/evidence/*` | **否**，需 `include_evidence=true` |
| 生成脚本 | `runs/<id>/generated/*` | `include_evidence=true` 时包含；默认排除 |
| 请求缓存 | 顶层 `requests/` | 否 |
| Mock 判定缓存 | 顶层 `.cache/mock/` | 是（随工作空间打包，非业务记录） |
| 旧备份 | 顶层 `backups/` | 否 |
| 工作空间锁 | `.workspace.lock` | 否 |

- 备份按工作空间全量文件打包，只排除 `.workspace.lock`、`requests/`、`backups/` 与（默认）`evidence/`、`generated/`；新增项目级目录会随 `projects/**` 一并包含。

- 模型密钥、GitHub token 不写入工作空间，因此不应出现在备份里；发现即按凭据泄露处理。
- 证据默认不打包，是为了控制体积；需要完整交接时再显式包含。
- 备份文件本身不加密；存放位置由用户选择，不能放进被测源码仓库。

## 2 创建备份

```bash
python -m aitest.cli backup.create --workspace "C:\aitest\data" --input backup.json
```

`backup.json`：

```json
{
  "command": "backup.create",
  "request_id": "req-backup-20261116-01",
  "payload": {
    "path": "D:\\aitest-backup\\20261116-before-upgrade.zip",
    "include_evidence": false
  }
}
```

返回示例：

```json
{
  "ok": true,
  "data": {
    "path": "D:\\aitest-backup\\20261116-before-upgrade.zip",
    "sha256": "…",
    "bytes": 123456,
    "includes_evidence": false,
    "files": 87,
    "estimated_evidence_bytes": 78901234,
    "estimated_evidence_mb": 75.2
  }
}
```

- `path` 用绝对路径；父目录不存在时自动创建。
- `estimated_evidence_*` 是当前工作空间证据总大小的估算，供 `include_evidence=true` 时参考；面板当前不展示该值，只显示保存路径、文件数与 sha256。
- 备份包内含 `manifest.json`，列文件清单并带逐文件 `sha256` 与 `file_count`；整包摘要以返回的 `sha256` 为准。
- 创建失败不会留下可用的半截 zip；目标已存在时直接拒绝（`INVALID_REQUEST`），不覆盖；请用带时间戳的新文件名。
- 不包含证据时，`run.json` 里的 `evidence_refs` 仍指向 `evidence/…`，恢复后这些文件不存在，属于预期缺口。

## 3 校验备份

1. 把返回的 `sha256`、字节数、文件数记入变更记录或验证批次。
2. 需要复核时重新计算摘要：

```powershell
Get-FileHash D:\aitest-backup\20261116-before-upgrade.zip -Algorithm SHA256
```

3. 列出包内文件，确认 `workspace.json`、至少一个 `projects/<id>/project.json` 存在：

```powershell
Add-Type -AssemblyName System.IO.Compression.FileSystem
[System.IO.Compression.ZipFile]::OpenRead("D:\aitest-backup\20261116-before-upgrade.zip").Entries |
  Select-Object -First 20 FullName
```

- 摘要不一致、zip 打不开、`manifest.json` 缺失，都按“备份不可用”处理，不要尝试恢复。
- 备份不自动轮换、不自动删除；保留几份由用户决定。

## 4 恢复到新目录

恢复只允许写入**新的空目录**，不覆盖现有工作空间。

```bash
python -m aitest.cli backup.restore --workspace "C:\aitest\data" --input restore.json
```

`restore.json`：

```json
{
  "command": "backup.restore",
  "request_id": "req-restore-20261116-01",
  "payload": {
    "path": "D:\\aitest-backup\\20261116-before-upgrade.zip",
    "target": "D:\\aitest-restore\\20261116"
  }
}
```

步骤：

1. 确认没有活动运行；有运行先等待完成或取消，不直接结束进程。
2. 选择不存在或为空的目录；目标非空会被拒绝。
3. 执行恢复，返回 `target` 与 `files` 数量。
4. 核对目标目录中的 `workspace.json`、项目目录与报告文件是否齐全。
5. 把该目录配置为新的 `aitest.workspacePath`，打开面板或运行 `doctor` 确认可读。
6. 原工作空间保留不动，确认新副本可用后再决定是否清理。

- 恢复会拒绝绝对路径与含 `..` 的 zip 成员，防止越界写入。
- 恢复会按 manifest 逐文件校验 sha256，并核对文件总数、清单、重复条目与符号链接；不校验包外记录的整包摘要。
- 恢复先校验备份 manifest 的 `schema_version`，只接受 `1`；不是 `1` 时返回 `SCHEMA_UNSUPPORTED`，提示用当前版本重新备份或先转换。
- 恢复本身不做业务记录迁移；恢复后的业务 JSON 由各命令按当前 `schema_version` 校验并拒绝旧格式，提示转换或重建。
- 恢复返回 `missing_evidence` 与 `notes`（“证据未包含：N 个引用…”）；不会改写 `run.json` 中的原引用。

## 5 典型场景

| 场景 | 做法 | 注意 |
| --- | --- | --- |
| 升级前 | 创建不含证据的备份，记录 sha256 | 升级后旧格式可能不可读 |
| 交接/换机 | 创建含证据的备份，核对体积 | 证据大时先确认目标磁盘 |
| 误删记录 | 从最近备份恢复到新目录 | 不覆盖原目录，先比对再切换 |
| 磁盘将满 | 先删旧备份或转移，不删证据 | 证据永久保留，清理需人工决定 |
| 备份损坏 | 换另一份已校验备份 | 不尝试修补 zip |

含证据的备份体积估算：`backup.create` 返回 `estimated_evidence_bytes` / `estimated_evidence_mb`，可据此判断加上 zip 压缩余量后的体积；面板当前不展示“预计大小”，需要时以返回字段或人工统计为准。

## 6 演练要求

发布前至少完成一次：

1. 在测试工作空间创建备份，记录 `sha256`、`files`、`bytes`。
2. 重新计算摘要，确认与返回值一致。
3. 恢复到新的空目录，核对文件数与关键 JSON。
4. 故意用非空目标恢复一次，确认被拒绝且没有半成品。
5. 恢复后打开一次项目与运行详情，记录缺证据的引用位置。
6. 把命令、退出码、摘要与缺口写入运行记录与 `tests/acceptance/p1/evidence/<批次>/`；`status.json` 只更新 P1-AC24 的 `evidence.path`。

未演练的发布不满足[发布方案](01-发布方案.md)第 7 节。物理掉电、运行中备份与跨机恢复没有证据时，只能登记为未验证。
