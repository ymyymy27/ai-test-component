# 安装与操作说明

本文件面向**使用者**：从零安装核心与 Trae 扩展，走完首次向导，完成一次测试、看报告、处理问题、排查故障和卸载。只用界面上的名称与外壳命令，不涉及内部字段。

适用范围：Windows 11 x64 本地安装、单机单用户。当前版本为 `0.4.10`（以[pyproject.toml](../../../../pyproject.toml)为准）；真实 Trae 完整流程仍在验收中，界面能打开不等于验收通过，未验证边界见[项目现状](../../../现状.md)。

## 1 前置条件

| 项 | 要求 | 说明 |
| --- | --- | --- |
| 操作系统 | Windows 11 x64 | 其它系统未纳入本期范围 |
| Python | 3.11 及以上、低于 3.14；建议 3.13 | 产品声明范围来自 `pyproject.toml`；CI 与隔离安装冒烟只用 3.13 |
| Tcl/Tk | 随 Python 安装（含 `tkinter`） | 人工确认窗口依赖它；精简安装可能缺失 |
| 编辑器 | 支持 VS Code 扩展接口 1.85 及以上（Trae） | 扩展声明 `^1.85.0`；本机曾用于 Trae CN 1.107.1 |
| 数据目录 | 本机磁盘上的独立空目录 | 网络盘、同步盘会被明确拒绝；不能选源码目录或安装目录 |
| 磁盘空间 | 预留业务数据 + 备份两倍以上空间 | 报告、证据、诊断永久保留，不自动清理 |
| Node.js | 仅从源码构建时需要，安装不需要 | 安装用 wheel 与 VSIX 即可 |

1. 确认 Python 可用：`py -3.13 --version`；再确认 `py -3.13 -c "import tkinter"` 无报错。
2. 新建两个目录：数据目录（例如 `C:\aitest\data`）与备份目录（另一块盘，例如 `D:\aitest-backup`）。两者都不放在源码仓库里。

## 2 安装核心

1. 建独立虚拟环境（不要装进被测项目的环境）：

```powershell
py -3.13 -m venv C:\aitest\venv
C:\aitest\venv\Scripts\python.exe -m pip install --upgrade pip
```

2. 安装本条 wheel（文件名中的版本以发布物为准）：

```powershell
C:\aitest\venv\Scripts\python.exe -m pip install C:\aitest\pkg\ai_test_component-0.4.10-py3-none-any.whl
```

离线机器需先保证 `pydantic`（2.11 以上、3 以下）与 `portalocker`（3.2 以上、4 以下）可安装。

3. 自检：

```powershell
C:\aitest\venv\Scripts\python.exe -m aitest.interfaces.tools.cli templates
C:\aitest\venv\Scripts\python.exe -m aitest.interfaces.tools.cli doctor
```

`templates` 应列出 6 个模板；`doctor` **退出码 2 且显示 `NOT_READY` 是正常的**，因为此时还没有工作空间。安装成功不等于 `READY`。

4. 首次启动核心（目录必须已存在）：

```powershell
C:\aitest\venv\Scripts\python.exe -m aitest.interfaces.tools.cli ensure-core --workspace "C:\aitest\data"
```

看到 `status: READY` 并给出工作空间与实例标识即表示核心已启动。该命令不会替你创建目录：路径写错会返回 `WORKSPACE_NOT_FOUND`。

## 3 安装扩展

1. 打开编辑器的扩展视图，选择"从 VSIX 安装"，选中 `integrations/trae/dist/aitest-trae.vsix`。
2. 安装后重载窗口（不重载不会激活新版本）。
3. 打开设置，填写三项：

| 设置项 | 填什么 | 常见错误 |
| --- | --- | --- |
| Python 解释器 | `C:\aitest\venv\Scripts\python.exe` | 填了系统 `python`，扩展找不到已安装的包 |
| 工作空间目录 | `C:\aitest\data` | 填成被打开的源码目录，或网络/同步盘 |
| 项目编号 | 首次向导生成后自动写入 | 手工乱填会导致读取不到项目 |

4. 侧栏出现"AI 测试"图标；命令面板里应有"AI Test: 打开测试面板"和"AI Test: 配置工作空间与项目"。

首次配置向导以隔离模式（`-I`）调用该解释器，因此**该解释器必须已装好本包**；只把源码目录加进环境变量过不了向导。核心派发与 `ensure-core` 不走隔离模式，但同样建议用同一解释器。

## 4 首次向导操作

1. 命令面板执行"AI Test: 配置工作空间与项目"，选择上面建好的数据目录，向导会登记项目并给出项目编号；关闭窗口不会提交。
2. 执行"AI Test: 打开测试面板"，点击"连接 / 刷新核心"；页头显示已连接、并列出可用动作后才可继续。
3. 在"本次测试"页进入首次向导，按六步走：

| 步骤 | 你要做的事 | 完成标志 |
| --- | --- | --- |
| 选择项目 | 确认项目与源码根目录 | 页面显示固定项目 |
| 准备环境 | 选择实际解释器与依赖 | 环境登记成功，不是"未知" |
| 发现测试 | 让核心扫描用例 | 列出可测用例 |
| 生成计划 | 生成并核对计划提案 | 计划草稿可见 |
| 核对发布 | 阅读确认材料后发布计划 | 计划状态变为已发布 |
| 准备运行 | 准备并登记本次运行 | 出现运行编号，可进工作台 |

4. 模型为可选：不配置时计划生成会明确阻塞，执行、规则和报告不受影响。要配置就在"设置 → 模型 API"填写地址、模型名与超时，密钥通过"管理安全凭据"保存，**不要把密钥粘进任何输入框或文档**。
5. 向导完成后，页头可"重启核心"使新配置生效；有执行在跑时重启会被拒绝，先处理执行。

## 5 日常操作（本次测试 / 报告 / 问题）

**一次测试的完整路径**

1. 打开"本次测试 → 概览"，看当前进度与待办。
2. 进"计划"核对本轮范围；如需调整，先存草稿再发布，草稿不等于发布。
3. 进"工作台"：点"查看将执行的操作"→"确认并授权"→"执行已确认的操作"；需要人工操作时按提示补证据。
4. 执行中可用"暂停 / 继续 / 取消"；单步失败点"重试这一步"，需要回到上一阶段点"退回上游"（两者都会产生新尝试），材料缺失时用补证按钮把人工证据绑定到已完成的尝试。
5. 每步执行后点"核验这次执行结果"；未核验的步骤不会计入有效验证，界面不会替你标成通过。

**看报告**

1. 进"问题与报告 → 报告"，点"读取报告修订"。
2. 选择修订后查看结论、证据与覆盖范围；点证据编号可打开证据正文，点"打开源码"跳转位置。
3. 导出："导出 Markdown 摘要"给人看，"导出证据包"用于交接复核；导出后核对文件数与摘要。

**处理问题**

1. 进"问题与报告 → 问题"，选中问题查看证据与复测建议。
2. 修复后用"提交问题操作"登记修复与回归请求；需要交接时"复制复测简报"。
3. 关闭问题需要新的执行证据；复用旧结论不能作为关闭依据。

**提测**：进"提测"页，确认交付、源码与报告引用后提交；提交属于人工动作，面板会要求再次确认。

## 6 诊断与重启

| 想确认 | 入口 | 看什么 |
| --- | --- | --- |
| 核心是否连上、能力有哪些 | 设置页"连接 / 刷新核心"；页头"诊断" | 连接状态、依赖状态、可用动作清单 |
| 最近发生了什么 | 诊断页"读取最近事件" | 事件列表与游标，可续读 |
| 磁盘占用与材料规模 | 诊断页"空间诊断" | 各目录文件数与字节数 |
| 某个常用界面没覆盖的操作 | 诊断页"高级动作" | 参数必须来自准确记录；写动作仍会要求确认 |

重启原则：

1. 先在设置页点"重启核心"；命令行为 `restart-core --workspace "C:\aitest\data"`。
2. 有活动执行或未知执行时重启会被拒绝，这是保护措施：先排空或核实，不要强杀进程。
3. 重启后核对：工作空间标识不变、实例标识变化、面板能重新读取项目与运行。
4. 查询列表异常时可让核心未运行时重建索引：`rebuild-index --workspace "C:\aitest\data"`；重建不是日常操作，先记录现象。

备份与恢复由运维按[备份与恢复预案](02-备份与恢复预案.md)执行，不要在面板里试用未经验证的路径。

## 7 卸载与清理

1. 关闭编辑器窗口并等待核心退出；有活动执行时核心会继续服务，要先在面板排空或完成核验。**不要强杀进程**，也不要指望自动清理临时文件。
2. 卸载扩展：扩展视图中找到"AI Test — Phase One Preview"，选择卸载并重载窗口。
3. 卸载核心包：`C:\aitest\venv\Scripts\python.exe -m pip uninstall ai-test-component`。
4. 删除虚拟环境目录 `C:\aitest\venv`。
5. 数据目录 `C:\aitest\data` **默认保留**：里面有记录、证据、报告与诊断，卸载不会删除，也没有一键清理命令。确需清理时先按预案做备份，再人工删除整个目录。
6. 备份目录按保留策略处理，不要与数据目录一起删。

没有官方卸载脚本；以上步骤需手工执行并留记录。卸载不会回滚任何业务数据。

## 8 常见失败处理

| 现象 | 常见原因 | 处理 |
| --- | --- | --- |
| 侧栏没有"AI 测试"图标 | 未重载窗口、VSIX 未装成功、编辑器版本过低 | 重载窗口；重新从 VSIX 安装；核对编辑器版本 ≥1.85 |
| 面板提示未连接核心 | 解释器路径填错、包没装到该解释器、数据目录不存在 | 在设置里重填解释器；用同一解释器跑 `templates` 自检；确认目录已手工创建 |
| 提示工作空间路径不存在或不是目录 | 目录被删或写错 | 重建目录或改设置；入口不会替你造目录 |
| 提示工作空间被占用 | 另一个窗口或残留核心在写 | 关闭其他窗口；用 `restart-core` 受控重启，不要强杀 |
| 提示位置被拒绝（网络盘/同步盘） | 数据目录在 OneDrive、网盘或映射盘上 | 换到本机固定磁盘 |
| `doctor` 一直 `NOT_READY` | 没有工作空间，或核心未启动 | 先 `ensure-core`；带 `--workspace` 的 `doctor` 只连已有核心，不负责启动 |
| 人工确认窗口不出现 | 缺 Tcl/Tk、窗口被最小化或已超时 | 重装带 Tk 的 Python；重新发起动作；超时不会提交 |
| 某动作被拒绝（需要人工确认/不在允许范围） | 该动作不能由当前入口发起 | 回到面板对应页面操作；不要用普通写入参数绕过 |
| 导出或报告缺证据 | 证据修订缺失或材料失效 | 打开记录看缺口提示；补证后重新生成报告 |
| 计划生成被阻塞 | 未配置模型或模型不可用 | 配置模型或接受阻塞；不能手工伪造 AI 内容 |

## 9 偏差记录

| 来源表述 | 代码／脚本事实 | 处理 |
| --- | --- | --- |
| [Trae 扩展说明](../../../../integrations/trae/README.md)写"先安装同版本 Python 包（Windows、Python 3.13）" | `pyproject.toml` 声明 `>=3.11,<3.14`；CI 与隔离冒烟只在 3.13 上验证 | 本文写"3.11 以上、3.14 以下，建议 3.13"，并注明只有 3.13 有构建证据 |
| [README](../../../README.md)开发命令用 `.venv/Scripts/python.exe` 与 `scripts/check_docs_facts.py --full` | 仓库根 `.venv` 是开发环境；`--full` 会额外跑 mypy 与真实装配 | 使用者文档改用独立安装目录 `C:\aitest\venv`，不依赖仓库内 `.venv` |
| README 命令行示例写 `mcp-relay --workspace ... --project ... --binding ...` | `cli.py` 只要求 `--binding`，`--workspace` 与 `--project` 可选；但 relay 实际需要工作空间与项目才能工作 | 本文把三参数作为实际配置要求写 |
| 旧材料称面板"高级动作 → 备份工作空间"可直接用 | 扩展会拒绝该动作（不在普通写入允许集，也不在受控确认集），需用 CLI `dispatch` 派发普通维护动作 | 第 6 节改为指向备份预案，不引导用户在面板里点 |
| 旧材料称卸载有清理脚本 | 仓库无卸载脚本、无数据清理命令；数据目录不随卸载删除 | 第 7 节按手工步骤写，并说明数据保留 |
| 旧材料把 `doctor` 返回 `NOT_READY` 当作安装失败 | 无工作空间时退出码 2 + `NOT_READY` 是设计行为 | 第 2 节明确写为正常结果 |
