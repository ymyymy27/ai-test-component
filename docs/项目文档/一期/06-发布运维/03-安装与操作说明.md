# 安装与操作说明

> 状态：2026-11-16 轻量插件基线；待真实环境验证

本文件面向使用者：从零准备 Python、安装 wheel 与 Trae 扩展，配置模型与 `gh`，走完首次项目与运行流程，并处理常见错误。只用界面名称与外壳命令，不涉及内部字段。当前版本以[pyproject.toml](../../../../pyproject.toml)为准（0.5.0）；完整宿主闭环未验收（仅 P1-AC02 有真实面板截图），界面能打开不等于验收通过。

## 1 前置条件

| 项 | 要求 | 说明 |
| --- | --- | --- |
| 操作系统 | Windows 11 x64 | 其他系统未纳入本期 |
| Python | 3.11 及以上、低于 3.14；建议 3.13 | 只有 3.13 有构建与冒烟证据 |
| Trae | 支持 VS Code 扩展接口 1.85 及以上 | 扩展声明 `^1.85.0` |
| 工作空间 | 本机磁盘上的独立目录 | 不要指向源码、安装目录或同步盘 |
| 磁盘 | 业务数据、证据与备份留足空间 | 证据永久保留，不自动清理 |
| `gh` | 使用 GitHub 关联时需要 | 只读提交、PR、检查与部署版本 |
| Node/npm | 仅从源码构建时需要 | 安装现成 wheel 与 VSIX 不需要 |

## 2 Python 发现与准备

扩展按以下顺序寻找解释器，任一步成功即停：

1. 设置 `aitest.pythonPath` 指向的解释器；
2. 工作空间目录下的 `.venv/Scripts/python.exe`；
3. `%APPDATA%/aitest/runtime/<版本>/` 中已缓存的便携运行时；
4. `py -3`；
5. `PATH` 中的 `python`。

校验条件：版本 ≥3.11，且 `import aitest` 成功或 `aitest --version` 可执行。缺任何一项都会在候选中记失败原因，不会静默改用其他解释器。

候选全部失败时会自动准备：下载便携 Python 到 `%APPDATA%/aitest/runtime/<版本>/`，创建 venv，用 VSIX 自带 wheel 执行 `pip install --no-index`，校验 SHA256；任一步失败即停并显示阶段与原因。离线或排障时也可手工执行：

```powershell
py -3.13 -m venv C:\aitest\venv
C:\aitest\venv\Scripts\python.exe -m pip install --upgrade pip
C:\aitest\venv\Scripts\python.exe -m pip install C:\aitest\pkg\ai_test_component-0.5.0-py3-none-any.whl
C:\aitest\venv\Scripts\python.exe -c "import aitest; print(aitest.__version__)"
```

- 已有合格 Python 的用户直接设置 `aitest.pythonPath`，不需要额外安装运行时。
- 便携运行时目录可在排障时删除，下一次使用会重新准备；删除它不影响工作空间数据。

## 3 安装扩展与设置工作空间

1. 在 Trae 扩展视图选择“从 VSIX 安装”，选中 `integrations/trae/dist/aitest-trae.vsix`，安装后重载窗口。
2. 打开设置，填写：
   - `aitest.pythonPath`：已安装 wheel 的解释器，例如 `C:\aitest\venv\Scripts\python.exe`；
   - `aitest.workspacePath`：用户数据工作空间，例如 `C:\aitest\data`。
3. 工作空间默认 `%APPDATA%/aitest/workspaces/default`，可用 `aitest.workspacePath` 改；项目仓库内不留数据。
4. 侧栏出现“AI 测试”；命令面板有“打开测试面板”“检查环境”“查看运行状态”。

工作空间只放插件数据，不放被测源码；一个工作空间可以登记多个项目，项目仓库内不写插件文件。

## 4 配置模型密钥

模型 API 是必需依赖，用于目标候选、验收项、计划、脚本、Mock 判定、失败分析与报告摘要。密钥解析顺序：

1. 环境变量 `AITEST_MODEL_KEY`；
2. 用户级配置 `%APPDATA%\aitest\config.json` 的 `model.api_key`；
3. 都没有 → `doctor` 显示 `model.ok=false`，AI 步骤不可用。

用户配置示例：

```json
{
  "model": {
    "api_key": "sk-…",
    "base_url": "https://api.deepseek.com",
    "name": "deepseek-chat",
    "timeout_seconds": 120
  }
}
```

- 默认 `base_url` 为 `https://api.deepseek.com`，默认模型名为 `deepseek-chat`；项目配置可覆盖地址、模型名与超时，但不能写密钥。
- 密钥不进入工作空间、日志、证据、报告或导出；`doctor` 只显示来源（环境变量/用户配置/未配置），不显示密钥。
- 模型不可用时，测试执行、证据、报告仍可用；计划生成会明确报 `MODEL_UNAVAILABLE`，不伪造用例。

## 5 配置 GitHub（一期必需，只读）

GitHub 只读关联依赖 `gh` 登录态：

```powershell
winget install --id GitHub.cli
gh auth login
gh auth status
gh api user
```

- 插件不保存 token，只通过 `gh api` 发 GET；`gh` 缺失或未登录时返回 `GITHUB_UNAVAILABLE`，本地测试继续。
- `doctor` 通过 `gh auth status` 检查登录状态，并记录账号与主机；未登录时给 `gh auth login` 指引。
- 读取结果记录账号与主机；失败不返回缓存冒充最新。

## 6 首次使用流程

1. **绑定项目**：在面板选择源码目录，填写项目名与目标。根目录与已登记项目重叠时会提示选择，不自动合并。
2. **建任务**：输入一句目标，或从 AI 候选目标中选一条；无信号的新项目给通用目标“验证项目能否启动并跑通主流程”。自定义输入始终可用。
3. **登记验收项**：从任务描述或需求文档提取；不可观察的条目标“待补充”，不进入范围。
4. **选范围**：按验收项选“全部适用”或“自选”；空范围不能发布计划。
5. **生成计划**：AI 按选中验收项生成用例并发布为初版；每个验收项至少一条用例，预期必须引用验收项原文。模型不可用时改人工编写或导入。
6. **执行前确认**：核对范围、用例数、环境、凭据边界、副作用、将安装的依赖与预计耗时；确认记录写入 `run.json`。
7. **执行**：`run.start` 启动一次性 worker，面板轮询状态；关闭 Trae 不中断运行，取消在用例边界生效。
8. **看结果**：运行结束后查看结论、范围覆盖、证据、Mock 判定、问题与 AI 分析；报告导出 Markdown。
9. **备份**：按[备份与恢复预案](02-备份与恢复预案.md)创建 zip，记录摘要。

## 7 常见错误

| 现象 | 错误码 | 处理 |
| --- | --- | --- |
| 工作空间不可写或路径无效 | `INVALID_PATH` / 写盘错误 | 换一个可写目录，或修正 `aitest.workspacePath` |
| 扩展找不到解释器 | `PYTHON_NOT_FOUND` | 安装 Python 3.11+ 与 wheel，设置 `aitest.pythonPath` |
| 另一个进程占用工作空间 | `WORKSPACE_LOCKED` | 关闭另一个 Trae/CLI，等待命令结束 |
| 项目不存在 | `PROJECT_NOT_FOUND` | 先 `project.add` 或检查项目 ID |
| 计划未发布 | `PLAN_NOT_PUBLISHED` | 先 `plan.publish` |
| 范围为空 | `SCOPE_EMPTY` | 至少选一条可用验收项 |
| 缺执行确认 | `CONFIRMATION_REQUIRED` | 在面板确认，或 CLI 加 `--confirm` |
| 同一项目已有运行 | `RUN_ACTIVE` | 等待完成、取消或查看现有运行 |
| 模型未配置/不可达 | `MODEL_UNAVAILABLE` | 配置密钥与地址；或接受 AI 步骤不可用 |
| `gh` 缺失/未登录 | `GITHUB_UNAVAILABLE` | 安装 `gh` 并 `gh auth login` |
| 链路缺配置 | `LINK_CONFIG_MISSING` | 在 `project.config.json` 补日志路径或查询命令 |
| 生成脚本含危险操作 | `SCRIPT_REJECTED` | 检查脚本或改用手写 |
| 磁盘不足 | `DISK_FULL` | 清理磁盘或转移备份；不删已有证据 |
| 旧数据格式 | `SCHEMA_UNSUPPORTED` | 先备份，再转换或重建 |

- 错误响应的 `next_step` 是给人看的下一步；不要用修改 JSON 或删锁文件绕过。
- 运行中异常在 `runs/<id>/worker-error.txt`；服务启动日志在 `runs/<id>/service.log`。

## 8 卸载与数据保留

1. 等待运行结束或取消，关闭 Trae 窗口，不直接结束 worker 进程。
2. 在扩展视图卸载“AI Test — Trae 轻量扩展”，重载窗口。
3. `C:\aitest\venv\Scripts\python.exe -m pip uninstall ai-test-component`。
4. 工作空间目录默认保留：项目、运行、证据、报告都在里面，卸载不会删除；确需清理先备份再人工删除。
5. `%APPDATA%/aitest/runtime` 可一并删除；它只含便携运行时，不含业务记录。
5. 保留上一版 wheel 与 VSIX，便于按[发布方案](01-发布方案.md)第 6 节回滚。

没有官方卸载脚本；以上步骤手工执行并留记录。卸载不会回滚业务数据。
