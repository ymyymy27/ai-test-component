# 运行观测与数据采集

> 状态：2026-11-16 轻量插件基线，2026-11-17 按代码事实核对。完整宿主闭环与试点项目待验证。

本文件定义运行观测指标与采集口径，不替代效果评估；一期不设效果基线、目标值或“是否有效”的自动判定。产品没有遥测、没有上报接口、没有账号体系；所有指标由维护者在本地读取工作空间与仓库材料得出。指标不改变验收结论，也不替代真实 Trae 验收。2026-11-18 自动化基线为 pytest 265、面板 vitest 48、扩展 node test 48。

## 1 原则

1. **本地**：只读本机工作空间与 `tests/acceptance/p1/status.json`。
2. **无遥测**：不发送使用次数、点击、崩溃、机器标识或路径清单。
3. **不外传**：模型调用、`gh` 读取、链路查询是用户显式触发的业务动作，不是指标上报；指标本身不出本机。
4. **可复算**：每个数字都能由 `run.json`、`report.json`、`status.json` 或文件大小重算。
5. **不伪造**：空分母不显示 100%；未执行、未知、阻塞不折算成通过。

## 2 指标定义

| 指标 | 定义 | 数据来源 | 不能说明什么 |
| --- | --- | --- | --- |
| 运行数 | 指定项目下 `runs/*/run.json` 的数量 | `run.json` | 运行多不代表覆盖全 |
| 运行状态分布 | `running/completed/cancelled/interrupted/execution_error` 各计数 | `run.json.status` | `completed` 不等于业务通过 |
| 结论分布 | `passed/failed/incomplete/not_applicable` 各计数 | `report.json.outcome` 或 `run.status` 返回的 `outcome` | 只对本次范围 `S` 成立 |
| 运行通过率 | `outcome=passed` 的运行数 ÷ 分母；分母为 `completed` 且 `outcome in {passed, failed, incomplete}` 的运行数，不含 `cancelled/interrupted/not_applicable` | `report.json` / `run.json` | 分母为 0 时不显示百分比；不跨项目合并；不是效果指标 |
| 用例结果 | `passed/failed/blocked/error/not_run/manual_pending` 计数 | `run.json.cases[].result` | 一个用例覆盖多个验收项时按验收项另计 |
| 覆盖计数 | `selected/applicable` 见 `report.coverage`；`passed/failed/incomplete` 见 `report.counts` | `report.json` | `selected < applicable` 时只说“本范围通过” |
| 证据大小 | `runs/*/evidence` 与 `runs/*/generated` 字节总和 | 文件系统 | 不含备份与项目源码；两项都要统计 |
| 截断证据数 | `*.truncated` 标记文件数量 | `runs/*/evidence` | 截断不代表证据无效，但要看原始大小 |
| AI 未生成次数 | `run.analysis[]` 中 `status != "generated"` 的条目数 | `run.json.analysis`（数组） | 模型失败不等于测试失败 |
| Mock 未判定数 | `run.mock_judgement[].kind == "unknown"` 的条目数 | `run.json.mock_judgement` | `unknown` 不能获得“真实链路通过” |
| 人工兜底数 | `run.json.cases[].result == "manual_pending"` 的用例数 | `run.json` | 人工未记录计入未完成 |

补充口径：

- 通过率按**项目**或**批次**分别算，不把不同项目、不同范围混成一个“总通过率”。
- `not_applicable` 不计入通过率分子，也不把分母撑大；没有任何有结论运行时显示“无数据”。
- 证据大小按字节统计，报告时换算 MB/GB；备份 zip 单列，不混进运行证据。
- AI 未生成包括 `not_generated` 与 `invalid`；模型未配置时也会出现在 `analysis` 里。

## 3 采集方法

工作空间结构见[运维手册](04-运维手册.md)；以下命令在工作空间根目录执行。

统计运行与结论：

```powershell
$runs = Get-ChildItem "projects\*\runs\*\run.json" -File
$data = $runs | ForEach-Object { Get-Content $_.FullName -Raw | ConvertFrom-Json }
$data | Group-Object status | Select-Object Name, Count
$data | ForEach-Object { $_.cases } | Group-Object result | Select-Object Name, Count
```

统计报告结论与覆盖：

```powershell
Get-ChildItem "projects\*\reports\*.json" -File |
  ForEach-Object { Get-Content $_.FullName -Raw | ConvertFrom-Json } |
  Group-Object outcome | Select-Object Name, Count
```

统计证据大小与截断（`evidence` 与 `generated` 都要计入）：

```powershell
$evidence = Get-ChildItem "projects\*\runs\*\evidence" -Recurse -File -ErrorAction SilentlyContinue
$generated = Get-ChildItem "projects\*\runs\*\generated" -Recurse -File -ErrorAction SilentlyContinue
$all = @($evidence) + @($generated)
[pscustomobject]@{
  Files = $all.Count
  MB = [math]::Round((($all | Measure-Object Length -Sum).Sum) / 1MB, 1)
  Truncated = ($evidence | Where-Object Name -like "*.truncated").Count
}
```

统计 AI 未生成与 Mock 未判定（`analysis` 是数组，要展平后逐条统计）：

```powershell
$analysis = $data | ForEach-Object { $_.analysis } | Where-Object { $_ }
$analysis | Where-Object { $_.status -ne "generated" } | Measure-Object
$data | ForEach-Object { $_.mock_judgement } |
  Where-Object { $_.kind -eq "unknown" } | Measure-Object
```

验收登记通过率单独统计，不与运行通过率混用：

```powershell
$status = Get-Content "tests\acceptance\p1\status.json" -Raw | ConvertFrom-Json
$status.results | Group-Object result | Select-Object Name, Count
```

- 当前验收状态见 `tests/acceptance/p1/status.json`：27/27 `verified`，其中 26 条 `real_cli`、1 条 `real_trae_panel`（P1-AC02）；AC09/AC12 为 2026-11-18 当前代码证据。不能据此写成“产品通过率”。
- 真实 Trae 面板页面证据另有 `tests/acceptance/p1/evidence/2026-11-17-trae-panel/` 与 `2026-11-17-trae-panel-v2/`，覆盖目标选择、计划、结果、报告、历史、问题、设置等页面；除 AC02 外这些截图未登记为 AC 证据。统计时先区分“AC 证据”和“面板页面证据”，不要把页面截图数量当成 AC 通过数。
- 运行通过率只反映已执行范围；未选验收项不属于本次范围，不进入分母。

## 4 报告节奏

- **按批次**：每完成一次验证（本地闭环、真实宿主、适配器、备份恢复）更新 `tests/acceptance/p1/status.json`，附本次证据位置。
- **按里程碑**：M0—M4 各汇总一次，口径见[交付计划](../01-项目/03-交付计划.md)第 4 节。
- **发布前**：汇总运行数、结论分布、证据占用、AI 未生成数、未验证项；不写“趋势向好”之类无依据结论。
- 记录必须包含：批次名、提交、版本、命令或界面动作、范围、指标值、证据路径、未验证原因。

## 5 不采集什么

| 不采集 | 原因 |
| --- | --- |
| 功能点击、活跃时长、使用频率 | 无遥测实现，也不需要 |
| 机器名、用户名、绝对路径清单 | 与效果无关，且属于环境信息 |
| 崩溃自动上报、后台心跳 | 无上报端点与账号 |
| 被抓取源码全文、提示词与模型响应全文 | 只作为本地执行材料，不作指标原料 |
| 密钥、token、连接串 | 落盘前过滤，指标不引用正文 |
| 第三方统计 SDK | 面板与扩展不引入分析依赖 |

## 6 限制

- 没有实时看板、没有指标服务；所有数字靠本地脚本或人工读取。
- 没有自动聚合跨项目数据；需要汇总时由维护者导出后人工合并。
- `run.json` 没有独立结束时间字段，耗时统计以 `started_at` 与文件时间为近似，报告时要注明口径。
- 指标只描述“运行与证据”，不描述“业务正确性”；业务结论仍以 `report.outcome` 与验收登记为准。

## 7 汇报模板

```text
批次：<名称>    提交：<sha>    版本：<version>
运行数：N（completed/cancelled/interrupted/execution_error）
结论：passed N / failed N / incomplete N / not_applicable N
覆盖：selected N / applicable M；未覆盖清单见报告
证据：X 个文件，Y MB（evidence + generated）；截断 Z 个
AI：未生成 N 次；Mock unknown N 条；manual_pending N 条
未验证：<缺什么>
```

- 空分母写“无数据”，不写 100%。
- 失败与阻塞逐条给原因与证据位置，不用“基本通过”概括。
- 指标与验收登记冲突时，先核对 `status.json` 与证据，再改汇报。
