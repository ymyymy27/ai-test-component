## 1 发布单元

| 单元 | 来源 | 构建方式 | 产物 | 说明 |
| --- | --- | --- | --- | --- |
| 核心 wheel | `src/aitest/` | `uv build` | `dist/ai_test_component-<版本>-py3-none-any.whl` | 含 Python 包与模板 JSON；不含面板 |
| 源码包 | 仓库 | `uv build` | `dist/ai_test_component-<版本>.tar.gz` | 只作源码留档 |
| 共享面板 | `panel/` | `npm run build` | `panel/dist/index.html` 与 `assets/*` | 复制到 `integrations/trae/media/panel/`，随 VSIX 发布 |
| Trae 扩展 | `integrations/trae/` | `npm run package` | `integrations/trae/dist/aitest-trae.vsix` | 扩展入口 + 面板资源 + 运行时 wheel + 命令声明 |
| 校验清单 | 发布人 | `sha256sum` | `SHA256SUMS` | 记录 wheel 与 VSIX 摘要 |

- 发布对象是**同一提交构建**的 wheel、VSIX 与文档；旧 `dist/` 目录里的文件不构成发布依据。
- `dist/` 内非本次构建的旧产物（如 0.4.10）不得作为本次发布物。
- wheel 内容由 `pyproject.toml` 的 `[tool.hatch.build] include` 决定：`src/aitest/**/*.py` 与 `src/aitest/resources/templates/**/*.json`；面板不在 wheel 内。改打包配置属于发布变更，必须整体重建。
- 共享面板只有一份源码；扩展侧面板由 `integrations/trae/scripts/build.mjs` 从 `panel/dist` 整体复制到 `media/panel`，发布前核对两边文件清单与摘要一致。
- VSIX 内置 wheel 与便携运行时安装脚本；首次使用自动发现 Python，找不到时下载便携 Python 并用 VSIX 自带 wheel 离线安装。

## 2 版本一致性

版本以 `pyproject.toml` 为基线，以下位置必须完全一致：

| 位置 | 作用 | 当前值 |
| --- | --- | --- |
| `pyproject.toml` `project.version` | 产品版本基线 | 0.5.0 |
| `src/aitest/__init__.py` `__version__` | 核心自报版本 | 0.5.0 |
| `panel/package.json` 与 `package-lock.json` | 面板版本 | 0.5.0 |
| `integrations/trae/package.json` 与 `package-lock.json` | 扩展版本 | 0.5.0 |

```bash
uv run python scripts/check_versions.py
uv run python scripts/check_versions.py v0.5.0   # 打标签前核对标签
```

- 任一位置不一致即停止发布，不用“只差文档版本”放行。
- 发布标签必须是 `v<版本>`，且标签提交已合入 `main`；从功能分支或未合并提交打标签会被拒绝。
- 版本号变更要同步 wheel、VSIX、文档与发布说明；旧产物不能改名为新版本。

## 3 安装前置

| 项 | 要求 | 缺失后果 |
| --- | --- | --- |
| 操作系统 | Windows 11 x64 | 其他系统未验证 |
| Python | 3.11 及以上、低于 3.14；建议 3.13 | 扩展先尝试自动准备便携运行时；失败才提示 `PYTHON_NOT_FOUND` |
| Python 包 | 用户 Python 或便携运行时中可 `import` 本版本 | 自动准备失败则 bridge 调用失败，面板无数据 |
| Trae | 支持 VS Code 扩展接口 1.85 及以上 | 扩展无法激活或面板不显示 |
| 工作空间 | 用户目录，不能是源码或安装目录；默认 `%APPDATA%/aitest/workspaces/default` | 目录不可写时报错 |
| 磁盘 | 业务数据、证据与备份留足空间 | 写入失败 `DISK_FULL`，不驱逐旧证据 |
| 模型密钥 | 环境变量或用户级配置 | AI 步骤不可用，本地记录与报告仍可用 |
| `gh` | GitHub 关联需要，且已登录 | `GITHUB_UNAVAILABLE`，本地测试不受影响 |
| Node/npm | 仅从源码构建时需要 | 不影响已安装插件运行 |

- 模型不是核心测试前置：只有 AI 功能（目标候选、用例生成、分析等）需要模型；本地执行、证据与报告不依赖模型。
- GitHub 是一期关联能力，不是运行前置；`gh` 缺失或未登录只影响 GitHub 关联，本地测试继续。

## 4 构建顺序与命令

顺序固定：**面板 → wheel / VSIX → 校验**。面板构建产物会被复制进 VSIX，先打包 VSIX 再改面板会让 VSIX 内面板过期。

```bash
git status --short
uv sync --extra dev --locked
uv run python scripts/check_versions.py
uv run ruff check .
uv run mypy
uv run pytest

npm --prefix panel ci
npm --prefix panel run build

npm --prefix integrations/trae ci
npm --prefix integrations/trae run package

uv build
sha256sum dist/*.whl integrations/trae/dist/*.vsix
```

| 检查 | 看什么 | 失败处理 |
| --- | --- | --- |
| 版本 | `check_versions.py` 退出 0 | 改版本或停发 |
| 静态检查 | `ruff`、`mypy` 退出 0 | 修代码，不带病发布 |
| 测试 | `pytest` 退出 0；未跑完写“未跑完” | 不用历史结果冒充本次 |
| 面板 | `panel/dist/index.html` 与 `assets/*` 生成成功 | 先修构建，不手改产物 |
| VSIX | `dist/aitest-trae.vsix` 生成且含 `media/panel/index.html`、`media/panel/assets/*`、`media/runtime/*.whl` | 检查扩展打包配置 |
| wheel | 含 Python 包与 `templates/` JSON，不含面板 | 检查 hatch include |
| wheel 一致性 | VSIX 内 `media/runtime/ai_test_component-*.whl` 的 sha256 必须等于 `dist/` 下同版本 wheel | 不同即停发，重新用同一 wheel 打包 |

- `pytest` 全量较慢时按批次跑，记录命令、批次与退出码；不以分块数字相加冒充全量。
- 2026-11-21 自动化基线：后端 pytest 357 个节点、面板 vitest 121 项、扩展 node test 94 项；这些结果只说明对应层通过，不替代真实 Trae、试点项目或平台对拍。
- `check_docs_facts.py` 扫 `AGENTS.md`、根 `README.md` 与代码事实；发布前必须清零或明确记录为已知缺口。
- 构建产物不提交仓库；每次发布重新构建并附摘要。

## 5 安装与升级

```powershell
py -3.13 -m venv C:\aitest\venv
C:\aitest\venv\Scripts\python.exe -m pip install C:\aitest\pkg\ai_test_component-0.5.0-py3-none-any.whl
C:\aitest\venv\Scripts\python.exe -c "import aitest; print(aitest.__version__)"
```

1. 在 Trae 中“从 VSIX 安装”选择 `integrations/trae/dist/aitest-trae.vsix`，重载窗口；首次使用会自动准备便携运行时。
2. 如需指定解释器，设置 `aitest.pythonPath`；`aitest.workspacePath` 可选，默认 `%APPDATA%/aitest/workspaces/default`。
3. 运行 `aitest doctor`，确认 Python、包、模型、`gh`、工作空间状态；`model.ok=false` 不阻止本地记录。
4. 升级时替换 wheel 与 VSIX，重启 Trae；旧工作空间数据不随升级删除，但旧 `schema_version` 可能被拒绝。
5. 升级前先按[备份与恢复预案](02-备份与恢复预案.md)创建 zip 并记录摘要。

- 扩展找不到合格 Python 时会自动准备便携运行时并用 VSIX 自带 wheel 安装；任一步失败即停并显示阶段与原因，不静默改用其他解释器。
- 升级只替换 wheel 与 VSIX，不迁移旧格式；旧格式只提示重建或重新生成，没有自动转换工具。

## 6 回滚

回滚是**版本回滚**，不是数据回滚：

1. 保留上一版 wheel、VSIX 与 `SHA256SUMS` 到工作空间之外的目录，文件名带版本号。
2. 回滚前确认没有活动运行；有运行先等待完成或取消，不直接结束 worker 进程。
3. 卸载新 wheel，安装上一版 wheel；卸载新 VSIX，安装上一版 VSIX；重启 Trae。
4. 若新版本已写入新 `schema_version`，旧版本可能读不出；此时不要覆盖原工作空间，改用发布前备份恢复到**新的空目录**。
5. 记录回滚时间、版本、命令、失败现象与证据位置，写入运行记录与 `tests/acceptance/p1/evidence/<批次>/`；`status.json` 只更新对应 AC 的 `evidence.path`。

- 没有自动回滚脚本，也没有“一键降级”；回滚由人执行并留痕。
- 备份能救数据，救不回已写入的新结构；重装能换回旧二进制，不能把旧记录变回可读。

## 7 不发布条件

出现任一条即停止发布：

1. 版本四处不一致，或标签不是 `v<版本>`，或标签提交不是 `main` 的祖先。
2. wheel、VSIX 与面板不是同一提交构建；VSIX 内 `media/panel` 与 `panel/dist` 文件清单/摘要不一致且未说明。
3. `ruff`、`mypy`、`pytest` 有未定位失败，或全量未跑完却写“通过”。
4. 发布说明把单测、文档一致、面板能打开写成真实 Trae 验收或 AC 通过。
5. 没有发布前备份，或上一版产物缺失导致无法回滚。
6. 旧工作空间格式高于本次可读范围，且没有可校验备份。
