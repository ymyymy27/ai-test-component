# 发布方案

本文件定义 0.4.x 本地预览的**发布单元、门禁命令、构建顺序与不发布条件**。它不登记验收结论：CI 通过、`verify_artifacts.py` 通过、隔离安装通过都只证明**产物可复核**，不证明任一 P1-AC 已通过。当前状态与未验证边界只以[项目现状](../../../现状.md)和[tests/acceptance/p1/status.json](../../../../tests/acceptance/p1/status.json)为准。

发布对象是**同一提交构建的三个产物**（核心 wheel、Trae VSIX、共享面板字节），不是某台机器上的 `dist/` 目录内容。任何"上次构建过"的目录都不构成本次发布依据。

## 1 发布单元

| 单元 | 来源 | 构建方式 | 分发形态 | 与其他单元的关系 |
| --- | --- | --- | --- | --- |
| 核心 wheel | `src/aitest/` | `uv build` | `dist/ai_test_component-<版本>-py3-none-any.whl` | 内含面板 `dist/index.js`、6 个模板 JSON、生成 Schema |
| 源码包 sdist | 仓库 | `uv build` | `dist/ai_test_component-<版本>.tar.gz` | 只作源码留档，不作推荐安装物 |
| Trae 扩展 VSIX | `integrations/trae/` | `npm run package` | `integrations/trae/dist/aitest-trae.vsix` | 内含 `extension/dist/panel.js`，必须与核心面板同字节 |
| 共享面板 | `src/aitest/resources/panel/` | `npm run build` | `dist/index.js` | 无独立发行渠道，只随上面两个单元发布 |
| 发布附件 | CI 生成 | `sha256sum` / `verify_artifacts.py` | `SHA256SUMS`、`docs/validation/artifacts.json` | 记录摘要与检查范围，不是安装物 |

- 面板只有一份源码：`integrations/trae/scripts/build.mjs` 直接复制 `src/aitest/resources/panel/dist/index.js` 为 `dist/panel.js`，扩展侧不留第二份面板源码。
- `pyproject.toml` 的 `[tool.hatch.build] include` 决定 wheel 内容（`**/*.py`、模板 JSON、`contracts/schemas/*.json`、`resources/panel/dist/*.js`）；打包配置改动属于发布变更，必须重跑本文件第 3 节全部命令。
- `dist/`、`*.vsix`、`docs/validation/artifacts.json` 均被 `.gitignore` 忽略：**发布物不靠仓库保存**，每次发布都要重新构建并附摘要。

## 2 版本与门禁（真实命令）

版本以后四项为准，任何一处不一致即阻塞（`scripts/check_versions.py` 会拒绝）：

| 位置 | 当前值 | 作用 |
| --- | --- | --- |
| `pyproject.toml` `project.version` | `0.4.10` | **版本基线，以文件为准** |
| `src/aitest/__init__.py` `__version__` | `0.4.10` | 核心自报版本 |
| `src/aitest/resources/panel/package.json` 与 `package-lock.json` | `0.4.10` | 面板锁版本 |
| `integrations/trae/package.json` 与 `package-lock.json` | `0.4.10` | 扩展锁版本 |

| 门禁层级 | 触发条件 | 实际执行内容 | 缺什么就停 |
| --- | --- | --- | --- |
| 提交/PR 检查 | 推送或 PR 到 `main`/`develop`、手动、被 Release 调用 | `basic-checks`（windows-latest，Python 3.13，20 分钟上限） | 任一命令非零退出、Schema 有 diff、动作数/节点数与文档不符 |
| 夜间全量 | 每日计划任务或手动指定 ref | 全量 `pytest`，`-n 8 --dist loadfile`，6 小时上限 | 未跑完或出现失败，不得用分块结果相加代替 |
| 版本标签构建 | 推送 `v*` 标签 | 构建面板与 VSIX、`uv build`、制品核对、隔离冒烟、上传 `skeleton-windows-latest` | 任一制品缺失或核对失败 |
| 发布草稿 | 标签构建成功 | 生成 `SHA256SUMS`，`gh release create --draft` | 未人工审核即视为未发布 |

`basic-checks` 的实际命令（[.github/workflows/ci.yml](../../../../.github/workflows/ci.yml)）：

```powershell
uv sync --extra dev --locked
uv run python scripts/check_versions.py
uv run ruff check .
uv run mypy
uv run python scripts/generate_schemas.py
# 之后核对 git status --porcelain --untracked-files=all -- src/aitest/contracts/schemas 必须为空
uv run python scripts/check_docs_facts.py
uv run pytest --collect-only -q
uv run pytest tests/contracts tests/architecture tests/recovery tests/acceptance tests/integration `
  tests/unit/test_bounded_query_directory.py tests/unit/test_review_decision.py `
  tests/unit/test_query_material_identity.py tests/unit/test_finite_query_routes.py `
  tests/unit/test_query_spec_bridge.py tests/unit/test_reporting_application.py `
  tests/unit/test_saved_reports.py tests/unit/test_panel_view_dto.py `
  tests/unit/test_sharded_record_authority.py tests/unit/test_source_identity_runtime_observation.py
```

版本标签门禁（[.github/workflows/release.yml](../../../../.github/workflows/release.yml)）：`scripts/check_versions.py "$TAG"` 要求标签等于 `v<版本>`，且 `git merge-base --is-ancestor HEAD origin/main` 成立——**标签提交必须是 `origin/main` 上的提交**，从功能分支或未合并提交打标签会被拒绝。

门禁**不覆盖**的部分（发布说明必须原样保留）：

- 面板 Playwright 测试（`npm --prefix src/aitest/resources/panel test`）与扩展 `node --test` 不在任何 CI 作业中执行。
- 夜间全量是定时任务，标签构建只跑有界子集；"今天 CI 绿"不等于"当前提交跑过全量"。
- 没有真实 Trae、其他编辑器、物理掉电、跨机恢复或三期平台对拍的自动化门禁。

## 3 构建与字节核对

顺序不可交换：面板 → VSIX → wheel → 核对 → 冒烟。`verify_artifacts.py` 断言 wheel 与 VSIX 里的面板字节**同时**等于 `src/aitest/resources/panel/dist/index.js`，先 `uv build` 再改面板会让 wheel 过期。

```powershell
git status --short
uv sync --extra dev --locked --python 3.13
uv run python scripts/check_versions.py v0.4.10
npm --prefix src/aitest/resources/panel ci
npm --prefix src/aitest/resources/panel run build
npm --prefix integrations/trae ci
npm --prefix integrations/trae run package
uv build
uv run python scripts/verify_artifacts.py
uv run python scripts/smoke_wheel.py
```

| 检查 | 脚本断言的实际内容 | 失败含义 |
| --- | --- | --- |
| wheel 模板 | `templates/` 下正好 6 个 `.json` | 打包 include 漏项或模板增删未同步 |
| wheel Schema | 含 `aitest/contracts/schemas/Command.json` | 生成 Schema 未入包 |
| wheel 杂质 | 不含 `node_modules`、不以 `ai_test/` 开头 | 打包路径写错，装出重复模块树 |
| 面板字节 | wheel、VSIX、源码三处 `index.js` 完全相同 | 有构件过期，必须按上面的顺序整体重建 |
| 摘要记录 | 写 `docs/validation/artifacts.json`，含两件产物 sha256 | 未留发布摘要，不得对外分发 |

`verify_artifacts.py` 自己登记的范围是 `artifact_contents_and_shared_panel_identity_only`——它只证明**内容与面板同一性**，不证明功能、兼容性或验收。`smoke_wheel.py` 在仓库外的临时 venv（Python 3.13）安装 wheel 后要求：`templates` 退出 0 且返回 6 项、`doctor` 退出 2 且状态为 `NOT_READY`、`mcp-relay --binding smoke` 退出 2 且错误码为 `CAPABILITY_UNAVAILABLE`；任一不符即失败。

## 4 安装与回滚

安装（详见[安装与操作说明](03-安装与操作说明.md)）：

```powershell
py -3.13 -m venv C:\aitest\venv
C:\aitest\venv\Scripts\python.exe -m pip install dist\ai_test_component-0.4.10-py3-none-any.whl
C:\aitest\venv\Scripts\python.exe -m aitest.interfaces.tools.cli templates
C:\aitest\venv\Scripts\python.exe -m aitest.interfaces.tools.cli doctor
```

- `doctor` 无工作空间时返回退出码 2 与状态 `NOT_READY` 是**预期行为**，不是安装失败。
- VSIX 通过编辑器"从 VSIX 安装"侧载；扩展的 `aitest.pythonPath` 必须指向已装该 wheel 的解释器：首次配置向导以 `-I` 隔离模式运行，把源码目录加进环境变量不能替代安装。

回滚（**版本回滚，不是数据回滚**）：

1. 保留上一版 wheel、VSIX 与 `SHA256SUMS` 到工作空间之外的目录，命名含版本号。
2. 回滚前先确认没有活动执行。仓库没有单独的"停止核心"子命令，`restart-core` 会在停机后立刻启动新实例，不能当作关机使用；关闭编辑器并等核心退出后，再卸载新版本 wheel、卸载扩展并安装上一版，不要强杀进程。
3. 若新版本已写入新记录，降级后**不保证可读**：结构迁移只前向，禁止丢弃式回滚。此时保留现工作空间原状，改为在**新目录**用发布前备份恢复（见[备份与恢复预案](02-备份与恢复预案.md)）。
4. 仓库没有自动回滚脚本或降级入口，回滚是人工操作并需记录命令、版本与摘要。

## 5 渠道与灰度

| 项 | 当前事实 |
| --- | --- |
| 灰度/分批 | **无**。没有灰度、分批或按比例放量的机制，也没有开关控制新旧版本共存 |
| 分发方式 | 本地侧载：本机安装 wheel + 从 VSIX 文件安装扩展 |
| GitHub Release | 由标签触发，产物为 **draft**，需人工审核后发布；不发布到 PyPI，不发布到任何扩展市场 |
| 扩展标识 | `publisher: aitest-local`、`private: true`，打包参数 `--allow-missing-repository --skip-license` |
| 试用范围 | 同一 VSIX + 各自独立的用户数据工作空间；一个工作空间只允许一个核心进程持写锁 |
| 回滚渠道 | 保存上一版分发包副本，按第 4 节人工回滚 |

## 6 发布检查单

勾选项表示"本次发布已满足"，未勾选即不发布；本文件不预先勾选任何一项。

- [ ] `pyproject.toml`、`__version__`、两个 `package.json` 与 `package-lock.json` 版本一致
- [ ] `git status --short` 无业务未提交改动；他人的未提交成果已保留
- [ ] 待发布提交已合入 `main`，标签为 `v<版本>` 且通过 `check_versions.py v<版本>`
- [ ] `basic-checks` 在待发布提交上通过（ruff、mypy、Schema 无 diff、文档事实检查、bounded pytest）
- [ ] 夜间全量在待发布提交（或其后仅文档改动的提交）上有单次完整运行记录与退出码
- [ ] 面板 `ci`/`build`、扩展 `ci`/`package`、`uv build` 按第 3 节顺序在同一提交完成
- [ ] `verify_artifacts.py` 通过，`docs/validation/artifacts.json` 已生成并含两件产物 sha256
- [ ] `smoke_wheel.py` 在隔离 venv 通过
- [ ] 发布前备份已演练（见备份与恢复预案第 6 节）
- [ ] 上一版 wheel、VSIX 与 `SHA256SUMS` 已留档，回滚步骤可执行
- [ ] 发布说明写明：CI 通过不等于一期业务验收或真实 Trae 兼容；已知未验证项按[项目现状](../../../现状.md)列出
- [ ] `CHANGELOG.md` 与实际版本、构建结果一致，未把旧版本结论当作本次结论

## 7 不发布条件

出现任一条即停止发布，且不得用"文档一致""单测通过""夹具通过"抵消：

1. 四处版本号不一致，或标签不等于 `v<版本>`，或标签提交不是 `origin/main` 的祖先。
2. 三个产物不是同一提交构建；`verify_artifacts.py` 或 `smoke_wheel.py` 任一失败（含面板字节不一致）。
3. `generate_schemas.py` 产生 diff 而未提交，或生成物被手工编辑。
4. 全量回归未跑完、有失败未定位，或用历史分块数字相加冒充全量通过。
5. 未做发布前备份演练，或上一版分发包缺失导致无法回滚。
6. 发布说明把组件证据、接口 frozen、面板 Playwright 通过写成业务验收或真实宿主通过。
7. 数据兼容性未知：已有工作空间的结构版本高于本次发布可读范围，且没有可校验备份。
