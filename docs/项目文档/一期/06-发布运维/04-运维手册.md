# 运维手册

> 状态：2026-11-16 轻量插件基线，2026-11-17 按代码事实核对。完整宿主闭环与试点项目待验证。

本手册面向维护者：工作空间在哪、日志看什么、锁与中断怎么处理、磁盘不足怎么办。产品没有常驻服务与集中日志系统，排障以文件与 CLI 输出为主；未验证边界以 `tests/acceptance/p1/status.json` 为准。2026-11-18 自动化基线为 pytest 265、面板 vitest 48、扩展 node test 48。

## 1 工作空间位置

- 默认位置为 `%APPDATA%/aitest/workspaces/default`；可用 `aitest.workspacePath` 改。目录不可写时才报错，不静默换目录。
- 项目仓库内不留插件数据；不要把工作空间指向源码、安装目录、网络盘或同步盘。

```text
workspace/
  workspace.json
  projects/<project_id>/
    project.json
    project.config.json
    tasks/<task_id>.json
    tasks/revisions/<task_id>/<revision>.json
    deliveries/<task_id>.json
    rules/<rules_version_id>.json
    plans/<plan_id>.json
    plans/revisions/<plan_id>/<revision>.json
    confirmations/<confirmation_id>.json
    github/<commit>.json
    runs/<run_id>/
      run.json
      plan.json
      task.json
      generated/
      evidence/
      manual/<case_id>.json
      link.json
      cancel.requested
      worker-error.txt
      service.log
      postprocess-error.txt
    issues/<issue_id>.json
    reports/<report_id>.json
  requests/<request_id+command+payload 的短哈希>.json
  actions/<yyyy-mm>.jsonl
  actions/doctor.jsonl
  .cache/mock/<key>.json
  backups/<timestamp>.zip
  .workspace.lock
```

- `workspace.json` 记录 `workspace_id` 与创建时间；项目移动后路径对不上时重新绑定，不自动猜。
- `requests/` 是幂等结果缓存，`.cache/mock/` 是 Mock 判定缓存，`backups/` 是用户备份，三者不参与业务记录。
- `actions/doctor.jsonl` 与环境修复相关，`actions/<yyyy-mm>.jsonl` 记录运行副作用与数据清理；它们是审计材料，不是业务状态。
- `runs/<run_id>/` 运行期由 worker 独占；CLI 只通过 `run.manual`/`evidence.add`/`analysis.run`/`run.cancel` 写运行目录，面板不直接写文件。

## 2 日志与诊断材料

产品不写滚动日志文件；CLI 成功与错误都向 stdout 输出一行 JSON，stderr 只承载诊断日志（`AITEST_LOG`）与未预期异常堆栈，不承载协议 JSON。

| 材料 | 位置 | 用途 |
| --- | --- | --- |
| CLI 错误 | stdout 一行 JSON 的 `error` 字段 | 命令失败原因与 `next_step`；不要只看 stderr |
| 扩展错误 | 面板提示或 bridge 返回 | 解释器、工作空间、超时、非法 JSON |
| 运行异常 | `runs/<id>/worker-error.txt` | worker 未捕获异常 |
| 后处理异常 | `runs/<id>/postprocess-error.txt` | 分析、问题草稿或报告生成失败 |
| 服务日志 | 单服务 `runs/<id>/service.log`；命名服务 `runs/<id>/service-<name>.log` | 启动/停止命令输出 |
| 用例输出 | `runs/<id>/evidence/*.log` | stdout/stderr，单文件 20MB 截断 |
| 诊断快照 | `doctor` 的 JSON | Python、包、模型来源、`gh`、工作空间 |
| 运行状态 | `run.json` 的 `status`、`heartbeat_at`、`pid` | 判断运行中、完成、取消、中断 |

- `run.status` 与 `run.list` 会刷新过期心跳；读它们比手动改 `run.json` 安全。
- 证据截断会额外写 `<name>.truncated`，记录原始字节数；预算耗尽被跳过的通过用例证据写 `<name>.skipped`，失败用例不会被跳过。
- 动作日志分两处：`actions/doctor.jsonl` 记录 doctor 与环境修复；`actions/<yyyy-mm>.jsonl` 记录运行副作用与 `data.cleanup`。没有滚动日志目录，不要按旧文档找 `logs/`。

## 3 锁

| 锁 | 位置 | 持有者 | 行为 |
| --- | --- | --- | --- |
| 工作空间锁 | `.workspace.lock` | 只有 `MUTATING` 且不在 `_SELF_LOCKED` 的 CLI 命令；`_SELF_LOCKED` 为 `run.start`、`run.manual`、`evidence.add`、`analysis.run`、`run.cancel` | `portalocker` 排他锁；CLI 外层默认等待 30 秒，内部 `ws.lock()` 默认 10 秒，模型/备份等命令有更长专用超时；只读命令不加锁 |
| 运行独占 | `runs/<run_id>/` | 运行期 worker；CLI 受控命令 | worker 独占执行写入；CLI 只通过 `run.manual`/`evidence.add`/`analysis.run`/`run.cancel` 写运行目录；面板不直接写文件 |
| 单项目单运行 | 由 `run.start` 检查 | 项目级 | 已有活动运行时返回 `RUN_ACTIVE` |

- `run.start`、`run.manual`、`evidence.add`、`analysis.run`、`run.cancel` 不进 CLI 外层加锁分支；前四个在内部调用 `ws.lock()`，`run.cancel` 只写运行目录标志；`data.cleanup` 走 CLI 外层锁。
- 锁文件残留不代表锁仍有效；进程退出后操作系统释放锁，下一次命令可接管。
- 不要手工删除 `.workspace.lock`；删除正在使用的锁文件可能让两个进程同时写入。
- `WORKSPACE_LOCKED` 时先确认是否有另一个 Trae 窗口或 CLI 正在运行；等待或关闭另一实例，不强杀。
- 同一项目第二个运行被 `RUN_ACTIVE` 拒绝，返回现有 `run_id`；不排队、不并发。

## 4 运行中断处理

```text
run.start → run.json(status=running, pid, heartbeat_at)
worker 每 3 秒刷新 heartbeat_at
run.status / run.list：
  status=running 且 PID 不在、心跳超过 5 秒 → interrupted；PID 存活不判死；无 PID 时 120 秒兜底
```

处理顺序：

1. 先读 `run.status`，不要直接编辑 `run.json`。
2. 看 `runs/<id>/worker-error.txt` 与 `service.log` / `service-<name>.log`；有证据先保留。
3. 已完成的用例结果与证据保留；未完成用例标 `not_run` 或保持原状态，不补造结果。
4. 确需重跑时，按验收项新建运行；旧运行完整保留，不覆盖。
5. 若只是关闭了 Trae，worker 仍可能继续；重开后用 `run.list` 查看，不要重复 `run.start`。

- 取消：`run.cancel` 写 `cancel.requested`；worker 在边界检查并终止正在执行的命令进程树，当前用例记阻塞，剩余用例 `not_run`，最终写 `cancelled`；worker 异常退出写 `execution_error`，被杀后由心跳接管标 `interrupted`。
- 中断不会自动重跑；未知副作用不重放。
- PID 不在且心跳超过 5 秒即接管；PID 存活时不因心跳单独判死；无 PID 时才用 120 秒兜底。

## 5 磁盘不足与容量

- 业务 JSON 写入失败时，`storage/files.py` 映射 `DISK_FULL`，提示检查磁盘空间与权限。
- 证据文件直接写字节，磁盘满时可能表现为 worker `execution_error` 并留下 `worker-error.txt`，或 CLI 退出 2；不一定统一成 `DISK_FULL`。
- 磁盘不足时停止写入，不驱逐已有证据；不要为了腾空间删除失败用例证据。
- 可清理项：旧备份、`requests/` 缓存、用户明确不要的运行目录；清理前先备份并记录。
- 不可自动清理：证据、报告、问题、运行记录；产品没有自动回收策略。
- 单文件 20MB 截断；单次运行媒体软上限 500MB；视频默认关闭。超限顺序为：通过用例截图只留最后一张 → 跳过通过用例的新证据 → 失败用例证据不跳过；没有“压缩截图”步骤。

日常容量检查：

```powershell
Get-ChildItem "C:\aitest\data" -Recurse -File |
  Measure-Object -Property Length -Sum |
  Select-Object Count, @{n='MB';e={[math]::Round($_.Sum/1MB,1)}}
```

## 6 升级、回滚与数据

1. 升级前创建备份并记录 sha256；确认没有活动运行。
2. 替换 wheel 与 VSIX，重启 Trae；工作空间数据不随升级删除。
3. 旧 `schema_version` 会被命令拒绝并提示转换或重建；不自动迁移。
4. 回滚只换二进制，不保证读出新格式；需要旧数据时从备份恢复到新的空目录。
5. 升级或回滚后核对：项目能读、运行列表能读、报告证据引用是否存在。

## 7 可选维护检查

- 每天/每次使用前：工作空间可写；`doctor` 的 Python 与包状态正常；模型密钥来源符合预期。
- 每次运行前：没有同项目活动运行；磁盘余量足够；服务配置与日志路径正确。
- 每次运行后：`run.json` 状态与报告一致；证据引用可打开；失败/阻塞有原因。
- 需要时：统计运行数、失败数、证据占用；清理不再需要的旧备份（保留最近一份）。
- 每次发布前：按[发布方案](01-发布方案.md)与[备份与恢复预案](02-备份与恢复预案.md)执行检查与演练。
