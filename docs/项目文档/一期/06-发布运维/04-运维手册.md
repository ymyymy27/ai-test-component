# 一期 · 运维手册

- 适用版本：0.4.10（`pyproject.toml` 当前版本）；适用系统：Windows 11 x64，Python 3.11+。
- 事实源：`src/aitest/interfaces/tools/cli.py`、`src/aitest/bootstrap.py`、`src/aitest/infrastructure/file_store/`、`integrations/trae/README.md`、`.github/workflows/`。
- 现状与未验证边界以[项目现状](../../../现状.md)为准，本手册不复制问题清单。

## 1 运行拓扑

```text
Trae 薄扩展（webview 面板）┐
CLI `aitest`               ├──> 一个本地核心进程（每工作空间一个）──> 工作空间文件
stdio MCP relay            ┘        持有 writer.lock 生命周期排他锁
```

- 核心由宿主启动（`ensure-core`/面板连接），入口间不各自写业务文件；业务变更只在核心内提交。
- 核心与入口之间是 Windows 命名管道 `\\.\pipe\aitest/<workspace_id>/session-<n>/<instance_id>`，**不监听 TCP 端口、不提供本地 HTTP 服务**，也没有数据库、消息队列或独立发送 Worker。
- 有活动执行或可推进的执行时，核心脱离宿主保活；退出判据见[Trae 接入第 6 节](../04-架构/06-Trae接入.md#6-核心保活与退出)。断开编辑器不会伪造取消。
- 第二个入口只能接同一核心或被明确拒绝（`WORKSPACE_IN_USE`），不产生第二写入者。

| 项 | 位置/命令 |

| Python 包（wheel） | `dist/ai_test_component-0.4.10-py3-none-any.whl`（同目录含 `.tar.gz`） |

| 共享面板源码 | `src/aitest/resources/panel`，`npm ci` + `npm run build` |
| Trae 扩展 | `integrations/trae`，`npm ci` + `npm run package` → `integrations/trae/dist/aitest-trae.vsix` |
| 扩展配置项 | `aitest.workspaceRoot`、`aitest.projectId`、`aitest.runId`、`aitest.pythonPath`、`aitest.modelConfigurationFile`、`aitest.businessQueriesFile`、`aitest.pythonCarriersFile` |
| 扩展命令 | `AI Test: 配置工作空间与项目`、`AI Test: 打开测试面板` |
| 宿主环境变量 | `AITEST_PYTHON_CARRIERS`、`AITEST_BUSINESS_QUERIES`、`AITEST_MODEL_CONFIGURATION`、`AITEST_MIGRATION_BACKUP_ROOT` |

工作空间是用户自选的**专用本地目录**，不得是安装目录或被测源码目录；网络盘、同步盘（OneDrive/Dropbox 等）以 `WORKSPACE_LOCATION_REJECTED` 拒绝，路径链上的符号链接与 junction 一律拒绝。一个工作空间属单个 OS 用户。

| 目录/文件 | 写入者 | 说明 |
| --- | --- | --- |
| `workspace.json` | 核心 | `workspace_id`、`schema_version`、`writer_epoch`；损坏即拒绝启动 |
| `writer.lock` | 核心 | 生命周期排他锁载体；存在不代表锁有效 |
| `.core-instance-id` | 启动器 | 当前实例发现指针 |
| `core/launch.json`、`core/launch.lock`、`core/launch-history/` | 启动器 | 启动事实与启动互斥；状态含 creating/created/stopping/exited 等 |
| `core/startup-diagnostic.json` | 核心 | 启动失败结论，脱敏且 ≤4096 字符 |
| `core/connection-ledger.jsonl` | 核心 | 不可变连接台账，跨重启可核对 |
| `records.json`、`record-store/`、`manifests/`、`current.json` | 核心 | 权威记录与不可变提交材料 |
| `objects/<project>/<sha256>` | 核心 | 证据对象；落盘前已过滤凭据 |

| `checkpoints/`、`transactions/` | 核心 | Attempt 恢复检查点、活动标记与幂等结果 |
| `event-log/`、`events/` | 核心 | 已提交事件与有序事件页 |
| `indexes/`、`record-store/` | 核心 | 可分片重建的查询投影 |
| `diagnostics/recovery/` | 核心 | 恢复结论（`healthy/repaired/blocked`） |
| `maintenance/audit.jsonl` | 核心 | 备份、迁移、回收审计 |
| `migrations/` | 核心 | 迁移计划、步骤检查点、迁移前备份 |

上述目录均由运行时创建；安装包与 `src/` 中不存放任何业务记录、证据或诊断。

## 3 启动、停止、重启与诊断命令

控制台脚本为 `aitest`，与 `python -m aitest.interfaces.tools.cli` 等价。所有子命令成功退出 0，失败退出 2 并输出带 `code`/`message` 的结构化结论；不同子命令写 stdout 或 stderr 不统一（如 `ensure-core` 错误写 stderr，`restart-core` 错误写 stdout），采集时两者都保留。

| 命令 | 用途 | 失败表现 |
| --- | --- | --- |
| `aitest templates` | 列出内置模板版本 | 读不到资源即异常退出 |
| `aitest doctor` | 离线诊断，不启动核心 | 返回 `NOT_READY`，退出 2 |
| `aitest doctor --workspace <目录>` | 连既有核心取状态 | 无核心时 `CLI_INPUT_OR_CONNECTION_UNVERIFIED` |
| `aitest ensure-core --workspace <目录>` | 发现或启动唯一核心并核对身份 | `WORKSPACE_NOT_FOUND`、`CORE_UNAVAILABLE`（附 `startup_diagnostic_path`） |
| `aitest restart-core --workspace <目录>` | 优雅停机后启动并核对新实例 | `CORE_RESTART_BLOCKED`（活动执行未排空）、`CORE_RESTART_FAILED` |
| `aitest rebuild-index --workspace <目录>` | 核心未运行时按权威边界重建查询索引 | 核心在跑时 `WORKSPACE_IN_USE` |
| `aitest dispatch --workspace <目录>` | 从 stdin 读一条完整 Command JSON 派发 | 输入或连接不可核实即拒绝，不自动换号重跑 |
| `aitest mcp-relay --binding <绑定ID> [--workspace] [--project]` | stdio MCP 诊断与有限查询 | 上下文或核心不可用时退出 2 |
| `aitest python-carrier --project ... --environment ... --python ... --base-python ... --venv-root ... --dependencies ...` | 生成宿主 Python 载体登记 JSON，不执行 | 路径或解释器不合规返回 `INVALID_ENVIRONMENT_CONFIGURATION` |

- `dispatch` 的写动作必须带 `project_id`、`intent_id`、`expected_revision`；`request_id` 不能当 `intent_id` 用。取消或结果未知时保留原意图核对。
- `read_view` **不是 CLI 子命令**，它是 `mcp-relay` 暴露的只读 MCP 工具 `aitest_read_view`。
- 备份与迁移不是 CLI 子命令，是 `dispatch` 的 `backup`（`create`/`inspect`/`restore`）与 `migrate`（`inspect`/`plan`/`apply`/`resume`/`rollback`）动作，须在受控交互会话中执行，stdin 中继会话一律拒绝。
- 不要用强杀进程代替停止：`restart-core` 会先请求活动核心优雅停机，排空失败即明确拒绝。

## 4 日志与证据位置

本产品**不写滚动日志文件**，核心 stderr 被父进程置为 `DEVNULL`；排障只能读结构化诊断与永久材料，不要期望 `logs/` 目录。

| 材料 | 位置 | 读法 |
| --- | --- | --- |
| 启动失败结论 | `core/startup-diagnostic.json` | `doctor`/`ensure-core` 失败的 stderr 中已带内容与路径 |
| 连接事实 | `core/connection-ledger.jsonl` | 每行一条不可变事实，按 seq 读最后一条 |
| 恢复结论 | `diagnostics/recovery/<digest>.json` | 启动恢复与显式完整检查的结果 |
| 维护审计 | `maintenance/audit.jsonl` | 备份、迁移、回收的实际位置与清单摘要 |
| 已提交事件 | `event-log/journal.jsonl`、`event-log/pages/` | 通过 `events` 动作读取，不手工拼接 |
| 执行输出块 | `spool/<attempt_id>/` | 由核心封口后成为证据，不按时间清理 |
| 证据与导出 | `objects/`、`exports/`、`reports/` | 按引用读取；列表读摘要，详情按引用 |
| CI 结果 | Actions artifact `pytest-windows`、`pytest-full-windows`（JUnit XML，保留 14 天） | CI 基本检查/夜间全量 |

诊断与维护材料同属永久材料，不提供"一键清理"；`spool/` 与 `workdirs/` 永不进入回收扫描。

## 5 常见故障分类与处置

| 类别 | 典型信号 | 处置 |
| --- | --- | --- |
| 连接失败 | `CORE_UNAVAILABLE`、`CLI_INPUT_OR_CONNECTION_UNVERIFIED`、面板一直"未连接" | 核 `.core-instance-id` 与 `core/launch.json` 状态、`connection-ledger` 最后一条；确认扩展配置的工作空间路径对 Trae 进程可见；不要删锁文件 |
| 核心未就绪 | `ensure-core` 等待约 5 秒后失败，stderr 带 `startup_diagnostic` | 读 `core/startup-diagnostic.json`；常见原因是恢复 `blocked`、迁移被未核实活动阻塞、提交材料不可核实 |
| 管道/启动锁占用 | `another host is claiming this core startup`、`prior core creation is uncertain` | 说明另一入口正在启动或上次启动事实不明；关闭其他入口后重试，保留 `core/launch.json` 现场 |
| 版本不匹配 | `protocol` 非 `aitest.local/2.0`、`supported_actions` 缺动作、旧核心不认 `panel-confirmation/2` | 安装新版 wheel 不会热替换活动实例；按 `restart-core` 受控重启；不得假设旧核心具备新动作 |
| 工作空间锁 | `WORKSPACE_IN_USE` | 已有核心持 `writer.lock`；先优雅停机再执行 `rebuild-index`，或复用现有核心 |
| 迁移/恢复闸门 | 核心拒绝启动、`MIGRATION_FAILED`、`rollback_pending` | 先 `backup inspect` 核迁移前备份；存在未核实活动时禁止迁移/回滚；不删除 `spool/`、`transactions/` |
| 位置被拒 | `WORKSPACE_LOCATION_REJECTED`（`network_drive`/`sync_folder`） | 换到本地固定盘目录；只读数据目录可查询但禁止新运行 |
| 索引不可用 | 列表报索引待重建、游标失效 | 核心未运行时 `aitest rebuild-index --workspace <目录>`；重建失败保留旧游标结论，不伪造列表 |

通用顺序：**保现场 → 只读取证 → 判断能否受控重启 → 记录到 `docs/validation/`**。未知副作用不自动重放，结果未知时不新开意图重试。

## 6 升级与回退

1. **升级前**：记录当前版本、`workspace_id`、最近 `connection-ledger` 事实；对活动工作空间执行 `backup`（`mode=create`），确认 `verified=true`、`complete=true`、`known_missing` 为空。
2. **换包**：替换 Python 环境中的 wheel，重新 `npm run package` 生成 VSIX 并在 Trae 中重装；扩展配置项与宿主环境变量保持不变。
3. **重启**：`aitest restart-core --workspace <目录>`，确认返回 `READY` 且 `workspace_id` 不变、`instance_id` 更新。
4. **核对**：`aitest doctor --workspace <目录>` 为 `READY`；打开报告/问题/导出各读一次；格式迁移会在核心装配内按可校验备份执行，结果记入 `maintenance/audit.jsonl`。
5. **回退**：重新安装旧轮子并 `restart-core`。**没有自动降级迁移**，已迁移的原位格式不会因换回旧包而撤销；需要回到旧格式只能从迁移前备份恢复到**新的空目录**（`backup` 的 `restore` 只允许空目标），不得用备份覆盖活动工作空间。
6. **VSIX 回退**：换回旧 `dist/aitest-trae.vsix` 并在 Trae 重装；0.4.10 当前只完成强制安装，未重载激活，回退前先确认扩展实际加载版本。

发布门禁以 `.github/workflows/ci.yml` 与 `release.yml` 为准：tag 构建才产出 wheel/VSIX 与 `docs/validation/artifacts.json`，`create` 草稿发布不构成真实 AC 验收。

## 7 值班与升级路径

- **无正式值班、无 on-call 轮转、无监控告警系统。** 本项目为**单人维护**：仓库没有值班表、告警通道或 SLA 记录，任何"7×24 支持"的表述都不成立。
- 响应顺序：先保现场（不删锁、不清 `spool`、不换号重跑）→ 只读取证（诊断、台账、审计）→ 判断能否受控重启 → 把过程写进 `docs/validation/` 与[修改日志](../../../修改日志/README.md)。
- 必须升级处理的信号：启动恢复 `blocked`、迁移 `rollback_pending`/不可逆、`spool` 或对象校验失败、跨入口双写疑似、真实 Trae 阻断。
- 升级目标：按[交付计划](../01-项目/03-交付计划.md)里程碑与[项目现状第 9 节](../../../现状.md#9-建议的下一步优先级)排序；涉及合同字段或判定口径时，先回到需求/功能/架构主责分册，不能只在代码里选一种解释。
- 验收状态只登记在 `tests/acceptance/*/status.json`；运维过程发现登记与证据不符，先改登记再改文档。
