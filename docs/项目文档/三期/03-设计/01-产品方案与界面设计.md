# 产品方案与界面设计（三期）

> 适用期次：三期；主责：页面、动作、文案与交互状态；状态：开发基线，平台与界面均未验证
> 本册只覆盖 P3-FR01／P3-FR02。**状态名一律引用[功能清单](../02-需求/02-功能清单.md) 第 2 节的 7 个展示态**，本册不新增状态、不改写含义；字段与取值见[结果上传](../04-架构/03-结果上传.md) 第 4 节。无共享查询、审核界面、远程执行或平台宿主。

## 1 设计目标与入口

1. **账号先于材料。** 不知道"这份结果属于谁"，就不提供发送按钮。
2. **发送是明确动作。** 默认人工；自动同步是一个需要显式开启、可一键关闭的策略，不是一个默认开关。
3. **缺口必须可见。** 已送达与业务证据缺口并列显示，不用一个绿色标记掩盖另一个红色事实。

| 入口 | 用户在这里完成 | 关键约束 |
| --- | --- | --- |
| 设置·平台账号 | 登录、刷新、退出、切换账号；查看参与项目 | 未登录仍可进入本地功能，登录不抢走当前工作台 |
| 上传页 | 查看候选、预览冻结材料、确认发送、查询或补交 | 列表只显示摘要，正文在独立预览中按需读取 |
| 提交详情 | 看回执、接收状态、控制状态、证据覆盖与历史 | 只读事实，动作按钮各自独立 |

上传入口是本地导航的一级增量，不替代任何一期页面；平台接口未配置时只说明所缺配置，本地导航不变。

## 2 账号页

```text
设置 / 平台账号
账号：Alice（平台标识 issuer:account_id）
会话：有效，剩余 42 分钟            [刷新] [退出]
参与项目：工单系统 P1 / 结算中心 P2  [选择]
关联仓库：仅 Git 且平台确有该关联时显示
本地绑定：本地项目「工单系统」→ 平台项目 P1 / 接收方已确认
发送方式：人工发送                   [修改策略]
```

| 字段 | 显示与操作 | 来源与保护 |
| --- | --- | --- |
| 账号 | 平台返回的账号标识与显示名 | 身份为精确 `(issuer, account_id)`，显示名非键 |
| 会话 | 有效／过期／刷新失败，提供刷新、退出、切换 | 不显示令牌正文；并发刷新由核心合并 |
| 参与项目 | 平台返回列表与当前选择 | 旧缓存标"未重新核实"，不能作为发送权限 |
| 关联仓库 | 仅 Git 且平台确有关系时可选项 | plain 整块省略，不要求伪造仓库 |
| 本地绑定 | 本地项目 → 实际平台项目与接收方 | 与本地目录绑定分开，不修改历史提交 |
| 发送策略 | 人工／运行结束／逐步，含账号、项目、目标、类别 | 默认人工；范围变化重新确认 |

账号切换后不把旧账号材料显示为"当前待发"，只保留原归属摘要提示重登处理；不跨账号打开正文或重绑旧提交。

## 3 发送策略与关闭同步

| 展示态 | 策略相关文案 | 允许操作 |
| --- | --- | --- |
| 待发送 | "人工发送：需要你确认这一份" | 预览并确认；或改为自动 |
| 待发送 | "运行结束自动发送（已批准范围）" | 关闭自动同步；查看批准范围 |
| 已暂停 | "同步已关闭，候选与回执仍保留" | 查询一次；重新确认单份送达 |
| 已放弃 | "已停止自动发送，材料永久保留" | 查看接收情况 |

- 开启自动同步必须同时确认账号、项目、目标与材料类别；只改范围不确认时按钮不可用，并说明缺哪一项。
- "关闭自动同步"的说明固定包含三句：停止后续候选的自动发送、撤销当时未完成的送达许可（含查询与补交）、已发出的请求可能仍会返回结果。
- 关闭之后单份重新确认不会重新开启其他候选的自动同步；界面上新授许可须显示其确认来源，避免"同步已关闭却仍在发送"的误解。

## 4 候选与安全预览

```text
上传 / 本地项目：工单系统
账号：Alice（平台标识）   目标：项目 P1 / 接收方已确认
方式：人工发送                     [管理账号] [修改策略]
---------------------------------------------------------
候选：运行 R1、报告修订 3、尚未冻结提交    [选择并预览]
---------------------------------------------------------
冻结预览：提交 S1 / 报告修订 3
包含：运行事实、报告、日志投影
排除：截图 1 项（无法安全去除源码）；业务证据有缺口
路径/文件名：不发送     源码正文：不发送
范围与接收方：本次固定值
[确认发送并完成本份送达] [返回]
---------------------------------------------------------
回执：清单已全部接收
接收状态：已送达        业务证据：仍缺截图 1 项
[查看回执] [查看缺口]
```

- 列表只显示摘要：本地来源、运行与报告修订、目标、接收状态、控制状态、覆盖缺口及原因。
- 独立预览显示当前账号这份提交的冻结安全投影；打开与继续读取都由核心核对账号、项目、提交与清单摘要，切账号立即关闭旧预览并清临时视图。
- 预览只读已冻结字节，不展示原始密钥与原始敏感材料；返回不发送；"确认发送并完成本份送达"包含同份材料的有界查询与补交。
- 预览期间源记录变化时，仍发送原预览字节；用户要新内容须新建提交，界面提示"已生成新修订，可新建提交"。

## 5 队列状态与文案

七个展示态在列表与详情中的文案与动作固定如下，不得改写为同义新词：

| 展示态 | 界面文案 | 允许操作 |
| --- | --- | --- |
| 待发送 | 待发送 | 预览并确认；查看冻结材料 |
| 发送中 | 发送中 | 等待；查询原号 |
| 结果未知 | 接收结果尚未确定 | 查询原提交（不重跑业务） |
| 部分接收 | 部分接收，尚缺 N 项 | 按缺失清单补交 |
| 已送达 | 已送达 | 查看回执、查看缺口 |
| 已暂停 | 已暂停：认证失效／摘要冲突／投影需复核／重试耗尽 | 按原因处理；明确恢复原提交 |
| 已放弃 | 已放弃（已送达时显示"已送达；此前已放弃"） | 查看接收情况；新建关联提交 |

"已暂停"必须带具体原因，不允许只显示一个红色圆点；"重试耗尽"的文案写"本周期请求额度已用尽"，不把正常大对象传输统称网络失败。

## 6 空态与异常呈现

| 情形 | 界面呈现 | 可用操作 |
| --- | --- | --- |
| 没有可上传结果 | 尚无可上传的已保存结果 | 返回本地检查 |
| 候选未关联 | 需要确认账号和目标 | 选择目标，不自动猜测 |
| 平台接口未配置 | 上传不可用，缺少平台配置 | 本地检查、报告、导出继续 |
| 平台不可用 | 仅上传不可用及具体原因 | 本地继续；稍后补交 |
| 逻辑队列满 | 新提交待处理，候选仍保留 | 补交或明确放弃；不承诺释放磁盘占用 |
| 磁盘不足 | 无法保存新增材料及原因 | 清理可回收临时材料；不静默丢弃 |
| 摘要或归属冲突 | 列出具体冲突对象 | 查看原回执，处理后新建关联提交 |
| 投影需复核 | 列出关键材料排除项及影响 | 预览并确认部分材料，或停止发送 |

放弃确认框必须说明：停止自动发送、不删除材料、不能撤回平台已接收内容。暂停、关闭同步、退出与放弃是四个不同按钮，界面不得用通用"停止"代替。

## 7 交互与边界

- 预览、确认与返回支持键盘操作；状态同时用文字、图标与原因表达，不仅靠颜色区分。
- 提交详情分别显示发送策略模式、当前单份许可状态、接收状态与覆盖缺口，四个维度不合并成一个"进度"。
- 面板只消费核心 DTO，不计算权威接收进展、不自行判断是否送达；无新业务候选时不显示虚假同步进度，也不自行轮询核心。
- 人工确认与策略确认只能由核心认可的用户交互完成，MCP 与 AI 工具调用不能确认策略或提交。
- 不提供审核按钮、跨账号查询视图或平台接收管理界面；需要查看平台审核时只打开经核实的平台链接。
