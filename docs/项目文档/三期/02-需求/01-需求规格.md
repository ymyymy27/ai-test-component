# 需求规格（三期）

> 适用期次：三期（P3-FR01—P3-FR02 / P3-AC01—P3-AC08）
> 主责：产品目标、范围边界、账号与项目身份、验收预期；**第 6 节是 P3-AC 场景与预期的唯一维护点**
> 状态：规划稿。平台合同未定，本册不表示任一功能已实现、已对接或已通过验收。

三期只解决"把本地已保存的结果可靠送上去"。平台侧账号体系、接收端、共享查询、跨账号审核、宿主加载与运维由平台项目承担，不在插件交付范围（见[期次说明](../01-项目/01-期次说明.md) 第 3 节）。字段、状态、许可与摘要的技术合同由[功能清单](02-功能清单.md)与[结果上传](../04-架构/03-结果上传.md)维护，本册不另起定义。

## 1 产品目标

让本地已经产生的测试结果可以上传到平台，其余协作能力交给平台：

- 用平台给定的账号标识把结果归到项目；插件本地不保存第二份成员目录，也不另行注册身份或保存密码。
- 只上传一期已经产生的事实：运行、证据、报告与本地问题记录的安全投影；不上传代码正文、GitHub Issue 与 PR。
- 平台不可用、接口未就绪或上传失败都不影响本地测试与本地结论；一、二期的本地能力保持原样。
- 判定与投递解耦：上传成功不改变执行状态、断言结果、验收结论与问题状态。

### 1.1 成功指标

成功指标用于判断三期是否达成，不引入百分比口径；每项仍以第 6 节对应场景的输入、版本与证据为准。

| 成功指标 | 合同判定要求 |
| --- | --- |
| 身份稳定 | 各入口关联同一平台账号；显示名与正文自填编号不能改变归属 |
| 归属可追溯 | 每次提交可追溯到账号、项目、源码快照、运行与尝试编号及内容修订 |
| 只传允许内容 | 上传材料经脱敏投影；源码正文、GitHub Issue、PR 始终排除；路径与文件名默认不发 |
| 送达可核对 | 只有回执的清单摘要与逐对象上传摘要全部匹配才显示"已送达"；缺项显示缺口 |
| 幂等与补交 | 同号同内容返回原回执；断连后先查原号、只补缺，不重跑被测业务 |
| 本地不受影响 | 平台不可用时本地测试、证据、报告与导出完全不受影响 |
| 判定不变 | 上传与回执不确认缺陷、不关闭问题、不发布规则、不改写结论 |

## 2 范围与边界

### 2.1 功能与验收基线

三期覆盖 2 项功能、8 项验收，编号基线固定，不随实现拆分重编。

| 功能 | 内容 | 关联验收 |
| --- | --- | --- |
| P3-FR01 统一账号与项目关联 | 使用平台会话，选择参与项目与接收目标，绑定本地项目；只读平台数据 | P3-AC01、02、06、07 |
| P3-FR02 结果上传 | 提交冻结、回执核对、失败与断连后的查询与补交、离线待发送队列 | P3-AC02—08 |

两条功能的需求级行为分别在 §3（账号与项目身份）与 §4（冻结投影与单份送达）展开；详细规则与字段见[功能清单](02-功能清单.md)，本节只固定编号与验收归属。

### 2.2 平台职责与插件职责

| 事项 | 平台 | 插件 |
| --- | --- | --- |
| 账号、项目编号、成员关系 | 提供并维护 | 只读取，不维护第二套 |
| 项目与仓库关联 | 提供并维护 | 仅在 Git 且平台确有关联时读取并可选，plain 省略 |
| 接收结果、去重、回执 | 提供接口与存储 | 按合同提交、查询、补交 |
| 会话校验与身份认定 | 校验会话并给出稳定账号 | 使用返回的账号，正文自填不作身份依据 |
| 共享查询、跨账号审核、宿主、运维 | 提供并承担 | 不实现、不部署独立服务端 |

### 2.3 上传边界

| 事项 | 约定 |
| --- | --- |
| 上传内容 | 运行、证据、报告与问题记录（脱敏投影）；不含代码正文、GitHub Issue 与 PR；本地问题记录按白名单投影后可传 |
| 上传触发 | 每步结束与运行终止后先本地保存，再生成候选；默认人工发送，自动发送须有有效策略与送达许可 |
| 上传不改判定 | 提交成功不改变执行、断言、验收结论，也不确认缺陷、不发布规则 |
| 平台不可用 | 一期的本地测试、证据、报告与导出完全不受影响；待发送材料保留在本地 |

失败、阻塞、取消的运行同样保存并形成候选；候选生成不等于已获发送许可。

### 2.4 使用形态与前提

| 使用形态 | 前提 | 本期范围 |
| --- | --- | --- |
| 已登录后上传 | 有效平台会话、已确认的参与项目与接收目标 | 生成候选、冻结投影、预览确认、发送与核对回执 |
| 未登录或离线 | 无会话，或平台接口未配置 | 本地测试照常；候选保留并标"未关联"，不猜归属 |
| 平台不可用 | 连接失败、凭据失效或接口报错 | 只降上传能力，本地记录、报告与导出完全可用 |

出站只有一条通道：插件调用平台接收接口（HTTPS 出站）。不引入本地监听端口、不要求平台在线才能启动本地核心。

### 2.5 明确不做

- 不新建独立站点或数据库；插件侧不引入数据库、消息队列、独立发送 Worker 或本地 HTTP 服务。
- 不做平台侧任何能力：不实现接收端、共享查询、跨账号审核与审核投影、宿主接收模块与远程 MCP，不监听端口。
- 不做自动操作录制与回放、任意语言自动插桩。
- 不做自动处理合并冲突、无人确认的自动修复发布、生产部署管理。
- 不做 GitHub 写操作：Issue 与 PR 既不读取上传，也不因上传而创建。

## 3 账号与项目身份

- 身份是精确的 `(issuer, account_id)` 对，由验证后的会话给出；不整体小写，不做 Unicode 归一化。显示名只用于展示，不能作为账号唯一键；正文自填的用户编号不能作为身份依据。
- 目录键 `account_key` 取版本化规范 JSON 的安全摘要，不把原始标识拼进路径；真实标识仍保存在记录中，校验任何解析路径不逃出 outbox。字段定义见[账号与项目关联](../04-架构/02-账号与项目关联.md) 第 1 节。
- 登录后取得参与项目列表。选择平台项目必需；仓库关联仅在 Git 且平台确有该关联时适用，普通目录不被强制选择，也不伪造仓库。
- 退出或切换账号：清当前账号的令牌与临时视图，保留尚未送达的材料；已发请求不可假装撤销，迟到响应核对账号与绑定修订后只更新原提交。
- 本地记录保留本地来源，登录与上传不改写采集来源；本地身份与实际发送账号分开记录。
- 登录不等于同意自动上传：默认人工发送，自动同步须用户显式开启策略并确认范围。

## 4 冻结投影与单份送达

### 4.1 冻结投影

- 入队时冻结脱敏字节，记录 `source_digest`（本地原对象，仅本地追溯）与 `upload_digest`（实际出站字节）；两者不互相替代。
- 路径与文件名默认在所有字段与正文中去掉，只有显式上传策略允许时才加入合同允许的信息；源码正文始终排除。
- 无法生成满足策略的投影时，该材料被排除并记为业务证据缺口，不宣称材料完整。
- 报告以"报告内容修订 + 冻结投影摘要"形式上送；报告修订变化时提示需要新的提交，旧回执不被覆盖。

### 4.2 只出站，不接收

插件只调用平台接收接口，不提供可加载子应用、不建立接收侧路由，也不为平台内部事务建模。平台可采用单次或分块接口，插件只要求幂等、原号查询与完整回执三项语义成立。

### 4.3 单份送达许可

- 手动确认授权的是一份精确提交（`submission_id` + `manifest_hash`）的**一次完整送达过程**：包含同份材料的有界查询、补交与合同允许的同号同字节重传；不授权新材料、新目标或后续候选。
- 许可持久保存：重启不重置失败周期，重登只恢复会话、不复活许可。
- 退出、切换账号、暂停本份或关闭同步会撤销对应未完成许可；只有用户明确"放弃这份提交"才进入放弃态，暂停与关闭同步都不是放弃。
- 摘要冲突与关键投影缺口不能靠重登或普通重试解除；认证恢复不替代这些决定。

决策表见[功能清单](02-功能清单.md) 第 4、5 节，字段见[结果上传](../04-架构/03-结果上传.md) 第 5 节。

### 4.4 送达与业务交付分开

- 回执只证明"冻结清单被完整接收"，不证明业务证据齐全，也不证明测试结论成立。被脱敏排除的截图、未采集或损坏的材料仍作为业务证据缺口显示。
- 因此界面可以同时显示"提交已送达"和"业务证据有缺口"，两者不互相抵消；平台侧的"完整业务交付"标记须按双方合同与缺口判断，不能由 HTTP 成功或完整回执推断。
- 上传期间与上传之后，本地执行状态、断言结果、验收结论与问题状态一律不改写；模型出站策略也不能授权平台发送代码。

## 5 与一期、二期的关系

| 主题 | 处理方式 |

## 7 交付验收与前置条件

- 平台具备后，账号、项目参与与仓库关联以平台返回结果为准，插件不保存第二份成员目录。
- 结果提交可追溯到账号、项目、源码快照、运行与尝试编号及内容修订。
- 断连与重复提交不产生错误结论；重发不重跑被测业务。
- **平台不可用时，一期的本地测试、证据、报告与导出功能完全不受影响。**
- **上传实现的前置条件（未满足则不启动上传实现）**：平台提供 ① 会话获取与刷新方式（含失效提示）；② 提交接口形态（单次或分块、字段、大小限制、错误码）；③ 回执语义（什么算完整接收、如何按原编号查询、回执带每个对象的内容摘要）；④ 账号与项目标识的取值口径。插件侧负责脱敏投影、离线候选队列、幂等键、重试与补交、清单摘要与本地只读状态展示。
- 双方以固定样例对拍规范清单与报告摘要；未通过字节级对拍前不声明平台可互通，也不宣称上传可用。

## 8 变更控制

1. 增删、改义或跨期移动 FR/AC 须显式更新本册第 6 节、映射与验收范围，不通过重编号掩盖变化。
2. 发现登记与需求或真实证据不符时，先改登记再改文档，不反向迁就。
3. 平台合同确定后只补充取值与字段，不改变已发布的判定语义与排除规则。
