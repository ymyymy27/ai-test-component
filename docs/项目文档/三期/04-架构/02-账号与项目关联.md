# 账号与项目关联（三期）

> 适用期次：三期 P3-FR01；主责：账号身份、会话、项目参与与本地绑定、凭据分区；状态：规划稿
> 本册只定义"谁在用、属于哪个项目"。展示态与文案见[功能清单](../02-需求/02-功能清单.md) 第 2 节与[界面设计](../03-设计/01-产品方案与界面设计.md)，上传投递见[结果上传](03-结果上传.md)。核心只使用验证后的会话，不从正文、显示名或本地责任人推断身份。

## 1 AccountRef 与账号键

| 记录 | 字段与约束 |
| --- | --- |
| `AccountRef` | `issuer`、`account_id`、`display_name`；前两项按平台合同保留精确值，作为唯一身份，显示名可变 |
| `SessionContext` | 账号引用、会话编号、会话修订、有效期、`SecretRef`；由验证后的会话构造，不落令牌正文 |
| `ProjectMembership` | 账号引用、平台项目编号与名称、参与状态、可选关联仓库清单、核对时间；缓存只供展示 |
| `PlatformProjectBinding` | 本地项目、平台项目、可选 Git 关联、接收目标、上传策略、账号、`binding_revision`；不得与本地目录绑定混用 |

子域位置（三期新增，依赖方向同一期）：

```text
application/collaboration/account_session.py   # 会话、参与项目、绑定修订
infrastructure/adapters/account.py             # AccountPort 实现（出站）
infrastructure/credentials.py                  # 三期增加按账号的令牌命名空间
domain/identity/accounts.py                    # 账号引用与参与模型（纯规则）
```

`AccountPort` 在一期只预留名称与用途，三期为它定义方法签名与返回类型，登记进 `application/ports.py`，实现经 `bootstrap.py` 注入。

**账号键计算**：`account_key = SHA-256(版本化规范 JSON 编码 [issuer, account_id])`。

- 输入是二元组而不是拼接字符串：不做整体小写、不做 Unicode 归一化、不擅自裁剪空白；`issuer` 的规范化规则须双方合同约定。
- 编码使用固定版本标记（如 `["aitest.account/1", issuer, account_id]`），版本变化产生新键并保留旧键映射。
- 输出取小写十六进制，只作为目录分量与凭据命名空间；真实标识仍保存在记录中，校验任何解析路径不逃出 `outbox/`。

## 2 会话与并发刷新

- 同账号的刷新请求合并：以 `expected_revision` 核对，过期结果不能覆盖新会话。
- 刷新成功必须身份不变；身份改变即结束旧会话，不把新材料算到新身份。
- 退出或切换账号递增 `session_revision`，停止尚未发出的提交，清令牌与界面临时缓存，**保留候选、冻结材料与已收回执**。
- 已发出的网络请求可能成功：迟到响应核对原账号、绑定与请求后，只更新原提交，不移交新账号、不显示到新账号视图。

## 3 参与关系与绑定修订

| 时点 | 核对内容 | 失败结果 |
| --- | --- | --- |
| 取得或刷新会话 | 平台验证的 `issuer`/`account_id`、会话修订、凭据引用、有效性 | 身份不一致结束原会话，不改旧材料归属 |
| 展示项目列表 | 平台项目标识、名称、参与状态、可选仓库、核对来源 | 旧缓存标"只供展示"，不能据此发送 |
| 冻结提交 | 会话、项目参与、目标绑定与策略修订 | 保留候选待处理，不伪造提交 |
| 发请求前 | 当前会话与策略仍允许该冻结账号/目标/类别 | 停止尚未发出的请求；已发请求保留核对路径 |
| 核对回执 | 原请求的账号、项目、提交、绑定、内容与对象摘要 | 归属不符不写到新账号，按冲突记录 |
| 退出或切换 | 清令牌与临时视图，递增会话修订 | 不删除候选、投影、回执与永久事实 |

- 项目选择必需；仓库关联仅在 Git 且平台确有该关联时可选。plain 项目不显示仓库字段，也不因本地无 Git 阻断上传；平台确有关系而本地无法确认时，按合同说明缺项。
- 账号、目标、材料类别或投影规则变化须新建绑定修订与提交；仅发送模式或暂停状态变化不新建提交。
- 采集来源与实际上传账号分别保存，登录不回写旧本地来源；未登录时采集的材料保持原来源与"未关联"候选。

## 4 凭据分区

| 项 | 约定 |
| --- | --- |
| 令牌类凭据 | 登录会话令牌；退出、会话失效或切换账号时清除 |
| 存放 | 凭据设施保存正文，工作空间与落盘记录只存逻辑引用；令牌不进日志、导出与面板 |
| 轮换 | 平台要求轮换时替换引用，旧引用仅为在途请求收尾保留，随后按会话策略清除 |
| 换机器 | 重新登录即可恢复共享能力；未登录时上传不可用，本地记录与待发送材料不受影响 |
| 命名空间 | 与 `account_key` 关联，不从显示名或含路径分隔符的原始账号拼接目录 |

**`outbox` 不加密声明**：待发送材料按 `account_key` 分目录，以**脱敏明文**保存，依赖"工作空间属于单个操作系统用户 + 用户数据目录权限"保护，不做应用层加密。理由：应用层加密需要一个独立于令牌长期保留的密钥，跨机器恢复在当前凭据后端（Windows 凭据管理器或编辑器 SecretStorage）下没有实现路径，引入后会把待发送材料变成取不回来的黑盒。

因此本册只承诺三条行为：**令牌与材料分区、引用可解析、重新登录可继续补交**。**同一操作系统用户下的其他进程理论上可读取 `outbox`**，插件不承诺防止，用户需自行控制机器账户与目录权限。账号与队列列表只显示摘要；当前账号可在独立受控预览中查看本账号提交的冻结安全投影，不允许预览其他账号材料。

## 5 安全预览的归属校验

预览与发送授权分开：核心先核对当前 `account_key`、项目与提交归属、冻结清单摘要，再返回安全对象流；预览本身不产生发送许可。切换账号使原预览流与缓存失效，每次分块读取仍核对会话与归属。禁止展示原始密钥与原始敏感材料；跨账号隔离保护的是"归属与补交对象"，不是"防同机读取"。

## 7 验收映射

| 验证主题 | 关键检查 | 场景 |
| --- | --- | --- |
| 会话闭环 | 登录、刷新、退出、重登关联同一稳定账号；退出清会话但保留待发送材料 | P3-AC01 |
| 归属隔离 | 两账号（含大小写差异）不串用来源与材料；显示名不改变身份 | P3-AC02 |
| 离线候选 | 无会话候选保持未关联，显式确认账号与目标后才生成提交 | P3-AC03、P3-AC06 |
| 本地不受影响 | 平台失联或凭据失效时本地测试、记录与导出继续 | P3-AC06 |
