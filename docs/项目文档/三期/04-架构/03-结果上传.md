# 结果上传（三期）

> 适用期次：三期 P3-FR02；主责：候选、冻结投影、清单与摘要、四组状态字段、送达许可、传输与回执；状态：规划稿，平台合同未定
> **本册只定义字段与取值，不定义展示态。** 界面看到的 7 个展示态及其与四组字段的组合关系只在[功能清单](../02-需求/02-功能清单.md) 第 2 节定义；页面动作见[界面设计](../03-设计/01-产品方案与界面设计.md)。账号与归属见[账号与项目关联](02-账号与项目关联.md)。

插件只实现出站侧：调用平台接收接口提交、查询与核对，不提供接收端实现。平台可采用单次或 prepare/upload/query/finalize 等流程，分块大小与网络字段随平台能力确定，本册不约束平台内部架构。

## 1 候选与游标

- 业务事实本地提交成功后，由持久游标按已提交序号与记录修订生成 `DeliveryCandidate`；登记失败可由游标补建，不回滚本地事实。
- 候选只订阅允许业务类型（运行、步骤、证据、问题、报告）的提交，**不订阅候选、提交、回执与游标自身的写入**，避免自激。
- 去重键为 `(origin_workspace_id, project_id, record_type, record_id, content_revision)`；候选登记与游标推进在同一工作单元提交。
- 队列满时候选仍登记（或游标停在原处），不先推进再丢材料；未登录候选保持"未关联"，不自动归到下次登录的账号。

三种身份必须分开，不得互相替代：

| 身份 | 组成 | 作用 |
| --- | --- | --- |
| 运行身份 | `(origin_workspace_id, project_id, run_id)` | 同一次运行可产生多个内容修订，不参与幂等判断 |
| 提交身份 | `submission_id` + 账号/目标 + `manifest_hash` | 冻结一次出站内容；同号不得改账号、目标或字节 |
| 请求身份 | `request_id` | 一次传输尝试；同一请求的迟到或重复响应只归并一次 |

## 2 投影与排除

- 按类型白名单投影运行、证据、报告与本地问题；源码正文、GitHub Issue 与 PR 始终排除。
- 日志与截图中可能含路径或源码，**不能只按类型认定安全**；无法生成满足策略的投影时排除该对象并记为业务证据缺口。
- 入队时冻结字节，同时记录 `source_digest`（本地原对象，仅本地追溯）与 `upload_digest`（实际出站字节），并记录投影策略版本与大小。
- 路径与文件名的开关作用于所有字段与正文，默认去除；本地绝对路径不作为隐含来源字段发送。显式开启只加入合同允许的信息，不放开源码正文。
- 采集阶段已过滤凭据不替代上传白名单、路径排除与投影缺口检查。

`EvidenceDeliveryCoverage` 与清单一起冻结，记录预期证据 ID、已包含、被排除、缺失及原因；**对象全部接收只驱动接收事实，不能抹掉覆盖缺口**。

## 3 清单与摘要

### 3.1 Manifest/1 字段

| 层级 | 字段 | 约束 |
| --- | --- | --- |
| 顶层 | `schema_version` | 固定字符串 `aitest.manifest/1` |
| 顶层 | `report_hash` | 无报告时为 `null`；有报告时为 `sha256:` + 64 位小写十六进制 |
| 顶层 | `objects` | 对象数组，业务提交至少一个允许对象；空数组只用于算法样例 |
| 对象 | `record_type`、`object_id`、`content_revision` | 非空不透明字符串；修订为 1 至 9007199254740991 的整数 |
| 对象 | `upload_digest`、`size`、`projection_policy_version` | 摘要为 `sha256:` 前缀；`size` 为实际字节长度（非字符数） |
| 对象 | `metadata` | 只允许 `label` 与 `media_type` 字符串；`path`/`filename` 仅在显式路径策略允许时加入，默认空对象 |

未知顶层或对象字段一律拒绝，不静默纳入摘要；缺省字段不得用省略代替 `null` 或空对象。

### 3.2 排序与去重

- 同一 `(record_type, object_id, content_revision)` 只能出现一次；重复即拒绝，不靠摘要不同绕过。
- 数组按 `(record_type, object_id, content_revision, upload_digest)` 升序：字符串按 Unicode 标量值比较，修订按整数比较；**排序在 JCS 之前**，排序阶段不做大小写折叠或 Unicode 归一化。

### 3.3 计算顺序

1. 从精确来源修订生成可上传字节与覆盖缺口，冻结字节；`upload_digest` 对实际字节取 SHA-256，`size` 取实际字节长度。
2. 生成报告投影：包含 `schema_version`、报告 ID 与修订、来源修订、判定策略、结论及附件 `upload_digest` 清单；**不得包含报告自身的 `report_hash`、`manifest_hash` 或自身 `upload_digest`**。
3. 对报告投影做 JCS 规范化并计算 `report_hash`；报告作为 `record_type=report` 对象时，其 `upload_digest` 与 `report_hash` 值相等但用途不同。无报告时跳过此步。
4. 收集最终对象条目、按 3.2 排序并构造 Manifest/1，对其 JCS UTF-8 字节计算 `manifest_hash`。`manifest_hash` 不进入自身字节。

JCS 的属性排序、数值序列化、字符转义与 UTF-8 按 [RFC 8785](https://www.rfc-editor.org/rfc/rfc8785.html#section-3) 执行；`sort_keys` 开关不等于 JCS 合规。`submission_id`、账号/目标、`binding_revision` 与 `manifest_hash` 共同作为冻结 `Submission` 信封保存。

任何投影字节、材料范围或投影策略变化都产生新提交；发送阶段不二次改写字节。

### 3.4 固定对拍样例

以下为构造的算法样例，不是已执行或已接收的记录；代码块末尾换行不属于摘要输入。

附件 `e1` 的上传字节为十六进制 `6f 6b 0a`（"ok" 后一个 LF），`size=3`，`upload_digest=sha256:dc51b8c96c2d745df3bd5590d990230a482fd247123599548e0632fdbf97fc22`。

```json
{"objects":[{"content_revision":1,"metadata":{},"object_id":"e1","projection_policy_version":"1","record_type":"evidence","size":3,"upload_digest":"sha256:dc51b8c96c2d745df3bd5590d990230a482fd247123599548e0632fdbf97fc22"}],"report_hash":null,"schema_version":"aitest.manifest/1"}
```

预期 `manifest_hash`：`sha256:2dfefe5cd2b196af7a833ffab4e5619abdf50d5e690a377cf0b7d4649749b635`。

| 变体输入 | 必须结果 |
| --- | --- |
| 同一对象属性顺序不同 | 规范字节与摘要不变 |
| 去掉附件末尾 LF | `size=2`，两个摘要均改变 |
| `report_hash` 省略或用空串代替 `null` | Schema 拒绝，不补默认值参与摘要 |
| 同一对象键重复出现 | 拒绝，不合并、不保留最后一个 |
| `content_revision` 为 0、浮点或超出安全整数 | Schema 拒绝 |
| 字符串含中文或换行 | 原样保留并按 JCS 转义，不做 Unicode 归一化 |

对拍还须覆盖补充平面字符、非法代理项、整数边界、同 ID 新修订、被排除附件与报告变化；双方各自输出规范字节与摘要逐字节比对，未通过前不声明平台可互通。

## 4 四组状态字段

接收事实、传输在途、控制决定与送达许可分别保存，互不回写。字段取值如下，**本表不定义界面状态名**。

| 字段 | 合法取值 | 责任与语义 |
| --- | --- | --- |
| `receipt_state` | `PENDING` / `UNKNOWN` / `INCOMPLETE` / `ACKNOWLEDGED` | 记录平台接收事实；`PENDING` 表示尚无接收信息，`UNKNOWN` 表示无法确认 |
| `transport_state` | `IDLE` / `IN_FLIGHT` | 记录某次请求是否在途；请求结束回到 `IDLE`，不替代接收事实 |
| `control_state` | `ACTIVE` / `PAUSED` / `ABANDONED` | 记录暂停、放弃等控制决定；`ACTIVE` 不等于已有发送许可 |
| `grant_state` | `active` / `revoked` / `completed` | 来自精确提交的 `SubmissionDeliveryGrant`，限定允许的操作范围 |

组合规则：

1. 控制决定优先于传输在途，传输在途优先于接收事实；派生结果与界面文案见[功能清单](../02-需求/02-功能清单.md) 第 2 节映射表，本册不复述。
2. 在途请求**不回写** `receipt_state`；请求结束只改 `transport_state` 与请求记录。
3. 完整有效迟到回执仍更新接收事实，但不解除暂停/放弃、不重新授予许可。
4. 送达后对账出现异常，新增冲突记录并保存原因，不删除历史 `ACKNOWLEDGED` 回执。

## 5 送达许可（Grant）

| 字段 | 内容 |
| --- | --- |
| 标识 | `grant_id`、`revision` |
| 绑定 | `submission_id`、`manifest_hash`、账号与目标、`binding_revision` |
| 修订引用 | 发送控制修订、材料策略修订、投影修订 |
| 范围 | `allowed_operations`：首次发送、原号查询、缺失对象补交、合同允许的同号同字节重传 |
| 来源 | `confirmation_ref`（人工确认）或 `approved_policy_ref`（已批准策略） |
| 状态 | `active` / `revoked` / `completed`，附失败周期引用与撤销原因 |

- 许可作为投递子域的提交控制记录，沿用工作单元保存；不另建调度器、队列服务或账号 Worker。
- 人工确认须在核心校验来源与挑战后创建；自动模式只按已批准策略创建匹配许可，且首次发送仍要求预览确认。
- 存在撤销或暂停记录的原提交，不能被扫描循环自动再授许可，必须显式人工确认；重登、重复扫描不能绕过停止决定。
- 发送循环每次：取许可 → 核对当前会话/参与/策略与冻结摘要 → 短事务登记意图与轮次 → 事务外出站 → 追加响应。查询与补交同样过此门禁；单次查询许可不含补交。
- 仅模式或启停修订变化不改变冻结字节，可为原提交建立新许可；账号、目标、内容或材料/投影策略变化必须新建提交。
- 许可失效不改冻结字节；`ACKNOWLEDGED` 结束该许可并保留回执。

## 6 候选扫描与停止条件

- 每轮固定当前已提交高水位 `h` 与索引根，按冻结的白名单版本在允许 `record_type` 的索引中 seek 到 `candidate_cursor` 之后，合并读到 `h`；不把本轮新增的游标或上传提交纳入范围，不遍历无关事件尾部。
- 索引项包含 `commit_sequence`、`record_type`、来源实例与项目、`record_id`、`content_revision`；同一提交的相关项完整登记后才可跨过该序号。
- 扫描位置只在内存推进；**只有确有新增候选时**，候选引用与 `candidate_cursor` 才经同一工作单元发布。上传自身事件、已去重候选与空结果不产生纯游标提交、不自唤醒。
- 某业务提交无法完整登记时，只提交该阻塞点之前的连续前缀及对应候选；不得把游标直接推到 `h` 而漏掉中间材料。
- 重启从持久游标 seek 恢复并按稳定候选键去重；成本不随上传/诊断尾部长度线性增长。索引缺失返回 `INDEX_REBUILD_REQUIRED`，不得静默改为全历史扫描。
- 各类型根的最大业务序号均不大于游标时可直接结束；该最大值只是短路提示，不能取代有缺口时的范围读取。
- 客户端退出时，无活动执行且无可推进的发送/候选工作即可收尾；无业务可扫不是保活理由。

## 7 传输、周期与回执

### 7.1 端口行为映射

下表是插件所需能力，不要求平台提供同名接口，也不要求插件实现接收端。

| 能力 | 插件行为 | 失败处理 |
| --- | --- | --- |
| 准备/协商 | 冻结清单、账号与目标、已存在对象与续传位置 | 保存原提交；准备成功不等于完整回执 |
| 对象传输 | 指定对象与实际 `upload_digest`；支持分块时按确认偏移续传 | 失联先查，不假定未写入 |
| 原号查询 | 在原账号与原项目下按 `submission_id` 查询 | 得缺口则补交；仍未知按同一有界周期控制 |
| 最终核对 | 清单、接收内容修订、完整标志、对象集合与逐项摘要 | 缺项为 `INCOMPLETE`；多对象/错摘要/错归属为冲突 |

若平台只支持单次提交，也必须表达原号查询、幂等与完整回执。完整回执至少包含：提交编号、清单摘要、目标项目、接收记录编号与时间、接收内容修订、附件清单摘要与完整性，以及每个对象的对象编号与 `upload_digest`。

### 7.2 周期与接收进展

同一冻结提交持久保存 `cycle_id`、`policy_revision`、`cycle_attempt_count`、`no_progress_count`、已接收对象引用、`confirmed_offsets` 与请求归并状态。

- 周期策略由一期 connectivity 给出有限上限与有界退避，周期内冻结；发送、查询、补交与完成确认**共用总轮次**。
- 先持久登记请求并递增轮次，再出站；崩溃后的未知请求按已消耗轮次恢复，不重复免费尝试。
- 真实进展仅三种：已完整接收对象集合严格增加；某对象可信连续偏移严格增加；完整匹配回执到达 `ACKNOWLEDGED`。
- 不构成进展：HTTP 成功、客户端已发送字节、仅平台版本号变化、重复偏移、无偏移增长的相同 `UNKNOWN` 或相同缺失集合。
- 真实进展将 `no_progress_count` 归零，但**不重置** `cycle_attempt_count`。每个请求最多计一次无进展；重复投递同一响应只归并事实。
- 偏移为整数且 `0 ≤ offset ≤ 冻结 size`；只认可连续前缀，平台返回离散区间时由适配器校验归属与摘要后归一化，未填平的后段不虚增前缀。`offset=size` 仍须取得该对象完整接收确认。
- 总轮次或连续无进展达上限且未完成则转 `PAUSED`，原因记 `RETRY_EXHAUSTED` 或 `NO_PROGRESS`；完整有效回执优先保存为 `ACKNOWLEDGED`，不因恰好用完最后一轮误报未送达。
- 重启、重登、重复唤醒与默认值变更都不重置周期；只有用户明确恢复、原因可处理且许可有效才新建周期。
- 周期开始前按平台已确认能力与冻结 `size` 计算正常请求计划（每对象剩余块数 + 必要控制请求），再加有限额外额度；最长连续无变化控制段必须小于无进展上限，否则拒绝该周期计划。分块规格变化或取不到有限计划时暂停并展示原因。
- 平台无法提供可信部分接收事实时，只启用已对拍的原子对象上传；不得用本地发送字节伪造进展，也不宣称支持自动分块续传。

### 7.3 回执核对

- 逐项核对账号与目标、`submission_id`、`manifest_hash`、接收修订、对象集合与数量、每项 `upload_digest` 与完整性。
- 对象缺失为 `INCOMPLETE`；摘要错误、多余冲突对象、修订或归属错误为冲突并转 `PAUSED`，不标送达。
- 回执摘要只证明双方声明一致，不宣称防止恶意平台篡改。
- 按请求顺序与平台权威接收修订识别迟到旧回执：旧有效回执保留历史，不用较小集合或偏移回退当前事实；更新的权威事实回退、越界偏移、清单外对象按协议冲突暂停。

## 8 冲突与恢复决策

| 情形 | 处理 |
| --- | --- |
| 本地事实提交后、候选写入前崩溃 | 从游标重扫允许类型；去重与游标同事务，不漏结果 |
| 预览后源记录变化 | 旧预览与旧提交字节不变；新修订另建候选与提交 |
| 发送成功但本地未收回执 | 原号查询，核对完整回执后登记；不再次执行被测业务 |
| 平台明确无原提交 | 原提交仍允许发送时同号同字节重发；放弃或撤销的不能自动恢复 |
| 同号不同内容或目标 | 冲突并暂停，保留原记录，新提交关联旧提交 |
| 同运行新报告修订 | 新 `submission_id`，不判为同号冲突，不覆盖旧回执 |
| 退出或换账号后回执迟到 | 校验原账号、绑定与请求，只追加原提交事实 |
| 放弃后完整回执迟到 | 记录真实送达，同时保留放弃决定，不恢复发送循环 |
| 完整接收后对账冲突 | 新增冲突记录，旧回执不可删除，本地结论不变 |

## 9 待平台确定

登录与刷新协议、提交接口形态与错误码全集、回执语义与完整性判定、分块大小与偏移语义、账号与项目标识口径，均由双方接口合同确定；**本册第 3 节的清单与摘要规范不在此列**（已由插件侧定稿）。上述内容未定前不宣称上传可用，也不妨碍一期与二期的本地交付。
