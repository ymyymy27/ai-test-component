# 架构总览（三期）

> 适用期次：三期；主责：分层增量、出站边界与依赖方向；状态：规划稿，平台合同未定
> 本册只描述三期在既有工程上**新增**的部分。账号字段见[账号与项目关联](02-账号与项目关联.md)，清单、状态字段与传输见[结果上传](03-结果上传.md)；判定、覆盖与证据等级仍由一期合同维护，本册不重述。

## 1 分层增量

三期沿用一期的依赖方向：入口 → 接口适配 → 应用用例 → 纯领域规则，端口在 `application/ports.py`，实现在 `infrastructure/`，装配在 `bootstrap.py`。

| 层 | 增量 | 约束 |
| --- | --- | --- |
| 应用 | 账号会话用例、结果投递用例（候选、冻结、发送、查询、补交） | 不直接 import 基础设施；网络在事务外 |
| 领域 | 账号引用与参与模型、提交与清单、送达许可、接收进展纯规则 | 不做 I/O、不读时钟；判定结论只从一期领域规则读取 |
| 端口 | `AccountPort`（会话与参与查询）、`ResultSubmitterPort`（出站提交与查询） | 方法签名与返回类型待平台合同定稿后补 |
| 适配器 | 平台账号适配器、平台接收适配器（出站 HTTPS） | 不绕过端口暴露给应用层 |
| 凭据 | 按账号增加令牌引用命名空间 | 令牌正文只在凭据后端，工作空间只存引用 |
| 视图 | 账号与项目设置、本账号提交队列与预览 | 只读 DTO，不写业务文件、不重算状态 |
| 存储 | 沿用工作单元，新增候选游标、不可变提交与回执、脱敏产物引用 | 不引入数据库、消息队列或独立发送 Worker |

`AccountPort` 与 `ResultSubmitterPort` 在一期只预留名称与用途，三期为二者定义签名；新增记录与字段按版本化 Schema 声明，不改已发布字段语义。

端口冻结的准确含义：一期只冻结 DTO 契约（命令、响应、事件、能力），`application/ports.py` 中预留端口名称与用途；三期允许在方法签名层面变动，但不改变既有字段语义、判定规则与上传排除规则。适配器在平台四项合同确定后实现，未确定时端口只作编译期占位，不暴露给入口。

## 2 出站边界

```text
本地面板 / CLI / MCP
   │ 只发 Command、只读 DTO
应用用例（候选 → 冻结 → 许可 → 发送 → 核对）
   │
端口  AccountPort（会话、参与）· ResultSubmitterPort（准备、传输、查询、核对）
   │
适配器  出站 HTTPS 调用平台
```

- **只有出站。** 插件不监听端口、不提供接收端、不注册服务端路由、不实现 ASGI 宿主或远程 MCP。
- 平台可以采用单次或分块接口；插件只要求幂等、原号查询与完整回执三项语义成立，不约束平台内部事务。
- 上传模块可选装配：平台依赖缺失或导入失败时，只把上传能力标为不可用并给出原因，不连带阻断一期模块导入与本地执行。

## 3 事务与恢复

1. 业务事实先本地提交，再由同一工作单元登记候选与推进游标；候选登记失败不回滚事实，可由持久游标补建。
2. 发送在事务外：先在短事务登记请求意图与轮次，再出站，响应回来经工作单元追加回执或进展。
3. 一个工作空间仍由唯一核心进程持排他写锁；写锁换代只用于拒绝旧写入，不影响历史候选与回执。
4. 崩溃恢复从持久游标与许可重建：不重跑被测业务、不重置失败周期、不自动复活已撤销许可或已作出放弃决定的原提交。
5. 候选扫描经业务变更稀疏索引读取允许类型，固定高水位、只提交连续前缀；上传自身写入不产生候选（见[结果上传](03-结果上传.md) 第 6 节）。

## 4 不实现的能力

| 能力 | 插件 | 由谁负责 |
| --- | --- | --- |
| 接收结果、去重、存储 | 不做 | 平台接收端 |
| 共享查询与跨账号可见性 | 不做（不展示他人结论） | 平台页面 |
| 审核、意见留痕、审核状态投影 | 不做（不写审核、不算投影） | 平台 |
| 宿主接收模块、远程 MCP、服务端部署与运维 | 不做 | 平台 |

若平台后续要求插件展示只读的审核结论，按新增需求单独立项，不在本册承诺范围。

## 5 降级与可验证边界

- 平台不可用时，一期新旧验收场景、二期 P2-AC01—09 的本地能力仍全部可用；上传显示独立原因，不阻塞执行通道。
- "平台不可用不影响本地"不等于"存储不可写仍可运行"：本地存储守卫照常生效。
- 验证重点是：平台 SDK 缺失、会话过期、接口未配置、断网、回执冲突与队列压力下，本地闭环仍然成立且上传状态如实显示。
