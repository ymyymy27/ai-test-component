# 二期架构05：操作系统与运行时兼容

版本：3.3  
更新日期：2026年9月23日  
文档类型：工程设计文档

新增平台仍一个核心/一个用户工作空间/一个写入者，不引入常驻服务或第二套业务。先试点编辑器，再新增系统组合；不扩大技术栈自动执行承诺。

| 差异 | 适配方式与验证 |
| --- | --- |
| IPC | Windows受限命名管道；Linux/Unix本地socket，适配器get_peer_identity按平台实现，Linux可SO_PEERCRED，Apple采用支持的getpeereid等方式，不能统一写死一个API |
| socket权限 | 私有目录与socket权限、对端用户、实例握手分别验证；仅本机路径 |
| 文件系统 | 锁释放、同卷原子替换、文件/目录刷新与断电恢复逐系统实测，不支持则拒绝活动存储 |
| 路径 | 大小写/Unicode/符号链接按实际文件系统处理；项目ID稳定，路径不是业务主键 |
| 凭据 | Windows凭据管理、macOS Keychain或Linux Secret Service等受控后端；不可用明确提示，禁止明文回退 |
| 运行时与打包 | Python、编辑器发行版、制品和依赖锁文件纳入兼容清单，未测不声明支持 |

参考：[Linux unix(7)](https://man7.org/linux/man-pages/man7/unix.7.html)、[Apple getpeereid官方归档](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man3/getpeereid.3.html)。资料描述接口，不替代目标版本实测。

升级重新验证受影响组合；迁移遵守一期备份/维护模式。兼容数据记录os/os_version/runtime/editor及发行版/version/core/adapter/artifact_digest/evidence_path/verified_at/result。验收P2-AC02，至少一新增系统真实闭环，失败或未测如实记录。

## 1 组合验收与升级清单

| 类别 | 实测输入与失败注入 | 交付证据 |
| --- | --- | --- |
| 路径 | 空格/中文/大小写差异、符号链接、目录移动 | 正确绑定与边界拒绝，不按显示名串项目 |
| IPC/锁 | 第二入口、旧发现、进程退出、对端身份不符 | 单写成立，旧身份不能接管，权限拒绝明确 |
| 文件提交 | 各发布中断点、空间不足、损坏指针/对象、恢复再中断 | 仅原提交或完整新提交可见，证据缺口如实 |
| 凭据 | 后端缺失、引用失效、跨机恢复 | 需要凭据的能力不可用，其他本地能力继续，无明文回退 |
| 运行时/制品 | 缺解释器、版本不兼容、扩展/核心主版本冲突 | 安装/动作拒绝原因、版本和制品摘要 |
| 升级 | 宿主版本变更、需要实际格式迁移 | 重新探测，受影响组合重新实测；不继承旧pass |

核心支持区间在实际pyproject与锁文件确定后记录，不用文档推测任意组合兼容。新增系统不强制同时支持所有编辑器；每个组合独立列result/evidence_path。平台差异由基础设施和入口实现，上层只依赖统一端口。

### 模块职责

本册负责把支持范围扩展到更多操作系统与运行时。扩展的前提是**不引入第二套实现**：能力边界与记录格式保持一致。

### 扩展顺序

先完成本地历史、定位与图联动，再试点至少一个非Trae编辑器及至少一个新增桌面系统（macOS或Linux）；被测技术栈自动执行扩展另行立项。每个组合独立评估、独立实测，不同时推进多类。

### 平台差异清单

| 差异点 | 一期实现 | 二期处理 |
| --- | --- | --- |
| 排他锁 | `portalocker` | 按平台确认锁语义与释放时机；锁文件不按时间强删 |
| 原子替换 | 同卷替换 `current.json` | 确认目标文件系统的替换与刷新语义；不支持时明确报错 |
| 凭据设施 | Windows 凭据管理器 | 使用平台等价设施（如 macOS Keychain、Secret Service），保持"只存引用、不落正文"；**后端不可用时**：该凭据全部标为不可用并给出"配置可用后端或改用环境变量引用"的下一步，仅不依赖该凭据且满足核心/存储前置的本地能力继续；需要该凭据的被测请求或核验阻塞，新导出仍须核心可用且记录目录可写；不得静默降级为把密钥正文写入工作空间 |
| 路径规则 | 规范路径、真实文件身份及所在文件系统的大小写/链接语义 | project_id/workspace_id为稳定身份；规范路径仅用于当前绑定查找约束，移动目录形成绑定修订，不作历史业务主键；不得一律转小写 |
| 编辑器扩展打包 | VSIX（Windows） | 按平台与编辑器确认打包与安装方式 |

任何一项差异都必须在实现层内部处理，**不得让上层感知平台分支**；平台差异只允许出现在 `infrastructure/` 与入口适配中。

### 运行时与依赖

- 运行时版本按实测结果记录；核心包声明支持的运行时区间，超出区间明确报错。
- 新增第三方依赖需要评审：不得引入数据库、消息队列或常驻服务。
- 依赖版本纳入锁文件；制品摘要记入兼容清单。

### 升级与回归

- 编辑器或操作系统升级后，重新验证受影响行为；已通过结论在新版本下不自动继承。
- 能力探测结果随版本更新重新采集（见[能力降级与诊断](04-能力降级与诊断.md)）。
- 兼容清单记录：实际操作系统与版本、运行时、编辑器与版本、核心与适配器版本、制品摘要、验证证据位置。

### 验收映射

| 验证主题 | 关键检查 | 场景 |
| --- | --- | --- |
| 组合实测 | 新增组合完成一次完整本地测试闭环 | 二期 P2-AC02 |
| 缺项报告 | 不兼容版本或运行时缺失时明确报缺项，不宣称可用 | 二期 P2-AC02 |
| 隔离性 | 平台差异不泄漏到应用与领域层；记录格式一致 | 二期 P2-AC02 |
| 未测标记 | 未实测组合在兼容清单中如实标记 | 二期 P2-AC02 |

### 边界

- 不在本册扩展被测技术栈的自动执行能力（属后续评估）。
- 不改变一期的单写与工作空间规则；跨主机、跨用户不共享活动目录。

## 2 生命周期与来源的组合验证

每个新增系统组合按[核心生命周期](../../一期/架构文档/05-Trae接入.md#11-核心保活与退出合同)验证核心脱离临时入口、启动竞争、draining重连、关闭宿主继续执行、包装器/进程组及无工作退出。进程标识、句柄继承和退出机制仅在基础设施适配，不向领域增加平台分支。

同组合还须验证[执行来源](../../一期/架构文档/01-项目与计划.md#12-执行来源与物化边界)中的editable/入口映射及[当前文档](02-源码定位与行内标注.md#4-当前编辑器文档与校验请求)的编码、dirty、身份和版本语义；不能把Windows或另一个编辑器通过的记录直接复制为本组合通过。
