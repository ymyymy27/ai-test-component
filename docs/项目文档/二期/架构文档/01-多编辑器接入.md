# 二期架构01：多编辑器接入

版本：3.2  
更新日期：2026年9月23日  
文档类型：工程设计文档

integrations/<editor>分别承载命令、目录、宿主面板和工具配置，不互相import；公共视图和DTO共用。Trae为一期基线，新编辑器不复制调度、重试、判定或存储。

启动向核心report_capabilities，来源携editor_instance_id、版本、能力与实际失败信息；应用用例校验后持久化，扩展不写records。目录切换核对绑定修订，迟到响应保留原缓存。第二入口发现同核心并核验实例后连接；无法连接报WORKSPACE_IN_USE，不绕锁。

接入必须覆盖安装、绑定、计划/执行/查询/导出、面板、工具入口、文件跳转、目录切换、停用升级卸载和能力替代；接口允许向后兼容新增动作，通过能力声明识别，未知动作明确拒绝而非猜测。

源码只读但本地工作空间可写可运行；数据目录不可写只能查询已保存结果，导出仅在无需登记新产物的只读获取路径可用，创建新导出记录须恢复写入。工作区信任不足不自动启用项目命令或MCP。

验证P2-AC01/06/09，真实版本写入兼容清单，不能以其他编辑器通过替代本编辑器结果。

## 1 接入检查清单

定位能力需声明能否取得干净文档状态、稳定URI/版本、显示文本摘要和变化通知。按[当前文档校验](02-源码定位与行内标注.md#4-当前编辑器文档与校验请求)绑定请求；缺能力只开历史快照/展示位置文字，不声称当前内容已核实。核心保活、退出和重连沿用[一期生命周期](../../一期/架构文档/05-Trae接入.md#11-核心保活与退出合同)，新增宿主不能把核心绑定到窗口关闭。

| 责任 | 每个宿主须完成 | 共享内容 |
| --- | --- | --- |
| 命令映射 | 安装/菜单/快捷入口映射明确动作与参数 | contracts动作语义及错误 |
| 项目上下文 | 打开/切换/多根目录事件映射project与binding_revision | 核心项目记录，不能自己按目录名建业务键 |
| 面板宿主 | 加载同一Web Component、CSP、Schema和净化渲染 | resources/panel唯一源码 |
| 工具配置 | 按实际宿主方式登记或指导手动stdio配置 | 固定relay、参数中的绑定、无密钥 |
| 定位装饰 | 消费LocationDTO/标注，不自行推断内容一致 | application/locations输出 |
| 生命周期 | 断开订阅、清自己登记、升级版本协商、卸载保留数据 | 单核心与维护合同 |

各integrations目录互不import或借用对方构建产物；共同类型进入contracts。新增图/定位动作通过能力协商开放，不要求一期接口实现已有未知动作。接入验收逐项记录通过/失败/不适用及原因，临时CLI替代不能证明该宿主面板已支持。

### 模块职责

本册负责"同一套能力在更多编辑器里可用"。新增编辑器复用核心、DTO和判定，不建立第二套记录格式；二期定位、图和能力上报可向后兼容增加应用用例、动作及字段。

### 子域结构

```text
interfaces/local/            # 沿用一期；二期按能力协商增加动作路由
  api.py · pipe.py · editor_host.py
integrations/<editor>/       # 每个新编辑器一个目录，互不引用
  src/                       # 命令注册、工作目录事件、面板宿主、工具登记
resources/panel/             # 唯一一份面板源码，被所有编辑器复用
```

约束：`integrations/<editor>/` 之间**不得互相 import**，也不得引用彼此的构建产物；所有编辑器只依赖 `interfaces/local` 暴露的接口与 `contracts/` 的 DTO。

### 接口层不变，入口可变

| 项 | 是否随编辑器变化 | 说明 |
| --- | --- | --- |
| 应用 DTO 与动作名 | 既有动作语义不变；允许新增动作和兼容字段 | 面板、CLI、MCP 与各编辑器共用同一批动作；二期新增定位、图和能力上报动作及所需DTO字段，LocationDTO使用 `location_state`／`reason`，不改既有字段语义（兼容处理见[二期架构总览](00-架构总览.md)“二期新增记录与字段的兼容处理”） |
| 判定、统计、结论上限 | 否 | 由领域层唯一计算 |
| 记录格式与编号 | **既有记录：否**；二期新增投影记录与能力状态记录 | 本地项目编号、内容修订口径一致；新增 `DiagramDefinition`／`DiagramRevision`／`CapabilityState` 见[二期架构总览](00-架构总览.md)“二期新增记录与字段的兼容处理” |
| 命令注册方式、事件 API、Webview 宿主 API | 是 | 由各编辑器的入口适配处理 |
| 面板的宿主容器 | 是 | Web Component 不变，宿主适配不同 |

### 新增编辑器的接入清单

每个新编辑器须完成本册第1节的安装/卸载、命令与目录绑定、共享面板、工具配置、能力上报、用户确认来源及生命周期检查清单；成功和降级均保留真实输入输出与版本证据。

### 验收映射

| 验证主题 | 关键检查 | 场景 |
| --- | --- | --- |
| 记录一致性 | 同一操作在基准编辑器与新编辑器产出相同 DTO 与相同判定结论 | 二期 P2-AC01 |
| 目录与绑定 | 多目录切换不串项目；绑定修订一致 | 二期 P2-AC09 |
| 单写 | 第二、第三入口不产生第二写入者 | 二期 P2-AC09 |
| 缺能力降级 | 宿主缺面板或工具登记时给出替代入口 | 二期 P2-AC06 |

新增编辑器的实测结果记入 `docs/compatibility.json`，未实测组合不得声明通过。

## 2 多入口时序

第二入口先验证实例握手，再查询自己的project/绑定；相同intent只得到原运行。切换目录时关闭旧订阅后取新快照；原项目活动运行继续并保留导航。第三入口与前两个共用同一OS锁持有者；版本不兼容不得启动独立写入者“兼容”旧核心。可读源码与可写数据空间分别核对，信任不足单独拒绝执行。

新宿主须实现一期入口第9节的受控用户确认来源和挑战核对，不能把MCP请求映射为用户点击。所有入口复用该权限检查，不以同一OS用户身份替代人工确认。

### 单写与进程

- 一个工作空间仍只由一个核心进程持有写锁；新编辑器通过已验证的本地通道连接同一核心。
- 第二窗口或多编辑器同时打开时，能接入现有核心就接入；发现不一致或无法接入时返回 `WORKSPACE_IN_USE`，不另建写入者。
- 面板、CLI 与各编辑器不得各自启动单写循环或重试循环，重试策略统一由 `connectivity` 提供。
