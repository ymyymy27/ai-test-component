# 测试计划（二期）

> 适用期次：二期；主责：验证分层、验收覆盖与真实环境要求；状态：规划稿——P2-AC01—09 全部登记为 `untested`

本计划只说明二期怎么验证、什么算证据、当前登记是什么，不产生验收结论。验收场景与预期结果由[需求规格第 5 节](../02-需求/01-需求规格.md#5-验收场景)唯一维护；登记以 `tests/acceptance/p2/status.json` 为准。

## 1 目的与范围

- 验证二期 6 项功能在**不改变一期判定、统计与存储合同**的前提下，于新增编辑器与系统组合可用，定位、图件与面板增量行为如实。
- 验证命令与动作只经同一核心与同一批 DTO；编辑器插件、面板与导出不各自重算结论。
- 不验证三期账号与上传；不验证被测技术栈自动执行扩展。

## 2 测试分层

| 层次 | 对象 | 通过含义 | 不能替代什么 |
| --- | --- | --- | --- |
| 单元 | 六态判定、图事实守卫、游标与筛选条件、降级决策 | 规则自洽、边界可拒绝 | 真实宿主与真实系统接入 |
| 合同/schema | DTO 字段、动作协商、错误码、旧记录降级 | 接口与字段一致 | 真实编辑器中的完整闭环 |
| 架构依赖 | 入口 → 接口适配 → 应用用例 → 领域规则的依赖方向；无平台分支上浮 | 结构未越界 | 运行行为与故障恢复 |
| 故障注入 | 删事实边/缺口、dirty 文档、迟到响应、索引损坏、写锁竞争 | 拒绝与降级路径可控 | 真实掉电或真实平台故障 |
| 真实环境 | 至少一个非 Trae 编辑器 + 至少一个新增桌面系统组合 | 该组合完成真实接入与本地闭环 | 其他编辑器或系统组合 |

分层通过只是**进入下一层的条件**，不是验收通过。文档一致、单元与合同测试通过、夹具通过，均不得写成真实环境已验证。

## 3 验收覆盖矩阵

| 验收 | 关键输入与注入 | 验证层次 | 真实环境要求 |
| --- | --- | --- | --- |
| P2-AC01 | 非 Trae 编辑器安装、绑定、执行、查询、导出 | 合同 + 真实环境 | 该编辑器真实版本；与 Trae 记录逐项对比 |
| P2-AC02 | macOS 或 Linux 安装；不兼容版本、运行时缺失 | 合同 + 故障注入 + 真实环境 | 新增系统真实组合；缺项与只读目录分别验证 |
| P2-AC03 | 文件变更、快照缺失、旧 mtime、同大小同 mtime 异内容、路径缺失、dirty、CRLF/BOM | 单元 + 故障注入 + 真实环境 | 宿主能提供干净文档摘要与文档身份；不同宿主同版本号 |
| P2-AC04 | 生成依赖/链路图并跳证据；行内标注 | 合同 + 真实环境 | 图件在真实面板与独立窗口均可打开 |
| P2-AC05 | 布局/标注调整；删除事实节点/边、删除或替换缺口、重复函数调用 | 单元 + 故障注入 | 保存守卫在真实工作单元下生效 |
| P2-AC06 | 缺工具登记/面板/跳转；源码只读、数据目录只读、不受信任工作区 | 合同 + 故障注入 + 真实环境 | 至少一个真实宿主缺项组合；权限与信任真实设置 |
| P2-AC07 | 历史分组、同提交不同 diff/环境/模板/策略、完整重跑取消、分页、组内新修订、索引损坏 | 单元 + 合同 + 故障注入 | 真实历史数据；四维 16 种掩码与跨源码/限定源码查询 |
| P2-AC08 | 缺口跳链路节点；未隔离环境；链路节点缺失 | 合同 + 故障注入 + 真实环境 | 运行后视图与配置页自检在真实宿主中完成 |
| P2-AC09 | 多目录切换；第二、第三入口连接同一工作空间 | 单元 + 故障注入 + 真实环境 | 两个以上真实入口同时连接，核对写入者数量 |

16 种筛选掩码指范围、环境、档位、业务结果四维的全部组合（2⁴）；入口与游标条件沿用[一期存储与恢复第 4 节](../../../归档/系统级文档-2026-11-16/05-存储与恢复.md#4-有限查询与索引键)。

### 3.1 必测注入清单

| 注入 | 预期 |
| --- | --- |
| 删除事实节点或边 | 保存被拒绝，原图修订不变 |
| 删除或同数量替换缺口 | 逐 ID 核对后拒绝 |
| 重复函数调用 | 不因函数同名合并节点 |
| 校验前 dirty 或校验中编辑 | 不给当前内容已核实，不自动保存 |
| 同大小同 mtime 异内容 | 只能得到元数据候选，不能标内容已核实 |
| 迟到响应或目录切换 | 只更新原缓存，不进入当前视图 |
| 第二、第三入口同时连接 | 单写成立，不产生第二写入者 |
| 索引损坏 | 显示需恢复，不回退全历史扫描 |
| 图件生成失败 | 统计与缺口入口仍可用 |

## 4 真实环境与组合要求

- **至少一个新增编辑器**与**至少一个新增桌面系统**都要有真实接入证据；不能用一个编辑器或一个系统的结果代替其他组合。
- 顺序：先完成历史、定位与图等本地增量，再试点编辑器与新增系统；技术栈自动执行扩展另行立项。
- 每个组合记录：操作系统与版本、运行时版本、编辑器与版本、核心与适配器版本、制品摘要、验证证据位置、结果。
- 同一组合的升级（编辑器或系统版本变化）须重新验证受影响行为，旧结论不自动继承。
- 宿主能力缺失只能在真实宿主中验证替代入口；临时 CLI 替代不能证明该宿主面板已支持。
- 不允许以模拟系统、容器冒充目标桌面系统；无法构造的组合登记 `blocked` 并说明缺什么。

## 5 当前登记

- 9 项验收全部为 `untested`：没有真实编辑器/系统组合的接入证据，也没有定位、图件与面板增量的实测记录。
- `verified` 必须同时满足证据位置非空且 `real_environment_verified=true`；测了但前提不足写 `not_verified` 并说明缺什么；无法构造输入写 `blocked`。
- `untested` 行不得填写实际结果；每行必须写明未验证原因或阻塞项。
- `scenario`／`expected`／`related_frs` 逐字取自需求规格第 5 节，由 `tests/unit/test_acceptance_status_phases.py` 对账；任一一方改动都会使对账失败。
