# 需求规格（二期）

> 适用期次：二期（P2-FR01—P2-FR06 / P2-AC01—P2-AC09）
> 主责：范围、功能要求与验收预期
> 状态：规划稿——本文件只定义范围、规则与验收预期，P2-AC01—09 全部登记为 `untested`；不表示任一功能可用或已完成真实环境验收

本文件回答二期做什么、不做什么、按什么预期验收。字段、枚举、状态时序与提交/恢复的技术合同由功能分册与架构分册维护，本文件不另起定义；判定与统计公式只在一期功能清单定义一次。

## 1 目标

二期在一期本地能力之上**扩展使用面**：让同一套能力在更多编辑器与操作系统上可用，并让证据与依赖关系看得更清楚。

- 复用同一核心、同一 DTO 与同一判定口径，新增编辑器只增加入口适配与面板宿主。
- 从已保存记录回到源码位置，并在编辑器内只读标注问题、Mock 声明与证据缺口。
- 把依赖与实际调用链路投影为可独立打开、可交互、可跳转的本地图件。
- 宿主能力不一致时明确报缺项与替代入口，不让单一能力缺失扩散为全部本地能力不可用。
- 在一期三段信息面板之上增加历史记录页、环境自检可视化与图联动。

二期不引入账号、登录、结果上传、跨账号审核，也不增加平台服务依赖。一期的三层判定、统计口径、问题清单与本地导出规则保持不变。

### 1.1 成功指标

成功指标用于判断二期是否达成，不设新阈值；每项仍以第 5 节对应场景的输入、步骤、版本与原始证据为准。

| 成功指标 | 合同判定要求 |
| --- | --- |
| 能力一致 | 非 Trae 编辑器与 Trae 产出同语义的 DTO、记录与判定，不出现第二套规则 |
| 组合可核对 | 每个声明支持的系统与编辑器组合都有实际版本、制品摘要与证据位置 |
| 定位如实 | 无法确认的位置保持未知并说明原因，不以元数据相同宣称内容一致 |
| 图不产生判定 | 图节点与缺口只来自已采集事实，人工调整不改判定与统计分母 |
| 增量只读 | 历史页、自检可视化与图联动不新增判定，不改写一期三段 |

## 2 范围与边界

### 2.1 交付范围

| 分组 | 功能 |
| --- | --- |
| 编辑器与平台 | P2-FR01 多编辑器接入、P2-FR02 操作系统与运行时兼容扩展、P2-FR05 编辑器能力降级与诊断 |

### 2.2 支持范围

| 使用形态 | 环境 | 说明 |
| --- | --- | --- |
| 多编辑器客户端 | Windows 11 x64 及至少一个新增桌面系统（macOS 或 Linux） | 以一期 Trae 为基线，逐个编辑器实测 |
| 操作系统扩展 | macOS 或 Linux 桌面端，至少一个新增系统 | 逐组合实测，不承诺两者同时交付 |
| 展示增强 | 任意一期支持环境 | 图与标注在本地生成，不上传 |
| 面板增量 | 任意一期支持环境 | 历史页、自检可视化、图联动；三段本身属一期 P1-FR17 |

支持范围只按实测结果登记；**未实测组合不得声明通过**，也不得用文档一致或组件测试代替真实接入。

### 2.3 与一期的关系

- **同一核心**：二期新增定位、图与能力上报的应用用例与动作，既有动作语义保持兼容；不复制判定逻辑。
- **规则不重写**：三层判定、统计分母、证据等级、结论上限只在[一期功能清单第 3 节](../../一期/02-需求/03-功能清单.md#3-判定与统计唯一口径)定义；本文件只引用。
- **三段不重定义**：运行前／运行时／运行后信息面板的职责与实时值/快照值口径由一期 P1-FR17 维护；二期只在其上增加历史页、自检可视化与图联动。
- **存储不另建**：仍由一个核心进程持工作空间写锁，新增记录经同一工作单元不可变提交，见[一期存储与恢复](../../../归档/系统级文档-2026-11-16/05-存储与恢复.md)。

### 2.4 试点与顺序

- 先完成本地历史、定位与图增量，再用真实在用的编辑器与系统组合试点；不做全部编辑器的全量铺开。
- 试点至少覆盖一个非 Trae 编辑器与一个新增桌面系统；两者可以属于不同组合，但各自独立实测。
- 被测技术栈自动执行扩展不随本期系统兼容自动获得，须另行立项。

### 2.5 明确不做

- 不做统一账号、项目参与关系、结果上传与回执（属三期）；跨账号审核由平台项目承担。
- 不做自动操作录制与回放、任意语言自动插桩、跨语言静态影响分析。
- 不让任何编辑器插件实现第二套业务规则、记录格式或重试逻辑。
- 不重新定义三段信息面板；信息区不放动作，不新增判定规则，插件不修改被测代码。
- 不交付独立分层结果图；分层结果只作为依赖/链路图节点的已有事实展示。
- 不扩大被测技术栈的自动执行承诺；技术栈自动执行扩展另行立项。

## 4 功能要求

### 4.1 P2-FR01 多编辑器接入

- **目标**：在 Trae 之外的编辑器提供同一套能力，且不产生第二套规则、记录格式或重试逻辑。
- **输入**：实测宿主与版本、当前目录、绑定修订、同一核心与协议能力清单、本地项目、测试环境与模型配置。
- **操作与规则**：安装适配扩展 → 核实能力 → 绑定目录 → 加载共享面板 → 在面板或命令中执行、查询、导出；新增编辑器只替换入口与面板宿主；多目录时显式选择项目；同一持久业务意图跨入口只产生一次执行，明确重跑生成新意图。
- **输出**：与 Trae 语义一致的动作结果、DTO、报告与运行记录；记录按本地项目隔离。
- **异常分支**：缺面板、跳转或工具登记时给替代入口；数据目录不可写禁止新写；源码只读与工作区信任分别判断；停用或卸载先保存检查点与未保存材料。

### 4.2 P2-FR02 操作系统与运行时兼容扩展

- **目标**：把支持范围扩展到至少一个新增桌面系统，并按组合记录实测结果。
- **输入**：目标操作系统与版本、核心运行时、依赖锁文件、编辑器版本、核心与适配器制品。
- **操作与规则**：先完成本地历史、定位与图增量，再试点至少一个非 Trae 编辑器与至少一个新增桌面系统；每个组合完成安装、连接、必要能力检查与一次本地闭环，通过后写入兼容清单，记录实际版本、制品摘要与证据位置；平台差异只留在入口适配与基础设施。
- **输出**：兼容清单条目（系统/版本、运行时、编辑器/版本、核心/适配器版本、制品摘要、证据位置、结果）。
- **异常分支**：版本不兼容、运行时缺失或能力不足时给出具体提示；核心可用且记录可读时保留查询；新导出还须记录目录可写；核心不能启动时只能用普通文件工具查看已导出产物。

### 4.3 P2-FR03 源码定位与行内标注

- **目标**：从已保存记录回到代码位置并在编辑器内只读标注，不编造定位。
- **输入**：问题、证据与链路节点已有位置；项目与绑定修订；源码快照修订；项目相对路径；可选行号或符号。
- **操作与规则**：优先打开冻结快照；只有用户显式校验当前文件时才读取并哈希目标文件；元数据相同只表示可能未变；mtime 与快照记录的该文件 mtime 比较，不与快照创建时间比较；同一文件共享一次校验结果，不同文件逐文件核对；六态定义唯一在[定位架构分册第 1 节](../04-架构/03-源码定位与行内标注.md#1-用例与六态)，本文件只引用。
- **输出**：`LocationDTO`（`target_kind`、`location_state`、`reason` 与可确认位置）及同源行内标注。
- **异常分支**：校验前已有未保存修改、校验期间或之后文档变化、无法证明显示内容对应磁盘时，不得标 `current_verified`；路径变化、逃逸、缺失与权限不足分别给原因；无宿主跳转能力时给相对路径与行号文字；插件不自动保存、不回滚用户代码。

### 4.4 P2-FR04 依赖与链路图

- **目标**：把已提交记录投影为可独立打开、可缩放、可搜索的本地图件，节点可回到证据。
- **输入**：模块与依赖、测试计划与运行、分层结果、`TraceNode`、证据与问题记录、精确来源修订集合。
- **操作与规则**：依赖图节点用 `module_id`，边为使用者 → 提供者；链路图节点用实际 `(run_id, attempt_id, trace_node_id)`，边只连实际父子或请求关联；源码位置只是导航属性，不同实际调用不因函数同名合并；人工只调整布局、折叠与注释，保存形成新的图修订；图定义与图修订经工作单元不可变提交、编号独立于领域记录，不参与判定与统计分母；报告引用精确到图修订，新布局不自动改报告。
- **输出**：图定义、图修订、缺口标记、自包含 HTML 图件、节点到证据/日志/问题的关联。
- **异常分支**：缺采集以已知范围挂缺口，不新增虚构节点；删除或同数量替换事实节点、边、缺口集合时拒绝保存；图件生成失败保留原始记录查看；导出遵循统一脱敏规则，不含密钥。

### 4.5 P2-FR05 编辑器能力降级与诊断

- **目标**：宿主能力不一致时明确报缺项与替代入口，让不受影响的本地动作继续。
- **输入**：宿主能力探测事实、实例与版本、工作空间可写性、项目信任状态、已有环境连接记录。
- **操作与规则**：启动或显式重检时探测工具登记、面板宿主、文件跳转、只读工作区等；宿主只上报事实，核心经用例校验并保存能力状态；降级按**具体动作的真实依赖**判断，矩阵唯一维护在[能力降级与诊断第 2 节](../04-架构/05-能力降级与诊断.md#2-按动作依赖降级矩阵)；诊断与 `aitest doctor` 使用同一健康模型。
- **输出**：能力清单与缺失项、替代入口、统一健康结果（检查时间、原因、下一步）。
- **异常分支**：探测超时返回已完成阶段与具体卡点；区分“能力缺失”与“存在但调用失败”；记录目录不可写禁止新运行与新导出登记；不受信任工作区不自动执行命令或加载项目 MCP 配置；诊断不返回密钥与私有正文。

### 4.6 P2-FR06 面板增量（一期 P1-FR17 之上）

- **目标**：在一期三段之上增加历史记录页、环境自检可视化与图联动，不重算判定。
- **输入**：一期已保存的 `Run`／`Step`／`Attempt`、`ReportSnapshot`、`DecisionDTO`、源码身份、环境连接记录，以及二期图投影。
- **操作与规则**：历史页按源码身份分组，组内按一期结论键区分范围、环境、规则/验收/模板与判定策略；行显示记录时间、档位与驱动、业务结论、证据等级或“未打分”、必测完成与跳过数；点击载入只读运行后视图；当前结论键、报告修订折叠与永久留存沿用[一期报告合同](../../../归档/系统级文档-2026-11-16/04-报告与缺陷.md#1-报告快照与不可变)；环境自检展示四项并调用既有维护用例重检；缺口与链路节点同源，点击聚焦对应节点。
- **输出**：只读历史视图、四项环境事实、缺口到节点的导航入口。
- **异常分支**：记录缺失显示空态与原因，不显示推测值；无图或缺节点保留证据详情与缺口标记，不用推断补全；图件生成失败不影响统计与缺口入口；查看旧运行不覆盖当前活动运行；索引损坏明确暂不可用。
