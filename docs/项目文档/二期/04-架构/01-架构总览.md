# 架构总览（二期）

> 适用期次：二期；主责：分层增量、模块落点、与一期共享的单写与存储；状态：规划稿，未实现、未验收
>
> 二期在一期本地规则之上新增展示与适配，不改变三层判定、证据等级、问题关闭与永久留存。一期分层、端口与调用流程见[一期架构总览](../../一期/04-架构/01-架构总览.md)，本册只写增量。

## 1 分层增量

| 层 | 二期增量 | 不得做的事 |
| --- | --- | --- |
| 入口层 | 每个编辑器一个 `integrations/<editor>/` 目录，承载命令、目录事件、面板宿主与工具配置 | 互相 import 或引用彼此的构建产物；直接写业务文件 |
| 接口适配层 | 各编辑器的跳转与装饰器适配；能力探测结果上报 | 自算定位状态、图节点或判定结论 |
| 应用用例层 | `application/locations.py` 统一位置解析；`application/diagrams.py` 统一图投影；能力上报与历史查询用例 | 绕过端口直接读文件；为每个入口复制一套用例 |
| 领域模型层 | 判定、统计与证据等级**无新增** | 把投影记录当业务记录参与判定 |
| 外部能力层 | `adapters/diagram_render.py` 渲染自包含图件；平台相关实现留在基础设施 | 让平台分支泄漏到应用层与领域层 |
| 资源 | `resources/diagrams/` 图件模板；`resources/panel/` 唯一面板源码 | 手改生成产物或维护第二份面板 |

### 1.1 新增调用流程

1. 入口收到用户动作，映射到共享动作名与参数；能力不满足时按降级矩阵返回替代入口。
2. 应用用例读取已提交记录，经端口取得受限源码或渲染能力，不直接读文件。
3. 定位与图分别形成 `LocationDTO` 与图 DTO；事实集合与来源修订在同一读取边界内核对。
4. 需要保存的投影经工作单元提交不可变修订；外部渲染与模型调用在事务外。
5. 面板、CLI、导出与报告读取同一修订的 DTO，不各自拼装。

### 1.2 与一期端口的关系

- 复用一期 `SourceSnapshotPort`、工作单元与查询目录，不新建并存端口。
- `DiagramRenderPort` 在二期定稿签名，渲染器只接收已冻结修订。
- 能力上报复用 `connectivity` 的健康模型；面板与 `doctor` 读同一结果。

## 2 新增模块落点

| 新增内容 | 落点 | 职责 | 端口与注册 |
| --- | --- | --- | --- |
| 位置解析 | `application/locations.py` | 校验项目/绑定/来源，读取受限目标元数据与冻结内容，输出 `LocationDTO` | `SourceSnapshotPort` |
| 当前文件校验 | `application/locations.py` | 显式请求时只读目标文件，计算原始摘要与显示摘要 | `SourceSnapshotPort` 受限读取 |
| 图投影 | `application/diagrams.py` | 从已提交记录生成图定义与图修订，核对事实集合 | 经工作单元提交 |
| 图件渲染 | `infrastructure/adapters/diagram_render.py` | 渲染自包含 HTML，DTO 与导出同源 | `DiagramRenderPort` |
| 能力上报 | `application/connectivity.py`（一期已有）+ 入口上报 | 校验宿主实例与能力事实后保存 | 一期工作单元 |
| 编辑器入口 | `integrations/<editor>/src/` | 命令、目录、面板宿主、工具登记、装饰器 | 只依赖 `interfaces/local` 与 `contracts` |

`DiagramRenderPort` 在一期端口文件中只预留名称与用途；方法签名与返回类型在二期定稿并在 `bootstrap.py` 注册。图与定位的导航统一调用核心动作，编辑器不另算位置或自行拼装数据。

## 3 与一期共享的单写与存储

- 一个工作空间仍只由一个核心进程持排他写锁；新增编辑器、第二窗口与 CLI 通过已验证的本地通道接入同一核心，无法接入时返回 `WORKSPACE_IN_USE`，不另建写入者。
- 二期新增记录经一期 `WorkspaceUnitOfWork` 提交，遵循同一提交边界、不可变修订与幂等结果；外部执行、模型与网络调用仍在事务外。
- 记录权威、索引与事件边界沿用[一期存储与恢复](../../../归档/系统级文档-2026-11-16/05-存储与恢复.md)；二期不新增数据库、消息队列、常驻服务或第二套索引。
- 新增记录编号独立于领域记录；投影记录不参与判定、不计入统计分母，报告对其只做附件式引用。

## 4 新增记录与字段兼容

| 新增项 | 归属 | 兼容处理 |
| --- | --- | --- |
| `DiagramDefinition`、`DiagramRevision` | 投影记录，按不可变修订经工作单元提交，编号独立 | 旧记录不含该类型时读作“图定义缺失”并保留缺口入口，不重建、不推测 |
| `CapabilityState` | 宿主能力状态记录，由核心校验后保存 | 与一期 `ConnectionState` 分记录、互不覆盖；键、修订与投影见[能力降级与诊断](05-能力降级与诊断.md)，宿主不得直接写记录 |
| `LocationDTO` 的 `location_state`、`reason` | 定位投影 DTO 字段 | 只增不改；旧记录缺字段按 `unknown`，旧客户端忽略未知字段不得报错 |
| 历史与图 DTO | 由已保存来源派生的查询/显示投影 | 沿用一期结论与永久留存，不新建第二套统计 |
| `TraceNode` 与 `DiagramDefinition` 引用 | 图节点→证据/问题/源码的导航引用 | 只引用精确业务 ID 与修订；引用失效显示缺口，不改变原记录 |

新增动作（如 `resolve_location`、`verify_current_file`、`generate_diagram`、`save_diagram_layout`、`query_diagram`、`report_capabilities`）按能力协商暴露；既有动作名与字段语义不变。

## 5 演进规则

- **加适配器不加分支**：平台与编辑器差异只出现在 `infrastructure/` 与入口适配中。
- **各有唯一投影入口**：定位只由 `application/locations.py` 生成，图只由 `application/diagrams.py` 生成。
- **不做第二套规则**：新增编辑器不实现自己的重试、判定或记录格式。
- **实测才声明**：每个编辑器与操作系统组合实测通过后才可声明支持；未实测组合不得写成通过。
- **建设顺序**：先做本地定位、图与面板增量，再按试点用户真实在用的编辑器与系统组合逐个铺开，不做全量铺开。
