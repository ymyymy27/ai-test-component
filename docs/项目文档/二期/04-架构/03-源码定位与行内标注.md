# 源码定位与行内标注

> 适用期次：二期 P2-FR03；主责：六态定位、当前文档校验、只读标注；状态：规划稿，未实现、未验收
>
> 本册负责“从记录回到代码”：把问题、证据与链路节点上的定位信息在编辑器里打开并标注。定位是**记录的投影**，不产生新事实。图形化依赖与链路视图见[依赖与链路图](04-依赖与链路图.md)。

## 1 用例与六态

本节的六态枚举与判定顺序是二期**唯一正文**，需求、功能与界面分册只引用，不另列枚举。

`application/locations.py` 经 `SourceSnapshotPort` 读取目标元数据与冻结内容，不直接做文件 I/O。`resolve_location` 默认选择可复取的历史快照；用户要求当前文件时，先比较目标记录的相对路径、大小与该文件在快照中记录的 mtime（**不与快照创建时间比较**），只有显式 `verify_current_file` 才读取目标文件计算摘要。

| 状态 | 含义与允许动作 |
| --- | --- |
| `unknown` | 定位来源或校验不足；说明原因，不当成当前一致，不输出猜测行号 |
| `snapshot_verified` | 已取得并校验冻结内容，可按原位置只读打开；**不证明当前文件相同** |
| `metadata_match` | 元数据相同，只是候选一致；可打开历史快照，当前文件仍需显式校验 |
| `current_verified` | 用户显式校验完成磁盘摘要与干净编辑器文档一致性核对，且请求/文档身份与版本未变，才允许按原行跳当前文件 |
| `stale` | 当前内容已不一致，提示重新固定源码或打开原快照，不错指新内容 |
| `missing` | 必要快照或路径不可用，明确缺口并保留原记录 |

- 同大小、同 mtime 仍可能异内容；元数据相同只能得到 `metadata_match`。
- 未知枚举值按 `unknown` 处理并附“客户端能力不足”原因，不能当“忽略未知字段”继续定位。
- `current_verified` 与 `snapshot_verified` 分别携带不同身份：前者绑定当前文档身份与版本，后者不套用当前缓冲区身份。

## 2 定位来源与身份

| 来源 | 可用位置 | 不能推断的内容 |
| --- | --- | --- |
| `IssueRecord` | 明确采集的相对路径、函数或行号、关联源码快照 | AI 候选根因不是已核实位置 |
| `EvidenceRef` | 采集位置、关联节点与来源修订 | 日志提及的路径不自动成为允许读取路径 |
| `TraceNode` | 实际节点附带的位置（若已采集） | 同函数多次调用不是同一节点 |

- 路径一律使用**相对本地项目根目录**的路径，不写机器绝对路径；路径归属、链接逃逸、缺文件与权限错误经端口校验。
- 定位绑定项目、绑定修订、源码快照修订与内容修订；无法复取历史快照时如实报错，不指向变化后的内容。
- 输出 `LocationDTO`：`schema_version`、`project_id`、`binding_revision`、`snapshot_revision`、`relative_path`、`line_hint`（可空正整数）、`symbol`（可空）、`location_state`、`reason`（稳定原因码与可读说明，无异常为 null）、`target_kind`（`snapshot`／`current`）、`verified_digest`、`document_version`、`verification_request_id`、`editor_instance_id`、`document_id`、`display_digest`。
- `verified_digest` 只在内容已核实后填写；`document_version` 只在当前编辑器文件已核实后填写。宿主只消费 DTO 做只读打开与装饰，不自行判断内容是否一致。

## 3 当前文档校验与脏缓冲区守卫

- 用户选择当前文件时，宿主提供 `editor_context`：`editor_instance_id`、`document_id`、`document_version`、`dirty`、`request_id`、`binding_revision` 与干净文档的 `display_digest`。
- 文档 `dirty` 即返回 `unknown`，原因 `UNSAVED_BUFFER`；若另有可信的不一致事实可为 `stale`。默认提供“打开冻结快照”和“自行保存后重新校验”，**插件不自动保存、不回滚或改写用户代码**。
- `verify_current_file` 携带同一 `editor_context`。核心只经 `SourceSnapshotPort` 读取受限目标文件原始字节，计算摘要并保留编码、BOM、换行方式与可供显示核对的 `display_digest`（按确定编码解码、去 BOM 后的显示字符取 UTF-8，不折叠换行或 Unicode；原始字节摘要仍含 BOM）。
- 核心对比宿主请求所带 `display_digest`、目标显示摘要与冻结原始摘要；缺字段、不符、无法可靠解码或目标读取中变化，均不给 `current_verified`。
- 宿主在响应后再次核对同一已打开文档：文档会话 ID、项目绑定、`editor_instance_id`、`document_version` 未变，重新取得的显示文本摘要仍与 `display_digest` 一致，才应用 `current_verified` 与原位置。
- 干净文档与显示摘要能力缺失时，通过能力协商只提供历史快照或位置文字，不用“磁盘相同”假装显示文本相同。

## 4 跳转与标注

| 动作 | 行为 | 边界 |
| --- | --- | --- |
| 跳转 | 打开对应文件并定位到函数或行 | 只读打开，不修改文件 |
| 行内标注 | 在本行展示关联问题、Mock 声明与证据缺口 | 展示层行为，不改变断言、缺陷或档位 |
| 缺口提示 | 该行证据缺失或未采集时显式标出 | 不隐藏缺口，不用推断补全 |

- 装饰器与跳转 API 由入口适配实现；应用层只输出“路径 + 行号 + 标注内容 + `location_state` + `reason`”的投影。
- 标注内容由 `application/locations.py` 统一投影，多个编辑器共用同一份数据。
- 同一文件按可视区批量共享一次目标校验；不同文件各自有结果，不能把一个文件的 `current_verified` 用于整张图或整批标注。
- 读内容只在用户显式校验目标时发生；面板打开、切页、进度刷新与历史查询不触发该读取，不递归扫描整仓。
- 标注更新不得阻塞编辑；大文件或大量标注按可视区按需渲染。

## 5 失效、迟到与验收

- 后续编辑、文档重新加载、关闭重开、磁盘变化通知、项目/绑定/宿主切换，均使当前验证缓存失效；不以 `document_version` 数字恰好相同跨文档复用结果。
- 校验期间或之后内容变化即标失效，不使用旧行号继续装饰；已证明变化与“没有核实”分开，不用 `stale` 掩盖未知。
- 迟到的跳转响应只更新原目录缓存并标“非当前视图”，不进入已切换项目或已切换快照的视图。
- 需要历史只读虚拟文档时，由宿主能力声明并通过核心分块取冻结字节，不把存储裸路径暴露成任意文件访问。

| 验证主题 | 关键检查 | 场景 |
| --- | --- | --- |
| 可跳转 | 相对路径与行号正确打开；快照用 `target_kind=snapshot` + `snapshot_verified`，当前文件用 `target_kind=current` + `current_verified` | P2-AC03 |
| 不编造 | 无法确认时保持 `unknown` 且 `reason` 非空 | P2-AC03 |
| 变更保护 | 文件已变为 `stale`，快照缺失为 `missing`，均不指向变化后的内容 | P2-AC03 |
| 标注只读 | 标注不修改代码、不触发新工具、不改变断言与缺陷状态 | P2-AC04 |

覆盖校验前 dirty、校验中编辑、迟到响应、关闭重开、不同宿主同版本号、CRLF/UTF-8/BOM、磁盘相同但显示不同、旧客户端与六态降级。
