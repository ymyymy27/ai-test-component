# 能力降级与诊断

> 适用期次：二期 P2-FR05；主责：能力探测记录、按动作依赖降级、健康模型；状态：规划稿，未实现、未验收
>
> 本册负责“宿主缺什么、怎么替代”：各编辑器能力不一致时明确报缺项并给出替代入口，不让单一能力缺失阻塞本地测试。判定与执行安全仍由一期合同约束。

## 1 探测记录与唯一写入者

- 宿主负责探测并上报**事实**：编辑器实例、发行版与版本、能力项、`supported`／`unsupported`／`failed`／`unknown`、错误原因与探测来源；扩展不直接写记录。
- 核心 `connectivity` 校验实例与修订后，经一期工作单元保存 `CapabilityState`；键为 `(workspace_id, editor_instance_id, editor_version)`，独立修订，**不与**环境 `ConnectionState` 混写或相互覆盖。
- 启动、显式重检或宿主版本变化时更新；不在每条界面查询时重复探测。权限与信任变化由宿主事件上报，执行入口仍须校验实际操作权限，不能只信旧缓存。
- 调用失败与能力不存在分开记录：前者是同一动作的真实失败，后者是缺项；两者都不能被统一解释为“可无条件执行”。
- 日志与诊断脱敏，不返回私有正文、敏感地址参数或密钥；重试由 `connectivity` 统一提供，界面不维护重试循环。

> 名称说明：本册的 `CapabilityState` 指**宿主能力状态记录**；基础设施中表示外部依赖条件的同名枚举是另一对象，落盘类型不得复用它。

## 2 按动作依赖降级矩阵

本节是二期降级规则的**唯一正文**；需求、功能、界面与测试分册只引用，不另列表格。`connectivity` 统一返回动作可用性及原因，UI 与 CLI 不依据全局健康色推断全部动作可用；调用时仍检查真实依赖，不仅依靠缓存。

| 缺失条件 | 可继续 | 必须阻塞 |
| --- | --- | --- |
| 可选模型凭据或网络 | 核心与存储满足时的已有规则、手工配置、其他执行与查询 | 依赖该模型的生成与分析 |
| 被测 HTTP 或核验凭据 | 不依赖该凭据的步骤与历史查询 | 使用该凭据的请求或核验；不回退明文 |
| 被测运行时缺失，核心可用 | 历史查询；记录目录可写时的新导出 | 相应执行方式 |
| 核心运行时缺失或核心不能启动 | 普通文件工具读取已经导出的文件 | 插件查询、新执行、新导出 |
| 记录目录可读不可写，核心可用 | 已发布事实的只读查询 | 新运行、确认、报告与导出登记等写动作 |
| 宿主面板、跳转或工具登记缺失 | 对应的替代入口（命令/CLI、路径文字、手动配置） | 该宿主原本承担的面板或跳转动作 |

- 可替代的宿主能力缺失只降级对应动作，不扩散为“全部本地能力不受影响”；核心不可用也不能用面板降级掩盖。
- 恢复后不自动重放未知副作用；结果未知且无法核实时保持待核实。

## 3 健康结果

| 状态 | 判断 | 下一步 |
| --- | --- | --- |
| `READY` | 当前所需本地核心与写入条件就绪，可用能力已核实 | 进入既有流程；不等于测试通过 |
| `DEGRADED` | 有可替代的宿主能力缺失，或可选模型/连接故障 | 列出缺项、影响动作与替代入口 |
| `NOT_READY` | 核心或记录写入不可用，或所需运行条件无法解析 | 阻止受影响动作；核心可用且记录可读时保留查询 |

- 健康结果包含检查来源与修订、最近确认时间、已完成阶段、未检查项与下一步；一次自检超时只把未完成项标未知，不抹掉已确认结果。
- 诊断与 `aitest doctor` 读取同一份核心结果，不另算健康规则；面板显示合并投影，不自行探测。
- **与一期现状的差异**：一期 `doctor` 顶层只返回 `READY`／`NOT_READY`，分项依赖条件可带 `DEGRADED`／`NOT_CONFIGURED`。二期要把可替代能力缺失投影为顶层 `DEGRADED`，必须先扩展核心健康模型与 `doctor`，不能只改面板；扩展现状登记为未实现、未验收。
- 健康结果按实例与版本分别缓存；宿主版本变化后旧结果失效并重新探测。
- 面板展示缺项时同时给出替代入口与受影响动作，不只显示颜色或状态字。
- `doctor` 与面板对同一实例应给出相同结论；出现差异按缺陷处理，不能各留一份口径。

## 4 权限、信任与错误分类

- 源码目录只读但数据目录可写：可固定到可写工作目录执行，不修改源仓库。
- 数据目录不可写：写动作 `NOT_READY`，已有记录可查询；不承诺新运行或新导出登记。
- 未信任的项目代码或配置：不自动执行入口，不自动加载项目 MCP 配置，说明宿主的信任步骤。
- 被测目标不可达、依赖缺失或数据条件不满足：阻塞关联步骤，不伪装成业务失败。
- 模型连接不可用：只降级依赖模型的 AI 动作，人工、证据与本地报告继续。
- 权限与信任的判定以实际动作为准；历史 `READY` 不能绕过新发生的不可写或未信任状态。

## 5 诊断输出与验收

- 诊断呈现能力清单、缺失项、错误分类、替代入口、检查时间、原因与下一步；未知项明确标未知。
- 每次编辑器或系统组合的实测结果写入兼容清单，不把运行时报错写成兼容清单通过记录。
- 不实现平台侧健康检查（三期）；不在本模块实现重试策略。

| 验证主题 | 关键检查 | 场景 |
| --- | --- | --- |
| 缺项可见 | 缺文件跳转、工具登记或面板时明确报缺项 | P2-AC06 |
| 替代可用 | 缺面板或跳转时仍能通过命令入口完成执行与导出 | P2-AC06 |
| 按动作降级 | 某依赖缺失只阻塞对应动作，其他允许动作继续 | P2-AC02/06/08 |
| 不误报 | “能力存在但调用失败”与“能力缺失”分开显示 | P2-AC06 |

多宿主并发上报、权限或信任中途变化、探测超时与恢复后不重放未知副作用均属必测注入。
