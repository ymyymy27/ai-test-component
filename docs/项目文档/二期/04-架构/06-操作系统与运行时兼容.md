# 操作系统与运行时兼容

> 适用期次：二期 P2-FR02；主责：平台差异、运行时与依赖、组合验收与升级；状态：规划稿，未实现、未验收
>
> 新增平台仍坚持一个核心、一个用户工作空间、一个写入者，不引入常驻服务或第二套业务。核心生命周期与执行来源见[一期 Trae 接入](../../../归档/系统级文档-2026-11-16/06-Trae接入.md#6-核心保活与退出)、[一期项目与计划](../../../归档/系统级文档-2026-11-16/02-项目与计划.md#8-执行来源与物化边界)。

## 1 扩展顺序与组合验收

- 先完成本地历史、定位与图联动，再试点至少一个非 Trae 编辑器及至少一个新增桌面系统（macOS 或 Linux）；被测技术栈自动执行扩展另行立项。
- 每个组合独立评估、独立实测，不同时推进多类；不承诺 macOS 与 Linux 同时交付。
- 组合通过后写入兼容清单，记录：操作系统与版本、运行时、编辑器与发行版/版本、核心与适配器版本、制品摘要、验证证据位置、验证时间、结果。
- 未实测组合在清单中如实标 `untested`；不得用另一个系统或编辑器通过的结果代替本组合。
- 运行时报缺项由宿主能力探测与健康结果报告，不写进兼容清单充当支持结论。

## 2 平台差异清单

| 差异点 | 二期处理 | 验证要点 |
| --- | --- | --- |
| IPC | Windows 受限命名管道；Linux/Unix 本地 socket；对端身份按平台实现（Linux `SO_PEERCRED`，Apple 使用受支持的 `getpeereid` 等方式），不写死单一 API | socket 权限、对端用户、实例握手；仅本机路径 |
| 排他锁 | 沿用一期 `portalocker` 语义，按平台确认释放时机；锁文件不按时间强删 | 第二入口、进程退出、旧身份不能接管 |
| 原子替换与刷新 | 确认目标文件系统同卷替换与刷新语义；不支持时拒绝活动存储并说明 | 各发布中断点、空间不足、损坏指针/对象、恢复再中断 |
| 路径规则 | 大小写、Unicode、符号链接按实际文件系统处理；`project_id`／`workspace_id` 为稳定身份，规范化路径只用于当前绑定查找 | 空格/中文/大小写差异、符号链接、目录移动 |
| 凭据设施 | 使用平台受控后端（Windows 凭据管理器、macOS Keychain、Linux Secret Service 等），只存引用不落正文；后端不可用明确提示，禁止明文回退 | 后端缺失、引用失效、跨机恢复 |
| 编辑器扩展打包 | 按平台与编辑器确认打包与安装方式，制品与依赖锁文件纳入清单 | 安装、升级、制品摘要核对 |

- 平台差异只在基础设施与入口适配内部处理，应用层与领域层不出现平台分支。
- 文件系统不支持所需语义时明确报错并拒绝把该位置作为活动存储，不静默降级。

## 3 运行时、依赖与制品

- 运行时支持区间以实际 `pyproject.toml` 与锁文件为准，超出区间明确报错；不用文档推测任意组合兼容。
- 新增第三方依赖需要评审：不得引入数据库、消息队列或常驻服务；依赖版本进入锁文件。
- 每个组合记录实际运行时版本与制品摘要；核心与适配器主版本冲突时拒绝安装或动作，并给出原因。
- 凭据后端不可用时，只阻塞需要该凭据的被测请求或核验；不依赖该凭据且满足核心/存储前置的本地能力继续，新导出仍须核心可用且记录目录可写。

## 4 升级与回归

- 编辑器或操作系统升级后重新验证受影响行为；既有组合的通过结论在新版本下不自动继承。
- 宿主版本变化时重新采集能力探测结果（见[能力降级与诊断](05-能力降级与诊断.md)），不沿用旧缓存。
- 格式迁移遵守一期备份与维护模式：迁移前完成可校验备份，恢复先核实活动执行与可抢救输出，未知副作用不自动重放。
- 兼容清单按组合独立列结果与证据位置，不设“整体兼容”汇总代替逐项实测。

## 5 生命周期与来源的组合验证

### 5.1 组合验证顺序

1. 核对安装前提：系统版本、运行时区间、依赖锁与制品主版本。
2. 安装并连接核心，核对实例握手、单写与对端身份。
3. 跑通一次本地闭环：绑定、固定源码、执行、证据、判定与导出。
4. 注入缺项与失败：运行时缺失、凭据后端不可用、数据目录不可写、进程退出。
5. 记录实际版本、制品摘要与证据位置；未完成项写明卡点。

每个新增系统组合还需验证：

- 核心脱离临时入口、启动竞争、退出时 draining 重连、关闭宿主后继续执行、包装器/进程组与无工作退出。
- 进程标识、句柄继承与退出机制只在基础设施适配，不向领域增加平台分支。
- [执行来源](../../../归档/系统级文档-2026-11-16/02-项目与计划.md#8-执行来源与物化边界)中的 editable 与入口映射，以及[当前文档校验](03-源码定位与行内标注.md#3-当前文档校验与脏缓冲区守卫)中的编码、dirty、文档身份与版本身份。
- 不能把 Windows 或另一个编辑器通过的记录直接复制为本组合通过。

## 6 验收映射

| 验证主题 | 关键检查 | 场景 |
| --- | --- | --- |
| 组合实测 | 新增组合完成一次完整本地测试闭环 | P2-AC02 |
| 缺项报告 | 不兼容版本或运行时缺失时明确报缺项，不宣称可用 | P2-AC02 |
| 故障隔离 | 分别区分缺核心/被测运行时、模型/被测凭据与只读记录目录 | P2-AC02 |
| 隔离性 | 平台差异不泄漏到应用与领域层，记录格式一致 | P2-AC02 |
| 未测标记 | 未实测组合在兼容清单中如实标记 | P2-AC02 |

至少一个新增系统完成真实闭环；失败或未测如实记录，不用模拟系统替代。

### 6.1 证据要求

- 每个组合的证据包含真实输入、软件与制品版本、预期与实际、证据位置；截图或日志不能单独证明业务闭环。
- 兼容清单条目与运行记录一一对应，不把运行时报缺项写成支持结论。
- 升级后的重新验证生成新的条目或新证据，不覆盖旧条目，也不继承旧结论。
