# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Stack

Vue 3 + Vite + TypeScript（用户指定）。纯本地资源构建：无 CDN、无在线字体、无外部图标库。

## Users

Windows 11 上的测试与开发人员，在 Trae 编辑器里对一个本地项目做上线前自测。他们熟悉代码与命令行，但不希望在编辑器里读英文状态码或手工拼命令。使用场景是白天在办公桌前、编辑器深色主题下、面板宽度 400–900px 的窄侧栏或标签页。

## Product Purpose

把“选目录 → 给目标 → 确认验收标准 → 选范围 → 生成计划 → 执行 → 看结论”收进一个面板。面板只展示本地测试服务（CLI）返回的事实：结论、覆盖、用例结果、证据引用与 AI 分析；它不计算判定，也不写业务文件。

## Positioning

与通用测试面板的差别在“分母可见”：范围、覆盖与未验证项始终与结论同时出现；AI 只解释事实，不改变结论。面板是跨编辑器共享的同一份前端，Trae 只是第一个宿主。

## Operating Context

- 宿主注入 `window.aitestHost`（call/getState/setState），面板只通过它取数与触发动作。
- 业务能力来自一期 CLI：项目、任务、计划、运行、证据、问题、报告、doctor。
- 运行在后台 worker 中进行；关闭面板不中断运行，重开后在历史里找回。
- 数据保存在用户数据工作空间，不写进被测源码。

## Capabilities and Constraints

- 必须支持：无项目引导、四步新建测试、运行进度与取消、结果与失败证据、问题列表、历史、设置自检与修复。
- 后端缺口（不伪造）：验收项编辑通过重新保存任务实现，没有独立的修订命令；模块选择只随计划保存，后端不按模块过滤验收项；没有报告列表命令，报告从结果页按需生成；服务与链路配置没有读写命令，设置页只说明位置与影响。
- 状态与枚举只做中文显示；界面不出现 plan_id / run_id / JSON / CLI 等内部词，也不显示错误码。
- 不引入外部字体、图标库或网络请求；不实现判定、覆盖计算与 Mock 真实性推断。

## Brand Commitments

- 全中文，面向测试与开发用户；文案说“哪里错了 + 下一步怎么做”。
- 状态用“未开始 / 运行中 / 已完成 / 已中断 / 已取消”，不用英文枚举。
- 不知道就写“未知 / 未提供 / 未验证”，不用绿色掩盖。
- 视觉：Trae/VSCode 深色编辑器气质，低饱和、精密、层级清楚；禁止霓虹渐变、玻璃拟态、超大圆角、花哨动画。

## Product Principles

1. 事实优先：结论、覆盖、用例结果只来自后端字段。
2. 分母可见：没有分母的数字不展示，未覆盖范围要说出来。
3. 少点击：正常路径只有选目录、给目标、确认执行三件人工动作。
4. 不假装：缺能力、缺证据、未验证都明确写出来。
5. 一个面板：所有宿主共用同一份前端与同一套桥接契约。
