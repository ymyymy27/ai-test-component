# Design — 测试台账

> 产品事实见 `PRODUCT.md`，方向合同见 `SURFACE.md`。
>
> 2026-11-17 第五版：从“单页三相位 + 抽屉”改为“任务 → 计划 → 运行”的测试台账。计划、运行、结果共用同一张验收项台账；计划/报告/问题详情是二级完整文档页。

## 1 世界与基调

一个工程师的测试台账：固定头、单列台账、固定尾。界面像测试运行器或检验记录，不像仪表盘、聊天或卡片墙。专业感来自短标签、稳定行高、真实计数和诚实空态，不来自装饰、渐变或 AI 图标。

## 2 颜色

| 角色 | 浅色 | 深色 | 用法 |
| --- | --- | --- | --- |
| 页面 | `#f4f5f3` | `#0f1211` | 背景 |
| 表面 | `#fbfbfa` | `#151917` | 文档、输入框 |
| 抬升 | `#eef0ed` | `#1a201c` | 确认区、告警条 |
| 下沉 | `#f7f8f6` | `#0b0e0c` | 证据、代码、当前用例 |
| 边框 | `#d8dcd8` | `#272d29` | 分隔线、控件 |
| 强边框 | `#b7beb8` | `#3a423c` | 台账脊、表头 |
| 主文本 | `#171a18` | `#e7ece7` | 标题与正文 |
| 次文本 | `#4f5a52` | `#a4ada6` | 说明、值 |
| 弱文本 | `#6f7a72` | `#737d75` | 元数据、标签 |

强调色只给主操作、当前行和焦点；状态色只给文字/小记号，不给整行底色或胶囊。

## 3 字体与数字

- UI：`Segoe UI Variable Text` → `Segoe UI` → 系统中文字体；不加载在线字体。
- 等宽：`Cascadia Mono` → `Consolas`；只给数字、路径、证据文件名、命令。
- 正文 11–13px；任务标题 18px；设置/问题页标题 20px；不用巨型结论字。
- 中文行高 1.45–1.6；数字用 tabular-nums；比率写 `本次 3 / 共 8 项`，不出现 S/M。
- 标签 10px，不全大写、不加字距装饰。

## 4 形状与层级

- 1px 分隔线、2–4px 圆角；无卡片、无渐变、无玻璃；菜单浮层允许轻阴影，文档页全屏。
- 层级靠分隔线、留白、字重；台账左侧序号/记号形成一条“脊”。
- 主操作 30px 高、实心强调色；次操作透明底 1px 边框；危险操作用失败色边框。
- 焦点环 2px 强调色；项目、任务、报告版本菜单是轻阴影浮层；计划/报告/问题详情用全屏文档页，不做抽屉套抽屉。

## 5 布局

- 顶栏 42px：项目按钮（点开是自绘菜单，含项目列表与“添加项目”，不用原生下拉框）；测试 / 问题 / 历史；设置。任务“切换目标”与报告版本也用自绘菜单。
- 测试工作区单列，内容最大 900px；内边距 16px，≤520px 为 12px。
- 固定头只留三层：任务标题与“切换目标”；一行计划/时间/用例数/状态；覆盖条与计数图例。不再放重复的工具栏。
- 项目级检查单独一行；不计入范围。没有配置时写“本次没有项目级检查”，不写“未配置”。
- 台账只列本次纳入的验收项；未纳入项收在底部“未纳入本次 N 项”里，展开只读。计划/结果页不再显示可勾选方块，避免被读成未完成表单。
- 台账：验收项行 36–44px；用例缩进在验收项下；失败项默认展开。
- 每个状态只有一个主操作：准备/过期是“生成/重新生成计划”，计划态是“开始测试”，运行态是“停止”，结果态是“重跑未通过项”或“再次运行”。范围编辑只在无计划、计划过期或主动“调整范围”（含结果页）时出现。
- 固定尾：计划态是执行前确认；运行态是进度/停止；结果态是完成数、查看计划/报告与主操作。
- 二级文档页：顶部返回 + 标题 + 状态；主体分段；底部保存/生成。
- 证据查看器：全屏列表；点击用系统程序打开；没有缩略图或内嵌大图；缺失/截断直接标出。

## 6 组件词汇

| 组件 | 规则 |
| --- | --- |
| 覆盖地图 | 每个方块对应一个验收项；下方给“通过/失败/阻塞/等待中/未纳入”计数；点击跳到对应验收项 |
| 验收项行 | 序号 + 状态记号 + 原文 + 右侧状态；只列本次纳入项；未纳入项在底部摘要里展开 |
| 用例行 | 标题 + 检查方式 + 结果；预期/实际并排；窄屏上下 |
| 证据 | 台账内只给文件名按钮；全屏列表查看器用系统程序打开；没有缩略图或内嵌大图；缺失/截断直接写 |
| 补充证据 | 证据查看器内填写文件路径与说明，登记到当前运行 |
| 导入链路 | 报告文档内的“导入调用链日志”，导入后报告引用新证据 |
| 规则 | 设置页只列出/查看/绑定；保存、导入、导出没有 UI |
| 报告版本菜单 | 报告页顶部自绘菜单；列出历史版本与结论，切换后只读旧版本 |
| 问题链接 | 失败用例下给问题标题与状态；不显示内部 ID |
| 解释 | 默认折叠在证据之后；标题“解释 · 不改变结论” |
| 执行前确认 | 固定尾；计划版本、范围、依赖、会改动什么；人勾选后才可开始 |
| 运行条 | 运行中、已耗时、已完成/总数、停止；不伪造当前步骤 |
| 结论 | 一行结论 + 本次范围 + 未覆盖；不放大成海报 |
| 文档页 | 计划/报告/问题详情；返回测试；保存动作明确“新版本” |
| 状态记号 | 通过=勾；失败=实心方块；阻塞=斜纹；等待/已计划=空心强调色；未运行=空心灰；待人工=半填充 |

## 7 状态与文案

- 结论：通过 / 没通过 / 没测完 / 这次不用测；运行：运行中 / 已完成 / 已取消 / 已中断 / 执行出错。
- 用例：通过 / 失败 / 阻塞 / 出错 / 未运行 / 待人工。
- 检查方式：项目级检查 / 自动检查 / 人工检查；验证方式：项目快速检查 / 按验收项验证。
- 计划版本：计划 2 · 第 1 版；范围：本次 3 项 / 共 8 项。
- 面板写“未纳入”“未核实”“未完成”，报告仍按合同写“未覆盖”；不合并成“未验证”。
- 不把“未执行”写成通过；不把“没选”写成不适用；空分母不显示 100%。
- 不出现冒烟、L1/L2/L3、S/M、Mock、plan_id/run_id、失败签名、错误码。

## 8 动效与键盘

- 只保留展开/收起和状态变化，120–160ms；不做呼吸点、闪烁光标、页面入场。
- 未实现：`Ctrl+Enter` 开始、`Esc` 关闭文档页/查看器、关闭后焦点回到原按钮；当前只依赖按钮和默认 Tab 顺序。
- `prefers-reduced-motion` 下关闭动效。

## 9 主题

- `data-theme="light" | "dark"`；默认跟随系统；设置可切跟随系统 / 浅色 / 深色。
- 两套主题共用同一结构、组件和文案，不允许只在一套主题成立。
- 偏好写 `localStorage["aitest.theme"]`；禁用时只影响本次会话。

## 10 避免的“AI 味”

- 不做聊天框、人格化叙述、气泡历史、机器人/火花图标。
- 不用紫蓝渐变、玻璃拟态、发光、超大圆角、卡片墙、胶囊状态。
- 不做巨型结论、假进度百分比、无分母的 100%、假置信度。
- 不把 AI 摘要放在结论上方；不让 AI 解释覆盖证据。
- 不把“未执行/阻塞/未知”涂成绿色通过。
- 不重复同一数字；不在标题、说明、按钮、底栏各写一遍。
