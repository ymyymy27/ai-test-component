# 面板视觉与交互契约

本文件是 `panel/` 的界面约束。颜色、字号、间距、圆角的唯一来源是
[`src/styles/tokens.css`](src/styles/tokens.css)；本文件只说明用法，不复制数值。

## 1. 场景

本地测试工作台：先看结论，再核对范围、证据和运行记录。页面不承担营销、
账号、支付或社交功能。所有视觉选择服务于“快速判断这次能不能过”。

## 2. 布局

- 桌面侧栏固定 248px；工作区内容最大 820px。
- 页面从上到下：页面标题 → 当前结论/状态 → 需要处理的内容 → 明细。
- 一屏只保留一个主操作。次要动作降为普通按钮或链接。
- 侧栏的项目分区用轻量文字标签和当前项下划线，不用四个等宽按钮。
- 任务列表可收起；收起只隐藏任务，保留“任务 / 新建”入口。
- 开始测试并列展示“按目标测试 / 按范围测试 / 快速检查”，不预选某一种。
- 320 / 768 / 1200 宽度都不能横向滚动；窄屏用“返回 + 当前分区”，
  不把面包屑压成无意义的碎片。

## 3. 文字

- 语义文本最小 12px。10–11px 只允许纯装饰，不承载计划版本、次数、确认人
  这类需要核对的事实。
- 页面标题使用 `page-title`；区块标题使用 `section-title`（14px）或
  `section-title-lg`（16px），不跨页面借用设置页类名。
- 中文标点统一全角；按钮和标签不加句号；说明句只写事实，不写“赋能、一站式、
  无缝”这类空话。

## 4. 颜色与语义

- 冷灰绿工作台，单强调色。强调色只用于主操作、当前项、焦点和正在发生的状态。
- 结论只有四值：`通过 / 失败 / 未完成 / 不适用`。阻塞、出错、未运行只作为
  步骤或用例子状态，不出现在结论位置。
- 通过、失败、警告、缺失各自使用对应 token；不要用强调色表达失败。
- 正文和次要文字必须达到 AA 对比度；`ink-disabled` 只给禁用态。

## 5. 容器与层级

- 两种容器足够：
  - `panel`：1px 边框 + `radius-strip` + surface，用于需要操作或独立阅读的块；
  - 扁平列表：1px 分隔线，用于连续记录、台账和设置项。
- 阴影只留给 toast、popover、dialog。左 3px 色条只留给运行页“当前用例”。
- 空区块不渲染；不要用“本次没有……”占位撑出一屏。

## 6. 交互

- 主按钮必须有明确动词；危险操作使用 `btn-danger` 并二次确认。
- 可点击文字链接最小命中高度 28px；窄屏 36px。图标按钮至少 32×32。
- 焦点环使用 `--focus`，不能被输入框的浅色 outline 覆盖。
- 表单错误就地显示；错误文案说明缺什么、下一步做什么。
- 运行中禁止切换任务、新建任务和快速检查；禁用态要说明原因。

## 7. 动效

- 只用 token 中的时长：120ms 交互、180ms toast、200ms dialog、220ms 抽屉。
- 不做渐变、玻璃、发光、视差和自动播放动画。
- 尊重 `prefers-reduced-motion`；过渡只表达状态变化，不制造注意力。

## 8. 可访问性

- 页面有唯一的 `h1`；区块按层级使用 `h2/h3`。
- 交互控件使用原生 `button`、`a`、`input`、`select`；不要用 `div` 模拟。
- 筛选按钮组使用 `aria-pressed`；不要只写 `role="tab"` 而没有 `tabpanel`。
- 图标按钮必须有 `aria-label`；状态不能只靠颜色表达。
- 跳过链接、主内容焦点、Esc 关闭抽屉/对话框、焦点返回触发元素，必须可用。
