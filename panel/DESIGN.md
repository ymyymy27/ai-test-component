# Design — 工具化工作台

> 产品事实见 `PRODUCT.md`，方向合同见 `SURFACE.md`。
>
> 2026-11-17 第四版：从“平静工作台”继续收敛为开发者工具。去掉步骤行、外层卡片和重复解释，首屏只留目标、验收项和主操作；结果页先给结论与失败项，其余信息折叠。目标是像测试运行器，而不是 AI 工作台。

## 1. 世界与基调

一个本地测试工具：页面就是编辑器侧栏的一部分，内容左对齐、平铺、密度接近 IDE。专业感来自短标签、稳定的行高、真实的计数和诚实的空态，不来自 onboarding 文案、卡片堆叠、终端道具或装饰性状态线。

## 2. 颜色

| 角色 | 浅色 | 深色 | 用法 |
| --- | --- | --- | --- |
| 页面 | `#f6f7f9` | `#111318` | 背景 |
| 表面 | `#ffffff` | `#181b21` | 抽屉、输入框、浮层 |
| 次级表面 | `#f1f3f6` | `#20242c` | 次级按钮、选中行 |
| 下沉 | `#f9fafb` | `#0d0f13` | 代码、输出块 |
| 边框 | `#e4e7ec` | `#2a2f38` | 分隔、控件 |
| 主文本 | `#1b1f27` | `#eef0f3` | 标题与正文 |
| 次文本 | `#4b5565` | `#aeb6c2` | 说明 |
| 弱文本 | `#6b7280` | `#7f8997` | 辅助信息（≥4.5:1） |
| 强调 | `#2f6bed` | `#7aa2ff` | 主按钮、选中、焦点 |
| 通过 | `#16794c` | `#5cc98d` | 成功状态 |
| 没通过 | `#b42318` | `#ff8a80` | 失败状态 |
| 未得出 | `#b54708` | `#f2b95c` | 卡住、未跑完、需人工 |

强调色只用于“可操作 / 已选中 / 当前”，占屏面积保持很小。状态色只给文字或图标，不给整行填色，也不用发光圆点。

## 3. 字体与数字

- UI：`Segoe UI Variable Text` → `Segoe UI` → 系统中文无衬线；不加载在线字体。
- 等宽：`Cascadia Mono` → `Consolas`，只用于路径、命令、证据文件名和执行输出。
- 13px 正文 / 12px 辅助 / 11px 极短标签；页面标题 16px；结论 26px；不再使用 30px 以上标题。
- 中文行高 1.5–1.6；数字用 `tabular-nums`；比率写成 `X / Y`，同一屏只保留一个分母。
- 状态用普通 UI 字体，不用等宽字、全大写或字距装饰。

## 4. 形状与层级

- 卡片 8px 圆角、控件 6px、徽标 4px；主视图不再使用外层卡片。
- 层级靠 1px 分隔线、留白和字重，不靠卡片表面、阴影或左侧彩色描边。
- 区块之间用分隔线；列表行不套卡片，不加整行 hover 底色。
- 焦点环 2px 强调色，偏移 2px。
- 阴影只给弹层与抽屉。

## 4.1 默认自动，人只处理异常

按修改计划的剩余人工动作收敛：正常路径只有选项目目录、给/选目标、执行前确认三次人工动作。Trae 已打开目录且工作空间没有项目时自动绑定当前目录；目标候选与验收项由 AI 产出并默认全选；交付说明在展开时自动起草，和范围共用一次“保存调整”落盘；计划自动发布；失败分析、问题草稿和报告自动生成。

## 5. 组件词汇

| 组件 | 规则 |
| --- | --- |
| 顶栏 | 40px：项目选择在左；环境仅在异常时显示；主题、设置靠右。不显示产品字标 |
| 目标行 | 16px 目标名；右侧一个小 `⌄` 切换目标；项目与历史是 12px 文本按钮 |
| 验收项列表 | 13px 文本、34px 行高、方形勾选；右上只写“已选 8 / 8”，未选时才补一句“N 项未选，不计入结论” |
| 交付说明 | 展开即自动起草，不再要求先点“AI 起草”；“保存调整”同时保存交付说明 |
| 主操作 | 蓝色实心、34px 高；一屏只出现一个；建议单底部吸底，左侧只写“8 项检查” |
| 结果摘要 | 26px 结论 + 状态/时间同一行；下一行“6 项检查 · 2 项通过 · 2 项失败…”；再一行只写未测、无结论、推测未验证 |
| 结果操作 | 一行按钮：看第一条失败 / 重跑没通过（N）/ 换个目标；不做标题和解释段落 |
| 失败检查 | 折叠行，首条展开；标题 + 状态一行；验收标准、预期、层级与方法用 12px；原始输出收进“技术细节” |
| 运行进度 | 3px 单色进度条 + `4 / 6`；当前项用 2px 左边框；“后台运行，可关闭面板”只出现一次 |
| 状态文字 | 12px 普通字体，颜色表示状态；不用浅底徽标、发光点或胶囊 |
| 抽屉 | 右侧 420px，标题用正常中文；关掉后焦点回到原按钮 |
| 空态 | 一句状态 + 一句动作；不写欢迎语和产品介绍 |
| 主题 | 跟随系统 / 浅色 / 深色；只换 token，不换布局和文案 |

## 6. 布局

- 顶栏 40px；内容最大宽度 780px 居中；页面内边距 16px，≤520px 为 12px。
- 建议单：目标行、验收项列表、副作用一行、吸底主操作；没有外层卡片、步骤行和说明块。
- 运行：状态行、3px 进度、当前步骤、实时验收项、证据与停止。
- 结果：标题、结论摘要、操作行、没通过的检查、未完成、分析、历史问题、证据与报告、折叠的验收意见与全部检查。
- 设置：环境、模型、工作空间、GitHub、外观、高级配置；平铺分组，用分隔线而不是卡片。
- 抽屉宽度 420px；≤520px 占满宽度；焦点留在抽屉内。

## 7. 状态与文案

- 结论：通过 / 没通过 / 没测完 / 这次不用测；运行：正在运行 / 已完成 / 已取消 / 已中断 / 出错了。
- 检查结果：通过 / 没通过 / 卡住了 / 出错了 / 还没跑 / 等你确认。
- 未验证必须分开写：没测项、卡住、等你确认、推测没验证，不能合并成一个“未验证”。
- 按钮用动词，错误说“哪里错了 + 下一步”，空态教下一步；不出现内部 ID、run_id、错误码。
- 同一事实只说一次：不在标题、说明、按钮、底栏各写一遍；用户刚做完的动作不解释（如“你手动填写的目标”）。
- 取消后只写“中途停止，已完成的检查仍然有效”，不把取消说成失败。

## 8. 动效与键盘

- 只保留状态变化：120–200ms 的背景/边框/展开/进度；不做闪烁光标、呼吸点、页面入场。
- `Ctrl+Enter` 可从建议单开始测试；Esc 关闭抽屉与目标菜单；`prefers-reduced-motion` 下全部关闭。

## 9. 主题

- `data-theme="light" | "dark"`；默认由 `prefers-color-scheme` 决定，用户可在设置里选“跟随系统 / 浅色 / 深色”。
- 偏好写入 `localStorage["aitest.theme"]`；禁用存储时只影响本次会话。
- 两套主题共用同一布局、组件与文案，不允许出现只在一套主题成立的结构。

## 10. 避免的“AI 味”

- 不做步骤向导（“第 N 步 + 下一步说明”）、大卡片外层、结论旁的 action card、每屏一条服务态度式安抚。
- 不出现全大写英文标签、终端状态线、闪烁光标、`[01]` 编号、PASS/FAIL 代码、等宽 10px 状态字。
- 不用紫蓝渐变、发光、玻璃拟态、机器人/火花图标、奶油+陶土配色。
- 不重复解释同一数字；不把覆盖率画成“进展顺利”的蓝色进度条；不把“AI 猜测”放在结果摘要里。
- 不假装有遥测（READY、每 2 秒、POLL/2S）；只展示能据此行动的状态。
